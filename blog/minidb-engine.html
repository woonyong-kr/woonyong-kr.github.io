디스크에 남는 SQL 엔진의 뼈대

메모리 자료구조는 껐다 켜면 사라집니다. 디스크에 남는 데이터베이스는 전혀 다른 제약에서 시작합니다. 모든 것이 페이지 단위로 읽히고 쓰여야 한다는 제약입니다. MiniDB 는 이 제약을 바닥부터 받아들이고 만든 C 엔진입니다.

파일의 첫 세 페이지

DB 파일은 세 페이지로 시작합니다.

[page 0: DB 헤더] [page 1: 첫 힙 페이지] [page 2: B+Tree 루트]

헤더에는 매직 넘버, 페이지 크기, 힙 체인의 시작, 인덱스 루트, 다음 할당 페이지, 자동 증가 id 가 들어갑니다. 모든 온디스크 구조체에는 __attribute__((packed)) 를 붙였습니다. 구조체 크기가 디스크 바이트와 정확히 같아야 하고, 컴파일러 패딩이 끼는 순간 파일 포맷이 컴파일러 마음대로 바뀌기 때문입니다.

페이지 크기는 상수가 아니라 sysconf(_SC_PAGESIZE) 입니다. x86_64 는 4,096바이트, Apple Silicon 은 16,384바이트 — 상수로 박으면 한쪽에서 만든 파일이 다른 쪽에서 안 열립니다. 실제로 두 아키텍처를 오가며 같은 파일을 열어 확인했습니다.

Slotted Page — 행은 뒤에서, 목차는 앞에서

힙 페이지 안에서 행 데이터는 페이지 끝에서 앞으로 자라고, 슬롯 디렉터리(행의 위치·상태)는 헤더 뒤에서 뒤로 자랍니다. 둘이 만나면 페이지가 가득 찬 겁니다.

삭제는 데이터를 지우지 않습니다. 슬롯을 FREE 로 표시하고 빈 슬롯 체인에 걸어 두면, 다음 INSERT 가 그 자리를 재활용합니다. 이 재활용 탐색이 나중에 대규모 삽입에서 O(N²) 병목으로 드러났는데, 그 이야기는 따로 정리했습니다.

B+Tree — 포인터가 아니라 page_id

트리의 모든 노드는 페이지 하나에 대응하고, 자식 참조는 메모리 포인터가 아니라 page_id 입니다. 디스크에 그대로 쓰여야 하니까요. 리프에는 형제 포인터(next_leaf_page_id)가 있어 정렬 순서대로 옆으로 걸을 수 있습니다 — 범위 조회 개선이 이 포인터 위에서 만들어졌습니다.

동시 접근은 래치 커플링으로 풀었습니다. 트리 전체를 잠그지 않고, 자식을 잡으면 부모를 놓습니다.

Buffer Pool — 무엇을 읽었는지 세기

디스크와 실행기 사이에 256프레임 LRU 버퍼 풀을 두고, page_id → frame 해시(512버킷)로 찾습니다. dirty 페이지가 임계치를 넘으면 선제 flush 합니다.

여기서 가장 유용했던 건 성능이 아니라 계측입니다. 쿼리마다 통계를 초기화해 페이지 로드 · 캐시 적중 · 디스크 기록을 세고, .debug 를 켜면 쿼리가 끝날 때마다 출력됩니다.

minidb> SELECT * FROM bench WHERE id = 5000
[debug] 소요: 0.04ms | 페이지 로드: 3 (히트: 1, 미스: 2)

minidb> SELECT * FROM bench WHERE id >= 5000 LIMIT 1000
[debug] 소요: 3.89ms | 페이지 로드: 36 (히트: 36, 미스: 0)

“인덱스를 걸면 빨라진다”가 아니라 “이 질의가 페이지를 몇 장 읽었는가” 를 보게 되는 지점입니다. 점 조회는 3장, 범위 조회는 36장 — 이 숫자가 범위 조회 개선의 출발점이 됐습니다.

그 위의 층

같은 엔진 위에 SQL 파서(CREATE / INSERT / SELECT / UPDATE / DELETE / EXPLAIN), 플래너(접근 경로 선택), 실행기, 그리고 Strict 2PL 락 테이블(구간 잠금 포함)과 HTTP 서버까지 하나의 경로로 이었습니다. REPL 에서 친 SQL 이 파서 → 플래너 → 실행기 → 버퍼 풀 → 디스크까지 어디를 지나는지 전부 따라갈 수 있습니다.

실제 데이터베이스라고 말하지 않는 이유

교육 프로젝트입니다. WAL 이 없어 크래시하면 복구할 수 없고, 질의 최적화기도 통계 기반 플래닝도 없습니다. 격리 수준은 고를 수 없고, 데드락은 탐지 대신 3초 타임아웃으로 끊습니다. 실제 데이터베이스를 만들었다고 말하지 않습니다 — 다만 인덱스와 잠금이 왜 그 모양인지는, 만들어 보고 나서야 알게 됐습니다.
