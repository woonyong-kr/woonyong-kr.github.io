PintOS 가상 메모리 흐름

PintOS 가상 메모리의 page fault·claim·swap·mmap 복구 흐름을 연결한다.

최종 다이어그램 설계 메모

최종 그림 세트:

  • VM 전체 흐름: 유저 VA 접근 → MMU → PTE miss → page fault → SPT → frame → PTE 설치
  • 코드 로딩 과정: load_segment()가 UNINIT page와 lazy aux를 만들고 첫 접근 때 실제로 읽는 흐름
  • 주소 참조 과정: CR2, error_code, vm_try_handle_fault() 판단 분기
  • VM 데이터 구조: struct page, struct frame, SPT hash, PML4의 역할 분리
  • Frame/SPT API: vm_alloc_page(), vm_do_claim_page(), swap_in(), destroy(page)의 호출 관계

한 장으로 보는 VM 흐름

Mermaid는 현재 정본의 복구·실패 경로를 포함한 탐색 지도다. 원본 source의 시각적 구획은 아래 도판 세트에서 보존한다.

flowchart LR
  User["유저 명령어<br/>mov rax, [0x401000]"] --> MMU["MMU<br/>VA → PA 번역"]
  Stack["스택 명령어<br/>push rax"] --> MMU
  MMU --> PML4["PML4<br/>현재 주소 공간의 하드웨어 page table"]
  PML4 -->|PTE 있음| Memory["Frame bytes<br/>실제 데이터 읽기/쓰기"]
  PML4 -->|PTE 없음| PF["page_fault()<br/>CR2와 error_code 읽기"]
  PF --> Try["vm_try_handle_fault()<br/>합법 fault인지 판단"]
  Try -->|권한 위반| Exit["process exit"]
  Try -->|SPT page 있음| Claim["vm_do_claim_page()"]
  Try -->|SPT page 없음| StackCheck{"stack growth 조건 만족?"}
  StackCheck -->|No| Exit
  StackCheck -->|Yes| Grow["vm_stack_growth()"]
  Grow --> Alloc["vm_alloc_page()"] --> Claim
  Claim --> Frame["vm_get_frame()"]
  Frame --> Link["page ↔ frame 연결"]
  Link --> SetPte["pml4_set_page()<br/>PTE 설치"]
  SetPte -->|성공| SwapIn["swap_in(page, frame->kva)"]
  SetPte -->|실패| Rollback["claim rollback<br/>link / PTE / frame 정리"]
  SwapIn -->|실패| Rollback
  SwapIn --> Uninit{"page type"}
  Uninit -->|UNINIT| Init["uninit_initialize()"]
  Uninit -->|ANON| Anon["anon_swap_in()"]
  Uninit -->|FILE| File["file_backed_swap_in()"]
  Init --> Initializer["anon_initializer() 또는<br/>file_backed_initializer()"]
  Init --> Lazy["lazy_load_segment()"]
  Lazy -->|실패| InitFail["UNINIT swap_in 실패<br/>aux / type metadata 정리"]
  InitFail --> AuxChecklist["lazy aux cleanup<br/>success / failure / destroy"]
  AuxChecklist --> Rollback
  Lazy --> Memory
  Anon --> Memory
  File --> Memory
  Memory --> ByteCheck["GDB byte check<br/>fault_addr vs frame->kva+offset"]
  Rollback --> Exit
  Exit --> ExitCleanup["process_cleanup()<br/>SPT page destroy"]
  ExitCleanup --> Kill["supplemental_page_table_kill()<br/>UNINIT / ANON / FILE 정리"]

링크 표

  • 구현 전 전체 질문
    • 코드에서 볼 위치: VM 전체
  • VA -> MMU -> PA
    • 코드에서 볼 위치: pintos/threads/mmu.c
  • PML4 / CR3
    • 코드에서 볼 위치: pml4_activate(), pml4_get_page(), pml4_set_page()
  • PAGE / FRAME / SPT
    • 코드에서 볼 위치: pintos/include/vm/vm.h
  • 코드 로딩 과정
    • 코드에서 볼 위치: load_segment(), lazy_load_segment()
  • fork lazy UNINIT page
    • 코드에서 볼 위치: supplemental_page_table_copy(), uninit_new(), uninit_initialize()
  • 주소 참조 과정
    • 코드에서 볼 위치: page_fault(), vm_try_handle_fault(), spt_find_page()
  • page claim
    • 코드에서 볼 위치: vm_do_claim_page(), vm_get_frame()
  • frame eviction / clock
    • 코드에서 볼 위치: vm_get_frame(), vm_get_victim(), pml4_is_accessed()
  • claim rollback
    • 코드에서 볼 위치: pml4_set_page() 실패, swap_in() 실패, pml4_clear_page()
  • UNINIT swap_in 실패
    • 코드에서 볼 위치: uninit_initialize(), lazy_load_segment(), anon_initializer(), file_backed_initializer()
  • lazy aux cleanup 구현
    • 코드에서 볼 위치: lazy_load_segment(), mmap lazy callback, uninit_destroy(), file_backed_destroy()
  • byte equivalence
    • 코드에서 볼 위치: pml4_get_page(), frame->kva + offset, QEMU GDB memory read
  • process cleanup
    • 코드에서 볼 위치: process_cleanup(), supplemental_page_table_kill(), destroy(page)
  • stack growth
    • 코드에서 볼 위치: vm_stack_growth(), setup_stack()
  • UNINIT -> ANON / FILE
    • 코드에서 볼 위치: uninit_initialize(), uninit_destroy(), anon_initializer(), file_backed_initializer()
  • fork swapped ANON page
    • 코드에서 볼 위치: supplemental_page_table_copy(), anon_swap_in(), anon_swap_out()
  • 바이트 관찰
    • 코드에서 볼 위치: raw bytes, PTE, struct page, struct intr_frame
