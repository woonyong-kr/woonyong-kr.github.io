웹 서버와 프록시

소켓에서 HTTP, 프록시, 백엔드 확장으로 이어지는 기본 흐름.

큰 흐름

flowchart TD
  A["브라우저 요청"] --> B["소켓 프로그래밍"]
  B --> C["Tiny Web Server"]
  C --> D["HTTP 요청/응답"]
  D --> E["웹 프록시 서버"]
  E --> F["DBMS 서버화와 백엔드 확장"]

요청이 지나가는 길

  • socket -> bind -> listen -> accept -> read -> write
  • browser -> proxy -> origin server

실험

  • Tiny 서버를 한 줄씩 따라 실행하기
  • 프록시가 받은 요청과 보낸 요청을 로그로 비교하기
  • 동시 요청 처리 방식을 순차 처리와 비교하기

웹 서버와 프록시 쟁점

  • 네트워크 프로그래밍과 네트워크 공학은 무엇이 다른가?
  • C로 만든 Tiny 서버의 흐름은 Flask/FastAPI 내부와 어떻게 연결되는가?
