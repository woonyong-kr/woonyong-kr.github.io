PintOS 운영체제 학습 프로젝트

PintOS는 운영체제 개념을 실제 코드로 확인하기 좋은 실습 프로젝트다. Threads, User Programs, Virtual Memory 흐름을 따라가며 QEMU가 제공하는 하드웨어 경계까지 함께 본다.

학습 흐름

학습은 Threads의 실행 모델에서 시작해 User Programs의 실행 경계를 거쳐 Virtual Memory의 주소 변환으로 이어진다. Threads에서는 스레드와 스케줄러, 인터럽트, 동기화, 컨텍스트 전환을 살펴본다. User Programs에서는 유저 모드와 ELF 로딩, 시스템 콜, 파일 디스크립터, 프로세스 생명주기를 따라간다. Virtual Memory에서는 페이지 테이블과 프레임, 페이지 폴트, swap, mmap이 주소 변환에 어떻게 참여하는지 확인한다.

이 흐름을 실제 구현과 연결할 때는 PintOS 코드 SW_AI-W11-pintos를 기준으로 삼는다. 하드웨어 동작이 에뮬레이션되는 경계는 QEMU 코드 QEMU에서 확인한다. QEMU 사용자 포크는 https://github.com/woonyong-kr/qemu이며, QEMU 소스 링크는 master 브랜치를 기준으로 한다.

실행 흐름을 찾는 지도

먼저 실행 흐름에서 전체 코드 좌표를 잡는다. 이후 학습 영역에 따라 Threads · Scheduling · 동기화, User Kernel 경계, Virtual Memory와 Demand Paging으로 나누어 읽는다.

Virtual Memory 구현을 준비할 때는 VM 구현 준비와 PintOS VM 구현 준비를 함께 본다. 프로세스 생명주기와 VM 구조를 시각적으로 따라가려면 PintOS 프로세스 생명주기 시각화와 PintOS VM 시각화를 사용한다.

개념과 경계를 확인하는 문서

CPU 실행과 초기 커널 상태를 이해하려면 CPU 레지스터와 명령어 실행과 PintOS 초기 main thread와 커널 주소 공간을 읽는다. guest 상태와 인터럽트가 QEMU 경계에서 어떻게 드러나는지는 QEMU GDB Stub은 어떤 상태를 보여주는가와 QEMU 타이머 인터럽트에서 확인한다.

User Programs의 실행 경계는 write(1, buffer, size) 전체 흐름 Trace와 x86 64 TSS와 커널 스택 전환으로 이어서 살펴본다. 주소 변환과 VM 객체 모델, 지연 로딩의 흐름은 주소 변환과 메모리, PintOS VM 객체 모델 — struct page, frame, operations가 나누는 책임, Lazy Loading Segment 흐름를 따라간다.

메모리를 바이트 단위로 해석하는 과정은 바이트 버퍼와 캐스팅 실험에서 확인한다. 학습용 환경과 실제 운영체제의 차이를 구분할 때는 실제 OS, PintOS, QEMU의 차이를 참고한다.

문서를 읽으며 확인할 질문

각 문서는 개념의 필요성에서 시작해 구현과 하드웨어 경계로 설명을 확장해야 한다. 처음 배우는 사람에게 왜 필요한 개념인지 확인한 뒤, Linux와 Windows에서는 어떻게 다루는지 살펴본다. 이어서 PintOS에서 어떤 코드와 구조체로 구현되는지 찾고, 그 아래 하드웨어 동작이 QEMU에서 어떻게 에뮬레이션되는지 연결한다.

이 과정에서는 실제 OS와 PintOS/QEMU의 차이를 구분해야 한다. 숫자와 메모리 바이트로 표현했을 때 무엇이 계산되는지도 함께 확인한다.

다음에 넓힐 질문

  • Threads 흐름을 실제 코드 좌표로 더 촘촘히 따라가려면 어디를 봐야 하는가?
  • User Programs에서 syscall과 user pointer 검증은 어떤 실패 사례로 확인할 수 있는가?
  • VM 시각화의 각 박스는 어떤 개념 설명, 흐름 추적, 실험 문서로 나눠 읽을 수 있는가?
  • QEMU에서 guest register와 guest memory는 어떤 구조체와 파일에서 확인되는가?
