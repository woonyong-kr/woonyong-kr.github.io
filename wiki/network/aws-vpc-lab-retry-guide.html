AWS VPC 실습 재도전 가이드

VPC 실습에서는 EC2, RDS, ALB가 놓일 전용 네트워크를 만들고, public subnet과 private subnet을 route table 기준으로 나눠 본다.

VPC는 AWS 안에 만드는 내 전용 네트워크다. EC2, RDS, ALB 같은 리소스는 그냥 “AWS 어딘가”에 놓이는 것이 아니라, 특정 VPC의 특정 subnet 안에 놓인다.

이 실습의 목표는 public subnet과 private subnet을 나누고, 외부에서 들어오는 길과 내부에서 나가는 길을 분리하는 것이다. 이 구조를 이해해야 뒤의 EC2, ALB, RDS 실습이 왜 그렇게 생겼는지 보인다.

AWS VPC 실습 문제

  • VPC를 모르면
    • EC2를 만들 때 subnet을 왜 고르는지 이해할 수 없다.
    • ALB는 public subnet에 두고 웹 서버는 private subnet에 두는 이유가 흐릿하다.
    • RDS를 public으로 열지 말아야 하는 이유가 콘솔 옵션 하나처럼 보인다.
  • 실습이 끝나면 남아야 하는 판단 기준
    • public subnet과 private subnet의 차이를 route table 기준으로 구분한다.
    • internet gateway와 NAT gateway의 방향 차이를 설명한다.
    • security group과 NACL을 “인스턴스 문 앞”과 “서브넷 경계”로 나눠 본다.

VPC를 나누는 기본 구조

public subnet과 private subnet은 이름이 아니라 route table로 갈린다.

  • public subnet
    • 0.0.0.0/0 -> Internet Gateway 경로가 있다.
    • public IP를 가진 리소스가 인터넷과 직접 통신할 수 있다.
  • private subnet
    • 0.0.0.0/0 -> NAT Gateway 또는 외부 경로 없음으로 둔다.
    • 인터넷에서 직접 들어올 수 없고, 필요한 경우 내부에서 밖으로만 나간다.

실습에서 쓰는 기본 값

  • VPC
    • 이름 태그: VPC-Lab
    • CIDR: 10.0.0.0/16
    • DNS hostnames: enabled
    • DNS resolution: enabled
  • Availability Zone
    • ap-northeast-2a
    • ap-northeast-2c
  • Subnet
    • public 2a: 10.0.10.0/24
    • public 2c: 10.0.20.0/24
    • private 2a: 10.0.100.0/24
    • private 2c: 10.0.200.0/24
  • Internet Gateway
    • VPC에 attach한다.
  • NAT Gateway
    • public subnet 한 곳에 둔다.
    • Elastic IP를 붙인다.

이 값들은 외우는 숫자가 아니라 구조를 보여주는 예시다. 10.0.0.0/16이라는 큰 주소 공간을 만들고, 그 안을 /24 단위 subnet 네 개로 잘라 public 2개와 private 2개를 만든다.

실제 흐름

  • VPC 생성
    • VPC only 또는 VPC wizard에서 10.0.0.0/16 대역을 정한다.
    • DNS hostnames와 DNS resolution을 켠다.
  • Subnet 생성
    • 두 AZ에 public subnet을 하나씩 만든다.
    • 같은 두 AZ에 private subnet을 하나씩 만든다.
    • ALB와 Auto Scaling은 두 AZ를 요구하므로 subnet도 최소 두 AZ에 둔다.
  • Internet Gateway 연결
    • Internet Gateway를 만들고 VPC에 attach한다.
    • public route table에 0.0.0.0/0 -> igw-... 경로를 넣는다.
  • NAT Gateway 연결
    • public subnet에 NAT Gateway를 만들고 Elastic IP를 붙인다.
    • private route table에 0.0.0.0/0 -> nat-... 경로를 넣는다.
  • Route table association 확인
    • public subnet 2개가 public route table에 연결되어야 한다.
    • private subnet 2개가 private route table에 연결되어야 한다.

보안 경계

  • Security Group
    • 리소스 단위 방화벽이다.
    • stateful이라 inbound를 허용하면 응답 outbound는 자동으로 허용된다.
    • 예: ALB security group은 HTTP 80을 인터넷에서 받고, 웹 인스턴스 security group은 ALB security group에서 오는 HTTP만 받는다.
  • NACL
    • subnet 단위 방화벽이다.
    • stateless라 inbound와 outbound를 따로 맞춰야 한다.
    • 실습에서는 기본 NACL을 크게 건드리지 않고, security group으로 흐름을 이해하는 것이 우선이다.

AWS VPC 실습 확인

  • VPC
    • VPC 목록에서 CIDR이 10.0.0.0/16인지 본다.
  • Subnet
    • public/private subnet이 서로 다른 CIDR을 가지는지 본다.
    • 두 AZ에 분산되어 있는지 본다.
  • Route table
    • public route table에는 internet gateway 경로가 있다.
    • private route table에는 NAT gateway 경로가 있다.
  • NAT Gateway
    • 상태가 Available인지 확인한다.
    • public subnet에 있어야 한다.

자주 막히는 지점

  • “private subnet인데 인터넷으로 패키지 설치가 안 된다”
    • private route table이 NAT Gateway로 나가지 않는 경우가 많다.
    • NAT Gateway가 아직 pending 상태일 수도 있다.
  • “ALB가 EC2를 못 본다”
    • ALB는 public subnet, target EC2는 private subnet에 있어도 된다.
    • 대신 target group과 security group이 맞아야 한다.
  • “리소스가 콘솔에 안 보인다”
    • 리전이 다를 가능성이 높다.
    • 실습 전체에서 리전을 하나로 고정한다.
