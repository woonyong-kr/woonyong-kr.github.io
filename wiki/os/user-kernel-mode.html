유저 모드 / 커널 모드

유저 모드 / 커널 모드

한 줄 요약: 유저 모드(Ring 3)와 커널 모드(Ring 0)는 CPU가 CS 레지스터 하위 2비트(CPL)로 매 명령어마다 강제하는 권한 수준이다. 커널에는 syscall·인터럽트·예외라는 세 가지 하드웨어 게이트를 통해 진입한다.

유저 모드 / 커널 모드 상태

유저 프로그램이 특권 명령어를 실행하거나 커널 메모리에 접근하려 하면 CPU가 이를 차단한다. 이때 적용되는 실행 권한 수준이 유저 모드(Ring 3)와 커널 모드(Ring 0)다.

CPU는 명령어를 실행할 때마다 CS 레지스터의 하위 2비트인 CPL을 확인한다. 이를 바탕으로 현재 코드가 특권 명령어를 실행할 수 있는지, 특정 메모리 주소에 접근할 수 있는지를 판단한다. 소프트웨어만으로 이 검사를 우회할 수는 없다. 유저 모드에서 커널 모드로 진입하려면 syscall, 인터럽트, 예외라는 세 가지 하드웨어 게이트를 거쳐야 한다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

CPL이 저장되는 곳

CPL(Current Privilege Level)은 CS(Code Segment) 레지스터의 하위 2비트에 저장된다. x86-64에서는 세그먼테이션 기능 대부분이 무력화되었지만, CS의 이 2비트는 여전히 권한 게이트로 작동한다.

CPL은 mov 명령어로 직접 바꿀 수 없다. CS에는 mov cs, rax와 같은 명령으로 값을 쓸 수 없기 때문이다. CPL 전환에는 다음과 같이 정해진 명령어를 사용한다.

전환 방향허용된 명령어
User→Kernel (3→0)syscall, int n (인터럽트/예외)
Kernel→User (0→3)sysretq, iretq

명령어와 메모리 접근을 각각 검사한다

1. 명령어 실행 검사 (CPL vs 특권 명령어)

CPU는 명령어를 decode하는 단계에서 해당 명령어가 특권 명령어인지 확인한다. CPL=3인 상태에서 특권 명령어를 실행하면 gp(General Protection) 예외가 즉시 발생한다.

특권 명령어의 예로는 mov cr3, rax, wrmsr, hlt, lgdt, cli/sti, in/out이 있다. 이 목록은 하드웨어에 고정되어 있으므로 OS가 변경할 수 없다.

2. 메모리 접근 검사 (CPL vs PTE U/S bit)

MMU는 주소를 변환할 때 PTE의 User/Supervisor 비트(bit 2)를 확인한다.

CPLPTE U/S=1 (유저 페이지)PTE U/S=0 (커널 페이지)
0 (커널)접근 가능접근 가능
3 (유저)접근 가능pf 발생

이 검사는 매 메모리 접근마다 TLB를 통해 수행된다. 따라서 유저 코드가 커널 주소를 알고 있더라도 해당 메모리를 물리적으로 읽을 수 없다.

Linux는 SMAP(Supervisor Mode Access Prevention)과 SMEP(Supervisor Mode Execution Prevention)을 사용해 커널 모드에서의 유저 페이지 접근과 실행도 추가로 제한한다. PintOS는 이 기능들을 사용하지 않는다.

GDT와 세그먼트 셀렉터

x86-64에서는 세그먼테이션이 사실상 무효화되었지만 GDT(Global Descriptor Table)는 여전히 필요하다. CS의 DPL(Descriptor Privilege Level)이 CPL 전환의 기준이 되고, TSS 디스크립터가 커널 스택 주소를 제공하기 때문이다. syscall과 sysretq도 GDT 셀렉터 값을 참조한다.

각 GDT 엔트리에는 해당 세그먼트의 권한 수준을 정의하는 2-bit DPL 필드가 있다.

셀렉터 값DPL용도
0x00-NULL 디스크립터 (필수)
0x080커널 코드 (SEL_KCSEG)
0x100커널 데이터 (SEL_KDSEG)
0x1B3유저 데이터 (SEL_UDSEG)
0x233유저 코드 (SEL_UCSEG)
0x280TSS

셀렉터 값의 하위 2비트는 RPL이다. 예를 들어 0x08은 0b1000이므로 RPL=0이고, 0x23은 0b100011이므로 RPL=3이다.

실제 OS (Linux/Windows)

Linux도 같은 원리에 따라 4-엔트리 GDT 구조를 사용한다. __KERNEL_CS=0x10, __USER_CS=0x33으로 셀렉터의 순서는 PintOS와 다르다.

KPTI (Kernel Page Table Isolation): Meltdown 취약점에 대응하기 위해 유저 모드에서는 커널 페이지 대부분을 페이지 테이블에서 제거한다. 커널에 진입할 때 CR3를 교체해 전체 커널 매핑을 복원한다. 이는 PTE U/S 비트 검사에 더해 적용되는 2차 방어선이다.

SMAP/SMEP:

  • SMAP: 커널 모드에서 유저 페이지 읽기와 쓰기를 금지한다. 의도적으로 접근해야 할 때는 stac/clac으로 일시 해제한다.
  • SMEP: 커널 모드에서 유저 페이지의 코드를 실행하지 못하게 한다.

Windows도 Ring 0과 Ring 3을 사용한다. 여기에 Hyper-V 기반 VBS(Virtualization-Based Security)를 적용하면 hypervisor가 커널 자체를 감시하는 계층이 추가된다.

PintOS 구현

PintOS는 x86-64 Long Mode에서 동작하며 GDT에 5개의 유효 엔트리를 설정한다.

GDT 초기화 (gdt.c)

SEG64 매크로에서 type=0xa는 Execute/Read 코드 세그먼트를, type=0x2는 Read/Write 데이터 세그먼트를 뜻한다.

QEMU 에뮬레이션

QEMU TCG는 CPUX86State.hflags의 HF_CPL_MASK 비트를 사용해 CPL을 검사한다. 특권 명령어를 만나면 TCG가 gen_check_privilege() 헬퍼를 삽입한다. 이때 hflags & HF_CPL_MASK != 0이면 gp 예외가 발생한다.

GDB에서는 CS 값을 확인해 현재 모드를 구분할 수 있다.

(gdb) p/x $cs
$1 = 0x8      ← 커널 모드
$1 = 0x23     ← 유저 모드
