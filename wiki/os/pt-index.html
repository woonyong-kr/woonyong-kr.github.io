PT Index — 4단계 Page Table Walk의 네 번째(마지막) 단계

한 줄 요약: 가상 주소 비트 20:12는 4단계 walk의 마지막 테이블(PT)에서 엔트리를 고르는 9비트 인덱스로, 여기서 얻은 PTE가 물리 프레임 번호를 담은 최종 엔트리다.

PT Index 상태

x86-64 4단계 페이지 테이블에서 가상 주소(VA)의 비트 20:12가 PT index(Page Table index)다. 세 번째 단계에서 PD 엔트리가 가리키는 PT(Page Table) 테이블(512개 엔트리)에서 이 9비트 index로 하나의 PTE(Page Table Entry)를 선택한다. PTE는 최종 물리 프레임의 주소와 권한 비트(P, W, U, A, D 등)를 담고 있다. 여기에 VA[11:0] 12비트 offset을 더하면 최종 물리 주소가 완성된다. PT는 주소 변환의 마지막 테이블이자, page fault·COW·eviction 등 VM 핵심 메커니즘이 PTE 비트를 직접 조작하는 곳이다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

MMU가 4단계 walk을 수행할 때 마지막으로 참조하는 테이블이 PT다.

  CR3 → PML4[VA[47:39]]
       → PDPT[VA[38:30]]
       → PD[VA[29:21]]
       → PT[VA[20:12]]      ← 이 단계 (마지막)
       → 물리 프레임 + VA[11:0]

VA의 비트 필드 분해:

 63    48 47        39 38        30 29        21 20        12 11         0
+--------+-----------+-----------+-----------+-----------+-----------+
| sign   | PML4 idx  | PDPT idx  | PD idx    | PT idx    | offset    |
| extend |  9 bits   |  9 bits   |  9 bits   |  9 bits   | 12 bits   |
+--------+-----------+-----------+-----------+-----------+-----------+
                                               ^^^^^^^^^^
                                               이 문서의 범위

PT index 추출:

PT_index = (VA >> 12) & 0x1FF

PTE 하나가 가리키는 물리 프레임 크기는 2^12 = 4,096 bytes = 4 KiB다. PT 테이블 전체(512 엔트리)가 커버하는 범위는 512 × 4 KiB = 2 MiB로, 이는 상위 PDE 하나의 커버 범위와 일치한다.

PTE는 walk의 종착점이다. 상위 3단계 엔트리(PML4E, PDPTE, PDE)는 “다음 테이블의 주소”만 담지만, PTE는 “실제 물리 프레임의 주소”를 담는다. 또한 PTE의 비트들(A, D, W, U 등)이 MMU 하드웨어에 의해 자동으로 세팅되거나 OS에 의해 조작되며, 이것이 page fault, COW, eviction의 근거가 된다.

실제 OS (Linux/Windows)

Linux에서 pte_t가 PT 엔트리다. pte_offset_kernel(pmd, addr)과 pte_offset_map(pmd, addr)이 PT index 추출과 PTE 접근을 수행한다.

pte_index(addr) = (addr >> PAGE_SHIFT) & (PTRS_PER_PTE - 1)
PAGE_SHIFT = 12, PTRS_PER_PTE = 512

Linux의 VM 서브시스템은 PTE 비트를 직접 조작하는 함수를 제공한다:

  • pte_mkwrite() / pte_wrprotect() — writable 비트 on/off (COW)
  • pte_mkyoung() / pte_mkold() — accessed 비트 on/off (eviction)
  • pte_mkdirty() / pte_mkclean() — dirty 비트 on/off (writeback)

Windows의 _MMPTE 구조체가 PTE에 해당하며, MiGetPteAddress() 매크로로 VA에서 PTE 주소를 계산한다.

PintOS 구현

PintOS는 include/threads/pte.h에서 PT index를 추출하는 매크로를 정의한다:

pgdir_walk() 함수의 마지막 줄에서 PT index가 사용된다. PDE에서 PT의 물리 주소를 추출한 뒤, PTX(va) × 8로 최종 PTE의 바이트 오프셋을 계산한다:

이 한 줄이 하는 일:

  1. PTE_ADDR(pdp[idx]) — PDE에서 PT의 물리 주소 추출 (하위 12비트 플래그 제거)
  2. PTX(va) — VA에서 PT index (비트 20:12) 추출
  3. 8 * PTX(va) — 각 PTE가 8 bytes이므로 바이트 오프셋으로 변환
  4. 물리 주소에 오프셋을 더해 PTE의 물리 주소를 구함
  5. ptov() — 물리 주소를 커널 가상 주소로 변환하여 반환

반환된 포인터가 가리키는 uint64_t 값이 바로 PTE이며, 여기에 물리 프레임 주소와 P/W/U/A/D 비트가 들어 있다.

PT Index 값 추적

예시: VA = 0x0000004000401000

PML4 index = (0x4000401000 >> 39) & 0x1FF = 8
PDPT index = (0x4000401000 >> 30) & 0x1FF = 0
PD index   = (0x4000401000 >> 21) & 0x1FF = 2
PT index   = (0x4000401000 >> 12) & 0x1FF = 1    ← 이 단계
offset     = 0x4000401000 & 0xFFF            = 0x000

PT index = 1이므로, PT 테이블의 2번째 엔트리(0-based)를 참조한다. PTE 바이트 오프셋 = 1 × 8 = 8 bytes.
