가상 주소 공간 (Virtual Address Space)

가상 주소 공간 (Virtual Address Space)

한 줄 요약: 가상 주소 공간은 OS가 프로세스마다 부여하는 독립된 메모리 환상이다. 컨텍스트 스위치 때 CR3를 교체하면 같은 가상 주소도 프로세스마다 다른 물리 메모리로 변환된다.

가상 주소 공간이 프로세스를 분리하는 방식

가상 주소 공간은 OS가 각 프로세스에 제공하는 독립된 메모리 환상이다. 각 프로세스는 자신만의 0x0~최대 주소 범위를 사용하며 다른 프로세스의 메모리를 직접 볼 수 없다. CPU의 MMU는 가상 주소(VA)를 물리 주소(PA)로 변환한다. OS가 이 변환 규칙을 담은 페이지 테이블을 프로세스마다 다르게 설정하므로 프로세스 사이의 메모리가 격리된다.

CPU와 MMU가 정하는 주소 공간

x86-64의 주소 범위

이 문서에서 다루는 x86-64 모델은 48비트 가상 주소와 canonical form을 사용한다. 2^48에 해당하는 256 TB의 주소 공간은 유저 공간과 커널 공간으로 나뉘며, 그 사이에는 canonical form을 위반하는 영역이 있다.

  • 하위 절반: 0x0000_0000_0000_0000 ~ 0x0000_7FFF_FFFF_FFFF (128 TB) — 유저 공간
  • 상위 절반: 0xFFFF_8000_0000_0000 ~ 0xFFFF_FFFF_FFFF_FFFF (128 TB) — 커널 공간
  • 중간 영역: canonical form 위반 → CPU가 gp(General Protection) 예외 발생

CR3 레지스터는 프로세스의 PML4, 즉 최상위 페이지 테이블의 물리 주소를 가리킨다. 컨텍스트 스위치 때 CR3를 교체하면 CPU가 따르는 주소 변환 규칙 전체가 바뀐다. 따라서 같은 VA 0x400000도 프로세스 A와 B에서는 서로 다른 PA를 가리킬 수 있다.

하드웨어는 다음 두 조건을 통해 격리를 뒷받침한다.

  • PTE의 user/supervisor 비트가 유저 코드의 커널 페이지 접근을 차단한다.
  • 프로세스마다 별도의 페이지 테이블을 사용하므로 다른 프로세스의 메모리 매핑이 존재하지 않는다.

Linux의 일반적인 주소 공간 배치

Linux x86-64 프로세스가 보는 가상 주소 공간은 일반적으로 다음과 같이 배치된다.

ASLR(Address Space Layout Randomization)은 텍스트, 스택, mmap 베이스의 위치를 무작위로 배치해 공격을 어렵게 만든다.

PintOS가 주소 공간을 구성하는 방식

PintOS는 x86-64에서 동작하지만 48비트 주소 공간 전체를 사용하지 않고 더 단순한 배치를 사용한다.

주소 공간의 경계를 이해할 때 필요한 상수는 다음과 같다.

상수값의미
KERN_BASE0x80_0400_0000커널 영역 시작 (= LOADER_KERN_BASE)
USER_STACK0x4748_0000유저 스택 최상단
PGSIZE4096 (0x1000)페이지 크기

주소가 유저 영역과 커널 영역 중 어디에 속하는지는 다음 매크로로 판별하고 변환한다.

  • is_user_vaddr(va): va < KERN_BASE이면 유저 주소
  • is_kernel_vaddr(va): va >= KERN_BASE이면 커널 주소
  • ptov(pa): 물리 주소 → 커널 가상 주소 (pa + KERN_BASE)
  • vtop(va): 커널 가상 주소 → 물리 주소 (va - KERN_BASE)

PML4 생성과 활성화

pml4_create()는 커널 부팅 때 만든 기본 테이블인 base_pml4를 복사해 커널 매핑을 상속한다. 이때 유저 영역 매핑은 비어 있다. 이후 load()가 ELF 세그먼트를 적재하면서 유저 영역을 채운다.

프로세스가 전환될 때는 다음 코드가 실행된다.

pml4_activate(next->pml4)가 CR3를 교체해 다음 프로세스의 유저 매핑으로 전환하고, tss_update(next)가 TSS rsp0를 갱신한다.

QEMU에서 주소 변환을 관찰하는 방법

QEMU가 guest의 가상 주소 공간을 직접 정의하는 것은 아니다. 가상 주소 공간은 OS인 PintOS가 페이지 테이블로 정의한다. QEMU는 MMU 하드웨어가 수행할 page table walk를 소프트웨어로 재현한다.

Guest 코드가 VA에 접근하면 QEMU SoftMMU는 CPUX86State.cr[3]에서 시작해 4단계 walk를 수행한다. 변환 결과는 SoftTLB에 캐시하므로 같은 VA에 접근할 때마다 walk를 반복하지 않는다.

GDB에서는 다음 명령으로 현재 주소 공간을 관찰할 수 있다.

(gdb) info registers cr3               # 현재 PML4 물리 주소
(gdb) p/x ((struct thread *)$rsp)->pml4 # 현재 스레드의 PML4 VA
(gdb) x/s 0x400000                      # 유저 공간 text 영역 읽기
(gdb) x/8gx 0x4747f000                  # 유저 스택 내용
(gdb) x/4i 0x8004000000                 # 커널 코드 시작

QEMU monitor(Ctrl-A C)에서는 다음 명령으로 현재 매핑을 확인한다.

(qemu) info tlb          # 현재 TLB에 캐시된 VA→PA 매핑
(qemu) info mem          # guest의 현재 VA 매핑 테이블

주소 값으로 따라가기

PintOS에서 사용하는 가상 주소의 범위는 다음과 같다.

영역시작끝크기
유저 (PintOS)0x00x80_03FF_FFFF~32 GB
커널 (PintOS)0x80_0400_0000—물리 메모리만큼
USER_STACK 아래 성장 가능0x4748_0000 - N × PGSIZE0x4748_0000가변

유저 스택은 USER_STACK에서 낮은 주소 방향으로 성장한다.

  • 스택 최상단: 0x4748_0000
  • 첫 push 후 RSP: 0x4747_FFF8 (8바이트 감소)
  • 1페이지 사용 시 최저: 0x4747_F000 (pg_round_down)

커널 가상 주소와 물리 주소는 KERN_BASE를 더하거나 빼서 변환한다.

  • 물리 주소 0x200000 → 커널 VA: 0x200000 + 0x80_0400_0000 = 0x80_0420_0000
  • 커널 VA 0x80_0500_0000 → 물리: 0x80_0500_0000 - 0x80_0400_0000 = 0x100_0000 (16 MB)

프로세스마다 달라지는 매핑

flowchart LR
    subgraph "프로세스 A의 VA 공간"
        A1["0x400000<br/>text"] --> PA1["PA: 0x1A3000"]
        A2["0x47480000<br/>stack"] --> PA2["PA: 0x2F7000"]
    end
    subgraph "프로세스 B의 VA 공간"
        B1["0x400000<br/>text"] --> PB1["PA: 0x8C1000"]
        B2["0x47480000<br/>stack"] --> PB2["PA: 0x5D2000"]
    end
    subgraph "커널 공간 (공유)"
        K1["0x8004000000+<br/>커널 코드"] --> PK["PA: 0x0+"]
    end

프로세스 A와 B가 같은 VA 0x400000을 사용해도 각자의 페이지 테이블에 따라 서로 다른 PA로 변환된다. 반면 커널 공간은 pml4_create()가 base_pml4를 복사하므로 모든 프로세스에서 같은 매핑을 공유한다.

프로세스 주소 공간의 생명주기

flowchart TD
    A["pml4_create()"] -->|"memcpy(base_pml4)"| B["빈 유저 영역\n+ 커널 매핑 상속"]
    B --> C["load_segment()\nELF PT_LOAD → VA 매핑\n(text: 0x400000+)"]
    C --> D["setup_stack()\nUSER_STACK 아래 1페이지 매핑\n(0x4747F000)"]
    D --> E["argument_passing()\nargv/argc 스택에 배치"]
    E --> F["do_iret()\nRIP=e_entry, RSP=USER_STACK\nCPU가 유저 VA에서 fetch 시작"]
    F --> G["실행 중\nstack growth, mmap으로\nVA 매핑 동적 추가"]
    G --> H["process_exit()\nprocess_cleanup()"]
    H --> I["pml4_activate(NULL)\nCR3 → base_pml4"]
    I --> J["pml4_destroy()\n유저 하위 테이블 재귀 해제"]

프로세스의 PML4는 커널 매핑을 상속한 상태로 생성된다. 여기에 ELF 세그먼트와 초기 스택을 매핑한 뒤 유저 코드를 실행한다. 실행 중에는 stack growth와 mmap으로 매핑이 추가될 수 있다. 프로세스가 종료되면 CR3를 base_pml4로 바꾼 다음 유저 영역의 페이지 테이블을 해제한다.
