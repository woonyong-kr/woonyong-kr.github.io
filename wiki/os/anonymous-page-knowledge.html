익명 페이지 — 파일 없이 태어나는 메모리

익명 페이지 — 파일 없이 태어나는 메모리

한 줄 요약: Anonymous page는 디스크 파일에 대응하지 않는 가상 메모리 페이지다. 스택, 힙, BSS가 여기에 속한다.

익명 페이지 필요성

프로그램이 사용하는 메모리가 전부 파일에서 오는 것은 아니다. ELF 실행 파일의 .text나 .data 섹션은 디스크 파일에서 읽어오므로, 메모리에서 쫓겨날 때 원본 파일에 다시 쓰거나 버리면 된다. 그런데 스택에 쌓인 지역 변수, malloc()으로 잡은 힙 영역, 0으로 초기화되는 BSS 영역은 어떤 파일에서도 오지 않는다. 이런 페이지를 **익명 페이지(anonymous page)**라 부른다.

익명 페이지가 별도로 구분되어야 하는 이유는 eviction 정책이 다르기 때문이다. file-backed page는 쫓겨날 때 원본 파일에 쓰거나(dirty), 그냥 버리면(clean) 된다. 익명 페이지는 원본이 없으므로, 내용을 보존하려면 swap 디스크라는 별도 공간에 저장해야 한다.

이 개념을 모르면 “왜 swap이 필요한지”, “왜 page type을 나누는지”를 이해할 수 없다.

익명 페이지 흐름

비유

도서관 책(file-backed page)은 빌려온 곳이 있으니 반납하면 끝이다. 하지만 내가 메모장에 직접 쓴 노트(anonymous page)는 반납할 곳이 없다. 보관하려면 별도 사물함(swap slot)에 넣어야 한다.

정의

익명 페이지는 어떤 파일 시스템 객체에도 매핑되지 않은 가상 메모리 페이지다. “anonymous”라는 이름은 “이름 없는(backing file이 없는)“이라는 뜻이다.

어디에 쓰이나

  • 스택: 함수 호출마다 쌓이는 지역 변수, 리턴 주소
  • 힙: malloc() / calloc()으로 동적 할당한 영역
  • BSS: 초기값이 0인 전역/정적 변수. ELF에 데이터가 없으므로 로더가 0으로 채운다

익명 페이지 vs file-backed 페이지

  • 익명 페이지 (Anonymous)
    • backing store: 없음 (swap 디스크 사용)
    • 생성 시점: 스택/힙 확장, BSS 로드
    • eviction: swap 디스크에 쓰기
    • 대표 예: 스택, 힙, BSS
  • file-backed 페이지
    • backing store: 디스크 파일
    • 생성 시점: mmap(), ELF .text/.data 로드
    • eviction: dirty면 파일에 쓰기, clean이면 버림
    • 대표 예: 코드 세그먼트, mmap 영역

생애 주기

익명 페이지는 다음 순서로 살아간다.

  1. 등록 — vm_alloc_page(VM_ANON, va, writable) 호출. SPT에 UNINIT 상태로 등록된다. 이 시점에 물리 프레임은 없다.
  2. 최초 fault — 해당 가상 주소에 처음 접근하면 page fault 발생. vm_do_claim_page()가 프레임을 할당하고, anon_initializer()가 page->operations를 anon_ops로 설정한다.
  3. 사용 — 프레임에 매핑되어 정상적으로 읽기/쓰기 가능.
  4. eviction — 메모리 부족 시 anon_swap_out()이 프레임 내용을 swap 디스크에 저장. PTE에서 present 비트 제거.
  5. 재접근 — 다시 접근하면 page fault → anon_swap_in()이 swap에서 복원.
  6. 소멸 — 프로세스 종료 시 anon_destroy()가 swap slot 참조를 해제.

flowchart LR
  register["등록(UNINIT)<br/>SPT 등록<br/>frame 없음<br/>VM_UNINIT"]
  first_fault["최초 fault<br/>프레임 할당<br/>anon_ops"]
  active["사용 중<br/>정상 읽기/쓰기"]
  eviction["eviction<br/>swap out<br/>PTE 해제<br/>swap_idx"]
  revisit["재접근<br/>swap in<br/>프레임 재할당"]
  register --> first_fault
  first_fault --> active
  active --> eviction
  eviction --> revisit

Linux와 PintOS의 차이

Linux에서 익명 페이지는 vm_area_struct에 vm_file == NULL로 표현된다. mmap(MAP_ANONYMOUS)로 명시적으로 만들 수도 있고, brk()/sbrk()로 힙을 확장할 때도 생긴다. eviction 시 swap 파티션이나 swap 파일의 slot에 저장하며, PTE에 swap entry(디바이스 번호 + slot 번호)를 인코딩한다.

PintOS는 이를 단순화했다. struct page의 union 안에 struct anon_page가 들어가고, page->operations를 anon_ops로 설정하는 것으로 타입을 구분한다. swap 디스크는 QEMU의 두 번째 IDE slave 디스크(disk_get(1,1))를 사용하며, bitmap으로 slot을 관리한다.

익명 페이지 코드

구조체 정의

struct page의 union 안에 들어간다. page->anon으로 접근한다. swap_idx와 swapped 두 필드만으로 상태를 추적한다.

초기화 — anon_initializer()

최초 page fault 시 uninit_initialize()가 이 함수를 호출한다. page->operations를 anon_ops로 설정하면, 이후 swap_in(), swap_out(), destroy() 매크로가 anonymous 전용 함수를 호출하게 된다.

등록 — vm_alloc_page 매크로

스택 확장이나 load_segment()에서 vm_alloc_page(VM_ANON, va, true)를 호출하면, 내부적으로 vm_alloc_page_with_initializer()가 SPT에 UNINIT 페이지를 등록한다. 이때 init과 aux는 NULL이다. 나중에 page fault가 발생하면 anon_initializer()가 불려서 진짜 anonymous page가 된다.

함수 테이블 — anon_ops

PintOS의 VM은 C로 다형성을 구현한다. page->operations에 함수 포인터 테이블을 넣고, swap_in(page, kva) 매크로가 page->operations->swap_in(page, kva)를 호출한다. anonymous page, file-backed page, uninit page가 각각 자기만의 ops를 가진다.

swap slot 참조 카운팅 (COW 지원)

COW fork를 하면 부모와 자식이 같은 swap slot을 가리킬 수 있다. swap_ref_count로 참조 수를 추적하여, 마지막 소유자가 swap_in하거나 destroy할 때만 slot을 해제한다. anon_copy()에서 swap 상태의 페이지를 복사할 때 swap_slot_ref()를 호출하여 참조를 증가시킨다.

타입 판별 흐름

%% 익명 페이지 타입 판별 흐름
flowchart TD
  alloc["vm_alloc_page(VM_ANON)"]
  register_uninit["vm_alloc_page_with_initializer()<br/>type=VM_ANON<br/>SPT에 UNINIT 등록<br/>uninit.init = anon_initializer"]
  initialize["uninit_initialize()<br/>프레임 할당<br/>anon_initializer() 호출<br/>operations = anon_ops"]
  alloc --> register_uninit
  register_uninit -->|page fault 발생| initialize

UNINIT 상태일 때 page->uninit.type에 VM_ANON이 저장되어 있다. page fault가 발생하면 uninit_initialize()가 이 타입을 보고 anon_initializer()를 호출한다. 이 시점부터 page->operations가 anon_ops를 가리키므로 진짜 anonymous page로 동작한다.

정리

익명 페이지는 파일에 대응하지 않는 가상 메모리 페이지다. 스택, 힙, BSS가 대표적이며, eviction 시 swap 디스크를 사용한다는 점이 file-backed 페이지와 근본적으로 다르다.

PintOS에서 struct anon_page는 swap_idx와 swapped 두 필드로 swap 상태를 추적하고, anon_ops 함수 테이블로 swap in/out/destroy/copy를 다형적으로 처리한다. 모든 anonymous page는 처음에 UNINIT 상태로 등록되고, 최초 page fault 때 anon_initializer()가 호출되어 비로소 anonymous page가 된다.
