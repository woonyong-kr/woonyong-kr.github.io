페이지 오프셋 12비트

페이지 오프셋 12비트

한 줄 요약: 가상 주소 하위 12비트는 4 KiB 페이지 안의 바이트 위치(page offset)로, page table walk에 쓰이지 않고 최종 물리 프레임 번호 뒤에 그대로 붙어 물리 주소를 완성한다.

페이지 오프셋 12비트 상태

x86-64 가상 주소의 하위 12비트(bit [11:0])는 page offset으로, 4 KiB 페이지 안에서의 바이트 위치를 가리킨다. 4단계 page table walk(PML4 → PDPT → PD → PT)는 물리 프레임의 시작 주소만 결정하고, 이 12비트 offset은 변환 없이 그대로 물리 주소에 붙는다. 이것이 주소 변환의 마지막 조각이다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 가상 주소 48비트의 구조:

%% x86-64 가상 주소의 페이지 오프셋 12비트
flowchart TD
  address["47..39 &#124; 38..30 &#124; 29..21 &#124; 20..12 &#124; 11..0<br/>PML4 idx<br/>9 bits &#124; PDPT idx<br/>9 bits &#124; PD idx<br/>9 bits &#124; PT idx<br/>9 bits &#124; Page Offset<br/>12 bits"]

MMU는 상위 36비트(bit [47:12])를 사용하여 4단계 테이블을 워크하고 최종 PTE에서 물리 프레임 번호(PFN)를 얻는다. 물리 주소는 다음과 같이 구성된다:

물리 주소 = (PTE의 PFN × 4096) + page offset
         = (PTE & 0x000FFFFF_FFFFF000) | (VA & 0xFFF)

12비트이므로 표현 범위는 04095(0x0000xFFF), 정확히 4096 = 4 KiB 크기의 페이지 하나를 커버한다.

핵심 성질: page offset은 변환 과정에서 절대 바뀌지 않는다. 가상 주소와 물리 주소의 하위 12비트는 항상 동일하다. 이 때문에:

  • 한 페이지 내의 모든 바이트가 같은 PTE를 공유한다
  • TLB는 VPN→PFN 매핑만 캐시하면 된다 (12비트 offset 불필요)

Linux arch/x86/include/asm/page_types.h:

PAGE_MASK로 하위 12비트를 제거하면 페이지 시작 주소, ~PAGE_MASK(= 0xFFF)로 마스크하면 offset을 얻는다. Huge page(2 MiB)에서는 하위 21비트가 offset이 되고(PD 단계에서 PS bit=1로 walk 종료), 1 GiB page에서는 30비트가 offset이다(PDPT 단계에서 종료).

PintOS 구현

include/threads/vaddr.h에 관련 매크로가 정의되어 있다:

사용 예 1: 버퍼 경계 계산 (userprog/syscall.c)

현재 user 포인터의 offset이 0x300이면 chunk = 4096 - 768 = 3328 바이트까지만 이 페이지에서 접근 가능하다.

사용 예 2: page fault 처리 (vm/vm.c)

fault_addr이 0x401234이면 pg_round_down → 0x401000으로 정렬, SPT는 페이지 단위로 관리되므로 정렬된 주소로 검색한다.

사용 예 3: thread_current() (threads/thread.c)

RSP를 pg_round_down으로 4 KiB 정렬하면 현재 스레드의 struct thread 시작 주소를 O(1)로 얻는다. 이는 커널 스택이 항상 4 KiB 페이지의 상단에 위치하고 struct thread가 같은 페이지의 시작에 놓이기 때문이다. 12비트 마스킹만으로 스레드를 식별하는 트릭이다.

사용 예 4: stack growth 판단 (vm/vm.c)

fault 주소도 page base로 정규화해 현재 stack page 또는 바로 아래 성장 후보인지 비교한다. 실제 허용 여부에는 user range, RSP 근접성, 최대 stack 크기 정책도 함께 적용한다.

QEMU 에뮬레이션

QEMU TCG(softmmu) 관점에서 page offset 12비트는 하드웨어와 동일하게 처리된다.

TCG 주소 변환 경로: PintOS가 메모리에 접근하면 TCG는 mmu_translate()를 호출한다. 이 함수는 가상 주소의 상위 비트(VPN)로 TLB를 검색하고, TLB miss 시 page table walk를 수행하여 PFN을 구한다. 하위 12비트는 TLB에 저장되지 않으며, PFN에 직접 OR된다:

addend 필드가 핵심이다. host_addr = addend + guest_va이므로, guest VA의 하위 12비트가 그대로 host 메모리 주소에 반영된다. 4단계 walk 결과와 12비트 offset을 분리/합성하는 과정이 실제 CPU와 동일하다.

페이지 오프셋 12비트 값 추적

가상 주소 0x0000_0000_4001_A03C의 분해:

전체 48비트: 0000 0000 0000 0000 0100 0000 0000 0001 1010 0000 0011 1100

비트 분해:
  PML4 [47:39] = 000000000 = 0
  PDPT [38:30] = 000000001 = 1
  PD   [29:21] = 000000000 = 0
  PT   [20:12] = 000011010 = 26  (0x1A)
  Offset[11:0] = 001111001100 = 0x3C = 60

pg_ofs(0x4001A03C) = 0x4001A03C & 0xFFF = 0x3C  (60번째 바이트)
pg_no(0x4001A03C)  = 0x4001A03C >> 12   = 0x4001A
pg_round_down(0x4001A03C) = 0x4001A03C & ~0xFFF = 0x4001A000

PTE에서 PFN이 0x12345라면:

물리 주소 = 0x12345000 | 0x3C = 0x1234503C
          ↑ PFN × 4096        ↑ page offset (동일)
