세마포어 down 블록 (Sema Down Block)

세마포어 down 블록 (Sema Down Block)

확인 범위: 이 문서는 세마포어 down 연산의 블로킹 원리와 구현 선택 기준을 설명하며, Linux·PintOS·QEMU 관련 코드 경로와 동작은 입력에 제시된 특정 구현을 전제로 한 설명이다. 코드 좌표, 버전별 세부 동작, 실행 흐름, 우선순위 처리, 명령어·구조체 크기·시간·성능 수치는 실제 소스 버전과 빌드 환경, 실행 기록 및 측정을 통해 별도로 검증해야 한다.

sema_down()은 세마포어 값이 0이면 현재 스레드를 waiters에 넣고 thread_block()으로 재운다. 값이 생길 때까지 CPU를 쓰지 않는 대기다.

언제 CPU를 놓고 기다리나

세마포어 값은 남은 자리 수다. 값이 1 이상이면 sema_down()은 그 자리 하나를 가져가며 value--로 바로 통과한다. 문제는 value == 0일 때다. 이 상태에서 계속 반복 검사만 하면 CPU 시간을 태우지만, 실제로는 다른 스레드가 sema_up()을 호출해야 상황이 바뀐다.

그래서 sema_down()은 현재 스레드의 elem을 waiters에 넣고, 상태를 BLOCKED로 바꾼 뒤 schedule()을 통해 CPU를 내려놓는다. 나중에 sema_up()이 대기 스레드를 READY로 깨우면, 깨어난 스레드는 while 조건을 다시 확인하고 value--로 자리를 소비한다. 이 검사-대기-감소 묶음은 intr_disable() 안에서 실행되어 중간 상태가 끼어들지 못하게 한다.

블록킹 동기화의 기본 모양

Blocking synchronization은 보통 다음 흐름을 따른다.

세마포어의 down 연산은 이 패턴의 가장 기본적인 인스턴스다. 조건은 value > 0이고, 자원 획득은 value--다.

Busy-wait와의 차이: sema_try_down()을 반복 호출하면 CPU 사이클을 낭비한다. sema_down()은 조건이 만족될 때까지 CPU를 놓으므로, 대기 시간이 context switch 비용(~수 μs)보다 긴 경우에 효율적이다.

QEMU 에뮬레이션

QEMU TCG 관점에서 sema_down()은 일반 C 코드일 뿐이다. TCG가 특별히 인식하는 것은 없지만, 관찰 가능한 동작이 있다.

cli/sti 명령어 변환: intr_disable()의 cli 명령이 TCG에서 gen_helper_cli로 번역되어 CPUX86State.eflags의 IF 비트를 클리어한다. 이 상태에서는 QEMU가 타이머 인터럽트를 보류(pending)하므로, sema_down() 내부의 조건 검사와 waiters 삽입이 원자적으로 실행된다.

QEMU는 PintOS의 스레드 개념을 모르므로, BLOCKED 스레드를 찾으려면 PintOS의 all_list를 수동으로 순회해야 한다. list_entry 매크로의 offset 계산이 필요하다.

TCG 최적화 영향: while (sema->value == 0) 루프는 실제로 한 번만 실행되고 thread_block()에서 CPU를 놓는다. TCG Translation Block은 이 루프를 포함하는 코드를 캐시하지만, 깨어난 후 재진입 시 TB cache hit가 발생하여 재번역 비용이 없다.

핵심 설계 결정

1. while loop (if가 아닌 이유)

sema_up()이 먼저 value++를 하고 thread_unblock()을 호출한다. 하지만 깨어난 스레드가 실행되기 전에 더 높은 우선순위의 스레드가 먼저 sema_down()을 성공할 수 있다. while로 재검사하면 이 race를 안전하게 처리한다.

2. 우선순위 정렬 삽입

원본 PintOS는 list_push_back()(FIFO)이었으나, priority scheduling 구현 시 list_insert_ordered()로 변경했다. 이렇게 하면 sema_up()에서 list_pop_front()만으로 최고 우선순위 스레드를 깨울 수 있다.

3. intr_context() 검사

인터럽트 핸들러 내에서는 thread_block()을 호출할 수 없다 (CPU를 양보하면 ISR이 미완료 상태로 남음). 대신 sema_try_down()을 사용해야 한다.
