IDE 컨트롤러 모델

IDE 컨트롤러 모델

한 줄 요약: CPU가 I/O 포트로 명령·섹터 번호를 보내 디스크를 읽고 쓰게 하는 IDE(ATA) 컨트롤러 인터페이스.

IDE 컨트롤러 모델 구조

IDE(Integrated Drive Electronics, ATA라고도 함)는 CPU가 디스크에 데이터를 읽고 쓸 수 있게 하는 컨트롤러 인터페이스다. CPU는 I/O 포트를 통해 명령과 섹터 번호를 보내고, 컨트롤러가 디스크에서 데이터를 준비하면 인터럽트로 완료를 알린다. PintOS에서는 OS 커널, 파일 시스템, scratch, swap의 4개 디스크가 이 인터페이스를 통해 연결되며, QEMU가 IDE 컨트롤러를 소프트웨어로 에뮬레이션한다.

상세 설명

추상 개념 (하드웨어 규칙)

IDE/ATA 컨트롤러는 레거시 PC에서 표준 2개 채널을 제공한다. 각 채널은 master/slave 2개 장치를 제어할 수 있어 총 4개 디스크를 연결한다.

CPU ↔ IDE 통신은 PIO(Programmed I/O) 모드로 이루어진다:

  1. CPU가 I/O 포트에 섹터 번호와 명령을 쓴다
  2. 컨트롤러가 디스크에서 데이터를 준비한다
  3. 준비가 끝나면 IRQ(인터럽트)를 발생시킨다
  4. CPU가 데이터 포트에서 512바이트를 읽는다 (또는 쓴다)

ATA 명령 블록 레지스터는 채널의 base I/O port로부터 오프셋으로 접근한다:

오프셋레지스터읽기/쓰기역할
+0DataR/W16비트 데이터 전송
+1Error / FeaturesR / W오류 코드 / 기능 설정
+2Sector CountR/W전송할 섹터 수
+3LBA LowR/WLBA 비트 0:7
+4LBA MidR/WLBA 비트 15:8
+5LBA HighR/WLBA 비트 23:16
+6DeviceR/WLBA 27:24 + 장치 선택
+7Status / CommandR / W상태 읽기 / 명령 쓰기
+0x206Alt Status / ControlR / W보조 상태 / 제어

실제 OS (Linux)

Linux의 drivers/ata/ 서브시스템은 libata 프레임워크 위에 구축되어 있다. 레거시 IDE는 piix.c, ata_piix.c 등이 담당하며, DMA 모드를 기본으로 사용한다. PIO 모드는 DMA 초기화 실패 시 fallback으로만 사용된다. AHCI(Advanced Host Controller Interface)가 레거시 IDE를 대체했지만, QEMU 기본 설정은 여전히 레거시 IDE를 에뮬레이션한다.

PintOS 구현

PintOS의 devices/disk.c는 순수 PIO 모드 IDE 드라이버를 구현한다.

채널과 장치 구조:

채널 할당 (PintOS 관례):

채널:장치이름I/O BaseIRQ용도
0:0hd0:00x1F014 (vec 0x2E)부트 + 커널
0:1hd0:10x1F014 (vec 0x2E)파일 시스템
1:0hd1:00x17015 (vec 0x2F)scratch
1:1hd1:10x17015 (vec 0x2F)swap

같은 채널의 두 장치는 I/O base와 IRQ를 공유하므로, Device 레지스터의 DEV 비트로 선택한다.

읽기 흐름 (disk_read):

%% disk_read 호출 흐름
flowchart TD
  lock["채널 잠금<br/>lock_acquire(&amp;c-&gt;lock)<br/>같은 IDE 채널 접근 직렬화"]
  select_sector["섹터 선택<br/>select_sector(d, sec_no)"]
  command["PIO 읽기 명령<br/>issue_pio_command(c, CMD_READ_SECTOR_RETRY)"]
  wait_irq["IRQ 완료 대기<br/>sema_down(&amp;c-&gt;completion_wait)<br/>IDE IRQ가 오면 interrupt_handler()가 sema_up()"]
  transfer["데이터 수신<br/>wait_while_busy(d)<br/>input_sector(c, buffer)"]
  unlock["채널 해제<br/>lock_release(&amp;c-&gt;lock)"]
  lock --> select_sector
  select_sector --> command
  command --> wait_irq
  wait_irq --> transfer
  transfer --> unlock

현재 PintOS disk_read()의 코드 수준 경계는 다음과 같다.

  1. lock_acquire(&c->lock)으로 같은 채널의 master/slave 접근을 직렬화한다.
  2. select_sector(d, sec_no)가 먼저 select_device_wait(d)를 호출한다. 이 함수는 장치 선택 전후에 wait_until_idle(d)로 BSY와 DRQ가 내려갈 때까지 기다린다.
  3. 이어서 sector count를 1로 쓰고 LBA 하위·중간·상위 바이트와 device/LBA/상위 4비트를 각 ATA 레지스터에 outb한다.
  4. issue_pio_command(c, CMD_READ_SECTOR_RETRY)가 expecting_interrupt = true로 설정한 뒤 command 0x20을 기록한다.
  5. sema_down(&c->completion_wait)으로 IRQ 완료를 기다린다.
  6. wait_while_busy(d)가 실패하면 해당 sector를 포함해 PANIC한다.
  7. input_sector(c, buffer)가 insw(..., DISK_SECTOR_SIZE / 2)로 16-bit word 256개, 즉 512 B를 읽는다.
  8. d->read_cnt++ 후 채널 lock을 해제한다.

IRQ 핸들러:

동기화 패턴: lock은 같은 채널의 두 장치 간 직렬화, semaphore는 명령 발행 → IRQ 완료 대기를 구현한다. 인터럽트가 켜진 상태(INTR_ON)에서만 PIO 명령을 발행할 수 있다.

QEMU 에뮬레이션

QEMU의 hw/ide/core.c가 IDE 컨트롤러를 에뮬레이션한다. PintOS가 I/O 포트 0x1F0에 outb를 하면, QEMU가 이를 가로채 내부 IDEState 구조체를 갱신하고, 호스트 파일에서 데이터를 읽어 데이터 레지스터에 채운다. IRQ 발생도 QEMU가 가상 PIC(i8259)에 신호를 보내는 것으로 구현한다.

-drive file=disk.img,format=raw,if=ide 옵션으로 호스트 파일을 IDE 장치로 연결한다.

IDE 컨트롤러 모델 값 추적

섹터 크기 = 512 바이트 (DISK_SECTOR_SIZE)
1 page = 4096 바이트 = 8 섹터

swap 디스크 (hd1:1)에서 page 5를 읽으려면:
  시작 섹터 = 5 × 8 = 40
  disk_read(swap_disk, 40, buf)   → 섹터 40
  disk_read(swap_disk, 41, buf+512) → 섹터 41
  ... (8회 반복)

LBA 28비트 → 최대 2^28 섹터 = 256M 섹터 × 512B = 128 GB
PintOS 디스크는 수 MB 수준이므로 충분하다.

채널 0 IRQ = 14 → 벡터 번호 = 14 + 0x20 = 0x2E (46)
채널 1 IRQ = 15 → 벡터 번호 = 15 + 0x20 = 0x2F (47)

flowchart LR
