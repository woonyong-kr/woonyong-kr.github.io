struct intr_frame 레이아웃

struct intr_frame 레이아웃

확인 범위: 이 문서는 x86-64 인터럽트·예외의 일반적인 상태 저장·복원 원리를 바탕으로 PintOS의 struct intr_frame 레이아웃과 사용 흐름을 설명한다. 구체적인 크기·오프셋·파일 위치와 Linux·Windows·QEMU 관련 내용은 특정 구현과 코드에 의존하므로, 실제 적용 여부는 대상 소스와 버전 및 GDB 실행 결과로 별도 검증해야 한다.

한 줄 요약: struct intr_frame은 인터럽트·예외 발생 시 중단된 실행 상태를 스택에 저장하는 스냅샷 구조체로, 핸들러 진입·syscall·context switch·do_iret 복원까지 모든 실행 상태 전환의 공통 매개체다.

struct intr_frame 레이아웃 구조

struct intr_frame은 인터럽트나 예외가 발생했을 때 중단된 실행 상태를 스택에 저장하는 스냅샷 구조체다. 이 구조체 하나로 interrupt handler 진입, syscall 처리, context switch, do_iret() 복원까지 모든 실행 상태 전환이 이루어진다. OS에서 가장 자주 등장하는 데이터 구조 중 하나이며, 이 레이아웃을 정확히 이해해야 register 저장/복원, 권한 전환, 스택 전환의 원리를 파악할 수 있다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 CPU는 인터럽트나 예외가 발생하면 하드웨어가 자동으로 다음 5개 값을 현재 스택(또는 IST/TSS가 지정한 커널 스택)에 push한다:

handler 관점에서는 이후 intrNN_stub과 intr_entry가 vec_no, segment register, general-purpose register를 더 쌓는다. 그래서 PintOS의 struct intr_frame은 CPU가 자동 push한 꼬리와 stub이 보강한 앞부분이 합쳐진 snapshot이다. 핵심 규칙은 다음과 같다:

  • 권한 전환(CPL 3→0)이 일어나면 SS와 RSP는 TSS의 rsp0에서 가져온 커널 스택으로 교체된다.
  • 같은 권한(CPL 0→0)이면 SS/RSP는 현재 스택을 그대로 쓴다.
  • error code는 CPU가 push하는 예외(#PF=0x0E, gp=0x0D 등)에서만 존재한다. 나머지는 소프트웨어가 0을 push해 일관성을 맞춘다.

실제 OS (Linux/Windows)

Linux의 struct pt_regs가 PintOS의 struct intr_frame에 해당한다. Linux는 arch/x86/include/asm/ptrace.h에 정의되며, 레이아웃은 거의 동일하지만 segment register 패딩 방식이 다르다. SAVE_REGS/RESTORE_REGS 매크로로 entry_64.S에서 저장/복원한다.

Windows는 KTRAP_FRAME 구조체가 같은 역할을 한다.

PintOS의 struct intr_frame은 include/threads/interrupt.h에 정의된다. 메모리 레이아웃(낮은 주소 → 높은 주소)은 다음과 같다:

읽는 법:

  • struct gp_registers R는 0x00부터 0x77까지 15개 uint64_t register를 담는다.
  • intr_handler(struct intr_frame *f)가 받는 f는 위 그림의 0x00, 즉 R.r15 위치를 가리킨다.
  • do_iret / iretq가 마지막에 복원하는 값은 CPU가 만든 꼬리(rip, cs, eflags, rsp, ss)다. 저장 순서는 스택에 push되는 역순(높은 오프셋이 먼저 push)이므로, 메모리에서는 R.r15가 가장 낮은 주소에 위치한다.

저장 과정 (intr-stubs.S)

  1. CPU가 EFLAGS, CS, RIP를 push하고, CPL 3→0처럼 권한이 바뀔 때만 old SS와 old RSP도 push한다. 이때 TSS의 rsp0 스택을 사용한다.
  2. CPU가 error_code를 push (해당 예외만)
  3. intrNN_stub이 error code가 없는 경우 pushq $0으로 보정, 이후 push $vec_no
  4. intr_entry로 점프
  5. intr_entry가 ds, es를 저장하고 subq $120, %rsp로 공간 확보 후 범용 레지스터 15개를 저장한다. 이어 SEL_KDSEG를 ds, es, ss, fs, gs에 설정한 뒤 C handler를 호출한다.
  6. %rsp를 %rdi에 넣어 intr_handler(struct intr_frame *f)의 인자로 전달

복원 과정

intr_entry의 후반부에서 역순으로 복원:

  1. 범용 레지스터 15개 복원
  2. ds, es 복원
  3. addq $32, %rsp로 16-byte segment 저장 슬롯(es, ds)과 16-byte vec_no + error_code를 함께 건너뜀
  4. iretq가 RIP, CS, EFLAGS를 복원하고, privilege level이 바뀌는 복귀에서만 RSP와 SS도 복원

error code를 push하는 예외 벡터

CPU가 error code를 자동으로 push하는 예외는 정해져 있다. intr-stubs.S에서 REAL 매크로로 구분한다:

벡터이름error code
0x08df (Double Fault)항상 0
0x0Ats (Invalid TSS)selector index
0x0Bnp (Segment Not Present)selector index
0x0Dgp (General Protection)selector 또는 0
0x0Epf (Page Fault)P|W|U 비트 조합

나머지 ~249개 벡터는 zero 매크로로 pushq $0을 삽입하여 구조체 레이아웃을 일관되게 맞춘다.

thread 구조체 안에서의 위치

struct thread의 tf 멤버가 struct intr_frame이다. thread_launch()에서 현재 스레드의 tf에 레지스터를 저장하고, 다음 스레드의 tf로 do_iret()를 호출해 복원한다.

QEMU 에뮬레이션

QEMU TCG는 do_interrupt_64() (target/i386/seg_helper.c)에서 x86-64 인터럽트 진입을 에뮬레이션한다. 하드웨어가 하는 5개 값 push(SS, RSP, RFLAGS, CS, RIP)를 CPUX86State의 레지스터를 읽어 guest 메모리에 순서대로 기록한다.

GDB stub에서 info registers로 보는 값은 CPUX86State에서 읽는 것이므로, intr_frame에 저장된 값과 CPUX86State 값은 intr_entry 직후에는 다를 수 있다. intr_frame에는 중단된 실행 상태가 들어 있고, CPUX86State에는 현재 실행 상태가 들어 있기 때문이다.

GDB에서 intr_frame 내용 확인:

(gdb) p/x *(struct intr_frame *)$rdi

$rdi는 intr_handler의 첫 번째 인자이므로, handler 진입 직후에 이 명령으로 중단된 실행 상태 전체를 볼 수 있다.

  stub["intrNN_stub<br/>pushq $0 보정 또는 skip<br/>push $vec_no"]
  entry_save["intr_entry 저장<br/>subq $16, %rsp<br/>subq $120, %rsp<br/>R.r15부터 R.rax 저장"]
  entry_restore["intr_entry 복원<br/>general-purpose register 복원<br/>segment register 복원<br/>addq $32, %rsp"]
  iret["iretq<br/>rip, cs, eflags 복원<br/>권한 전환 복귀 시 rsp, ss 추가 복원"]
  handler["handler"]
  cpu -->|"IDT vector 진입"| stub
  stub -->|"jmp intr_entry"| entry_save

  handler -->|"return"| entry_restore
  entry_restore -->|"CPU 꼬리 영역"| iret

시간 순서로 보면 struct intr_frame은 CPU hardware, intrNN_stub, intr_entry가 차례로 같은 스택 위에 덧붙여 완성한 구조다.

  1. CPU hardware는 interrupt/exception 순간 eflags, cs, rip 꼬리 영역을 먼저 만든다. privilege level이 바뀔 때만 old ss, rsp가 추가되며, 일부 exception에서는 error_code도 CPU가 push한다.
  2. intrNN_stub은 CPU가 error_code를 만들지 않는 vector에서 pushq $0으로 보정하고, 모든 vector에서 push $vec_no를 수행한 뒤 jmp intr_entry로 공통 진입 코드에 합류한다.
  3. intr_entry는 subq $16, %rsp로 es, ds 저장 공간을 만들고, subq $120, %rsp로 struct gp_registers R 영역을 만든 뒤 R.r15부터 R.rax까지 15개 general-purpose register를 저장한다.

최종 메모리에서는 R.r15부터 R.rax가 나중에 저장됐지만 가장 낮은 주소에 놓인다. 복원할 때는 intr_entry 후반부가 general-purpose register와 segment register를 먼저 복원하고, addq $32, %rsp로 segment 저장 슬롯과 vec_no·error_code를 건너뛴다. 마지막 iretq는 rip, cs, eflags를 복원하며 privilege level 전환 복귀에서만 rsp, ss까지 소비한다. struct intr_frame의 rsp·ss 필드는 same-CPL hardware interrupt에서는 CPU가 만든 유효 필드라고 가정하지 않는다.
