ready_list — 우선순위 정렬

확인 범위: 이 문서는 정렬된 ready_list를 사용하는 우선순위 스케줄링의 일반 원리와 자료구조 선택 기준을 설명하고, 제시된 PintOS·Linux·Windows 구현 정보는 개념 비교를 위한 사례로 다룬다. 코드 위치, 버전별 세부 동작, QEMU·GDB 실행 기록, 시간·성능 관련 수치는 해당 소스와 실행 환경에서 별도로 검증해야 한다.

ready_list는 CPU를 받을 준비가 끝난 스레드들의 줄이다. PintOS는 이 줄을 우선순위 내림차순으로 유지해서, 다음 스레드를 고를 때 리스트 앞만 꺼내면 되게 만든다.

왜 ready_list를 정렬해 두나

스케줄러는 매번 “지금 실행 가능한 스레드 중 누가 가장 급한가”를 골라야 한다. 그 판단을 스케줄 시점마다 전체 리스트를 훑어 처리하면 선택 비용이 커진다. PintOS는 반대로 READY 상태가 되는 순간에 ready_list 안의 위치를 정해 둔다.

삽입은 O(n)이지만, 실제 실행할 스레드를 고르는 next_thread_to_run()은 리스트 앞(front)을 꺼내기만 하면 된다. 스레드 수가 많지 않은 PintOS에서는 이 단순한 설계가 우선순위 기반 선점형 스케줄링을 설명하기 좋다.

스케줄러 Run Queue 선택

OS 스케줄러는 실행 가능한 스레드/프로세스를 관리하는 자료구조(run queue)를 유지한다. 설계 선택지는 크게 두 가지다.

  1. 정렬된 리스트: 삽입 시 O(n), 추출 시 O(1). 스레드 수가 적으면 단순하고 효율적.
  2. 우선순위별 큐 배열: Linux O(1) 스케줄러처럼 priority 수만큼 큐를 두고 bitmap으로 비어 있지 않은 큐를 찾는다. 삽입/추출 모두 O(1).

PintOS는 교육 목적으로 방법 1을 사용한다.

실제 OS (Linux)

CFS (Completely Fair Scheduler): Linux의 CFS는 red-black tree를 사용해 vruntime(가상 실행 시간)이 가장 작은 태스크를 O(log n)에 선택한다. vruntime은 실제 실행 시간을 nice 값으로 가중한 값이며, 모든 태스크의 vruntime이 균등해지도록 스케줄링한다.

RT (Real-Time) 클래스: 우선순위별 linked list 배열(100개 큐, priority 0~99) + bitmap으로 O(1) 선택한다. sched_rt_entity가 각 태스크를 표현하며, PintOS의 priority 방식과 개념이 가장 유사하다.

Windows: Windows는 32단계 우선순위(0~31)에 대해 큐 배열을 유지하며, KiFindReadyThread()가 bitmap을 스캔해 최고 우선순위 큐에서 스레드를 꺼낸다.

PintOS 구현

PintOS의 ready_list는 intrusive doubly-linked list다.

정렬 삽입

스레드가 ready 상태로 전환될 때 list_insert_ordered()로 우선순위 내림차순 위치에 삽입한다.

비교 함수 thread_priority는 a->priority > b->priority를 반환하여 높은 우선순위가 리스트 앞에 오도록 한다.

추출

리스트 front가 항상 최고 우선순위이므로 list_pop_front()만으로 O(1) 선택이 완료된다.

선점 검사

새 스레드가 ready_list에 들어올 때, 현재 running 스레드보다 우선순위가 높으면 즉시 양보한다.

QEMU 에뮬레이션

QEMU 자체는 스케줄링에 관여하지 않는다 — ready_list는 순수 소프트웨어 자료구조로, guest OS(PintOS) 커널 메모리에만 존재한다. QEMU가 관여하는 지점은 timer interrupt다: i8254 PIT 모델이 TIMER_FREQ(100 Hz)마다 IRQ0를 발생시키고, PintOS의 timer_interrupt() → thread_tick() → intr_yield_on_return()이 TIME_SLICE 만료 시 스케줄링을 유발한다.

같은 우선순위의 스레드가 여러 개면 list_insert_ordered는 같은 priority를 가진 기존 원소 뒤에 삽입한다 (> 비교이므로). 이는 같은 우선순위 내에서 FIFO(Round-Robin) 순서를 보장한다.
