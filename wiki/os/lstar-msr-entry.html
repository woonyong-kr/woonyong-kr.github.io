LSTAR MSR → syscall 진입점

LSTAR MSR → syscall 진입점

범위: 이 문서는 x86-64 syscall 진입에서 LSTAR·STAR·SFMASK가 담당하는 일반 원리와 이를 Linux·PintOS·QEMU 코드에 대응시킨 특정 구현 설명을 함께 다룬다. 제시된 코드 경로·상수·보안 동작은 해당 구현과 배치에 종속되며, 실제 성능 비교는 CPU 세대·mitigation·측정 경계·cache 상태를 정한 실행 측정 없이는 검증 결과로 볼 수 없다.

유저 프로그램이 syscall 명령어를 실행하면 CPU는 LSTAR MSR에 적힌 주소로 곧장 점프한다. OS는 부팅할 때 이 주소에 커널의 syscall 진입 함수를 넣어 둔다.

LSTAR MSR → syscall 진입점 상태

x86-64에서 syscall 명령어를 실행하면 CPU는 LSTAR MSR(Model-Specific Register, 주소 0xC0000082)에 저장된 64비트 주소로 무조건 점프한다. OS는 부팅 시 이 MSR에 syscall 진입 함수의 주소를 기록해 두어야 한다. LSTAR와 함께 STAR MSR(세그먼트 셀렉터)과 SFMASK MSR(RFLAGS 마스크)도 설정해야 syscall/sysret 메커니즘이 완전히 동작한다.

상세 설명

추상 개념 — syscall 명령어와 MSR 3종 세트

syscall은 interrupt가 아니라 fast system call 명령어다. IDT를 거치지 않고 MSR에 미리 등록된 주소로 직접 점프하므로 int 0x80보다 훨씬 빠르다.

MSR주소역할
STAR0xC0000081커널/유저 CS/SS 셀렉터 인코딩
LSTAR0xC0000082syscall 진입점 RIP (64비트 주소)
SFMASK (SYSCALL_MASK)0xC0000084syscall 시 RFLAGS에서 클리어할 비트

syscall 명령어가 실행되면 CPU가 하는 일:

1. RCX ← 현재 RIP (return address)
2. R11 ← 현재 RFLAGS
3. RFLAGS &= ~SFMASK    (인터럽트 비활성화 등)
4. CS ← STAR[47:32]     (커널 코드 세그먼트)
5. SS ← STAR[47:32] + 8 (커널 데이터 세그먼트)
6. RIP ← LSTAR          (진입점으로 점프)
7. CPL ← 0              (커널 모드)

주의: syscall은 RSP를 바꾸지 않는다. 진입 직후 RSP는 여전히 유저 스택을 가리키므로, 진입 함수가 직접 커널 스택으로 전환해야 한다.

실제 OS — Linux의 접근

Linux에서는 arch/x86/kernel/cpu/common.c의 syscall_init()에서 LSTAR에 entry_SYSCALL_64(arch/x86/entry/entry_64.S)의 주소를 기록한다. entry_SYSCALL_64는 swapgs로 커널 GS base를 설정하고, per-cpu 영역에서 커널 스택 주소를 가져와 RSP를 전환한 뒤, pt_regs를 push하고 do_syscall_64()를 호출한다.

PintOS 구현

syscall_init() (userprog/syscall.c):

각 MSR 설정의 의미:

STAR MSR — 세그먼트 셀렉터 인코딩:

  • 비트 [47:32] = SEL_KCSEG (0x08) → syscall 시 CS = 0x08 (커널 코드), SS = 0x10 (커널 데이터)
  • 비트 [63:48] = SEL_UCSEG - 0x10 → sysret 시 CS = SEL_UCSEG (유저 코드), SS = SEL_UCSEG + 8 (유저 데이터)

LSTAR MSR — syscall_entry 함수 주소:

syscall_entry는 어셈블리 함수(userprog/syscall-entry.S)로, 다음 순서를 따른다:

syscall_entry:
  1. %rdi ← %rsp          (유저 RSP 임시 보관)
  2. %rsp ← tss->rsp0     (커널 스택으로 전환)
  3. push ss, rsp, eflags, cs, rip  (intr_frame 빌드)
  4. push 범용 레지스터 15개
  5. %rdi ← %rsp           (intr_frame 포인터)
  6. call syscall_handler
  7. pop 범용 레지스터
  8. sysretq               (유저 모드 복귀)

SFMASK MSR — FLAG_IF | FLAG_TF | FLAG_DF | FLAG_IOPL | FLAG_AC | FLAG_NT:

  • FLAG_IF를 마스크하여 syscall 진입 시 인터럽트를 자동 비활성화
  • FLAG_TF를 마스크하여 single-step 트랩 방지
  • 나머지는 보안/안정성을 위해 클리어

write_msr (include/intrinsic.h):

x86의 wrmsr 명령어는 ECX에 MSR 번호, EDX:EAX에 64비트 값을 넣고 실행한다. ring 0에서만 가능하다.

QEMU 에뮬레이션

QEMU(TCG)에서 syscall 명령어는 target/i386/tcg/sysemu/excp_helper.c의 helper_syscall()로 처리된다:

게스트: syscall 명령어 실행
  → TCG: helper_syscall(env, next_eip) 호출
    1. env->regs[R_ECX] = next_eip       (RCX ← return address)
    2. env->regs[11]    = env->eflags     (R11 ← RFLAGS)
    3. env->eflags     &= ~env->fmask     (SFMASK 적용)
    4. CS/SS 셀렉터를 env->star에서 추출하여 설정
    5. env->eip         = env->lstar      (RIP ← LSTAR)
    6. CPL ← 0

실제 하드웨어의 syscall 비용은 CPU 세대, mitigation, 측정 경계와 cache 상태에 따라 달라진다. 따라서 진입 상태 변경만을 1~4 cycles로 고정하거나 전체 syscall 비용과 혼용하면 안 된다. QEMU TCG에서도 helper 호출과 상태 갱신이 필요하며, host instruction 수를 guest hardware cycle과 직접 비교할 수 없다.

wrmsr 에뮬레이션:

syscall_init()에서 호출하는 write_msr(MSR_LSTAR, ...)는 게스트의 wrmsr 명령어를 실행한다. QEMU에서:

게스트: wrmsr (ECX=0xC0000082, EDX:EAX=syscall_entry 주소)
  → TCG: helper_wrmsr(env)
    → env->lstar = val  (CPUX86State의 lstar 필드에 저장)

이후 helper_syscall()이 env->lstar를 읽어 RIP에 설정하므로, 실제 하드웨어와 동일한 효과를 낸다.

SYSRET 엣지 케이스와 보안

sysretq는 syscall의 역방향이지만 몇 가지 보안 위험이 있다:

항목동작위험
RIP 설정RIP ← RCXRCX가 non-canonical 주소면 gp ring 0에서 발생
RFLAGS 복원RFLAGS ← R11유저가 R11에 임의 값을 넣을 수 있음
CPL 전환CPL ← 3RIP 검증 전에 gp가 뜨면 커널 모드에서 fault 처리

Linux는 이 RCX non-canonical 문제 때문에 모든 경우에 sysretq를 쓰지 않고, RCX가 비정상이면 iretq로 대체한다. PintOS는 이 검사를 하지 않으므로, 악의적 유저가 intr_frame의 RIP를 non-canonical로 변조하면 커널 gp가 발생할 수 있다.

int 0x80 vs syscall 성능 비교

항목int 0x80 (레거시)syscall (fast)
진입 경로IDT[0x80] → gate descriptor → CS:RIPMSR_LSTAR → RIP 직접 점프
스택 전환CPU가 TSS에서 RSP0를 읽고 자동 pushCPU가 스택을 안 건드림, OS가 수동 전환
레지스터 저장CPU가 SS/RSP/RFLAGS/CS/RIP 자동 pushCPU는 RCX, R11만 설정, 나머지 OS 몫
사이클 비용 (실제 HW)~100 cycles~20-30 cycles
PintOS 사용미사용 (x86-64이므로)유일한 syscall 진입 경로

LSTAR MSR → syscall 진입점 값 추적

  • MSR_STAR = 0xC0000081
  • MSR_LSTAR = 0xC0000082
  • MSR_SYSCALL_MASK = 0xC0000084
  • SEL_KCSEG = 0x08, SEL_UCSEG = 0x20 (PintOS GDT 배치)
  • STAR 값: (0x20 - 0x10) << 48 | 0x08 << 32 = 0x0010000800000000
  • SFMASK 값: FLAG_IF(0x200) | FLAG_TF(0x100) | FLAG_DF(0x400) | FLAG_IOPL(0x3000) | FLAG_AC(0x40000) | FLAG_NT(0x4000) = 0x47700
