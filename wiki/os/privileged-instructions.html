특권 명령어 (Privileged Instructions)

특권 명령어 (Privileged Instructions)

범위: 이 문서는 x86-64 특권 명령어의 일반 원리와 판단 기준을 설명하고 Linux, Windows, VT-x/VMX, PintOS, QEMU의 동작 및 코드 위치를 예시로 다룬다. 특정 구현에 관한 서술은 실제 코드·버전·실행 기록으로 검증된 결과가 아니며, 구현별 동작과 성능에 대한 판단에는 해당 환경에서 별도 확인과 측정이 필요하다.

특권 명령어는 CPU가 커널 모드에서만 허용하는 명령어다. 유저 코드가 페이지 테이블, 인터럽트, 장치 I/O를 마음대로 바꾸지 못하게 막는 가장 낮은 층의 안전장치다.

특권 명령어 상태

특권 명령어는 CPL=0(커널 모드)에서만 실행할 수 있는 x86-64 명령어 집합이다. CPL=3(유저 모드)에서 실행하면 CPU가 즉시 gp(General Protection) 예외를 발생시킨다. 이 목록은 하드웨어에 고정되어 있어 OS가 임의로 추가하거나 제거할 수 없다. 특권 명령어 제한이 유저/커널 분리의 물리적 기반이다 — 유저 코드가 페이지 테이블을 바꾸거나, 인터럽트를 끄거나, I/O에 직접 접근하는 것을 CPU가 원천 차단한다.

상세 설명

추상 개념 (CPU 하드웨어 규칙)

특권 검사 시점

CPU는 명령어 decode 단계에서 opcode를 확인한다. 해당 명령어가 특권 명령어이고 현재 CPL ≠ 0이면, 명령어를 실행하지 않고 곧바로 gp(vector 13) 예외를 발생시킨다. OS의 예외 핸들러가 이 gp를 받아 해당 프로세스를 종료하거나 시그널을 보낸다.

특권 명령어 분류

1. 제어 레지스터 조작

명령어동작보호하는 것
mov crN, regCR0/CR2/CR3/CR4 쓰기페이지 테이블(CR3), 보호 모드(CR0), PAE/PSE(CR4)
wrmsrMSR(Model-Specific Register) 쓰기LSTAR(syscall 진입점), EFER(Long Mode) 등
rdmsrMSR 읽기일부 MSR은 유저에서도 읽을 수 있지만 쓰기는 항상 특권
ltrTask Register에 TSS 셀렉터 로드커널 스택 주소(RSP0)

CR3를 유저가 바꿀 수 있다면: 자기만의 페이지 테이블을 만들어 커널 메모리를 매핑할 수 있다. → 보호 무력화.

2. 디스크립터 테이블 조작

명령어동작보호하는 것
lgdtGDT 레지스터 교체세그먼트 권한 구조 전체
lidtIDT 레지스터 교체인터럽트/예외 핸들러 주소
lldtLDT 레지스터 교체로컬 디스크립터 (현대 OS 미사용)

IDT를 유저가 바꿀 수 있다면: syscall 핸들러를 자기 코드로 교체하여 커널 권한 탈취 가능.

3. 인터럽트 제어

명령어동작보호하는 것
cli인터럽트 비활성화 (RFLAGS.IF=0)스케줄링, 선점
sti인터럽트 활성화 (RFLAGS.IF=1)인터럽트 상태

유저가 cli를 실행할 수 있다면: 타이머 인터럽트를 끄고 CPU를 독점할 수 있다. 다른 프로세스는 영원히 실행되지 않는다.

4. CPU 정지/특수 동작

명령어동작보호하는 것
hltCPU를 인터럽트가 올 때까지 정지CPU 가용성
invlpgTLB 엔트리 무효화TLB 일관성
invpcidPCID 기반 TLB 무효화TLB 일관성
wbinvd전체 캐시 write-back + 무효화캐시 일관성

5. I/O 접근

명령어동작보호하는 것
in / outI/O 포트 읽기/쓰기디스크, 키보드, 네트워크 등 장치
ins / outs문자열 I/O동일

I/O 명령어는 RFLAGS.IOPL(I/O Privilege Level) 필드와 비교된다. 일반적으로 IOPL=0이므로 CPL=0만 I/O 가능. TSS의 I/O Permission Bitmap으로 특정 포트만 유저에 허용할 수도 있지만, 현대 OS는 거의 사용하지 않는다.

유저에서 실행 가능한 “위험해 보이는” 명령어

명령어유저 실행 가능?이유
cpuidOCPU 정보 읽기 전용, 상태 변경 없음
rdtsc조건부CR4.TSD=1이면 gp, 아니면 허용. 타이밍 공격 방지용
syscallO유저→커널 게이트, 의도된 진입점
int NO소프트웨어 인터럽트로 커널 진입 (IDT DPL 검사)

실제 OS (Linux/Windows)

Linux: #GP 핸들러 do_general_protection()이 유저 프로세스의 특권 명령어 실행을 SIGSEGV(또는 SIGILL)로 변환한다. 프로세스는 기본적으로 core dump와 함께 종료된다.

유저가 "cli" 실행
→ CPU #GP (vector 13)
→ do_general_protection()
→ force_sig(SIGSEGV)
→ 프로세스 종료 + core dump

Windows: KiTrap0D() 핸들러가 STATUS_PRIVILEGED_INSTRUCTION 예외를 발생시킨다. SEH(Structured Exception Handling)로 잡지 않으면 프로세스 종료.

VT-x/VMX: 하드웨어 가상화에서는 게스트 OS(Ring 0)의 특권 명령어도 일부 VM exit을 유발한다. CR3 쓰기, MSR 접근 등이 하이퍼바이저로 트랩된다. 이는 “특권”의 또 다른 계층이다.

PintOS 구현

PintOS는 exception.c의 kill() 함수에서 gp를 처리한다:

#GP의 벡터 번호는 13 (0x0D). PintOS에서 유저가 hlt나 cli를 실행하면:

  1. CPU가 gp 발생 (vec_no=13)
  2. IDT → intr_entry → 등록된 핸들러 호출
  3. kill() → 유저 모드(CS=0x23)이므로 프로세스 종료

PintOS 커널이 사용하는 특권 명령어들:

사용 위치명령어목적
thread.c:do_iret()iretqregister 복원 + 모드 전환
interrupt.ccli/stiintr_disable()/intr_enable()
mmu.c:pml4_activate()mov cr3, rax페이지 테이블 전환
gdt.c:gdt_init()lgdtGDT 로드
tss.cltrTSS 셀렉터 로드
thread.c:idle()hltidle 스레드에서 CPU 절전
intrinsic.hinvlpgTLB 엔트리 무효화
init.cwrmsrLSTAR, STAR, FMASK MSR 설정
loader.Sin/outIDE 컨트롤러로 커널 이미지 로드

QEMU 에뮬레이션

QEMU TCG는 각 특권 명령어를 번역할 때 CPL 검사 코드를 삽입한다. 예를 들어 mov cr3, rax 번역 시:

if (CPL != 0) {
    raise_exception(EXCP0D_GPF);   // #GP
} else {
    env->cr[3] = new_value;
    tlb_flush(env);                // TLB 전체 무효화
}

GDB에서 gp가 발생하는 순간을 관찰하려면:

(gdb) catch signal SIGSEGV    # Linux
(gdb) b kill                   # PintOS: exception.c의 kill 함수
