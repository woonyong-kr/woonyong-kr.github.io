i8254 PIT 가상 타이머

i8254 PIT 가상 타이머

확인 범위: 이 문서는 i8254 PIT의 일반 동작 원리와 PintOS·QEMU에서의 구현 흐름 및 선택 기준을 설명하는 개념 자료다. 제시된 코드 좌표, 버전별 구현 세부, 실행 기록, 타이머 정밀도와 성능 관련 수치는 해당 소스와 실제 환경에서 별도로 검증해야 한다.

i8254 PIT는 1,193,180Hz 입력 클럭을 나눠 IRQ0을 주기적으로 만든다. PintOS는 이 신호를 받아 tick을 세고, QEMU는 같은 I/O 포트와 IRQ 흐름을 소프트웨어로 흉내 낸다.

i8254 PIT 가상 타이머 변화

Intel 8254 Programmable Interval Timer(PIT)는 x86 시스템에서 주기적 하드웨어 인터럽트를 생성하는 칩이다. 내부 오실레이터가 1,193,180 Hz로 카운터를 감소시키고, 카운터가 0에 도달할 때마다 IRQ0을 발생시킨다. OS는 이 주기적 인터럽트를 받아 시간 추적, 스케줄링(time slice 만료 검사), sleep/wake 처리를 수행한다. PintOS에서는 QEMU가 i8254를 소프트웨어로 에뮬레이션하여 동일한 인터페이스를 제공한다.

상세 설명

하드웨어 규격

8254 PIT에는 3개의 독립 카운터가 있다. OS 타이머로 쓰는 것은 Counter 0이다.

레지스터I/O 포트용도
Counter 00x40OS 타이머 인터럽트 (IRQ0)
Counter 10x41DRAM 리프레시 (레거시)
Counter 20x42PC 스피커 톤 생성
Control0x43모드/형식 설정

동작 원리:

  1. 오실레이터 클럭: 1,193,180 Hz (= 14.31818 MHz ÷ 12)
  2. OS가 Control 레지스터(0x43)에 모드를 쓰고, Counter 0(0x40)에 초기값(count)을 로드한다
  3. 매 클럭 틱마다 카운터가 1 감소한다
  4. 카운터가 0에 도달하면 → OUT 핀 활성화 → IRQ0 발생
  5. Mode 2(Rate Generator)에서는 자동으로 초기값을 다시 로드하여 반복

주파수 계산:

인터럽트 주파수 = PIT_FREQ / count
count = PIT_FREQ / TIMER_FREQ
      = 1,193,180 / 100
      = 11,932 (반올림: (1193180 + 50) / 100 = 11,932)

따라서 Counter 0은 11,932 클럭마다 한 번씩 IRQ0을 발생시키고, 이는 초당 약 100회(10 ms 간격)가 된다.

실제 OS (Linux/Windows)

Linux는 부팅 초기에 PIT로 타이머를 설정하지만, 이후 더 정밀한 타이머(HPET, APIC Timer, TSC)로 전환한다. 현대 Linux에서 PIT는 fallback 용도이며, CONFIG_HZ=1000이면 1 ms 간격으로 tick이 발생한다. tickless 커널(CONFIG_NO_HZ)에서는 idle 시 타이머 인터럽트를 멈추기도 한다.

Windows도 유사하게 APIC Timer를 주로 사용하며, PIT는 레거시 호환용이다.

PintOS 구현

PintOS는 PIT만 사용한다 (APIC Timer 미사용). timer_init()에서 PIT를 프로그래밍한다:

Control byte 0x34 해석:

비트값의미
7-600Counter 0 선택
5-411LSB 먼저, 그 다음 MSB (16-bit)
3-1010Mode 2: Rate Generator
00Binary 카운팅 (BCD 아님)

인터럽트 전달 경로:

timer_interrupt()가 호출되면:

  1. 전역 ticks 변수를 1 증가
  2. thread_tick()으로 현재 스레드의 time slice 검사
  3. thread_awake(ticks)로 sleep 중인 스레드 깨우기

timer_calibrate():

부팅 시 PIT 인터럽트 간격을 기준으로 busy-wait 루프의 속도(loops_per_tick)를 보정한다. 이 값은 timer_mdelay(), timer_udelay() 같은 짧은 지연에 사용된다.

QEMU 에뮬레이션

QEMU는 hw/timer/i8254.c에서 8254 PIT를 소프트웨어로 에뮬레이션한다.

핵심 구조체와 함수:

  • PITChannelState (hw/timer/i8254.c)
    • count: OS가 로드한 초기 카운터값, 예를 들어 11,932
    • latched_count: 카운터 래치 명령 시 캡처된 값
    • count_load_time: count를 로드한 호스트 시점, ns 단위
    • mode: 동작 모드, PintOS 설정에서는 Mode 2 Rate Generator
    • gate: 게이트 입력 상태
    • irq_timer: 호스트 타이머 콜백을 담는 QEMUTimer
    • irq: PIC 모델의 IRQ0 라인을 가리키는 qemu_irq

에뮬레이션 메커니즘:

QEMU는 실제로 1,193,180 Hz로 루프를 돌지 않는다. 대신 호스트 타이머를 사용하는 이벤트 기반 방식이다:

  1. Guest가 outb(0x43, 0x34) 실행 → QEMU pit_ioport_write()가 모드 설정
  2. Guest가 outb(0x40, LSB), outb(0x40, MSB) 실행 → pit_load_count()가 count=11,932 저장
  3. pit_load_count() → pit_irq_timer_update() 호출 → 호스트 타이머에 다음 만료 시점 등록
  4. 만료 시점 = count_load_time + count × (1,000,000,000 / 1,193,180) ns
  5. 호스트 타이머 만료 → pit_irq_timer_update() 콜백 → qemu_irq_raise(irq) → PIC 모델에 IRQ0 전달
  6. Mode 2이므로 자동으로 다음 만료 시점을 재등록 (반복)
%% QEMU i8254 모델이 호스트 타이머로 IRQ0을 재등록하는 흐름
flowchart TD
  guest_control["Guest outb(0x43, 0x34)<br/>Control: Counter 0, LSB/MSB, Mode 2"]
  pit_io["pit_ioport_write()<br/>모드 설정"]
  guest_count["Guest outb(0x40, LSB)<br/>Guest outb(0x40, MSB)"]
  load_count["pit_load_count(channel=0, val=11932)<br/>count 저장"]
  timer_update["pit_irq_timer_update(channel=0)<br/>다음 만료 시점 계산"]
  timer_mod["timer_mod(irq_timer, expire_time)<br/>호스트 타이머 등록"]
  host_expire["호스트 타이머 만료"]
  callback["pit_irq_timer_update()<br/>콜백"]
  raise_irq["qemu_irq_raise(irq)<br/>IRQ0 발생"]

Guest에서 카운터 읽기:

Guest가 inb(0x40)으로 현재 카운터를 읽으면, QEMU는 실시간 계산을 한다:

현재 카운터 = count - ((현재_호스트_시간 - count_load_time) × 1,193,180 / 1,000,000,000) % count

실제로 감소 루프를 돌지 않으므로 오버헤드가 거의 없다.

정밀도 한계:

QEMU의 타이머 정밀도는 호스트 OS의 타이머 해상도에 의존한다. Linux 호스트에서 timerfd 또는 CLOCK_MONOTONIC의 해상도(보통 1 ns)를 사용하지만, 실제 콜백 지연은 호스트 스케줄러에 의해 수백 μs~수 ms까지 변동할 수 있다. 따라서 guest에서 관측되는 tick 간격이 정확히 10 ms가 아닐 수 있다.
