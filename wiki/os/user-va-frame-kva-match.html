user VA와 frame kva + offset 일치

user VA와 frame kva + offset 일치

한 줄 요약: 유저 VA와 커널 frame kva는 숫자는 다르지만 같은 물리 프레임의 같은 바이트를 가리키며, 이 일치를 GDB·메모리 덤프로 직접 확인하는 것이 byte-level 디버깅의 핵심이다.

user VA와 frame kva + 차이

유저 프로그램이 접근하는 가상 주소(user VA)와 커널이 같은 데이터를 읽을 때 쓰는 커널 가상 주소(frame kva)는 숫자가 전혀 다르지만, 궁극적으로 같은 물리 프레임의 같은 바이트를 가리킨다. 이 일치를 GDB나 메모리 덤프에서 직접 확인할 수 있다는 것이 byte-level 디버깅의 핵심이다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 MMU는 가상 주소를 물리 주소로 변환한다. 같은 물리 프레임을 서로 다른 가상 주소로 매핑하는 것은 완전히 합법적이다. 핵심 불변식은 다음과 같다.

user VA → (PML4 walk) → 물리 프레임 PA + page offset
kernel VA → (커널 PML4 walk) → 같은 물리 프레임 PA + page offset

따라서 두 가상 주소로 같은 바이트를 읽으면 동일한 값이 나온다. CPU 관점에서 이 두 접근은 최종적으로 같은 RAM 셀을 읽는다.

page offset은 가상 주소의 하위 12비트다. 같은 4 KB 프레임 안에서 바이트 위치를 정하는 이 12비트는 가상 주소에서 물리 주소로의 변환 과정에서 바뀌지 않는다.

실제 OS (Linux/Windows)

Linux에서도 동일한 원리가 적용된다. kmap() 또는 direct mapping(__va(phys))으로 물리 프레임에 대한 커널 가상 주소를 만들고, 유저 프로세스의 PTE는 같은 물리 프레임을 유저 VA로 매핑한다.

Linux의 direct mapping은 물리 메모리 전체를 커널 주소 공간의 특정 오프셋에 1:1로 매핑한다. PAGE_OFFSET 상수를 더하면 물리 주소가 커널 가상 주소가 된다. PintOS의 ptov()/vtop()은 이 Linux direct mapping의 단순화된 버전이다.

Windows도 MDL(Memory Descriptor List)을 통해 물리 페이지에 대한 커널 VA를 얻는 MmGetSystemAddressForMdlSafe() 같은 API를 제공한다.

PintOS 구현

PintOS에서 user VA와 kernel VA의 관계는 세 가지 구조체를 거쳐 연결된다.

struct page {
    void *va;              // user VA (page-aligned)
    struct frame *frame;   // 연결된 프레임
};

struct frame {
    void *kva;             // kernel VA (palloc으로 받은 주소)
    struct page *page;     // 역참조
};

vm_do_claim_page()가 이 연결을 만든다.

pml4_set_page()는 유저의 PML4에 page->va → frame->kva가 가리키는 물리 프레임이라는 매핑을 설치한다. 설치 후 유저 코드가 page->va + offset에 접근하면, 커널이 frame->kva + offset에서 읽는 것과 같은 바이트를 얻는다.

frame->kva는 palloc_get_page(PAL_USER)로 할당받는다. 이 함수는 user pool에서 물리 프레임을 하나 꺼내고, 그 물리 주소에 KERN_BASE를 더한 커널 가상 주소를 반환한다.

따라서 물리 주소 PA에 대해:

frame->kva = ptov(PA) = PA + 0x8004000000
PA = vtop(frame->kva) = frame->kva - 0x8004000000

QEMU 에뮬레이션

QEMU에서 GDB로 메모리를 보면, x/Nx <address> 명령은 guest 가상 주소를 guest MMU 규칙에 따라 변환한 뒤 guest RAM에서 바이트를 읽어 보여준다.

따라서 GDB에서:

x/4xb 0x400123      (user VA로 읽기)
x/4xb 0x800400xxxx  (같은 프레임의 kernel VA로 읽기)

두 명령이 같은 4바이트를 보여주면, 두 가상 주소가 같은 물리 프레임을 가리킨다는 증거다.

QEMU 내부적으로는 guest 물리 주소가 RAMBlock의 호스트 메모리 영역에 대응된다. 즉 guest의 물리 주소 PA는 RAMBlock->host + PA 위치의 호스트 메모리 바이트다.

user VA와 frame kva + 값 추적

예제: user VA 0x400520에서 “hello” 읽기

유저 프로그램이 0x400520에 문자열 "hello"를 갖고 있다고 하자.

user VA = 0x400520
page VA = 0x400000  (하위 12비트 제거)
offset  = 0x520     (하위 12비트)

이 page가 claim되면 palloc_get_page()가 물리 프레임을 할당한다. 물리 주소가 0x1234000이라고 가정하면:

frame PA  = 0x1234000
frame kva = ptov(0x1234000) = 0x1234000 + 0x8004000000 = 0x8005234000

바이트 일치 확인:

user VA 기준:   0x400520 → (MMU walk) → PA 0x1234520
kernel VA 기준: 0x8005234000 + 0x520 = 0x8005234520 → (vtop) → PA 0x1234520

두 경로 모두 물리 주소 0x1234520에 도달한다. 이 주소의 5바이트가 0x68 0x65 0x6c 0x6c 0x6f (“hello”)다.

| 접근 경로     | 가상 주소        | 물리 주소    | 바이트           |
|-------------|----------------|------------|-----------------|
| user VA     | 0x400520       | 0x1234520  | 68 65 6c 6c 6f  |
| kernel kva  | 0x8005234520   | 0x1234520  | 68 65 6c 6c 6f  |

offset 불변식

page offset = VA & 0xFFF는 가상→물리 변환에서 그대로 보존된다.

user VA    = [PML4 idx][PDPT idx][PD idx][PT idx][12-bit offset]
                          ↓ PML4 walk
physical   = [frame number (PA >> 12)][12-bit offset ← 그대로 복사]

이것이 “같은 프레임 안에서 같은 offset이면 같은 바이트”인 이유다.
