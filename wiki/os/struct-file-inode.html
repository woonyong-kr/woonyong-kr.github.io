struct file → inode

struct file → inode

한 줄 요약: open()이 만든 struct file(열린 인스턴스)과 struct inode(디스크 파일의 메모리 표현)를 거쳐 데이터에 도달하는 경로.

struct file → inode 구조

유저 프로세스가 open()으로 파일을 열면 커널은 struct file과 struct inode를 거쳐 디스크 데이터에 접근한다. struct file은 열린 파일 인스턴스이고, struct inode는 디스크 파일의 메모리 표현이다. 따라서 접근 경로는 fd 번호 → struct file → inode → 디스크 섹터로 이어진다.

상세 설명

추상 개념

파일을 두 계층으로 나누면 같은 파일을 여러 번 열면서도 각 open()의 상태를 따로 관리할 수 있다. 각 struct file은 독립적인 pos를 가지며, 여러 struct file이 하나의 inode를 가리킬 수 있다.

반대로 부모와 자식이 같은 struct file을 공유하는 구조에서는 한쪽이 read()하여 pos를 바꾸면 다른 쪽에서도 바뀐 위치를 보게 된다. 이 설명은 같은 inode를 가리키는 서로 다른 struct file이 아니라, 하나의 struct file 자체를 공유하는 경우에 해당한다.

쓰기 금지 상태는 inode의 deny_write_cnt로 관리한다. 여러 오프너가 요청한 쓰기 금지를 이 카운터로 추적한다.

실제 OS (Linux)

Linux에서는 fd 번호, 열린 파일, 디스크 파일의 세 계층으로 볼 수 있다.

계층Linux 구조체역할
fd 번호task_struct.files->fd_array[]정수 → struct file* 매핑
열린 파일struct filepos, flags, f_op (VFS ops)
디스크 파일struct inodei_no, i_size, i_blocks, i_op

Linux struct file의 주요 필드는 다음과 같다.

  • f_pos: 현재 파일 오프셋
  • f_flags: O_RDONLY, O_APPEND 등
  • f_op: read/write/mmap 등의 함수 포인터 테이블
  • f_inode: 가리키는 inode

Linux struct inode의 주요 필드는 다음과 같다.

  • i_ino: inode 번호
  • i_size: 파일 크기
  • i_nlink: 하드링크 수
  • i_blocks: 할당된 블록 수
  • i_count: 참조 카운트

PintOS 구현

PintOS의 struct file은 filesys/file.c에 정의되어 있다.

PintOS의 struct inode는 filesys/inode.c에 정의되어 있다.

struct inode_disk는 디스크에 저장되는 메타데이터이며 크기는 정확히 512B다.

주요 연산의 흐름

**file_open(inode)**는 struct file을 calloc으로 할당한다. 이어 file->inode = inode, file->pos = 0, file->deny_write = false로 초기화하며, inode의 소유권은 file로 이전된다.

**inode_open(sector)**는 먼저 open_inodes 리스트에서 같은 sector의 inode가 이미 열려 있는지 찾는다. 존재하면 open_cnt++한 뒤 기존 inode를 반환한다. 존재하지 않으면 새 inode를 malloc하고 disk_read()로 inode_disk를 읽는다. 이 구현에서는 같은 파일을 열 때 같은 inode 객체를 재사용한다.

**file_close(file)**는 file_allow_write()로 deny_write 카운터를 복원한 뒤 inode_close(file->inode)로 open_cnt를 줄이고 free(file)을 호출한다.

**inode_close(inode)**는 --open_cnt를 수행한다. open_cnt가 0이 되면 list_remove()로 open_inodes에서 제거한다. removed가 true이면 free_map_release()로 블록을 해제한 뒤 free(inode)로 객체를 해제한다.

struct file → inode 값 추적

PintOS에서 struct file → inode → 디스크로 이어지는 주소 계산은 다음 값으로 설명할 수 있다.

항목값
sizeof(struct file)16 B (포인터 8 + off_t 4 + bool 4)
sizeof(struct inode)552 B (list_elem + sector + cnt들 + inode_disk 512B)
sizeof(struct inode_disk)512 B (= DISK_SECTOR_SIZE)
INODE_MAGIC0x494e4f44 (“INOD” ASCII)

inode_disk에서 데이터 섹터로의 매핑은 연속 할당을 전제로 계산한다.

  • byte_to_sector(inode, offset) = inode->data.start + offset / 512
  • 파일 크기 10,000 B → bytes_to_sectors(10000) = DIV_ROUND_UP(10000, 512) = 20 섹터
  • offset 5000의 섹터 = start + 5000/512 = start + 9

struct file → inode 점검

  • fd 번호는 fd_table에서 struct file을 찾기 위한 인덱스이고, struct file은 열린 파일 한 번의 상태를 담는다.
  • struct file의 pos는 읽기/쓰기 위치이고, struct inode는 파일의 디스크 위치와 크기 같은 메타데이터를 담는다.
  • 같은 inode를 가리켜도 struct file이 다르면 offset은 따로 움직이고, 같은 struct file을 공유하면 offset도 함께 움직인다.
