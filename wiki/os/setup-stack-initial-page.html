setup_stack — 초기 유저 스택 페이지 설정

확인 범위: 이 문서는 초기 유저 스택 설정의 일반 원리와 선택 기준을 설명하고, 입력에 제시된 PintOS Project 2·3 구현 및 Linux·QEMU 동작을 구현 사례로 구분해 다룬다. 구체적인 코드 좌표, 주소·크기·호출 흐름과 성능 관련 판단은 해당 코드 버전의 확인이나 실행 기록·측정으로 검증된 결과가 아니라 입력 본문에 기반한 설명이다.

한 줄 요약: setup_stack()은 load()의 마지막 단계로 USER_STACK 바로 아래 한 페이지를 매핑하고 RSP를 설정하며, Project 2는 eager로 Project 3은 SPT를 경유해 할당한다.

setup_stack 상태

setup_stack()은 ELF 적재(load())의 마지막 단계로, 유저 프로세스의 초기 스택 페이지를 생성한다. 유저 스택은 USER_STACK(0x47480000) 바로 아래 한 페이지(4 KB)로 시작하며, RSP를 USER_STACK으로 설정한다. 이후 argument_passing()이 이 스택에 argv 문자열과 포인터를 push한다. Project 2에서는 즉시 물리 frame을 할당하고(eager), Project 3(VM)에서는 vm_alloc_page + vm_claim_page로 SPT를 경유한다.

상세 설명

추상 개념 (CPU 하드웨어 관점)

CPU는 스택을 특별히 관리하지 않는다. RSP 레지스터가 현재 스택 꼭대기를 가리킬 뿐이고, push/call 명령어는 RSP를 감소시키고 해당 주소에 쓴다. 만약 그 주소에 유효한 매핑이 없으면 page fault가 발생한다.

따라서 OS가 해야 할 일은:

  1. 스택 영역에 최소 한 페이지의 물리 메모리를 매핑한다.
  2. RSP를 스택 영역의 꼭대기로 설정한다.
  3. (선택) 추가 스택 공간은 page fault 시 동적으로 할당한다(stack growth).

x86-64에서 스택은 아래로 자란다(높은 주소 → 낮은 주소). RSP가 가리키는 곳이 현재 사용 가능한 가장 낮은 주소이며, push는 RSP를 8 감소시킨 뒤 그 주소에 값을 쓴다.

실제 OS (Linux)

Linux에서 setup_arg_pages()가 유저 스택을 설정한다.

  • 스택 VMA(Virtual Memory Area)를 STACK_TOP_MAX(보통 0x7ffffffff000) 아래에 생성한다.
  • 초기 스택 크기는 rlimit(RLIMIT_STACK) 기본값 8 MB지만, 실제 물리 페이지는 demand paging으로 필요할 때만 할당된다.
  • ASLR(Address Space Layout Randomization)이 적용되면 스택 시작 주소에 랜덤 오프셋이 추가된다.
  • execve → load_elf_binary → setup_arg_pages → expand_stack 순서로 호출된다.

PintOS와 달리 Linux는 초기에 물리 frame을 할당하지 않고, argv/envp를 push하면서 page fault로 자연스럽게 할당된다.

PintOS 구현 — Project 2 (eager)

동작 순서:

  1. palloc_get_page(PAL_USER | PAL_ZERO): user pool에서 1 frame 할당, 0으로 초기화
  2. install_page(upage, kpage, true): PML4에 upage → kpage 매핑 설치 (writable)
  3. if_->rsp = USER_STACK: RSP를 페이지 상단(0x47480000)으로 설정

스택은 아래로 자라므로, RSP = USER_STACK에서 시작해서 push할수록 0x4747F000 방향으로 내려간다. 한 페이지(4 KB)가 초기 용량이다.

PintOS 구현 — Project 3 (VM)

차이점:

  • palloc + install_page 대신 vm_alloc_page + vm_claim_page 사용
  • VM_ANON | VM_MARKER_0: 스택 페이지는 anonymous + MARKER_0 플래그로 구분
  • curr->stack_bottom 기록: stack growth 시 이 값을 기준으로 “아래로 1 페이지씩” 확장 허용 여부를 판단
  • SPT에 page 구조체가 등록되므로 eviction, swap, fork 시 일관된 관리가 가능

vm_alloc_page는 SPT에 UNINIT 페이지를 등록하고, vm_claim_page가 즉시 frame을 할당하여 매핑한다. 스택은 lazy가 아니라 즉시 claim하는 이유: argument_passing에서 곧바로 write해야 하므로 fault를 기다릴 필요가 없다.

install_page 함수

두 가지를 확인한다:

  1. 해당 VA에 이미 매핑이 없는지 (pml4_get_page == NULL)
  2. PML4에 새 매핑 설치 (pml4_set_page)

중간 테이블(PDPT, PD, PT)이 없으면 pml4_set_page가 자동으로 할당한다.

QEMU 에뮬레이션

QEMU에서 palloc_get_page는 guest physical memory(RAMBlock) 내 빈 영역을 반환한다. pml4_set_page가 guest page table을 업데이트하면, 이후 RSP 근처 주소 접근 시 QEMU의 softmmu가 4단계 page table walk를 수행하여 guest PA → host VA로 변환한다.
