PDPT 인덱스

PDPT 인덱스

범위: 이 문서는 x86-64 4단계 페이지 테이블에서 PDPT 인덱스가 선택되는 일반 원리와 입력에 제시된 Linux·Windows·PintOS의 구현상 대응을 설명한다. 실제 코드의 동작 여부, 버전별 지원 범위, 실행 기록 및 성능 효과는 검증 결과가 아니므로 해당 코드와 환경에서 별도로 확인해야 한다.

한 줄 요약: 가상 주소 비트 38:30은 4단계 페이지 테이블 walk의 두 번째 테이블(PDPT)에서 엔트리를 고르는 9비트 인덱스다.

PDPT 인덱스 상태

x86-64 4단계 페이지 테이블에서 가상 주소(VA)의 비트 38:30이 PDPT index(Page Directory Pointer Table index)다. 첫 번째 단계에서 PML4 엔트리가 가리키는 PDPT 테이블(512개 엔트리)에서 이 9비트 index로 하나의 PDPT 엔트리(PDPTE)를 선택한다. PDPTE는 다음 단계인 PD(Page Directory)의 물리 주소를 담고 있다. PDPT 엔트리 하나가 커버하는 범위는 1 GiB다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

MMU가 4단계 walk을 수행할 때 두 번째로 참조하는 테이블이 PDPT다.

%% PDPT 인덱스가 4단계 페이지 테이블 walk에서 쓰이는 위치
flowchart LR
  cr3["CR3<br/>페이지 테이블 루트"]
  pml4["PML4[VA[47:39]]<br/>PML4E 선택"]
  pdpt["PDPT[VA[38:30]]<br/>PDPTE 선택<br/>이 문서의 주제"]
  pd["PD[VA[29:21]]<br/>PDE 선택"]
  pt["PT[VA[20:12]]<br/>PTE 선택"]
  frame["Frame + VA[11:0]<br/>최종 물리 주소"]
  cr3 --> pml4
  pml4 --> pdpt
  pdpt --> pd
  pd --> pt
  pt --> frame

PDPTE 구조 (8바이트):

%% PDPTE 8바이트 비트 레이아웃
flowchart TD
  pdpte["63..52 &#124; 51..12 &#124; 11..9 &#124; 8 &#124; 7 &#124; 6 &#124; 5 &#124; 4 &#124; 3 &#124; 2 &#124; 1 &#124; 0<br/>Available<br/>NX 등 &#124; PD Physical Addr<br/>비트 51:12 &#124; Avl &#124; G &#124; PS<br/>1 GiB page &#124; D &#124; A &#124; CD &#124; WT &#124; U/S &#124; W/R &#124; P"]

비트 0(P)이 0이면 이 엔트리는 “not present”이고, MMU는 pf(page fault)를 발생시킨다.

1 GiB 대형 페이지:

x86-64는 PDPTE에서 PS(Page Size) 비트(비트 7)를 1로 설정하면 1 GiB 대형 페이지를 직접 매핑할 수 있다. 이 경우 PD, PT 단계를 건너뛰고 VA[29:0](30비트)이 바로 1 GiB 프레임 내 offset이 된다. 서버의 대용량 메모리 매핑에 사용된다.

실제 OS (Linux/Windows)

Linux에서 PDPT 단계는 PUD(Page Upper Directory)라 부른다.

Linux는 1 GiB huge page를 지원한다(hugetlbfs로 할당). 서버에서 대규모 메모리 풀(데이터베이스 버퍼 등)을 1 GiB 페이지로 매핑하면 TLB 미스를 극적으로 줄인다. /proc/meminfo의 HugePages_Total로 확인 가능하다.

Windows에서는 Large Page(2 MiB)를 기본 지원하고, 1 GiB는 특수 API로 사용한다.

PintOS 구현

PintOS에서 PDPT 단계는 pdpe_walk() 함수가 처리한다.

핵심 동작:

  1. PDPE(va): (va >> 30) & 0x1FF로 9비트 index 추출
  2. pdpe[idx]에서 PTE_P 확인
  3. present가 아니면: create가 true일 때 palloc_get_page(PAL_ZERO)로 PD 테이블용 1 page 할당
  4. 새 엔트리에 vtop(new_page) | PTE_U | PTE_W | PTE_P 기록 (물리 주소 + 권한 비트)
  5. pgdir_walk()로 다음 단계(PD) 진행
  6. rollback: pgdir_walk()가 실패하고 이 단계에서 PD를 새로 할당했다면, 그 PD 페이지를 회수하고 엔트리를 0으로 초기화

PintOS는 1 GiB 대형 페이지를 사용하지 않는다. PDPTE의 PS bit로 walk를 조기 종료하지 않고, 모든 매핑은 4 KiB 단위의 최종 PT/PTE까지 내려간다.

호출 체인:

%% PintOS에서 pml4_get_page가 PDPT 단계까지 내려가는 호출 체인

PDPT 인덱스 값 추적

예시 1: 가상 주소 0x0000_0040_0000_0000 (256 GiB)

PML4 index = (0x40_0000_0000 >> 39) & 0x1FF = 0 (PML4[0])
PDPT index = (0x40_0000_0000 >> 30) & 0x1FF = 256 (0x100)
PD   index = 0
PT   index = 0
Offset     = 0

PDPT index 256은 256 × 1 GiB = 256 GiB를 의미한다. ✓

예시 2: PintOS KERN_BASE 0x80_0400_0000

PML4 index = 1
PDPT index = (0x80_0400_0000 >> 30) & 0x1FF = 0

PML4 index 1 아래의 첫 PDPT 엔트리(index 0)가 이 주소 범위를 담당한다.

예시 3: 유저 스택 0x4747_F000

PML4 index = 0
PDPT index = (0x4747_F000 >> 30) & 0x1FF = 1
PD   index = (0x4747_F000 >> 21) & 0x1FF = 0x23A = 570
PT   index = (0x4747_F000 >> 12) & 0x1FF = 0x07F = 127

유저 공간에서도 PDPT index 1이 사용된다. PML4[0] → PDPT의 여러 엔트리가 유저 주소 범위를 커버한다.

커버 범위 비교:

단계한 엔트리 커버전체 테이블(512 엔트리) 커버
PML4512 GiB256 TiB
PDPT1 GiB512 GiB
PD2 MiB1 GiB
PT4 KiB2 MiB

not-present + create 시 rollback 흐름:

%% pdpe_walk에서 하위 walk 실패 시 새 PD 페이지를 회수하는 rollback 흐름
flowchart TD
  start["pdpe_walk(pdpe, va, create=1)"]
  not_present["pdpe[idx] not present"]
  alloc["palloc_get_page(PAL_ZERO)<br/>new PD page"]
  install["pdpe[idx] = vtop(new) &#124; U &#124; W &#124; P<br/>allocated = 1"]
  pgdir["pgdir_walk(new PD, va, create=1)"]
  fail["하위 walk 실패<br/>pte == NULL"]
  rollback["palloc_free_page(new PD)<br/>pdpe[idx] = 0"]
  ret["return NULL"]
  start --> not_present
  not_present --> alloc
  alloc --> install
  install --> pgdir
  pgdir --> fail
  fail --> rollback
  rollback --> ret
