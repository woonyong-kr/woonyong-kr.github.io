파일 시스템 마운트

파일 시스템 마운트

한 줄 요약: 마운트(Mount)는 디스크나 파티션에 담긴 파일 시스템을 운영체제의 디렉터리 트리 특정 위치에 붙여서, 그 아래에서 파일을 읽고 쓸 수 있게 만드는 동작이다.

파일 시스템 마운트 필요성

컴퓨터에는 디스크가 여러 개 있을 수 있다. SSD, USB, 네트워크 드라이브와 각 디스크의 파티션은 저마다 독립된 파일 시스템을 가질 수 있다. 그러나 사용자는 파일에 접근할 때 “디스크 2의 파티션 3에 있는 파일 foo.txt”라고 지정하지 않는다. <local-home>/foo.txt처럼 하나의 경로를 사용한다.

마운트가 디스크의 파일 시스템과 이 경로를 연결한다. 파일 시스템을 디렉터리 트리의 한 지점인 마운트 포인트(Mount Point)에 붙이면, 그 지점 아래의 경로가 해당 파일 시스템으로 이어진다. 파일 시스템이 디스크에 있어도 마운트하지 않으면 커널은 그 파일 시스템에 접근할 수 없다.

파일 시스템 마운트 흐름

비유

마운트는 도서관 서가에 새 책장을 끼워 넣는 것과 같다. 책장에 해당하는 디스크의 파일 시스템에는 책에 해당하는 파일이 이미 정리되어 있다. 마운트는 이 책장을 마운트 포인트에 해당하는 도서관의 특정 구역에 놓는 행위다. 책장을 놓은 뒤에는 프로세스가 그 구역을 통해 파일에 접근할 수 있다. 책장을 빼는 언마운트(Unmount)를 수행하면 더 이상 그 경로로 접근할 수 없다.

정의

마운트는 세 요소를 연결한다.

  1. 블록 장치 — 디스크 또는 파티션이며, 섹터 단위로 읽고 쓸 수 있는 하드웨어다.
  2. 파일 시스템 타입 — FAT, ext4, NTFS처럼 블록 장치 위의 데이터 구조를 해석하는 규칙이다.
  3. 마운트 포인트 — 디렉터리 트리에서 파일 시스템이 보이는 위치이며, 빈 디렉터리를 사용한다.

Linux에서의 마운트 동작 순서

%% Linux 마운트 동작 순서
flowchart LR
  user["사용자<br/>mount -t ext4 /dev/sdb1 /mnt/data"]
  block_device["블록 장치 열기<br/>/dev/sdb1"]
  superblock["슈퍼블록 읽기<br/>block size, root inode"]
  vfsmount["VFS 등록<br/>vfsmount 생성"]
  mount_point["마운트 포인트 연결<br/>/mnt/data dentry"]
  lookup["이후 경로 탐색<br/>/mnt/data/foo.txt"]
  user -->|mount 요청| block_device
  block_device -->|메타데이터 확인| superblock
  superblock -->|파일 시스템 해석| vfsmount
  vfsmount -->|마운트 테이블 추가| mount_point
  mount_point -->|요청 전달| lookup
  1. 사용자가 mount -t ext4 /dev/sdb1 /mnt/data를 실행한다.
  2. 커널이 /dev/sdb1 블록 장치를 열고 슈퍼블록을 읽는다.
  3. 슈퍼블록에서 파일 시스템 메타데이터인 블록 크기와 루트 inode 등을 확인한다.
  4. VFS(Virtual File System)가 vfsmount 구조체를 만든다.
  5. 마운트 포인트 /mnt/data의 dentry에 vfsmount를 연결한다.
  6. 이후 /mnt/data/foo.txt에 접근하면 VFS가 이 파일 시스템으로 요청을 전달한다.

VFS와 마운트 테이블

Linux 커널은 VFS(Virtual File System)라는 추상 계층을 둔다. VFS는 파일 시스템 타입과 관계없이 open(), read(), write() 같은 동일한 인터페이스를 제공한다. 파일 시스템을 마운트하면 VFS가 마운트 테이블에 새 항목을 추가한다. 이후 경로를 탐색(path lookup)하다가 마운트 포인트를 만나면 해당 파일 시스템으로 건너간다.

%% VFS 마운트 포인트 분기
flowchart TD
  vfs["VFS (Virtual FS)<br/>경로 탐색 + 마운트 테이블 관리"]
  ext4["ext4 드라이버<br/>/dev/sda1<br/>/ (루트)"]
  fat["FAT 드라이버<br/>/dev/sdb1<br/>/mnt/usb"]
  vfs -->|/| ext4
  vfs -->|/mnt/usb| fat

루트 파일 시스템과 부팅

부팅할 때 커널이 가장 먼저 마운트하는 대상은 루트 파일 시스템(/)이다. 루트가 없으면 다른 파일 시스템을 연결할 디렉터리도 존재하지 않는다. 부트 로더가 커널에 루트 장치 정보를 넘기면, 커널이 그 장치의 파일 시스템을 /에 마운트한다.

PintOS — 마운트가 없는 이유

PintOS에는 마운트 개념이 없다. 파일 시스템 디스크로 hd0:1 하나만 사용하고, FAT와 원본 free-map 기반 FS 가운데 하나를 컴파일할 때 선택하기 때문이다. VFS 같은 추상 계층도 없으며 filesys_disk 전역 변수가 디스크를 직접 가리킨다.

실제 OS에서는 USB를 연결하면 자동으로 마운트하거나, NFS로 네트워크 디스크를 마운트하거나, /proc처럼 디스크가 없는 가상 파일 시스템을 마운트하기도 한다. PintOS는 이런 복잡도를 제거하여 FAT, inode, 디렉터리 같은 파일 시스템의 디스크 자료구조에 집중하도록 설계되었다.

파일 시스템 마운트 코드

PintOS: 디스크 직접 지정

disk_get(0, 1)은 마운트 대신 채널 0의 장치 1, 즉 두 번째 디스크를 전역 변수 filesys_disk에 직접 저장한다. 이후 filesys_create, filesys_open, filesys_remove를 비롯한 모든 파일 연산은 이 디스크만 사용한다.

Linux에서 같은 연결을 만들려면 커널이 블록 장치를 열고 슈퍼블록을 파싱한 뒤, 파일 시스템을 VFS에 등록하고 마운트 테이블에 추가해야 한다. PintOS에서는 disk_get() 한 줄이 이 과정을 대신한다.

PintOS: 마운트 포인트 없는 경로 탐색

dir_open_root()는 항상 ROOT_DIR_SECTOR(섹터 1)에서 시작한다. 마운트 포인트를 확인하는 분기는 없다. 하나의 디스크, 하나의 루트 디렉터리, 하나의 파일 시스템만 사용한다는 전제가 있기 때문이다.

정리

마운트는 디스크의 파일 시스템을 디렉터리 트리에 연결하는 커널 동작이다. Linux는 VFS 추상 계층과 마운트 테이블을 이용해 여러 파일 시스템을 하나의 트리에 통합한다. PintOS는 디스크와 파일 시스템을 하나씩만 사용하므로 마운트가 필요 없다. filesys_disk = disk_get(0, 1)이 디스크를 직접 지정하여 마운트의 역할을 대신한다.
