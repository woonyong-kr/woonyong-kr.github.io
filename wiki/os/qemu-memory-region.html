QEMU MemoryRegion — 게스트 메모리 공간 모델링

확인 범위: 이 문서는 MemoryRegion 트리와 FlatView를 통한 주소 해석의 일반 개념과 구성 요소를 설명하며, 제시된 PintOS 메모리 맵·호출 흐름·성능 수치는 특정 QEMU 버전이나 실제 실행 기록으로 검증된 결과로 보지 않는다. 실제 환경에 적용할 때는 해당 QEMU 소스와 머신 설정을 대조하고 GDB·모니터 관찰 및 성능 측정을 통해 코드 좌표, 주소 범위, 호출 횟수와 비용을 별도로 확인해야 한다.

QEMU는 guest가 보는 물리 주소 공간을 MemoryRegion 트리로 나누어 RAM, ROM, MMIO 장치 중 어디로 접근을 보낼지 결정한다.

QEMU MemoryRegion 상태

QEMU는 게스트 머신의 물리 주소 공간을 MemoryRegion 트리로 모델링한다. 실제 하드웨어에서 CPU가 물리 주소로 메모리에 접근하면, 주소에 따라 RAM, ROM, 또는 장치의 MMIO 레지스터에 도달한다. QEMU는 이 주소 디코딩을 MemoryRegion의 계층 구조와 우선순위로 재현한다. MemoryRegion이 없으면 QEMU는 어떤 물리 주소가 RAM이고 어떤 주소가 디스크 컨트롤러 레지스터인지 구분할 수 없다.

상세 설명

추상 개념 (하드웨어의 주소 디코딩)

실제 PC 하드웨어에서 CPU가 물리 주소를 버스에 올리면:

  • 0x00000000 ~ 0x0009FFFF: 메인 RAM (640 KB conventional memory)
  • 0x000A0000 ~ 0x000BFFFF: VGA 비디오 메모리
  • 0x000F0000 ~ 0x000FFFFF: BIOS ROM
  • 0x00100000 ~ (top of RAM): 확장 RAM
  • 0xFEC00000: I/O APIC MMIO
  • 0xFEE00000: Local APIC MMIO
  • I/O 포트 0x1F0~0x1F7: IDE 컨트롤러 (별도 I/O 주소 공간)

이 디코딩은 칩셋 하드웨어가 물리적으로 수행한다. QEMU는 이것을 소프트웨어 자료구조로 재현해야 한다.

MemoryRegion의 핵심 속성:

속성설명
addr부모 기준 상대 오프셋
size이 영역이 차지하는 크기
priority겹치는 영역 간 우선순위 (높을수록 우선)
ops읽기/쓰기 콜백 함수 포인터 (MMIO용)
ram_blockRAM인 경우 host 메모리 backing
subregions자식 MemoryRegion 목록

MemoryRegion의 종류:

  1. RAM: memory_region_init_ram()으로 생성. RAMBlock이 host mmap으로 backing. 게스트 read/write가 직접 host 메모리에 반영.
  2. MMIO: memory_region_init_io()로 생성. ops에 read/write 콜백 등록. 게스트가 이 주소에 접근하면 콜백 함수 실행.
  3. ROM: memory_region_init_rom()으로 생성. 읽기만 가능, 쓰기 무시.
  4. Container: memory_region_init()으로 생성. 자식을 묶는 논리 그룹. 자체로는 메모리 없음.
  5. Alias: 다른 MemoryRegion의 일부를 참조. 같은 물리 메모리를 다른 주소에 매핑.

주소 해석 과정 (FlatView)

MemoryRegion 트리는 설정이 바뀔 때마다 FlatView로 평탄화된다:

%% FlatView와 FlatRange 배열
flowchart TD
  flatview["FlatView &#124; MemoryRegion &#124; offset<br/>0x00000000 - 0x0009FFFF &#124; ram &#124; 0<br/>0x000A0000 - 0x000BFFFF &#124; vga-vram &#124;<br/>0x000F0000 - 0x000FFFFF &#124; bios-rom &#124;<br/>0x00100000 - 0x07FFFFFF &#124; ram &#124; 0x100000<br/>0xFEC00000 - 0xFEC00FFF &#124; ioapic &#124;<br/>... &#124; ... &#124; ..."]

게스트 CPU가 물리 주소 X에 접근하면:

  1. FlatView에서 X를 포함하는 FlatRange를 이진 탐색
  2. 해당 MemoryRegion의 타입에 따라 동작:
    • RAM → host 메모리 직접 접근
    • MMIO → ops->read/write 콜백 호출
    • 없음 → 무시 (unmapped 영역)

PintOS가 inb(0x1F0)으로 IDE 데이터를 읽으면:

  1. QEMU의 TCG가 inb 명령어를 번역하여 실행
  2. system_io FlatView에서 포트 0x1F0 검색 → ide MemoryRegion
  3. ide의 ops->read 콜백 호출 → 가상 디스크 이미지에서 데이터 읽기
  4. 결과값을 게스트 AL 레지스터에 반환

GDB 관찰 스크립트

관찰 시나리오

시나리오 1: PintOS 부팅 시 MemoryRegion 생성

QEMU에 -S -s 옵션을 주고 부팅 초기에 GDB를 연결하여 memory_region_init_ram_nomigrate와 memory_region_init_io에 breakpoint를 설정하면:

  1. 가장 먼저 pc.ram (128 MB RAM) 생성
  2. pc.bios (64 KB ROM) 생성
  3. i8254 PIT I/O 영역 (포트 0x40, 4B)
  4. i8259A master/slave PIC (포트 0x20/0xA0)
  5. ide 컨트롤러 (포트 0x1F0, 8B)
  6. 순서를 기록하면 PC 하드웨어 초기화 시퀀스를 이해할 수 있다

시나리오 2: PintOS disk_read()가 MMIO로

break memory_region_dispatch_read로 IDE MMIO 읽기를 추적하면:

  1. PintOS disk_read() → input_sector() → inb(0x1F0) 반복
  2. QEMU TCG가 inb를 번역 → address_space_read() 호출
  3. system_io FlatView에서 포트 0x1F0 탐색 → ide MemoryRegion
  4. ide_data_readw() 콜백 호출 → 디스크 이미지에서 2바이트 읽기
  5. 한 섹터(512B)에 대해 read 콜백이 256회 호출됨 (16-bit PIO)
