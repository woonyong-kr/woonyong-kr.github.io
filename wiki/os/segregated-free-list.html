분리 가용 리스트 — 크기별 리스트를 따로 두어 탐색을 O(1)에 가깝게 만드는 구조

분리 가용 리스트 — 크기별 리스트를 따로 두어 탐색을 O(1)에 가깝게 만드는 구조

확인 범위: 이 문서는 분리 가용 리스트의 일반 원리와 크기 클래스 설계의 선택 기준을 설명하고, PintOS malloc·glibc malloc·Linux 커널 SLUB 및 Malloc Lab 구현과의 관계를 입력 본문의 코드와 서술을 바탕으로 비교한다. 특정 버전의 실제 소스와 실행 기록 또는 성능 측정을 검증한 결과는 아니므로, 구현별 세부 동작과 복잡도·성능 판단에는 별도 확인이 필요하다.

한 줄 요약: Segregated free list는 빈 블록을 크기 범위별로 분류해 여러 개의 free list에 나눠 담고, 할당 요청이 오면 해당 크기 클래스의 리스트만 탐색하는 구조다.

분리 가용 리스트 구분

Explicit free list는 빈 블록만 연결해 탐색 범위를 줄였다. 그러나 빈 블록이 수천 개라면 여전히 하나씩 순회해야 한다. 더 큰 문제는 크기가 맞지 않는 블록을 계속 건너뛰는 것이다. 128바이트를 요청했는데 16바이트짜리 빈 블록 수백 개를 지나쳐야 한다면 시간 낭비다.

Segregated free list는 이 문제에 대한 자연스러운 답이다. 빈 블록을 크기 범위별로 분류해 별도의 리스트에 담는다. 128바이트 요청이 오면 128바이트 이상을 담당하는 리스트만 보면 된다. 크기 클래스를 잘 설계하면 탐색이 O(1)에 가까워진다.

이 구조를 모르면 glibc malloc의 bins 설계, PintOS malloc()의 descriptor 배열, 그리고 실제 범용 할당기가 왜 단일 free list를 쓰지 않는지 이해할 수 없다.

이 문서를 읽고 나면 다음을 구분할 수 있어야 한다.

  • 크기 클래스를 나누는 기준과 트레이드오프
  • Simple segregated storage와 segregated fits의 차이
  • PintOS malloc()이 실제로 segregated free list인 이유
  • glibc malloc의 bins 구조와의 관계

분리 가용 리스트 흐름

크기 클래스 — 빈 블록을 분류하는 기준

모든 빈 블록을 크기 범위(size class)로 나눈다. 각 크기 클래스마다 하나의 free list를 둔다. 대표적인 분류 방식은 2의 거듭제곱이다.

할당 요청 크기를 올림하여 해당 크기 클래스를 결정하고, 그 리스트에서 블록을 꺼낸다. 리스트가 비어 있으면 다음 크기 클래스로 올라간다.

왜 크기 클래스를 2의 거듭제곱으로 나누는가?

크기 클래스 수 = log₂(최대 블록 크기 / 최소 블록 크기)

예를 들어 최소 16바이트, 최대 4096바이트라면 클래스 수는 log₂(4096/16) = 8개다. 클래스가 많으면 내부 단편화가 줄지만 관리해야 할 리스트가 늘어난다. 2의 거듭제곱은 비트 연산으로 클래스 인덱스를 빠르게 계산할 수 있어 할당기에서 널리 쓰인다.

두 가지 변형 — Simple Segregated Storage

Segregated free list에는 크게 두 가지 설계가 있다.

  • Simple segregated storage
    • 각 크기 클래스의 블록 크기가 고정이다. 64바이트 클래스의 블록은 모두 정확히 64바이트다.
    • 블록 분할(splitting)이 없다. 할당 시 리스트에서 꺼내기만 하면 되므로 O(1)이다.
    • 병합(coalescing)도 없다. 같은 크기끼리만 관리하므로 인접 블록 확인이 불필요하다.
    • 단점: 내부 단편화가 심하다. 33바이트를 요청해도 64바이트 블록을 통째로 준다.
    • PintOS malloc()이 이 방식이다.
  • Segregated fits
    • 각 크기 클래스에 다양한 크기의 블록이 들어간다. 64~127바이트 범위의 블록이 하나의 리스트에 섞여 있다.
    • 블록을 찾으면 요청 크기에 맞게 분할한다. 남은 조각은 적절한 크기 클래스의 리스트에 넣는다.
    • 해제 시 인접 블록과 병합한다.
    • glibc malloc이 이 방식이다.

할당 흐름

%% Segregated free list 할당 흐름
flowchart TD
  start["malloc(100) 호출"]
  n_class["크기 클래스 결정<br/>100 -&gt; 128바이트 클래스<br/>클래스 3"]
  list3["free_list[3] 탐색<br/>(128~255B)"]
  list4["free_list[4] 탐색<br/>(256~511B)"]
  simple_return["블록 반환<br/>(simple seg.)"]
  split_return["분할 후 반환<br/>(segregated fits)"]
  start --> n_class
  n_class --> list3
  list3 --> simple_return
  list3 --> list4
  list4 --> split_return

Simple segregated storage는 해당 클래스에 블록이 없으면 새 페이지를 할당해 블록을 만든다. Segregated fits는 더 큰 클래스에서 블록을 가져와 분할한다.

실제 OS와의 비교

  • glibc malloc (ptmalloc2): segregated fits 방식이다. small bins(크기별 exact fit), large bins(크기 범위), unsorted bin(임시 버퍼), fastbin(작은 블록 캐시)으로 4종류의 bin을 운영한다. fastbin은 병합 없이 LIFO로 빠르게 재활용하는 최적화다.
  • PintOS malloc(): simple segregated storage 방식이다. descs[] 배열이 크기 클래스별 descriptor이고, 각 descriptor가 free list를 하나씩 갖는다. 분할·병합 없이 고정 크기 블록을 페이지(arena) 단위로 관리한다.
  • Linux 커널 SLUB: 커널 객체 할당에 사용하는 slab allocator다. 객체 크기별로 캐시를 두는 점에서 segregated free list와 유사하다.

분리 가용 리스트 코드

PintOS malloc — descriptor 배열이 크기

descs[]가 segregated free list의 핵심이다. 각 원소가 하나의 크기 클래스를 담당하고, 자기만의 free_list를 갖는다. 이것은 explicit free list를 여러 개 두는 것과 같다.

초기화 — 크기 클래스를 2배씩 늘리며 생성

PGSIZE가 4096이면 PGSIZE / 2 = 2048이다. 크기 클래스는 16, 32, 64, 128, 256, 512, 1024 — 총 7개가 만들어진다. 2048바이트 이상의 요청은 페이지 할당기(palloc)에 직접 위임한다.

할당 — 크기 클래스를 찾아 블록 꺼내기

탐색이 O(1)인 이유가 여기 있다. 크기 클래스를 결정하면(for 루프는 클래스 수만큼 = 최대 7번) list_pop_front로 바로 블록을 꺼낸다. 빈 블록 수에 무관하다.

해제 — arena가 완전히 비면 페이지를 반환

block_to_arena는 블록 주소를 페이지 경계로 내림(pg_round_down)해서 arena 헤더를 찾는다. arena가 자기 descriptor를 가리키고 있으므로 역으로 크기 클래스를 알 수 있다. 이것은 블록에 별도 메타데이터를 두지 않는 simple segregated storage의 장점이다.

Malloc Lab과의 비교

이 볼트의 Malloc Lab 최종 구현(mm.c)은 segregated free list가 아니라 AVL 트리 기반 best fit을 사용한다. AVL 트리는 모든 빈 블록을 크기 순으로 정렬해 best fit을 O(log M)에 찾는다. 반면 segregated free list는 크기 클래스를 나눠 first fit을 O(1)에 가깝게 만든다. 둘 다 explicit free list의 “빈 블록만 관리한다”는 원칙을 따르되, 탐색 자료구조가 다르다.

정리

Segregated free list는 빈 블록을 크기 범위별로 분류해 여러 free list에 나눠 담는다. 할당 요청이 오면 해당 크기 클래스의 리스트에서 O(1)에 블록을 꺼낸다. PintOS malloc()은 simple segregated storage로, descs[] 배열이 크기 클래스이고 arena(페이지)를 고정 크기 블록으로 쪼개 관리한다. glibc malloc은 segregated fits로, small/large/unsorted/fast bin 4종류를 운영하며 분할과 병합을 함께 수행한다. Implicit → explicit → segregated로 이어지는 진화의 마지막 단계이며, 현대 범용 할당기의 기본 설계다.
