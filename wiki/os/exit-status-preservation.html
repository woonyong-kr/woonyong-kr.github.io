종료 상태 보존 (Exit Status Preservation)

종료 상태 보존 (Exit Status Preservation)

자식 스레드는 먼저 사라질 수 있지만, 부모가 wait(pid)로 읽을 종료 코드는 더 오래 남아야 한다. 이 간격을 메우는 객체가 struct child_status다.

종료 상태 보존 구조

프로세스가 exit(status)를 호출하면 자신의 struct thread는 곧 해제된다. 하지만 부모가 나중에 wait(pid)로 종료 코드를 수거해야 한다. exit status가 thread 수명보다 오래 살아남아야 하는 문제를 해결하는 메커니즘이 exit status preservation이다.

핵심 아이디어: thread 외부에 독립된 힙 객체(struct child_status)를 두고, 자식이 죽기 직전 거기에 종료 코드를 기록하면 부모가 나중에 읽어간다.

상세 설명

추상 개념 (수명 불일치 문제)

프로세스 종료와 부모의 wait 호출 사이에는 시간 갭이 있다. 부모가 먼저 기다리는 경우, 자식이 먼저 끝나는 경우, 부모가 wait 없이 종료하는 경우의 세 갈래는 아래 순서도에서 하나의 정본 흐름으로 설명한다.

이 세 시나리오를 모두 안전하게 처리하려면, exit status를 담는 객체의 수명이 thread와 독립적이어야 한다.

실제 OS (Linux)

Linux zombie 메커니즘:

Linux에서 프로세스가 do_exit()를 호출하면 task_struct가 EXIT_ZOMBIE 상태로 남는다. 대부분의 자원(메모리, 파일 등)은 해제되지만 task_struct 자체와 커널 스택은 유지된다. 부모가 waitpid()를 호출하면:

waitpid(pid, &status, 0)
  → do_waitpid()
    → wait_task_zombie()
      → status = p->exit_code          // exit status 읽기
      → release_task(p)
        → __exit_signal()
        → __unhash_process()
        → put_task_struct()             // task_struct 최종 해제

Linux exit_code 인코딩:

Linux의 exit_code는 16비트 값으로, 상위 8비트가 exit status, 하위 8비트가 signal 번호다:

종료 방식exit_code 값WIFEXITEDWIFSIGNALED
exit(42)42 << 8 = 0x2A00truefalse
SIGKILL0x0009falsetrue
SIGSEGV + core0x008B (0x80 | 11)falsetrue

PintOS의 exit_status는 단순 int로, signal 개념이 없어 exit() 인자가 그대로 저장된다.

Linux zombie 누적 위험과 대응:

zombie가 수거되지 않으면 PID를 계속 점유한다. Linux 방어책:

  1. SIGCHLD 시그널 — 자식 종료 시 부모에게 통보, SA_NOCLDWAIT로 자동 수거 가능
  2. subreaper — prctl(PR_SET_CHILD_SUBREAPER) 로 init 대신 중간 프로세스가 고아 입양
  3. waitid(P_ALL, ...) — 조건에 맞는 자식 하나의 상태를 반환하므로, 종료한 자식을 모두 수거하려면 반복 호출

PintOS에는 시그널이 없으므로 process_wait()를 명시적으로 호출해야 한다. 고아 처리는 orphan_status_list + finish_self_status()의 자가 해제로 zombie 누적을 방지한다.

PintOS 구현

PintOS는 zombie 상태 대신 경량 힙 객체 struct child_status를 사용한다.

수명 타임라인:

  1. fork/exec 시점에 malloc(child_status)로 상태 객체를 만든다.
    • exit_status = -1 기본값으로 시작한다.
    • exited = false, waited = false, orphaned = false로 초기화한다.
    • 부모의 child_status_list에 push_back한다.
  2. 자식의 exit 시점에 finish_self_status()가 상태를 기록한다.
    • cs->exit_status = status로 종료 코드를 보존한다.
    • cs->exited = true로 종료 완료를 표시한다.
    • sema_up(&cs->wait_sema)로 기다리는 부모를 깨운다.
  3. 부모의 wait 시점에 process_wait()가 값을 수거한다.
    • cs->waited = true로 중복 wait를 막는다.
    • cs->exited가 아직 false이면 sema_down(&cs->wait_sema)로 기다린다.
    • status = cs->exit_status로 보존된 종료 코드를 읽는다.
    • list_remove(&cs->elem) 뒤 free(cs)로 수거가 끝난 객체를 해제한다.

QEMU 에뮬레이션 관점

QEMU는 exit status 보존에 직접 관여하지 않는다. 이것은 순수하게 OS 소프트웨어의 책임이다. QEMU가 하는 일은 guest OS의 메모리(힙)에 struct child_status가 올바르게 할당·해제되도록 RAM을 제공하는 것뿐이다.

GDB 관찰 스크립트

관찰 시나리오

시나리오 1: 정상 fork → exit → wait 왕복 —

wait-simple 테스트에서 부모가 fork() 후 wait()로 자식 exit status를 수거하는 전체 흐름을 추적한다.

관찰 절차:
1. trace_cs_alloc → process_fork에서 cs 할당 확인 (exit_status=-1 초기값)
2. dump_child_status $cs → 초기 상태 (exited=false, waited=false, orphaned=false)
3. trace_exit_status_write → 자식 exit(42) 시 cs->exit_status=42, exited=true 확인
4. trace_exit_status_read → 부모 process_wait 진입, sema_down 즉시 통과 (exited==true)
5. dump_child_status $cs → exit_status=42, exited=true, waited=true 확인
6. free(cs) 호출 후 cs 메모리 해제 확인

기대 결과:
- exit_status 값: -1 → 42 (finish_self_status에서 기록)
- exited: false → true (finish_self_status)
- waited: false → true (process_wait)
- sema_down은 exited==true이므로 즉시 통과 (자식이 먼저 종료한 경우)
- cs는 process_wait에서 free되어 메모리 누수 없음

시나리오 2: 고아 프로세스 자가 해제 — 부모가 wait 없이

multi-oom 등에서 부모가 wait 없이 exit하고, 자식이 나중에 exit하는 경우 고아 자가 해제를 확인한다.

관찰 절차:
1. trace_reparent → 부모 exit 시 reparent_or_reap_children 진입
   - exited==true인 자식: 즉시 free (이미 죽은 자식)
   - exited==false인 자식: orphaned=true 설정 + orphan_status_list에 이동
2. dump_child_status $cs → orphaned=true 확인
3. trace_exit_status_write → 고아 자식이 나중에 exit
   - finish_self_status에서 orphaned==true && !waited 확인
   - cs를 스스로 free → 메모리 누수 방지
4. orphan_status_list 상태 확인 → 해제 후 비어있음

기대 결과:
- 부모가 wait하지 않으면 waited=false 유지
- 부모 종료 시 orphaned=true로 책임 이전
- 고아 자식의 finish_self_status()가 cs를 자가 해제
- zombie 누적 없이 모든 child_status가 해제됨
