install_page — 유저 가상 주소 매핑 설치

install_page — 유저 가상 주소 매핑 설치

한 줄 요약: 유저 가상 주소(upage)와 palloc이 준 프레임(kpage)을 PML4 4단계 테이블에 연결해 present·writable·user 비트를 채워 넣는 매핑 설치 함수다.

install_page 상태

install_page(upage, kpage, writable)은 PintOS Project 2에서 유저 가상 주소(upage)와 커널 가상 주소(kpage, palloc이 반환한 frame)를 PML4 페이지 테이블에 연결하는 함수다. load_segment()에서 코드/데이터 페이지를, setup_stack()에서 스택 페이지를 매핑할 때 사용한다. Project 3(VM)에서는 SPT 기반의 vm_alloc_page + vm_do_claim_page로 대체되지만, 내부적으로 PML4 매핑 설치 원리는 동일하다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 관점)

x86-64 MMU는 가상 주소를 물리 주소로 변환할 때 CR3가 가리키는 PML4 테이블에서 4단계 walk을 수행한다. 각 단계(PML4 → PDPT → PD → PT)에서 테이블 엔트리를 읽고, 최종 PT 엔트리가 물리 frame의 PFN(Physical Frame Number)을 담고 있다.

“매핑 설치”란 이 4단계 테이블 체인에 엔트리를 채워 넣는 것이다. 중간 테이블이 아직 없으면 새로 할당해야 한다. 하드웨어는 매핑을 읽기만 하고, 매핑을 만드는 것은 OS의 책임이다.

PTE 비트 설정:

  • present (P): 1이어야 MMU가 이 엔트리를 유효하게 인식한다
  • writable (R/W): 1이면 write 허용, 0이면 read-only
  • user (U/S): 1이어야 CPL=3(유저 모드)에서 접근 가능

실제 OS (Linux)

Linux에서 페이지 테이블 매핑 설치는 여러 계층을 거친다:

  • __set_pte_at(): PT 엔트리에 PFN과 권한 비트를 기록한다
  • pgd_alloc(), p4d_alloc(), pud_alloc(), pmd_alloc(), pte_alloc(): 중간 테이블이 없으면 자동 할당한다
  • vm_fault → do_anonymous_page/do_wp_page → set_pte_at: page fault handler에서 호출된다

Linux는 PintOS의 install_page처럼 load 시점에 직접 매핑하지 않고, demand paging으로 fault handler에서 매핑한다. 하지만 최종 PTE 설치 원리는 동일하다.

PintOS 구현

두 단계 방어:

  1. pml4_get_page(t->pml4, upage) == NULL: 이미 매핑이 있으면 false 반환. 동일 VA에 두 번 매핑하면 이전 frame이 누수되므로 방지한다.
  2. pml4_set_page(t->pml4, upage, kpage, writable): 4단계 테이블을 순회하며 엔트리를 설치한다.

pml4_set_page 내부 동작:

pml4_set_page(pml4, upage=0x400000, kpage=0x8004123000, writable=false)
  1. pml4_idx = (0x400000 >> 39) & 0x1FF = 0
     → pml4[0]에 PDPT 주소 설치 (없으면 palloc으로 새 PDPT 할당)
  2. pdpt_idx = (0x400000 >> 30) & 0x1FF = 0
     → pdpt[0]에 PD 주소 설치 (없으면 새 PD 할당)
  3. pd_idx = (0x400000 >> 21) & 0x1FF = 2
     → pd[2]에 PT 주소 설치 (없으면 새 PT 할당)
  4. pt_idx = (0x400000 >> 12) & 0x1FF = 0
     → pt[0] = (kpage의 PA) | PTE_P | PTE_U | (writable ? PTE_W : 0)

중간 테이블(PDPT, PD, PT)은 커널 풀(PAL_ZERO)에서 할당된다. 기존 PML4가 있는 프로세스에서 한 VA를 처음 매핑할 때 새로 필요한 중간 테이블은 최대 3개, 즉 12 KB다. 프로세스 전체 page-table 비용은 VA 분포에 따라 여러 PDPT·PD·PT가 생기므로 12 KB보다 커질 수 있고, PML4 자체 4 KB도 별도다.

Project 3 (VM)에서의 대체

VM 프로젝트에서 install_page는 직접 사용되지 않는다. 대신:

vm_alloc_page(type, upage, writable)
  → SPT에 UNINIT page 구조체 등록

vm_do_claim_page(page)
  → palloc으로 frame 확보
  → pml4_set_page(t->pml4, page->va, frame->kva, page->writable)
  → page->frame = frame

차이점:

  • install_page: PML4에만 매핑. SPT 모름. frame 추적 없음.
  • vm_do_claim_page: SPT의 page↔frame 양방향 연결 + PML4 매핑. eviction/swap/fork에서 page를 찾을 수 있다.

QEMU 에뮬레이션

pml4_set_page가 guest page table(guest physical memory 내)을 수정한다. 이후 해당 VA 접근 시 QEMU softmmu가:

  1. CR3에서 PML4 기저 주소를 읽는다
  2. 4단계 walk으로 PTE까지 도달한다
  3. PTE의 PFN → guest PA 계산
  4. RAMBlock에서 guest PA → host VA로 변환
  5. 실제 메모리 접근 수행

QEMU에는 소프트웨어 TLB가 있어, 한번 변환한 결과를 캐시한다. pml4_set_page가 PTE를 변경해도 QEMU TLB는 자동 무효화되지 않으며, CR3 재설정(process_activate)이나 invlpg 명령어로 flush된다.

pml4_set_page 실제 코드

pml4e_walk(pml4, va, 1)의 1은 “중간 테이블이 없으면 palloc으로 새로 할당”하라는 의미다. vtop(kpage)는 커널 VA → 물리 주소 변환(kpage - KERN_BASE). 이 한 줄이 4단계 walk의 최종 목적지다.

GDB 관찰 스크립트

1. install_page 호출 추적 — 어떤 upage에 어떤 kpage가 매핑되는지:

(gdb) break install_page
(gdb) commands
  silent
  printf "install_page: upage=%p kpage=%p writable=%d\n", upage, kpage, writable
  continue
  end

2. pml4_set_page의 PTE 기록 관찰:

(gdb) break threads/mmu.c:258
(gdb) commands
  silent
  printf "PTE written: *pte=%p = PA 0x%lx | flags\n", pte, vtop(kpage)
  continue
  end

*pte 주소가 PT 엔트리의 커널 VA이고, 기록되는 값이 물리 주소 + 비트 플래그다.

3. 중간 테이블 할당 감지 — pml4e_walk 내부:

(gdb) break palloc_get_page if flags == PAL_ZERO
(gdb) commands
  silent
  printf "PT table allocated: caller=%p\n", *(void**)($rsp)
  continue
  end

PAL_ZERO로 할당되는 것은 페이지 테이블(PDPT/PD/PT)이다.

4. setup_stack에서의 install_page 확인:

(gdb) break userprog/process.c:1263
(gdb) commands
  printf "stack install: upage=%p kpage=%p\n", upage, kpage
  continue
  end

upage가 USER_STACK - PGSIZE(= 0x47480000 - 0x1000 = 0x4747F000)인지 확인한다.

5. load_segment에서의 반복 install_page 관찰:

(gdb) break userprog/process.c:1236
(gdb) commands
  silent
  printf "segment install: upage=%p read=%d zero=%d writable=%d\n", upage, read_bytes, zero_bytes, writable
  continue
  end

ELF 세그먼트의 각 페이지가 순서대로 매핑되는 과정을 확인한다.

install_page 값 추적

항목값
PTE 크기8 bytes (64-bit)
PT 한 개 엔트리 수512 (2^9)
PT 한 개 크기512 × 8 = 4096 bytes (1 page)
VA → PML4 indexbits [47:39] (9 bits)
VA → PDPT indexbits [38:30] (9 bits)
VA → PD indexbits [29:21] (9 bits)
VA → PT indexbits [20:12] (9 bits)
VA → page offsetbits [11:0] (12 bits)
PTE_P (present)bit 0
PTE_W (writable)bit 1
PTE_U (user)bit 2

매핑 설치 예시 — install_page(0x4747F000, kpage, true):

VA = 0x4747F000
  PML4 idx = (0x4747F000 >> 39) & 0x1FF = 0
  PDPT idx = (0x4747F000 >> 30) & 0x1FF = 1
  PD   idx = (0x4747F000 >> 21) & 0x1FF = 0x03A
  PT   idx = (0x4747F000 >> 12) & 0x1FF = 0x07F
→ pt[0x7F] = (kpage PA) | PTE_P | PTE_W | PTE_U = ...07
