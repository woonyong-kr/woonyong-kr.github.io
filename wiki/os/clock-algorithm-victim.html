시계 알고리즘 희생자 (Clock Algorithm Victim)

시계 알고리즘 희생자 (Clock Algorithm Victim)

확인 범위: 이 문서는 Clock algorithm의 일반 원리와 victim 선택 기준을 설명하고, 제시된 Linux·PintOS·QEMU 내용은 특정 구현을 이해하기 위한 사례로 다룬다. 코드 좌표, 버전별 동작, 실제 프레임 수·순회 횟수·I/O 비용·성능에 관한 판단은 해당 소스와 실행·측정 기록을 별도로 확인해야 하며, 본문만으로 특정 환경에서 검증된 결과로 간주하지 않는다.

메모리가 꽉 찼을 때 OS는 어떤 프레임을 내보낼지 골라야 한다. Clock algorithm은 PTE의 accessed bit를 보며 최근에 쓰인 프레임에는 한 번 더 기회를 주고, 조용했던 프레임을 victim으로 고른다.

왜 최근 사용 여부를 대충 봐도 되는가

정확한 LRU(Least Recently Used)를 구현하려면 모든 페이지 접근 시점을 계속 기록해야 한다. 메모리 접근은 너무 자주 일어나기 때문에, 그 기록 자체가 큰 비용이 된다. Clock algorithm은 대신 하드웨어가 자동으로 세워 주는 accessed bit(A bit) 하나만 본다. “최근에 접근된 적이 있는가”만 알면 완벽한 순서는 몰라도 꽤 그럴듯한 victim을 고를 수 있다.

물리 메모리가 가득 찼을 때 clock hand가 프레임 목록을 돌며 A bit를 확인한다. A bit가 1이면 최근에 쓰였다는 뜻이므로 bit를 0으로 내리고 지나간다. A bit가 0이면 지난 순회 이후 조용했던 프레임이므로 eviction victim이 된다.

A bit와 D bit가 알려주는 것

x86-64 MMU는 PTE의 accessed bit를 자동으로 설정한다:

  • 페이지에 읽기 또는 쓰기 접근이 발생하면 → A bit = 1 (하드웨어가 설정)
  • OS가 명시적으로 A bit = 0으로 초기화할 수 있다 (소프트웨어가 클리어)

**dirty bit(D bit)**도 함께 사용된다:

  • 페이지에 쓰기 접근이 발생하면 → D bit = 1
  • eviction 시 D bit = 1이면 디스크에 write-back 필요

이 두 비트가 eviction 정책의 전부다. CPU는 “언제” 접근했는지 기록하지 않는다. 오직 “접근했는가”만 알려준다.

Clock Algorithm 동작

프레임들을 원형 리스트로 배치하고, clock hand(시계 바늘)가 순회한다:

%% Clock algorithm victim 선택
flowchart LR
  hand["clock hand"]
  frame_a["frame A<br/>accessed bit = 1<br/>second chance"]
  frame_b["frame B<br/>accessed bit = 1<br/>accessed bit = 0으로 클리어"]
  frame_c["frame C<br/>accessed bit = 0<br/>victim"]
  frame_d["frame D<br/>accessed bit = 1<br/>second chance"]
  hand --> frame_a
  frame_a --> frame_b
  frame_b --> frame_c
  frame_c --> frame_d
  frame_d --> frame_a

순회 규칙:

  1. clock hand가 가리키는 프레임의 A bit를 확인한다.
  2. A bit = 1이면: “second chance”를 준다. A bit = 0으로 클리어하고 다음으로 전진한다.
  3. A bit = 0이면: 이 프레임이 victim이다. eviction 수행.
  4. 한 바퀴를 돌아도 victim을 못 찾으면 (모든 프레임의 A bit가 1이었던 경우), 두 번째 순회에서는 모두 0으로 클리어된 상태이므로 반드시 victim을 찾는다.

최악의 경우: 프레임 N개일 때 최대 2N번 검사 (한 바퀴 클리어 + 한 바퀴 선택).

Enhanced Clock (NRU 변형)

일부 OS는 (accessed, dirty) 쌍을 4등급으로 나눈다:

등급AD의미eviction 우선순위
000미참조, 깨끗가장 먼저 내보냄
101미참조, 더럽두 번째
210참조됨, 깨끗세 번째
311참조됨, 더럽가장 나중에 내보냄

등급 0부터 순서대로 찾으면 불필요한 disk I/O를 줄인다 (dirty 페이지는 write-back 비용이 크다).

실제 OS (Linux)

Linux는 clock algorithm을 직접 쓰지 않고 LRU 이중 리스트 (active list + inactive list) + kswapd 데몬을 사용한다:

  • active list: 최근 참조된 페이지
  • inactive list: 한동안 미참조된 페이지
  • kswapd가 주기적으로 inactive list에서 victim을 선택
  • A bit를 주기적으로 스캔하여 페이지를 active ↔ inactive 사이에서 이동

원리는 동일하다: A bit로 “최근 사용 여부”를 판단하고, 미사용 페이지를 우선 evict한다.

QEMU 에뮬레이션

QEMU는 어떤 frame을 victim으로 고를지 결정하지 않는다. vm_get_victim()은 guest인 PintOS의 소프트웨어 정책이고, QEMU는 그 명령을 실행하며 x86 페이지 테이블 walk와 A/D bit 설정 효과를 에뮬레이션한다. 이 책임 경계를 먼저 분리해야 한다.

A bit 자동 설정 경로:

  1. guest가 가상 주소에 접근 → QEMU SoftMMU가 page table walk 수행
  2. walk 중 PTE를 찾으면, TCG 헬퍼가 해당 PTE의 bit 5(accessed)를 1로 설정
  3. SoftTLB에 캐시 → 이후 같은 페이지 접근은 TLB hit으로 PTE를 다시 건드리지 않음

A bit 클리어 시 TLB 무효화: pml4_set_accessed(pml4, va, false)가 PTE의 A bit를 클리어하면, TLB와 실제 PTE가 불일치할 수 있다. 현재 PintOS 구현은 pml4_set_accessed()에서 수정 대상 PML4가 현재 CR3에 올라온 주소 공간이면 invlpg(va)를 호출한다. 그래서 같은 VA의 다음 접근은 다시 page walk를 거치며 A bit를 새로 세울 수 있다.

GDB에서 clock algorithm 관찰법:

# 1. frame_table 전체 크기 확인
(gdb) p list_size(&frame_table)

# 2. clock_ptr의 현재 위치
(gdb) p clock_ptr
(gdb) set $f = (struct frame *)((char *)clock_ptr - offsetof(struct frame, elem))
(gdb) p/x $f->kva
(gdb) p $f->page->va

# 3. vm_get_victim에 breakpoint → victim 선택 관찰
(gdb) b vm_get_victim
(gdb) c
# victim이 결정되는 순간까지 step
(gdb) b vm.c:302  # return clock_frame 직전
(gdb) c
(gdb) p/x clock_frame->kva
(gdb) p clock_frame->page->va

# 4. A bit 상태 직접 확인
(gdb) set $va = clock_frame->page->va
(gdb) set $pml4 = clock_frame->owner_thread->pml4
(gdb) p pml4_is_accessed($pml4, $va)

# 5. eviction 전후 swap 상태
(gdb) b vm_evict_frame
(gdb) c
(gdb) finish
(gdb) p victim->page   # NULL이면 eviction 완료

시계 알고리즘 희생자 값 추적

현재 user pool에 실제 등록된 frame 수를 U라고 할 때:

항목값
총 유저 프레임 수U (frame_table 또는 user pool 초기화 결과로 측정)
clock 최악 순회최대 약 2U번 (첫 바퀴에서 accessed clear, 둘째 바퀴에서 선택)
eviction 1회 비용 (ANON)swap write: 8 sectors x 512 B = 4 KB
eviction 1회 비용 (FILE, clean)0 (버리기만 하면 됨)
eviction 1회 비용 (FILE, dirty)파일 write-back: 최대 4 KB

4 MB를 단순히 4 KB로 나눈 1024는 전체 물리 page의 이론적 개수일 뿐이다. 커널 예약 영역과 user/kernel pool 분할 뒤의 유저 프레임 수로 사용할 수 없다.

ANON 페이지를 swap out할 때 PintOS의 swap disk는 IDE 채널 1:1에 연결되며, sector 크기는 512 B이므로 4 KB 페이지 = 8 sectors를 기록한다.

시계 알고리즘 희생자 점검

  • Clock algorithm은 정확한 LRU가 아니라 A bit 하나로 최근 접근 여부를 근사한다.
  • A bit가 1이면 victim으로 고르지 않고, 0으로 내린 뒤 다음 프레임을 본다.
  • A bit가 0이면 최근 순회 이후 접근 흔적이 없다는 뜻이므로 victim 후보가 된다.
  • COW 공유 frame에서는 owner 중 하나라도 A bit가 1이면 frame 전체가 최근 접근된 것으로 본다.
  • dirty bit는 victim 선택의 핵심 기준은 아니지만, swap_out()이 swap/file write-back 비용을 판단할 때 중요하다.
