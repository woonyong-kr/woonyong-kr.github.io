accessed/dirty bit로 victim 판단

accessed/dirty bit로 victim 판단

PTE의 A/D bit가 eviction 판단에 필요한 이유

물리 메모리가 부족하면 OS는 내보낼 frame을 선택해야 한다. 이 문서에서 다루는 x86-64와 PintOS 구현에서는 PTE의 accessed bit (A) 와 dirty bit (D) 가 그 판단에 쓰인다. A bit는 페이지가 최근에 접근되었는지 살피는 신호이고, D bit는 페이지를 내보낼 때 저장 장치에 써야 하는지 판단하는 신호다.

  • A bit (PTE_A, 0x20): CPU가 이 페이지에 read 또는 write로 접근하면 1로 설정
  • D bit (PTE_D, 0x40): CPU가 이 페이지에 write하면 1로 설정 (PTE 레벨에서만)

두 비트의 조합을 보면 “최근에 안 쓰인 페이지”와 “내보낼 때 디스크 쓰기가 필요한 페이지”를 구분할 수 있다. 다만 실제 victim 선정에서 각 비트를 사용하는 방식은 OS와 알고리즘에 따라 다르다.

x86-64 MMU가 A/D bit를 바꾸는 과정

이 문서에서 설명하는 x86-64 MMU 규칙에 따르면, MMU는 page table walk 중 PTE를 읽을 때 A/D bit를 자동으로 설정한다.

메모리 접근 발생
  → MMU가 PTE를 찾음 (4단계 page table walk)
  → PTE의 A bit = 1 (항상)
  → write 접근이면 PTE의 D bit = 1 (추가)
  → 물리 주소로 접근 완료

CPU는 A와 D를 0→1 방향으로만 자동 설정한다. 반대로 1→0은 OS가 소프트웨어로 처리해야 한다. A/D를 0으로 초기화한 뒤에는 stale TLB entry가 비트의 재설정을 막지 않도록 TLB를 flush해야 한다.

A/D 조합으로 보는 eviction 후보와 비용

AD의미Eviction 비용
00최근 미접근, 미수정최저 — 그냥 버려도 됨 (clean)
01최근 미접근, 수정됨중간 — 디스크에 써야 함
10최근 접근, 미수정높음 — 곧 다시 쓸 수 있음
11최근 접근, 수정됨최고 — 곧 다시 쓸 수 있고, 쓰기도 필요

이 표는 A를 최근 접근 여부의 신호로, D를 저장 비용의 신호로 해석한 것이다. Clock algorithm은 A bit만 사용하여 “최근 접근 여부”를 판단한다. D bit는 victim이 정해진 뒤 “디스크에 써야 하는가?”를 판단할 때 사용한다.

Linux에서 기록된 page replacement 방식

이 문서에 기록된 Linux 설명에서는 page replacement가 LRU 기반의 2-list 방식인 active_list와 inactive_list를 사용한다.

  • page_referenced(): PTE의 A bit를 검사하고 clear → 최근 접근 여부 판단
  • PageDirty(): page가 dirty인지 확인 → writeback 필요 여부
  • kswapd 데몬이 주기적으로 A bit를 clear하며, clear 후에도 다시 set되지 않은 page를 inactive_list로 이동

또한 PTE만 보는 것이 아니라 struct page의 PG_referenced, PG_dirty 플래그도 별도로 관리하여 판단에 사용한다.

PintOS의 Clock Algorithm과 victim 선정

이 문서에 제시된 PintOS 구현은 Clock Algorithm을 사용하며, A bit만으로 victim을 결정한다.

vm_get_victim()의 순회 과정

clock_ptr이 비어 있으면 frame_table의 시작점에서 출발한다. 순회 중 list_end()를 만나면 list_begin()으로 돌아가 원형 순회를 이어간다.

각 frame에서는 vm_frame_accessed(clock_frame)를 호출해 owner들 가운데 하나라도 A bit가 1인지 확인한다. A=1이면 vm_frame_set_accessed(clock_frame, false)로 owner들의 A bit를 clear하고 다음 frame으로 이동한다. A=0이면 해당 frame을 victim으로 반환한다. 반환하기 전에 clock_ptr을 한 칸 전진하므로 다음 eviction은 victim 다음 위치에서 시작한다.

제시된 구현에는 반복 횟수를 제한하는 별도 counter가 없다. 첫 순회에서 접근된 frame들의 A bit를 내리기 때문에, frame table에 evict 가능한 frame이 있다는 조건에서는 다음 순회에서 victim을 찾는 구조다.

D bit가 swap_out 정책에 미치는 영향

PintOS에서 D bit는 victim 선정에는 쓰이지 않지만, swap_out 정책에는 영향을 줄 수 있다.

  • anonymous page: 원본이 없으므로 항상 swap disk에 써야 함
  • file-backed page: D=1이면 파일에 writeback 필요, D=0이면 그냥 버릴 수 있음

pml4_is_accessed / pml4_set_accessed와 TLB 무효화

여기서 invlpg는 A bit를 다시 관찰하기 위해 필요하다. A bit를 clear해도 이전 PTE가 TLB에 남아 있으면 CPU는 TLB hit으로 메모리에 접근한다. 그러면 page table walk가 일어나지 않아 PTE의 A bit가 다시 set되지 않는다. invlpg로 해당 VA의 TLB entry를 무효화하면 다음 접근에서 page table walk가 다시 일어나고 A bit가 set될 수 있다.

QEMU softmmu에서 TLB 무효화가 반영되는 위치

이 문서에 기록된 QEMU softmmu 설명에서는 TLB를 소프트웨어로 에뮬레이션한다. guest OS가 PTE를 수정할 때 QEMU의 TLB(CPUTLBEntry)와 guest PTE는 별도로 관리된다. invlpg 명령어를 에뮬레이션하면 QEMU는 해당 guest VA의 softmmu TLB entry를 무효화한다. QEMU는 victim 정책을 선택하지 않고, guest page table walk와 invlpg의 하드웨어 효과를 에뮬레이션한다.

PTE_A와 PTE_D의 값 및 위치

PTE_A 비트 위치: bit 5 = 0x20 = 32
PTE_D 비트 위치: bit 6 = 0x40 = 64

PTE 64-bit 레이아웃에서:
  bit 0  : Present (P)
  bit 1  : Writable (W)
  bit 2  : User (U)
  bit 3  : Write-Through
  bit 4  : Cache-Disable
  bit 5  : Accessed (A)  ← CPU가 접근 시 자동 set
  bit 6  : Dirty (D)     ← CPU가 write 시 자동 set
  bit 7  : Page Size (PS)
  bit 8  : Global (G)
  bits 9-11 : AVL (OS 사용 가능)
  bits 12-51: Physical page number (40-bit)

Clock algorithm 최악 케이스:
  frame 수 = N일 때
  1바퀴: 모든 frame의 A=1 → 전부 clear, victim 없음
  2바퀴: 모든 frame의 A=0 → 첫 frame이 victim
  최대 반복 = 2N

PintOS eviction 흐름

flowchart TD
    A[vm_get_frame: palloc 실패] --> B[vm_evict_frame 호출]
    B --> C[vm_get_victim: Clock Algorithm]
    C --> D{현재 frame의 A bit?}
    D -->|A=1| E["A bit = 0 (clear) + invlpg"]
    E --> F[다음 frame으로 이동]
    F --> D
    D -->|A=0| G[이 frame = victim]
    G --> H{page type?}
    H -->|anonymous| I[swap disk에 write]
    H -->|file-backed, D=1| J[파일에 writeback]
    H -->|file-backed, D=0| K[그냥 버림]
    I --> L[pml4_clear_page: PTE 제거]
    J --> L
    K --> L
    L --> M[frame 반환]

판단할 때 확인할 조건

  • A bit는 “최근 접근됨”을 알려주는 근사 신호다. OS가 clear한 뒤 다시 set되는지를 관찰해야 의미가 생긴다.
  • D bit는 이 PintOS 구현에서 victim을 고르는 기준이 아니라, 내보낼 때 swap/file write-back이 필요한지 판단하는 비용 신호다.
  • 제시된 PintOS의 vm_get_victim()은 frame->owners를 통해 COW 공유 frame의 여러 PTE를 함께 본다.
  • pml4_set_accessed()와 pml4_set_dirty()는 현재 CR3의 PML4를 수정할 때 invlpg()로 해당 VA의 TLB entry를 무효화한다.
