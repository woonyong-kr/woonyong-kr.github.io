MMU

MMU

한 줄 요약: MMU는 CPU 안의 하드웨어 회로로 페이지 단위 가상 주소를 물리 주소로 명령어 실행과 동시에 변환하고, 변환에 실패하면 page fault 예외로 OS에 넘긴다.

MMU 혼동

프로그램이 사용하는 주소(가상 주소)와 실제 메모리 칩의 주소(물리 주소)는 다르다. 프로그램은 0x400000에 코드가 있다고 믿지만, 실제 RAM에서는 0x1A3000에 들어 있을 수 있다. 이 변환을 매번 소프트웨어로 하면 메모리 접근마다 수십 클럭이 추가된다.

MMU는 CPU 안에 있는 하드웨어 회로로, 가상 주소를 물리 주소로 변환하는 작업을 명령어 실행과 동시에 수행한다. OS가 페이지 테이블을 설정해두면, MMU가 하드웨어 속도로 자동 변환한다. 변환에 실패하면 MMU가 page fault 예외를 발생시켜 OS에게 알린다.

MMU 흐름

주소 변환의 기본 단위: 페이지

메모리를 바이트 단위로 변환하면 변환 테이블이 너무 커진다. 대신 페이지(보통 4 KB = 4096 바이트) 단위로 변환한다.

가상 주소 = [ 페이지 번호 (상위 비트) | 페이지 오프셋 (하위 12비트) ]
물리 주소 = [ 프레임 번호 (상위 비트) | 같은 오프셋 (하위 12비트) ]

MMU는 페이지 번호를 프레임 번호로 바꾸고, 오프셋은 그대로 통과시킨다.

CR3 레지스터

x86-64에서 CR3 레지스터는 현재 프로세스의 페이지 테이블 최상위 주소(PML4의 물리 주소)를 가리킨다. 프로세스를 전환할 때 OS가 CR3을 새 프로세스의 페이지 테이블 주소로 바꾸면, MMU가 즉시 새 주소 공간을 사용한다.

x86-64 4단계 페이지 테이블

x86-64의 4단계 paging 모드는 48비트 canonical virtual address를 사용한다. LA57를 활성화한 5단계 paging은 57비트 canonical virtual address를 사용하므로 아래 비트 분해의 적용 범위에서 제외한다.

%% x86-64 가상 주소 비트 구조
flowchart TD
  address["63..48 &#124; 47..39 &#124; 38..30 &#124; 29..21 &#124; 20..12 &#124; 11..0<br/>Sign Extend<br/>63..48 &#124; PML4<br/>9b &#124; PDPE<br/>9b &#124; PD<br/>9b &#124; PT<br/>9b &#124; Offset<br/>12b"]

각 단계 테이블은 512개(2^9) 엔트리를 가진다. 각 엔트리는 8바이트이므로 테이블 하나가 정확히 4 KB(한 페이지)를 차지한다.

변환 경로:

%% CR3에서 물리 프레임까지 이어지는 페이지 테이블 변환 경로
flowchart LR
  cr3["CR3<br/>PML4 물리 주소"]
  pml4["PML4 테이블<br/>[PML4 idx]<br/>512 entries"]
  pdpe["PDPE 테이블<br/>[PDPE idx]<br/>512 entries"]
  pd["PD 테이블<br/>[PD idx]<br/>512 entries"]
  pt["PT 테이블<br/>[PT idx]<br/>512 entries"]
  frame["물리 프레임<br/>4KB 페이지<br/>+ offset"]
  cr3 --> pml4
  pml4 --> pdpe
  pdpe --> pd
  pd --> pt
  pt --> frame

PTE 플래그 비트

각 페이지 테이블 엔트리(PTE)의 하위 12비트는 플래그로 사용된다.

비트이름의미
0P (Present)1이면 매핑 존재, 0이면 page fault 발생
1W (Writable)1이면 쓰기 가능, 0이면 읽기 전용
2U (User)1이면 유저 모드 접근 가능, 0이면 커널 전용
5A (Accessed)MMU가 이 페이지에 접근하면 자동으로 1로 설정
6D (Dirty)MMU가 이 페이지에 쓰기하면 자동으로 1로 설정

A 비트와 D 비트는 MMU가 하드웨어적으로 설정한다. OS는 이 비트를 읽어서 페이지 교체 정책(예: clock 알고리즘)에 활용한다.

page fault

MMU가 주소를 변환하다가 실패하면 #PF(page fault) 예외를 발생시킨다. 이때:

  1. CPU가 CR2 레지스터에 fault를 일으킨 가상 주소를 저장한다.
  2. 에러 코드를 스택에 push한다 (P 비트 상태, W/R, U/S 정보 포함).
  3. OS의 page fault 핸들러로 점프한다.

OS는 이 정보를 보고 페이지를 디스크에서 불러오거나, 접근 권한 위반이면 프로세스를 종료한다.

실제 운영체제

Linux에서 MMU는 커널의 메모리 관리 서브시스템과 밀접하게 동작한다. Linux는 x86-64에서 4단계(때로 5단계, LA57) 페이지 테이블을 사용하며, struct mm_struct가 프로세스의 주소 공간을 관리한다. pgd_t, p4d_t, pud_t, pmd_t, pte_t 타입으로 각 단계를 추상화한다. CR3 전환은 switch_mm() → load_new_mm_cr3()로 수행하고, 이때 TLB flush를 최소화하기 위해 PCID(Process Context ID)를 활용한다.

Windows는 유사하게 4단계 페이지 테이블을 사용하며, EPROCESS → DirectoryTableBase가 CR3 값을 담고 있다. Working Set 관리자가 page fault 시 물리 메모리 할당과 교체를 관리한다.

실제 OS와 PintOS의 차이:

항목실제 OS (Linux)PintOS
페이지 테이블 단계4~5단계4단계 (PML4)
대형 페이지2MB, 1GB 지원4KB만
PCID지원 (TLB 효율)미지원
KPTIMeltdown 대응 분리없음
NUMA노드별 메모리 정책단일 메모리

PintOS

PintOS의 MMU 관련 코드는 소프트웨어 측면에서 페이지 테이블을 관리하는 부분이다. 실제 하드웨어 MMU는 QEMU가 에뮬레이션한다.

CR3 전환 (mmu.c)

lcr3()는 인라인 어셈블리로 CR3 레지스터를 교체한다. 이 순간 MMU가 새 페이지 테이블을 참조하기 시작하고, 이전 TLB 캐시는 무효화된다.

연산 예시

가상 주소 0x0000_0040_1234 변환

가상 주소:  0x0000 0000 0040 1234
이진:      ... 0000 0000 0000 | 0 0000 0000 | 0 0000 0001 | 0 0000 0000 | 0 0001 0010 0011 0100

PML4 인덱스 = (0x401234 >> 39) & 0x1FF = 0     → PML4[0]
PDPE 인덱스 = (0x401234 >> 30) & 0x1FF = 0     → PDPE[0]
PD   인덱스 = (0x401234 >> 21) & 0x1FF = 2     → PD[2]
PT   인덱스 = (0x401234 >> 12) & 0x1FF = 1     → PT[1]
오프셋      =  0x401234 & 0xFFF        = 0x234

워크 경로:

%% 가상 주소 0x401234의 페이지 테이블 워크 예시
flowchart LR
  cr3["CR3"]
  pml4["PML4[0]"]
  pdpe["PDPE[0]"]
  pd["PD[2]"]
  pt["PT[1]"]
  pte["PTE = 0x1A3067<br/>프레임 주소 = 0x1A3000 (PTE_ADDR)<br/>플래그 = 0x067<br/>P=1, W=1, U=1, A=1, D=1"]
  physical["물리 주소<br/>0x1A3000 + 0x234<br/>= 0x1A3234"]
  cr3 --> pml4
  pml4 --> pdpe
  pdpe --> pd
  pd --> pt
  pt --> pte
  pte --> physical
