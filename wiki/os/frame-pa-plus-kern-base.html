Frame PA + KERN_BASE 변환

Frame PA + KERN_BASE 변환

확인 범위: 이 문서는 direct mapping의 일반 원리와 주소 변환 관계를 설명하고, 입력에 제시된 PintOS·Linux·QEMU 사례를 통해 구현 형태와 선택 이유를 구분해 살펴본다. 구체적인 상수, 코드 동작, 주소 예시, 지원 범위와 성능·안전성에 관한 판단은 해당 버전의 실제 코드와 설정, 실행 기록 및 측정으로 별도 검증해야 한다.

한 줄 요약: PintOS 커널은 물리 주소에 KERN_BASE를 더하는 일대일 선형 매핑으로 커널 가상 주소를 얻어, page table walk 없이 모든 물리 메모리를 곧바로 들여다본다.

Frame PA + KERN_BASE 변환 상태

PintOS에서 커널은 물리 주소(PA)에 KERN_BASE를 더해 커널 가상 주소(KVA)를 만든다. 이 일대일 선형 매핑 덕분에 커널은 page table walk 없이도 모든 물리 메모리에 접근할 수 있다. ptov(pa) = pa + KERN_BASE, vtop(kva) = kva - KERN_BASE가 그 전부다. Frame(물리 페이지)을 커널이 읽고 쓸 때는 항상 이 KVA를 사용하며, struct frame의 kva 필드가 바로 이 변환된 주소를 저장한다.

상세 설명

추상 개념 — Direct Mapping

x86-64에서 CPU가 메모리에 접근할 때는 반드시 가상 주소를 사용한다 (paging이 켜져 있으므로). 커널도 예외가 아니다. 그래서 커널은 물리 메모리를 가상 주소 공간의 상위 영역에 일정 offset으로 선형 매핑해 둔다. 이것이 이 문서의 direct mapping이다. VA = PA인 identity mapping과는 다르며, 여기서는 KVA = PA + KERN_BASE다.

KVA = PA + KERN_BASE
PA  = KVA - KERN_BASE

이 매핑은 커널의 page table에 미리 설정되어 부팅 시부터 유효하다.

실제 OS (Linux)

Linux x86-64에서는 PAGE_OFFSET(보통 0xffff888000000000)이 PintOS의 KERN_BASE에 해당한다. __va(pa) = pa + PAGE_OFFSET, __pa(kva) = kva - PAGE_OFFSET으로 동일한 변환을 수행한다. 물리 메모리가 64TB까지 direct mapping된다.

PintOS 구현

PintOS의 KERN_BASE는 0x8004000000이다.

Frame 할당과 KVA:

palloc_get_page(PAL_USER)는 물리 페이지를 할당하고, 그 KVA를 반환한다.

frame->kva가 0x800400a000이라면, 이 frame의 물리 주소는:

PA = 0x800400a000 - 0x8004000000 = 0xa000

즉 물리 메모리의 40KB 지점에 있는 frame이다.

QEMU 에뮬레이션

QEMU에서 guest의 물리 메모리는 호스트의 malloc으로 할당된 RAMBlock이다. guest가 PA 0xa000에 접근하면, QEMU는 RAMBlock->host + 0xa000으로 변환하여 호스트 메모리를 읽는다. KERN_BASE 변환은 guest CPU의 page table이 처리하므로 QEMU 자체는 이 변환을 에뮬레이트하지 않는다 — page table walk를 에뮬레이트할 뿐이다.

page table에서의 역할

pml4_set_page(pml4, upage, kpage, writable)에서:

  • upage: 유저 가상 주소 (유저 프로세스가 보는 주소)
  • kpage: KVA (= PA + KERN_BASE) — 커널이 frame에 접근하는 주소

내부적으로 kpage에서 vtop()으로 PA를 추출하고, 이 PA를 PTE에 기록한다.

왜 이렇게 설계하는가

  1. 단순성: 커널이 물리 메모리에 접근할 때 page table을 수정할 필요 없이, 고정된 오프셋 하나로 변환한다.
  2. 성능: 커널의 direct mapping은 부팅 시 한 번만 설정하면 되고, TLB에 캐시된다.
  3. 안전성: is_kernel_vaddr()로 유저 주소와 커널 주소를 쉽게 구분한다. >= KERN_BASE이면 커널, 아니면 유저.
