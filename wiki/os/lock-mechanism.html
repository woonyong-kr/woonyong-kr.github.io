락 메커니즘 (Lock Mechanism)

Lock은 한 번에 한 스레드만 임계 영역에 들어가게 하는 도구다. PintOS에서는 초기값 1인 세마포어에 holder를 붙여, 누가 잡았고 누가 풀 수 있는지까지 추적한다.

왜 세마포어에 소유자를 더하나

초기값 1인 binary semaphore도 상호 배제를 만들 수 있다. 하지만 세마포어에는 “누가 지금 들고 있는가”라는 정보가 없다. down()한 스레드와 up()하는 스레드가 달라도 구조적으로 막지 않는다.

Lock은 이 빈칸에 소유권을 더한다. lock_acquire()에 성공한 스레드가 holder가 되고, lock_release()는 그 holder만 호출할 수 있다. 이 정보가 있어야 높은 우선순위 스레드가 lock을 기다릴 때 “누구에게 우선순위를 빌려줘야 하는지”를 알 수 있다. 그래서 priority donation은 세마포어가 아니라 lock을 기준으로 동작한다.

소유권이 만드는 규칙

운영체제 이론에서 Lock(또는 Mutex)은 상호 배제를 위한 가장 기본적인 도구다. 핵심 규약은 세 가지다:

규약의미
소유권acquire한 스레드만 release할 수 있다
비재귀성같은 스레드가 다시 acquire하면 데드락 (recursive mutex는 별도 설계)
상호 배제동시에 최대 1개 스레드만 임계 영역에 진입

세마포어는 “down한 스레드 A, up하는 스레드 B”가 다를 수 있지만, Lock은 A == B를 강제한다. 이 차이가 priority donation의 전제 조건이 된다.

실제 OS (Linux)

Linux 커널은 struct mutex (kernel/locking/mutex.c)를 사용한다. owner 필드에 현재 소유 태스크를 기록하며, optimistic spinning — Lock holder가 CPU에서 실행 중이면 대기 태스크가 sleep 대신 짧게 spin하여 context switch 비용을 줄인다 — 을 적용한다. Linux의 struct semaphore와 달리, mutex는 CONFIG_DEBUG_MUTEXES에서 소유자 외 release를 잡아내는 ASSERT를 제공한다.

유저 공간에서는 pthread_mutex_t가 대응한다. futex(fast userspace mutex) syscall로 커널 진입 없이 uncontended 경로를 처리하고, contended일 때만 FUTEX_WAIT로 sleep한다.

Linux futex 보충: pthread_mutex_lock()은 먼저 atomic CAS로 uncontended 획득을 시도한다. 실패하면 FUTEX_WAIT syscall로 커널에 진입하여 대기 큐에 들어간다. 해제 시 대기자가 있으면 FUTEX_WAKE로 깨운다. 이 2단계 설계 덕분에 uncontended 경로에서 syscall이 0회다.

QEMU 에뮬레이션

QEMU 관점에서 Lock 연산은 전부 guest 커널 코드다. lock_acquire()와 lock_release()에는 특권 명령어나 I/O가 없으므로, TCG는 일반 메모리 읽기/쓰기와 함수 호출로 번역한다.

관찰 포인트:

  • sema_down 내부의 intr_disable()/intr_set_level()은 x86 cli/sti 명령어를 사용한다. TCG는 이를 guest EFLAGS.IF 조작으로 에뮬레이션하며, QEMU의 가상 인터럽트 전달에 영향을 준다.
  • Lock contention 시 thread_block() → schedule() → do_iret까지 이어지는 경로에서 RSP가 바뀌므로, GDB의 thread_current() 결과도 함께 변한다.
  • KVM 모드에서도 cli/sti는 VM exit을 유발하지 않는다 (guest 커널이 CPL 0에서 실행하므로).

GDB 관찰 스크립트

1. Lock 상태 한눈에 보기 — holder와 대기자 목록

(gdb) # lock 변수의 현재 상태 확인
(gdb) p *lock
(gdb) # holder가 누구인지
(gdb) p lock->holder->name
(gdb) p lock->holder->tid
(gdb) # semaphore의 현재 value (0이면 contended)
(gdb) p lock->semaphore.value

2. Lock contention 관찰 — acquire 시 대기

(gdb) b lock_acquire
(gdb) commands
  silent
  printf ">>> lock_acquire: tid=%d(%s) wants lock@%p, holder=", \
    thread_current()->tid, thread_current()->name, lock
  if lock->holder != 0
    printf "tid=%d(%s)\n", lock->holder->tid, lock->holder->name
  else
    printf "NONE (uncontended)\n"
  end
  continue
end

3. Priority donation 발동 관찰

(gdb) b lock_acquire if lock->holder != 0 && lock->holder->priority < thread_current()->priority
(gdb) commands
  silent
  printf "!!! DONATION: tid=%d(pri=%d) -> tid=%d(pri=%d) via lock@%p\n", \
    thread_current()->tid, thread_current()->priority, \
    lock->holder->tid, lock->holder->priority, lock
  continue
end

4. 중첩 donation chain 추적

(gdb) # 특정 스레드의 donation_list 순회
(gdb) set $t = thread_current()
(gdb) set $e = $t->donation_list.head.next
(gdb) while ($e != &$t->donation_list.tail)
  set $donor = (struct thread *)((char *)$e - offsetof(struct thread, donation_elem))
  printf "  donor: tid=%d name=%s pri=%d waiting_lock=%p\n", \
    $donor->tid, $donor->name, $donor->priority, $donor->waiting_lock
  set $e = $e->next
end

5. Lock release 시 priority 복원 관찰

(gdb) b lock_release
(gdb) commands
  silent
  set $before = thread_current()->priority
  # release 후 refresh_priority가 호출된다
  printf "<<< lock_release: tid=%d releasing lock@%p, pri_before=%d\n", \
    thread_current()->tid, lock, $before
  continue
end
(gdb) b refresh_priority
(gdb) commands
  silent
  set $t = t
  printf "    refresh_priority: tid=%d base=%d -> effective=%d\n", \
    $t->tid, $t->base_priority, $t->priority
  continue
end

6. 데드락 의심 탐지 — waiting_lock chain 순회

(gdb) # 현재 스레드부터 waiting_lock chain을 따라감
(gdb) set $curr = thread_current()
(gdb) set $depth = 0
(gdb) while ($curr->waiting_lock != 0 && $depth < 10)
  printf "depth %d: tid=%d waits on lock@%p held by tid=%d\n", \
    $depth, $curr->tid, $curr->waiting_lock, \
    $curr->waiting_lock->holder->tid
  set $curr = $curr->waiting_lock->holder
  set $depth = $depth + 1
end
(gdb) # $curr == 최초 스레드면 순환 = 데드락

항목값
struct lock 크기holder(8 bytes) + semaphore(~24 bytes) = ~32 bytes
semaphore 초기값1 (binary)
중첩 기부 최대 깊이8단계 (idx < 7 + 초기 기부 1)

순서도

flowchart TD
    subgraph "lock_acquire"
        A1[ASSERT: 재귀 아닌지 확인] --> A2{holder 있나?}
        A2 -->|Yes| A3[donation_list에 삽입]
        A3 --> A4[waiting_lock 설정]
        A4 --> A5[priority donation 전파]
        A5 --> A6[sema_down → 대기]
        A2 -->|No| A6
        A6 --> A7[waiting_lock = NULL]
        A7 --> A8[holder = curr]
    end

    subgraph "lock_release"
        R1[donation_list에서 이 lock 대기자 제거] --> R2[refresh_priority]
        R2 --> R3[holder = NULL]
        R3 --> R4[sema_up → 대기자 깨움]
    end
