장치 I/O 처리 — QEMU의 I/O 에뮬레이션

확인 범위: 이 문서는 장치 I/O 에뮬레이션의 일반 원리와 PintOS/QEMU 조합에서의 처리 흐름을 설명하는 개념 자료다. 제시된 코드 좌표, 콜백 경로·횟수, 타이머 주기 등 특정 구현에 의존하는 내용은 실제 소스 버전과 실행 기록 또는 측정으로 검증된 결과가 아니라 별도 확인이 필요한 설명이다.

PintOS가 in/out 명령어로 장치 포트에 접근하면 실제 장치가 아니라 QEMU의 콜백이 실행된다. 포트 번호와 MMIO 주소 범위를 기준으로 guest의 장치 접근을 소프트웨어 장치 모델에 연결하는 구조다.

장치 I/O 처리 상태

실제 PC에서 CPU는 in/out 명령어로 I/O 포트에 접근하거나, MMIO(Memory-Mapped I/O) 주소에 읽기/쓰기를 하여 장치와 통신한다. QEMU는 각 I/O 포트 번호와 MMIO 주소 범위에 대해 콜백 함수를 등록해 두고, guest OS가 해당 주소에 접근할 때 콜백을 호출하여 장치 동작을 소프트웨어로 재현한다. PintOS는 PIO(Port I/O) 방식만 사용하며, QEMU가 에뮬레이션하는 주요 장치는 PIT(타이머), PIC(인터럽트 컨트롤러), IDE(디스크), Serial(콘솔)이다.

x86 아키텍처에는 두 가지 I/O 방식이 있다:

방식명령어주소 공간특징

PintOS/QEMU 조합에서는 거의 모든 장치가 PIO를 사용한다. guest OS가 outb(0x1F0, data)를 실행하면, 실제 하드웨어에서는 CPU가 I/O 버스를 통해 IDE 컨트롤러에 데이터를 보내지만, QEMU에서는 TCG가 이 명령어를 가로채서 등록된 콜백을 호출한다.

3. 장치 모델의 상태 머신

각 장치 모델은 C 구조체로 내부 상태를 유지한다. I/O 콜백이 호출되면 이 상태를 갱신하고, 필요하면 인터럽트를 발생시킨다 (PIC 모델을 통해 guest CPU에 전달).

실제 OS (Linux)

Linux에서는 PIO보다 MMIO와 DMA가 지배적이다. 현대 NVMe 드라이버는 PCIe BAR 영역(MMIO)에 doorbell 레지스터를 쓰고, DMA로 데이터를 전송한다. QEMU는 MMIO도 MemoryRegion의 콜백으로 동일하게 에뮬레이션한다. PintOS의 PIO 방식은 1990년대 ISA 버스 시절의 접근법이다.
