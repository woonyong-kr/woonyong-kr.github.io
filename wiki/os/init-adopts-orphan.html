Orphan 입양

Orphan 입양

부모가 자식보다 먼저 종료하면 child_status의 소유자가 사라진다. PintOS는 이 레코드를 고아 상태로 표시해, 나중에 자식이 종료될 때 안전하게 회수한다.

Orphan 입양 변화

부모 프로세스가 자식보다 먼저 종료하면 자식은 고아(orphan) 가 된다. 이때 자식의 child_status 레코드는 더 이상 부모의 child_status_list에 속할 수 없다. 다른 곳에서 소유권을 인수하지 않으면 이 레코드는 해제되지 않아 메모리 누수가 발생한다.

PintOS는 고아가 된 레코드를 전역 orphan_status_list로 옮겨 관리한다. 이후 고아 자식이 종료되면 자신의 child_status를 직접 해제한다.

상세 설명

추상 개념

부모와 자식 프로세스의 종료 순서는 일정하지 않다. 부모가 wait하기 전에 자식이 먼저 종료될 수도 있고, 자식이 실행 중일 때 부모가 먼저 종료될 수도 있다. 이 가운데 부모가 먼저 종료해 자식의 상태를 관리할 주체가 사라지는 경우가 orphan 문제다.

따라서 부모가 사라진 뒤 자식의 child_status를 누가, 언제 해제할지 결정해야 한다. 종료 순서와 wait 여부에 따라 처리는 다음 세 가지로 나뉜다.

실제 OS (Linux/Windows)

Linux에서는 부모가 종료되면 자식이 init(PID 1) 또는 subreaper(prctl(PR_SET_CHILD_SUBREAPER))에게 입양된다. forget_original_parent() → find_new_reaper()가 새 부모를 결정하고, reparent_leader()가 자식의 parent를 변경한다. init은 주기적으로 waitpid(-1, ...)를 호출해 좀비를 수거한다.

Windows의 부모-자식 관계는 Linux보다 약하다. 프로세스 핸들을 명시적으로 닫지 않으면 커널 객체가 유지되며, 자원 관리가 핸들을 중심으로 이루어지므로 orphan의 의미도 다르다.

PintOS 구현

PintOS는 Linux처럼 자식을 새 부모에게 입양하지 않는다. 대신 전역 orphan_status_list에서 고아 레코드를 관리하는 단순한 방식을 사용한다.

자료구조

orphan_status_list_initialized는 전역 list가 lazy initialization을 마쳤는지만 나타내는 플래그다. 이 플래그가 레코드를 소유하는 것은 아니다. 실제 레코드는 부모의 child_status_list와 전역 orphan_status_list 가운데 한 곳에 속해야 한다.

부모 exit 시

부모가 process_exit()를 호출하면 reparent_or_reap_children()이 부모의 child_status_list를 순회한다.

자식이 이미 종료됐지만 부모가 wait하지 않았다면 부모가 child_status를 즉시 해제한다. 자식이 아직 실행 중이면 레코드에 고아 표시를 남기고 전역 리스트로 옮긴다.

조건의미처리
exited && !waited자식은 죽었지만 부모가 wait 안 함child_status 즉시 free (좀비 수거)
!exited자식이 아직 실행 중orphaned=true, orphan_status_list로 이동

자식 exit 시: finish_self_status()

고아가 된 자식이 나중에 종료하면 finish_self_status()가 종료 상태를 기록하고 대기 중인 실행 흐름에 신호를 보낸다. 이어서 레코드가 고아 상태이며 wait로 수거되지 않았는지 확인한다.

orphaned == true이면 상태를 수거할 부모가 없으므로 자식이 자신의 child_status를 직접 해제한다. PintOS에서는 이 처리가 Linux의 “init이 입양한다”는 동작에 대응하는 최소한의 구현이다.

process_exit() 호출 순서

process_exit()은 먼저 현재 프로세스가 소유한 자식들의 상태를 처리한 뒤, 현재 프로세스 자신의 상태를 마무리한다. 마지막에는 페이지 테이블을 비롯한 나머지 자원을 해제한다.

PintOS vs Linux 비교

Linux는 고아 자식의 부모를 바꾸고 새 부모가 wait로 상태를 수거한다. PintOS는 parent 포인터를 변경하지 않고, 전역 리스트와 orphaned 플래그를 이용해 레코드의 해제 시점을 관리한다.

항목LinuxPintOS
orphan 부모init(PID 1) 또는 subreaper없음 (전역 리스트)
wait 수거init이 waitpid(-1) 호출자식이 스스로 free
parent 포인터 변경task->parent 갱신없음 (orphaned 플래그만)
좀비 수거init의 wait loop부모 exit 시 즉시 free
