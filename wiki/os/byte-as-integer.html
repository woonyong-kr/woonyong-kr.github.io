바이트 정수 해석

바이트 정수 해석

한 줄 요약: little-endian으로 바이트를 정수로 해석하는 기본 방식 — GDB x/x·x/d로 확인.

바이트 정수 해석

메모리의 바이트 시퀀스를 정수로 해석하는 것은 가장 기본적인 해석 방식이다. x86-64는 little-endian이므로 LSB(Least Significant Byte)가 낮은 주소에 온다. GDB에서 x/x(hex), x/d(decimal), x/u(unsigned)로 같은 바이트를 보면 표현만 다를 뿐 같은 정수 값을 읽는다. OS 디버깅에서 정수 해석은 tid, priority, sector 번호, page offset, PTE 비트 필드 등 거의 모든 곳에서 필요하다.

상세 설명

추상 개념 (정수 인코딩 규칙)

x86-64의 정수 저장 규칙:

속성규칙
바이트 순서Little-endian: LSB가 낮은 주소
정렬자연 정렬 (4바이트 정수는 4의 배수 주소)
부호2의 보수 (signed), 그대로 (unsigned)
크기1, 2, 4, 8 바이트 (byte, word, dword, qword)

Little-endian 예제:

64비트 정수 0x0000000000001000 (= 4096)이 주소 0x8004e000에 저장:

주소:   0x8004e000  e001  e002  e003  e004  e005  e006  e007
바이트:     00       10    00    00    00    00    00    00
            ↑ LSB                                    ↑ MSB

GDB 출력:
(gdb) x/8bx 0x8004e000    → 0x00 0x10 0x00 0x00 0x00 0x00 0x00 0x00
(gdb) x/1gx 0x8004e000    → 0x0000000000001000
(gdb) x/1gd 0x8004e000    → 4096

세 명령어가 같은 8바이트를 읽지만, 표현 방식만 다르다.

크기별 해석 차이

같은 주소의 같은 바이트도 읽는 크기에 따라 다른 정수가 된다:

주소 0x8004e000의 내용: 05 00 00 00 03 00 00 00

(gdb) x/1bx 0x8004e000   → 0x05           (1바이트: 5)
(gdb) x/1hx 0x8004e000   → 0x0005         (2바이트: 5)
(gdb) x/1wx 0x8004e000   → 0x00000005     (4바이트: 5)
(gdb) x/1gx 0x8004e000   → 0x0000000300000005  (8바이트: 12884901893)

처음 4바이트가 tid=5, 다음 4바이트가 status=3(THREAD_BLOCKED)이라면:
(gdb) x/2wx 0x8004e000   → 0x00000005  0x00000003

이것이 “같은 바이트, 다른 해석”의 가장 기초적인 형태다. 4바이트 경계를 무시하고 8바이트로 읽으면 두 필드가 하나의 큰 정수로 합쳐져 의미 없는 값이 된다.

PintOS에서 정수로 해석하는 핵심 값들

OS 디버깅에서 자주 만나는 “바이트를 정수로 해석해야 하는” 상황들:

값크기범위/예시출현 위치
tid4 bytes1 ~ Nstruct thread offset 0
priority4 bytes0 ~ 63 (PRI_MIN ~ PRI_MAX)struct thread offset 8
wake_tick8 bytes0 ~ 2^63struct thread offset 16
sector 번호4 bytes (disk_sector_t)0 ~ 4,095 (2MB 디스크)inode_disk.start, free_map
page offset8 bytes (off_t)0 ~ file_lengthinode_read_at() 인자
PTE8 bytes (uint64_t)비트 필드PML4/PDPT/PD/PT 엔트리
syscall 번호8 bytes (RAX)0 ~ 21 (PintOS)intr_frame.R.rax
exit status4 bytes-1 ~ 255 관례process_exit() 인자

GDB 정수 포맷 비교

GDB에서 같은 메모리를 정수로 읽는 포맷들:

GDB 명령포맷예시 출력
x/wx addrhex 32-bit0x00000005
x/wd addrsigned decimal 32-bit5
x/wu addrunsigned decimal 32-bit5
x/gx addrhex 64-bit0x0000000000001000
x/gd addrsigned decimal 64-bit4096
x/bx addrhex 8-bit0x05

x = hex, d = signed decimal, u = unsigned decimal, t = binary, o = octal. b = byte(1), h = halfword(2), w = word(4), g = giant(8).

부호 해석의 차이

exit status처럼 signed/unsigned가 중요한 경우:

바이트: ff ff ff ff  (4바이트)

(gdb) x/1wd 0x...   → -1     (signed: 2의 보수)
(gdb) x/1wu 0x...   → 4294967295  (unsigned: 0xFFFFFFFF)

PintOS에서 exit(-1)은 실패를 의미한다.
struct child_status의 exit_code 필드가 0xFFFFFFFF이면
signed로 -1, unsigned로 약 43억. 해석 방식이 의미를 결정한다.

실제 OS (Linux)에서의 비교

Linux 커널에서도 동일한 바이트-정수 해석이 적용된다:

PintOSLinux정수 크기
thread->tidtask_struct->pid4 bytes (pid_t)
thread->prioritytask_struct->prio4 bytes (int)
inode_disk.startext4_inode->i_block[]4 bytes × N
PTE (8 bytes)PTE (8 bytes)동일한 하드웨어 포맷

Linux의 crash 디버거에서도 rd -d(decimal), rd -x(hex)로 같은 메모리를 다른 정수 포맷으로 읽는다.

QEMU 에뮬레이션

QEMU 입장에서 guest memory의 모든 것은 바이트이고, 정수 해석은 guest 코드가 한다:

  • guest가 MOV EAX, [addr]를 실행하면 QEMU softmmu가 4바이트를 읽어 EAX에 넣는다
  • 이때 little-endian 바이트 순서를 적용하는 것은 QEMU의 ld_le_p() (load little-endian) 함수
  • GDB stub이 x/wx를 처리할 때도 동일한 little-endian 변환을 적용
QEMU가 하는 것: 바이트 순서 적용 (little-endian → CPU 레지스터)
QEMU가 하지 않는 것: "이 4바이트가 tid인지 priority인지" 해석

바이트 정수 해석 값 추적

PintOS struct thread의 처음 24바이트를 정수로 해석하는 예제:

주소: 0x8004e000 (thread 페이지 시작)

offset  bytes (hex)                 정수 해석           의미 (PintOS만 앎)
------  --------------------------  -----------------  -------------------
0x00    05 00 00 00                 5                   tid = 5
0x04    01 00 00 00                 1                   status = THREAD_READY
0x08    1f 00 00 00                 31                  priority = 31 (PRI_DEFAULT)
0x0c    1f 00 00 00                 31                  base_priority = 31
0x10    00 00 00 00 00 00 00 00     0                   wake_tick = 0 (not sleeping)

QEMU가 아는 것: 0x8004e000에서 24바이트의 값
QEMU가 모르는 것: 이 바이트들이 어떤 구조체의 필드인지
GDB가 하는 것: 사용자가 지정한 크기/부호로 정수 표현

PTE를 정수로 읽는 예제:

PTE 값: 0x000000000800B067

비트 분해 (정수 → 비트 필드 해석):
  bit 0 (Present):  1  → 페이지 존재
  bit 1 (Writable): 1  → 쓰기 가능
  bit 2 (User):     1  → 유저 접근 가능
  bit 5 (Accessed): 1  → 접근됨
  bit 6 (Dirty):    1  → 수정됨
  bits 12-51 (PFN): 0x800B → 물리 프레임 번호
  물리 주소: 0x800B × 4096 = 0x800B000

같은 8바이트 정수 0x0800B067이:
  - hex로는: 0x0800B067
  - decimal로는: 134,258,791
  - 비트 필드로는: Present+Writable+User+Accessed+Dirty, PFN=0x800B
해석 방식에 따라 완전히 다른 정보가 된다.
