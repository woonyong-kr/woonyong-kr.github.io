pml4_clear_page — PTE에서 present 비트 제거

pml4_clear_page — PTE에서 present 비트 제거

확인 범위: 이 문서는 PTE의 present 비트 제거와 TLB 무효화에 관한 일반 원리와 선택 기준을 설명하고, 제시된 PintOS·Linux·QEMU 코드와 동작을 구현 사례로 다룬다. 코드 위치·호출 관계·버전별 동작과 실행 기록·성능 수치는 해당 소스 및 측정 환경에서 별도로 검증해야 한다.

한 줄 요약: pml4_clear_page()는 특정 유저 VA의 PTE에서 present 비트만 끄고 나머지 비트는 보존해, eviction·munmap·exit에서 물리 프레임 해제 전 매핑을 안전하게 끊는다.

pml4_clear_page 상태

pml4_clear_page()는 4단계 page table에서 특정 유저 가상 주소의 PTE를 찾아 present 비트(PTE_P)를 끄는 함수다. 이후 해당 주소에 접근하면 page fault가 발생한다. frame eviction, munmap, process exit 등 “가상 주소 ↔ 물리 프레임 매핑을 끊어야 하는” 모든 상황에서 사용된다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 MMU는 가상 주소 접근 시 PML4 → PDPT → PD → PT 4단계를 walk한다. 최종 PTE의 bit 0(Present)이 0이면 pf(page fault) 예외를 발생시킨다. OS가 매핑을 끊을 때는 물리 프레임을 해제하기 전에 반드시 PTE_P를 0으로 만들어야 한다. 그래야 다른 스레드/프로세스가 해제된 프레임에 접근하지 못한다.

중요한 점: PTE_P만 끄고 나머지 비트는 보존한다. dirty, accessed, writable 등의 비트가 남아 있으면, 나중에 swap-in 등에서 복원 시 참고할 수 있다.

TLB 무효화

PTE를 수정한 뒤에도 TLB에 이전 매핑이 캐싱되어 있을 수 있다. 현재 프로세스의 CR3와 수정한 PML4가 같다면(= 현재 실행 중인 프로세스의 page table이라면), invlpg 명령으로 해당 가상 주소의 TLB 엔트리를 무효화해야 한다. 다른 프로세스의 page table이면 그 프로세스가 다음에 CR3를 로드할 때 TLB가 전부 flush되므로 invlpg가 필요 없다.

실제 OS (Linux)

Linux에서는 pte_clear() 매크로가 PTE를 0으로 초기화한다. PintOS와 달리 PTE 전체를 0으로 만들어 버린다. TLB 무효화는 flush_tlb_page() 또는 멀티코어 환경에서 flush_tlb_others()(IPI 기반)로 수행한다. 멀티코어에서는 다른 코어의 TLB도 무효화해야 하므로 IPI(Inter-Processor Interrupt)를 보내는 비용이 추가된다.

PintOS 구현

단계별 동작:

  1. pg_ofs(upage) == 0 — upage가 4 KiB 경계에 정렬되었는지 확인
  2. is_user_vaddr(upage) — 커널 주소가 아닌지 확인 (0 ~ KERN_BASE 미만)
  3. pml4e_walk(pml4, upage, false) — 4단계 walk. false = 중간 테이블 없으면 생성하지 않음
  4. PTE가 존재하고 PTE_P가 켜져 있으면, ~PTE_P 비트마스크로 present만 끔
  5. rcr3() = 현재 CR3 레지스터 값, vtop(pml4) = pml4의 물리 주소. 같으면 현재 프로세스이므로 invlpg 실행

pml4_clear_page 값 추적

PTE_P = bit 0 = 0x1

PTE 원본:  0x0000000004005067
           = ...0110 0111 (binary 하위 12비트)
           P=1, W=1, U=1, A=1, D=1

~PTE_P:    0xFFFFFFFFFFFFFFFE

PTE & ~PTE_P: 0x0000000004005066
              = ...0110 0110
              P=0, 나머지 동일

invlpg 명령은 단일 TLB 엔트리만 무효화하므로 전체 TLB flush보다 훨씬 가볍다. x86-64에서 invlpg는 약 100~300 사이클, 전체 TLB flush(CR3 재로드)는 수천 사이클이다.

순서도

flowchart TD
    A["pml4_clear_page(pml4, upage)"] --> B["ASSERT: page-aligned & user vaddr"]
    B --> C["pml4e_walk(pml4, upage, false)"]
    C --> D{PTE 찾았나?}
    D -- NULL --> E[return — 매핑 자체가 없음]
    D -- "pte != NULL" --> F{"*pte & PTE_P?"}
    F -- 0 --> G[return — 이미 not present]
    F -- 1 --> H["*pte &= ~PTE_P"]
    H --> I{"rcr3() == vtop(pml4)?"}
    I -- Yes --> J["invlpg(upage) — TLB 무효화"]
    I -- No --> K[return — 다른 프로세스, TLB 무효화 불필요]

QEMU 에뮬레이션

QEMU TCG 모드에서 *pte &= ~PTE_P는 일반적인 메모리 쓰기로 처리된다. QEMU는 guest의 page table 수정을 직접 감시하지 않는다. 대신 invlpg 명령어를 만나면 QEMU의 소프트웨어 TLB(env->tlb_table)에서 해당 엔트리를 무효화한다. QEMU의 tlb_flush_page() 함수가 이를 처리한다.

만약 invlpg를 빼먹으면? 실제 하드웨어에서는 stale TLB 엔트리로 해제된 프레임에 접근하는 보안 버그가 발생한다. QEMU TCG에서도 소프트웨어 TLB가 stale 상태로 남아 동일한 증상이 재현되므로, QEMU에서도 디버깅이 가능하다.

pml4_clear_page와 dirty/accessed 비트

*pte &= ~PTE_P는 bit 0만 끄고 나머지 비트를 보존한다. 이것이 중요한 이유:

PintOS에서는 eviction 시 pml4_is_dirty()를 먼저 호출한 뒤 pml4_clear_page()를 호출하는 순서를 지켜야 한다. 혹은 dirty 정보를 struct page에 별도로 저장해두는 방식도 가능하다.

COW(Copy-on-Write)와의 관계

COW에서 pml4_clear_page는 사용되지 않는다. COW는 PTE의 writable bit만 끄는 방식(*pte &= ~PTE_W)을 사용한다. present는 유지되므로 읽기 접근은 정상이고, 쓰기 접근 시에만 write-protect pf가 발생한다. 반면 pml4_clear_page는 present를 끄므로 읽기도 쓰기도 모두 pf가 발생한다.

연산변경 비트읽기 접근쓰기 접근사용 상황
pml4_clear_pagePTE_P → 0pfpfeviction, munmap, exit
COW (writable off)PTE_W → 0정상write-protect pffork

pml4_clear_page → swap_in 전체 사이클

매핑 해제부터 재매핑까지의 전체 lifecycle:

sequenceDiagram
    participant EV as vm_evict_frame
    participant CLR as pml4_clear_page
    participant SO as swap_out
    participant PF as page_fault_handler
    participant SI as swap_in
    participant SET as pml4_set_page

    EV->>CLR: pml4_clear_page(victim_pml4, va)
    Note over CLR: PTE_P=0, invlpg(va)
    EV->>SO: swap_out(page) → 디스크에 기록
    Note over EV: page->frame = NULL

    Note over PF: ... 시간 경과 ...

    PF->>PF: 유저가 va에 접근 → #PF 발생
    PF->>SI: vm_try_handle_fault → swap_in(page)
    SI->>SI: 새 frame 할당, 디스크에서 읽기
    SI->>SET: pml4_set_page(pml4, va, new_kva, writable)
    Note over SET: PTE_P=1, 새 프레임 매핑 완료
