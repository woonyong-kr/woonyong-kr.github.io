Stack과 Heap — 프로그램 메모리는 어떻게 나뉘는가

Stack과 Heap — 프로그램 메모리는 어떻게 나뉘는가

확인 범위: 이 문서는 Stack과 Heap을 비롯한 프로그램 메모리 영역의 일반 개념과 선택 기준을 설명한다. PintOS 관련 내용은 제시된 코드와 구조를 바탕으로 한 특정 구현 사례다. Linux 기본값, 주소 배치, 할당 범위, 동작·성능에 관한 판단은 실제 환경의 코드와 버전, 실행 기록 및 측정으로 별도 검증해야 한다.

한 줄 요약: 프로그램이 실행 중 사용하는 메모리는 용도에 따라 영역이 나뉜다. Stack은 함수 호출에 따라 자동으로 자라고 줄어들며, Heap은 프로그래머가 직접 요청해 할당하고 해제한다.

Stack과 Heap 혼동

프로그램이 실행되면 OS는 프로그램에 가상 주소 공간을 할당한다. 이 공간은 하나의 평평한 바이트 배열이 아니라 용도에 따라 여러 영역으로 나뉜다. 이러한 구분을 알아야 다음 질문에 답할 수 있다.

  • 지역 변수는 왜 함수가 끝나면 사라지는가
  • malloc()으로 잡은 메모리는 왜 직접 free()해야 하는가
  • 스택 오버플로우와 힙 메모리 누수는 어떤 영역에서 일어나는 문제인가
  • PintOS에서 커널 스택이 4KB뿐인 이유는 무엇인가

프로그램 메모리를 이루는 Text, Data, BSS, Heap, Stack의 역할부터 살펴보면 Stack과 Heap의 성장 방향, 할당 방식, 생애주기가 어떻게 다른지 설명할 수 있다.

Stack과 Heap 차이

프로그램 메모리의 다섯 영역

프로세스 하나의 가상 주소 공간은 아래에서 위로 다음과 같이 배치된다.

  • 높은 주소

  • Stack | ← 함수 호출마다 아래로 자란다

  • ↓

  • (빈 공간 — 여유)

  • ↑

  • Heap | ← malloc() 호출마다 위로 자란다

  • BSS | ← 초기화 안 된 전역/정적 변수 (0으로 채움)

  • Data | ← 초기값이 있는 전역/정적 변수

  • Text (Code) | ← 기계어 명령어 (읽기 전용)

  • 낮은 주소

  • Text: 컴파일된 기계어 명령어가 들어간다. CPU의 RIP 레지스터가 이 영역을 가리키며 명령어를 가져간다. 읽기 전용이다.

  • Data: 초기값이 있는 전역 변수와 정적 변수가 놓인다. ELF 파일에 초기값이 기록되어 있으며, 로드할 때 그대로 복사된다.

  • BSS (Block Started by Symbol): 초기값이 없는 전역 변수와 정적 변수가 놓인다. 실행을 시작할 때 OS가 0으로 채운다. ELF에는 크기만 기록되므로 파일 크기를 줄일 수 있다.

  • Heap: 프로그래머가 malloc(), calloc(), new 등으로 명시적으로 요청하는 동적 메모리 영역이다. 낮은 주소에서 높은 주소 방향으로 자란다.

  • Stack: 함수 호출마다 프레임이 자동으로 쌓이는 영역이다. 높은 주소에서 낮은 주소 방향으로 자라며, 함수가 반환되면 해당 프레임이 사라진다.

Stack — 함수 호출의 자동 기록판

Stack은 LIFO(Last-In, First-Out) 구조로 동작한다. 함수를 호출하면 스택 프레임(stack frame)이 하나 쌓이고, 함수가 반환되면 그 프레임 전체가 사라진다.

하나의 스택 프레임에는 다음 정보가 들어간다.

  • 함수의 지역 변수
  • 함수 인자 (x86-64에서는 처음 6개를 레지스터로 전달하고 나머지를 스택에 둔다)
  • 리턴 주소 (함수가 끝나면 돌아갈 명령어 주소)
  • 이전 프레임 포인터 (RBP)

스택의 꼭대기는 RSP(Stack Pointer) 레지스터가 추적한다. 함수를 호출하면 RSP가 내려가고, 함수가 반환되면 올라간다. 프로그래머가 할당과 해제를 직접 관리할 필요는 없지만 사용할 수 있는 크기에는 제한이 있다. Linux의 기본 스택 크기는 보통 8MB이고, PintOS의 커널 스택은 4KB뿐이다.

재귀 호출이 너무 깊거나 지역 변수가 너무 크면 스택 오버플로우가 발생한다. 스택이 허용 범위를 넘어서면 OS가 프로세스를 종료시킨다(segfault).

Heap — 프로그래머가 직접 관리하는 창고

Heap에서는 프로그래머가 필요한 크기를 요청하고, 할당기(allocator)가 빈 공간을 찾아 돌려준다. 대표적인 함수가 malloc()이다.

  • 할당: malloc(size) → 할당기가 빈 블록을 찾아 포인터를 반환한다.
  • 해제: free(ptr) → 해당 블록을 빈 블록 목록에 돌려놓는다.
  • 수명: 명시적으로 free()하거나 프로세스가 종료될 때까지 유지된다.

Heap에서는 메모리의 크기와 수명을 자유롭게 조절할 수 있다. 다만 프로그래머가 해제를 잊으면 메모리 누수가 생기고, 이미 해제한 메모리를 다시 사용하면 Use After Free 버그가 발생한다.

Linux/Windows 실제 OS와 PintOS의 차이

**실제 OS (Linux)**에서는 유저 프로세스마다 독립된 가상 주소 공간이 있다. 그 안에 Text, Data, BSS, Heap, Stack이 배치된다. Heap은 brk()/sbrk() 시스템 콜로 확장하며, 큰 할당에는 mmap()으로 별도 영역을 잡는다. Stack은 page fault가 발생하면 OS가 자동으로 페이지를 추가해 성장시킨다.

PintOS에는 두 종류의 스택이 있다.

  • 커널 스택: 스레드 하나당 4KB 페이지 하나를 사용하며, 그 안에 struct thread와 커널 스택이 함께 들어간다. struct thread는 페이지 바닥(오프셋 0)에 놓이고, 커널 스택은 페이지 꼭대기(오프셋 4KB)에서 아래로 자란다. 커널 함수에서 큰 지역 변수를 선언해 스택이 지나치게 커지면 magic 값을 덮어쓰므로 스택 오버플로우를 감지할 수 있다.
  • 유저 스택: Project 2부터 유저 프로그램이 실행될 때 USER_STACK(0x47480000) 아래에 유저 스택이 배치된다. Project 3에서는 page fault 기반 스택 성장을 구현한다.

PintOS의 Heap은 커널 레벨에만 존재한다. palloc_get_page()가 페이지 단위로 물리 메모리를 할당하고, malloc()이 그 위에서 더 작은 블록 단위의 할당을 제공한다.

PintOS 커널 스택: struct thread와 4KB 페이지

struct thread는 페이지 바닥에 놓이고, 커널 스택은 꼭대기에서 아래로 자란다. 둘 사이에는 magic 필드(0xcd6abf4b)가 있다. 스택이 너무 자라면 이 값이 덮어씌워지고, thread_current()가 호출될 때마다 값을 검사해 스택 오버플로우를 감지한다.

이 구조 때문에 PintOS 커널 함수에서는 큰 배열을 지역 변수로 선언하면 안 된다. 대신 malloc()이나 palloc_get_page()를 사용해야 한다.

PintOS 커널 Heap: malloc()의 arena 구조

PintOS의 malloc()은 요청 크기를 2의 거듭제곱으로 올림한 뒤 해당 크기의 desc에서 빈 블록을 찾는다. 빈 블록이 없으면 palloc_get_page()로 새 페이지(arena)를 가져와 여러 블록으로 나눈다. desc가 다루는 블록 크기는 16바이트부터 1024바이트까지다. 이는 PGSIZE / 2 = 2048 미만에 해당하므로 최대 크기는 1024바이트다. 따라서 1KB(1024바이트)를 넘는 요청은 desc에 맞지 않으며, palloc_get_multiple()로 arena 헤더를 포함한 연속 페이지를 직접 할당한다. free()는 블록을 desc의 free list에 반환한다. arena 안의 모든 블록이 비면 arena 자체도 palloc에 돌려준다.

PintOS 물리 메모리 풀: palloc

PintOS는 물리 메모리를 커널 풀과 유저 풀로 나누고, 기본적으로 시스템 RAM의 절반씩 배분한다. 커널 풀에서 할당한 페이지는 스레드나 페이지 테이블 같은 커널 자료구조에 사용한다. 유저 풀에서 할당한 페이지는 유저 프로세스의 페이지에 사용한다. 두 풀을 분리하면 유저 프로세스가 메모리를 과도하게 사용하더라도 커널이 동작하는 데 필요한 메모리를 보장할 수 있다.

정리

프로그램의 메모리는 Text(코드), Data(초기화된 전역), BSS(초기화 안 된 전역), Heap(동적 할당), Stack(함수 호출)으로 나뉜다. Stack은 RSP를 이동하는 방식으로 빠르게 자라고 줄어들지만 크기가 제한된다. Heap은 크기와 수명을 유연하게 조절할 수 있는 대신 빈 블록을 찾는 비용, 단편화, 수동 관리의 부담이 따른다.

PintOS에서는 이 차이가 커널 스택과 커널 Heap의 구조에 드러난다. 커널 스택은 스레드당 4KB 페이지 안에서 struct thread와 공간을 공유한다. 커널 Heap은 palloc → malloc의 2단 구조로 동작한다. 이 구조를 이해하면 커널 함수에서 큰 지역 변수를 피해야 하는 이유와 malloc()과 free()를 짝지어 사용해야 하는 이유를 판단할 수 있다.
