COW — PTE Writable 비트 해제

COW — PTE Writable 비트 해제

확인 범위: 이 문서는 PTE writable 비트 해제와 write fault를 이용하는 COW의 일반 원리와 선택 기준을 설명하고, Linux 및 COW를 추가한 현재 로컬 PintOS branch의 구현 흐름을 예시로 구분해 다룬다. 제시된 코드 좌표, 비트 값, 실행 흐름, 메모리 절약 수치는 특정 소스 버전이나 실제 실행·성능 측정으로 검증한 결과가 아니므로, 해당 판단에는 대상 코드와 버전, 실행 기록 및 측정 결과를 별도로 확인해야 한다.

한 줄 요약: Copy-on-Write는 fork 시 부모·자식 PTE의 writable 비트를 0으로 꺼 같은 프레임을 공유하다가, 누군가 쓰려 할 때 발생하는 page fault에서 비로소 프레임을 복제한다.

COW 상태

Copy-on-Write(COW)의 핵심 트리거는 PTE의 writable bit(bit 1, PTE_W)를 0으로 설정하는 것이다. fork 시 부모와 자식이 같은 물리 프레임을 공유하면서 양쪽 PTE 모두 read-only로 만든다. 이후 어느 쪽이든 해당 페이지에 쓰기를 시도하면 MMU가 write protection fault(#PF, error code에 PF_W=1, PF_P=1)를 발생시키고, OS의 page fault handler가 이를 감지하여 프레임을 복사하고 새 프레임에 writable PTE를 설정한다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 PTE의 writable bit:

PTE (64-bit):
bit 0: Present (P)    — 1이면 유효한 매핑
bit 1: Writable (W)   — 1이면 쓰기 허용, 0이면 읽기 전용
bit 2: User (U)       — 1이면 유저 모드 접근 허용
...
bit 63-12: 물리 프레임 번호 (상위 비트)

MMU의 쓰기 검사 흐름:

  1. CPU가 MOV [addr], val 같은 쓰기 명령 실행
  2. MMU가 4단계 page table walk 수행
  3. walk 경로의 모든 레벨(PML4E, PDPTE, PDE, PTE)에서 W bit 확인
  4. 어느 레벨이든 W=0이면 #PF 발생, error code의 bit 1(PF_W) = 1
  5. error code의 bit 0(PF_P)도 1 — 페이지 자체는 present하지만 쓰기 보호 위반

이 하드웨어 동작이 COW를 가능하게 한다. OS는 pf handler에서 error code를 분석하여:

  • PF_P=1, PF_W=1 → present page에 대한 write fault → COW 후보
  • PF_P=0 → not present → demand paging (다른 경로)

실제 OS (Linux)

Linux의 COW 구현:

fork 시 PTE 복사 (copy_page_range → copy_one_pte):

  • 부모 PTE에서 writable bit 제거: ptep_set_writable(pte, 0)
  • 자식 PTE도 동일하게 read-only로 설정
  • 물리 프레임의 reference count 증가: page_ref_inc(page) (mapcount)
  • VM_WRITE vma flag는 유지 — “원래는 쓸 수 있었다”는 정보 보존

write fault 처리 (do_wp_page):

  • page의 mapcount가 1이면 → 다른 공유자 없음 → PTE에 writable 복원 (reuse)
  • mapcount > 1이면 → 새 프레임 할당 → 내용 복사 → 새 PTE(writable) 설치 → 원본 프레임 mapcount 감소

PintOS 구현

기본 과제 skeleton 또는 upstream PintOS에는 COW가 없으며, __do_fork() → supplemental_page_table_copy()에서 페이지를 즉시 복사한다. 아래 설명의 기준은 COW를 추가한 현재 로컬 branch다. 이 branch의 fork 경로는 __do_fork() → supplemental_page_table_copy() → anon_copy()로 내려가며, resident anonymous page는 즉시 복사하지 않고 같은 frame을 공유한다.

핵심은 SPT의 원래 쓰기 가능성(page->writable)은 유지하면서, 실제 PTE만 잠시 read-only로 설치하는 것이다.

1. PTE writable bit를 끄는 기본 도구

pml4_set_page()는 마지막 인자 rw가 false이면 PTE를 present/user로만 설치하고 PTE_W를 넣지 않는다.

2. fork 시 부모/자식 PTE를 read-only로 전환

anon_copy()는 resident page를 만나면 같은 frame->kva를 부모와 자식에게 read-only로 매핑한다.

이때 dst_page->writable은 src_page->writable에서 복사된다. 즉 PTE는 read-only지만 SPT metadata는 “원래 writable page”라는 사실을 보존한다.

3. write fault handler에서 COW 감지

PTE가 present인데 write 권한 때문에 fault가 나면 vm_handle_write_protect_fault()가 SPT에서 page를 찾고 vm_handle_wp()로 넘긴다.

여기서 page->writable == false이면 진짜 read-only page이므로 살리지 않는다. page->writable == true이고 frame이 공유 중이면 COW로 처리한다.

COW 동작에서 주의할 엣지 케이스

상황처리
fork 후 exec자식이 exec하면 주소 공간 전체 교체 → COW 프레임 해제, ref count 감소
다중 fork (A→B→C)같은 프레임을 3개 프로세스가 공유, ref count=3, 어느 쪽이 쓰든 개별 복사
read-only 페이지의 fork원래 read-only면 W=0 유지, COW 표시 불필요 (write fault → kill)
COW + evictioneviction 시 ref count>1인 프레임은 공유 중 → swap out 전략 필요
커널 스택 페이지커널 스택은 프로세스별 독립 → COW 대상 아님, 항상 즉시 복사

COW 값 추적

COW의 메모리 절약 예:

시나리오: 프로세스가 100 페이지(400 KB) 사용 중 fork → exec

Eager copy:
  fork: 100 페이지 복사 = 100 × 4 KB = 400 KB 할당 + 400 KB 복사
  exec: 100 페이지 즉시 해제 → 낭비
  총 비용: 400 KB 임시 할당 + 400 KB memcpy

COW:
  fork: 100 PTE 수정 (W bit 해제) = 100 × 8 byte PTE 수정
  exec: ref count만 100번 감소, 부모 PTE W bit 복원
  총 비용: 800 byte PTE 수정 + ref count 조작
  절약: ~99.8%

PTE writable bit 위치:

PTE 값 예시:
  0x0000000004205067  (P=1, W=1, U=1, A=1, D=1, frame=0x4205)

COW 전환 후:
  0x0000000004205065  (P=1, W=0, U=1, A=1, D=1, frame=0x4205)
                  ^
              bit 1: 1→0 (PTE_W 해제)

순서도

flowchart TD
    A[fork 호출] --> B[부모 PTE 순회]
    B --> C{PTE present?}
    C -- No --> B
    C -- Yes --> D{원래 writable?}
    D -- No --> E[자식 PTE 그대로 복사]
    D -- Yes --> F["부모 PTE: W bit → 0"]
    F --> G["자식 PTE: 같은 PA, W=0"]
    G --> H[frame ref count++]
    H --> I[invlpg 부모 TLB]
    I --> B

    J[자식이 해당 VA에 write] --> K["#PF: PF_P=1, PF_W=1"]
    K --> L{SPT에서 원래 writable?}
    L -- No --> M[segfault → kill]
    L -- Yes --> N{frame ref count}
    N -- "== 1" --> O[PTE W bit 복원]
    N -- "> 1" --> P[새 frame 할당]
    P --> Q[memcpy 4KB]
    Q --> R["새 PTE 설치 (W=1)"]
    R --> S[원본 frame ref count--]

COW 점검

  • PTE_W=0은 COW의 신호일 수 있지만, 그 자체로 COW라는 뜻은 아니다.
  • COW 판별에는 PTE 상태와 SPT metadata가 함께 필요하다. PintOS에서는 page->writable이 원래 쓰기 가능한 page였는지 알려 준다.
  • fork 시 anon_copy()는 부모와 자식 PTE를 모두 read-only로 만들고 vm_frame_add_owner()로 공유 frame의 owner/ref_count를 늘린다.
  • 첫 write fault가 오면 vm_handle_wp()가 진짜 read-only page를 걸러내고, vm_handle_cow()가 ref_count로 복사 여부를 결정한다.
  • pml4_clear_page() 뒤 pml4_set_page()로 PTE를 다시 설치하면 이전 writable TLB entry가 남아 있는 문제도 함께 정리된다.
