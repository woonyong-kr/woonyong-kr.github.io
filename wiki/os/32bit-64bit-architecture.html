32비트와 64비트 아키텍처

32비트와 64비트 아키텍처

확인 범위: 이 문서는 32비트와 64비트 아키텍처의 주소 공간, 정수 연산, ABI, 페이지 테이블에 관한 일반 원리를 설명하고 이를 PintOS, x86-64, QEMU 사례에 연결한다. 제시된 코드·주소·페이지 테이블 구성은 특정 구현의 실제 버전이나 실행 기록을 검증한 결과가 아니며, 구현별 동작과 성능을 판단하려면 해당 코드 버전, 실행 환경, 측정 결과를 별도로 확인해야 한다.

한 줄 요약: “32비트”와 “64비트”는 CPU 범용 레지스터의 폭을 말하며, 이 폭이 주소 공간 크기, 페이지 테이블 깊이, 정수 연산 범위, ABI 전체를 결정한다.

32비트와 64비트 아키텍처 문제

PintOS는 x86-64(64비트) 위에서 돌아간다. 코드를 읽다 보면 uint64_t, uint32_t, 4단계 페이지 테이블, KERN_BASE 0x8004000000 같은 값이 등장한다. 이 숫자들이 왜 그 크기인지 이해하려면 “비트 폭”이 무엇을 결정하는지 먼저 알아야 한다.

32비트와 64비트의 차이를 모르면 다음을 이해하지 못한다.

  • 가상 주소 공간이 왜 4GB(32비트) 또는 256TB(48비트 유효)로 제한되는지
  • 페이지 테이블이 왜 2단계(32비트)에서 4단계(64비트)로 바뀌는지
  • 레지스터 이름이 왜 EAX에서 RAX로 확장되는지
  • PintOS의 LOADER_KERN_BASE가 왜 0x8004000000처럼 큰 값인지

32비트와 64비트 아키텍처 차이

비트 폭이란

“32비트 CPU”란 범용 레지스터(General Purpose Register)의 폭이 32비트라는 뜻이다. 레지스터 하나에 32개의 0/1을 담을 수 있다. 64비트 CPU는 64개를 담는다.

비유하면, 레지스터는 CPU가 계산할 때 쓰는 손바닥이다. 32비트는 한 손에 32자리 이진수를 올릴 수 있고, 64비트는 64자리를 올릴 수 있다. 손바닥이 넓을수록 한 번에 더 큰 숫자, 더 먼 주소를 다룬다.

레지스터 폭이 결정하는 세 가지

레지스터 폭은 단순히 “빠르다/느리다”가 아니라 시스템 설계 전체를 바꾼다.

  • 주소 공간 크기
    • 32비트 → 주소 버스 32비트 → 표현 가능한 주소 = 2^32 = 4,294,967,296 = 4GB
    • 64비트 → 이론상 2^64 = 16EB(엑사바이트). 실제로 x86-64는 48비트만 사용하므로 2^48 = 256TB
  • 정수 연산 범위
    • 32비트 → 한 번의 ADD 명령으로 최대 약 43억(2^32 - 1)까지 계산
    • 64비트 → 한 번의 ADD 명령으로 최대 약 1844경(2^64 - 1)까지 계산
  • ABI와 호출 규약
    • 32비트 x86 → 인자를 스택에 push
    • 64비트 x86-64 → 처음 6개 인자를 RDI, RSI, RDX, RCX, R8, R9 레지스터로 전달

왜 주소 공간이 4GB에서 256TB로 뛰는가?

주소 = 레지스터 한 개에 담긴 이진수다. 레지스터가 32비트이면 표현 가능한 서로 다른 주소 수는:

2^32 = 4,294,967,296 (약 4GB)

32비트 시스템에서 프로세스가 볼 수 있는 가상 주소 공간은 최대 4GB다. 커널이 상위 12GB를 가져가면 유저 프로그램은 23GB밖에 쓸 수 없다.

64비트 시스템에서 이론상 주소 공간은:

2^64 = 18,446,744,073,709,551,616 (약 16EB)

그러나 16EB는 현실에서 필요하지 않다. 물리 메모리가 그만큼 없기 때문이다. x86-64는 가상 주소의 하위 48비트만 유효하게 사용하고, 나머지 상위 16비트는 47번째 비트의 부호 확장(sign extension)으로 채운다.

유효 가상 주소 공간 = 2^48 = 256TB
유저 영역: 0x0000_0000_0000_0000 ~ 0x0000_7FFF_FFFF_FFFF (128TB)
커널 영역: 0xFFFF_8000_0000_0000 ~ 0xFFFF_FFFF_FFFF_FFFF (128TB)
중간 구멍: canonical hole (사용 불가 영역)

왜 페이지 테이블이 2단계에서 4단계로 바뀌는가?

32비트 x86에서 4KB 페이지를 관리하려면:

전체 주소 32비트 = 10비트(PD 인덱스) + 10비트(PT 인덱스) + 12비트(오프셋)
→ 2단계 테이블: Page Directory + Page Table

64비트 x86-64에서 48비트 유효 주소를 관리하려면:

유효 주소 48비트 = 9비트(PML4) + 9비트(PDPT) + 9비트(PD) + 9비트(PT) + 12비트(오프셋)
→ 4단계 테이블: PML4 → PDPT → PD → PT → 물리 프레임

각 테이블은 512개(2^9) 엔트리를 가진다. 엔트리 하나가 8바이트이므로 테이블 하나는 512 × 8 = 4096바이트 = 정확히 1페이지(4KB)에 들어간다.

레지스터 이름의 확장

x86 → x86-64로 넘어가면서 레지스터가 확장되었다.

  • 32비트 범용 레지스터: EAX, EBX, ECX, EDX, ESI, EDI, EBP, ESP (8개)
  • 64비트 범용 레지스터: RAX, RBX, RCX, RDX, RSI, RDI, RBP, RSP + R8~R15 (16개)

“E”는 Extended(32비트 확장), “R”은 Register(64비트 확장)를 뜻한다. RAX의 하위 32비트가 EAX, 하위 16비트가 AX, 하위 8비트가 AL이다.

%% RAX 레지스터 하위 이름 구조
flowchart LR
  rax["RAX<br/>64비트 범용 레지스터<br/>비트 63..32<br/>상위 32비트 &#124; 비트 31..16<br/>EAX의 상위 부분 &#124; 비트 15..8<br/>AH &#124; 비트 7..0<br/>AL<br/>&#124; EAX<br/>하위 32비트<br/>&#124; &#124; AX"]

64비트에서 R8~R15가 추가로 8개 더 생겼다. 레지스터가 많아지면 함수 호출 시 인자를 스택 대신 레지스터로 전달할 수 있어 빨라진다.

실제 OS와 PintOS의 차이

  • Linux / Windows (64비트)
    • 5단계 페이지 테이블(LA57)을 지원하는 CPU도 있다. 이 경우 유효 주소가 57비트로 확장되어 128PB까지 가능하다. 대부분의 현재 시스템은 48비트(4단계)를 사용한다.
    • 커널과 유저 주소 분리에 KASLR(Kernel Address Space Layout Randomization)을 적용한다.
  • PintOS (x86-64)
    • 4단계 페이지 테이블(PML4)을 사용한다.
    • 커널 주소 시작점 KERN_BASE는 0x8004000000이다. 이 값은 x86-64의 canonical 주소 규칙을 따르면서 PintOS가 정한 고정값이다.
    • 물리 메모리를 KERN_BASE 위에 직접 매핑(identity mapping + offset)한다.
  • QEMU
    • 게스트 CPU가 64비트 long mode로 동작하도록 에뮬레이션한다. QEMU의 TCG(Tiny Code Generator)가 게스트 x86-64 명령어를 호스트 명령어로 변환할 때, 64비트 레지스터 폭과 4단계 페이지 테이블 워크를 그대로 재현한다.

32비트와 64비트 아키텍처 코드

PintOS의 주소 폭: 64비트 포인터와 KERN_BASE

이 값은 32비트 주소로는 표현 불가능하다. 0x8004000000은 약 34GB 위치로, 32비트의 4GB 한계를 넘는다. PintOS가 x86-64(64비트)에서 돌아가기 때문에 이 주소를 쓸 수 있다.

ptov와 vtop에서 물리↔가상 변환이 단순 덧셈/뺄셈인 이유는 커널 영역이 물리 메모리를 고정 오프셋으로 직접 매핑하기 때문이다. 이 오프셋이 KERN_BASE이고, 64비트 주소 공간이 넉넉하기에 가능하다.

PintOS의 4단계 페이지 테이블: 9비트씩 쪼개기

0x1FF는 이진수 111111111 = 9비트 마스크다. 64비트 가상 주소를 9비트씩 4번 쪼개서 각 테이블의 인덱스로 사용한다. 32비트였다면 10비트씩 2번만 쪼개면 되었을 것이다.

정리

32비트와 64비트는 CPU 레지스터의 폭이다. 이 폭이 주소 공간 크기(4GB → 256TB), 페이지 테이블 깊이(2단계 → 4단계), 레지스터 개수와 호출 규약까지 결정한다. PintOS는 x86-64 위에서 동작하므로 uint64_t 포인터, 4단계 PML4 페이지 테이블, KERN_BASE 0x8004000000 같은 64비트 전용 구조를 사용한다. 이 문서의 숫자들이 어디서 나왔는지 이해했다면, 다음은 이 주소가 실제로 물리 메모리에 도달하는 과정을 볼 차례다.
