Swap Lab (anonymous page가 디스크 슬롯으로 나갔다 돌아오는 법)

Swap 쟁점

프로그램이 RAM보다 큰 anonymous memory를 쓰면, 운영체제는 그 데이터를 어디에 숨겨 두었다가 다시 가져올까?

예를 들어 swap-anon 테스트는 10MB 메모리 설정에서 20MB짜리 배열을 4KB 간격으로 건드린다. 모든 페이지를 RAM에 계속 둘 수 없다면, 어떤 페이지는 잠깐 디스크로 밀려나야 한다.

이 Lab의 질문은 이것이다.

4KB짜리 anonymous page 한 장은 swap disk의 몇 번째 sector들에 저장될까?

Swap 필요성

프레임 교체 (Frame Eviction) Trace는 빈 frame이 없을 때 victim page를 골라 frame을 재사용해야 한다고 설명한다. 하지만 victim이 anonymous page라면 한 가지 문제가 남는다.

anonymous page는 실행 파일이나 mmap 파일처럼 “원본 파일의 offset”으로 돌아갈 곳이 없다.

예:

이 바이트는 프로그램이 실행 중에 만든 값이다. frame을 비우기 전에 이 값을 어딘가에 저장하지 않으면, 나중에 같은 주소를 다시 읽을 때 값이 사라진다.

그래서 swap은 이런 질문에 답한다.

  • RAM에서 쫓겨난 anonymous page의 4096B를 어디에 보관할까?
  • 나중에 page fault가 다시 나면 어느 위치에서 읽어 올까?
  • 그 위치가 이미 사용 중인지 아닌지는 누가 기억할까?

Swap 흐름

처음에는 swap을 “RAM 밖에 있는 임시 4KB 보관함 배열”로 생각하면 된다.

개념뜻
frame지금 RAM에 올라와 있는 4KB 자리
anonymous page파일 원본 없이 실행 중에 생긴 page
swap diskanonymous page 내용을 임시 저장하는 디스크
swap slotpage 하나를 저장하는 swap disk의 연속 sector 묶음
slot bitmap어떤 swap slot이 비었는지 표시하는 표

흐름은 두 방향이다.

이 말은 즉, swap은 SPT와 함께 동작한다. page table은 “지금 resident인가”만 말해 주고, SPT와 page metadata가 “resident가 아니라면 swap slot 몇 번에 있는가”를 기억해야 한다.

테스트는 각 page의 첫 바이트에 값을 쓴다.

(char) i로 저장하므로 256마다 값이 반복된다. 중요한 것은 모든 페이지의 첫 바이트가 나중에 다시 읽어도 같은 값이어야 한다는 점이다.

겉으로는 단순한 배열 검사지만, 내부에서는 이런 일이 일어날 수 있다.

실제 운영체제

Linux와 Windows도 anonymous memory를 RAM에 계속 둘 수 없으면 swap/pagefile 같은 backing store를 사용할 수 있다.

하지만 현실 OS는 PintOS보다 훨씬 많은 상태를 본다.

  • Linux는 anonymous page, file-backed page, page cache, reclaim, cgroup, NUMA, dirty/writeback 상태를 함께 고려한다.
  • Windows는 working set, standby/modified page list, pagefile, memory compression 같은 정책을 함께 다룬다.

현실 OS에서도 핵심 질문은 같다.

파일 원본이 없는 page를 RAM에서 내보내려면, 나중에 복원할 수 있는 backing store가 필요하다.

다만 현실 OS의 swap은 단순한 “slot 배열”보다 훨씬 복잡하고, 성능과 보안 정책도 함께 들어간다.

현재 코드에서 중요한 점은, swap slot이 단순한 번호 하나만으로 끝나지 않는다는 것이다. anon_swap_out()은 frame을 공유하는 owner 수를 보고 같은 swap slot의 참조 수를 맞춘다. 그래서 한 frame을 여러 page metadata가 가리키던 경우에도, 마지막 참조가 사라질 때까지 slot을 free로 돌리지 않는다.

vm_anon_init()은 swap disk와 slot 관리 구조를 초기화한다.

그리고 struct anon_page는 해당 page가 swap에 나가 있는지와 어느 slot에 있는지를 기억한다.

이 말은 즉, page table PTE가 지워져도 struct page의 metadata에는 복원에 필요한 좌표가 남는다.

PintOS의 디스크 배치는 disk.c 주석에 명시되어 있다.

따라서 현재 구현에서 swap disk를 잡는 흐름은 disk_get(1, 1)이다.

QEMU

QEMU는 “이 sector가 swap slot이다”라는 의미를 모른다.

QEMU가 보는 것은 guest인 PintOS가 ATA 디스크 명령을 보내고, 어떤 sector를 읽거나 쓰는 동작이다.

PintOS 쪽에서는 disk_read()와 disk_write()가 ATA PIO 포트에 명령을 보낸다.

  • SW_AI-W11-pintos/pintos/devices/disk.c
    • select_sector()
    • issue_pio_command()
    • output_sector()
    • input_sector()

QEMU 쪽에서는 IDE 장치 모델이 그 명령을 block backend I/O로 바꾼다.

  • hw/ide/core.c
    • WIN_READ -> cmd_read_pio
    • WIN_WRITE -> cmd_write_pio
    • ide_sector_read()
    • ide_sector_write()
  • block/block-backend.c
    • blk_aio_preadv()
    • blk_aio_pwritev()

이 말은 즉:

PintOS의 swap 정책은 PintOS가 정한다. QEMU는 그 정책을 이해하지 않고, 디스크처럼 보이는 장치를 제공한다.

파일:

  • SW_AI-W11-pintos/pintos/utils/pintos

pintos 실행 스크립트는 drive를 다음 순서로 QEMU에 붙인다.

PintOS의 disk.c는 이것을 1:1 - swap으로 설명한다. 그래서 guest PintOS 코드에서는 swap disk를 disk_get(1, 1)로 잡는 흐름이 자연스럽다.

이 테스트는 “anonymous page를 쫓아냈다가 다시 읽어도 값이 유지되는가”를 확인한다.

4. 테스트로 확인

이 명령은 anonymous page가 swap out/in을 거친 뒤에도 값이 유지되는지 보는 회귀 테스트다. 테스트가 실패하면 먼저 anon_swap_out()이 slot 8개 sector를 모두 쓰는지, anon_swap_in()이 같은 slot에서 읽는지, swap_slot_unref()가 slot을 너무 빨리 해제하지 않는지 확인한다.

정리

  • anonymous page는 원본 파일이 없으므로 eviction 때 swap backing이 필요하다.
  • PintOS의 page는 4096B이고 disk sector는 512B라서, page 하나는 sector 8개로 나뉜다.
  • anon_swap_out()은 frame의 4096B를 빈 swap slot에 기록하고, 모든 owner page에 swap_idx를 남긴다.
  • anon_swap_in()은 같은 slot에서 다시 읽은 뒤 swap_slot_unref()로 참조를 줄인다.
  • PintOS가 swap slot 정책을 구현하지만, QEMU는 그 의미를 모른다. QEMU는 IDE/block I/O만 에뮬레이션한다.

Swap 관련 문서

  • Frame Eviction Trace
    • swap out이 호출되는 앞 단계.
  • anonymous page swap slot
    • SPT와 struct anon_page가 swap slot을 기억해야 하는 이유.
  • Swap Disk QEMU Trace
    • slot 번호가 PintOS sector I/O와 QEMU block backend offset으로 내려가는 흐름.
  • Page Fault Trace
    • swap in이 다시 시작되는 입구.
  • SPT
    • page metadata가 resident/swap 상태를 기억해야 하는 이유.
  • mmap file backed page
    • anonymous page와 file-backed page의 backing 차이.
  • swap fork isolation Lab
    • 한 프로세스의 swap을 여러 child 격리 문제로 확장해서 보는 Lab.
