OS의 정의 — 하드웨어와 프로그램 사이에 끼어드는 소프트웨어

OS의 정의 — 하드웨어와 프로그램 사이에 끼어드는 소프트웨어

한 줄 요약: 운영체제(OS)는 하드웨어 자원을 관리하고, 프로그램이 하드웨어를 직접 다루지 않아도 되게 추상화를 제공하는 시스템 소프트웨어다.

여러 프로그램은 하드웨어를 어떻게 나눠 쓰는가

컴퓨터에서 프로그램 하나만 실행하고 그 프로그램이 CPU, 메모리, 디스크를 독점한다면 OS가 없어도 된다. 그러나 여러 프로그램이 동시에 실행되면 각각 CPU 시간, 메모리 공간, 디스크, 네트워크를 요구한다. 이때 자원을 나눠 주고 충돌을 막으며, 한 프로그램이 다른 프로그램의 메모리를 건드리지 못하게 하는 소프트웨어가 필요하다. 그 역할을 운영체제가 맡는다.

OS가 없다면 프로그램 A가 프로그램 B의 메모리를 덮어쓸 수 있다. 한 프로그램이 CPU를 독점하면 다른 프로그램은 계속 실행되지 못한다. 디스크에 데이터를 쓸 때도 프로그램마다 디스크 컨트롤러를 직접 제어해야 하며, 하드웨어가 바뀔 때마다 모든 프로그램을 다시 작성해야 한다.

OS가 맡는 두 가지 역할

OS는 자원 관리자(Resource Manager)이자 추상화 제공자(Abstraction Provider)다. 건물 관리인에 비유하면, 입주자인 프로그램에 방에 해당하는 메모리를 배정하고 복도에 해당하는 CPU 시간을 돌아가며 쓰게 한다. 디스크와 네트워크 같은 공용 시설도 OS를 통해 이용하게 한다. 입주자가 전기 배선을 직접 만지지 않듯 프로그램도 하드웨어를 직접 다루지 않는다.

자원 관리자로서 OS는 CPU, 메모리, 디스크, I/O 장치를 여러 프로그램에 나눠 준다. 스케줄러는 CPU 시간을 분배하고, 메모리 관리자는 주소 공간을 할당하며, 파일 시스템은 디스크 접근을 중재한다.

추상화 제공자로서 OS는 하드웨어의 구체적인 동작을 프로그램으로부터 숨긴다. 프로그램이 “파일을 연다”라고 요청하면 OS가 디스크 컨트롤러, 섹터 위치, 버퍼 관리를 처리한다. 이 추상화를 통해 프로그램은 SSD와 HDD의 차이를 직접 처리하지 않고도 동작할 수 있다.

역할을 나누어 수행하는 하위 시스템

OS는 하나의 거대한 프로그램이 아니라 여러 하위 시스템의 조합이다. 사용자 프로그램과 하드웨어 사이에는 시스템 콜 인터페이스가 있으며, 그 아래에서 프로세스 관리자, 메모리 관리자, 파일 시스템, 장치 드라이버가 CPU, RAM, Disk, Network, I/O를 다룬다.

  • 프로세스 관리자: 프로그램 실행 단위인 프로세스와 스레드를 생성하고 스케줄링한 뒤 종료한다. (프로세스와 스레드 추상화)
  • 메모리 관리자: 가상 주소 공간을 만들어 프로세스마다 독립된 메모리를 보장한다. (주소 변환과 메모리)
  • 파일 시스템: 디스크의 바이트를 파일과 디렉터리로 추상화한다. (파일 시스템 설계)
  • 장치 드라이버: 하드웨어 차이를 숨기고 통일된 인터페이스를 제공한다.
  • 시스템 콜 인터페이스: 유저 프로그램이 커널 기능을 요청하는 유일한 관문이다. (syscall 전체 흐름)

실제 OS와 PintOS의 범위

Linux나 Windows는 수백만 줄의 코드를 가진 완성된 OS다. Linux에는 수천 개의 장치 드라이버, 네트워크 스택, 보안 모듈, SMP 지원이 포함된다.

PintOS는 핵심 메커니즘을 학습할 수 있도록 설계된 작은 교육용 OS다. 타이머·키보드·디스크 드라이버만 있고 네트워크는 지원하지 않으며 단일 CPU를 사용한다. 범위가 제한되어 있으므로 스케줄링, 동기화, 가상 메모리, 파일 시스템을 코드로 읽고 구현하는 데 사용할 수 있다.

부팅 코드에서 확인하는 OS의 역할

PintOS의 main() 함수는 OS가 부팅할 때 각 관리 체계를 어떻게 세우는지 보여준다. OS를 자원 관리자이자 추상화 제공자로 본다면, 부팅은 그 역할을 맡을 하위 시스템을 의존 관계에 따라 준비하는 과정이다.

PintOS main()은 스레드, 메모리, 인터럽트, 스케줄러 순서로 하위 시스템을 초기화한다. 이 순서는 각 시스템의 의존 관계를 따른다. 스레드 시스템이 없으면 락을 쓸 수 없고, 메모리 관리가 없으면 페이지 테이블을 만들 수 없다. 인터럽트 처리가 없으면 타이머 틱도 받을 수 없다.

이 코드는 핵심 흐름만 추린 것이다. 실제 threads/init.c의 main()에는 프로젝트 단계에 따른 조건부 초기화가 더 붙는다. #ifdef USERPROG이면 tss_init()·gdt_init()·exception_init()·syscall_init()이 추가된다. #ifdef FILESYS이면 disk_init()·filesys_init()이, #ifdef VM이면 vm_init()이 추가된다. 따라서 부팅 코드는 Project 2(User Programs), 3(Virtual Memory), 4(File System)로 진행할수록 함께 확장된다.

각 부팅 단계는 OS의 역할과 다음과 같이 대응한다.

  • bss_init(): BSS를 초기화해 기반을 준비한다.
  • thread_init(): 스레드 시스템을 초기화해 프로세스 관리의 기반을 만든다.
  • palloc_init(), paging_init(): 물리 메모리 할당과 페이지 테이블을 준비한다.
  • intr_init(), timer_init(): 인터럽트와 타이머를 초기화해 하드웨어 이벤트를 처리할 수 있게 한다.
  • thread_start(): 스케줄러를 시작해 CPU 시간을 분배한다.

thread_start()가 호출되면 인터럽트가 활성화되고, 타이머 인터럽트가 발생할 때마다 스케줄러가 실행 스레드를 전환한다. 이 시점부터 여러 스레드가 CPU를 나눠 쓰고 메모리를 할당받으며, 시스템 콜을 통해 커널 기능을 요청할 수 있다.

OS의 정의를 코드와 연결하기

OS는 여러 프로그램이 하드웨어를 함께 사용할 때 자원을 관리하고 충돌을 막는다. 동시에 프로그램이 하드웨어의 세부 동작을 직접 다루지 않도록 추상화를 제공한다. PintOS의 main()은 이 두 역할을 수행할 스레드, 메모리, 인터럽트, 스케줄러를 차례로 준비하는 과정을 보여준다.
