묵시적 가용 리스트

묵시적 가용 리스트

한 줄 요약: Implicit free list는 모든 블록에 헤더(크기 + 할당 비트)를 붙여, 힙 처음부터 끝까지 블록을 하나씩 건너뛰며 빈 블록을 찾는 구조다.

묵시적 가용 리스트 필요성

malloc()을 호출하면 힙에서 빈 공간을 찾아 돌려줘야 한다. 가장 먼저 드는 질문은 “빈 블록이 어디 있는지 어떻게 아는가?”다.

Implicit free list는 이 질문에 대한 가장 단순한 답이다. 모든 블록(사용 중이든 빈 블록이든)에 크기를 기록한 헤더를 붙이고, 첫 블록부터 크기만큼 점프하며 순회한다. 별도의 자료구조 없이 헤더만으로 다음 블록 위치를 계산할 수 있기 때문에 “묵시적(implicit)“이라 부른다.

이 구조를 모르면 explicit free list, segregated list, buddy system이 왜 필요한지 이해할 수 없다. 모든 동적 메모리 할당기의 출발점이다.

  • 이 개념이 없으면 malloc/free 구현에서 “블록 경계를 어떻게 알아내는가”를 설명할 수 없다.
  • explicit free list와의 차이를 이해하려면 implicit free list의 한계를 먼저 체감해야 한다.
  • 이 문서를 읽고 나면 다음을 구분할 수 있어야 한다.
    • 헤더/푸터가 블록 경계를 표시하는 방법
    • 할당 비트를 크기 필드에 끼워 넣는 트릭
    • first fit, next fit, best fit 탐색 전략의 차이
    • 인접 빈 블록을 합치는(coalescing) 이유

묵시적 가용 리스트 흐름

블록 구조 — 헤더, 페이로드, 푸터

힙 위의 모든 블록은 같은 형태를 가진다.

%% 묵시적 가용 리스트 블록 구조
flowchart TD
  block["블록 시작 (HDRP)<br/>헤더 4B<br/>크기 + 할당 비트<br/>bp<br/>페이로드 시작<br/>페이로드<br/>사용자 데이터 영역<br/>푸터 4B<br/>헤더 값 복사<br/>다음 블록의 헤더 바로 앞"]
  header_note["헤더: size &#124; alloc"]
  footer_note["푸터: boundary tag"]
  block_header["block:header"]
  block_footer["block:footer"]
  header_note -->|"HDRP(bp)"| block_header
  block_footer -->|"FTRP(bp)"| footer_note

헤더 4바이트에 블록 크기와 할당 여부를 함께 담는다. 블록 크기는 항상 8의 배수(더블 워드 정렬)이므로 하위 3비트가 항상 0이다. 이 빈 비트 중 최하위 1비트를 할당 플래그로 쓴다.

크기 = 헤더 + 페이로드 + (패딩) + 푸터 정렬 단위 = 8바이트 (DSIZE) 최소 블록 크기 = 헤더(4) + 최소 페이로드(1) + 패딩(3) + 푸터(4) = 16바이트

PACK 매크로 — 크기와 할당 비트를 한 워드에 묶기

PACK(size, alloc)은 크기 값의 하위 3비트가 0이라는 점을 이용해 비트 OR로 할당 플래그를 끼워 넣는다.

반대로 읽을 때는 GET_SIZE가 하위 3비트를 마스킹(& ~0x7)하고, GET_ALLOC이 최하위 비트만 꺼낸다(& 0x1).

힙 순회 — 다음 블록으로 점프

헤더에서 크기를 읽으면 다음 블록의 위치를 계산할 수 있다. 이것이 “묵시적 리스트”의 핵심이다. 빈 블록만 모은 별도 링크가 없어도 힙 전체를 순회할 수 있다.

%% 묵시적 가용 리스트 힙 순회
flowchart LR
  start["힙 시작"]
  n_end["힙 끝"]
  block32["32B 블록<br/>H:32 a=1 / F:32 a=1<br/>페이로드 사용 중"]
  block16["16B 블록<br/>H:16 a=0 / F:16 a=0<br/>빈 블록"]
  block48["48B 블록<br/>H:48 a=1<br/>할당 블록"]
  epilogue["에필로그 헤더<br/>E:0 a=1"]
  rule["NEXT_BLKP(bp)<br/>bp + 현재 블록 크기"]
  start -->|"첫 블록"| block32
  block32 -->|"+32B"| block16
  block16 -->|"+16B"| block48
  block48 -->|"+48B"| epilogue
  epilogue -->|"크기 0"| n_end
  rule -->|"다음 헤더 계산"| block16

H = 헤더, F = 푸터, E = 에필로그 헤더(크기 0, 할당 1)다. a는 할당 비트다.

NEXT_BLKP(bp) = bp + 현재 블록 크기. 이 한 줄로 다음 블록으로 건너뛴다. 에필로그 헤더(크기 0, 할당 1)를 만나면 순회가 끝난다.

PREV_BLKP(bp) = bp - 이전 블록 크기. 이전 블록의 크기는 현재 헤더 바로 앞에 있는 이전 블록의 푸터에서 읽는다. 푸터가 있어야 뒤로도 갈 수 있다.

탐색 전략

빈 블록을 찾는 세 가지 전략이 있다.

  • First fit: 힙 처음부터 순회하여 크기가 맞는 첫 빈 블록을 선택한다. 단순하지만 힙 앞쪽에 작은 조각이 쌓여 탐색이 느려진다.
  • Next fit: 마지막으로 탐색한 위치에서 이어서 찾는다. First fit보다 빠르지만 메모리 이용률이 나쁠 수 있다.
  • Best fit: 모든 빈 블록을 순회하여 크기가 가장 가까운 블록을 선택한다. 이용률은 좋지만 항상 전체 힙을 순회해야 한다.

Implicit free list에서는 세 전략 모두 할당된 블록까지 순회해야 한다. 빈 블록만 따로 연결하지 않기 때문이다. 이것이 가장 큰 단점이다.

해제와 병합 (Coalescing)

free()는 블록의 할당 비트를 0으로 바꾼다. 그런데 인접한 블록이 이미 빈 상태라면 두 블록을 합쳐야 한다. 합치지 않으면 작은 빈 블록이 늘어나 외부 단편화가 심해진다.

병합은 네 가지 경우로 나뉜다.

  • Case 1: 이전 블록 할당, 다음 블록 할당 → 병합 없음
  • Case 2: 이전 블록 할당, 다음 블록 빈 상태 → 현재 + 다음 병합
  • Case 3: 이전 블록 빈 상태, 다음 블록 할당 → 이전 + 현재 병합
  • Case 4: 이전 블록 빈 상태, 다음 블록 빈 상태 → 이전 + 현재 + 다음 병합

이전 블록의 할당 상태를 확인하려면 이전 블록의 푸터를 읽어야 한다. 이것이 푸터(boundary tag)가 존재하는 이유다. 푸터가 없으면 뒤쪽 병합을 O(1)에 할 수 없다.

실제 OS와의 차이

  • Linux glibc malloc (ptmalloc2): implicit free list를 기반으로 시작했지만, bins(explicit free list의 크기별 배열)와 unsorted bin, fastbin 등으로 탐색을 최적화했다. 순수 implicit 순회는 사용하지 않는다.
  • Malloc Lab 과제: CS:APP 교재의 과제다. implicit free list부터 시작해 explicit, segregated, buddy로 발전시키며 할당기 설계를 배운다.

왜 implicit free list만으로는 부족한가?

할당 요청이 올 때마다 힙의 모든 블록(할당 + 빈 블록)을 순회해야 한다. 블록 수를 N이라 하면 탐색은 O(N)이다. 힙이 커지고 단편화가 심해지면 대부분의 블록이 할당 상태이므로, 빈 블록 하나를 찾기 위해 할당 블록을 수백 개 건너뛰어야 한다.

이 문제를 해결하려면 빈 블록만 따로 연결하는 explicit free list가 필요하다.

묵시적 가용 리스트 코드

매크로 — 블록 경계를 읽고 쓰는 도구

이 매크로들이 implicit free list의 전부다. NEXT_BLKP는 현재 블록 크기만큼 포인터를 전진시켜 다음 블록을 찾고, PREV_BLKP는 이전 푸터에서 크기를 읽어 뒤로 간다.

힙 초기화 — 프롤로그와 에필로그

프롤로그 블록(크기 8, 할당)은 병합 시 힙 시작 경계를 보호한다. 에필로그 헤더(크기 0, 할당)는 순회 종료 조건이자 힙 끝 경계다. extend_heap이 힙을 늘릴 때마다 에필로그가 뒤로 밀린다.

병합 — 네 가지 경우

이전 블록의 할당 여부를 O(1)에 확인하려면 이전 블록의 푸터를 읽어야 한다. FTRP(PREV_BLKP(bp))가 가능한 이유는 현재 헤더 바로 앞이 이전 블록의 푸터이기 때문이다.

정리

Implicit free list는 헤더/푸터(boundary tag)만으로 힙의 모든 블록을 순회하는 가장 단순한 할당기 구조다. 블록 크기를 읽어 다음 블록으로 점프하고, 할당 비트로 빈 블록을 식별한다. 푸터 덕분에 이전 블록 확인과 양방향 병합이 O(1)에 가능하다. 단점은 빈 블록을 찾을 때 할당 블록까지 전부 순회해야 한다는 것이다. 이 한계를 넘으려면 빈 블록만 따로 연결하는 explicit free list로 진화해야 한다.

여기서 본 매크로(PACK, GET_SIZE, HDRP, NEXT_BLKP 등)와 coalesce()의 네 가지 경우는 이 볼트의 Malloc Lab 실제 구현 mm.c에 그대로 들어 있다. 다만 최종 구현은 빈 블록 탐색을 AVL 트리 기반 best fit으로 바꿔 O(log M)에 찾는다. 즉 이 문서의 boundary tag 구조 위에 더 빠른 탐색 자료구조를 얹은 것이다.
