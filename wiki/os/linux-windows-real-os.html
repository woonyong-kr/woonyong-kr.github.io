Linux/Windows 실제 운영체제

확인 범위: 이 문서는 PintOS의 교육용 개념이 Linux와 Windows의 구조·서브시스템으로 확장되는 방식을 설명하고 비교하는 개념적 개요다. 표에 제시된 구조체 크기, 한도, 시간·비용 등의 수치와 코드 좌표 및 동작 세부는 특정 버전의 실제 코드, 설정, 실행 기록이나 성능 측정으로 검증한 결과가 아니므로 적용 시 별도 확인이 필요하다.

한 줄 요약: 교육용 PintOS와 달리 멀티코어 확장성·보안 격리를 갖춘 프로덕션 OS Linux·Windows의 위치.

Linux/Windows 실제 운영체제 구조

Linux와 Windows는 수십 년간 발전해 온 프로덕션 운영체제다. PintOS가 “OS가 해야 하는 일”을 가르치기 위해 핵심만 추린 교육용 OS라면, Linux/Windows는 그 핵심 위에 멀티코어 확장성, 보안 격리, 장치 다양성, ABI 호환성, 성능 최적화를 수십 겹 쌓아 올린 실전 시스템이다. PintOS에서 배운 개념이 실제 OS에서 어떤 형태로 확장되는지 이해하면, 학습한 지식을 현실에 연결할 수 있다.

Linux buddy allocator vs PintOS palloc:

PintOS의 palloc은 bitmap 기반으로 단일 page 할당만 지원한다. Linux의 buddy allocator는 2^n 페이지 블록을 관리하여 연속 물리 메모리 할당이 가능하다. NUMA 시스템에서는 node별 zone별로 독립된 buddy를 운용한다.

항목PintOS pallocLinux buddyWindows PFN DB
할당 단위1 page (고정)2^0 ~ 2^10 pages1 page
자료 구조bitmapfree_area[MAX_ORDER]PFN array
NUMA미지원node/zone별 분리node별 분리
연속 할당불가가능 (order 지정)MDL scatter/gather

Linux CFS (Completely Fair Scheduler) vs PintOS priority:

PintOS는 priority 기반 round-robin으로 TIME_SLICE(4 tick = 40ms)마다 preemption한다. Linux CFS는 vruntime(virtual runtime)을 red-black tree에서 관리하여, vruntime이 가장 작은 task를 다음에 실행한다. nice 값이 vruntime 증가 속도의 가중치를 결정한다.

계층PintOSLinuxWindows

PintOS는 단일 CPU이므로 intr_disable()만으로 critical section을 보호할 수 있다. 멀티코어에서는 다른 CPU가 동시에 같은 데이터에 접근하므로 spinlock이 필수다.
