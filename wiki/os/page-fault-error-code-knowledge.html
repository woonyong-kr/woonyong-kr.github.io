페이지 폴트 error code

페이지 폴트 error code

한 줄 요약: page fault error code는 fault 주소가 아니라 접근 실패의 종류를 나타내며, PintOS는 그중 P/W/U 비트를 not_present·write·user로 분해해 복구 여부를 판단한다.

페이지 폴트 error code 상태

x86 page fault가 발생하면 CPU는 CR2(fault 주소)뿐 아니라 여러 상태 비트를 가진 error code를 함께 스택에 push한다. PintOS는 이 가운데 P/W/U 세 비트를 not_present/write/user boolean으로 분해하여 vm_try_handle_fault()에 넘긴다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 pf error code에는 여러 비트가 있으며, PintOS의 기본 판단에는 하위 P/W/U 세 비트가 핵심이다.

비트이름값0이면1이면
bit 0P (Present)0x1page not presentprotection violation (page는 있었음)
bit 1W/R (Write)0x2read accesswrite access
bit 2U/S (User)0x4kernel mode accessuser mode access

추가로 bit 3(RSVD), bit 4(I/D, instruction fetch), bit 5(PK, protection key) 등이 있지만 PintOS에서는 사용하지 않는다.

error code 값에서 각 비트를 읽는 방법:

이 둘의 차이가 중요하다. 0x6은 demand paging/stack growth 후보이고, 0x7은 COW 후보이거나 진짜 권한 위반이다.

실제 OS (Linux/Windows)

항목LinuxWindows
error code 해석do_page_fault() → VMA lookup + 권한 검사Exception dispatcher → VAD tree
not-present (P=0)demand paging, file mapping, stack expansioncommitted/reserved page, file mapping
protection (P=1)COW, NX violation, SMEP/SMAPCOW, DEP, guard page
실패 결과SIGSEGV, SIGBUSSTATUS_ACCESS_VIOLATION

두 OS 모두 P=0과 P=1을 첫 분기점으로 사용한다.

PintOS 구현

PintOS의 page_fault()는 error code를 세 boolean으로 분해한다.

이 값들이 vm_try_handle_fault()의 판단표로 변환된다.

QEMU 에뮬레이션

QEMU는 PintOS의 VM 정책을 모른다. QEMU의 역할은 x86 pf의 CR2/error code를 정확히 재현하는 것이다.

QEMU 코드의 비트 이름은 PG_ERROR_*이지만 의미는 동일하다.

PintOSQEMU의미
PF_P (0x1)PG_ERROR_P_MASKpresent / not-present
PF_W (0x2)PG_ERROR_W_MASKwrite / read
PF_U (0x4)PG_ERROR_U_MASKuser / kernel

QEMU의 TCG system 경로에서 page translation 실패 시:

페이지 폴트 error code 값 추적

error_code = 0x6 비트 분해

error_code = 0x7 비트 분해

fault 주소 → page base 변환

테스트별 예상 error code

테스트예상 error_code해석
pt-grow-stack0x6user write, not-present → stack growth 후보
pt-bad-addr0x4 또는 0x6user, not-present → SPT에 없으면 kill
pt-write-code0x7user write, protection → 코드 영역 쓰기 시도
cow-simple0x7user write, protection → COW copy 후보
mmap-ro0x6 (첫 접근)lazy page 상태에서 not-present
