PTE 쓰기허용 Bit (PTE Writable Bit)

PTE 쓰기허용 Bit (PTE Writable Bit)

한 줄 요약: PTE bit 1(Writable)은 페이지 쓰기 허용 여부를 정하며, W=0 페이지에 쓰면 write protection fault(#PF)가 발생해 코드 보호·COW·read-only mmap의 하드웨어 기반이 된다.

PTE 쓰기허용 Bit 상태

PTE의 bit 1(Writable bit, W 또는 R/W)은 해당 페이지에 쓰기가 허용되는지를 MMU에 알려주는 1비트 플래그다. W=1이면 읽기와 쓰기 모두 가능하고, W=0이면 읽기만 허용된다. W=0인 페이지에 쓰기를 시도하면 MMU가 write protection fault(#PF, error code에 PF_W=1, PF_P=1)를 발생시킨다. 이 비트는 코드 영역 보호, Copy-on-Write, read-only mmap 등 OS의 메모리 보호 메커니즘의 하드웨어 기반이다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 PTE에서 writable bit의 위치:

bit 0: Present (P)   — 매핑 유효 여부
bit 1: Writable (W)  — 쓰기 허용 여부  ← 이 문서의 주제
bit 2: User (U)      — 유저 모드 접근 허용

유저 모드에서의 동작:

PW읽기쓰기
0xpf (not present)pf (not present)
10허용pf (write protection)
11허용허용

커널 모드에서의 동작:

전통적 x86에서 커널 모드(CPL 0)는 W=0인 페이지에도 쓸 수 있었다. 하지만 x86-64의 CR0.WP(Write Protect) 비트가 1로 설정되면 커널 모드에서도 W=0 페이지에 쓰기 시 pf가 발생한다. PintOS는 CR0.WP=1로 설정하여 커널도 read-only 보호를 받는다.

4단계 walk에서의 W bit:

W bit는 page table의 모든 단계에서 적용된다. 최종 접근 권한은 walk 경로에 있는 모든 엔트리의 W bit의 AND다:

PML4E.W=1 → PDPTE.W=1 → PDE.W=1 → PTE.W=0 → 최종: 읽기 전용

어느 한 단계라도 W=0이면 해당 페이지는 읽기 전용이 된다.

실제 OS (Linux/Windows)

Linux에서 _PAGE_RW (bit 1)는 다음 용도로 사용된다:

  • 코드 영역 보호: ELF text 세그먼트는 W=0으로 매핑되어 실행 중 코드 변조를 방지한다.
  • COW (Copy-on-Write): fork 시 부모와 자식 양쪽의 PTE에서 W=0으로 설정. 쓰기 시 write fault가 발생하면 커널이 프레임을 복사하고 새 PTE에 W=1을 설정한다.
  • mmap MAP_PRIVATE: 파일을 MAP_PRIVATE로 mmap하면 처음에는 W=0. 쓰기 시 COW 발생.

Windows의 page protection도 유사하며 PAGE_READONLY, PAGE_READWRITE, PAGE_EXECUTE_READ 등의 속성이 PTE W bit에 매핑된다.

PintOS 구현

PintOS에서 writable bit의 정의:

pml4_set_page()에서 W bit 설정:

rw 파라미터가 true이면 PTE_W가 OR되어 쓰기 가능, false이면 읽기 전용으로 설정된다.

W bit가 사용되는 주요 장면:

장면rw 값이유
text 세그먼트 적재false코드 영역은 읽기 전용
data 세그먼트 적재true전역 변수는 쓰기 가능
스택 페이지true스택은 읽기/쓰기 필요
COW fork 시false양쪽 모두 read-only로 전환
COW fault 처리 후true새 프레임은 독점 소유이므로 쓰기 허용
mmap read-onlyfalse파일 원본 보호

is_writable() 매크로:

page fault handler가 COW fault인지 판단할 때 사용한다: PTE가 present이지만 writable이 아니고, SPT에서 해당 page가 원래 writable이라고 기록했다면 COW fault로 처리한다.

SPT의 writable 필드와의 관계:

PTE의 W bit는 현재 하드웨어 상태를 나타내고, page->writable은 논리적 권한을 나타낸다. COW 때문에 PTE.W=0이더라도 page->writable=true일 수 있다. 이 차이가 write protection fault를 COW로 처리할지, segfault로 처리할지 결정한다.

QEMU 에뮬레이션

QEMU SoftMMU는 target/i386/tcg/excp_helper.c에서 write 접근 시 PTE의 W bit를 검사한다. W=0이고 쓰기 접근이면 error code에 PF_W(bit 1)=1을 설정하고 pf를 주입한다.

PTE 쓰기허용 Bit 값 추적

Write protection fault error code 구성:

error code = PF_P | PF_W | PF_U
           = 0x1  | 0x2  | 0x4
           = 0x7

의미: present page(P=1)에 대한 write(W=1) 접근을 user mode(U=1)에서 시도

not-present fault와의 구분:

not-present read:  error_code = 0x4 (PF_U만)
not-present write: error_code = 0x6 (PF_W | PF_U)
write protection:  error_code = 0x7 (PF_P | PF_W | PF_U)

PintOS page_fault handler에서 이 구분이 핵심이다:

PTE 값 예시:

읽기/쓰기 가능 page:
  PTE = PA | PTE_P | PTE_W | PTE_U = PA | 0x7

읽기 전용 page:
  PTE = PA | PTE_P | PTE_U = PA | 0x5

COW로 전환 후:
  PTE = PA | PTE_P | PTE_U = PA | 0x5  (W bit 제거)

순서도 / 개념도

flowchart TD
    A["유저 코드: MOV addr, val"] --> B{"PTE present?"}
    B -->|P=0| C["#PF: not_present=true, write=true"]
    B -->|P=1| D{PTE.W=1?}
    D -->|W=1| E["쓰기 성공, dirty bit 설정"]
    D -->|W=0| F["#PF: not_present=false, write=true"]
    C --> G["page fault handler"]
    F --> G
    G --> H{"SPT에서 page 조회"}
    H -->|page writable true| I["COW: 프레임 복사, W=1 설정"]
    H -->|page writable false| J["정당한 read-only 위반 → kill"]
    H -->|SPT에 없음| K["segfault → kill"]
    I --> A
