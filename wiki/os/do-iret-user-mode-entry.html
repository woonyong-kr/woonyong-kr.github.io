do_iret() → user mode 진입

do_iret() → user mode 진입

확인 범위: 이 문서는 x86-64의 iretq 권한 전환 원리와 PintOS에서 process_exec()·__do_fork()가 intr_frame을 구성해 user mode로 진입하는 방식을 설명한다. 함수 경로, 구조체 크기·오프셋, Linux·Windows·QEMU와의 비교, 실패 조건과 성능 관련 판단은 특정 코드와 버전 및 실제 실행·측정 기록을 대조해야 하는 구현 수준의 내용이며, 본문만으로 검증 결과를 뜻하지 않는다.

커널은 process_exec()와 __do_fork()에서 intr_frame을 직접 조립한 뒤 do_iret()를 호출해, CPU가 처음으로 user mode의 RIP와 RSP를 복원하게 만든다.

do_iret() → user mode 진입 상태

do_iret()는 레지스터 복원 함수이지만, 최초 user mode 진입이라는 특수한 쓰임이 있다. process_exec()와 __do_fork()는 struct intr_frame을 직접 조립하여 user-mode 세그먼트 셀렉터(CS=SEL_UCSEG, SS=SEL_UDSEG)를 설정한 뒤 do_iret()를 호출한다. iretq가 CS의 RPL을 보고 CPL 0→3 전환을 수행하면, CPU는 user mode에서 프로그램을 실행하기 시작한다. 이것이 커널이 유저 프로세스를 “태어나게” 하는 유일한 경로다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64의 iretq는 스택에서 RIP, CS, RFLAGS, RSP, SS 5개 값을 pop하여 CPU에 적재한다. 이때 **CS의 하위 2비트(RPL)**가 현재 CPL과 다르면 권한 전환이 발생한다.

전환 방향CS RPL결과
커널→커널0CPL 유지, 스택 전환 없음
커널→유저3CPL 0→3, RSP/SS도 새 값으로 교체

핵심: iretq는 interrupt return이라는 이름이지만, 실제로는 “이 세그먼트와 레지스터 상태로 전환하라”는 범용 전환 명령어다. 최초 user mode 진입은 “돌아가는” 것이 아니라, intr_frame을 가짜로 꾸며 처음부터 유저 모드에 진입하는 트릭이다.

실제 OS (Linux/Windows)

Linux에서도 동일한 패턴을 사용한다. execve() 시 start_thread() → force_iret()가 pt_regs를 조립하여 iretq로 유저 모드에 진입한다. fork() 시 자식은 ret_from_fork() → iretq 경로를 통해 유저 코드를 시작한다. Windows는 KiInitializeUserApc() 등에서 IRETD/IRETQ를 사용한다.

항목LinuxPintOS
exec 진입 함수start_thread() (arch/x86/kernel/process_64.c)process_exec() → do_iret()
fork 자식 진입ret_from_fork() (arch/x86/entry/entry_64.S)__do_fork() → do_iret()
레지스터 저장 구조체struct pt_regs (29개 필드, 168 bytes)struct intr_frame (24개 필드, 192 bytes)
iretq 대안sysretq (syscall return 시 빠른 경로, CS/SS 고정)항상 iretq (sysret 미사용)
EFLAGS 설정X86_EFLAGS_IF | X86_EFLAGS_FIXEDFLAG_IF | FLAG_MBS (동일 의미)
ASLR 적용있음 — randomize_va_space로 RIP/RSP 무작위화없음 — e_entry 고정
signal trampoline있음 — signal handler도 iretq로 진입없음

Linux의 sysretq는 iretq보다 빠르지만 (Spectre 완화 등으로 차이 감소) CS/SS가 고정이어서 특정 조건에서만 사용 가능하다. PintOS는 단순성을 위해 항상 iretq를 사용한다.

PintOS 구현

PintOS에서 user mode 진입은 정확히 두 곳에서 발생한다.

1. process_exec() — 새 프로그램 적재 후 진입

load() 함수가 ELF를 파싱하여 _if.rip에 e_entry(엔트리 포인트), _if.rsp에 유저 스택 꼭대기를 설정한다. do_iret()이 이 값들을 CPU에 적재하면 프로그램이 시작된다.

2. __do_fork() — 자식 프로세스의 유저 모드 복귀

자식은 부모의 intr_frame을 복사한 if_로 do_iret()를 호출한다. CS/SS는 부모 것 그대로(유저 세그먼트)이므로 자연스럽게 user mode로 돌아간다. RAX만 0으로 바꿔서 fork()가 0을 반환하게 만든다.

do_iret() → user mode 진입 값 추적

intr_frame에서 iretq가 읽는 5개 필드의 오프셋과 값:

필드intr_frame 오프셋값 (process_exec)의미
RIP+152ELF e_entry (예: 0x400000)유저 코드 시작 주소
CS+1600x23 (SEL_UCSEG)RPL=3 → user code
RFLAGS+1680x202 (IF=1, MBS=1)인터럽트 허용
RSP+176USER_STACK - argv 크기유저 스택 꼭대기
SS+1840x1B (SEL_UDSEG)RPL=3 → user data

세그먼트 셀렉터 해석:

SEL_UCSEG = 0x23 = 0b00100_0_11
  index=4, TI=0(GDT), RPL=3(user)

SEL_UDSEG = 0x1B = 0b00011_0_11
  index=3, TI=0(GDT), RPL=3(user)

EFLAGS 값:

FLAG_MBS = 1<<1 = 0x002  (bit 1은 항상 1이어야 함)
FLAG_IF  = 1<<9 = 0x200  (인터럽트 허용)
합계:              0x202

QEMU 에뮬레이션

QEMU TCG는 iretq 명령어를 gen_helper_iret_protected()로 번역한다. 이 헬퍼가 수행하는 핵심 동작:

단계TCG 동작효과
1스택에서 RIP/CS/RFLAGS/RSP/SS popenv->eip, env->segs[R_CS] 등 갱신
2CS RPL 검사env->hflags CPL 비트 전환 (3으로 설정)
3SS 로드 + DPL 검사env->segs[R_SS] 갱신
4현재 TB 종료새 CPL에서 새 Translation Block 생성

CPL 전환이 일어나면 TCG는 현재 TB를 중단하고 새 TB를 생성한다. user mode 코드의 첫 TB는 RIP가 가리키는 e_entry(또는 fork 복귀 주소)에서 시작된다.

GDB에서 최초 user mode 진입 관찰 (5단계):

  1. b *do_iret — do_iret에 breakpoint
  2. p/x ((struct intr_frame *)$rdi)->rip — 진입할 유저 주소 확인
  3. p/x ((struct intr_frame *)$rdi)->cs — 0x23(SEL_UCSEG) 확인
  4. si 반복하여 iretq 직전까지 진행 → info registers 로 복원된 범용 레지스터 확인
  5. iretq 실행 후 info registers → CS의 하위 2비트가 3(CPL=3), RIP가 유저 주소로 전환됨 확인

QEMU에서 iretq가 실패하는 경우: CS의 RPL이 0이 아니면서 SS의 DPL과 불일치하면 #GP(0) 예외 발생. PintOS에서 SEL_UCSEG(RPL=3)과 SEL_UDSEG(RPL=3)은 항상 일치하므로 정상 동작.
