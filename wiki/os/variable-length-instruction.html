가변 길이 명령어 (1~15 bytes)

가변 길이 명령어 (1~15 bytes)

한 줄 요약: 1~15바이트로 길이가 다른 x86-64 가변 길이 명령어와 CPU의 fetch 디코딩.

가변 길이 명령어 구조

x86-64는 **가변 길이 명령어 집합(variable-length ISA)**이다. 하나의 명령어가 최소 1바이트(nop = 0x90)에서 최대 15바이트까지 될 수 있다. CPU는 fetch 단계에서 첫 바이트(들)를 읽어 opcode를 판별하고, 그 opcode가 요구하는 추가 바이트(ModR/M, SIB, displacement, immediate)를 더 읽어 명령어 경계를 결정한다. 이 가변 길이 특성은 OS 개발, 디버거 구현, QEMU TCG 번역 모두에 직접적 영향을 준다.

상세 설명

추상 개념 (x86-64 명령어 인코딩)

x86-64 명령어는 최대 6개 필드로 구성되며, 각 필드의 존재 여부는 opcode에 따라 달라진다:

[Prefix(es)] [REX/VEX] [Opcode] [ModR/M] [SIB] [Displacement] [Immediate]
  0~4 bytes   0~3 bytes  1~3 bytes  0~1 byte  0~1 byte  0/1/2/4 bytes  0/1/2/4/8 bytes
필드크기역할
Legacy Prefix0~4 bytesLOCK, REP, segment override, operand/address size
REX Prefix01 byte (0x400x4F)64비트 확장: W(64-bit operand), R/X/B(레지스터 확장)
Opcode1~3 bytes연산 종류 (1-byte, 2-byte 0x0F xx, 3-byte 0x0F 38/3A xx)
ModR/M0~1 byte피연산자 모드: mod(2) + reg(3) + r/m(3)
SIB0~1 byteScale-Index-Base 주소 지정: scale(2) + index(3) + base(3)
Displacement0/1/2/4 bytes메모리 주소 오프셋
Immediate0/1/2/4/8 bytes상수 피연산자

Intel 매뉴얼은 명령어의 최대 길이를 15바이트로 정의한다. 15바이트를 넘는 인코딩을 시도하면 CPU는 #UD (Undefined Opcode) 예외를 발생시킨다. 따라서 prefix가 과도하게 이어지더라도 CPU가 명령어를 끝없이 읽지는 않는다.

RISC vs CISC 비교:

ISA명령어 길이fetch 복잡도코드 밀도
ARM (AArch64)고정 4 bytes단순 (PC += 4)낮음
RISC-V2 or 4 bytes (compressed 확장)단순~보통보통
x86-641~15 bytes복잡 (디코더가 파싱)높음

x86-64의 높은 코드 밀도는 instruction cache 효율에 유리하지만, 디코더 회로가 복잡해진다.

PintOS에서 마주치는 구체적 명령어

PintOS 커널과 유저 프로그램에서 흔히 보이는 명령어들의 실제 바이트 크기:

명령어기계어크기설명
nop901 byte아무 것도 안 함
retc31 byte함수 복귀
syscall0f 052 bytes유저→커널 전환
iretq48 cf2 bytes인터럽트 복귀 (REX.W + IRET)
push rbp551 byte스택에 rbp 저장
mov rsp, rbp48 89 e53 bytesREX.W + MOV + ModR/M
mov rax, [rip+disp32]48 8b 05 xx xx xx xx7 bytesRIP-relative 메모리 접근
mov rax, imm6448 b8 xx xx xx xx xx xx xx xx10 bytes64비트 즉시값 로드
call rel32e8 xx xx xx xx5 bytes함수 호출 (32비트 상대 오프셋)
jmp rel8eb xx2 bytes짧은 점프
jmp rel32e9 xx xx xx xx5 bytes긴 점프

PintOS lib/user/syscall.c에서 syscall 명령어(0x0F 0x05)는 2바이트다. 이 명령어 하나로 CPL 3 → 0 전환, LSTAR MSR이 가리키는 커널 진입점으로 점프가 일어난다.

do_iret()에서 iretq(0x48 0xCF)도 2바이트다. REX.W prefix(0x48)가 64비트 모드의 IRET을 지정한다.

QEMU TCG와 가변 길이

QEMU TCG(Tiny Code Generator)는 guest 명령어를 Translation Block(TB) 단위로 번역한다. 가변 길이 ISA에서 TB 경계를 결정하려면:

  1. guest 코드를 바이트 단위로 디코딩하여 각 명령어 경계를 파싱
  2. branch 명령어를 만나면 TB를 끝냄
  3. TB 내 모든 명령어를 호스트 네이티브 코드로 번역
  4. 번역된 블록을 tb_hash에 캐싱

가변 길이가 복잡하게 만드는 점:

  • 자기 수정 코드(self-modifying code): 코드 영역 쓰기 시 해당 TB를 무효화해야 함
  • 명령어 중간 주소에 branch: 새로운 TB 시작점이 예측 불가
  • 크로스 페이지 명령어: 명령어가 페이지 경계를 걸치면 두 페이지 모두 매핑되어야 fetch 가능

PintOS는 자기 수정 코드를 쓰지 않으므로, 실질적으로 영향을 주는 것은 크로스 페이지 명령어다. 예를 들어 0x4FFF 주소에서 시작하는 7바이트 명령어는 0x4FFF~0x5005 범위를 읽어야 하므로 두 page가 모두 present여야 한다.

RIP 증가와 가변 길이

RIP는 현재 명령어 실행 후 해당 명령어의 바이트 수만큼 증가한다:

RIP = 0x401000  →  명령어: push rbp (1 byte)  →  RIP' = 0x401001
RIP = 0x401001  →  명령어: mov rsp,rbp (3 bytes)  →  RIP' = 0x401004
RIP = 0x401004  →  명령어: call rel32 (5 bytes)  →  RIP' = target address

이것이 고정 길이 ISA와의 핵심 차이다. ARM에서는 항상 PC += 4이지만, x86-64에서는 CPU 디코더가 명령어 길이를 파싱해야 다음 RIP를 결정할 수 있다.

GDB에서 확인: x/10i $rip는 RIP부터 10개 명령어를 디스어셈블한다. 각 줄의 주소 차이가 곧 해당 명령어의 바이트 수다.

0x401000: push   rbp             ← 1 byte
0x401001: mov    rbp,rsp         ← 3 bytes
0x401004: sub    rsp,0x10        ← 4 bytes
0x401008: mov    DWORD PTR [rbp-0x4],edi  ← 3 bytes

가변 길이 명령어 값 추적

명령어 길이 분포 (일반적 x86-64 코드)

실제 컴파일된 코드에서 명령어 길이 분포는 대략:

길이비율 (대략)대표 명령어
1 byte~15%push, pop, ret, nop
2 bytes~20%syscall, short jmp, mov reg,reg
3 bytes~25%mov reg,[reg], add reg,imm8
4~5 bytes~25%call rel32, jmp rel32, mov reg,[base+disp8]
6~10 bytes~14%mov reg,imm64, complex addressing
11~15 bytes~1%다중 prefix + disp32 + imm32

평균 명령어 길이: 약 3.5~4.0 bytes. 이는 고정 4-byte ARM 명령어와 비슷한 코드 밀도를 만든다.

15바이트 한계 도달 예시

실전에서 15바이트에 도달하는 경우는 극히 드물다. 컴파일러는 보통 불필요한 prefix를 생성하지 않는다.

크로스 페이지 명령어의 page fault 시나리오

Page A: 0x4000~0x4FFF (present)
Page B: 0x5000~0x5FFF (not present)

RIP = 0x4FFD → 명령어: mov rax, [rip+0x12345678] (7 bytes)
  fetch 범위: 0x4FFD ~ 0x5003
  → Page B에서 #PF 발생
  → OS가 Page B를 매핑 후 CPU가 같은 명령어를 재시도

PintOS의 lazy loading에서 이 시나리오가 실제로 발생할 수 있다.

    A["RIP 주소에서<br/>바이트 읽기"] --> B{"prefix?"}

    C --> B
    B -- no --> D["opcode 판별<br/>(1~3 bytes)"]
    D --> E{"ModR/M<br/>필요?"}
    E -- yes --> F["ModR/M 읽기"]
    F --> G{"SIB 필요?"}
    G -- yes --> H["SIB 읽기"]
    G -- no --> I{"disp 필요?"}
    H --> I
    E -- no --> J{"imm 필요?"}
    I -- yes --> K["disp 읽기<br/>(1/2/4 bytes)"]
    I -- no --> J
    K --> J
    J -- yes --> L["imm 읽기<br/>(1/2/4/8 bytes)"]
    J -- no --> M["디코딩 완료"]
    L --> M
    M --> N["RIP += 명령어 길이"]
