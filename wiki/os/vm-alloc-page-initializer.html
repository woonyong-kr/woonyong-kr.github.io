vm_alloc_page_with_initializer() — UNINIT 페이지 등록

vm_alloc_page_with_initializer() — UNINIT 페이지 등록

한 줄 요약: vm_alloc_page_with_initializer()는 물리 프레임을 한 바이트도 할당하지 않고 page fault가 났을 때 프레임을 채울 메타데이터만 SPT에 UNINIT 페이지로 등록하는 lazy loading의 출발점이다.

vm_alloc_page_with_initializer()가 예약하는 것

프로그램이 아직 접근하지 않은 가상 페이지에 물리 프레임부터 할당하면, 실제 사용 여부와 관계없이 메모리를 차지한다. PintOS의 vm_alloc_page_with_initializer()는 이를 피하기 위해 페이지를 즉시 적재하지 않고 SPT에 먼저 등록한다. 이 단계에서는 나중에 page fault가 발생했을 때 프레임을 어떻게 채울지 설명하는 메타데이터만 저장한다.

함수는 struct page를 malloc으로 할당하고 uninit_new()로 UNINIT 타입을 구성한 뒤, SPT 해시 테이블에 삽입한다. 이때 struct page 자체는 만들어지지만 실제 물리 프레임은 할당되지 않는다. 따라서 이 함수는 lazy loading과 demand paging이 시작되는 예약 단계에 해당한다.

Demand Paging에서 필요한 예약 정보

전통적인 즉시 적재(eager loading)는 프로그램이 시작될 때 모든 세그먼트를 물리 메모리에 올린다. Demand paging은 먼저 가상 주소를 예약한다. 이후 해당 주소에 실제 접근이 일어나 page fault가 발생하면 물리 프레임을 할당하고 내용을 채운다.

이 과정을 나중에 이어서 수행하려면 예약 시점에 다음 정보를 남겨야 한다.

  • 가상 주소 (va): 페이지를 매핑할 유저 주소
  • 최종 타입 (type): ANON인지 FILE인지 나타내며, page fault 후 실행할 initializer를 결정하는 값
  • 적재 콜백 (init): 프레임을 얻은 뒤 파일 데이터를 읽어 오는 함수. 예를 들어 lazy_load_segment가 있다.
  • 콜백 인자 (aux): 파일 오프셋과 읽을 바이트 수처럼 적재 콜백에 필요한 파라미터
  • 쓰기 가능 여부 (writable): PTE의 writable 비트를 설정하는 데 쓰이는 값

이 정보가 있으므로 현재는 프레임이 없는 UNINIT 페이지라도, 실제 접근이 발생한 뒤 최종 페이지 타입으로 전환하고 데이터를 적재할 수 있다.

Linux의 VMA와 비교

Linux에서는 mmap() 시스템 콜이 VMA(vm_area_struct)를 생성하는 과정이 비슷한 역할을 한다. mmap()은 물리 메모리를 바로 할당하지 않고 VMA를 먼저 등록한다. 이후 page fault가 발생하면 do_page_fault() → handle_mm_fault() → do_fault() 경로에서 실제 페이지를 할당하고 파일 데이터를 읽는다.

init 콜백vm_ops->fault
auxVMA의 vm_file, vm_pgoff 등
SPT 해시 테이블mm_struct의 VMA 트리 (maple tree)

등록 단계의 실행 흐름

먼저 함수는 upage가 페이지 경계에 정렬되어 있고 type이 UNINIT이 아닌 최종 타입인지 확인한다. 이어 현재 스레드의 SPT에서 같은 가상 주소가 이미 등록되었는지 검사한다. 주소가 NULL이거나 기존 페이지가 발견되면 등록하지 않는다.

검사를 통과하면 heap에 struct page를 할당한다. type이 VM_ANON이면 anon_initializer를, VM_FILE이면 file_backed_initializer를 선택한다. 선택한 initializer와 호출자가 넘긴 init, aux를 uninit_new()에 전달해 UNINIT 페이지를 만든다. 마지막으로 writable을 기록하고 페이지를 SPT에 삽입한다.

uninit_new()가 보존하는 정보

uninit_new()는 struct page를 designated initializer로 채운다.

.frame = NULL은 아직 물리 프레임이 없다는 뜻이다. .uninit에는 최종 타입, 타입별 initializer, 적재 콜백과 그 인자가 함께 저장된다. .operations = &uninit_ops로 설정되므로 이 페이지에서 swap_in이 호출되면 uninit_initialize()로 디스패치된다.

Page fault 이후의 실제 초기화

등록된 가상 주소에 사용자가 접근하면 page fault 처리 경로가 페이지를 claim한다. 이때 프레임과 PML4 매핑을 준비한 뒤 UNINIT 페이지의 swap_in을 호출한다.

%% vm_alloc_page_with_initializer page fault 초기화 흐름
flowchart TD
  load_segment["load_segment()<br/>VM_ANON"]
  alloc["vm_alloc_page_with_initializer()<br/>malloc(struct page)<br/>uninit_new(page, upage, init, type, aux, initializer)"]
  spt["SPT Hash Table<br/>spt_insert_page(page)<br/>frame = NULL<br/>PML4 매핑 없음"]
  elapsed["... 시간 경과: 유저가 upage 접근 ..."]
  fault["Page Fault Handler<br/>page_fault<br/>vm_try_handle_fault<br/>vm_do_claim_page"]
  frame["프레임과 PML4 매핑<br/>palloc_get_page(PAL_USER) -&gt; kva<br/>pml4_set_page(pml4, page-&gt;va, frame-&gt;kva, page-&gt;writable)"]
  swap_in["page-&gt;operations-&gt;swap_in(page, frame-&gt;kva)"]
  initialize["uninit_initialize()<br/>anon_initializer(page, type, frame-&gt;kva)<br/>init(page, aux)"]
  done["SPT의 page 갱신<br/>page.frame = frame<br/>UNINIT -&gt; ANON 전환 완료"]
  load_segment --> alloc
  alloc --> spt
  spt -.-> elapsed
  elapsed -.-> fault
  fault --> frame
  frame --> swap_in
  swap_in --> initialize
  initialize --> done

uninit_initialize()는 저장해 둔 두 종류의 함수를 차례로 실행한다.

  1. page_initializer(page, type, kva) — anon_initializer() 또는 file_backed_initializer()를 호출해 page의 operations를 최종 타입으로 전환한다. 이 시점에 .operations가 uninit_ops에서 anon_ops 또는 file_ops로 바뀐다.
  2. init(page, aux) — lazy_load_segment(page, aux)를 호출해 파일의 실제 데이터를 프레임(kva)에 읽어 들인다.

따라서 page_initializer는 페이지의 동작 타입을 바꾸고, init은 프레임에 필요한 내용을 채운다. 예약 단계에서 함께 저장한 두 함수가 page fault 시점에 서로 다른 역할을 수행한다.

UNINIT 페이지의 값과 메모리 비용

UNINIT 페이지 하나를 등록하면 물리 프레임 대신 struct page와 적재 인자만 먼저 할당된다.

항목크기설명
struct page약 72 bytesmalloc 할당 (heap)
struct lazy_load_arg (aux)약 24 bytesmalloc 할당 (호출자에서)
PML4 매핑0 bytes아직 없음
물리 프레임0 bytes아직 없음
합계~96 bytesvs. 즉시 적재 시 4096+ bytes

100 페이지짜리 프로그램을 가정한 계산은 다음과 같다.

  • 즉시 적재: 100 × 4096 = 400 KB (물리 프레임) + 100 × 72 = 7.2 KB (page 구조체)
  • Lazy 등록만: 100 × 96 = 9.6 KB
  • 실제 접근하는 페이지가 20개라면: 20 × 4096 + 100 × 96 = 80 KB + 9.6 KB = 89.6 KB

이 수치는 문서에 제시된 구조체 크기와 페이지 수를 바탕으로 한 계산이다. 실제 사용량을 측정한 실행 결과를 뜻하지는 않는다.

UNINIT에서 ANON으로 바뀌는 상태

다음 개념도는 예약 직후의 struct page와 page fault 이후의 상태를 비교한다. 예약 직후에는 frame = NULL이고 UNINIT 전용 정보가 들어 있다. 초기화가 끝나면 operations와 union의 내용이 ANON 상태에 맞게 바뀌고 실제 frame을 가리킨다.

%% struct page UNINIT에서 ANON 상태 전환
flowchart LR
  uninit["struct page (UNINIT 상태)<br/>operations = &amp;uninit_ops<br/>va = 0x400000 (예시)<br/>frame = NULL<br/>writable = true/false<br/>union { struct uninit_page }<br/>.init = lazy_load_segment<br/>.type = VM_ANON<br/>.aux = lazy_load_arg*<br/>.page_initializer = anon_initializer"]
  file_read["lazy_load_arg*<br/>{file"]
  final_type["최종 타입<br/>VM_ANON<br/>anon_initializer"]
  anon["page fault 후 (ANON 상태)<br/>operations = &amp;anon_ops<br/>va = 0x400000<br/>frame = &amp;frame<br/>writable = true/false<br/>union { struct anon_page }<br/>.swap_slot = -1 (not swapped)"]
  frame["struct frame<br/>{ kva"]
  uninit --> anon
  uninit --> file_read
  uninit --> final_type
  anon --> frame
