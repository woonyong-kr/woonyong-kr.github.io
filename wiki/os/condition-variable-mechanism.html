조건 변수 메커니즘 (Condition Variable)

조건 변수 메커니즘 (Condition Variable)

조건 변수는 락만으로는 표현하기 어려운 “조건이 될 때까지 기다리기”를 위한 동기화 도구다. 스레드는 조건이 거짓이면 잠들고, 다른 스레드가 조건을 바꾸면 다시 깨어나 확인한다.

락이 보호하고 조건 변수가 기다린다

Lock은 한 번에 한 스레드만 공유 상태를 바꾸게 해 주지만, “버퍼가 비어 있으면 기다린다” 같은 조건 자체를 기억하지는 않는다. Condition Variable은 이 빈칸을 채운다. 스레드는 lock을 잡은 채 조건을 확인하고, 조건이 맞지 않으면 cond_wait()으로 잠든다. 다른 스레드가 상태를 바꾼 뒤 cond_signal()을 호출하면 대기 중인 스레드가 깨어나 조건을 다시 확인한다. PintOS에서는 이 기다림을 각 대기자마다 하나씩 만드는 private semaphore로 구현한다.

기다림과 깨움의 규칙

Monitor와 Condition Variable

Hoare(1974)와 Hansen이 제안한 Monitor는 Lock + Condition Variable을 묶은 고수준 동기화 구조다. 두 가지 의미론이 있다:

스타일signal 후 누가 실행?사용처
Hoaresignal을 받은 스레드가 즉시 실행이론 교과서, 일부 연구 OS
Mesasignaler가 계속 실행, 대기자는 READY로 전이PintOS, pthread, Java, Linux

Mesa 스타일에서는 signal을 받아 깨어난 뒤에도 조건이 다시 거짓일 수 있다 (다른 스레드가 먼저 자원을 가져감). 따라서 while 루프로 조건을 재검사해야 한다:

실제 OS (Linux / POSIX)

POSIX pthread_cond_t는 pthread_mutex_t와 쌍으로 사용되지만 구현 수단은 규격이 정하지 않는다. Linux의 glibc 구현은 보통 futex를 활용한다:

  • pthread_cond_wait(): mutex unlock → futex WAIT → mutex relock
  • pthread_cond_signal(): futex WAKE 1개
  • pthread_cond_broadcast(): futex WAKE 전체

Linux 커널 내부에서는 wait_queue_head_t + wait_event() / wake_up()이 조건 변수 역할을 한다. wait_event(wq, condition) 매크로가 while 루프 + schedule()을 감싸고 있다.

PintOS 구현 — Private Semaphore 패턴

PintOS의 조건 변수는 세마포어 리스트로 구현된다. 각 대기 스레드가 자기만의 세마포어를 갖는다.

공유 세마포어 1개 (초기값 0)signal N회 → 나중 도착한 스레드가 가로챔각 대기자에 전용 sema → 정확한 대상 깨움
스레드 직접 unblocklock_release~sema_down 사이 racesema value로 signal 보존

전형적 사용 패턴: Producer-Consumer

조건 변수 메커니즘 값 추적

항목값
struct condition 크기list (16 bytes)
struct semaphore_elem 크기list_elem(16) + semaphore(~24) = ~40 bytes
private semaphore 초기값0 (signal 전까지 BLOCKED)
cond_signal 시 깨우는 수1개 (최고 우선순위)
cond_broadcast 시 깨우는 수waiters 전체
cond_wait의 lock release→reacquire원자적이 아님 (Mesa 스타일)

순서도

sequenceDiagram
    participant W as Waiter (Thread A)
    participant S as Signaler (Thread B)
    participant CV as Condition Variable
    participant LK as Lock

    W->>LK: lock_acquire
    W->>CV: cond_wait → sema_init(0)
    W->>CV: list_push_back(waiters)
    W->>LK: lock_release
    W->>W: sema_down → BLOCKED

    S->>LK: lock_acquire
    S->>S: 조건 변경
    S->>CV: cond_signal
    CV->>CV: list_sort(priority)
    CV->>W: sema_up → READY
    S->>LK: lock_release

    W->>LK: lock_acquire (재획득)
    W->>W: while 조건 재검사
    Note over W: 조건 충족 → 진행
