PintOS 교육용 OS

PintOS 교육용 OS

확인 범위: 이 문서는 PintOS가 운영체제의 핵심 메커니즘을 교육용으로 유지·단순화한 방식과 그 선택 기준을 개념적으로 설명한다. 제시된 디렉터리·함수·코드 규모와 Linux·Windows 비교 수치는 특정 코드베이스와 버전, 설정에 따라 달라질 수 있으므로 실제 구현·실행 기록·성능을 검증한 결과로 간주하지 않는다.

한 줄 요약: 약 3만 줄로 스레드·메모리 등 OS 본질 메커니즘을 직접 구현하며 배우는 Stanford 교육용 OS PintOS.

PintOS 교육용 OS 구조

PintOS는 Stanford에서 만든 교육용 운영체제로, 실제 OS의 핵심 개념을 직접 구현하며 배울 수 있도록 설계되었다. Linux 커널이 수천만 줄인 반면 PintOS는 약 3만 줄로, OS의 본질적 메커니즘(스레드, 가상 메모리, 파일 시스템, 시스템 콜)만 남기고 나머지를 과감히 단순화하거나 생략했다. “무엇을 남겼는가”보다 **“무엇을 빼고 왜 뺐는가”**를 이해하면 실제 OS의 복잡성이 어디서 오는지 역으로 파악할 수 있다.

상세 설명

PintOS가 유지하는 것 (실제 OS와 동일)

PintOS는 교육 목적에 핵심적인 메커니즘을 실제 하드웨어 규격 그대로 구현한다:

x86-64 하드웨어 규격 준수:

  • 4단계 page table walk (PML4 → PDPT → PD → PT)
  • PTE 비트 (Present, Writable, User, Accessed, Dirty)
  • CR3 레지스터로 주소 공간 전환
  • TSS의 rsp0으로 커널 스택 전환
  • syscall / sysret 명령어와 LSTAR MSR
  • interrupt descriptor table (IDT)과 pf, gp 등 exception
  • timer interrupt (PIT 8254) → preemptive scheduling

OS 핵심 추상화:

  • 스레드 상태 전이 (READY → RUNNING → BLOCKED)
  • 세마포어, 락, 조건 변수
  • 프로세스 fork / wait / exit
  • 가상 메모리와 demand paging
  • 파일 시스템 (FAT 기반)

핵심 단순화의 교육적 타당성

1. 단일 CPU:

실제 OS에서 spin_lock_irqsave()가 필요한 곳에 PintOS는 intr_disable()만으로 충분하다. 인터럽트를 끄면 같은 CPU에서 다른 스레드가 실행될 수 없으므로 임계 구역이 보호된다. 이 단순함 덕분에 세마포어와 lock의 의미론(왜 필요한지, 어떻게 BLOCKED 상태로 전이하는지)에 집중할 수 있다.

2. palloc 단순 할당자:

Linux의 buddy system은 2^n 페이지 블록을 분할/병합하는 복잡한 알고리즘이다. PintOS의 palloc은 비트맵에서 빈 페이지를 찾아 반환하는 O(n) 스캔이다. 이 단순함 덕분에 “페이지 할당 = 물리 프레임 하나 확보”라는 핵심에 집중할 수 있다.

3. FAT 파일 시스템:

ext4의 extent tree, 저널링, delayed allocation 대신 FAT의 단순 연결 리스트를 사용한다. 클러스터 N의 다음 클러스터를 FAT[N]에서 읽는 직관적 구조다. 블록 할당의 기본 원리(빈 블록 찾기, 연결, 해제)를 배우기에 충분하다.

PintOS 디렉터리 구조

  • pintos/
    • threads/: 커널 부트, 스레드, 동기화, 메모리 관리
      • init.c: main() 커널 진입점
      • thread.c: 스레드 생성, 스케줄링
      • synch.c: 세마포어, 락, 조건 변수
      • palloc.c: 페이지 할당자
      • malloc.c: 힙 할당자
      • mmu.c: page table 조작
      • interrupt.c: IDT, 인터럽트 처리
    • userprog/: 유저 프로그램 지원
      • process.c: fork, exec, wait, exit
      • syscall.c: system call handler
      • exception.c: page fault 등 exception
      • tss.c: TSS 관리
      • gdt.c: GDT 설정
    • vm/: 가상 메모리
      • vm.c: SPT, claim, eviction
      • anon.c: anonymous page + swap
      • file.c: file-backed page + mmap
      • inspect.c: 디버깅용 검사
    • filesys/: 파일 시스템
      • filesys.c: 파일 시스템 인터페이스
      • inode.c: FAT 위에 inode 추상화 구현
      • fat.c: FAT 테이블 관리
      • directory.c: 디렉터리
    • devices/: 하드웨어 드라이버
      • timer.c: PIT 타이머
      • disk.c: IDE 디스크
      • kbd.c: 키보드
      • vga.c: VGA 텍스트 모드
    • lib/: 유저/커널 공용 라이브러리
    • include/: 헤더 파일

실제 OS (Linux/Windows)

Linux 커널 6.x 기준:

  • 총 코드: ~3,000만 줄 (PintOS의 ~1,000배)
  • drivers/ 디렉터리만 전체의 60% 이상
  • 파일 시스템 종류: 30+ (ext4, xfs, btrfs, nfs, fuse 등)
  • 아키텍처 지원: 20+ (x86, ARM, RISC-V 등)
  • 스케줄러 클래스: CFS, RT, Deadline, IDLE
  • 메모리 관리: buddy + slab + vmalloc + huge pages + NUMA

Windows NT 커널:

  • 유사한 규모와 복잡도
  • HAL(Hardware Abstraction Layer)로 하드웨어 차이 흡수
  • 파일 시스템: NTFS (MFT 기반 B-tree)

QEMU 에뮬레이션

PintOS가 QEMU 위에서 돌아간다는 것은 “실제 하드웨어 없이도 OS 실습이 가능”하게 만드는 핵심 결정이다. QEMU가 PIT, PIC, IDE controller를 소프트웨어로 재현하므로, PintOS는 이 장치들이 실제로 존재하는 것처럼 I/O 포트에 접근한다. 이 덕분에 “운영체제가 하드웨어를 어떻게 다루는가”라는 본질적 질문을 안전한 환경에서 탐구할 수 있다.

프로젝트별 대표 구현 범위:

  • Project 1 — Threads: alarm clock, priority scheduling, priority donation
  • Project 2 — User Programs: argument passing, system call, fork/wait/exec, file descriptor
  • Project 3 — Virtual Memory: SPT, lazy loading, stack growth, mmap, eviction, swap
  • Project 4 — File System: extensible files, subdirectory, buffer cache(선택)
