섹터·클러스터·슈퍼블록

섹터·클러스터·슈퍼블록

확인 범위: 이 문서는 섹터·클러스터·슈퍼블록의 일반 개념과 크기 선택에 따른 관리 비용·내부 단편화의 trade-off를 설명하고, PintOS와 QEMU의 구조 및 동작은 입력에 제시된 코드와 계산을 바탕으로 한 구현 예시로 다룬다. 실제 코드·버전별 세부 동작, 디스크 레이아웃, 실행 결과와 성능은 별도의 소스 확인·실행 기록·측정 없이는 검증된 사실로 간주하지 않는다.

한 줄 요약: 섹터는 디스크 하드웨어가 한 번에 읽고 쓰는 최소 단위이고, 클러스터는 파일 시스템이 할당하는 논리 단위이며, 슈퍼블록은 파일 시스템 전체의 설계도를 담는 특수 영역이다.

섹터·클러스터·슈퍼블록 구분

디스크는 수십억 바이트의 연속된 공간이다. 이 공간을 아무 규칙 없이 사용하면 “파일 A는 어디서 시작하고 어디서 끝나는지”, “빈 공간은 어디인지”를 알 방법이 없다. 디스크 공간을 일정한 크기로 나누고, 그 나눈 단위로 할당·추적해야 파일 시스템이 동작한다.

이 문서는 디스크 공간을 나누는 세 가지 층위를 다룬다.

  • 섹터 (Sector): 하드웨어가 정하는 물리적 최소 단위
  • 클러스터 (Cluster): 파일 시스템이 정하는 논리적 할당 단위
  • 슈퍼블록 (Super Block): 파일 시스템의 메타데이터를 담는 특수 영역

이 세 개념을 모르면 inode, FAT, free map 같은 파일 시스템 구조를 이해할 수 없다.

섹터·클러스터·슈퍼블록 흐름

섹터 — 하드웨어의 최소 단위

디스크 컨트롤러에게 “이 데이터를 읽어라”라고 요청할 때, 1바이트만 읽을 수는 없다. 하드웨어는 항상 고정된 크기 단위로 읽고 쓴다. 이 단위가 섹터다.

전통적인 HDD와 대부분의 교육용 OS에서 섹터 크기는 512바이트다. 최신 HDD/SSD는 4KB 섹터(Advanced Format)를 쓰기도 하지만, 하위 호환을 위해 512B 에뮬레이션을 제공하는 경우가 많다.

핵심 속성:

  • 디스크의 물리적 읽기/쓰기 단위다. “섹터 37번을 읽어라”처럼 번호로 접근한다.
  • 파일이 1바이트여도 최소 1섹터(512B)를 차지한다.
  • 섹터 번호는 0번부터 시작하는 정수다. disk_sector_t 타입으로 표현한다.

클러스터 — 파일 시스템의 할당 단위

섹터 하나(512B)를 할당 단위로 쓰면 문제가 생긴다. 1GB 디스크에는 약 200만 개의 섹터가 있고, 각 섹터의 할당 상태를 추적하려면 200만 비트(약 250KB)의 비트맵이 필요하다. 디스크가 커지면 관리 비용이 급격히 증가한다.

그래서 파일 시스템은 여러 섹터를 묶어 하나의 클러스터로 취급한다. FAT32에서는 보통 4KB(8섹터) 또는 32KB(64섹터)를 하나의 클러스터로 쓴다. 할당 단위가 커지면 관리 테이블은 작아지지만, 작은 파일이 공간을 낭비하는 내부 단편화가 생긴다.

왜 클러스터 크기가 4KB~32KB인가?

비트맵 크기 = 전체 클러스터 수 × 1비트

  • 1GB 디스크, 512B 클러스터 → 2,097,152개 → 비트맵 256KB
  • 1GB 디스크, 4KB 클러스터 → 262,144개 → 비트맵 32KB
  • 1GB 디스크, 32KB 클러스터 → 32,768개 → 비트맵 4KB

클러스터가 클수록 비트맵은 작아지지만, 1KB 파일이 32KB를 차지하는 낭비가 생긴다. 4KB는 메모리 페이지 크기와 일치해서 가상 메모리 연동에도 유리하다.

슈퍼블록 — 파일 시스템의 설계도

디스크를 포맷하면 맨 앞 영역에 파일 시스템의 전체 구조 정보를 기록한다. 이 영역이 슈퍼블록이다.

슈퍼블록에는 다음 정보가 들어간다.

  • 매직 넘버: 이 디스크가 어떤 파일 시스템인지 식별하는 값
  • 전체 섹터/클러스터 수
  • FAT 시작 위치와 크기 (FAT 파일 시스템인 경우)
  • 루트 디렉터리 위치
  • 클러스터당 섹터 수

슈퍼블록이 망가지면 파일 시스템 전체를 읽을 수 없다. 그래서 실제 OS(ext4 등)는 슈퍼블록 복사본을 여러 곳에 분산 저장한다.

디스크 레이아웃 전체 그림

%% 디스크 레이아웃 전체 구조
flowchart LR
  layout["{슈퍼블록<br/>(부트섹터)<br/>섹터 0&#124;관리 영역<br/>(FAT/비트맵)<br/>섹터 1~N&#124;데이터 영역<br/>(파일 내용 + inode)<br/>섹터 N+1 ~ 끝}"]
  • 슈퍼블록(부트섹터): 파일 시스템 메타데이터. 섹터 0에 위치.
  • 관리 영역: 어떤 클러스터가 사용 중인지 추적 (FAT 테이블 또는 비트맵).
  • 데이터 영역: 실제 파일 내용과 inode가 저장되는 공간.

QEMU 에뮬레이션 관점

PintOS가 disk_read(filesys_disk, sector, buffer)를 호출하면 실제로는 QEMU가 에뮬레이션하는 IDE 컨트롤러에 I/O 포트 명령이 전달된다. QEMU 내부에서 섹터 번호는 바이트 오프셋으로 변환된다.

%% QEMU 섹터 읽기 흐름
flowchart TD
  pintos["PintOS 커널<br/>disk_read(disk, 24, buf)"]
  ports["IDE I/O 포트<br/>0x1F3~6: LBA=24<br/>0x1F7: READ SECTORS<br/>데이터 포트에서 읽기"]
  qemu_ide["QEMU IDE 에뮬레이션<br/>ide_sector_read()<br/>sector 24"]
  offset["바이트 오프셋 계산<br/>24 x 512 = 12288<br/>= byte offset 0x3000"]
  backend["QEMU BlockBackend<br/>blk_pread(offset, 512)"]
  host["호스트 파일<br/>pread(fd,<br/>offset=12288,<br/>size=512)"]
  pintos -->|디스크 명령 기록| ports
  ports -->|IDE 명령 처리| qemu_ide
  qemu_ide -->|섹터 번호 변환| offset
  offset -->|512바이트 읽기| backend
  backend -->|pintos.dsk 접근| host

QEMU의 블록 백엔드는 pintos.dsk 같은 호스트 파일을 열어두고, 섹터 번호 × 512를 바이트 오프셋으로 계산하여 호스트 파일의 해당 위치를 읽는다. 따라서 PintOS가 “섹터 24번”이라고 부르는 위치는 호스트 디스크 이미지 파일의 바이트 12288(0x3000) 지점이다. 디버깅 시 hexdump -C -s 0x3000 -n 512 pintos.dsk로 해당 섹터의 실제 내용을 확인할 수 있다.

자세한 변환 체인은 QEMU BlockBackend, IDE 컨트롤러 에뮬레이션 구조는 IDE 컨트롤러 모델.

섹터·클러스터·슈퍼블록 코드

PintOS의 섹터 정의

PintOS에서 모든 디스크 I/O는 disk_read()와 disk_write()로 이루어지며, 항상 512바이트 단위로 동작한다. 섹터 번호 하나를 넘기면 해당 위치에서 512바이트를 읽거나 쓴다.

PintOS의 클러스터 (FAT 모드)

PintOS는 교육 목적으로 SECTORS_PER_CLUSTER를 1로 고정한다. 즉 클러스터 = 섹터이며, 실제 FAT32처럼 여러 섹터를 묶지 않는다. 이 덕분에 클러스터 번호와 섹터 번호 사이의 변환이 단순해진다.

PintOS의 슈퍼블록 (FAT 부트 섹터)

이 구조체가 섹터 0(부트 섹터)에 기록된다. fat_boot_create()에서 값을 채우고, fat_init()에서 디스크에서 읽어온다. 파일 시스템을 처음 포맷할 때 fat_create() → fat_boot_create()가 호출되어 이 슈퍼블록을 생성한다.

PintOS의 슈퍼블록 (Original FS, 비트맵 모드)

FAT 모드가 아닌 원래 PintOS 파일 시스템에서는 슈퍼블록 대신 두 개의 고정 섹터를 예약한다.

Original FS는 별도의 슈퍼블록 구조체 없이, 섹터 0에 free map inode를, 섹터 1에 루트 디렉터리 inode를 고정 배치한다. free map은 비트맵으로 각 섹터의 사용 여부를 추적한다.

PintOS 디스크 레이아웃 비교

%% PintOS 디스크 레이아웃 비교
flowchart TD
  original["{Original FS&#124;섹터 0<br/>free-map inode&#124;섹터 1<br/>root-dir inode&#124;섹터 2~<br/>데이터 + inode}"]
  fat["{FAT 모드 (EFILESYS)&#124;섹터 0<br/>fat_boot<br/>(슈퍼블록)&#124;섹터 1~N<br/>FAT 테이블&#124;섹터 N+1~<br/>데이터<br/>(클러스터)}"]

실제 OS와 PintOS의 차이

항목실제 OS (ext4/FAT32)PintOS
섹터 크기512B 또는 4KB512B 고정
클러스터 크기4KB~64KB512B (클러스터 = 섹터)
슈퍼블록 복사본여러 곳에 백업복사본 없음
슈퍼블록 내용UUID, 마운트 횟수, 저널 위치 등매직, FAT 위치, 루트 디렉터리 위치

정리

섹터는 디스크 하드웨어의 물리적 I/O 단위(512B)이고, 클러스터는 파일 시스템이 공간을 할당하는 논리 단위이며, 슈퍼블록은 파일 시스템의 전체 구조 정보를 담는 메타데이터 영역이다. PintOS에서는 클러스터 크기를 섹터와 동일하게 유지하여 구조를 단순화했다. 이 세 개념은 inode, FAT 테이블, free map 등 파일 시스템의 모든 상위 구조를 이해하는 기반이 된다.
