deny_write_cnt 관리

deny_write_cnt 관리

한 줄 요약: 실행 중 ELF가 수정돼 코드가 깨지지 않도록 inode마다 deny_write_cnt 참조 카운터로 쓰기를 거부하는 메커니즘.

deny_write_cnt 관리 변화

실행 중인 프로그램의 ELF 파일이 수정되면 코드가 깨질 수 있다. 이를 방지하기 위해 inode마다 deny_write_cnt 카운터를 두고, 0보다 크면 해당 inode에 대한 모든 쓰기를 거부한다. 이 카운터는 참조 카운팅 방식으로 동작해서, 같은 실행 파일을 여러 프로세스가 동시에 실행해도 모든 프로세스가 종료할 때까지 쓰기가 차단된다.

상세 설명

추상 개념 (실행 파일 보호)

OS는 실행 중인 바이너리의 무결성을 보장해야 한다. CPU가 fetch하는 명령어의 원본이 디스크의 ELF 파일이므로, 해당 파일이 변경되면 page-in 시 다른 바이트가 올라와 예측 불가능한 동작이 발생한다.

보호 전략은 두 가지가 있다:

전략설명사용처
Copy 방식ELF를 메모리에 완전히 복사, 원본과 분리일부 임베디드 OS
Deny-write 방식원본 파일에 쓰기 잠금Linux, PintOS

PintOS는 deny-write 방식을 사용한다.

실제 OS (Linux)

Linux에서는 struct inode의 i_writecount가 같은 역할을 한다. execve() → deny_write_access() → atomic_dec(&inode->i_writecount)로 카운터를 -1로 만들고 (음수가 “deny” 의미), allow_write_access()로 복원한다. open() 시 O_WRONLY나 O_RDWR로 열려고 하면 i_writecount < 0이면 -ETXTBSY 에러를 반환한다.

카운터가 0이 되어야만 외부에서 해당 파일에 write할 수 있다.

rox-child 테스트 시나리오:

  1. 부모 exec(“rox-child”) → deny_write_cnt = 1
  2. 자식 open(“rox-child”) → open_cnt 증가하지만 deny_write_cnt는 그대로 (일반 open은 deny 안 함)
  3. 자식 write(“rox-child”, …) → inode->deny_write_cnt == 1이므로 return 0
  4. 부모/자식 exit → deny_write_cnt = 0
