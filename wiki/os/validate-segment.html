validate_segment() — ELF 세그먼트 유효성 검증

ELF Program Header는 파일의 어느 바이트를 어떤 유저 가상 주소에 올릴지 알려 준다. validate_segment()는 그 약속이 커널을 망가뜨리지 않는지 확인하고, 통과한 세그먼트만 load_segment()로 넘긴다.

validate_segment() 구조

validate_segment()는 ELF 파일의 Program Header(Phdr)가 유효한 로드 가능 세그먼트를 기술하는지 검증하는 함수다. 악의적이거나 손상된 ELF 파일이 커널을 망가뜨리지 못하도록 6가지 불변 조건을 검사한다. 이 함수를 통과해야만 load_segment()가 호출되어 실제 메모리에 세그먼트가 적재된다.

상세 설명

추상 개념 (CPU/하드웨어 규칙)

CPU/MMU는 ELF 형식을 모른다. ELF 파싱과 검증은 순전히 OS의 소프트웨어 책임이다. 그러나 검증이 실패하면 하드웨어 수준에서 문제가 발생할 수 있다:

위반 항목하드웨어 결과
커널 주소에 유저 세그먼트 매핑pf (PTE user bit 위반) 또는 커널 데이터 오염
0번 페이지 매핑NULL 포인터 접근이 성공해버림 (디버깅 불가능)
주소 wraparound64비트 주소 공간 끝을 넘어 예측 불가능 동작

PintOS 구현

6가지 검증 조건 상세:

#조건의미위반 시 위험
①(p_offset & PGMASK) == (p_vaddr & PGMASK)파일 offset과 VA의 페이지 내 위치가 동일load_segment가 잘못된 바이트를 읽음
②p_offset ≤ file_length파일 범위를 초과하는 offset 거부파일 밖 읽기 시도
③p_memsz ≥ p_filesz메모리 크기가 파일 크기 이상BSS 음수 크기 → 오버플로
④is_user_vaddr(p_vaddr) 및 끝 주소세그먼트 전체가 유저 공간 내커널 주소 공간 오염
⑤p_vaddr + p_memsz ≥ p_vaddr64비트 덧셈 wraparound 방지주소 공간 전체를 덮는 세그먼트
⑥p_vaddr ≥ PGSIZE0번 페이지(0x0~0xFFF) 매핑 방지NULL deref가 성공해버림

QEMU 에뮬레이션

QEMU는 validate_segment()를 인식하지 않는다. 이 함수는 순수 소프트웨어 검증이므로 일반 명령어 실행으로 처리된다. 단, 검증을 통과한 세그먼트가 MMU 테이블에 매핑되면, QEMU의 softmmu가 해당 PTE를 통해 guest physical memory 접근을 에뮬레이션한다.

검증이 없다면: QEMU 환경에서도 커널 주소에 유저 페이지가 매핑되어 GDB로 디버깅 시 혼란을 일으킬 수 있다.

validate_segment() 값 추적

예제: ls 바이너리의 PT_LOAD 세그먼트 검증

Phdr 값:
  p_offset = 0x1000
  p_vaddr  = 0x401000
  p_filesz = 0x2A00 (10752 bytes)
  p_memsz  = 0x3000 (12288 bytes)
  p_flags  = PF_R | PF_X

검증 ①: (0x1000 & 0xFFF) == (0x401000 & 0xFFF)
         0x000 == 0x000 → PASS

검증 ②: 0x1000 ≤ file_length(예: 0x5000) → PASS

검증 ③: 0x3000 ≥ 0x2A00 → PASS
         (BSS = p_memsz - p_filesz = 0x600 = 1536 bytes)

검증 ④: is_user_vaddr(0x401000) → 0x401000 < KERN_BASE(0x8004000000) → PASS
         is_user_vaddr(0x401000 + 0x3000 = 0x404000) → PASS

검증 ⑤: 0x401000 + 0x3000 = 0x404000 ≥ 0x401000 → PASS (no wrap)

검증 ⑥: 0x401000 ≥ 0x1000 (PGSIZE) → PASS

load_segment 호출 시 계산:

read_bytes = p_filesz - (p_vaddr 페이지 내 offset 보정)
           = 0x2A00 bytes → 파일에서 읽을 양
zero_bytes = p_memsz - p_filesz = 0x600 bytes → 0으로 채울 BSS

순서도 / 개념도

flowchart TD
    A[load_program_headers 루프] --> B{p_type == PT_LOAD?}
    B -->|No| A
    B -->|Yes| C[validate_segment]
    C --> D{offset & PGMASK<br>== vaddr & PGMASK?}
    D -->|No| FAIL[return false → load 실패]
    D -->|Yes| E{p_offset ≤ file_length?}
    E -->|No| FAIL
    E -->|Yes| F{p_memsz ≥ p_filesz?}
    F -->|No| FAIL
    F -->|Yes| G{is_user_vaddr 시작/끝?}
    G -->|No| FAIL
    G -->|Yes| H{no wraparound?}
    H -->|No| FAIL
    H -->|Yes| I{p_vaddr ≥ PGSIZE?}
    I -->|No| FAIL
    I -->|Yes| J[load_loadable_segment 호출]
