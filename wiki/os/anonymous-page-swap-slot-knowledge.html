Anonymous Page와 Swap Slot

Anonymous Page와 Swap Slot

한 줄 요약: Anonymous page는 파일 backing이 없는 스택·힙·BSS 페이지라 eviction될 때 원본 파일이 없어, bitmap으로 관리하는 swap 디스크의 4KB slot에 내용을 저장했다가 다시 접근하면 swap in한다.

Anonymous Page와 Swap 차이

Anonymous page는 파일에 의해 backing되지 않는 메모리 페이지다. 스택, 힙, BSS 영역이 여기에 해당한다. 이 페이지가 eviction될 때 디스크 상의 원본 파일이 없으므로, swap 디스크의 빈 slot에 내용을 저장해야 한다. swap slot은 디스크 상에서 한 페이지(4 KB) 분량을 담을 수 있는 공간이며, bitmap으로 사용/미사용을 관리한다.

상세 설명

추상 개념 (하드웨어/OS 규칙)

물리 메모리가 부족하면 OS는 victim 페이지를 골라 디스크로 내보낸다(swap out). file-backed page는 원본 파일에 쓰면 되지만, anonymous page는 원본이 없으므로 별도의 swap 영역이 필요하다. swap 영역은 보통 전용 디스크 파티션이나 파일로 구성되며, 고정 크기 slot 단위로 관리된다. 나중에 해당 페이지에 접근하면 page fault가 발생하고, OS는 swap slot에서 데이터를 읽어 새 frame에 채운다(swap in).

실제 OS (Linux)

Linux는 swap 파티션(또는 swap 파일)을 페이지 크기(4 KB) 단위 slot으로 나누고, swap_map 배열로 각 slot의 참조 카운트를 관리한다. anonymous page의 PTE는 swap out 시 present=0으로 바뀌고, swap entry(디바이스 번호 + slot 번호)가 PTE에 인코딩된다. Linux는 COW fork 때 swap_map의 참조 카운트를 증가시켜 부모/자식이 같은 swap slot을 공유할 수 있게 한다.

PintOS 구현

PintOS의 anonymous page swap은 vm/anon.c에 구현되어 있다.

자료구조:

COW 대응 — swap_ref_count: fork로 COW 공유된 anonymous page가 eviction되면 부모/자식 모두 같은 swap slot을 가리킨다. swap_ref_count[]가 각 slot의 참조 카운트를 관리하여, 마지막 참조자가 unref할 때만 bitmap을 해제한다. Linux의 swap_map과 동일한 역할이다.

초기화 (vm_anon_init, anon.c:39):

slot 관리 3함수 (COW 핵심):

Swap Out (anon_swap_out, anon.c:134):

  1. swap_slot_alloc()으로 빈 slot 확보 (ref_count=1)
  2. 8개 sector에 걸쳐 frame 내용을 디스크에 쓰기
  3. COW 공유 frame이면 owner_count - 1번 swap_slot_ref()를 호출해 ref_count를 owner 수에 맞춤
  4. frame->owners 리스트를 순회하며 모든 공유자의 page→anon.swap_idx 설정, pml4_clear_page

Swap In (anon_swap_in, anon.c:116):

  1. swap_idx에서 8개 sector 읽어 kva에 복원
  2. swap_slot_unref()로 참조 감소 (ref_count > 1이면 slot 유지됨)
  3. swapped=false, swap_idx=BITMAP_ERROR로 리셋

Destroy (anon_destroy, anon.c:176): 프로세스 종료 시 swapped 상태인 anonymous page의 swap slot을 swap_slot_unref()로 참조 감소한다. 마지막 참조자이면 bitmap이 해제되고, 아니면 slot이 유지된다. 디스크 I/O 없이 메모리 연산만 수행한다.

anon_copy (anon.c:190) — fork COW 지원:

fork 시 부모의 swapped page를 자식에게 복사하면, 실제 디스크 I/O 없이 swap_idx만 공유하고 ref_count를 증가시킨다.

page_operations 연결:

vm_do_claim_page()에서 swap_in(page, kva) 매크로를 호출하면 page→operations→swap_in이 호출되어 anon_swap_in이 실행된다.

QEMU 에뮬레이션

swap I/O는 QEMU의 IDE controller 에뮬레이션을 거친다:

  1. disk_write/disk_read 호출 → PintOS ide.c의 ide_write()/ide_read()
  2. IDE port I/O: outb(0x1F7, CMD_WRITE_SECTOR) → QEMU의 ide_ioport_write() (hw/ide/core.c)
  3. QEMU block backend: blk_pwrite() → 호스트 파일 시스템의 swap.dsk 파일에 실제 쓰기
  4. 응답: QEMU가 IRQ14를 발생시키거나 polling 완료

swap I/O의 특징: 한 page(4 KB)를 위해 disk_write/read를 8번 반복 호출한다. 각 호출이 512 B씩 처리하며, 매번 swap_lock을 acquire/release한다.

GDB에서 swap 관찰 6단계:

  1. b anon_swap_out → hit 시 p page->va — 어떤 가상 주소의 page가 swap out되는지
  2. p frame->ref_count — COW 공유자 수 확인 (1이면 단독, >1이면 COW)
  3. b swap_slot_alloc → finish → p $rax — 할당된 slot 번호
  4. b anon_swap_in → p page->anon.swap_idx — 어떤 slot에서 읽는지
  5. p swap_ref_count[N] — slot N의 현재 참조 카운트
  6. p bitmap_test(disk_bitmap, N) — slot N이 사용 중인지 확인

swap full 상황 관찰:

  • p bitmap_scan_and_flip(disk_bitmap, 0, 1, false) 결과가 BITMAP_ERROR(=SIZE_MAX)이면 swap 공간 고갈
  • 이 경우 anon_swap_out이 false를 반환하고, vm_evict_frame이 실패

예시: slot 5에 swap out하면, sector 40~47에 걸쳐 8번의 disk_write가 발생한다.

Anonymous Page와 Swap 점검

  • anonymous page는 파일 원본이 없기 때문에 eviction될 때 내용을 swap disk에 직접 저장해야 한다.
  • page 하나는 4096 bytes이고 disk sector 하나는 512 bytes라서, swap slot 하나는 8개 sector를 차지한다.
  • swap_idx는 “이 page가 swap disk의 몇 번째 slot에 있는가”를 가리키는 좌표다.
  • COW fork처럼 여러 page가 같은 swapped slot을 공유할 수 있으므로, slot 해제는 bitmap만이 아니라 swap_ref_count까지 함께 봐야 한다.
  • QEMU는 IDE와 block backend를 통해 disk read/write 효과를 재현할 뿐, 어떤 page를 swap out할지는 PintOS VM 정책이 결정한다.
