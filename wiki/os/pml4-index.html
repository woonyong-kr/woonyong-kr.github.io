PML4 Index

PML4 Index

확인 범위: 이 문서는 x86-64의 PML4 index와 4단계 page table walk의 일반 원리를 설명하고 Linux 및 PintOS의 구현 예시와 주소 분해 계산을 함께 제시한다. 다만 실제 코드·버전별 동작, 실행 결과, 메모리 사용량이나 성능에 관한 판단은 해당 구현과 실행 환경에서 별도로 검증해야 한다.

한 줄 요약: 가상 주소의 비트 47:39는 CR3가 가리키는 PML4 테이블에서 엔트리 하나를 선택하는 9비트 인덱스다. 이는 4단계 page table walk의 첫 단계에 해당한다.

PML4 Index 상태

x86-64의 4단계 페이지 테이블에서 가상 주소(VA)의 비트 47:39를 PML4 index로 사용한다. CR3는 512개 엔트리로 구성된 PML4 테이블을 가리키며, 이 9비트 index가 그중 하나인 PML4 엔트리(PML4E)를 선택한다. 선택된 PML4E에는 다음 단계인 PDPT(Page Directory Pointer Table)의 물리 주소가 들어 있다. 이 흐름을 이해하려면 PML4 index뿐 아니라 4단계 walk에서 사용하는 전체 index 구조를 함께 살펴봐야 한다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64의 48비트 가상 주소는 다음과 같이 5개 필드로 나뉜다.

%% x86-64 가상 주소 필드
flowchart TD
  address["63..48 &#124; 47..39 &#124; 38..30 &#124; 29..21 &#124; 20..12 &#124; 11..0<br/>Sign Extend<br/>16 bits &#124; PML4 idx<br/>9 bits &#124; PDPT idx<br/>9 bits &#124; PD idx<br/>9 bits &#124; PT idx<br/>9 bits &#124; Offset<br/>12 bits"]
필드비트 범위크기엔트리 수한 엔트리가 커버하는 범위
PML4 index47:399비트512512 GiB
PDPT index38:309비트5121 GiB
PD index29:219비트5122 MiB
PT index20:129비트5124 KiB
Page offset11:012비트40961 byte

walk 과정:

  1. CR3에서 PML4 테이블의 물리 주소를 얻는다.
  2. PML4[VA[47:39]]로 PML4E를 선택하고 PDPT의 물리 주소를 얻는다.
  3. PDPT[VA[38:30]]로 PDPTE를 선택하고 PD의 물리 주소를 얻는다.
  4. PD[VA[29:21]]로 PDE를 선택하고 PT의 물리 주소를 얻는다.
  5. PT[VA[20:12]]로 PTE를 선택하고 최종 물리 프레임 주소를 얻는다.
  6. 물리 프레임 주소에 VA[11:0]을 더해 최종 물리 주소를 구한다.

각 테이블은 정확히 1 page(4 KiB)를 차지한다. 엔트리 하나가 8바이트이고 한 테이블에 512개가 있으므로 전체 크기는 4096바이트다.

실제 OS (Linux/Windows)

Linux 6.x는 5단계 페이지 테이블(PGD → P4D → PUD → PMD → PTE)을 지원한다. 5-level paging에서는 57비트 가상 주소를 사용하며, 비트 56:48이 PGD(= PML5) index가 된다. 4-level paging 모드에서는 PGD가 곧 PML4다.

Linux에서는 다음 매크로 체인을 따라 각 단계의 엔트리를 찾는다.

pgd_offset(mm, addr)  → PML4 엔트리
p4d_offset(pgd, addr) → (5-level이면 P4D, 아니면 pass-through)
pud_offset(p4d, addr) → PDPT 엔트리
pmd_offset(pud, addr) → PD 엔트리
pte_offset(pmd, addr) → PT 엔트리

PintOS 구현

PintOS는 include/threads/pte.h에서 각 index를 추출하는 매크로를 정의한다.

0x1FF = 0b1_1111_1111 = 511이므로 하위 9비트만 남기는 마스크다.

pml4e_walk() — 4단계 walk 구현:

pml4e_walk()는 pdpe_walk(), pgdir_walk(), pt_walk()를 차례로 호출하며 각 단계를 재귀적으로 처리한다. 각 함수는 해당 레벨의 index를 추출하고 엔트리의 PTE_P(present)를 확인한다. present가 아니면서 create가 true이면 새 page를 할당한 뒤 다음 레벨의 함수를 호출한다.

PTE_ADDR() 매크로:

이 매크로는 엔트리의 하위 12비트에 있는 플래그를 마스킹하고 다음 테이블의 물리 주소만 추출한다.

PML4 Index 값 추적

가상 주소 0x0000_0000_0804_8123을 각 index와 offset으로 나누면 다음과 같다.

VA = 0x0000_0000_0804_8123
   = 0b ... 0000_0000_1000_0000_0100_1000_0001_0010_0011

PML4 index = VA[47:39] = 0b0_0000_0000 =   0
PDPT index = VA[38:30] = 0b0_0000_0000 =   0
PD   index = VA[29:21] = 0b1_0000_0010 =  66  (0x42)  ← 0x804_8000 >> 21
PT   index = VA[20:12] = 0b0_0100_1000 =  72  (0x48)
Offset     = VA[11:0]  = 0x123        = 291

검증식은 66 × 2MiB + 72 × 4KiB + 291 = 0x0840_0000 + 0x4_8000 + 0x123 = 0x0804_8123이다.

PintOS KERN_BASE인 0x80_0400_0000도 같은 방식으로 분해할 수 있다.

PML4 index = 0x80_0400_0000 >> 39 = 0x100 >> 0 = 1  (두 번째 PML4 엔트리)
PDPT index = (0x80_0400_0000 >> 30) & 0x1FF = 0x01 = 1
PD   index = (0x80_0400_0000 >> 21) & 0x1FF = 0x00 = 0
PT   index = (0x80_0400_0000 >> 12) & 0x1FF = 0x00 = 0

이 분해에 따르면 유저 공간은 PML4[0]에 있고, 커널 공간은 PML4[1]부터 시작한다.

모든 범위에 페이지 테이블을 구성한다고 가정한 최악의 경우에는 레벨별 메모리 소비가 다음과 같이 늘어난다.

레벨테이블 수크기
PML414 KiB
PDPT최대 5122 MiB
PD최대 512²1 GiB
PT최대 512³512 GiB

실제로는 사용하는 주소 범위에 해당하는 테이블만 할당한다. 따라서 일반 유저 프로세스의 페이지 테이블은 수십 KiB 수준이다.
