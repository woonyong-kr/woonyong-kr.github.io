Page Boundary Crossing — 페이지 경계를 넘는 유저 버퍼 검증

확인 범위: 이 문서는 유저 버퍼가 페이지 경계를 넘을 때 필요한 검증·복사 원리와 선택 기준을 설명하고, Linux와 PintOS의 구현 방식을 예시로 비교한다. 제시된 PintOS 코드 경로, QEMU·GDB 동작, 경계 사례와 성능 관련 판단은 특정 구현의 실제 코드·버전·실행 기록이나 측정으로 검증된 결과가 아니므로 별도 확인이 필요하다.

한 줄 요약: syscall로 받은 유저 버퍼(포인터+크기)는 여러 page에 걸칠 수 있다. 따라서 커널은 첫 바이트만 확인해서는 안 되며, page 경계를 넘을 때마다 새 page의 유효성을 검증해야 한다. 예를 들어 0x1FF0에서 시작하는 32바이트 버퍼는 0x1000·0x2000 두 page에 걸친다. 이를 확인하지 않으면 매핑되지 않은 page를 끼워 커널 pf와 패닉을 유발하는 공격이 가능하다.

페이지 경계를 넘는 버퍼가 만드는 문제

유저 프로그램이 syscall로 커널에 전달하는 버퍼는 포인터와 크기로 표현되며, 여러 페이지에 걸칠 수 있다. 커널이 버퍼의 첫 바이트만 검증하면 첫 페이지 뒤에 있는 페이지의 상태를 놓친다. 공격자는 유효한 첫 페이지 다음에 매핑되지 않은 페이지를 배치해 커널 패닉을 유발할 수 있다. 따라서 커널은 버퍼가 페이지 경계를 넘을 때마다 새 페이지도 유효한지 확인해야 한다.

메모리 연속성의 차이

가상 주소 공간에서 주소가 연속되어 있어도 물리 메모리까지 연속되어 있다고 볼 수는 없다. 0x0000_1FF0에서 시작하는 32바이트 버퍼를 예로 들면, 버퍼의 앞뒤 절반은 서로 다른 두 페이지에 놓인다.

Page 1: 0x0000_1000 ~ 0x0000_1FFF  (버퍼의 처음 16 bytes)
Page 2: 0x0000_2000 ~ 0x0000_2FFF  (버퍼의 나머지 16 bytes)

Page 1은 매핑되어 있지만 Page 2는 매핑되지 않을 수 있다. 이런 상태에서 커널이 Page 1만 확인한 뒤 memcpy를 수행하면 Page 2에 접근하는 순간 커널 모드에서 page fault가 발생한다.

Linux와 PintOS의 검증 방식

Linux의 copy_from_user() / copy_to_user()는 page fault를 이용해 유저 메모리 접근 실패를 처리한다. __copy_from_user_nocheck()가 실제 복사를 수행하다가 커널 모드 page fault가 발생하면 exception table의 fixup 코드로 이동해 -EFAULT를 반환한다. 사전에 모든 페이지를 검증하기보다 먼저 복사하고 실패를 처리하는 optimistic 방식이다.

PintOS는 페이지를 하나씩 찾아가며 명시적으로 사전 검증한다.

validate_user_buffer() — 페이지 단위 순회

pg_round_down(addr) + PGSIZE로 다음 페이지 경계를 계산한 뒤, 그 주소를 다시 검증한다. 버퍼의 모든 바이트를 하나씩 검사하지 않고 페이지 경계마다 한 번씩 검사하는 방식이다.

copy_in() / copy_out() — 페이지 단위 복사

pg_ofs(user)는 페이지 안의 offset, 즉 하위 12비트다. PGSIZE - pg_ofs는 현재 페이지에서 복사할 수 있는 최대 바이트 수를 뜻한다. 복사가 이 크기를 넘으면 다음 반복에서 새 페이지를 검증한다.

검증 흐름

validate_user_buffer(buf=0x4FF0, size=32)
  iter 1: addr=0x4FF0 → validate_user_addr(0x4FF0)
          next_page = pg_round_down(0x4FF0) + 0x1000 = 0x4000 + 0x1000 = 0x5000
          addr = 0x5000
  iter 2: addr=0x5000 → validate_user_addr(0x5000)
          next_page = 0x5000 + 0x1000 = 0x6000
          addr=0x6000 > end(0x5010) → 종료
  ✓ 2개 페이지 모두 검증 완료

페이지 수와 검증 횟수 계산

항목값
페이지 크기 (PGSIZE)4096 bytes (0x1000)
pg_ofs 마스크하위 12비트 (addr & 0xFFF)
pg_round_down 마스크상위 비트 (addr & ~0xFFF)
걸치는 페이지 수 (size > 0)floor((pg_ofs(buf) + size - 1) / PGSIZE) + 1

경계 사례

시작 주소가 정렬되지 않았거나 버퍼가 클수록 더 많은 페이지에 걸칠 수 있다. 정확한 페이지 수는 시작 offset을 포함한 floor((pg_ofs(buf) + size - 1) / PGSIZE) + 1로 계산한다. size == 0이면 검증 횟수는 0회다.

검증 순서도

flowchart TD

    B --> C{"size == 0?"}
    C -->|yes| Z["return OK"]
    C -->|no| D["addr = buf"]
    D --> E{"addr < buf + size?"}
    E -->|no| Z
    E -->|yes| F["validate_user_addr(addr)"]
    F --> G{"유효?"}
    G -->|no| H["exit(-1)"]
    G -->|yes| I["next_page = pg_round_down(addr) + PGSIZE"]
    I --> J["addr = next_page"]
    J --> E

flowchart LR

QEMU에서 해석할 때의 경계

  1. guest 검증 경계와 QEMU 경계는 다르다: PintOS가 page별 chunk로 나누는 주된 이유는 각 guest page의 유효성·권한과 fault를 독립적으로 처리하기 위해서다. QEMU TCG의 host-side memory helper가 guest memcpy() 호출 하나를 반드시 단일 TLB entry로 처리한다고 가정하면 안 된다.

  2. #PF 발생 경로: validate_user_addr()이 매핑되지 않은 주소를 검사할 때 VM이 활성화되어 있다면 vm_try_handle_fault()가 호출되어 lazy page나 stack growth를 처리한다. QEMU 관점에서 guest가 try_claim_user_addr()을 통해 소프트웨어적으로 page fault를 유발하는 것은 아니다. SPT를 조회하고 필요하면 frame을 할당해 PTE를 설치함으로써 실제 memcpy 시점에 하드웨어 page fault가 발생하지 않도록 한다.

  3. pg_round_down / pg_ofs 계산: 이 매크로들은 단순한 비트 연산이다. addr & ~0xFFF(pg_round_down)과 addr & 0xFFF(pg_ofs)는 QEMU TCG에서 and 명령 하나로 번역된다. Translation Block 안에서 인라인 처리되므로 오버헤드가 거의 없다는 설명이지만, 실제 성능을 판단하려면 별도 측정이 필요하다.

  4. cross-page copy 분할: PGSIZE - pg_ofs(user)로 chunk를 제한하면 다음 page로 넘어가기 전에 guest mapping과 권한을 다시 확인할 수 있다. 이는 정확성과 fault isolation을 위한 규칙이며, QEMU softmmu 성능을 근거로 정당화하는 방식은 아니다.

GDB 관찰 스크립트

다음 스크립트는 제시된 코드 좌표를 기준으로 작성된 관찰 방법이며, 실제 동작 여부는 해당 구현과 버전에서 별도로 확인해야 한다.

1. validate_user_buffer 진입 시 버퍼 범위:

(gdb) b syscall.c:492
(gdb) commands
  silent
  printf "validate_buffer: buf=%p size=%u pages=%u\n", \
    buffer, size, (unsigned)((size + ((uintptr_t)buffer & 0xFFF) + 0xFFF) >> 12)
  cont
end

2. 페이지 경계 검증 루프 추적:

(gdb) b syscall.c:515
(gdb) commands
  silent
  printf "  validate page: addr=%p (page=%p, ofs=%u)\n", \
    addr, (void *)((uintptr_t)addr & ~0xFFF), (unsigned)((uintptr_t)addr & 0xFFF)
  cont
end

3. copy_in chunk 크기 관찰:

(gdb) b syscall.c:530
(gdb) commands
  silent
  set $ofs = (unsigned)((uintptr_t)user & 0xFFF)
  set $chunk = 4096 - $ofs
  if $chunk > size
    set $chunk = size
  end
  printf "copy_in: user=%p chunk=%u (page_ofs=%u, remain=%u)\n", \
    user, $chunk, $ofs, (unsigned)size
  cont
end

4. copy_out write 검증 추적:

(gdb) b syscall.c:544
(gdb) commands
  silent
  printf "copy_out: user=%p chunk=%u → write validation\n", \
    user, (unsigned)(4096 - ((uintptr_t)user & 0xFFF))
  cont
end

5. 경계를 넘는 write syscall 전체 추적:

(gdb) b syscall.c:215
(gdb) commands
  silent
  set $buf = (void *)f->R.rsi
  set $sz = (unsigned)f->R.rdx
  set $cross = ($sz + ((uintptr_t)$buf & 0xFFF)) > 4096
  printf "write(fd=%d, buf=%p, size=%u) crosses_page=%d\n", \
    (int)f->R.rdi, $buf, $sz, $cross
  cont
end

6. 전체 페이지 경계 추적 매크로:

(gdb) define trace_page_boundary
  b syscall.c:492
  commands
    silent
    set $start = (uintptr_t)buffer
    set $end_addr = $start + size - 1
    set $start_page = $start >> 12
    set $end_page = $end_addr >> 12
    printf "[boundary] buf=%p..%p spans pages %u..%u (%u pages)\n", \
      buffer, (void *)$end_addr, $start_page & 0xFFFFF, \
      $end_page & 0xFFFFF, $end_page - $start_page + 1
    cont
  end
end

경계 사례로 따라가는 검증과 복사

시나리오 1: write() 버퍼가 2개 페이지에 걸치는 경우

조건: write(1, 0x47FFE0, 64) — 버퍼가 페이지 끝에서 32바이트 앞에서 시작한다.

1. syscall_handler → SYS_WRITE 분기
2. validate_user_buffer(0x47FFE0, 64, false, f) 호출
   - start=0x47FFE0, last=0x48001F → 2개 페이지
3. iter 1: addr=0x47FFE0
   - validate_user_addr(0x47FFE0) → SPT 조회 → 매핑 OK
   - next_page = pg_round_down(0x47FFE0) + 0x1000 = 0x47F000 + 0x1000 = 0x480000
   - addr = 0x480000
4. iter 2: addr=0x480000
   - validate_user_addr(0x480000) → SPT 조회 → 매핑 OK (또는 lazy load 트리거)
   - next_page = 0x481000
   - addr = 0x481000 > end(0x480020) → 종료
5. copy_in loop:
   - chunk 1: pg_ofs(0x47FFE0) = 0xFE0, chunk = 4096 - 0xFE0 = 32 bytes
   - memcpy(kpage, 0x47FFE0, 32)
   - chunk 2: pg_ofs(0x480000) = 0, chunk = min(4096, 32) = 32 bytes
   - memcpy(kpage+32, 0x480000, 32)
6. file_write로 64바이트 전달

이 흐름에서는 첫 페이지의 남은 32바이트와 다음 페이지의 32바이트를 따로 검증하고 복사한다. 다만 위 순서는 제시된 구현을 바탕으로 한 설명이며, 실제 실행 결과는 아니다.

시나리오 2: read() 버퍼의 두 번째 페이지가 stack인 경우

조건: read(fd, 0x47BFFC, 8) — 스택 영역이며 두 번째 페이지(0x47C000)는 아직 할당되지 않은 상태다.

1. syscall_handler → SYS_READ 분기
2. validate_user_buffer(0x47BFFC, 8, true, f)  ← write=true (버퍼에 쓰기)
   - start=0x47BFFC, last=0x47C003 → 2개 페이지
3. iter 1: addr=0x47BFFC
   - validate_user_addr(0x47BFFC, write=true) → try_claim_user_addr()
   - SPT에 페이지 있음 → OK
4. iter 2: addr=0x47C000
   - validate_user_addr(0x47C000, write=true) → try_claim_user_addr()
   - SPT에 없음 → stack growth 판단 (RSP 근처)
   - vm_stack_growth(0x47C000) → 새 ANON 페이지 할당 + PTE 설치
   - 이제 매핑 OK
5. copy_out:
   - chunk 1: 4 bytes (page offset 0xFFC → 남은 4 bytes)
   - chunk 2: 4 bytes (page offset 0x000)
6. 총 8바이트를 유저 버퍼에 복사 완료

두 번째 페이지가 아직 할당되지 않았다면 stack growth 조건을 확인한 뒤 페이지를 만들고 PTE를 설치하는 흐름으로 설명할 수 있다. 이 과정 역시 실제 코드와 실행 기록을 통해 별도로 검증해야 한다.
