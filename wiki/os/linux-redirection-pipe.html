Linux 리다이렉션과 파이프

Linux 리다이렉션과 파이프

확인 범위: 이 문서는 Linux 리다이렉션과 파이프의 일반 원리와 선택 기준을 개념적으로 설명하고, 제시된 Linux·PintOS 코드는 동작을 이해하기 위한 예시로 다룬다. 특정 구현의 지원 범위, 버전별 동작, 실행 결과와 파이프 버퍼 크기·성능에 관한 판단은 실제 소스와 환경에서 별도로 검증해야 한다.

한 줄 요약: 리다이렉션은 프로세스의 fd 테이블을 조작해 입출력 대상을 바꾸는 것이고, 파이프는 커널이 만든 메모리 버퍼 두 끝을 fd로 연결해 프로세스 간 데이터를 흘리는 것이다.

Linux 리다이렉션과 파이프 필요성

프로그램은 보통 표준 입력(stdin, fd 0)에서 읽고 표준 출력(stdout, fd 1)에 쓴다. 그런데 프로그램을 수정하지 않고도 입력을 파일에서 가져오거나, 출력을 파일에 저장하거나, 한 프로그램의 출력을 다른 프로그램의 입력으로 연결하고 싶을 때가 있다.

이 요구를 해결하는 것이 리다이렉션(redirection)과 파이프(pipe)다. 둘 다 프로그램 코드를 건드리지 않는다. 프로그램이 사용하는 fd 번호는 그대로 0, 1, 2이지만, 그 fd가 가리키는 대상을 커널 수준에서 바꿔치기한다.

이 구조를 이해하려면 먼저 파일 디스크립터가 프로세스별 테이블의 인덱스라는 것을 알아야 한다.

Linux 리다이렉션과 파이프 차이

리다이렉션 — fd가 가리키는 대상을 파일로 교체

셸에서 ls > output.txt를 실행하면 ls의 출력이 화면이 아닌 파일에 기록된다. 프로그램 ls는 여전히 write(1, ...) 를 호출한다. 달라진 것은 fd 1이 터미널이 아니라 output.txt 파일을 가리킨다는 점뿐이다.

셸이 하는 일을 순서대로 풀면 이렇다.

  1. fork()로 자식 프로세스를 만든다.
  2. 자식에서 open("output.txt", O_WRONLY | O_CREAT | O_TRUNC)을 호출해 파일을 연다. 반환된 fd가 예를 들어 3이다.
  3. dup2(3, 1)을 호출한다. fd 1이 이제 output.txt를 가리킨다.
  4. close(3)으로 더 이상 필요 없는 fd 3을 닫는다.
  5. exec("ls")로 프로그램을 교체한다.

dup2(oldfd, newfd)는 newfd가 oldfd와 같은 파일을 가리키도록 복제하는 시스템 콜이다. newfd가 이미 열려 있으면 먼저 닫는다. 이것이 리다이렉션의 전부다.

셸 문법과 내부 동작을 대응하면 다음과 같다.

  • cmd > file → stdout(fd 1)을 file로 교체. 파일을 새로 만들거나 덮어쓴다.
  • cmd >> file → stdout(fd 1)을 file로 교체. 파일 끝에 이어 쓴다. (O_APPEND)
  • cmd < file → stdin(fd 0)을 file로 교체. 파일에서 읽는다.
  • cmd 2> file → stderr(fd 2)를 file로 교체.

파이프 — 커널 버퍼를 fd 쌍으로 연결

ls | grep .txt에서 | 기호가 파이프다. ls의 stdout을 grep의 stdin에 연결한다. 파일이 아니라 커널 메모리 안의 버퍼가 중간 매개체다.

pipe() 시스템 콜은 fd 두 개를 만든다. pipefd[0]은 읽기 끝, pipefd[1]은 쓰기 끝이다. 한쪽에 쓰면 반대쪽에서 읽을 수 있다.

셸이 ls | grep .txt를 실행하는 순서는 다음과 같다.

  1. pipe(pipefd)를 호출해 pipefd[0](읽기)과 pipefd[1](쓰기)을 얻는다.
  2. 첫 번째 fork()로 자식 A를 만든다.
    • 자식 A: dup2(pipefd[1], 1) → stdout을 파이프 쓰기 끝으로 교체.
    • 자식 A: close(pipefd[0]), close(pipefd[1]) → 사용하지 않는 fd 정리.
    • 자식 A: exec("ls").
  3. 두 번째 fork()로 자식 B를 만든다.
    • 자식 B: dup2(pipefd[0], 0) → stdin을 파이프 읽기 끝으로 교체.
    • 자식 B: close(pipefd[0]), close(pipefd[1]) → 사용하지 않는 fd 정리.
    • 자식 B: exec("grep", ".txt").
  4. 부모: close(pipefd[0]), close(pipefd[1]) → 부모도 파이프 fd를 닫는다.
  5. 부모: wait()으로 자식들을 기다린다.

파이프 버퍼의 크기는 Linux에서 기본 64KB다. 버퍼가 가득 차면 쓰기 프로세스는 블록되고, 버퍼가 비면 읽기 프로세스가 블록된다. 이것이 생산자-소비자 동기화를 자연스럽게 구현한다.

리다이렉션과 파이프의 차이

리다이렉션은 fd를 파일에 연결한다. 파이프는 fd를 커널 내 메모리 버퍼에 연결한다. 리다이렉션은 프로세스 하나의 입출력 방향을 바꾸고, 파이프는 프로세스 두 개의 입출력을 연결한다. 하지만 둘 다 dup2()로 fd 테이블을 조작한다는 점에서 같은 메커니즘이다.

PintOS: dup2 시스템 콜

PintOS는 pipe()를 구현하지 않는다. 하지만 dup2()는 시스템 콜로 정의되어 있다. 리다이렉션의 핵심 메커니즘인 fd 복제를 지원한다.

유저 라이브러리에서 SYS_DUP2 시스템 콜 번호로 커널에 트랩한다. 커널 쪽 핸들러는 프로세스의 fd 테이블에서 oldfd가 가리키는 파일 객체를 newfd 위치에도 넣는 방식으로 동작한다.

PintOS에는 pipe() 시스템 콜이 없으므로 프로세스 간 파이프 통신은 불가능하다. 이는 PintOS가 교육용 OS로서 최소한의 시스템 콜만 구현하기 때문이다. 실제 Linux 커널은 pipe(), pipe2(), dup(), dup2(), dup3()까지 제공하며, 이름 있는 파이프(named pipe, FIFO)도 mkfifo()로 만들 수 있다.

정리

리다이렉션과 파이프는 프로그램을 수정하지 않고 입출력 대상을 바꾸는 Unix의 핵심 설계다. 둘 다 dup2()로 프로세스의 fd 테이블을 조작하는 것이 본질이다. 리다이렉션은 fd를 파일에 연결하고, 파이프는 fd를 커널 메모리 버퍼에 연결한다. PintOS는 dup2()만 제공하고 pipe()는 구현하지 않는다.

  • fd 테이블의 구조와 의미
  • write 시스템 콜이 커널까지 내려가는 경로
  • fork와 exec의 동작 흐름
