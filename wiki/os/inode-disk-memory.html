inode 구조

inode 구조

한 줄 요약: inode는 파일의 메타데이터와 데이터 위치를 기록하는 구조체이며, 디스크에 영구 저장되는 inode_disk와 커널 메모리에 올라오는 struct inode, 그리고 열린 inode를 관리하는 전역 리스트(open inode table)로 나뉜다.

inode 구조 필요성

파일의 내용(데이터)은 디스크 여러 섹터에 흩어질 수 있다. “이 파일은 몇 바이트이고, 데이터가 어느 섹터에 있고, 누가 읽고 있는가?”를 추적하는 장치가 없으면 파일 시스템은 동작할 수 없다.

inode(index node)가 바로 그 장치다. 파일 이름은 디렉터리가 관리하고, inode는 파일 이름과 무관하게 파일의 실체(크기, 위치, 상태)를 기록한다.

inode를 이해하지 못하면 파일 생성·읽기·쓰기·삭제의 내부 흐름을 따라갈 수 없다.

inode 구조 흐름

비유: 도서관 카드

도서관에서 책을 찾을 때, 책장에 직접 가기 전에 카탈로그 카드를 본다. 카드에는 “이 책은 3층 A서가 17번 칸에 있다”는 위치 정보가 적혀 있다. inode는 파일의 카탈로그 카드다. 파일 이름(책 제목)은 디렉터리(카탈로그 목록)에 있고, inode(카드)에는 파일 데이터가 디스크 어디에 있는지가 적혀 있다.

세 가지 층위

inode는 존재하는 위치에 따라 세 가지 형태로 나뉜다.

%% 디스크 inode와 메모리 inode의 관계
flowchart LR
  disk["디스크<br/>inode_disk<br/>512B"]
  memory["커널 메모리<br/>struct inode<br/>런타임 상태 포함"]
  open_inodes["open_inodes<br/>전역 열린 inode 리스트"]
  disk -->|"disk_read()"| memory
  memory -->|"disk_write()"| disk
  memory -->|"list_elem elem"| open_inodes

1. 디스크 inode (inode_disk) — 디스크에 영구 저장되는 메타데이터. 파일 크기, 데이터 시작 섹터, 매직 넘버를 담는다. 정확히 한 섹터(512B) 크기다.

2. 메모리 inode (struct inode) — 파일을 열면 디스크 inode를 읽어 커널 메모리에 올린 것. 열린 횟수(open_cnt), 삭제 여부(removed), 쓰기 거부 카운터(deny_write_cnt) 같은 런타임 상태를 추가로 갖는다.

3. 열린 inode 테이블 (open_inodes) — 현재 열려 있는 모든 메모리 inode를 담는 전역 리스트. 같은 파일을 두 번 열면 새 inode를 만들지 않고 기존 inode의 open_cnt를 증가시킨다. 이 테이블이 없으면 같은 파일에 대한 동시 접근을 조율할 수 없다.

파일 열기/닫기 흐름

  1. filesys_open("hello.txt") 호출
  2. 루트 디렉터리에서 “hello.txt”에 대응하는 inode 섹터 번호를 찾는다.
  3. inode_open(sector) 호출:
    • open_inodes 리스트를 순회하며 같은 섹터의 inode가 이미 있는지 확인한다.
    • 이미 열려 있으면 open_cnt++하고 그 inode를 반환한다.
    • 없으면 malloc으로 struct inode를 할당하고, disk_read()로 디스크에서 inode_disk를 읽어 inode->data에 저장한다. 리스트에 추가하고 반환한다.
  4. file_open(inode) 호출: struct file을 할당하고, inode를 연결하고, 현재 읽기 위치(pos)를 0으로 설정한다.

닫을 때는 반대 순서다:

  1. file_close() → inode_close()
  2. open_cnt--. 0이 되면 open_inodes 리스트에서 제거하고 메모리를 해제한다.
  3. removed 플래그가 true면(삭제 예약된 파일이면) inode 섹터와 데이터 섹터 모두 free map에 반환한다.

file 구조체와 inode의 관계

%% struct file, struct inode, inode_disk의 관계
flowchart LR
  file["struct file<br/>inode<br/>pos: 128<br/>deny_write"]
  inode["struct inode<br/>sector: 5<br/>open_cnt: 2<br/>removed: F<br/>data"]
  inode_disk["inode_disk<br/>start: 10<br/>length: 2048<br/>magic: ..."]
  file -->|"inode"| inode
  inode -->|"data"| inode_disk
  inode_disk -->|"disk_read()/disk_write()"| inode

struct file은 프로세스가 열어 놓은 파일 핸들이다. 같은 파일을 두 프로세스가 열면 struct file은 두 개이지만 struct inode는 하나다. pos(현재 읽기/쓰기 위치)는 file마다 독립적이고, 파일의 물리적 속성(크기, 위치)은 inode가 관리한다.

inode 구조 코드

디스크 inode

unused[125]가 존재하는 이유: inode_disk는 반드시 한 섹터(512B)와 크기가 같아야 한다. start(4B) + length(4B) + magic(4B) = 12B이고, unused가 125 × 4B = 500B를 채워서 총 512B가 된다. inode_create()에서 ASSERT(sizeof *disk_inode == DISK_SECTOR_SIZE)로 이를 검증한다.

PintOS의 inode_disk는 start 하나로 데이터 위치를 표현한다. 파일 데이터는 start부터 연속된 섹터에 저장된다. 이 방식은 **연속 할당(contiguous allocation)**으로, 단편화에 취약하다. 실제 OS의 inode는 직접/간접 블록 포인터나 extent를 써서 비연속 할당을 지원한다.

메모리 inode

data 필드에 inode_disk 전체를 복사해서 갖고 있다. 파일 크기나 시작 섹터를 알려면 inode->data.length, inode->data.start로 접근한다.

열린 inode 테이블과 inode_open()

open_inodes 리스트를 선형 탐색하여 같은 섹터의 inode가 이미 열려 있는지 확인한다. 이미 있으면 open_cnt만 증가시키고, 없으면 새 struct inode를 할당하고 디스크에서 inode_disk를 읽어온다. 이 설계 덕분에 같은 파일을 여러 프로세스가 열어도 메타데이터 일관성이 유지된다.

바이트 오프셋 → 섹터 변환

연속 할당이므로 단순 나눗셈으로 섹터를 구한다. 파일의 pos번째 바이트가 들어 있는 섹터 = start + pos / 512. 실제 OS에서는 inode의 블록 포인터 배열이나 extent 트리를 탐색해야 하므로 이보다 복잡하다.

정리

파일 시스템에서 inode는 파일의 실체를 기록하는 핵심 구조체다. 디스크에 영구 저장되는 inode_disk는 파일 크기와 데이터 위치를 담고, 커널 메모리의 struct inode는 열린 횟수와 삭제 상태 같은 런타임 정보를 추가로 관리한다. open_inodes 전역 리스트는 같은 파일의 중복 오픈을 방지하고 일관성을 유지한다. PintOS는 연속 할당과 고정 크기라는 단순한 설계를 택했지만, 실제 OS는 간접 블록 포인터와 extent로 유연한 비연속 할당을 지원한다.
