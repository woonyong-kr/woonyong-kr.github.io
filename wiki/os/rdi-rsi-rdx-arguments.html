RDI · RSI · RDX — syscall 인자 레지스터

RDI · RSI · RDX — syscall 인자 레지스터

확인 범위: 이 문서는 x86-64 syscall의 인자 레지스터 규약과 Linux·PintOS·QEMU에서의 처리 방식을 개념적으로 설명하고, 제시된 코드와 관찰 방법을 구현 이해의 예시로 다룬다. 구체적인 구조체 크기·오프셋·코드 경로·레지스터 값과 동작 여부는 특정 코드 버전 및 실제 빌드·실행 기록에 따라 별도 검증이 필요한 구현 수준의 주장이다.

한 줄 요약: x86-64 syscall 규약에서 RDI·RSI·RDX·R10·R8·R9가 인자 1~6번을, RAX가 번호를 전달하는 레지스터 규칙.

RDI · RSI · RDX 상태

x86-64 syscall 호출 규약에서 RDI, RSI, RDX, R10, R8, R9 여섯 레지스터가 syscall 인자 1~6번을 순서대로 전달한다. RAX가 syscall 번호를 담는 반면, 실제 데이터(파일명 포인터, fd 번호, 버퍼 주소, 크기 등)는 이 여섯 레지스터를 통해 커널로 건너간다. 커널의 syscall handler는 struct intr_frame에 보존된 레지스터 값을 읽어 각 인자를 꺼낸다.

상세 설명

추상 개념 (x86-64 하드웨어 규칙)

syscall 명령어 자체는 인자 레지스터를 건드리지 않는다. 하드웨어가 하는 일은 RCX ← RIP, R11 ← RFLAGS, RIP ← LSTAR 뿐이므로 RDI~R9는 유저가 넣은 값 그대로 커널 진입점에 도착한다.

함수 호출 ABI vs syscall ABI 차이:

인자 순서함수 호출 (cdecl64)syscall
1번RDIRDI
2번RSIRSI
3번RDXRDX
4번RCXR10
5번R8R8

4번째 인자만 다르다. syscall 명령어가 RCX를 복귀 주소(RIP)로 덮어쓰기 때문에 R10으로 대체한다.

실제 OS (Linux)

Linux의 syscall entry point(entry_SYSCALL_64)는 진입 직후 모든 범용 레지스터를 struct pt_regs에 저장한다. 이후 sys_call_table[rax]로 분기할 때 커널 함수 호출 규약(cdecl64)에 맞춰 R10 → RCX로 복사한 뒤 일반 C 함수처럼 호출한다.

예시 — read(int fd, void *buf, size_t count):

  • RAX = __NR_read (0)
  • RDI = fd
  • RSI = buf 포인터
  • RDX = count

RDI · RSI · RDX 값 추적

struct intr_frame 내부 레지스터 오프셋 (PintOS threads/interrupt.h):

struct gp_registers {
    uint64_t r15;    // offset 0x00
    uint64_t r14;    // offset 0x08
    uint64_t r13;    // offset 0x10
    uint64_t r12;    // offset 0x18
    uint64_t r11;    // offset 0x20
    uint64_t r10;    // offset 0x28  ← 4th arg
    uint64_t r9;     // offset 0x30  ← 6th arg
    uint64_t r8;     // offset 0x38  ← 5th arg
    uint64_t rsi;    // offset 0x40  ← 2nd arg
    uint64_t rdi;    // offset 0x48  ← 1st arg
    uint64_t rbp;    // offset 0x50
    uint64_t rdx;    // offset 0x58  ← 3rd arg
    uint64_t rcx;    // offset 0x60
    uint64_t rbx;    // offset 0x68
    uint64_t rax;    // offset 0x70  ← syscall number / return
};

write(1, "hello", 5) 호출 시 레지스터 상태:

  • RAX = 0x09 (SYS_WRITE)
  • RDI = 0x01 (fd = stdout)
  • RSI = 0x0000004747FFFF00 (buffer 주소, 유저 영역)
  • RDX = 0x05 (5 bytes)

QEMU 에뮬레이션

QEMU(TCG 모드)에서 syscall 명령어는 다음과 같이 처리된다:

  1. 게스트 코드의 mov %reg, ... + syscall 명령어 시퀀스가 TranslationBlock으로 번역된다
  2. syscall 실행 시 TCG helper가 CPUX86State의 레지스터를 조작한다:
    • env->regs[R_ECX] ← 복귀 RIP
    • env->regs[11] ← RFLAGS
    • env->eip ← LSTAR MSR 값
  3. RDI, RSI, RDX, R10은 변경되지 않는다 — env->regs[R_EDI], env->regs[R_ESI], env->regs[R_EDX], env->regs[10]에 유저가 넣은 값이 그대로 남아 있다
  4. GDB stub에서 info registers를 치면 이 값들이 그대로 보인다

QEMU 소스 위치: target/i386/tcg/sysemu/excp_helper.c의 x86_cpu_exec_interrupt() → do_syscall_64() 경로.

Linux는 syscall 번호를 sys_call_table 배열의 인덱스로 사용하여 함수 포인터를 호출한다. 이때 R10을 RCX로 옮겨 일반 C 호출 규약에 맞추지만, PintOS는 f->R.r10을 직접 읽으므로 이 변환이 불필요하다.
