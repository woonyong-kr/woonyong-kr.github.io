가상 머신과 하이퍼바이저 — 하드웨어를 소프트웨어로 만드는 기술

가상 머신과 하이퍼바이저 — 하드웨어를 소프트웨어로 만드는 기술

확인 범위: 이 문서는 가상 머신·하이퍼바이저·에뮬레이션의 일반 개념과 선택 기준을 설명하고, PintOS와 QEMU의 실행·디버깅 흐름을 특정 구현 사례로 다룬다. QEMU 내부 동작, 명령 옵션, 버전별 코드 경로, 실행 환경 및 성능에 관한 판단은 실제 소스 코드와 사용 버전, 실행 기록, 측정 결과를 별도로 확인해야 한다.

한 줄 요약: 가상 머신(VM)은 소프트웨어로 만든 컴퓨터이고, 하이퍼바이저는 그 가상 컴퓨터를 만들고 관리하는 프로그램이다.

PintOS는 어디에서 실행되는가

PintOS를 공부하면 먼저 “이 OS는 어디서 돌아가는가?”라는 질문을 만나게 된다. PintOS는 실제 컴퓨터에 직접 설치되지 않고 QEMU라는 프로그램 위에서 실행된다. 이때 QEMU가 소프트웨어로 만들어 내는 컴퓨터가 가상 머신이다.

이 실행 환경을 이해하면 다음 질문에도 답할 수 있다.

  • PintOS가 “진짜 CPU”라고 여기는 대상은 실제로 무엇인가?
  • 디버깅할 때 GDB는 왜 QEMU에 연결하는가?
  • KVM, Docker, WSL 같은 도구는 왜 존재하는가?

가상 머신과 하이퍼바이저

영화 인셉션처럼 컴퓨터 안에서 또 다른 컴퓨터가 돌아가는 장면을 떠올릴 수 있다. 바깥의 호스트는 실제 하드웨어를 가지고 있다. 안쪽의 게스트는 호스트가 소프트웨어로 구현한 하드웨어 위에서 동작한다. 게스트 OS는 자신에게 제공된 CPU, 메모리, 디스크를 실제 하드웨어처럼 사용한다.

**가상 머신(Virtual Machine, VM)**은 소프트웨어로 구현한 컴퓨터다. 프로그램이 CPU, 메모리, 디스크, 타이머, 인터럽트 컨트롤러 같은 하드웨어의 동작을 재현한다. 게스트 OS는 이 가상 하드웨어 위에서 부팅하고 자신이 하드웨어를 점유한 것처럼 동작한다.

**하이퍼바이저(Hypervisor)**는 가상 머신을 만들고 관리하는 소프트웨어다. 게스트 OS에 가상 CPU, 가상 메모리, 가상 장치를 제공한다. 게스트가 민감한 명령어를 실행하면 이를 가로채 대신 처리하기도 한다.

하이퍼바이저가 실행되는 위치

하이퍼바이저는 실행 위치에 따라 두 유형으로 나뉜다.

유형실행 구조예시주된 사용 환경
Type 1 (Bare-metal)하드웨어 바로 위에서 실행Xen, VMware ESXi, Microsoft Hyper-V데이터센터와 클라우드(AWS EC2 등)
Type 2 (Hosted)호스트 OS 위에서 일반 프로세스로 실행QEMU, VirtualBox, VMware WorkstationPintOS 개발 환경

Type 1에는 하이퍼바이저 아래에 별도의 호스트 OS가 없다. Type 2에서는 호스트 OS가 하드웨어를 관리하고, 하이퍼바이저는 그 위의 프로세스로 동작한다. PintOS가 사용하는 QEMU는 이 문서의 구분에서 Type 2에 해당한다.

에뮬레이션과 하드웨어 가상화

가상 머신이 게스트의 명령어를 실행하는 방식도 구분할 필요가 있다.

**에뮬레이션 (Emulation)**은 게스트 CPU의 명령어를 소프트웨어로 번역해 실행한다. 호스트와 게스트의 CPU 아키텍처가 달라도 동작할 수 있어 유연하지만 느리다. QEMU의 TCG 모드가 이 방식을 사용하며, PintOS도 이 모드에서 실행된다.

**하드웨어 가상화 (Hardware-assisted Virtualization)**는 게스트 명령어를 호스트 CPU에서 직접 실행한다. Intel VT-x, AMD-V 같은 하드웨어 확장이 필요하며 거의 네이티브 속도로 동작한다. QEMU + KVM 조합이 이 방식에 해당한다.

항목에뮬레이션 (TCG)하드웨어 가상화 (KVM)
속도5~10배 느림거의 네이티브
아키텍처 호환다른 아키텍처 가능같은 아키텍처만
하드웨어 요구없음VT-x / AMD-V 필요
PintOS 사용O (기본)X

PintOS는 TCG 에뮬레이션으로 실행된다. 이 문서에서 다루는 환경은 4MB RAM과 100Hz 타이머를 사용하는 단순한 구성이라 속도 차이를 체감하기 어렵다.

게스트 OS가 보는 하드웨어

가상 머신은 게스트 OS에 다음 실행 환경을 제공한다.

  1. 가상 CPU — 명령어 실행, 레지스터, 특권 레벨 전환
  2. 가상 메모리 — 물리 주소 공간, E820 메모리 맵
  3. 가상 장치 — 타이머(PIT), 인터럽트 컨트롤러(PIC), 디스크(IDE), 시리얼 포트
  4. 가상 부팅 환경 — BIOS/UEFI, 부트 섹터 로딩

게스트 OS는 이 구성 요소를 실제 하드웨어처럼 다룬다. cli/sti로 인터럽트를 끄고 켜며, mov cr3로 페이지 테이블을 전환하고, in/out으로 장치에 명령을 보낸다. 하이퍼바이저는 이러한 명령어를 처리해 게스트가 기대하는 효과를 재현한다.

QEMU 위에서 부팅하는 PintOS

PintOS의 부팅 과정을 코드와 함께 보면 가상 머신이 맡는 역할이 드러난다.

이 명령은 QEMU에 x86-64 가상 머신을 구성하도록 요청한다. -m 4는 RAM을 4MB로 설정한다. -drive ... index=0은 os.dsk를 첫 번째 디스크에 연결하고, index=3은 swap.dsk를 스왑 디스크에 연결한다. -cpu qemu64는 게스트 CPU 모델을 지정한다.

실행과 디버깅에 관한 옵션도 함께 들어 있다. -no-reboot은 게스트가 리셋을 시도할 때 재부팅하지 않고 종료하게 한다. -serial mon:stdio는 게스트의 시리얼 출력과 QEMU 모니터를 하나의 호스트 터미널에 묶는다. -s는 -gdb tcp::1234의 약어로 GDB 디버그 포트 1234를 연다. -S는 첫 명령어를 실행하기 전에 게스트를 멈춰 GDB가 연결될 때까지 기다리게 한다. 옛 -hda/-hdb 디스크 표기 대신 -drive를 사용한다.

인터럽트 명령이 처리되는 과정

PintOS 부트 코드에서는 인터럽트를 비활성화하는 명령을 통해 가상 머신의 동작을 직접 확인할 수 있다.

PintOS는 cli를 실행해 CPU의 인터럽트를 끈다. QEMU의 TCG는 이 명령어를 번역하고 CPUX86State.eflags의 IF 비트를 지운다. 이후 PIT가 IRQ를 발생시키더라도 IF가 꺼져 있으면 QEMU는 인터럽트를 게스트에 전달하지 않는다. PintOS가 관찰하는 결과는 실제 하드웨어에서 cli를 실행했을 때와 같다.

PintOS가 실행한 명령QEMU 내부 효과
clieflags &= ~IF → 인터럽트 차단
stieflags |= IF → 인터럽트 허용
mov cr3, raxhelper_write_crN() → 페이지 테이블 전환 (cr3 갱신)
in al, 0x21pic_ioport_read() → PIC 상태 읽기
out 0x20, 0x20pic_ioport_write() → EOI 명령 해석

위 QEMU 함수는 사용자 포크에서 직접 확인할 수 있다. cr3 갱신은 misc_helper.c의 helper_write_crN()이 받아 cpu_x86_update_cr3()로 내려간다. PIC 포트 입출력은 i8259.c의 pic_ioport_read() / pic_ioport_write()가 처리한다. out 0x20, 0x20(OCW2의 EOI 비트)도 별도 함수가 아니라 pic_ioport_write() 안에서 EOI 명령으로 해석된다.

Linux와 PintOS의 가상화 환경

Linux는 KVM 하이퍼바이저를 내장하고 있어 Type 1에 가까운 하이퍼바이저 역할을 할 수 있다. 게스트 명령어를 CPU에서 직접 실행하므로 성능 손실이 거의 없다.

PintOS는 QEMU TCG의 순수 에뮬레이션 위에서 실행된다. 모든 x86-64 명령어를 소프트웨어로 번역하기 때문에 느리지만 교육 목적으로 사용하기에는 충분하다. QEMU가 모든 명령어 실행을 통제하므로 GDB를 연결해 guest CPU 상태를 관찰할 수도 있다.

가상 머신은 CPU와 메모리, 장치 같은 하드웨어를 소프트웨어로 재현한 컴퓨터다. 하이퍼바이저는 이 가상 머신을 만들고 관리한다. Type 1은 하드웨어 바로 위에서 실행되고, Type 2는 호스트 OS 위에서 프로세스로 실행된다. PintOS는 Type 2인 QEMU 위에서 TCG 에뮬레이션 방식으로 동작하며, 제공된 가상 하드웨어를 실제 하드웨어처럼 사용한다.
