PTE 사용자 Bit (PTE User Bit)

PTE 사용자 Bit (PTE User Bit)

한 줄 요약: PTE bit 2(User)는 페이지를 유저 모드(CPL 3)에서 접근할 수 있는지 결정하며, U=0 페이지를 유저가 건드리면 MMU가 pf를 던져 커널 메모리를 막는 하드웨어 장벽이 된다.

PTE 사용자 Bit 상태

PTE의 bit 2(User bit, U/S)는 해당 페이지를 유저 모드(CPL 3)에서 접근할 수 있는지를 결정하는 1비트 플래그다. U=1이면 유저 모드와 커널 모드 모두 접근 가능하고, U=0이면 커널 모드(CPL 0)에서만 접근할 수 있다. 유저 프로세스가 U=0인 페이지에 접근하면 MMU가 즉시 pf(Page Fault)를 발생시킨다. 이 비트가 유저 프로그램이 커널 메모리를 직접 읽거나 쓰지 못하도록 막는 하드웨어 보호 장벽이다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 PTE 64비트 레이아웃에서 bit 2의 위치:

63    52 51        12 11  9 8 7 6 5 4 3 2 1 0
 NX      Physical    AVL  G   D A   U W P
         Address               / / /
         (40 bits)             S R V
값CPL 0 (커널)CPL 3 (유저)
U=1접근 허용접근 허용
U=0접근 허용#PF 발생 (protection violation)

핵심 규칙:

  • U bit 검사는 P=1(present)일 때만 의미가 있다. P=0이면 pf가 먼저 발생하므로 U bit는 해석되지 않는다.
  • 4단계 page table walk의 모든 단계(PML4E → PDPTE → PDE → PTE)에서 U bit가 검사된다. 어느 한 단계라도 U=0이면 해당 VA는 유저 모드에서 접근 불가다.
  • Page Fault error code의 bit 2(PF_U)는 fault 발생 시 CPU가 유저 모드였는지를 나타낸다. PTE의 U bit와 혼동하지 말 것: PF_U는 “누가 접근했는가”, PTE_U는 “누가 접근할 수 있는가”이다.

SMAP/SMEP (최신 CPU):

Intel Ivy Bridge 이후 SMAP(Supervisor Mode Access Prevention)과 SMEP(Supervisor Mode Execution Prevention)이 추가되었다. SMAP이 켜지면 커널 모드에서 U=1 페이지를 의도치 않게 접근하는 것을 차단한다. 이는 커널이 유저 포인터를 잘못 역참조하는 버그를 잡아준다. PintOS에서는 SMAP/SMEP을 사용하지 않는다.

실제 OS (Linux/Windows)

Linux에서 _PAGE_USER (bit 2)는 동일한 의미다. 커널 주소 공간(0xFFFF800000000000 이상)의 PTE에는 U=0이 설정되고, 유저 주소 공간(0x0 ~ 0x00007FFFFFFFFFFF)의 PTE에는 U=1이 설정된다. 이 분리가 커널 메모리 보호의 첫 번째 방어선이다.

Linux 4.15부터 KPTI(Kernel Page Table Isolation)가 도입되었다. Meltdown 취약점 대응으로, 유저 모드에서는 커널 영역 PTE를 아예 page table에서 제거한 별도의 PML4를 사용한다. U=0만으로는 사이드 채널 공격을 막을 수 없기 때문이다.

Windows는 동일하게 U bit로 유저/커널 페이지를 분리하며, KVA Shadow(KPTI와 동등)로 Meltdown을 방어한다.

QEMU 에뮬레이션

QEMU SoftMMU의 mmu_translate() 계열 함수에서 4단계 walk를 수행할 때 U bit를 검사한다. guest CPU가 CPL 3이고 PTE에 U=0이면, error code에 PF_U=1(유저 모드 접근)과 PF_P=1(present page이지만 권한 위반)을 설정하고 pf를 주입한다.

PTE 사용자 Bit 값 추적

PTE 값 구성 예시:

유저 페이지 (읽기/쓰기):
  PTE = PA | PTE_P(0x1) | PTE_W(0x2) | PTE_U(0x4) = PA | 0x7
  bit 2 = 1 → 유저 접근 허용

커널 전용 페이지:
  PTE = PA | PTE_P(0x1) | PTE_W(0x2) = PA | 0x3
  bit 2 = 0 → 커널만 접근 가능

유저 페이지 (읽기 전용, COW 등):
  PTE = PA | PTE_P(0x1) | PTE_U(0x4) = PA | 0x5
  bit 2 = 1, bit 1 = 0 → 유저가 읽기만 가능

PintOS 주소 공간 분할과 U bit:

0x0000000000000000 ~ 0x00007FFFFFFFFFFF  유저 영역  → PTE_U=1
0x8004000000000000 ~ ...                 커널 영역  → PTE_U=0

KERN_BASE = 0x8004000000000000

유저 프로세스가 KERN_BASE 이상 주소에 접근하면:

  1. is_user_vaddr() 검사에서 먼저 걸리거나
  2. 커널 page table의 PTE에 U=0이므로 MMU가 pf 발생

error code 비트 구분:

error code bit이름의미
bit 0 (PF_P)Present0=not present, 1=protection violation
bit 1 (PF_W)Write0=read access, 1=write access
bit 2 (PF_U)User0=커널 모드 접근, 1=유저 모드 접근

순서도 / 개념도

flowchart TD
    A[유저 코드가 VA 접근] --> B{PTE Present?}
    B -->|P=0| C["#PF: not-present"]
    B -->|P=1| D{PTE U bit?}
    D -->|U=1| E{W bit 등 추가 검사}
    D -->|U=0| F["#PF: protection violation<br/>error code: PF_P=1, PF_U=1"]
    E -->|통과| G[주소 변환 완료]
    E -->|실패| H["#PF: rights violation"]

    I[커널 코드가 VA 접근] --> J{PTE Present?}
    J -->|P=0| K["#PF: not-present"]
    J -->|P=1| L{U bit 무관}
    L --> M[주소 변환 완료<br/>CPL 0은 U=0도 접근 가능]

PTE 3대 권한 비트 비교표:

비트위치값=0값=1
