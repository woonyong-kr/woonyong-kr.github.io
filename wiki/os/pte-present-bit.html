PTE present 비트

PTE present 비트

한 줄 요약: PTE bit 0(Present)은 가상 페이지가 물리 메모리에 있는지를 알리는 1비트로, P=0이면 MMU가 즉시 pf를 던져 demand paging·swap·COW의 하드웨어 트리거가 된다.

PTE present 비트 상태

PTE의 bit 0(Present bit, P)은 해당 가상 페이지가 물리 메모리에 존재하는지를 CPU에 알려주는 1비트 플래그다. P=1이면 MMU는 나머지 비트(주소, writable, user 등)를 해석하여 주소 변환을 완료한다. P=0이면 MMU는 즉시 pf(Page Fault) exception을 발생시키고, 나머지 비트는 전혀 해석하지 않는다. 이 단순한 1비트가 demand paging, lazy loading, swap, COW 등 거의 모든 VM 기법의 하드웨어 트리거다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 PTE 64비트 레이아웃에서 bit 0의 위치:

63    52 51        12 11  9 8 7 6 5 4 3 2 1 0
 NX      Physical    AVL  G   D A   U W P
         Address               C   / / /
         (40 bits)             D   S R V
값MMU 동작
P=1유효한 매핑. 나머지 비트(W, U, A, D 등) 해석 후 주소 변환 수행
P=0무효한 매핑. #PF exception 즉시 발생. bits 1~63은 OS가 자유롭게 사용 가능

P=0일 때 나머지 비트가 “don’t care”라는 점이 중요하다. OS는 이 공간에 swap slot 번호나 파일 offset 같은 메타데이터를 인코딩할 수 있다 (Linux의 swap PTE 포맷이 이 방식이다).

4단계 page table walk에서 present bit 검사는 매 단계에서 이루어진다:

CR3 → PML4E[idx] → P 검사 → PDPTE[idx] → P 검사 → PDE[idx] → P 검사 → PTE[idx] → P 검사

어느 단계에서든 P=0이면 walk가 중단되고 pf가 발생한다.

실제 OS (Linux/Windows)

Linux에서 _PAGE_PRESENT (bit 0)은 PintOS와 동일한 의미다. 추가로 Linux는 P=0인 PTE의 나머지 비트를 swap entry로 재해석한다:

Linux swap PTE (P=0):
bit 0:     0 (not present)
bits 1-5:  swap type (어느 swap 장치인지)
bits 6-57: swap offset (swap 장치 내 위치)

Windows도 동일한 원리를 사용하며, PTE가 “transition” 상태일 때 bit 0=0이고 나머지 비트에 page file 정보를 인코딩한다.

PintOS 구현

PintOS는 include/threads/pte.h에서 present bit를 정의한다:

pml4e_walk() — 4단계 walk에서 P 검사:

threads/mmu.c의 walk 함수들(pgdir_walk → pdpe_walk → pml4e_walk)은 매 단계에서 동일한 패턴으로 P를 검사한다:

pml4_get_page() — VA → KVA 변환:

P=0이면 NULL 반환 — 이 VA에 대한 물리 매핑이 없다는 뜻이다.

pml4_set_page() — 매핑 설정:

새 매핑을 만들 때 반드시 PTE_P를 OR한다. P=0인 PTE에 주소만 넣으면 MMU가 무시한다.

pml4_clear_page() — 매핑 해제:

P bit만 끈다. 나머지 비트(물리 주소 등)는 보존된다. 이 시점 이후 해당 VA 접근은 pf를 유발한다.

QEMU 에뮬레이션

QEMU SoftMMU에서 page table walk를 에뮬레이션할 때 present bit 검사는 target/i386/tcg/excp_helper.c의 mmu_translate() 계열 함수에서 수행된다. P=0이면 EXCP0E_PAGE (exception 14, pf)를 주입한다. 이 때 error code의 bit 0(PF_P)에 0이 설정되어 “not-present fault”임을 나타낸다.

PTE present 비트 값 추적

Present bit가 관여하는 구체적 시나리오:

Lazy loading 예시:

load_segment() → vm_alloc_page_with_initializer()
  PML4에 PTE 없음 (P=0 상태)
  SPT에만 UNINIT page 등록

유저 코드가 해당 VA에 접근
  MMU walk → PTE 없음 → #PF 발생
  error code: PF_P=0 (not present), PF_U=1 (user mode)

vm_try_handle_fault() → vm_do_claim_page()
  palloc_get_page() → 프레임 확보
  pml4_set_page(pml4, upage, kpage, writable)
    → *pte = PA | PTE_P | PTE_W | PTE_U
  이제 P=1 → 같은 명령어 재시도 → 정상 접근

Eviction 예시:

victim frame 선택 → swap_out()
  pml4_clear_page(victim->pml4, victim->upage)
    → *pte &= ~PTE_P  (P=0으로)
  물리 프레임은 해제되어 다른 page에 재할당

나중에 같은 VA 접근
  MMU walk → P=0 → #PF 발생
  SPT 조회 → swap slot에서 복원
  pml4_set_page() → P=1로 복귀

PTE 값 예시:

매핑 설정 후 PTE 값:
  물리 주소 0x00000000_80005000 (frame PA)
  PTE = 0x00000000_80005007
        = PA | PTE_P(0x1) | PTE_W(0x2) | PTE_U(0x4)

clear 후 PTE 값:
  PTE = 0x00000000_80005006
        = PA | PTE_W(0x2) | PTE_U(0x4)  (P=0)

순서도 / 개념도

flowchart TD
    A[MMU: VA 접근] --> B{PTE 존재?}
    B -->|PTE entry 없음| C[#PF: not-present]
    B -->|PTE entry 있음| D{P bit = 1?}
    D -->|P=0| C
    D -->|P=1| E{W, U 등 권한 검사}
    E -->|통과| F[주소 변환 완료 → PA]
    E -->|실패| G[#PF: protection violation]
    C --> H[OS page fault handler]
    G --> H
    H --> I{SPT에 등록?}
    I -->|Yes| J[페이지 적재 후 P=1 설정]
    I -->|No| K[Segfault → 프로세스 종료]
    J --> A
