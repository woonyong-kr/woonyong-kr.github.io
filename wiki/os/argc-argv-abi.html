argc/argv ABI — 유저 프로그램 시작 인자 전달 규약

한 줄 요약: Linux의 프로세스 초기 진입은 스택 기반이지만, PintOS는 C 함수 호출 규약의 인자 레지스터를 빌려 _start 진입 전에 RDI=argc·RSI=argv를 직접 설정한다.

argc/argv ABI 상태

System V AMD64는 프로세스 최초 진입과 C 함수 호출을 구분한다. Linux 커널은 _start에 스택 기반 초기 상태를 제공하고, C 런타임이 나중에 main(int argc, char **argv)을 호출할 때 함수 호출 규약에 따라 RDI = argc, RSI = argv를 쓴다. PintOS는 이 시작 절차를 단순화해 커널이 _start로 진입하기 전부터 두 레지스터를 직접 설정한다.

상세 설명

추상 개념 (ABI 규약)

프로그램 시작 시 커널이 유저에게 전달해야 하는 정보:

  1. argc — 인자 개수 (int, 0 이상)
  2. argv — 인자 문자열 포인터 배열의 시작 주소 (char **)
  3. envp — 환경 변수 배열 (PintOS에서는 미구현)

x86-64 C 함수 호출 경계와 PintOS의 사용자 진입 경계에서는 다음 레지스터를 쓴다. 이는 Linux 커널이 제공하는 프로세스 초기 상태를 설명하는 표가 아니다.

레지스터값C 타입
RDIargcint
RSIargv 포인터char **

Linux의 envp와 auxv는 초기 스택에서 찾는다. 동적 링크된 ELF의 최초 RDX에는 종료 처리 함수 포인터가 전달될 수 있으므로 RDX=envp라고 일반화하면 안 된다. C 런타임은 초기 스택을 해석한 뒤 일반 함수 호출 규약으로 main을 호출한다.

실제 OS (Linux)

Linux에서는 execve() 시스템 콜 → load_elf_binary() → start_thread()를 거치며:

  1. 유저 스택에 환경 변수, argv 문자열, auxv를 배치
  2. 스택 최상단에 argc (8바이트 정수)를 push
  3. _start(ELF entry point)로 점프 시 RSP가 argc를 가리킴
  4. _start와 C 런타임이 초기 스택을 해석하고, 최종적으로 함수 호출 규약에 맞춰 main을 호출

Linux의 전통적 방식은 스택 기반 전달이지만, _start 코드가 즉시 레지스터로 변환한다.

PintOS 구현

PintOS는 C 런타임(_start)이 매우 단순하므로 커널이 직접 intr_frame의 레지스터를 설정한다. setup_initial_stack() (userprog/process.c L1064–1097):

유저 진입점 _start (lib/user/entry.c L7–9)는 커널이 설정한 레지스터를 그대로 사용한다:

Linux와 달리 PintOS의 _start는 스택에서 argc를 pop하지 않는다. 커널이 이미 RDI/RSI에 직접 넣어주기 때문이다.

QEMU 에뮬레이션

QEMU는 인자 전달에 개입하지 않는다. setup_initial_stack()이 guest physical memory에 쓴 스택 데이터와 intr_frame에 설정한 레지스터 값은 do_iret() 시점에 TCG가 guest CPU 상태(CPUX86State)로 복원한다. QEMU 관점에서는 일반적인 iretq 명령어 실행일 뿐이다.

argc/argv ABI 값 추적

/bin/ls -la foo.txt (argc=3) 실행 시 스택과 레지스터:

바이트 주소와 포인터 값을 함께 보아야 하므로 이 부분은 표로 보존한다. PintOS의 실제 loop가 argi = argc - 1부터 감소하므로 복사 순서는 foo.txt → -la → /bin/ls이고 주소는 매번 문자열 길이만큼 감소한다.

주소저장 값의미
0x4747FFF8"foo.txt\0"argv[2] 문자열, 8B
0x4747FFF4"-la\0"argv[1] 문자열, 4B
0x4747FFEC"/bin/ls\0"argv[0] 문자열, 8B
0x4747FFE8–0x4747FFEB0 padding8바이트 경계로 내림
0x4747FFE00x0000000000000000argv[3] = NULL
0x4747FFD80x4747FFF8argv[2] → "foo.txt"
0x4747FFD00x4747FFF4argv[1] → "-la"
0x4747FFC80x4747FFECargv[0] → "/bin/ls", RSI
0x4747FFC00x0000000000000000fake return address, RSP

유저 모드 진입 값은 RSP=0x4747FFC0, RDI=3, RSI=0x4747FFC8, RIP=e_entry다. 따라서 RSI가 가리키는 첫 포인터를 한 번 역참조하면 0x4747FFEC의 "/bin/ls"를 얻는다.
