경쟁 조건 — 공유 자원에 동시 접근하면 결과가 달라진다

경쟁 조건 — 공유 자원에 동시 접근하면 결과가 달라진다

범위: 이 문서는 경쟁 조건의 일반 개념과 발생 조건, 동기화 수단의 선택 기준을 설명하고 Linux와 PintOS 및 예시 코드를 통해 이를 구분해 보여 준다. 다만 제시된 코드는 특정 버전의 실제 구현이나 실행 기록을 검증한 결과가 아니므로, 구체적인 동작과 수치·성능 판단은 해당 코드와 환경에서 별도로 확인해야 한다.

한 줄 요약: 둘 이상의 실행 흐름이 공유 데이터를 동시에 읽고 쓸 때, 실행 순서에 따라 결과가 달라지는 현상이 경쟁 조건(Race Condition)이다.

경쟁 조건 혼동

싱글 스레드 프로그램에서는 코드가 한 줄씩 순서대로 실행된다. 공유 변수를 읽고 쓰는 순서가 항상 같으므로 결과도 항상 같다.

멀티스레드 환경에서는 다르다. 두 스레드가 같은 변수를 동시에 수정하면, 어느 스레드가 먼저 쓰느냐에 따라 최종 값이 달라진다. 이 비결정성이 경쟁 조건이다.

경쟁 조건을 이해하지 못하면 동기화 도구(세마포어, 락, 조건 변수)가 왜 필요한지 알 수 없다. 디버깅도 불가능하다. 재현이 안 되기 때문이다.

경쟁 조건 구조

비유

두 사람이 같은 은행 계좌에서 동시에 출금한다고 하자. 잔액이 100원이다. A가 잔액을 읽고(100원), B도 잔액을 읽고(100원), A가 50원을 빼서 50원을 쓰고, B도 50원을 빼서 50원을 쓴다. 결과는 50원이다. 실제로는 100원이 빠져야 하므로 0원이어야 한다. 읽기와 쓰기 사이에 다른 쓰기가 끼어들었기 때문이다.

정의

경쟁 조건은 다음 세 가지 조건이 모두 성립할 때 발생한다.

  1. 공유 자원 — 둘 이상의 실행 흐름이 같은 데이터에 접근한다.
  2. 동시 접근 — 최소 하나의 접근이 쓰기(write)다.
  3. 비원자적 연산 — 읽기-수정-쓰기가 하나의 원자적 단위로 실행되지 않는다.

세 조건 중 하나라도 제거하면 경쟁 조건은 사라진다.

임계 구역 (Critical Section)

경쟁 조건이 발생할 수 있는 코드 영역을 임계 구역이라 한다. 임계 구역에는 한 번에 하나의 스레드만 진입해야 한다. 이것을 상호 배제(Mutual Exclusion) 라 한다.

동작 순서: 경쟁 조건이 발생하는 과정

%% 경쟁 조건이 발생하는 과정
flowchart TD
  sequence["스레드 A &#124; 공유 변수 cnt &#124; 스레드 B<br/>&#124; [0] &#124;<br/>1. cnt 읽기 -&gt; 0 &#124; &#124;<br/>&#124; &#124; 2. cnt 읽기 -&gt; 0<br/>3. cnt = 0 + 1 &#124; &#124;<br/>&#124; &#124; 4. cnt = 0 + 1<br/>5. cnt 쓰기 -&gt; 1 &#124; [1] &#124;<br/>&#124; [1] &#124; 6. cnt 쓰기 -&gt; 1<br/>기대값: 2"]

A와 B 모두 cnt++를 실행했지만, 읽기-수정-쓰기 사이에 상대의 연산이 끼어들어 하나가 유실되었다.

실제 OS와 PintOS의 경쟁 조건 방지

Linux: spinlock, mutex, atomic 연산, RCU 등 다양한 동기화 메커니즘을 제공한다. 멀티코어 환경이므로 인터럽트 비활성화만으로는 충분하지 않다.

PintOS: 단일 CPU 환경이다. 인터럽트를 끄면 선점이 불가능해지므로 원자성이 보장된다. lock_acquire()와 lock_release()는 내부적으로 intr_disable()을 사용한다.

경쟁 조건 코드

PintOS에서 인터럽트 비활성화로 원자성 확보

intr_disable()부터 intr_set_level()까지가 임계 구역이다. 인터럽트가 꺼져 있으므로 타이머 인터럽트가 발생하지 않고, 다른 스레드로 전환되지 않는다. sema->value를 읽고 쓰는 사이에 다른 스레드가 끼어들 수 없다.

PintOS에서 락으로 임계 구역 보호

lock_acquire()는 내부적으로 sema_down()을 호출한다. 락을 이미 다른 스레드가 잡고 있으면 현재 스레드는 잠든다. 락이 해제되면 대기 중이던 스레드가 깨어나 락을 획득한다.

정리

경쟁 조건은 공유 자원 + 동시 쓰기 + 비원자적 연산이 만나면 발생한다. 해결 방법은 세 조건 중 하나를 제거하는 것이다. PintOS에서는 인터럽트 비활성화와 락으로 임계 구역을 보호한다. 실제 멀티코어 OS에서는 스핀락, 뮤텍스, 원자적 연산 등 더 정교한 도구가 필요하다.
