list_entry 매크로

list_entry 매크로

한 줄 요약: list_elem 포인터에서 그것을 멤버로 가진 바깥 구조체 포인터를 계산하는 list_entry() 매크로(container_of).

list_entry 매크로 구조

list_entry()는 struct list_elem 포인터를 받아, 그 elem을 멤버로 포함하는 바깥 구조체의 포인터를 계산해 돌려주는 매크로다. PintOS의 이중 연결 리스트는 Linux의 container_of와 같은 침입형(intrusive) 설계를 따르기 때문에, 리스트 노드 자체에는 데이터가 없고 바깥 구조체 안에 struct list_elem이 끼워져 있다. 이 매크로 없이는 리스트 순회 결과를 실제 데이터로 변환할 수 없으므로, PintOS 코드 전체에서 가장 많이 호출되는 매크로 중 하나다.

아래 8-byte 포인터와 offset 숫자는 KAIST x86-64 PintOS의 설명용 예시다. 32-bit PintOS에서는 포인터와 정렬이 달라지므로 숫자를 재사용하지 말고 대상 build에서 sizeof와 offsetof를 확인한다.

상세 설명

추상 개념 — 침입형 리스트와 역참조

일반적인 리스트 노드는 void *data 포인터를 들고 있지만, 침입형 리스트는 데이터 구조체 안에 노드를 끼워 넣는다. 장점은 두 가지다.

  1. 별도의 힙 할당 없이 기존 구조체만으로 리스트를 구성할 수 있다.
  2. 하나의 구조체가 여러 리스트에 동시에 속할 수 있다 (멤버를 여러 개 두면 된다).

역참조 문제: 리스트 함수는 struct list_elem *만 반환하므로, 호출자가 elem의 주소에서 바깥 구조체의 시작 주소를 역산해야 한다. 이것이 list_entry의 역할이다.

Linux 커널 — container_of

Linux에서는 동일한 개념을 container_of(ptr, type, member)로 구현한다.

offsetof(type, member)는 구조체 시작부터 해당 멤버까지의 바이트 오프셋이다. ptr - offset이 곧 바깥 구조체의 시작 주소가 된다.

PintOS 구현

PintOS의 list_entry는 include/lib/kernel/list.h 99–101행에 정의되어 있다.

Linux의 container_of와 원리는 같지만, 포인터 기준점이 다르다.

비교 항목Linux container_ofPintOS list_entry
기준 포인터ptr (멤버 자체)&(LIST_ELEM)->next
오프셋 대상offsetof(type, member)offsetof(STRUCT, MEMBER.next)
효과동일 — 바깥 구조체 시작 주소동일

PintOS가 ->next를 기준으로 잡는 이유: struct list_elem의 첫 필드가 prev이고 두 번째 필드가 next다. x86-64 예시에서 next는 prev 뒤 8바이트에 있고, 32-bit에서는 4바이트 뒤에 있다. 어떤 ABI든 &elem->next에서 같은 ABI로 계산한 offsetof(STRUCT, MEMBER.next)를 빼면 바깥 구조체의 시작 주소가 된다.

list_entry 매크로 숫자 추적

struct thread 안에 elem 멤버가 있을 때의 구체적 계산 예시:

struct thread {
    tid_t tid;                    // offset 0, 4 bytes
    enum thread_status status;    // offset 4, 4 bytes
    char name[16];                // offset 8, 16 bytes
    int priority;                 // offset 24, 4 bytes
    struct list_elem elem;        // offset 32 (가정)
        .prev  → offset 32, 8 bytes
        .next  → offset 40, 8 bytes
    ...
};

list_entry(e, struct thread, elem) 호출 시:

step 1: &(e)->next         = e의 주소 + 8  (next는 list_elem 내 offset 8)
step 2: offsetof(struct thread, elem.next) = 40
step 3: (uint8_t *)&(e)->next - 40 = struct thread의 시작 주소

결국 e - offsetof(struct thread, elem) = e - 32와 동치다.

다중 elem 멤버 — 하나의 구조체가 여러 리스트에 속하는 경우

두 호출은 각 멤버의 실제 offsetof 값을 사용하므로 같은 구조체를 서로 다른 연결에서 정확히 역산할 수 있다. 실제 값은 구조체 버전과 ABI에 따라 달라진다. 멤버 이름을 잘못 쓰면 엉뚱한 주소를 가리키며, 잘못된 객체를 읽거나 메모리를 훼손할 수 있다.

또 다른 예로 struct child_status (thread.h L37–43)도 elem을 통해 부모의 child_status_list에 연결된다.

사용 패턴

PintOS에서 list_entry가 쓰이는 대표적 패턴 4가지:

1. 리스트 순회

2. 리스트 front/back에서 꺼내기

3. 비교 함수 내부

4. 다른 멤버(donation_elem)로 역참조
