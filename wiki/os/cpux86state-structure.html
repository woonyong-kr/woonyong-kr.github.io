CPUX86State 구조체 — QEMU의 가상 CPU

CPUX86State 구조체 — QEMU의 가상 CPU

한 줄 요약: x86-64 게스트 CPU의 레지스터·제어 레지스터·세그먼트·FPU 상태를 하나로 담는 QEMU 가상 CPU 구조체 CPUX86State.

CPUX86State 구조체 상태

CPUX86State는 QEMU가 x86-64 게스트 CPU의 전체 아키텍처 상태를 C 구조체 하나로 표현한 것이다. 실제 CPU의 레지스터 파일, 제어 레지스터, 세그먼트 디스크립터 캐시, FPU/SSE 상태 등이 모두 이 구조체의 필드로 존재한다. GDB에서 info registers를 실행하면 QEMU는 이 구조체의 필드를 읽어 전달하고, TCG가 생성한 코드는 이 구조체의 필드를 직접 읽고 쓰면서 명령어를 에뮬레이션한다.

OS 디버깅에서 이 구조체를 이해하면 “GDB가 보여주는 값이 어디서 오는가”를 정확히 추적할 수 있다.

상세 설명

추상 개념 (실제 CPU의 상태)

실제 x86-64 CPU는 수백 개의 레지스터를 가진다. 소프트웨어에서 관찰 가능한 아키텍처 상태(architectural state)를 분류하면:

카테고리레지스터 예시크기
범용 레지스터RAX~R15 (16개)각 8 bytes
명령어 포인터RIP8 bytes
스택 포인터RSP (범용에 포함)8 bytes
플래그RFLAGS (EFLAGS의 64-bit 확장)8 bytes
세그먼트 셀렉터CS, DS, ES, FS, GS, SS각 2 bytes
세그먼트 캐시각 셀렉터의 base/limit/access각 ~16 bytes
제어 레지스터CR0, CR2, CR3, CR4각 8 bytes
MSREFER, LSTAR, STAR, FMASK 등각 8 bytes
FPU/SSEXMM0~XMM15, MXCSR각 16 bytes
디스크립터 테이블GDTR(base+limit), IDTR, LDTR, TR각 10~12 bytes

에뮬레이터가 이 모든 상태를 소프트웨어로 유지해야 게스트 OS가 실제 CPU 위에서 도는 것처럼 동작한다.

QEMU 구현 (CPUX86State)

QEMU 소스의 target/i386/cpu.h에 정의된 CPUX86State의 핵심 필드를 PintOS 디버깅에 필요한 것 위주로 정리한다:

범용 레지스터

target_ulong은 64-bit 모드에서 uint64_t다. CPU_NB_REGS는 16.

주의: regs[]의 인덱스 순서는 x86 인코딩 순서를 따른다. RAX=0, RCX=1, RDX=2, RBX=3 순이다. Intel 매뉴얼의 레지스터 인코딩과 일치한다.

세그먼트 레지스터

SegmentCache 하나는:

GDB에서 p/x $cs가 0x08을 반환하면, 실제로는 env->segs[R_CS].selector가 0x08이다.

제어 레지스터

PintOS 디버깅에서 가장 중요한 것:

  • cr[2] (CR2): 마지막 page fault의 fault 주소
  • cr[3] (CR3): 현재 활성 페이지 테이블의 물리 주소

MSR 레지스터

hflags — 에뮬레이션 가속 비트

hflags는 하드웨어에 존재하지 않는 QEMU 내부 필드다. 자주 참조되는 상태를 비트로 캐싱하여 TCG 코드에서 빠르게 검사한다:

  • HF_CPL_MASK (bit 0~1): 현재 CPL 값 캐시
  • HF_PE_MASK: Protected Mode 활성 여부
  • HF_LMA_MASK: Long Mode 활성 여부

TCG가 특권 명령어를 에뮬레이션할 때 hflags & HF_CPL_MASK로 CPL을 확인한다.

PintOS 디버깅에서의 활용

GDB로 PintOS를 디버깅할 때 보는 모든 값은 CPUX86State에서 온다:

GDB 명령읽는 CPUX86State 필드PintOS 디버깅 용도

p/x $cssegs[R_CS].selector유저 모드(0x23) vs 커널 모드(0x08) 확인
p/x $cr2cr[2]page fault 주소 확인

GDB Stub의 전달 경로

GDB 프로토콜의 레지스터 번호와 regs[] 인덱스는 다르다. GDB는 RAX=0, RBX=1, RCX=2, RDX=3 순서를 쓰지만 (GDB의 전통), regs[]는 Intel 인코딩 순서다. gdbstub.c가 이 매핑을 처리한다.

struct intr_frame과의 대응

PintOS의 struct intr_frame과 CPUX86State는 서로 다른 추상화 수준에서 같은 CPU 상태를 표현한다:

상태CPUX86State 필드intr_frame 필드크기
RAXregs[0]R.rax8 bytes
RCXregs[1]R.rcx8 bytes
RIPeiprip8 bytes
CSsegs[1].selectorcs2 bytes (+padding)
RFLAGSeflagseflags8 bytes
RSPregs[4]rsp8 bytes
SSsegs[2].selectorss2 bytes (+padding)
CR2cr[2](별도: fault_addr)8 bytes
CR3cr[3](thread→pml4)8 bytes

do_iret()의 iretq는 intr_frame의 5개 필드(rip, cs, eflags, rsp, ss)를 CPU에 복원한다. QEMU TCG에서는 이것이 CPUX86State의 eip, segs[R_CS], eflags, regs[R_ESP], segs[R_SS]에 기록되는 것이다.
