PTE 더티 Bit (PTE Dirty Bit)

PTE 더티 Bit (PTE Dirty Bit)

확인 범위: 이 문서는 PTE dirty bit의 일반 원리와 운영체제별 활용 방식을 설명하고, 제시된 PintOS 코드 및 QEMU 동작 경로를 특정 구현 사례로 구분해 다룬다. 코드 좌표·기본값·실행 예시·I/O 및 성능 관련 판단은 해당 버전의 실제 소스와 실행 기록 또는 측정으로 별도 검증해야 한다.

한 줄 요약: MMU가 store 시 자동으로 1로 세팅하고 OS만 클리어할 수 있는 PTE bit 6으로, eviction 시 프레임을 디스크에 써야 하는지(D=1) 즉시 회수해도 되는지(D=0)를 판단한다.

PTE 더티 Bit 상태

PTE의 **dirty bit(D bit, bit 6)**는 해당 페이지에 쓰기가 발생했는지를 나타내는 1-bit 플래그다. MMU가 store 명령어 실행 시 자동으로 1로 설정하고, OS만이 0으로 클리어할 수 있다. eviction 시 “이 프레임을 디스크에 써야 하는가?”를 판단하는 핵심 비트로, D=0이면 디스크 I/O 없이 프레임을 즉시 회수할 수 있어 성능에 직접적 영향을 준다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 PTE bit 6이 dirty bit이다.

63    12 11  9  8  7  6  5  4  3  2  1  0
+------+-----+--+--+--+--+--+--+--+--+--+
| ADDR | AVL |G |  |D |A |  |  |U |W |P |
+------+-----+--+--+--+--+--+--+--+--+--+
                    ^
                    D bit (0x40)

A bit와의 차이:

특성Accessed bit (A)Dirty bit (D)
비트 위치bit 5 (0x20)bit 6 (0x40)
설정 조건읽기 또는 쓰기쓰기만
설정 주체MMU 하드웨어MMU 하드웨어
클리어 주체OS 소프트웨어OS 소프트웨어
적용 범위모든 페이지 테이블 단계PTE(최하위)에만 의미
주 용도교체 대상 선정write-back 필요 여부

MMU의 동작:

  1. store 명령어 실행 → MMU가 page table walk
  2. PTE의 W=1 확인 (쓰기 허용)
  3. D=0이면 → D=1로 갱신 후 메모리에 write-back
  4. D=1이면 → 추가 동작 없음

W=0인 페이지에 쓰기 시도 → pf 발생 (D bit 설정 안 됨). COW에서 이 원리를 활용한다.

실제 OS (Linux/Windows)

Linux에서 dirty bit의 용도:

  1. 페이지 회수 (page reclaim): dirty page는 evict 전에 반드시 backing store(swap 또는 파일)에 써야 한다. clean page(D=0)는 즉시 버릴 수 있다.
  2. writeback daemon: kworker/u*:*+flush 스레드가 주기적으로 dirty page를 파일 시스템에 flush한다. 두 가지 트리거:
    • dirty_expire_centisecs (기본 3000 = 30초) — 이 시간이 지난 dirty page를 write-back
    • dirty_writeback_centisecs (기본 500 = 5초) — daemon 깨어나는 주기
  3. mmap write-back: msync(MS_SYNC) 또는 munmap() 시 dirty page만 디스크에 기록한다.
  4. page migration: NUMA balancing에서 page를 옮길 때 dirty page는 새 노드에 복사 후 기록해야 한다.

Linux dirty page 추적 계층:

하드웨어 PTE D bit (CPU가 설정)
  ↓ ptep_clear_flush()로 수거
struct page::flags PG_dirty (소프트웨어 플래그)
  ↓ set_page_dirty() / clear_page_dirty_for_io()
struct address_space::nr_dirty (파일별 dirty page 수)
  ↓ balance_dirty_pages()
/proc/meminfo Dirty: xxx kB (시스템 전체)

Linux는 하드웨어 D bit를 주기적으로 확인하여 소프트웨어 PG_dirty 플래그로 승격시킨다. 이후 하드웨어 D bit를 클리어해도 소프트웨어 플래그는 유지되므로, write-back이 완료될 때까지 dirty 상태가 보존된다. PintOS는 이 2단계 추적 없이 하드웨어 D bit를 직접 검사한다.

Linux dirty page 제한 (throttling):

시스템 메모리의 일정 비율 이상이 dirty면 쓰기 프로세스를 throttle한다:

파라미터기본값의미
vm.dirty_ratio20%이 비율 초과 시 동기 write-back (프로세스 블로킹)
vm.dirty_background_ratio10%이 비율 초과 시 백그라운드 write-back 시작

PintOS에는 dirty page throttling이 없다. 모든 anonymous page는 eviction 시점에서야 swap out된다.

PintOS vs Linux dirty 관리 비교:

항목PintOSLinux
dirty 추적하드웨어 PTE D bit 직접 검사PTE D → PG_dirty 2단계
write-back 시점eviction 또는 munmap 시에만주기적 + eviction + msync
throttling없음dirty_ratio로 프로세스 블로킹
파일 dirty 추적없음 (page 단위만)address_space 단위
TLB flushinvlpg (단일 PTE)ptep_clear_flush (배치 가능)

Windows에서는 Modified Page Writer가 dirty page를 배경으로 write-back하며, standby list의 clean page는 즉시 재할당한다.

QEMU 에뮬레이션

QEMU SoftMMU는 x86 하드웨어와 동일하게 D bit를 에뮬레이트한다.

store 명령 시 D bit 설정 경로:

guest: mov [addr], rax
  → SoftMMU TLB lookup
    → TLB hit, dirty bit 이미 설정 → fast path (직접 host 메모리에 쓰기)
    → TLB hit, dirty bit 미설정 → slow path:
      → store_helper()
        → tlb_fill() → x86_cpu_tlb_fill()
          → PTE walk → PTE.D=0 발견 → PTE.D=1로 갱신
          → TLB 재로드 (dirty flag 포함)

SoftMMU는 TLB 엔트리에 TLB_NOTDIRTY 플래그를 사용한다. 첫 write 시 slow path를 타서 PTE의 D bit를 설정하고 TLB를 갱신한 뒤, 이후 같은 페이지에 대한 write는 fast path로 처리한다.

GDB에서 dirty bit 관찰:

PTE 더티 Bit 값 추적

항목값
D bit 위치PTE bit 6 (0x40)
clean eviction 비용~0 disk I/O (프레임 즉시 회수)
dirty eviction 비용4 KB disk write (swap) 또는 file write
swap write 비용8 sectors × 512 B = 4096 B
mmap write-backfile_write_at(file, page->va, read_bytes, ofs)

예: PTE 값 0x0000000012345027:

  • bit 6 = 0 → D=0 (clean, write-back 불필요)
  • bit 5 = 1 → A=1 (접근됨)
  • bit 0~2 = 0x7 → P=1, W=1, U=1

PTE 값 0x0000000012345067:

  • bit 6 = 1 → D=1 (dirty, eviction 시 write-back 필수)

PTE 더티 Bit 점검

  • D bit는 “쓰기 발생” 신호지만, 현재 PintOS의 victim 선택 자체는 A bit와 clock hand가 맡는다.
  • Anonymous page는 원본 파일이 없어서 D=0이라는 이유만으로 버릴 수 없다. 현재 anon_swap_out()은 D bit를 보지 않고 4KB frame 내용을 swap disk에 저장한다.
  • File-backed/mmap page는 원본 파일이 backing store이므로 D=0이면 write-back을 건너뛰고, D=1이면 file_write_at()으로 변경분을 기록한다.
  • D bit를 0으로 내린 뒤 다음 쓰기를 다시 관찰하려면 pml4_set_dirty(..., false)가 TLB entry를 invlpg()로 무효화해야 한다.
  • COW page는 처음에 W=0이라 쓰기 시도에서 page fault가 먼저 나고, writable PTE로 다시 설치된 뒤 실제 쓰기가 성공하면 D bit가 세워진다.
