커널 주소 공간 배치

커널 주소 공간 배치

한 줄 요약: 커널 주소 공간은 프로세스들이 공유하는 커널 코드·데이터·스택·물리 메모리 매핑 영역이며, Linux x86-64는 보통 canonical 상위 절반을 쓰지만 이 문서의 PintOS는 하위 절반의 KERN_BASE부터 배치한다.

커널 주소 공간 배치 상태

커널 주소 공간은 OS 커널의 코드, 데이터, 스택과 물리 메모리 매핑이 배치되는 가상 주소 영역이다. x86-64의 canonical 주소 규칙은 유효한 하위·상위 범위를 정하지만, 어느 범위를 커널에 할당할지는 OS 정책이다. Linux x86-64는 보통 상위 절반을 쓰고, 이 문서의 PintOS는 하위 canonical 범위 안의 높은 KERN_BASE를 쓴다. 직접 매핑에서는 물리 주소와 커널 가상 주소 사이의 주소 계산이 고정 오프셋 연산이지만, 실제 접근은 일반적인 TLB 조회와 필요 시 page walk를 거친다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 Canonical 주소

x86-64는 가상 주소가 64비트이지만, 실제로 MMU가 사용하는 것은 하위 48비트(4-level paging) 또는 57비트(5-level paging)다. 48-bit 모드에서 유효한 주소 범위:

범위영역크기
0x0000_0000_0000_0000 ~ 0x0000_7FFF_FFFF_FFFF유저 영역 (하위 절반)128 TB
0x0000_8000_0000_0000 ~ 0xFFFF_7FFF_FFFF_FFFF비표준 (non-canonical hole)-
0xFFFF_8000_0000_0000 ~ 0xFFFF_FFFF_FFFF_FFFF커널 영역 (상위 절반)128 TB

Non-canonical 주소에 접근하면 gp가 발생한다. 이 “구멍”은 canonical 하위·상위 주소 범위를 떨어뜨려 놓지만, 그 자체가 user/supervisor 권한 경계를 정하지는 않는다. 실제 보호는 page table의 U/S 비트와 CPL 검사에 달려 있으며, PintOS처럼 하위 canonical 범위 일부를 커널에 쓰는 OS도 가능하다.

직접 매핑(Direct Mapping)의 원리

커널이 물리 프레임을 관리하려면 “물리 주소 X의 내용”을 읽을 수 있어야 한다. 매번 임시 매핑을 만들면 너무 느리므로, 부팅 시 전체 물리 메모리를 커널 가상 주소 공간에 고정 오프셋으로 매핑한다:

kernel_va = physical_addr + KERN_BASE
physical_addr = kernel_va - KERN_BASE

이 산술 변환 자체는 상수 시간이다. 그러나 메모리 접근은 다른 가상 주소와 마찬가지로 TLB miss와 page walk가 발생할 수 있으므로, 직접 매핑이 항상 TLB에 적재되어 있다고 가정하면 안 된다.

실제 OS (Linux)

Linux x86-64의 커널 주소 공간 (48-bit 모드):

%% Linux x86-64 48-bit canonical 주소 공간의 낮은 주소에서 높은 주소까지의 배치
flowchart TB
  low["0x0000_0000_0000_0000"] --> user["user space<br/>프로세스별 code·heap·mmap·stack"]
  user --> hole["non-canonical hole<br/>접근 시 #GP"]
  hole --> high["0xFFFF_8000_0000_0000 이후<br/>Linux kernel high half"]
  high --> direct["direct / linear map<br/>__va(pa)·__pa(va)<br/>page_offset_base는 KASLR 영향 가능"]
  high --> vmalloc["vmalloc / ioremap<br/>동적 kernel VA·device MMIO"]
  high --> vmemmap["vmemmap<br/>physical page의 struct page metadata"]
  high --> image["kernel text·rodata·data·modules"]
  high --> fixed["fixmap·per-CPU·CPU entry area"]
  direct --> top["0xFFFF_FFFF_FFFF_FFFF"]
  vmalloc --> top
  vmemmap --> top
  image --> top
  fixed --> top

Linux의 __pa(va) / __va(pa) 매크로가 직접 매핑 영역에서 물리↔가상 변환을 수행한다. page_offset_base는 KASLR로 런타임에 랜덤화될 수 있다.

PintOS 구현

PintOS는 Linux보다 훨씬 단순한 커널 주소 공간을 사용한다.

핵심 상수

KERN_BASE가 0x8004000000 (약 512.06 GiB)인 이유: PintOS는 48-bit canonical 주소의 상위 절반(0xFFFF...)이 아니라, 하위 절반 내의 높은 주소를 커널에 할당한다. 이는 4-level 페이지 테이블의 구조와 PintOS의 단순한 매핑 전략 때문이다.

주소 공간 배치

%% KAIST PintOS가 하위 canonical 범위에 user 공간과 kernel direct map을 배치하는 방식
flowchart TB
  low["0x0000000000"] --> user["user process area<br/>프로세스별 code·data·heap·mmap"]
  user --> stack["USER_STACK = 0x47480000<br/>stack은 아래 방향으로 성장"]
  stack --> gap["미사용 gap<br/>Linux high-half 배치와 다름"]
  gap --> base["KERN_BASE = 0x8004000000<br/>kernel direct map 시작"]
  pa["physical [0, mem_end)"] -->|"ptov(pa) = pa + KERN_BASE"| base
  base --> text["kernel text VMA = 0x8004200000<br/>physical LMA = 0x200000"]
  text --> end_node["KERN_BASE + mem_end<br/>direct map 끝"]
  base -. "vtop(va) = va - KERN_BASE" .-> pa

링커 스크립트 (kernel.lds.S)

. = LOADER_KERN_BASE + LOADER_PHYS_BASE;   // 0x8004200000
.text : AT(LOADER_PHYS_BASE) { ... }       // 물리 주소 0x200000에 로드

AT(LOADER_PHYS_BASE)는 로드 주소(LMA)를 물리 0x200000으로 지정한다. 가상 주소(VMA)는 0x8004200000이다. 즉 같은 코드가 물리적으로는 0x200000에 있지만, 가상 주소로는 KERN_BASE + 0x200000에서 실행된다.

paging_init() — 직접 매핑 설정

이 루프가 하는 일: 물리 주소 [0, mem_end) 전체를 가상 주소 [KERN_BASE, KERN_BASE + mem_end)로 1:1 매핑. 커널 코드 영역(.text ~ _end_kernel_text)만 쓰기 금지로 설정하여 코드 무결성을 보호한다.

ptov / vtop 변환

이 매크로가 동작하는 전제: paging_init()이 전체 물리 메모리를 KERN_BASE 오프셋으로 매핑해 두었기 때문.

QEMU 에뮬레이션

QEMU 입장에서 커널 주소 공간 매핑은 “페이지 테이블을 통한 정상적인 주소 변환”이다. paging_init()이 PTE를 채우고 CR3를 로드하면, 이후 QEMU는 게스트의 가상 주소를 4-level 페이지 테이블을 통해 게스트 물리 주소로 변환하고, RAMBlock에서 해당 바이트를 읽는다.

GDB에서 커널 주소↔물리 주소 확인:

(gdb) p/x 0x8004200000 - 0x8004000000
$1 = 0x200000                          # = LOADER_PHYS_BASE

(gdb) x/4x 0x8004200000               # 커널 텍스트 첫 4 워드 (가상)
(gdb) x/4x 0x200000                   # 같은 위치 물리 (QEMU monitor에서)

주소 변환 예제

palloc이 물리 프레임 0x400000 (4 MB)을 할당했다면:

커널 VA = ptov(0x400000) = 0x400000 + 0x8004000000 = 0x8004400000
물리 PA = vtop(0x8004400000) = 0x8004400000 - 0x8004000000 = 0x400000
