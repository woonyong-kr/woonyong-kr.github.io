세마포어 메커니즘 (Semaphore Mechanism)

세마포어 메커니즘 (Semaphore Mechanism)

확인 범위: 이 문서는 세마포어의 일반 원리와 선택 기준을 설명하고 PintOS·Linux·QEMU·futex 사례를 구현 관점에서 비교하지만, 제시된 코드 좌표·구조체 크기·동작 순서·사용 빈도·타이밍 및 성능 관련 판단은 특정 소스 버전이나 실제 실행 기록으로 검증한 결과로 간주하지 않는다. 이러한 구현별 세부 사항과 측정값은 대상 코드, 버전, 실행 환경에서 별도로 확인해야 한다.

세마포어는 정수 값과 대기 큐로 “지금 지나가도 되는 스레드 수”를 표현한다. down(P)은 자리가 생길 때까지 기다리고, up(V)은 값을 늘린 뒤 대기 스레드 하나를 깨운다.

왜 정수 하나로 기다림을 표현하나

공유 자원에는 동시에 들어갈 수 있는 자리 수가 있다. 임계 영역처럼 한 자리뿐인 자원도 있고, 버퍼 슬롯처럼 여러 스레드가 나눠 쓸 수 있는 자원도 있다. 세마포어(Semaphore)는 이 자리 수를 정수 value로 표현하고, 자리가 없을 때 기다릴 스레드를 waiters 리스트에 보관한다.

sema_down()은 자리가 생길 때까지 기다린 뒤 value를 1 줄인다. sema_up()은 value를 1 늘리고, 기다리던 스레드가 있으면 하나를 READY로 깨운다. 이 두 연산 덕분에 세마포어 하나로 상호 배제와 순서 동기화를 모두 만들 수 있다. PintOS의 lock과 condition variable도 결국 이 세마포어 위에 얹힌 구조다.

세마포어의 두 형태

Dijkstra(1965)가 제안한 세마포어는 두 종류로 구분된다:

종류초기값용도
Binary semaphore1상호 배제 (mutex) — 한 번에 하나의 스레드만 임계 영역 진입
Counting semaphoreN (≥1)자원 풀 관리 — 동시 접근 가능 수 제한

원자성 보장 방법은 구현마다 다르다. 단일 CPU 시스템에서는 인터럽트 비활성화, 멀티코어에서는 spinlock + 인터럽트 비활성화 조합을 쓴다.

실제 OS (Linux)

Linux 커널은 struct semaphore (include/linux/semaphore.h)를 제공하지만, 대부분의 상호 배제에는 더 가벼운 mutex를 권장한다. Linux 세마포어의 down()은 raw_spinlock으로 count를 보호하고, count가 0이면 태스크를 TASK_UNINTERRUPTIBLE 상태로 만들어 wait list에 넣는다. up()은 wait list에서 첫 태스크를 꺼내 wake_up_process()를 호출한다.

PintOS 세마포어는 인터럽트 비활성화로 원자성을 확보한다 (단일 CPU 전제).

세마포어를 기반으로 한 상위 추상화

PintOS에서 Lock과 Condition Variable은 세마포어 위에 구현된다:

Lock = struct semaphore (초기값 1) + holder 추적
       lock_acquire()  → sema_down(&lock->semaphore)
       lock_release()  → sema_up(&lock->semaphore)

Condition Variable = list of private semaphores
       cond_wait()    → private sema 생성, sema_down()
       cond_signal()  → sema_up() on first waiter's sema

세마포어 메커니즘 값

항목값
struct semaphore 크기8 bytes (value: 4, padding: 4) + list 구조 (16 bytes) = ~24 bytes
sema_down 인터럽트 비활성화 구간while 루프 전체 + value 감소
sema_up 인터럽트 비활성화 구간list_sort + unblock + value 증가
Lock의 semaphore 초기값1 (binary)
Condition의 private semaphore 초기값0 (signal 전까지 블록)

QEMU 에뮬레이션

QEMU는 세마포어를 전혀 인식하지 않는다 — struct semaphore는 guest memory에 있는 일반 데이터일 뿐이다. QEMU가 간접적으로 관여하는 지점:

  1. intr_disable()의 실체: PintOS에서 intr_disable()은 cli 명령어를 실행한다. QEMU TCG가 이를 번역하면 CPUX86State.eflags에서 IF(Interrupt Flag) 비트를 clear한다. IF=0이면 QEMU는 cpu_interrupt()로 타이머 인터럽트를 주입하지 않는다.
  2. 타이머 인터럽트와 선점: sema_up()이 check_preemption()을 호출하고, 이것이 thread_yield()로 이어지면 schedule()이 호출된다. 이 과정에서 intr_set_level()이 IF를 다시 켜는 순간, QEMU가 pending interrupt를 주입할 수 있다.
  3. 단일 CPU 보장: PintOS는 QEMU -smp 1 (단일 CPU)로 실행되므로, intr_disable()만으로 원자성이 보장된다. 만약 -smp 2면 다른 vCPU가 동시에 같은 메모리를 접근할 수 있어, spinlock이 필요해진다.

Linux futex 비교

Linux 사용자 공간에서 가장 많이 쓰는 동기화 기본 단위는 futex(Fast Userspace muTEX)다. 커널 세마포어와 비교:

futex의 핵심 아이디어: contention이 없으면 syscall 없이 atomic 연산만으로 acquire/release. contention이 있을 때만 futex(FUTEX_WAIT) syscall로 커널에 진입해 sleep.

        T->>S: value-- (즉시 획득)
        T->>IF: sti (intr_set_level)

    else value == 0
        T->>S: waiters에 삽입
        T->>T: thread_block() → BLOCKED
        Note over T: schedule() → 다른 스레드로 전환
        Note over T: IF는 다음 스레드가 복원
        Note over T: ⋯ (대기) ⋯
        Note over W: sema_up() → thread_unblock(A)
        T->>T: 깨어남 → while 재검사
        T->>S: value--
        T->>IF: sti (intr_set_level)
    end

핵심: thread_block() 후 IF=0인 채로 schedule()이 실행되지만, 새로 선택된 스레드의 intr_set_level()이 IF를 복원한다. BLOCKED 상태에서는 인터럽트가 비활성화된 채로 멈추는 것이 아니라, CPU가 다른 스레드를 실행하므로 시스템 전체가 멈추지 않는다.

binary semaphore(초기값 1)은 Lock으로 감싸서 쓰고, signaling semaphore(초기값 0)는 이벤트 대기에 직접 쓴다. PintOS에서 초기값 0 세마포어가 더 빈번하게 사용된다.
