주소 변환과 메모리

주소 변환과 메모리

확인 범위: 이 문서는 주소 변환의 일반 원리와 Linux·Windows·PintOS·QEMU의 구조 및 선택 기준을 설명하며, 포함된 코드 좌표·예제·GDB 스크립트·관찰 시나리오는 특정 구현을 확인하기 위한 절차다. 실제 코드의 일치 여부, 버전별 동작, 실행 결과와 성능에 관한 판단은 해당 환경에서 별도로 검증해야 한다.

한 줄 요약: 가상 주소 0x8048123은 곧장 RAM 바이트가 아니라, CR3가 가리키는 4단계 page table walk(PML4→PDPT→PD→PT)로 물리 프레임을 찾아야 실제 바이트로 이어진다.

주소 변환과 메모리 차이

프로그램이 0x8048123을 읽을 때, 그 숫자는 곧바로 RAM 바이트를 가리키지 않는다. 주소는 데이터를 찾기 위한 숫자이고, 그 숫자가 실제 바이트로 이어지려면 주소 변환(address translation)이 필요하다. 가상 메모리는 프로세스마다 독립된 연속 주소 공간을 보여 주면서, 실제 바이트는 물리 프레임에 흩어져 있도록 한다. page table이 가상 페이지를 물리 프레임으로 연결하는 사전 역할을 한다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 CPU가 가상 주소를 물리 주소로 변환하려면 4단계 page table walk를 거친다. 이때 CR3 레지스터는 최상위 테이블인 PML4의 물리 주소를 가리킨다. CPU는 가상 주소의 48비트를 다섯 필드로 나누어 각 단계에서 참조할 항목과 페이지 내부 위치를 찾는다.

 63    48 47    39 38    30 29    21 20    12 11       0
+--------+---------+---------+---------+---------+----------+
| sign   | PML4    | PDPT    | PD      | PT      | Offset   |
| extend | index   | index   | index   | index   |          |
| 16 bit | 9 bit   | 9 bit   | 9 bit   | 9 bit   | 12 bit   |
+--------+---------+---------+---------+---------+----------+

각 단계에서 9비트 index로 512-entry 테이블을 조회하고, 마지막 12비트는 4KB 페이지 안의 offset이다. MMU가 하드웨어에서 이 walk을 수행하며, TLB 캐시가 최근 변환 결과를 저장해 속도를 높인다.

핵심 하드웨어 동작:

  • present bit (PTE_P): 이 비트가 꺼져 있으면 page fault exception(#PF, 예외 벡터 14 = 0x0E)을 발생시키고, CR2에 fault address를 기록한다. 이를 INT 14라고 쓰면 소프트웨어 인터럽트 0x14와 혼동된다.
  • writable bit (PTE_W): read-only 페이지에 write하면 protection fault를 발생시킨다.
  • user bit (PTE_U): 꺼져 있으면 CPL 3(유저 모드)에서 접근 시 fault를 발생시킨다.
flowchart LR
    VA["VA 48-bit"] --> PML4["PML4\n[bits 47:39]"]
    PML4 --> PDPT["PDPT\n[bits 38:30]"]
    PDPT --> PD["PD\n[bits 29:21]"]
    PD --> PT["PT\n[bits 20:12]"]
    PT --> Frame["Frame base"]
    Frame --> PA["PA = Frame base\n+ offset[11:0]"]
    CR3["CR3 register"] -.-> PML4

실제 OS (Linux/Windows)

Linux와 Windows 모두 demand paging, COW(copy-on-write), mmap/section, swap/pagefile을 사용하며, 주소 변환은 단순 VA→PA 매핑 이상의 역할을 한다.

기능LinuxWindows
page table 구조5-level (PGD→P4D→PUD→PMD→PTE)4-level (PXE→PPE→PDE→PTE)
대형 페이지2MB (huge page), 1GB2MB (large page)
파일 캐시page cache = VM 통합section object + cache manager
swapswap partition / swapfilepagefile.sys
ASLRmmap randomization이미지/스택/힙 randomization
kernel mappingdirect map (physmem → 고정 offset)HAL 관리

실제 OS에서는 page table이 프로세스 격리, 파일 캐시, 보안(NX bit, SMEP/SMAP), NUMA 최적화까지 담당한다. PintOS에서는 이 복잡도를 교육 목적으로 축소한다.

PintOS 구현

PintOS는 x86-64 4단계 walk을 그대로 사용하되, 정책을 단순화한다. page fault가 발생하면 SPT(Supplemental Page Table)에서 원본 정보를 찾고, frame을 할당하고, 내용을 채운 뒤 PTE를 설치한다.

주소 변환의 핵심 흐름:

sequenceDiagram
    participant U as User Code
    participant CPU as CPU/MMU
    participant PF as page_fault()
    participant VM as vm_try_handle_fault()
    participant SPT as SPT lookup
    participant F as Frame alloc
    participant MMU as pml4_set_page()

    U->>CPU: load [0x8048123]
    CPU->>CPU: walk PML4→PDPT→PD→PT
    alt PTE present
        CPU->>U: return data
    else PTE not-present
        CPU->>PF: #PF, CR2=0x8048123
        PF->>VM: vm_try_handle_fault(addr)
        VM->>SPT: spt_find_page(0x8048000)
        SPT-->>VM: struct page *p
        VM->>F: palloc_get_page(PAL_USER)
        F-->>VM: frame (kva)
        VM->>MMU: pml4_set_page(pml4, upage, kpage, rw)
        Note over MMU: *pte = vtop(kpage) | PTE_P | PTE_W | PTE_U
        VM->>U: return, retry instruction
    end

커널이 유저 주소의 바이트를 읽을 때: pml4_get_page()는 유저 VA를 PML4 walk한 뒤, PTE에서 꺼낸 frame의 guest PA에 KERN_BASE를 더해 kernel VA로 변환한다.

이 계산은 guest PA → kernel VA 변환으로, 커널이 같은 물리 frame을 다른 가상 주소로 접근하는 방법이다.

PTE 설치: pml4_set_page()는 kernel VA(kpage)를 guest PA로 변환한 뒤 permission bit와 함께 PTE에 기록한다.

QEMU 에뮬레이션

QEMU에서는 주소가 세 층으로 나뉜다.

층이름예시관리 주체
1Guest Virtual Address (GVA)0x8048123PintOS process + page table
2Guest Physical Address (GPA)0x12345123PintOS가 물리 메모리라고 믿는 주소
3Host Virtual Address (HVA)RAMBlock.host + offsetQEMU process

PintOS의 page table은 guest OS 자료구조다. QEMU는 guest CPU가 메모리를 읽고 쓸 때 MMU 동작(4단계 walk, present bit 검사, protection fault)을 소프트웨어로 재현한다. QEMU 자체는 page table 정책을 결정하지 않는다.

guest physical address가 RAM 영역이면 memcpy로 RAMBlock.host + offset에 접근하고, MMIO 영역이면 memory_region_dispatch_read/write()로 장치 핸들러에 전달한다.

주소 변환과 메모리 값 추적

예제 1: VA → PA 변환

Virtual Address = 0x0000_0000_8048_0123

비트 분해 (48비트 canonical):
  PML4 index  = bits[47:39] = 0x000 = 0
  PDPT index  = bits[38:30] = 0x000 = 0
  PD index    = bits[29:21] = 0x040 = 64
  PT index    = bits[20:12] = 0x048 = 72
  Page offset = bits[11:0]  = 0x123

Page table이 VA page 0x8048000을 frame 0x12345000에 연결하면:
  Physical Address = 0x12345000 + 0x123 = 0x12345123

예제 2: PintOS 커널 VA ↔ PA 변환

KERN_BASE = 0x80_0400_0000

kpage (kernel VA) = 0x80_0523_4000
guest PA = vtop(kpage) = 0x80_0523_4000 - 0x80_0400_0000 = 0x0123_4000

ptov(0x0123_4000) = 0x0123_4000 + 0x80_0400_0000 = 0x80_0523_4000

예제 3: PTE 값 계산

vtop(kpage) = 0x01234000
PTE_P = 0x1, PTE_W = 0x2, PTE_U = 0x4

PTE 값 (rw=true) = 0x01234000 | 0x1 | 0x2 | 0x4
                  = 0x01234007

PTE에서 frame base 추출:
  PTE_ADDR(0x01234007) = 0x01234007 & ~0xFFF = 0x01234000

관찰 시나리오

시나리오 1: demand paging으로 PTE가 설치되는 순간

args-single one 테스트를 실행하면 ELF PT_LOAD 세그먼트의 첫 page fault에서 PTE가 not-present → present로 바뀐다.

  1. watch-fault-to-pte 정의 후 args-single one 실행
  2. 첫 #PF addr=0x400000에서 멈춤 → walk-va 0x400000 실행하면 PT 엔트리가 0x0(not-present)
  3. pml4_set_page breakpoint에서 upage=0x400000, frame_pa 확인
  4. 이후 같은 VA에 대해 walk-va 0x400000 재실행하면 PTE에 present|writable|user 비트가 켜져 있음

이 시나리오로 lazy loading → page fault → frame 할당 → PTE 설치 → instruction retry 전체 경로를 한 step씩 확인할 수 있다.

시나리오 2: fork 후 부모/자식 CR3와 PTE 비교

fork-once 테스트에서 fork 직후:

  1. watch-cr3-switch 정의, fork 실행
  2. 부모의 CR3와 자식의 CR3가 다른 PA를 가리키는지 확인
  3. 같은 user VA(예: 0x400000)에 대해 부모와 자식 각각 walk-va 실행
  4. COW가 아닌 경우 서로 다른 frame PA, COW인 경우 같은 frame PA + writable bit off 확인
