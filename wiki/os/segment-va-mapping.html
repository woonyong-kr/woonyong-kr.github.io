ELF Segment에서 가상 주소 매핑

ELF Segment에서 가상 주소 매핑

확인 범위: 이 문서는 ELF PT_LOAD segment의 가상 주소 매핑 원리와 Linux·PintOS·QEMU에서의 처리 방식을 개념적으로 설명하고, 제시된 계산 예제로 페이지 분할과 zero-fill 방식을 보여준다. 실제 구현의 정확성이나 코드 좌표·버전별 동작·실행 결과·성능은 검증한 결과가 아니므로, 해당 판단에는 대상 소스와 버전을 확인하고 실행 기록 및 측정 자료를 별도로 검토해야 한다.

한 줄 요약: ELF PT_LOAD segment의 p_vaddr·p_offset·p_filesz·p_memsz로 디스크 바이트를 가상 주소 공간에 매핑하는 로더 동작.

ELF Segment에서 가상 주소 매핑 상태

ELF 실행 파일의 PT_LOAD segment는 디스크 상의 바이트 범위를 프로세스 가상 주소 공간의 특정 영역에 매핑하는 지시서다. OS 로더는 Program Header의 p_vaddr, p_offset, p_filesz, p_memsz 네 필드를 읽어 “파일의 어디부터 어디까지를 VA 어디에 배치하고, 남는 공간은 0으로 채워라”는 명령을 수행한다.

상세 설명

추상 개념 (ELF 규격)

Program Header 하나가 표현하는 매핑 관계:

파일 offset [p_offset .. p_offset + p_filesz)  →  VA [p_vaddr .. p_vaddr + p_filesz)
VA [p_vaddr + p_filesz .. p_vaddr + p_memsz)   →  zero-fill (BSS)

핵심 불변식:

  • p_offset % PGSIZE == p_vaddr % PGSIZE — 페이지 내 오프셋이 파일과 메모리에서 동일해야 한다.
  • p_memsz >= p_filesz — 메모리 크기가 파일 크기 이상이어야 BSS 영역을 표현할 수 있다.
  • p_vaddr >= PGSIZE — 0번 페이지(NULL 포인터 참조 감지용)는 매핑하지 않는다.

실제 OS (Linux)

Linux load_elf_binary()는 각 PT_LOAD segment에 대해 elf_map() → do_mmap()을 호출한다. 파일의 해당 범위가 VMA(vm_area_struct)로 등록되고, 실제 물리 페이지 할당은 page fault 시점까지 지연된다. BSS 영역(p_filesz 이후)은 anonymous mapping으로 처리된다.

일반적인 ELF 바이너리는 PT_LOAD가 2개:

Segment내용권한예시 VA
TEXT.text + .rodataR-X0x400000
DATA.data + .bssRW-0x600000

PintOS 구현

PintOS는 load_loadable_segment() → load_segment()로 2단계 처리한다.

1단계: 바이트 분할 계산 (load_loadable_segment)

read_bytes는 파일에서 읽을 총 바이트, zero_bytes는 0으로 채울 바이트다. 둘의 합은 항상 PGSIZE의 배수가 된다.

2단계: 페이지 단위 등록 (load_segment)

VM 모드에서는 실제 적재 대신 SPT에 UNINIT page를 등록한다. 각 페이지의 aux에 (file, ofs, read_bytes, zero_bytes)를 담아두고, page fault 시 lazy_load_segment()가 실제 파일 I/O를 수행한다.

검증 (validate_segment)

QEMU 에뮬레이션

QEMU 자체는 ELF 적재에 관여하지 않는다 — ELF 파싱과 매핑은 전적으로 guest OS(PintOS)의 일이다. QEMU는 guest가 PML4 테이블에 새 매핑을 기록하면 그 매핑에 따라 guest virtual → guest physical 변환을 수행할 뿐이다.

GDB로 ELF 적재 과정을 디버깅할 때 유용한 명령:

(gdb) x/8x $cr3           # PML4 테이블 확인
(gdb) info proc mappings   # (Linux guest) VMA 목록
(gdb) x/32bx 0x400000     # 적재된 .text 첫 바이트 확인

load_segment() 페이지 분할 루프 상세

VM 모드의 load_segment()는 read_bytes + zero_bytes를 PGSIZE 단위로 소비하는 while 루프다:

핵심 관찰:

  • 매 페이지마다 file_reopen()으로 독립 파일 핸들을 생성한다. 이는 page fault가 비결정적 순서로 발생하므로 공유 file position이 위험하기 때문이다.
  • ofs는 page_read_bytes만큼만 전진한다 — 마지막 페이지에서 page_read_bytes < PGSIZE이면 파일의 남은 부분을 정확히 읽고 나머지를 zero-fill한다.
  • lazy_load_segment()가 호출될 때 aux를 소비하고 free(aux), file_close(aux->file)로 자원을 해제한다.

ELF Segment에서 가상 주소 매핑 값 추적

예제 1: 단일 페이지 (기존)

.data segment가 p_offset=0x3020, p_vaddr=0x804_3020, p_filesz=0x100, p_memsz=0x200일 때:

page_offset = 0x3020 & 0xFFF = 0x020
file_page   = 0x3020 & ~0xFFF = 0x3000
mem_page    = 0x804_3020 & ~0xFFF = 0x804_3000

read_bytes  = 0x020 + 0x100 = 0x120 (288 bytes)
zero_bytes  = ROUND_UP(0x020 + 0x200, 0x1000) - 0x120
            = 0x1000 - 0x120 = 0xEE0 (3808 bytes)

총 = 0x120 + 0xEE0 = 0x1000 = 4096 = 1 page

하나의 4 KB 페이지에 파일 데이터 288 B + 제로 3808 B가 담긴다.

예제 2: 멀티 페이지 (.text segment)

.text segment: p_offset=0x1000, p_vaddr=0x400000, p_filesz=0x2800, p_memsz=0x2800 (BSS 없음)

page_offset = 0x400000 & 0xFFF = 0x000  (페이지 정렬됨)
file_page   = 0x1000
mem_page    = 0x400000

read_bytes  = 0x000 + 0x2800 = 0x2800 (10240 bytes)
zero_bytes  = ROUND_UP(0x000 + 0x2800, 0x1000) - 0x2800
            = 0x3000 - 0x2800 = 0x800 (2048 bytes)

총 = 0x2800 + 0x800 = 0x3000 = 12288 = 3 pages

load_segment 루프 3회 반복:

반복upageofspage_read_bytespage_zero_bytes
10x4000000x10004096 (PGSIZE)0
20x4010000x20004096 (PGSIZE)0
30x4020000x300020482048

3번째 페이지의 앞 2048 B는 파일 데이터, 뒤 2048 B는 0으로 채워진다.

예제 3: BSS가 큰 .data segment

p_offset=0x4000, p_vaddr=0x600000, p_filesz=0x100, p_memsz=0x3000

page_offset = 0
read_bytes  = 0 + 0x100 = 256
zero_bytes  = ROUND_UP(0 + 0x3000, 0x1000) - 256 = 0x3000 - 0x100 = 12032

총 = 256 + 12032 = 12288 = 3 pages
반복page_read_bytespage_zero_bytes내용
12563840초기화된 .data 256 B + BSS 3840 B
204096순수 BSS (전부 0)

순서도

flowchart TD
    A[ELF header: e_phoff, e_phnum] --> B[load_program_headers loop]
    B --> C{phdr.p_type?}
    C -->|PT_LOAD| D[validate_segment]
    C -->|기타| B
    D -->|통과| E[load_loadable_segment]
    D -->|실패| F[return false]
    E --> G["바이트 분할\nread_bytes / zero_bytes 계산"]
    G --> H[load_segment]
    H --> I{"VM 모드?"}
    I -->|Yes| J["vm_alloc_page_with_initializer\n→ SPT에 UNINIT 등록"]
    I -->|No| K["palloc + file_read\n→ 즉시 적재"]
    J --> L[page fault 시 lazy_load_segment]
