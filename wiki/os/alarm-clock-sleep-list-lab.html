Alarm Clock 실험: `sleep_list`가 스레드를 깨우는 순간

Alarm Clock 실험: sleep_list가 스레드를 깨우는 순간

확인 범위: 이 문서는 대기 스레드를 실행 후보에서 제외했다가 사건이 발생하면 다시 깨우는 일반 원리와 PintOS·QEMU의 역할 구분을 설명하며, 제시된 코드 흐름과 값 추적은 입력에 명시된 특정 저장소 구현을 전제로 한다. 실제 동작 시점과 대기 시간, 인터럽트 안전성, 성능에 관한 판단은 해당 코드·버전의 실행 기록과 GDB 추적 또는 측정으로 별도 검증해야 한다.

timer_sleep()은 기다리는 동안 무엇을 하는가

timer_sleep(10)을 다음처럼 구현하면, 스레드는 10 tick이 지날 때까지 CPU를 사용하지 않는 것이 아니다.

thread_yield()를 호출한 스레드는 계속 ready queue로 돌아온다. 다시 CPU를 받을 때마다 시간이 지났는지 확인하므로, 잠든 상태라기보다 깨어서 기다리는 상태에 가깝다.

Alarm Clock은 이 스레드를 실행 후보에서 빼 두었다가 시간이 되면 다시 실행 가능 상태로 바꾼다. 현재 tick이 wake_tick에 도달하면 BLOCKED 스레드를 READY로 되돌리는 방식이다. lock, semaphore, condition variable도 구체적인 조건은 다르지만, 지금 실행할 수 없는 스레드를 큐에 넣고 조건이 맞을 때 깨운다는 모델을 공유한다.

ticks, wake_tick, sleep_list

이 코드베이스의 PintOS alarm clock은 세 요소로 연결된다.

요소의미대표 코드
ticks부팅 이후 지난 전역 타이머 tickdevices/timer.c의 static int64_t ticks
wake_tick이 스레드를 깨워야 하는 절대 tickstruct thread.wake_tick
sleep_list아직 깨우면 안 되는 BLOCKED 스레드 목록threads/thread.c의 static struct list sleep_list

스레드는 요청한 상대 시간을 절대 시간으로 바꿔 저장한다.

이 스레드는 wake_tick=110을 자기 struct thread에 기록하고 BLOCKED 상태가 된다. 이후 timer interrupt가 들어올 때마다 PintOS는 sleep_list의 맨 앞을 확인하고, 깨울 시간이 된 스레드만 READY로 되돌린다.

세 스레드가 다음 순서로 잠드는 장면을 생각해 볼 수 있다.

sleep_list를 wake_tick 오름차순으로 유지하면 목록은 다음 순서가 된다.

맨 앞 스레드조차 깨울 시간이 되지 않았다면 뒤의 스레드는 더 늦게 깨야 한다. 따라서 매 tick마다 전체 목록을 훑지 않고 검사를 멈출 수 있다.

잠들고 깨어나는 코드 흐름

이 코드베이스의 alarm clock 구현은 다음 경로를 따른다.

thread_sleep()은 인터럽트를 끈 뒤 sleep_list 삽입과 thread_block()을 한 덩어리로 처리한다. 목록에 넣기 전에 timer interrupt가 끼어들어 깨울 시간을 놓치는 상황을 막기 위한 구조다. thread_awake()는 timer interrupt 문맥에서 호출되므로 이미 인터럽트가 꺼진 상태라고 가정한다.

관련 코드는 다음 위치에서 이어진다.

PintOS timer 설정:

  • PintOS 저장소 상대 경로 pintos/include/devices/timer.h
    • #define TIMER_FREQ 100
  • PintOS 저장소 상대 경로 pintos/devices/timer.c
    • timer_init()에서 PIT count를 계산하고 I/O port 0x43, 0x40에 쓴다.
    • intr_register_ext(0x20, timer_interrupt, "8254 Timer")로 timer interrupt handler를 등록한다.
    • timer_sleep()은 busy-wait 루프 대신 thread_sleep(start + ticks)를 호출한다.
    • timer_interrupt()는 ticks++, thread_tick(), thread_awake(ticks) 순서로 실행된다.

PintOS thread 상태 전환:

  • PintOS 저장소 상대 경로 pintos/include/threads/thread.h
    • struct thread에 int64_t wake_tick이 있다.
  • PintOS 저장소 상대 경로 pintos/threads/thread.c
    • thread_init()에서 sleep_list를 초기화한다.
    • thread_sleep()이 현재 스레드를 sleep_list에 정렬 삽입하고 thread_block()으로 BLOCKED 상태로 만든다.
    • cmp_thread_ticks()가 wake_tick이 작은 스레드를 앞에 둔다.
    • thread_awake()가 wake_tick <= global_ticks인 스레드를 thread_unblock()한다.

인터럽트 문맥의 안전장치:

  • PintOS 저장소 상대 경로 pintos/threads/interrupt.c
    • 외부 인터럽트는 인터럽트가 꺼진 상태에서 처리된다.
    • 외부 인터럽트 핸들러는 sleep할 수 없고, 필요하면 intr_yield_on_return()으로 나중에 양보를 예약한다.

QEMU와 PintOS의 역할

QEMU는 PintOS의 sleep_list를 알지 못한다. PintOS가 사용하는 8254 PIT와 interrupt controller 같은 하드웨어를 흉내 내어 guest CPU에 타이머 사건을 전달한다.

이 저장소의 QEMU 코드에서 확인한 단서는 다음과 같다.

  • hw/isa/piix.c
    • i8254_pit_init(isa_bus, 0x40, 0, NULL)로 PIT를 ISA IRQ 0에 연결한다.
  • include/hw/timer/i8254.h
    • i8254_pit_init()이 isa-pit 장치를 만들고 GPIO 출력을 IRQ에 연결한다.
  • hw/timer/i8254.c
    • channel 0에 timer_new_ns(QEMU_CLOCK_VIRTUAL, pit_irq_timer, s)를 만든다.
    • pit_irq_timer_update()가 qemu_set_irq(s->irq, irq_level)로 PIT 출력선을 바꾼다.

두 구성 요소의 경계는 다음과 같다.

실제 OS도 기다리는 task를 실행 가능 상태에서 제외하고 사건이 생기면 다시 runnable로 만든다는 큰 모델은 비슷하다. Linux에서는 sleep, timer, I/O wait 뒤에 timer 만료나 장치 완료가 깨우는 사건이 될 수 있다. 다만 고해상도 타이머, tickless 정책, per-CPU run queue와 여러 task state를 함께 다루므로 PintOS보다 복잡하다. Windows도 thread wait state, dispatcher object, waitable timer를 통해 실행할 수 없는 스레드와 깨우는 사건을 분리한다.

구분실제 OSPintOSQEMU
기다리는 스레드다양한 wait state와 timer 구조sleep_list의 BLOCKED thread모름
깨우는 기준timer 만료, I/O 완료, signal 등wake_tick <= ticks가상 PIT/IRQ 상태 변화
시간 정밀도고해상도 타이머와 tickless 가능TIMER_FREQ=100, 1 tick = 10mshost timer로 guest 장치 동작 에뮬레이션

tick과 스레드 주소 추적

TIMER_FREQ=100이면 1초에 100 tick이다.

따라서 timer_sleep(25)는 대략 250ms를 기다린다는 뜻이다.

스레드 구조체 주소를 다음과 같이 놓고 내부 위치도 추적할 수 있다.

sleep_list가 직접 보관하는 값은 cur가 아니라 &cur->elem이다. GDB에서 목록 원소를 확인할 때는 PintOS intrusive list 실험: list elem 주소에서 struct thread 복원하기에서 다룬 것처럼 list_entry(e, struct thread, elem)로 struct thread *를 복원해야 한다.

GDB에서 깨우는 순간 확인하기

PintOS GDB에서는 잠드는 경로와 깨우는 경로에 breakpoint를 나누어 둔다.

각 지점에서 다음 값을 확인할 수 있다.

thread_sleep()에서는 현재 스레드가 sleep_list에 들어간 직후와 thread_block() 호출 직전을 살핀다.

thread_awake()에서는 global_ticks와 맨 앞 스레드의 wake_tick을 비교한다.

sleep_list는 thread.c의 static 전역이므로 파일이나 심볼 문맥에 따라 GDB에서 보이지 않을 수 있다. 이때는 thread_awake나 thread_sleep에 breakpoint를 걸고 해당 함수 안에서 확인한다.

thread_awake()는 timer interrupt 문맥에서 실행된다. 이 함수 안에서 thread_yield()처럼 sleep이나 스케줄을 직접 일으키는 함수를 함부로 호출해서는 안 된다. 외부 인터럽트 핸들러에서 양보가 필요하다면 intr_yield_on_return()으로 나중의 양보를 예약하는 흐름과 연결해 봐야 한다.

Alarm Clock의 변화는 반복해서 시간을 확인하던 스레드를 BLOCKED 상태로 옮기는 데 있다. PintOS는 wake_tick을 절대 tick으로 저장하고 sleep_list를 정렬한다. timer interrupt가 발생하면 목록 앞에서 wake_tick <= ticks인 스레드를 깨운다. QEMU는 PIT와 IRQ를 에뮬레이션할 뿐, 어떤 스레드를 깨울지는 결정하지 않는다.
