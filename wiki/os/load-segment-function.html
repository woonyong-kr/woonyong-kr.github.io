ELF 세그먼트 적재 흐름

한 줄 요약: ELF를 메모리에 올리는 load()→load_segment()→setup_stack() 세 함수의 역할.

ELF 세그먼트 적재 흐름 구조

ELF 실행 파일을 메모리에 올리는 과정은 load() → load_segment() → setup_stack()의 세 함수가 담당한다. load()가 ELF 헤더를 파싱하고 PT_LOAD 세그먼트마다 load_segment()를 호출하며, 마지막에 setup_stack()으로 유저 스택을 준비한다. Project 2에서는 즉시 적재(eager loading), Project 3에서는 lazy loading으로 구현이 바뀐다.

상세 설명

추상 개념 (ELF 적재의 일반 규칙)

ELF 실행 파일은 여러 segment로 구성되며, 각 PT_LOAD segment가 “파일의 어느 바이트를 메모리 어디에 올릴지”를 지정한다. OS loader의 책임:

  1. ELF header에서 e_phoff, e_phnum을 읽어 program header 위치 파악
  2. 각 program header의 p_type == PT_LOAD인 것만 처리
  3. p_offset(파일 내 위치)에서 p_filesz바이트를 읽어 p_vaddr(가상 주소)에 배치
  4. p_memsz - p_filesz 만큼 0으로 채움 (BSS 영역)
  5. p_flags의 PF_W 비트로 writable 여부 결정

실제 OS (Linux)

Linux의 load_elf_binary()(fs/binfmt_elf.c)는 각 PT_LOAD segment를 elf_map() → do_mmap()으로 매핑한다. 즉시 파일 내용을 읽지 않고 VMA(Virtual Memory Area)만 등록하여, page fault 시 파일에서 읽어오는 demand paging 방식이다.

setup_stack()

버전동작
Project 2palloc_get_page(PAL_USER | PAL_ZERO) → install_page(USER_STACK - PGSIZE, kpage, true)
Project 3vm_alloc_page(VM_ANON | VM_MARKER_0, stack_bottom, true) → vm_claim_page(stack_bottom)

Project 3에서 VM_MARKER_0은 이 page가 스택임을 표시한다. 이후 stack growth에서 이 마커를 확인한다.

Lazy loading의 page fault 처리에서 lazy_load_segment(page, aux)는 file_read_at(aux->file, kva, aux->read_bytes, aux->ofs)로 파일 바이트를 채운 뒤 memset(kva + read_bytes, 0, zero_bytes)로 나머지 영역을 0으로 채운다.

PT_LOAD segment 예시 (args-single 테스트):

segmentp_offsetp_vaddrp_fileszp_memszp_flags
.text0x00x4000000x2A000x2A00R-X
.data0x30000x4030000x1000x200RW-

.data segment: read_bytes = page_offset + p_filesz = 0x100, zero_bytes = ROUND_UP(0x200, 4096) - 0x100 = 0xF00. 즉 파일에서 256바이트를 읽고 나머지 3840바이트를 0으로 채운다.
