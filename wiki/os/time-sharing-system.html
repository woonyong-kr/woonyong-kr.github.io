시분할 시스템

한 줄 요약: 시분할 시스템(Time-sharing System)은 타이머 인터럽트로 CPU 시간을 잘게 쪼개어 여러 프로세스가 동시에 실행되는 것처럼 보이게 만드는 운영체제 구조다.

배치 처리에서 시분할로

CPU가 한 번에 하나의 명령어만 실행하는 환경에서 여러 사용자가 프로그램을 실행한다고 생각해 보자. 초기 컴퓨터의 배치 처리(Batch Processing)에서는 하나의 프로그램이 끝날 때까지 그 프로그램이 CPU를 독점했다. 실행 중인 프로그램이 I/O를 기다리면 CPU도 놀았고, 사용자가 여러 명이면 나머지 사용자는 앞선 작업이 끝날 때까지 기다려야 했다.

시분할(Time-sharing)은 CPU 시간을 짧은 조각인 타임 슬라이스(Time Slice)로 나누고 여러 프로세스에 차례로 배분한다. 각 조각이 충분히 짧으면 실제로는 프로세스가 번갈아 실행되더라도 사용자는 자신의 프로그램들이 동시에 실행되는 것처럼 느낀다.

은행 창구에 비유하면, 배치 처리는 한 고객의 업무가 완전히 끝나야 다음 고객을 부르는 방식이다. 시분할은 “5분마다 교대”라는 규칙을 두는 방식과 같다. 여러 고객을 실제로 동시에 처리하지는 않지만, 빠르게 교대하면 모두가 함께 서비스를 받는 것처럼 느낄 수 있다.

이 문서에서는 선점형 멀티태스킹(Preemptive Multitasking)을 시분할의 동작 방식과 연결해 설명한다. 스케줄러, 컨텍스트 스위치, 타이머 인터럽트는 여기서 CPU 사용 순서를 바꾸고 다음 실행 대상을 선택하는 과정에 관여한다.

시분할 시스템의 세 요소

시분할 시스템의 동작은 타이머 인터럽트, 타임 슬라이스, 선점으로 나누어 볼 수 있다.

  1. 타이머 인터럽트 — 하드웨어 타이머(PIT, Programmable Interval Timer)가 일정 주기로 CPU에 인터럽트를 건다. 현재 실행 중인 프로세스가 무엇이든 CPU는 인터럽트 핸들러로 점프한다.
  2. 타임 슬라이스 — 한 프로세스가 연속으로 CPU를 사용할 수 있는 최대 틱 수다. 이 수를 넘기면 강제로 CPU를 양보한다.
  3. 선점(Preemption) — 프로세스가 자발적으로 CPU를 놓지 않아도 OS가 타이머 인터럽트를 이용해 CPU를 빼앗는 방식이다.

동작 순서

1. 하드웨어 타이머(PIT)가 매 틱마다 인터럽트 발생
2. CPU가 현재 실행을 멈추고 timer_interrupt() 진입
3. thread_tick()에서 현재 스레드의 연속 실행 틱 수 증가
4. 틱 수가 TIME_SLICE 이상이면 → intr_yield_on_return() 호출
5. 인터럽트 핸들러 복귀 시 thread_yield() 실행
6. 현재 스레드는 ready_list 뒤로 가고, 다음 스레드가 CPU를 받는다

이 순서에서는 타이머 인터럽트가 실행 흐름을 끊는 계기가 된다. 이후 연속 실행 틱 수를 확인하고, 타임 슬라이스를 모두 사용했다면 현재 스레드를 양보시켜 다음 스레드에 CPU를 넘긴다.

실제 OS와 PintOS의 차이

Linux는 CFS(Completely Fair Scheduler)를 사용한다. 고정 타임 슬라이스 대신 가상 런타임(vruntime)을 기준으로 가장 적게 실행된 프로세스를 고른다. 타이머 인터럽트 주기(HZ, 보통 250 또는 1000)마다 스케줄링을 판단한다.

PintOS의 구조는 더 단순하다. 고정 타임 슬라이스 4틱을 사용하며 라운드 로빈 또는 MLFQS를 지원한다. 타이머 주파수는 TIMER_FREQ이고 기본값은 100Hz, 즉 1초에 100틱이다. 이 설정에서는 한 틱이 10ms이므로 한 스레드가 최대 40ms(4틱 × 10ms/틱) 동안 CPU를 연속으로 사용할 수 있다.

PintOS 코드에서 보는 시분할

타임 슬라이스 정의

TIME_SLICE는 각 스레드가 연속으로 사용할 수 있는 타이머 틱 수를 정한다. 이 값을 늘리면 컨텍스트 스위치가 줄어드는 대신 응답성이 떨어지고, 줄이면 그 반대가 된다.

선점 판단

thread_tick()은 타이머 인터럽트가 발생할 때마다 호출된다. 이 함수는 thread_ticks를 1만큼 늘린다. 값이 TIME_SLICE인 4 이상이 되면 intr_yield_on_return()을 호출해 인터럽트 핸들러가 복귀할 때 thread_yield()가 실행되도록 예약한다.

타이머 인터럽트 등록

이 코드는 8254 PIT를 TIMER_FREQ Hz로 설정한다. PIT 입력 클럭은 1,193,180Hz다. TIMER_FREQ가 100이면 1,193,180을 100으로 나눈 약 11,932 카운트마다 인터럽트가 발생하며, 시간으로는 10ms마다 한 번이다.

전체 흐름 다이어그램

%% 시분할 시스템 전체 흐름
flowchart LR
  pit["8254 PIT<br/>하드웨어 타이머<br/>10ms마다 IRQ 0 발생"]
  cpu["CPU<br/>IDT 0x20 벡터 진입<br/>현재 실행 흐름 일시 중단"]
  timer_interrupt["timer_interrupt()<br/>devices/timer.c<br/>ticks 증가"]
  thread_tick["thread_tick()<br/>threads/thread.c<br/>thread_ticks 증가"]
  yield_on_return["intr_yield_on_return()<br/>thread_ticks &gt;= TIME_SLICE<br/>복귀 시 양보 예약"]
  thread_yield["thread_yield()<br/>현재 스레드 ready_list 뒤로 이동<br/>다음 스레드로 전환"]
  pit --> cpu
  cpu --> timer_interrupt
  timer_interrupt --> thread_tick
  thread_tick --> yield_on_return
  yield_on_return --> thread_yield

시분할에서 스케줄링으로 이어지는 흐름

시분할 시스템에서는 타이머 인터럽트가 실행 중인 흐름을 주기적으로 중단하고, 타임 슬라이스를 모두 사용했는지 판단한다. PintOS에서는 TIME_SLICE = 4일 때 thread_tick()이 4틱마다 선점 여부를 판단한다. 선점이 필요하면 intr_yield_on_return()이 인터럽트 복귀 시점의 양보를 예약하고, 이후 현재 스레드가 ready_list 뒤로 이동하면서 다음 스레드가 CPU를 받는다.
