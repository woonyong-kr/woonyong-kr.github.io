swapped anonymous page fork snapshot 흐름

한 줄 요약: fork 시 부모 anonymous page가 이미 swap slot에 내려가 있으면 slot 번호만 얕게 복사해서는 안 되고, 자식은 fork 순간의 4096B 스냅샷을 독립으로 가져야 부모 swap-in 후 slot 해제로 인한 오염을 피한다.

swapped anon fork 구조

fork() 시 부모의 anonymous page가 이미 swap slot에 내려가 있다면, 자식은 “fork 순간의 4096B snapshot”을 독립적으로 보유해야 한다. slot 번호만 얕게 복사하면 parent swap-in 후 slot이 해제되어 child가 오염된 데이터를 읽는다. 이 Trace는 swap-out 상태 anonymous page의 fork 복사 흐름과 실패 rollback을 추적한다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

하드웨어는 swap slot이라는 개념을 모른다. MMU가 아는 것은 page table의 present bit뿐이다.

하드웨어가 아는 것하드웨어가 모르는 것
PTE의 present bit = 0 → pf 발생왜 present가 0인지 (eviction? 아직 적재 안 됨?)
CR2에 fault 주소를 기록fault 주소의 backing store가 swap disk인지 file인지
error code에 read/write, user/kernel 표시어떤 process의 어떤 page인지

따라서 swap-out된 page를 fork로 복사하는 것은 순전히 OS 소프트웨어의 책임이다. CPU/MMU는 “이 VA에 present mapping이 없다”만 전달하고, OS가 SPT를 참조해 backing bytes를 찾아야 한다.

실제 OS (Linux/Windows)

항목LinuxWindows
fork 모델copy_mm() → COW + swap entry 복사CreateProcess로 새 주소 공간 생성 (Unix fork 없음)
swap-out page 공유swap entry refcount로 여러 process가 같은 slot 참조 가능pagefile-backed section + VAD로 유사 효과
수명 관리swap_count, page refcount, reverse mappingpagefile reference count, prototype PTE
fork 실패 시dup_mm() 실패 → 부분 복사된 VMA/PTE rollbackNtCreateProcess 내부 cleanup

공통 원칙: backing store를 공유하면 lifetime metadata(refcount)가 필요하고, refcount가 없으면 독립 backing을 만들어야 한다.

PintOS 구현

PintOS W09 코드에서 swap-out된 anonymous page의 fork 복사는 현재 spt_copy_loaded_page()의 한계로 드러난다.

현재 코드의 문제점: spt_copy_loaded_page()는 page->frame == NULL이면 즉시 false를 반환한다.

swap-out된 page는 frame == NULL이므로 이 함수가 실패한다. 이를 해결하려면 swap-out 상태를 별도 분기로 처리해야 한다.

QEMU 에뮬레이션

QEMU는 struct page, SPT, swap slot owner를 전혀 모른다. QEMU 관점에서 보이는 사건은 딱 두 가지다.

QEMU가 보는 것의미
EXCP0E_PAGE + CR2 + error_codechild가 not-present VA를 접근하면 guest에 pf 전달
IDE disk_read/disk_write sector I/OPintOS가 swap slot sector를 읽거나 씀

QEMU에서 “slot 3을 parent가 소유하는가 child가 소유하는가”를 찾으면 안 된다. 그 의미는 PintOS 커널 자료구조 안에 있다.

fork swap snapshot 전체 흐름

sequenceDiagram
    participant P as Parent Process
    participant SPT as supplemental_page_table_copy
    participant SD as Swap Disk
    participant C as Child Process

    Note over P: parent page P at slot 3<br/>frame = NULL, swapped = true

    P->>SPT: fork → SPT copy 시작
    SPT->>SPT: page type == VM_ANON<br/>anon.swapped == true 확인

    alt 전략 A: slot-to-slot 복사
        SPT->>SD: disk_read(slot 3, sectors 24..31) → buffer
        SPT->>SD: bitmap_scan_and_flip → slot 7
        SPT->>SD: disk_write(slot 7, sectors 56..63) ← buffer
        SPT->>C: child page C: swap_slot=7, swapped=true
    else 전략 B: swap-in 후 memcpy
        SPT->>SD: anon_swap_in(parent page) → parent frame
        SPT->>C: vm_do_claim_page(child page) → child frame
        SPT->>C: memcpy(child frame, parent frame, 4096)
    end

    Note over P,C: parent owns slot 3<br/>child owns slot 7 (A) or resident frame (B)

slot 공유 위험 다이어그램

flowchart TD
    A[fork: child.slot = parent.slot = 3] --> B[parent fault → swap_in slot 3]
    B --> C[bitmap_set slot 3 = false]
    C --> D[다른 page X → swap_out → slot 3 재할당]
    D --> E[child fault → swap_in slot 3]
    E --> F[child reads page X bytes!<br/>fork snapshot 오염]

rollback 판단 Mermaid flowchart

flowchart TD
    START[child page 생성] --> SLOT{child slot<br/>할당 성공?}
    SLOT -->|실패| F1[child page free → return false]
    SLOT -->|성공| READ{parent slot<br/>read 성공?}
    READ -->|실패| F2[child slot free<br/>child page free<br/>return false]
    READ -->|성공| WRITE{child slot<br/>write 성공?}
    WRITE -->|실패| F3[child slot free<br/>child page free<br/>return false]
    WRITE -->|성공| INSERT{child SPT<br/>insert 성공?}
    INSERT -->|실패| F4[child page destroy<br/>→ slot free 포함]
    INSERT -->|성공| OK[return true]
