syscall_handler() — 번호별 분기

syscall_handler() — 번호별 분기

확인 범위: 이 문서는 시스템 콜 번호를 구현 함수로 분기하는 일반 원리와 Linux·PintOS의 선택 방식을 설명하며, 제시된 코드 경로·번호·보호 패턴은 특정 구현에 관한 서술이다. 정확한 분기, 버전별 번호, 포인터 검증·잠금 동작과 성능 특성은 해당 소스 코드, 빌드 설정, 실행 기록 및 측정을 통해 별도로 검증해야 한다.

한 줄 요약: syscall_handler()는 유저 진입 후 처음 닿는 C 코드로, intr_frame의 RAX에 든 번호를 함수 포인터 테이블이나 switch로 풀어 해당 시스템 콜 구현으로 분기한다.

syscall_handler() 흐름

syscall_handler()는 유저 프로그램이 syscall 명령어를 실행한 뒤 커널에서 가장 먼저 C 코드로 진입하는 함수다. intr_frame의 RAX 레지스터에 담긴 syscall 번호를 읽고, switch-case로 해당 구현 함수에 분기한다. 인자는 x86-64 ABI에 따라 RDI, RSI, RDX 레지스터에서 꺼내고, 반환값은 f->R.rax에 저장하여 유저 공간에 돌려준다.

상세 설명

추상 개념 — Syscall Dispatch Table

OS가 syscall을 처리하는 일반적 패턴은 번호 → 함수 포인터 테이블이다:

유저: syscall 명령어 (RAX = 번호, RDI/RSI/RDX = 인자)
    ↓
커널 진입점: 스택 전환 → register 저장
    ↓
dispatch: table[RAX] → 구현 함수 호출
    ↓
반환: RAX에 결과 저장 → sysret/iret

Linux에서는 sys_call_table[] 배열에 함수 포인터를 저장한다. PintOS는 switch-case로 동일한 역할을 수행한다.

실제 OS (Linux)

Linux x86-64 syscall 경로:

SYSCALL_DEFINE3(write, ...) → ksys_write() → vfs_write()
  • arch/x86/entry/entry_64.S: entry_SYSCALL_64 → C 함수 do_syscall_64() 호출
  • arch/x86/entry/common.c: do_syscall_64() → sys_call_tablenr
  • include/generated/asm-offsets.h: syscall 번호 자동 생성
  • 번호 범위: 0~약 450 (6.x 커널 기준)

Linux는 __SYSCALL_DEFINEx 매크로로 인자 타입 검사와 audit hook을 자동 생성한다.

PintOS 구현

진입 경로 (syscall_entry.S → syscall_handler):

유저 코드: syscall 명령어
    ↓ [CPU: LSTAR MSR → syscall_entry]
syscall_entry.S:
    ① movabs $tss, %r12 → rsp0 로드 (커널 스택 전환)
    ② push 유저 register → intr_frame 구성
    ③ call syscall_handler
    ④ pop → do_iret → 유저 복귀

보호 패턴: User Pointer 검증과 filesys_lock

모든 syscall 구현 함수는 두 가지 보호를 수행한다:

2. filesys_lock — 파일 시스템 연산의 상호 배제:

PintOS 파일 시스템은 thread-safe하지 않으므로, 전역 Lock으로 직렬화한다. 실제 OS는 파일별/inode별 세밀한 잠금을 사용한다.

fork와 exec의 특이한 점

  • fork: intr_frame 포인터 f를 __FORK에 전달하여 부모의 전체 register 상태를 자식에 복사한다.
  • exec: 성공 시 새 프로그램으로 완전히 교체되므로 반환하지 않는다. 실패 시만 -1로 exit.

항목값
PintOS syscall 번호 범위0 (SYS_HALT) ~ 13 (SYS_CLOSE) + VM 추가
Linux syscall 번호 범위0 ~ ~450 (kernel 6.x)
인자 레지스터RDI, RSI, RDX, R10, R8, R9 (최대 6개)
반환 레지스터RAX

순서도

flowchart TD
    U[유저: syscall 명령어] --> E[syscall_entry.S]
    E --> S[커널 스택 전환]
    S --> H[syscall_handler 진입]
    H --> SW{switch f->R.rax}
    SW -->|0| HALT[halt → power_off]
    SW -->|1| EXIT[exit → process_exit_with_status]
    SW -->|2| FORK[fork → process_fork]
    SW -->|3| EXEC[exec → process_exec]
    SW -->|4| WAIT[wait → process_wait]
    SW -->|5-13| FS[파일 syscall → filesys_lock 보호]
    FS --> RET[f->R.rax = 반환값]
    FORK --> RET
    WAIT --> RET
    RET --> IRET[do_iret → 유저 복귀]
