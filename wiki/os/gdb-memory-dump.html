GDB 메모리 덤프

GDB 메모리 덤프

확인 범위: 이 문서는 GDB의 메모리 읽기가 QEMU를 거쳐 guest 주소 공간을 해석하는 일반 원리와 GDB x/ 및 QEMU monitor xp의 선택 기준을 설명한다. 제시된 QEMU 내부 함수 경로, PintOS 주소와 출력 예시, 오류 형태, 패킷 크기와 동작 특성은 특정 소스 버전이나 실제 실행 기록·성능 측정으로 검증한 결과가 아니므로 적용 대상 환경에서 별도로 확인해야 한다.

한 줄 요약: GDB x/Nx가 QEMU stub을 통해 host가 아닌 guest 가상 주소 공간의 메모리를 읽는 원리.

GDB 메모리 덤프 상태

GDB의 x/Nx (examine memory) 명령은 QEMU GDB stub을 통해 guest 가상 주소 공간의 메모리를 읽는다. 호스트 프로세스의 메모리가 아니라, QEMU가 에뮬레이션하는 guest CPU 시점에서 주소를 해석한다. 즉 x/4xw 0x47480000은 PintOS의 USER_STACK 주소를 guest의 현재 CR3(PML4)를 사용해 변환한 뒤 해당 물리 프레임의 내용을 보여준다.

QEMU 내부 처리 경계

아래 순서도는 x86 system emulation에서 PintOS의 guest VA를 읽는 경로를 한 번만 정리한다. cpu_memory_rw_debug() 자체가 모든 아키텍처에서 CR3를 읽는 것은 아니다. x86 CPU의 현재 주소 변환 상태를 사용하기 때문에 이 문맥에서 CR3 기반 page table walk가 일어난다. 변환이나 읽기가 실패하면 GDB stub은 오류를 반환하며, 실패한 바이트를 0으로 읽었다고 일반화하면 안 된다.

x86 system emulation의 debug 주소 변환은 TLB lookup 대신 페이지 테이블 엔트리를 직접 조회한다. 따라서 TLB 캐시와 페이지 테이블의 매핑이 불일치하는 상황에서도 페이지 테이블 기준의 매핑을 확인할 수 있다.

guest VA vs guest PA 접근

GDB의 x/ 명령은 항상 guest VA를 사용한다. guest PA를 직접 읽으려면 QEMU 모니터 콘솔(qemu -monitor stdio)의 xp 명령을 사용해야 한다:

명령주소 공간사용처
GDB x/Nx <addr>guest VA유저/커널 코드 디버깅
QEMU monitor xp /Nx <addr>guest PA페이지 테이블 엔트리 직접 확인

page fault와 메모리 읽기

GDB의 x/ 명령은 page fault를 발생시키지 않는다. cpu_memory_rw_debug()는 PTE를 소프트웨어로 직접 walk하므로:

  • present bit이 0인 페이지: 읽기 실패 → GDB에 오류 응답
  • swap된 페이지: 물리 프레임이 없으므로 읽을 수 없음
  • UNINIT 페이지: 아직 매핑되지 않았으므로 읽을 수 없음

이는 디버깅 시 주의할 점이다. lazy-loaded 페이지는 x/로 볼 수 없고, page fault가 발생해 실제 프레임이 할당된 후에야 내용을 확인할 수 있다.

GDB 메모리 덤프 값 추적

m 패킷의 오버헤드 계산:

항목크기
요청: $m<16 hex addr>,<len>#xx~25 bytes
응답: $<2×len hex chars>#xx4 + 2×len bytes
x/256xb <addr> → 256바이트 읽기응답 ~516 bytes

GDB는 큰 메모리 범위를 읽을 때 여러 m 패킷으로 분할한다. 기본 최대 패킷 크기는 약 4096바이트 (PacketSize 협상에 따라 다름).

PintOS 디버깅에서 자주 쓰는 주소 범위:

영역주소 범위용도
유저 코드0x400000 ~ELF 코드/데이터 세그먼트
유저 스택~ 0x47480000argv, 로컬 변수
커널 코드0x8004000000 ~커널 함수, 전역 변수
커널 스택thread 구조체 상단interrupt frame, 로컬 변수

순서도

%% GDB x 명령에서 QEMU 응답까지의 메모리 덤프 순서
flowchart TD
  read_cmd["GDB: x/4xg 0x47480000"]
  packet["$m47480000,20 패킷 전송"]
  dispatch["QEMU: gdb_handle_packet()"]
  debug["cpu_memory_rw_debug(addr=0x47480000, len=32)"]
  cr3["guest CR3 → PML4 물리 주소"]
  walk["소프트웨어 page table walk<br/>PML4 → PDPT → PD → PT → 물리 프레임"]
  present["PTE present?"]
  guest_pa["guest PA = 프레임 주소 + offset"]
  as_rw["address_space_rw(guest PA)"]
  ram["RAMBlock → HVA → memcpy"]
  ok["hex 인코딩 → 응답 전송"]
  error["에러 응답 (E14)"]
  read_cmd --> packet
  packet --> dispatch
  dispatch --> debug
  debug --> cr3
  cr3 --> walk
  walk --> present
  present -->|Yes| guest_pa
  present -->|No| error
  guest_pa --> as_rw
  as_rw --> ram
  ram --> ok
