4KB 페이지와 8개 섹터

4KB 페이지와 8개 섹터

확인 범위: 이 문서는 4KB page와 512B sector를 전제로 한 swap 단위 변환의 일반 원리와 PintOS·Linux·Windows·QEMU에 적용하는 구현 패턴을 설명한다. 제시된 코드와 계산은 설명용 예시이며, 특정 구현·버전에서의 동작 여부와 실행 경로, 실제 디스크 구성 및 성능은 해당 소스와 실행 기록·측정을 통해 별도로 검증해야 한다.

한 줄 요약: 4KB page를 512B sector 8개로 나눠 swap 디스크에 저장·복원하는 단위 변환.

4KB 페이지와 8개 섹터 차이

OS의 메모리 관리 단위는 **page (4 KB = 4096 bytes)**이고, 디스크의 I/O 단위는 **sector (512 bytes)**다. 하나의 page를 swap disk에 저장하거나 읽으려면 8개의 연속 sector를 읽고 써야 한다. swap slot 하나는 이 8 sector 묶음이며, slot index에서 sector 번호로의 변환은 sector = slot_index × 8이다. 이 간단한 곱셈이 VM 계층(page 단위)과 disk 계층(sector 단위) 사이의 단위 변환 공식이다.

상세 설명

추상 개념 (하드웨어 규칙)

두 가지 하드웨어 상수가 이 관계를 결정한다:

상수값근거
Page size4096 bytes (4 KB)x86-64 아키텍처의 기본 page 크기. CR3 → PML4 → … → PTE에서 하위 12비트가 page offset
Sector size512 bytesATA/IDE 표준 디스크 sector 크기
SECTORS_PER_PAGE = PGSIZE / DISK_SECTOR_SIZE
                 = 4096 / 512
                 = 8

이 값은 아키텍처와 디스크 표준이 바뀌지 않는 한 상수다.

실제 OS (Linux/Windows)

Linux의 swap subsystem도 동일한 원리를 따른다. PAGE_SIZE (보통 4096)를 block 단위(512 또는 4096)로 나누어 I/O를 수행한다. 다만 현대 Linux는 block layer 추상화로 직접 sector 곱셈을 하지 않고, bio 구조체에 page와 offset을 전달한다. 또한 최신 디스크(Advanced Format)는 물리 sector가 4096 bytes인 경우도 있지만, 논리 sector는 여전히 512 bytes로 보고하는 경우가 많다.

Windows의 page file도 같은 수학이다. 4 KB page를 page file의 연속 영역에 저장하며, NTFS의 cluster 크기(보통 4 KB)와 page 크기가 일치하도록 설계되어 있다.

QEMU 에뮬레이션

QEMU에서 swap disk는 pintos-pool 명령행으로 지정하는 두 번째 IDE 디스크(hd1:0, 즉 disk_get(1, 1))다. PintOS가 disk_write(swap_disk, sector, buffer)를 호출하면:

  1. PintOS IDE driver가 ATA 레지스터에 sector 번호와 명령을 기록
  2. QEMU의 IDE controller model이 이를 가로챔
  3. BlockBackend → 호스트 파일의 sector × 512 offset에 512 bytes를 쓴다

즉, swap slot 3의 다섯 번째 sector를 쓴다면:

호스트 파일 offset = (3 × 8 + 4) × 512 = 28 × 512 = 14336 bytes

GDB에서 swap 내용을 직접 확인하려면 호스트에서 xxd -s 14336 -l 512 swap.dsk로 해당 offset을 덤프할 수 있다.

4KB 페이지와 8개 섹터 값 추적

단위 변환 표:

단위크기관계
1 byte1 B기본 단위
1 sector512 BDISK_SECTOR_SIZE
1 page4096 BPGSIZE = 8 sectors
1 swap slot4096 B= 1 page = 8 sectors

slot → sector 변환:

sector_start = slot_index × SECTORS_PER_PAGE
             = slot_index × 8

sector_end   = sector_start + 7

호스트 파일 byte offset = sector_start × DISK_SECTOR_SIZE
                        = slot_index × 8 × 512
                        = slot_index × 4096

구체적 예시:

page VA = 0x00000000_00401000 (유저 영역)
eviction → swap slot 42에 저장

disk_write 8회:
  sector 336 (= 42×8+0): kva[0..511]
  sector 337 (= 42×8+1): kva[512..1023]
  sector 338 (= 42×8+2): kva[1024..1535]
  sector 339 (= 42×8+3): kva[1536..2047]
  sector 340 (= 42×8+4): kva[2048..2559]
  sector 341 (= 42×8+5): kva[2560..3071]
  sector 342 (= 42×8+6): kva[3072..3583]
  sector 343 (= 42×8+7): kva[3584..4095]

호스트 파일 offset range: 172032 ~ 176127 (= 336×512 ~ 343×512+511)
