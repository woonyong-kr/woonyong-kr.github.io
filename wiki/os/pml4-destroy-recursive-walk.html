pml4_destroy() — 4-Level Page Table 재귀 해제

pml4_destroy() — 4-Level Page Table 재귀 해제

확인 범위: 이 문서는 4단계 페이지 테이블을 리프부터 해제하는 일반 원리와 입력에 제시된 PintOS·Linux·QEMU의 동작 설명을 구분해 다룬다. 구체적인 코드 경로, 주소 범위, 해제 규모, 재귀 깊이·스택 사용량 및 실행 효과는 특정 구현과 구성에 관한 서술이며, 실제 소스 버전·빌드 설정·실행 기록·성능 측정에 대한 검증 결과로 간주해서는 안 된다.

한 줄 요약: 유저 주소 공간의 4단계 페이지 테이블을 리프부터 루트까지 bottom-up으로 재귀 해제해, 프레임과 테이블 페이지를 누수 없이 회수하는 함수다.

pml4_destroy() 상태

pml4_destroy()는 유저 주소 공간의 모든 페이지 테이블 계층을 재귀적으로 순회하면서 할당된 물리 프레임과 테이블 페이지를 해제하는 함수다. 4단계 page table walk의 역방향 — “생성 시 top-down으로 할당, 파괴 시 bottom-up으로 해제”라는 원칙을 구현한다. 이 함수는 process_cleanup() 안에서 호출되어 exec과 exit 양쪽에서 주소 공간을 정리한다.

상세 설명

추상 개념 (페이지 테이블 해제 규칙)

x86-64의 4단계 페이지 테이블은 트리 구조다. 트리를 해제하려면 리프 노드부터 루트까지 bottom-up으로 해제해야 한다 — 루트를 먼저 해제하면 하위 테이블에 대한 포인터를 잃어버려 메모리 누수가 발생한다.

해제 순서:

  1. PTE (Level 1) 엔트리가 가리키는 유저 데이터 페이지 해제
  2. PT (Level 1) 테이블 페이지 자체 해제
  3. PD (Level 2) 엔트리 순회 → 각 PT 해제 → PD 테이블 페이지 해제
  4. PDPT (Level 3) 엔트리 순회 → 각 PD 해제 → PDPT 테이블 페이지 해제
  5. PML4 (Level 4) 엔트리 순회 → 각 PDPT 해제 → PML4 테이블 페이지 해제

커널 영역 매핑은 모든 프로세스가 공유하므로 해제하지 않는다. PintOS에서 PML4[0]만 유저 영역이고 PML4[1~511]은 커널 영역(또는 미사용)이므로, pml4_destroy()는 PML4[0]만 처리한다.

실제 OS (Linux)

Linux의 pgd_free()는 유사한 재귀 워크를 수행하지만, 몇 가지 차이가 있다:

  • 유저 데이터 페이지는 별도 경로로 해제: unmap_vmas() → zap_pte_range()가 VMA별로 PTE를 순회하며 데이터 프레임을 해제한다. pgd_free는 테이블 페이지만 정리한다.
  • TLB shootdown: 멀티코어에서 다른 CPU의 TLB도 무효화해야 한다 (IPI 전송).
  • RCU grace period: 페이지 테이블 해제를 즉시 하지 않고 RCU callback으로 지연하여 동시 접근 중인 다른 코어를 보호한다.
  • huge page 지원: 2MB/1GB huge page는 중간 레벨을 건너뛴다.

PintOS 구현

PintOS의 mmu.c에 있는 4개 함수가 재귀 워크를 구성한다:

핵심 패턴: 모든 레벨에서 동일한 구조를 반복한다:

  1. 512개 엔트리를 순회하며 PTE_P (present bit) 확인
  2. present인 엔트리의 하위 테이블/프레임을 PTE_ADDR()로 추출
  3. 하위 레벨을 재귀적으로 해제
  4. 자기 자신(테이블 페이지)을 palloc_free_page()로 해제

ptov()와 PTE_ADDR()의 역할

PTE 엔트리에는 물리 주소가 저장된다. 커널 코드에서 이 주소에 접근하려면:

  • PTE_ADDR(entry): 엔트리의 하위 12비트 플래그를 제거하여 물리 주소만 추출
  • ptov(pa): 물리 주소에 KERN_BASE(0x8004000000)를 더해 커널 가상 주소로 변환

이 변환이 필요한 이유: CPU는 가상 주소로 동작하므로, 물리 주소를 직접 역참조할 수 없다. PintOS 커널의 1:1 매핑(PA + KERN_BASE = KVA) 덕분에 ptov()가 단순 덧셈으로 구현된다.

PML4[0]만 처리하는 이유

x86-64에서 PML4의 각 엔트리는 512GB 주소 범위를 커버한다:

PML4 index주소 범위PintOS 용도
00x0 ~ 0x7FFFFFFFFF (512 GB)유저 영역
10x8000000000 ~ 0xFFFFFFFFFF커널 영역 시작 (KERN_BASE = 0x8004000000)
2~5111TB ~ 256TB미사용 (canonical address 제약)

커널 영역 PML4[1]은 base_pml4(부팅 시 생성된 커널 PML4)에서 복사한 것이므로 프로세스 종료 시 건드리면 안 된다. pml4_destroy()가 ASSERT(pml4 != base_pml4)로 커널 PML4 자체의 파괴를 방지한다.

QEMU 에뮬레이션

QEMU에게 pml4_destroy()는 다음과 같이 보인다:

  1. 메모리 읽기: 각 테이블 엔트리를 읽는 load 명령어 → SoftMMU를 통해 guest RAM 접근
  2. 조건 분기: PTE_P 비트 검사 → guest CPU의 일반 AND + branch 명령어
  3. 메모리 쓰기: palloc_free_page() 내부에서 bitmap 비트를 리셋 → guest RAM 쓰기
  4. 페이지 해제 효과: QEMU는 해제된 페이지를 “인식”하지 않는다. RAMBlock 메모리는 그대로 남아있고, guest OS가 bitmap으로 관리할 뿐이다.

PML4가 파괴된 후 pml4_activate(new_pml4) → lcr3()가 호출되면, QEMU는 SoftMMU TLB를 전면 flush한다. 이 시점에서 old PML4로의 TLB 엔트리가 모두 사라진다.

최대 재귀 깊이 4 — 커널 스택 오버플로 위험 없음. 각 함수의 스택 프레임은 ~100 bytes 수준이므로 총 ~400 bytes만 사용한다.

VM 모드에서의 중복 해제 방지

VM 모드(Project 3)에서는 process_cleanup() 순서가 중요하다:
