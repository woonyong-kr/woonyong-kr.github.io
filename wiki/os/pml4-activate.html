pml4_activate — CR3 전환으로 주소 공간 교체

확인 범위: 이 문서는 CR3 전환과 TLB 처리의 일반 원리 및 구현 선택 기준을 설명하며, Linux·PintOS·QEMU의 코드 경로, 호출 위치, 버전별 동작과 실행 결과는 해당 소스와 환경에서 별도로 검증해야 한다. 제시된 주소·비용·엔트리 수와 장애 양상은 예시 또는 특정 조건의 값이므로 실제 시스템에 적용하려면 대상 버전의 코드, 실행 기록과 성능 측정으로 확인해야 한다.

한 줄 요약: pml4_activate()는 CR3에 새 PML4 물리 주소를 로드해 주소 공간을 통째로 교체하는 함수로, TLB를 자동 flush해 프로세스 간 메모리 격리를 실현한다.

pml4_activate 상태

pml4_activate()는 CPU의 CR3 레지스터에 새 PML4의 물리 주소를 로드하는 함수다. CR3가 바뀌는 순간 CPU는 이전 프로세스의 가상 주소 매핑을 버리고 새 프로세스의 매핑을 사용한다. 이 단 한 줄이 프로세스 간 메모리 격리를 실현하는 핵심 동작이다. CR3 교체는 TLB(Translation Lookaside Buffer)를 자동으로 flush하여 이전 주소 변환 캐시가 새 프로세스에 영향을 주지 않도록 보장한다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64에서 CR3는 현재 활성 PML4 테이블의 물리 주소를 담는다. mov %rax, %cr3 명령어를 실행하면 두 가지 일이 동시에 일어난다:

  1. 주소 변환 루트 교체: 이후 모든 메모리 접근의 page table walk가 새 PML4에서 시작된다.
  2. TLB flush: CR3에 새 값을 쓰면 CPU는 기존 TLB 엔트리를 모두 무효화한다(Global bit가 설정된 엔트리 제외).

이 동작이 특권 명령인 이유: CR3는 주소 공간 전체를 결정하므로 유저 모드에서 변경할 수 있다면 다른 프로세스의 메모리에 접근할 수 있다. 따라서 CR3 쓰기는 CPL 0(커널 모드)에서만 허용된다.

CR3 포맷 (4-level paging, non-PCID 모드):

  • bit 63:12 — PML4 물리 주소 (4 KB 정렬이므로 하위 12비트는 항상 0)
  • bit 4 (PCD) — page-level cache disable
  • bit 3 (PWT) — page-level write-through

실제 OS (Linux)

Linux에서 CR3 전환은 switch_mm_irqs_off() 함수에서 이루어진다:

  1. load_new_mm_cr3() 호출 → 내부에서 write_cr3() 실행
  2. PCID(Process Context ID) 지원 시: CR3의 하위 12비트에 PCID를 설정하고 bit 63(NOFLUSH)을 세팅하면 TLB flush를 건너뛸 수 있다. 같은 PCID의 캐시만 유효하므로 격리는 유지된다.
  3. KPTI(Kernel Page Table Isolation) 활성 시: 유저 PGD와 커널 PGD가 분리되어 있으므로, 커널 진입/복귀 시에도 CR3 전환이 필요하다 (성능 비용 발생).

PintOS 구현

pml4_activate() — threads/mmu.c:221-223

3줄이지만 분해하면:

  1. pml4 ? pml4 : base_pml4 — NULL이면 커널 기본 테이블(base_pml4)을 사용한다. 커널 스레드는 thread->pml4 == NULL이다.
  2. vtop(...) — 커널 가상 주소를 물리 주소로 변환한다 (VA - KERN_BASE). CR3에는 반드시 물리 주소가 들어가야 한다.
  3. lcr3(...) — 인라인 어셈블리 movq %0, %%cr3로 CR3를 쓴다.

lcr3() — include/intrinsic.h:10-12

process_cleanup()에서의 순서가 중요하다:

(2)를 건너뛰고 (3)을 실행하면, 현재 CPU가 사용 중인 PML4를 해제하게 된다. 이후 메모리 접근 시 해제된 페이지를 page table로 읽게 되어 정의되지 않은 동작(보통 triple fault → 리부트)이 발생한다.

QEMU 에뮬레이션

QEMU TCG 모드에서 mov %rax, %cr3를 만나면:

  1. helper 호출: guest movq가 helper_write_crN() (target/i386/tcg/sysemu/misc_helper.c)로 디스패치된다.
  2. env->cr[3] 갱신: CPUX86State.cr[3]에 새 값을 저장한다.
  3. SoftTLB flush: tlb_flush(cs) 호출 → QEMU 내부 TLB 엔트리를 모두 무효화한다.
  4. TB 체인 끊기: 현재 Translation Block 실행 중단, 새 CR3 기준으로 재번역 시작.

GDB에서 CR3 전환 관찰:
