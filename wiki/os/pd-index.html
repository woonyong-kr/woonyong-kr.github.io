PD Index — 4단계 Page Table Walk의 세 번째 단계

한 줄 요약: VA 비트 29:21이 PD index로, 4단계 walk의 세 번째 단계에서 PD 테이블의 한 PDE를 선택하며 PDE 하나가 2 MiB를 커버한다.

PD Index 상태

x86-64 4단계 페이지 테이블에서 가상 주소(VA)의 비트 29:21이 PD index(Page Directory index)다. 두 번째 단계에서 PDPT 엔트리가 가리키는 PD(Page Directory) 테이블(512개 엔트리)에서 이 9비트 index로 하나의 PD 엔트리(PDE)를 선택한다. PDE는 다음 단계인 PT(Page Table)의 물리 주소를 담고 있다. PD 엔트리 하나가 커버하는 범위는 2 MiB다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

MMU가 4단계 walk을 수행할 때 세 번째로 참조하는 테이블이 PD다. 전체 CR3→PML4→PDPT→PD→PT 흐름은 아래 정본 Mermaid에서 PD 선택 지점을 강조해 보여준다.

VA의 비트 필드 분해:

 63    48 47        39 38        30 29        21 20        12 11         0
+--------+-----------+-----------+-----------+-----------+-----------+
| sign   | PML4 idx  | PDPT idx  | PD idx    | PT idx    | offset    |
| extend |  9 bits   |  9 bits   |  9 bits   |  9 bits   | 12 bits   |
+--------+-----------+-----------+-----------+-----------+-----------+
                                  ^^^^^^^^^^
                                  이 문서의 범위

PD index는 shift 21 후 하위 9비트를 마스킹하여 추출한다:

PD_index = (VA >> 21) & 0x1FF

PDE 하나가 커버하는 주소 범위는 2^21 = 2,097,152 bytes = 2 MiB다. PD 테이블 전체(512 엔트리)가 커버하는 범위는 512 × 2 MiB = 1 GiB로, 이는 상위 PDPT 엔트리 하나의 커버 범위와 일치한다.

Large Page (2 MiB): PDE에 PS(Page Size) 비트가 세팅되면 walk이 여기서 끝나고, PDE가 직접 2 MiB 물리 프레임을 가리킨다. 이 경우 VA[20:0]이 통째로 offset이 된다. Linux 커널은 CONFIG_HUGETLB_PAGE로 이를 지원한다.

실제 OS (Linux/Windows)

Linux의 pgd_t → p4d_t → pud_t → pmd_t → pte_t 5단계 구조에서 pmd_t가 PD에 해당한다. pmd_offset(pud, addr)이 PD index 추출과 PDE 접근을 수행한다.

pmd_index(addr) = (addr >> PMD_SHIFT) & (PTRS_PER_PMD - 1)
PMD_SHIFT = 21, PTRS_PER_PMD = 512

Linux는 2 MiB huge page를 투명하게 사용하는 THP(Transparent Huge Pages)를 지원한다. 이때 PMD 엔트리가 직접 2 MiB 프레임을 가리키고, PT 단계를 건너뛴다.

Windows에서도 PD는 “Page Directory”라 부르며, Large Page(2 MiB) 매핑을 SEC_LARGE_PAGES로 지원한다.

PintOS 구현

PintOS는 include/threads/pte.h에서 PD index를 추출하는 매크로를 정의한다:

실제 walk에서 PD index를 사용하는 함수는 pgdir_walk()다. 이 함수는 PD 테이블 포인터(pdp)와 VA를 받아 PT 엔트리의 주소를 반환한다:

이 함수의 핵심 동작:

  1. PDX(va)로 PD index(비트 29:21) 추출
  2. pdp[idx]로 PDE 읽기
  3. PDE의 present 비트 확인 → 없으면 create 플래그에 따라 새 PT 페이지 할당
  4. PDE에서 PT의 물리 주소 추출 후 PTX(va) × 8로 최종 PTE 위치 계산

pgdir_walk()는 pdpe_walk()에서 호출된다. PDPT 단계에서 PD 테이블의 물리 주소를 얻고, ptov()로 커널 가상 주소로 변환한 뒤 pgdir_walk()에 넘긴다:

PintOS는 2 MiB large page를 지원하지 않는다. 모든 매핑은 반드시 4단계 walk을 완주하여 4 KiB 프레임에 도달한다.

PD Index 값 추적

예시: VA = 0x0000004000401000

PML4 index = (0x4000401000 >> 39) & 0x1FF = 0
PDPT index = (0x4000401000 >> 30) & 0x1FF = 256
PD index   = (0x4000401000 >> 21) & 0x1FF = 2    ← 이 단계
PT index   = (0x4000401000 >> 12) & 0x1FF = 1
offset     = 0x4000401000 & 0xFFF            = 0

PD index = 2이므로, PD 테이블의 3번째 엔트리(0-based)를 참조한다.

PDE가 커버하는 주소 범위:

PD index시작 VA (PDPT idx=0 기준)끝 VA크기
00x0000_0000_00000x0000_001F_FFFF2 MiB
10x0000_0020_00000x0000_003F_FFFF2 MiB
20x0000_0040_00000x0000_005F_FFFF2 MiB
…………
5110x0000_3FE0_00000x0000_3FFF_FFFF2 MiB

메모리 소비:

  • PD 테이블 1개 = 512 × 8 bytes = 4,096 bytes = 1 page
  • PDE 1개 = 8 bytes (64비트 엔트리)
