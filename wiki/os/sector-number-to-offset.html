섹터와 바이트 오프셋

섹터와 바이트 오프셋

확인 범위: 이 문서는 섹터 번호와 바이트 오프셋의 일반적인 변환 원리와 파일·swap 위치 계산 기준을 설명하고, Linux·PintOS·QEMU 관련 내용은 입력에 제시된 구현 예시를 바탕으로 구분해 다룬다. 특정 코드·버전에서의 실제 동작과 실행 기록, 성능 특성은 별도의 소스 대조와 실행·측정 없이는 검증 결과로 간주하지 않는다.

한 줄 요약: 디스크 최소 단위 섹터(512B) 번호를 바이트 오프셋으로 변환하는 공식(byte_offset = sector × 512).

섹터와 바이트 오프셋 차이

디스크 I/O의 최소 단위는 섹터(512 바이트)다. 파일 시스템이나 swap 시스템이 “섹터 N번을 읽어라”라고 명령하면, IDE 컨트롤러는 이 숫자를 디스크 상의 바이트 위치로 변환해야 한다. 변환 공식은 단순하다: byte_offset = sector_number × 512. 이 관계를 이해하면 swap slot, inode 데이터 블록, free-map 비트맵 등 모든 디스크 기반 자료구조의 물리적 위치를 계산할 수 있다.

상세 설명

추상 개념 (하드웨어 규칙)

전통적 하드 디스크는 CHS(Cylinder-Head-Sector) 방식으로 물리 위치를 지정했다. 현대 디스크(ATA-3 이후)는 **LBA(Logical Block Addressing)**를 사용하며, 디스크 전체를 0번부터 시작하는 연속 섹터 배열로 취급한다.

섹터 0: byte 0 ~ 511
섹터 1: byte 512 ~ 1023
섹터 2: byte 1024 ~ 1535
...
섹터 N: byte (N × 512) ~ (N × 512 + 511)

LBA 28-bit 주소 → 최대 2^28 = 268,435,456 섹터 = 128 GB. LBA 48-bit 주소 → 최대 2^48 섹터 = 128 PB.

PintOS는 LBA 28-bit를 사용한다 (sec_no < (1UL << 28)).

실제 OS (Linux)

Linux의 블록 I/O 계층에서 struct bio는 섹터 번호(bi_sector)를 사용한다. 블록 디바이스 드라이버가 이를 물리 주소로 변환할 때 동일한 sector × sector_size 공식을 적용한다.

Linux 2.6 이후 기본 섹터 크기는 512 B이지만, 일부 디바이스(4Kn 디스크)는 물리 섹터 4096 B를 사용한다. 이 경우 논리 섹터(512 B)를 물리 섹터(4096 B)로 다시 변환하는 계층이 있다: phys_sector = logical_sector / 8.

PintOS 구현

타입과 상수:

select_sector() — LBA 레지스터 설정:

ATA PIO에서 섹터 번호를 IDE 컨트롤러에 전달하려면, 28-bit LBA를 4개 레지스터에 분할 기록한다:

레지스터I/O 포트 오프셋전달 비트
reg_lbalbase + 3LBA [7:0]
reg_lbambase + 4LBA [15:8]
reg_lbahbase + 5LBA [23:16]
reg_devicebase + 6LBA [27:24] + LBA 모드 플래그

disk_read() / disk_write() 전체 흐름:

disk_read(d, sec_no, buffer)
  → lock_acquire(&channel->lock)
  → select_sector(d, sec_no)        // LBA 레지스터에 섹터 번호 기록
  → issue_pio_command(c, 0x20)       // READ SECTOR 명령
  → sema_down(&completion_wait)      // IRQ14 대기
  → input_sector(c, buffer)          // 데이터 레지스터에서 512 B 읽기
  → lock_release(&channel->lock)

데이터 전송:

insw는 x86의 rep insw 명령으로, I/O 포트에서 16-bit 워드를 반복 읽어 메모리에 저장한다. 한 섹터 = 256 워드.

swap에서의 섹터 변환:

swap disk는 4 KB page를 8개 연속 섹터에 저장한다:

swap slot N → 시작 섹터 = N × 8
            → byte offset = N × 8 × 512 = N × 4096

QEMU 에뮬레이션

QEMU의 IDE 컨트롤러 모델(hw/ide/core.c)이 guest의 LBA 레지스터 기록을 캡처한다. guest가 READ SECTOR 명령을 보내면:

  1. QEMU가 LBA 28-bit를 조립: lba = lbal | (lbam << 8) | (lbah << 16) | ((device & 0xf) << 24)
  2. byte offset 계산: offset = lba × 512
  3. 호스트 파일에서 pread(fd, buf, 512, offset) 수행
  4. 데이터를 guest의 데이터 레지스터에 넣고 IRQ14 발생

호스트 파일(예: disk.img)은 섹터 0부터 순서대로 512 B씩 배치된 flat 이미지다.

섹터와 바이트 오프셋 점검

  • 섹터 번호는 디스크 안의 배열 인덱스다. PintOS 기준에서는 byte_offset = sec_no × 512만 기억해도 inode, swap, free-map 위치 계산의 출발점을 잡을 수 있다.
  • 파일 offset과 디스크 sector는 같은 값이 아니다. 파일 offset은 inode 내부의 byte_to_sector()를 거쳐 실제 디스크 섹터로 바뀐다.
  • 4 KB 페이지는 512 B 섹터 8개다. 그래서 swap slot N은 시작 섹터 N × 8, 바이트 오프셋 N × 4096으로 계산한다.
  • QEMU는 guest가 보낸 LBA 레지스터 값을 다시 조립해 host 파일의 byte offset으로 바꾼다. 이 경계에서는 PintOS의 섹터 번호와 host 파일 offset을 분리해서 봐야 한다.
