write(1, buffer, size) 전체 흐름 Trace

한 줄 요약: 유저의 write(1,“hello”,5) 한 줄이 유저 라이브러리 → syscall 명령어 → 커널 진입점 → handler → write 구현 → 파일시스템 → 디스크까지 7개 계층을 관통하는 전체 경로를 추적한다.

write 전체 흐름 구조

유저 프로그램이 write(1, "hello", 5)를 호출하면, 유저 라이브러리 → syscall 명령어 → 커널 진입점 → syscall_handler → 커널 write 구현 → 파일 시스템 → 디스크 I/O까지 7개 계층을 관통한다. 이 문서는 PintOS에서 하나의 write syscall이 유저 코드에서 디스크(또는 콘솔)까지 도달하는 전체 경로를 단계별로 추적한다.

상세 설명

전체 흐름 개관

유저 코드: write(1, buf, 5)
  ↓
lib/user/syscall.c: syscall3(SYS_WRITE, 1, buf, 5)
  ↓ inline asm: mov rax=SYS_WRITE, rdi=1, rsi=buf, rdx=5 → syscall
  ↓
userprog/syscall-entry.S: syscall_entry
  ↓ TSS.rsp0 → 커널 스택 전환, intr_frame 구성
  ↓
userprog/syscall.c: syscall_handler(f)
  ↓ switch(f->R.rax) → case SYS_WRITE
  ↓
userprog/syscall.c: write(fd=1, buffer, size, f)
  ↓ fd==1 → putbuf() (콘솔 출력)
  ↓ fd>1 → file_write() → inode_write_at() → disk_write()
  ↓
syscall_entry.S: sysretq → 유저 모드 복귀

1단계: 유저 라이브러리 (CPL 3)

lib/user/syscall.c에서 write()는 매크로로 정의된다:

syscall3은 syscall() 인라인 어셈블리 함수를 호출한다:

레지스터 배치:

레지스터값의미
RAX10 (SYS_WRITE)syscall 번호
RDI1fd (stdout)
RSIbuf 주소유저 버퍼 포인터
RDX5바이트 수

syscall 명령어가 실행되면 CPU가 자동으로:

  • RCX ← 다음 명령어 주소 (return RIP)
  • R11 ← RFLAGS
  • RIP ← LSTAR MSR 값 (= syscall_entry)
  • CPL ← 0 (커널 모드)

2단계: 커널 진입 (syscall-entry.S)

userprog/syscall-entry.S에서 커널 스택으로 전환하고 intr_frame을 구성한다:

핵심: TSS.rsp0에서 커널 스택 주소를 가져온다. 이 값은 process_activate()에서 스레드 전환 시마다 갱신된다.

3단계: syscall_handler (번호별 분기)

f->R.rax에서 syscall 번호를 읽고, f->R.rdi/rsi/rdx에서 인자를 추출한다. 반환값은 다시 f->R.rax에 저장한다 — sysretq 후 유저가 RAX에서 결과를 읽는다.

4단계: 커널 write() 구현

주요 설계 결정:

  • bounce 버퍼: 유저 포인터를 직접 파일 시스템에 넘기지 않는다. page fault가 filesys_lock 안에서 발생하면 deadlock 위험이 있기 때문이다.
  • PGSIZE 단위 분할: 페이지 경계를 넘는 버퍼를 안전하게 처리한다.
  • filesys_lock: PintOS는 파일 시스템이 thread-safe하지 않으므로 전역 lock으로 직렬화한다.

5단계: 파일 시스템 → 디스크 (fd > 1인 경우)

file_write(file, kpage, chunk)
  → inode_write_at(inode, buffer, size, file->pos)
    → disk_write(filesys_disk, sector_idx, bounce)
      → select_sector(d, sec_no)    /* I/O 포트에 LBA 주소 설정 */
      → issue_pio_command(c, CMD_WRITE_SECTOR_RETRY)
      → output_sector(c, buffer)    /* outsw로 512B 전송 */
      → sema_down(&c->completion_wait)  /* IRQ14 대기 */

6단계: 유저 복귀 (sysretq)

syscall_handler 반환 후 syscall-entry.S의 에필로그:

sysretq가 RCX → RIP, R11 → RFLAGS를 복원하고 CPL 0→3 전환한다. RAX에 write()의 반환값(쓴 바이트 수)이 들어 있다.

    E->>E: intr_frame 구성
    E->>H: syscall_handler(f)
    H->>W: write(1, buf, 5, f)
    W->>W: validate_user_buffer()
    W->>W: copy_in(kpage, buf, 5)
    alt fd == 1
        W->>W: putbuf(kpage, 5)
    else fd > 1

        F->>D: disk_write(sector)
    end
    W-->>H: return 5
    H-->>E: f->R.rax = 5
    E->>U: sysretq (CPL 0→3)
    Note over U: RAX = 5 (쓴 바이트 수)
