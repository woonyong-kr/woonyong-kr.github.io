파일 쓰기 거부 API

한 줄 요약: struct file 수준에서 inode의 deny_write_cnt를 증감해 쓰기 금지를 관리하는 file_deny_write()·file_allow_write() API.

파일 쓰기 거부 API 구조

file_deny_write()와 file_allow_write()는 개별 struct file 객체 수준에서 쓰기 금지를 관리하는 API다. 내부적으로 inode의 deny_write_cnt 참조 카운터를 증감시키되, struct file의 deny_write 플래그로 이중 호출을 방지한다. 이 두 함수가 deny-write 메커니즘의 중간 계층(file 계층)을 형성하며, 상위의 process 계층(load(), close_running_file())과 하위의 inode 계층(inode_deny_write(), inode_allow_write())을 연결한다.

상세 설명

추상 개념 (왜 file 계층이 필요한가)

inode에 직접 inode_deny_write()를 호출하면 카운터를 정확히 맞춰야 하는 부담이 호출자에게 온다. 같은 파일에 deny를 두 번 걸면 카운터가 2가 되고, allow를 한 번만 하면 영구 잠금이 된다. struct file의 deny_write 불리언이 이 문제를 해결한다: 이미 deny 상태인 file에 다시 deny를 호출하면 no-op이 되고, allow도 마찬가지다.

이 패턴은 Linux 커널의 deny_write_access() / allow_write_access()와 동일한 목적이다. Linux는 atomic_t i_writecount를 사용하지만, 핵심 원리(참조 카운팅 + 호출자별 상태 추적)는 같다.

PintOS 구현

struct file의 deny_write 플래그 (filesys/file.c):

struct file {
    struct inode *inode;
    off_t pos;
    bool deny_write;   /* 이 file이 deny를 걸었는가? */
};

file_deny_write() — 쓰기 금지 설정:

void file_deny_write (struct file *file) {
    ASSERT (file != NULL);
    if (!file->deny_write) {        /* 가드: 이미 deny면 skip */
        file->deny_write = true;
        inode_deny_write (file->inode);  /* cnt++ */
    }
}

file_allow_write() — 쓰기 금지 해제:

void file_allow_write (struct file *file) {
    ASSERT (file != NULL);
    if (file->deny_write) {         /* 가드: deny 상태가 아니면 skip */
        file->deny_write = false;
        inode_allow_write (file->inode);  /* cnt-- */
    }
}

가드 조건이 핵심이다. deny_write == false일 때 file_allow_write()를 호출해도 inode_allow_write()로 빠지지 않으므로, cnt가 음수가 되는 사고를 원천 차단한다.

file_close()에서의 자동 해제:

void file_close (struct file *file) {
    if (file != NULL) {
        file_allow_write (file);     /* deny 상태면 cnt-- */
        inode_close (file->inode);
        free (file);
    }
}

파일을 닫을 때 무조건 file_allow_write()를 호출하지만, deny 상태가 아니었다면 가드가 걸려 no-op이 된다. RAII 패턴과 유사하다.

file_duplicate()에서의 deny 전파:

struct file *file_duplicate (struct file *file) {
    struct file *nfile = file_open (inode_reopen (file->inode));
    if (nfile) {
        nfile->pos = file->pos;
        if (file->deny_write)
            file_deny_write (nfile);   /* 새 file도 deny → cnt++ */
    }
    return nfile;
}

fork 시 duplicate_running_file()이 file_duplicate()를 호출하므로, 자식 프로세스도 같은 inode에 대해 독립적인 deny를 건다. 이로써 부모가 먼저 exit해도 자식의 deny가 유지된다.
