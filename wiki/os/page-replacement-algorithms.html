페이지 교체 알고리즘 — Optimal, LRU, Clock

페이지 교체 알고리즘 — Optimal, LRU, Clock

한 줄 요약: 물리 프레임이 부족할 때 어떤 페이지를 쫓아낼지 정하는 정책으로, page fault를 최소화하는 것이 목표다 — Optimal은 이론적 하한선, LRU는 과거로 미래를 추정, Clock은 LRU의 근사 구현이다.

페이지 교체 알고리즘 상태

물리 메모리는 유한하다. 모든 페이지를 물리 프레임에 올려둘 수 없으니, 새 페이지를 올려야 할 때 기존 페이지 하나를 쫓아내야(evict) 한다. 이때 “어떤 페이지를 쫓아낼 것인가”를 결정하는 정책이 페이지 교체 알고리즘이다.

목표는 단순하다. page fault 횟수를 최소화하는 것. 앞으로 오래 안 쓸 페이지를 쫓아내면 fault가 줄고, 곧 다시 쓸 페이지를 쫓아내면 fault가 늘어난다.

Optimal (OPT, Belady’s Algorithm)

앞으로 가장 오래 사용되지 않을 페이지를 쫓아내는 알고리즘이다. 이론적으로 page fault를 가장 적게 만든다.

문제: 미래를 알아야 하므로 실제 OS에서는 구현할 수 없다. 다른 알고리즘의 성능을 비교하는 이론적 하한선으로만 쓴다. “우리 알고리즘이 OPT 대비 몇 % 더 fault가 나는가”를 측정하는 기준이다.

LRU (Least Recently Used)

가장 오래 전에 사용된 페이지를 쫓아내는 알고리즘이다. “과거에 오래 안 쓰인 페이지는 미래에도 안 쓰일 가능성이 높다”는 가정에 기반한다. OPT가 미래를 보는 것을 과거로 대체한 것이다.

문제: 정확한 LRU를 구현하려면 모든 메모리 접근마다 타임스탬프를 기록하거나 리스트를 갱신해야 한다. 메모리 접근은 나노초 단위로 일어나는데, 매번 자료구조를 업데이트하면 오버헤드가 너무 크다. 그래서 실제 OS는 정확한 LRU 대신 근사 LRU를 쓴다.

Clock (Second Chance)

LRU를 실용적으로 근사한 알고리즘이다. 실제 OS에서 가장 널리 쓰이고, PintOS에서도 이 방식으로 구현한다.

핵심 아이디어

CPU는 페이지에 접근할 때마다 해당 PTE의 **accessed bit(A bit)**를 자동으로 1로 설정한다. 이건 하드웨어가 해주므로 소프트웨어 오버헤드가 없다. Clock 알고리즘은 이 bit만 보고 “최근에 쓰였는가”를 판단한다.

동작 방식

모든 프레임을 원형 리스트(시계)로 연결하고, 시계 바늘(clock hand)이 프레임을 순회한다.

아래 정본 Mermaid는 clock hand가 A=1인 frame에 second chance를 주고 A=0인 frame을 victim으로 선택하는 원형 순회를 보여준다. 쫓아낼 페이지를 찾을 때:

  1. clock hand가 가리키는 프레임의 A bit을 확인
  2. A=1이면: “최근에 쓰였다” → 한 번 기회를 준다(second chance). A bit을 0으로 리셋하고, 다음 프레임으로 이동
  3. A=0이면: “최근에 안 쓰였다” → 이 프레임을 victim으로 선택

왜 LRU의 근사인가

정확한 LRU는 “가장 오래 전에 접근된 페이지”를 찾는다. Clock은 “최근에 접근되지 않은 페이지”를 찾는다. 정확한 시간 순서는 모르지만, A bit이 0인 페이지는 최소한 clock hand가 한 바퀴 도는 동안 접근되지 않은 페이지이므로, 대략적인 LRU 효과를 낸다.

Enhanced Clock (A bit + D bit)

dirty bit(D bit)까지 고려하면 더 정교해진다. dirty page를 쫓아내면 디스크에 써야 하므로 비용이 크다. 그래서 clean page를 우선적으로 쫓아낸다.

QEMU 에뮬레이션

QEMU는 페이지 교체 알고리즘에 직접 관여하지 않는다 — 이는 순수 소프트웨어(OS 커널) 정책이다. 하지만 QEMU가 에뮬레이션하는 하드웨어 동작이 Clock 알고리즘의 전제 조건이다:

  1. A bit 자동 설정: 실제 CPU는 TLB miss 시 page table walk를 하면서 PTE의 A bit을 1로 설정한다. QEMU TCG의 softmmu는 store_helper()/load_helper()에서 TLB miss가 나면 tlb_fill() → x86_cpu_tlb_fill()을 호출하고, 이 과정에서 PTE의 A bit을 소프트웨어로 설정한다.

  2. D bit 자동 설정: 쓰기 접근 시 CPU가 PTE의 D bit을 1로 설정한다. QEMU TCG는 쓰기 경로의 tlb_fill()에서 is_write=true일 때 D bit을 함께 설정한다.

  3. TLB flush: PintOS가 pml4_set_accessed()로 A bit을 0으로 리셋한 뒤 invlpg를 실행하면, QEMU TCG는 해당 가상 주소의 softmmu TLB 엔트리를 무효화한다. 다음 접근 시 다시 page walk가 발생하고 A bit이 재설정된다.

Belady’s Anomaly

FIFO 알고리즘에서 프레임 수를 늘렸는데 오히려 page fault가 증가하는 현상이다. LRU와 Optimal은 stack algorithm이므로 이 현상이 발생하지 않는다. Second-Chance/Clock은 LRU의 근사지만 stack algorithm은 아니므로 reference string에 따라 Belady’s anomaly가 발생할 수 있다.

이 현상은 FIFO가 “오래된 페이지”를 쫓아내는데, 오래됐다고 안 쓰이는 건 아니기 때문이다. LRU는 “오래 전에 접근된 페이지”를 쫓아내므로 이 문제가 없다.

페이지 교체 알고리즘 점검

  • 페이지 교체는 “어떤 frame을 비울 것인가”를 고르는 OS 정책이다. QEMU는 A/D bit 같은 하드웨어 효과를 재현하지만 victim 선택 정책은 모른다.
  • Clock은 A bit이 1인 page에 second chance를 주고, A bit을 0으로 내린 뒤 다음 후보로 넘어간다.
  • victim이 정해진 뒤에는 page type을 봐야 한다. anonymous page는 swap slot으로 나가고, file-backed dirty page는 원본 파일에 write-back한다.
  • file-backed clean page는 다시 파일에서 읽을 수 있으므로 디스크에 다시 쓰지 않고 버릴 수 있다.
  • A bit을 0으로 내린 뒤에는 TLB에 남은 오래된 접근 정보가 판단을 흐리지 않도록 flush/invalidate가 필요하다.
