Disk sector는 QEMU block backend에서 어떤 byte offset이 되나

Disk sector는 QEMU block backend에서 어떤 byte offset이 되나

한 줄 요약: PintOS의 sector 번호가 QEMU block backend에서 sector×512 바이트 오프셋이 되는 변환.

QEMU disk sector 변화

PintOS의 disk_write(swap_disk, 24, buffer)는 “24번 sector에 512바이트를 쓴다”는 뜻이다. QEMU까지 내려가면 이 sector 번호는 24 * 512 = 12288 = 0x3000이라는 byte offset이 된다. 핵심은 숫자 자체가 아니라, 같은 위치를 가리키는 값이 층마다 다른 단위를 쓴다는 것이다. PintOS VM은 swap slot을, disk driver는 sector 번호를, QEMU IDE는 LBA sector를, QEMU block backend는 byte offset을 사용한다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

CPU/MMU 자체는 disk sector를 모른다. CPU가 아는 것은 I/O port에 값을 쓰고 읽는 것뿐이다. ATA(IDE) 프로토콜에서 disk 주소 지정은 LBA(Logical Block Addressing)를 사용하며, sector 크기는 전통적으로 512바이트다.

개념크기의미
page4096B가상 메모리 관리 단위
frame4096Bpage가 올라가는 RAM 자리
sector512Bdisk I/O 주소 단위
file offsetbyte 단위파일 안의 위치
block backend offsetbyte 단위QEMU가 host image에 I/O 요청하는 위치

실제 OS (Linux/Windows)

실제 OS도 storage를 다룰 때 유사한 층 구분이 있지만 훨씬 복잡하다.

항목LinuxWindowsPintOS
sector 크기논리/물리 sector 분리 가능, 4KB sector 장치 존재유사512B 고정
I/O 방식DMA, queue, NVMe, io_uringSCSI miniport, StorPortATA PIO만
cachepage cache + writebackcache manager없음
파일 시스템ext4/btrfs의 block mapping, journalingNTFS없음 (raw sector)
swap 관리swap area → page slot, swap PTE 인코딩pagefile.sysswap bitmap + slot

핵심은 같다: 메모리 page를 보존하려면 언젠가는 storage 주소와 byte range로 내려가야 한다.

PintOS 구현

PintOS disk layer는 sector 크기를 512B로 고정한다.

disk_write(d, sec_no, buffer) 호출 흐름:

%% PintOS disk_write가 select_sector와 output_sector를 거쳐 ATA I/O port로 내려가는 흐름
flowchart LR
  vm["PintOS VM<br/>disk_write(swap_disk, sec_no, buffer)"]
  disk_write["disk_write()<br/>channel lock 획득<br/>WRITE command (0x30)<br/>semaphore로 완료 interrupt 대기"]
  select_sector["select_sector(d, sec_no)<br/>LBA 7:0 / 15:8 / 23:16 / 27:24 분해"]
  output_sector["output_sector(c, buffer)<br/>outsw(data_port, buffer, 512/2)<br/>16-bit word 256개"]
  ata_port["ATA I/O port<br/>LBA register<br/>data port"]
  vm --> disk_write
  disk_write --> select_sector
  select_sector --> ata_port
  disk_write --> output_sector
  output_sector --> ata_port

select_sector()는 sec_no를 ATA LBA28 register에 나눈다. LBA low/mid/high에는 각각 bit 7:0, 15:8, 23:16을 기록하고, device/head register에는 bit 27:24를 기록한다. 이어서 output_sector()의 outsw(reg_data(c), buffer, DISK_SECTOR_SIZE / 2)가 512바이트를 16-bit word 256개로 전송한다.

PintOS disk 배치:

VM swap 구현은 disk_get(1, 1)로 swap disk를 잡는 것에서 시작한다.

QEMU 에뮬레이션

QEMU는 “swap slot”이나 “mmap dirty page”라는 의미를 모른다. guest가 ATA device에 보낸 명령만 처리한다.

QEMU IDE write 경로:

flowchart TD
  guest["guest<br/>ATA WRITE(0x30) command"]
  cmd["cmd_write_pio()<br/>hw/ide/core.c"]
  transfer["ide_transfer_start()<br/>512B DMA/PIO 전송"]
  sector_write["ide_sector_write()"]
  pwritev["blk_aio_pwritev()<br/>sector_num &lt;&lt; BDRV_SECTOR_BITS"]
  host["host file I/O<br/>byte offset = sector × 512"]
  guest --> cmd
  cmd --> transfer
  transfer --> sector_write
  sector_write --> pwritev
  pwritev --> host

핵심 상수:

ide_sector_write()에서의 핵심 호출:

guest RAM backing과 disk image backing은 다른 층이다. Guest Physical Memory의 guest RAM은 QEMU process의 memory region으로 backing되지만, disk sector write는 block backend를 통해 host disk image 파일로 내려간다.

ATA sector-count register

select_sector()는 LBA 주소 register뿐 아니라 reg_nsect를 1로 설정한다. 따라서 PintOS의 disk_write() 한 호출은 ATA 명령 하나로 sector 하나(512B)를 전송하며, 4KB swap page는 이러한 호출 8회로 기록된다.

값 0x3000층의미
