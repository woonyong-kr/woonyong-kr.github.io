PTE 접근 Bit (PTE Accessed Bit)

PTE 접근 Bit (PTE Accessed Bit)

확인 범위: 이 문서는 PTE accessed bit의 일반 동작 원리와 페이지 교체 정책에서의 활용 기준을 설명하고, Linux·Windows·PintOS·QEMU 관련 내용과 GDB 시나리오는 특정 구현을 이해하고 검증하기 위한 예시로 다룬다. 코드 위치·버전별 동작·실행 결과·주기와 비용 같은 수치는 해당 소스와 실제 실행 환경에서 별도로 확인해야 하며, 본문의 예상 결과는 검증 기록 자체가 아니다.

한 줄 요약: PTE의 accessed bit(bit 5)는 하드웨어(MMU)가 접근 시 자동으로 1로 켜고 소프트웨어(OS)만 0으로 지울 수 있어, 이 비대칭이 clock 같은 페이지 교체 정책의 “최근 참조” 판별 근거가 된다.

PTE 접근 Bit 상태

PTE의 **accessed bit(A bit, bit 5)**는 해당 페이지가 최근에 접근(읽기 또는 쓰기)되었는지를 나타내는 1-bit 플래그다. 하드웨어(MMU)가 자동으로 1로 설정하고, 소프트웨어(OS)만이 0으로 클리어할 수 있다. 이 비대칭적 제어 덕분에 OS는 “일정 기간 동안 접근이 있었는가?”를 판별할 수 있으며, 이것이 clock algorithm 등 페이지 교체 정책의 근간이 된다.

상세 설명

추상 개념 (CPU/MMU 하드웨어 규칙)

x86-64 PTE 64비트 중 bit 5가 accessed bit이다.

63    12 11  9  8  7  6  5  4  3  2  1  0
+------+-----+--+--+--+--+--+--+--+--+--+
| ADDR | AVL |G |  |D |A |  |  |U |W |P |
+------+-----+--+--+--+--+--+--+--+--+--+
                       ^
                       A bit (0x20)

동작 규칙:

이벤트A bit 변화주체
페이지 읽기 접근0 → 1MMU 하드웨어
페이지 쓰기 접근0 → 1MMU 하드웨어
이미 A=1인 상태에서 재접근변화 없음—
페이지 교체 정책이 클리어1 → 0OS 소프트웨어

핵심 특성:

  • 읽기와 쓰기 모두 A bit를 설정한다 (dirty bit는 쓰기만).
  • MMU가 page table walk 중 PTE를 읽을 때, present=1이고 A=0이면 A=1로 갱신한 뒤 메모리에 다시 쓴다.
  • TLB에 캐시된 동안에는 PTE 갱신이 일어나지 않을 수 있다. 따라서 A bit를 정확히 읽으려면 TLB flush가 필요할 수 있다.

실제 OS (Linux/Windows)

Linux에서 accessed bit는 두 가지 주요 용도로 쓰인다:

  • 페이지 회수(page reclaim): kswapd 데몬이 LRU 리스트를 순회하면서 A bit를 검사한다. A=1이면 active list로 승격, A=0이면 inactive list로 강등하여 회수 후보로 만든다.
  • NUMA balancing: 페이지가 어느 노드에서 접근되는지 추적할 때 A bit를 클리어하고, 다음 접근 시 page fault를 유도하여 접근 노드를 파악한다.

Windows에서는 Working Set Manager가 유사하게 A bit를 주기적으로 클리어하고, 다음 검사 시점에 A=0인 페이지를 working set에서 제거한다.

threads/mmu.c에 읽기/쓰기 API가 있다:

pml4_set_accessed에서 invlpg 호출이 핵심이다. A bit를 소프트웨어로 클리어한 뒤, TLB에 남아있는 이전 매핑(A=1)을 무효화해야 다음 접근 시 MMU가 PTE를 다시 읽고 A bit를 정확히 재설정한다.

Clock algorithm에서의 사용 흐름:

clock hand가 frame을 가리킴
  → pml4_is_accessed(owner->pml4, page->va) 검사
     → A=1: "second chance" — pml4_set_accessed(..., false)로 클리어, 다음으로 이동
     → A=0: victim으로 선택, 이 frame을 evict

QEMU 에뮬레이션

QEMU TCG 모드에서는 실제 MMU 하드웨어 없이 소프트웨어로 page table walk를 에뮬레이트한다. guest가 메모리에 접근하면:

  1. QEMU의 softmmu가 guest PTE를 읽는다 (RAMBlock 내 guest physical memory에 저장된 PTE).
  2. present=1이고 A=0이면, QEMU가 PTE의 A bit를 1로 갱신하고 guest physical memory에 다시 쓴다.
  3. 쓰기 접근이면 D bit도 동시에 설정한다.

이 동작은 x86_cpu_tlb_fill() → mmu_translate() 경로에서 일어나며, 실제 x86 하드웨어의 동작을 충실히 재현한다. QEMU의 TLB 캐시(softmmu TLB)에 매핑이 있는 동안에는 PTE 갱신을 건너뛰는데, 이것도 하드웨어 TLB와 동일한 의미다.

GDB로 guest PTE를 직접 검사할 수 있다:

(gdb) x/gx $cr3_base + pml4_index*8    # PML4 entry
(gdb) # ... walk하여 최종 PTE 주소 계산
(gdb) x/gx <pte_addr>                   # PTE 값 확인
(gdb) p/x <pte_val> & 0x20              # A bit 추출

PTE 접근 Bit 값 추적

항목값
A bit 위치PTE bit 5 (0x20)
PTE 크기8 bytes (64-bit)
A bit 갱신 비용MMU가 PTE를 메모리에 write-back (8-byte atomic write)

clock 순회당 A bit 검사frame_table 크기만큼 (최대 user pool 프레임 수)
PintOS user pool약 367개 프레임 (기본 QEMU 메모리 설정)

예: PTE 값이 0x0000000012345067이면:

  • bit 5 = 1 → A=1 (접근됨)
  • bit 6 = 1 → D=1 (수정됨)
  • bit 0 = 1 → P=1 (존재)
  • bit 1 = 1 → W=1 (쓰기 가능)
  • bit 2 = 1 → U=1 (유저 접근 가능)

순서도

flowchart TD
    A[프로세스가 VA 접근] --> B{TLB hit?}
    B -->|Yes| C[TLB 캐시 사용 - A bit 갱신 없음]
    B -->|No| D[MMU page table walk]
    D --> E{PTE present?}
    E -->|No| F[#PF Page Fault]
    E -->|Yes| G{A bit = 1?}
    G -->|Yes| H[그대로 접근 허용]
    G -->|No| I[MMU가 A bit = 1로 설정]
    I --> J[PTE를 메모리에 write-back]
    J --> K[TLB에 캐시]
    K --> H

관찰 시나리오

시나리오 1: clock algorithm의 second

목표: eviction 시 A=1인 frame에 second chance가 부여되고, A=0으로 클리어된 뒤 다음 순회에서 victim으로 선택되는 과정을 관찰한다.

절차:

  1. 메모리를 고갈시키는 프로그램(mmap-multiple 등)을 실행하여 eviction을 유발
  2. GDB 스크립트 1, 2를 설정하고 vm_frame_accessed / vm_frame_set_accessed 호출을 추적
  3. 같은 frame이 첫 순회에서 A=1 → 클리어, 두 번째 순회에서 A=0 → victim 선택되는 것을 확인

예상 결과:

[A-bit] is_accessed: va=0x40001000 PTE=0x...67 A=1     ← 첫 순회: 접근됨
[A-bit] clear: va=0x40001000 PTE_before=0x...67 PTE_after=0x...47 invlpg=1
   ... (clock hand가 한 바퀴 돌고 다시 도착)
[A-bit] is_accessed: va=0x40001000 PTE=0x...47 A=0     ← 두 번째 순회: victim

시나리오 2: COW frame의 다중 owner A bit 검사

목표: fork 후 COW 공유 frame은 여러 owner가 있다. 부모만 접근하고 자식은 접근하지 않았을 때, 부모의 A=1 하나만으로 frame 전체가 accessed로 판정되는 것을 확인한다.

절차:

  1. fork 후 부모만 해당 페이지를 읽는 테스트 실행
  2. GDB 스크립트 3으로 owner 순회 관찰
  3. 부모의 PTE는 A=1, 자식의 PTE는 A=0이지만, vm_frame_accessed가 true를 반환하는 것을 확인

예상 결과:

[A-bit] owner[0] thread=main va=0x40002000 accessed=1    ← 부모: 접근됨
[A-bit] owner[1] thread=child va=0x40002000 accessed=0   ← 자식: 미접근
[A-bit] frame 0x...: 2 owners, accessed=1                ← 하나라도 1이면 true

PTE 접근 Bit 점검

  • A bit는 읽기와 쓰기 접근 모두에서 CPU/MMU가 1로 세우는 “최근 접근” 신호다.
  • OS가 A bit를 0으로 내린 뒤 TLB entry를 무효화해야 다음 접근이 다시 page table walk를 거쳐 A bit를 세울 수 있다.
  • 현재 PintOS는 vm_frame_accessed()에서 COW owner들의 PTE를 모두 보며, 하나라도 A=1이면 frame 전체를 최근 접근된 것으로 본다.
  • vm_frame_set_accessed(frame, false)는 owner들의 A bit를 같이 내려 clock algorithm의 second chance를 구현한다.
  • D bit는 쓰기 여부를 알려주는 별도 신호라서, victim 선택보다는 swap/file write-back 판단과 함께 읽는다.
