인터럽트 활성화/비활성화 — intr_enable · intr_disable · intr_set_level

인터럽트 활성화/비활성화 — intr_enable · intr_disable · intr_set_level

확인 범위: 이 문서는 인터럽트 활성화·비활성화의 일반 원리와 사용 기준을 설명하고, 입력에 제시된 PintOS·Linux·Windows·QEMU의 코드와 동작을 구현 사례로 다룬다. 구체적인 코드 좌표와 버전별 구현 일치 여부, GDB 실행 기록, 실행 시간과 성능에 관한 판단은 해당 소스·환경에서 별도로 검증해야 한다.

intr_disable()과 intr_enable()은 RFLAGS의 IF 비트를 바꿔, 짧은 커널 코드 구간이 타이머 인터럽트에 끊기지 않도록 만든다.

인터럽트 활성화/비활성화 변화

intr_disable()과 intr_enable()은 CPU의 인터럽트 수신을 끄고 켜는 함수다. 인터럽트가 꺼진 동안에는 타이머 인터럽트를 포함한 모든 외부 인터럽트가 CPU에 도달하지 않으므로, 코드가 중단 없이 실행된다. PintOS에서 이것은 가장 원시적인 동기화 메커니즘이다. 세마포어, 락, 조건 변수가 모두 내부적으로 intr_disable()을 사용해 임계 구역을 보호한다.

상세 설명

추상 개념 (CPU 하드웨어 규칙)

x86-64 CPU에는 RFLAGS 레지스터의 비트 9에 IF(Interrupt Flag)가 있다. IF=1이면 CPU는 INTR 핀의 외부 인터럽트를 수락하고, IF=0이면 무시한다.

두 가지 특권 명령어가 IF를 제어한다:

명령어동작opcode크기
cliIF ← 0 (인터럽트 비활성화)0xFA1 byte
stiIF ← 1 (인터럽트 활성화)0xFB1 byte

이 명령어들은 ring 0(커널 모드)에서만 실행 가능하다. 유저 모드(ring 3)에서 cli를 실행하면 gp(General Protection) 예외가 발생한다. 이것은 유저 프로그램이 인터럽트를 끄고 CPU를 독점하는 것을 방지하는 보호 메커니즘이다.

IF가 제어하는 것은 마스크 가능한(maskable) 외부 인터럽트뿐이다. NMI(Non-Maskable Interrupt), CPU가 명령 실행 중 생성하는 예외(page fault, divide-by-zero 등), software interrupt는 IF=0이어도 발생할 수 있다.

인터럽트 유형IF=0일 때예시
외부 인터럽트 (IRQ)차단됨타이머(IRQ0), 키보드(IRQ1), 디스크(IRQ14)
NMI차단 안 됨메모리 패리티 에러, 워치독 타이머
CPU 예외차단 안 됨pf(page fault), gp, de(divide error)
int n 명령어차단 안 됨int 0x80 (Linux 32-bit syscall)

실제 OS (Linux/Windows)

Linux: local_irq_disable() / local_irq_enable()로 IF를 제어한다. 이것은 현재 CPU의 인터럽트만 끈다. SMP 환경에서는 다른 CPU가 여전히 인터럽트를 받으므로, 인터럽트 비활성화만으로는 불충분하다. 그래서 spinlock과 조합해 spin_lock_irqsave()를 사용한다: 인터럽트를 끄고(로컬 CPU 보호) + spinlock을 잡는다(다른 CPU 보호).

패턴LinuxPintOS
인터럽트 끄기local_irq_disable() → cliintr_disable() → cli
인터럽트 켜기local_irq_enable() → stiintr_enable() → sti
이전 상태 저장/복원local_irq_save(flags) / local_irq_restore(flags)intr_set_level(old_level)
스핀락 + 인터럽트spin_lock_irqsave()불필요 (단일 CPU)

Windows: IRQL(Interrupt Request Level)로 인터럽트 우선순위를 단계적으로 제어한다. KeRaiseIrql(DISPATCH_LEVEL)은 그 이하 수준의 실행을 막지만, 더 높은 DIRQL의 device interrupt까지 모두 차단하지는 않는다. PintOS의 on/off 이진 모델보다 세밀하다.

PintOS 구현

PintOS는 threads/interrupt.c에 4개의 핵심 함수를 제공한다.

intr_get_level() — 현재 IF 상태를 읽는다 (interrupt.c:150):

pushfq가 RFLAGS 전체를 스택에 push하고, popq가 변수로 꺼낸 뒤 IF 비트(비트 9, 0x200)를 확인한다.

intr_disable() — 인터럽트를 끈다 (interrupt.c:195):

"memory" clobber는 컴파일러에게 “이 명령어 앞뒤로 메모리 접근 순서를 바꾸지 마라”고 지시한다. cli 전에 있어야 할 메모리 쓰기가 cli 뒤로 밀려나면 임계 구역이 깨질 수 있기 때문이다.

intr_enable() — 인터럽트를 켠다 (interrupt.c:177):

ASSERT로 인터럽트 핸들러 안에서 sti를 호출하는 것을 방지한다. 인터럽트 핸들러 안에서 인터럽트를 켜면 중첩 인터럽트가 발생하고, PintOS는 이를 지원하지 않는다.

intr_set_level() — 저장된 상태로 복원한다 (interrupt.c:169):

사용 패턴

PintOS에서 인터럽트 비활성화의 표준 패턴:

intr_set_level(old_level) 대신 intr_enable()을 직접 호출하면 안 되는 이유: 이미 인터럽트가 꺼진 상태에서 호출된 함수라면, 끝난 뒤에도 꺼진 상태를 유지해야 한다. old_level이 INTR_OFF였으면 복원 시에도 꺼진 채로 둔다.

QEMU 에뮬레이션

QEMU TCG에서 cli와 sti 명령어는 CPUX86State.eflags의 IF 비트를 직접 조작하는 것으로 에뮬레이션된다.

명령어TCG 동작CPUX86State 변화
clienv->eflags &= ~IF_MASKIF 비트 0으로 클리어
stienv->eflags |= IF_MASKIF 비트 1로 설정

sti 실행 후, QEMU는 다음 명령어를 실행한 뒤에야 대기 중인 인터럽트를 주입한다. 이것은 실제 x86 하드웨어의 “STI blocking” 동작을 재현한 것이다: sti 직후 1 명령어는 인터럽트 없이 실행된다. 이 규칙 덕분에 sti; hlt 패턴에서 hlt 전에 인터럽트가 끼어들지 않는다.

인터럽트 비활성화 시간 제약

PintOS의 타이머 인터럽트는 100 Hz (10 ms 간격)로 발생한다. 인터럽트가 10 ms 이상 꺼져 있으면 타이머 tick을 놓친다.

항목값
TIMER_FREQ100 Hz
tick 간격10 ms (10,000,000 ns)
cli, sti, pushfq; popq와 임계 구역의 시간은 CPU microarchitecture, virtualization, cache와 코드 경로에 의존한다. 고정 cycle/ns 값으로 단정하지 않는다. 검증해야 할 invariant는 인터럽트를 끈 구간이 sleep·blocking 없이 짧고 bounded해야 한다는 점이다.
