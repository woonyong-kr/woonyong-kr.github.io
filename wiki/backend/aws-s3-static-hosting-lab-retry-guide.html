AWS S3 정적 웹 호스팅 실습 재도전 가이드

S3 정적 호스팅 실습은 서버를 직접 띄우지 않고도 HTML과 이미지를 웹으로 공개해 보고, 그 페이지를 ALB 기반 웹 앱으로 이어 붙이는 연습이다.

S3는 파일을 객체로 저장하는 서비스다. 이번 실습에서는 이미지와 index.html을 S3 bucket에 올리고, 정적 웹 사이트 호스팅을 켜서 ALB 기반 웹 앱으로 이동하는 작은 프런트 페이지를 만든다.

이 문서의 핵심은 S3가 서버가 아니라 “객체 저장소”라는 점이다. 정적 호스팅은 HTML, 이미지, CSS처럼 실행 없이 내려줄 수 있는 파일에 적합하다.

AWS S3 정적 웹 호스팅 실습 구분

  • S3를 알면
    • 서버 없이 정적 파일을 배포할 수 있다.
    • 웹 앱이 쓰는 이미지, 다운로드 파일, 정적 프런트 파일을 분리할 수 있다.
  • 정적 웹 호스팅을 알면
    • bucket endpoint와 object URL, 퍼블릭 접근 정책의 차이를 구분할 수 있다.
  • versioning을 알면
    • 같은 object key를 다시 올렸을 때 이전 버전을 보존할 수 있다.

AWS S3 정적 웹 호스팅 실습 흐름

S3의 기본 단위는 bucket과 object다.

  • bucket
    • 객체를 담는 최상위 컨테이너다.
    • 이름은 전 세계에서 고유해야 한다.
  • object
    • key와 content로 저장되는 파일이다.
    • 예: index.html, aws.png
  • static website hosting
    • S3가 index.html을 웹 페이지처럼 응답하게 한다.

1단계: Bucket 만들기

  • Bucket name
    • 예: immersion-day-user-name
    • 전 세계 고유 이름이어야 하므로 자신의 식별자를 붙인다.
  • Object Ownership
    • 실습 안내에 맞춰 ACL 옵션을 설정한다.
    • 개인 계정에서는 public access를 열기 전에 정책을 다시 확인한다.
  • Block Public Access
    • 실습에서는 정적 웹 접근을 위해 일부 설정이 필요할 수 있다.
    • 공개 bucket은 비용보다 보안 위험이 더 크므로, 실습 후 반드시 닫거나 삭제한다.

2단계: Object 업로드

  • 업로드 파일
    • aws.png
    • index.html
  • index.html이 하는 일
    • S3 object URL의 이미지를 보여준다.
    • ALB DNS 주소로 이동하는 동작을 넣는다.

ALB DNS는 EC2/ALB/Auto Scaling 실습이 끝난 뒤 얻는다. 아직 ALB가 없다면 index.html은 나중에 수정해 다시 업로드하면 된다.

3단계: Static Website Hosting 켜기

  • bucket properties
    • Static website hosting: enabled
    • index document: index.html
  • 확인
    • website endpoint를 브라우저에 붙인다.
    • HTML이 열리고 이미지가 보이는지 확인한다.
    • ALB로 이동하는 링크나 버튼이 맞는지 확인한다.

object URL과 website endpoint는 다르다.

  • object URL
    • 특정 object 하나를 직접 가리킨다.
    • 예: 이미지 파일 하나.
  • website endpoint
    • bucket을 웹 사이트처럼 열고, index document를 기본 응답으로 쓴다.

4단계: Versioning 켜기

  • Versioning
    • bucket versioning을 enabled로 바꾼다.
    • 수정한 index.html을 다시 업로드한다.
  • 의미
    • 같은 key라도 이전 버전이 남는다.
    • 실수로 덮어쓴 파일을 되돌릴 수 있다.

AWS S3 정적 웹 호스팅 실습 콘솔

  • S3
    • bucket에 index.html과 aws.png가 있는가
    • object 권한이나 bucket policy 때문에 403이 나지 않는가
    • website endpoint가 index.html을 반환하는가
  • ALB 연결
    • HTML 안의 ALB DNS가 최신 값인가
    • ALB target group이 healthy인가
  • Versioning
    • 업로드 후 object versions가 보이는가

자주 막히는 지점

  • “S3 object는 보이는데 website endpoint가 안 열린다”
    • static website hosting이 꺼져 있거나 index document 이름이 다를 수 있다.
  • “403 AccessDenied가 뜬다”
    • public access block, bucket policy, object ACL을 함께 확인한다.
    • 실습 후에는 공개 설정을 반드시 되돌리거나 bucket을 삭제한다.
  • “ALB로 이동이 안 된다”
    • index.html 안의 ALB DNS가 이전 값일 수 있다.
    • ALB 자체가 삭제되었거나 target이 unhealthy일 수 있다.
