AVL 트리

AVL 트리

한 줄 요약: 이진 탐색 트리(BST)는 입력 순서가 나쁘면 한쪽으로 기울어 탐색이 O(n)으로 느려진다. AVL 트리는 삽입·삭제마다 각 노드의 좌우 높이 차이를 검사하고, 1을 넘으면 회전(rotation)으로 즉시 바로잡아 트리 높이를 항상 O(log n)으로 묶는다.

AVL 트리 필요성

이진 탐색 트리(Binary Search Tree)에 값을 넣을 때는 새 값과 현재 노드를 비교한다. 새 값이 작으면 왼쪽으로, 크면 오른쪽으로 내려가 빈 자리에 붙인다. 이 규칙만으로는 트리의 모양이 정해지지 않으며, 탐색 시간은 만들어진 트리의 높이에 좌우된다. 트리가 고르게 퍼져 높이가 O(log n)으로 유지되면 탐색도 O(log n)에 할 수 있다.

문제는 입력 순서다. 이미 정렬된 데이터 1, 2, 3, 4, 5를 차례로 넣어 보자. 1이 루트가 되고, 2는 1보다 크니 오른쪽, 3은 다시 오른쪽, 4도 오른쪽… 결국 오른쪽으로만 쭉 뻗은 막대가 된다.

%% 정렬 입력이 만든 편향 BST
flowchart TD
  n1["1"]
  n2["2"]
  n3["3"]
  n4["4"]
  n5["5"]
  n1 --> n2
  n2 --> n3
  n3 --> n4
  n4 --> n5

이건 트리가 아니라 사실상 연결 리스트다. 5를 찾으려면 노드 5개를 전부 거쳐야 한다. 높이가 n에 비례하니 탐색이 O(n)으로 떨어진다. BST를 쓴 이유가 통째로 사라진다.

이 편향(skew)을 막으려면 “트리가 한쪽으로 기울면 자동으로 펴 주는” 장치가 필요하다. AVL 트리가 바로 그 장치다. 1962년 두 고안자(Adelson-Velsky, Landis)의 이름을 딴 이 트리는, 모든 노드에서 좌우 높이 차이를 1 이하로 강제한다. 차이가 2가 되는 순간 회전으로 즉시 되돌린다.

이 개념은 다음 내용을 이해하는 바탕이 된다.

  • 왜 레드 블랙 트리가 “느슨한 균형”으로 같은 O(log n)을 더 싸게 달성하는지
  • 데이터베이스 인덱스와 B Tree가 균형을 유지하려고 무슨 일을 하는지
  • “균형 트리”라는 말이 정확히 무엇을 보장하는지 (최악의 경우에도 O(log n))

먼저 균형 인수로 기울어진 정도를 판단한다. 그런 다음 LL·RR·LR·RL 회전이 각각 어떤 모양을 어떻게 펴는지 따라간다.

AVL 트리 흐름

균형 인수 — 기울어진 정도를 숫자로 잰다

먼저 트리가 “얼마나 기울었는지”를 숫자로 측정해야 한다. 그래야 기준을 넘었는지 판단할 수 있다. 이 숫자가 균형 인수(balance factor)다.

어떤 노드의 균형 인수는 다음과 같이 정의한다.

균형 인수 = (왼쪽 서브트리 높이) - (오른쪽 서브트리 높이)

여기서 높이(height)는 그 노드에서 가장 먼 리프까지 내려가는 간선의 수다. 빈 트리의 높이는 -1, 리프 하나의 높이는 0으로 둔다.

AVL 트리의 불변식(invariant)은 단 하나다. 모든 노드의 균형 인수가 -1, 0, +1 중 하나여야 한다. 균형 인수가 +2나 -2가 되는 순간 그 노드는 “AVL 위반” 상태이고, 회전으로 고쳐야 한다.

앞의 막대 트리에서 루트 1의 왼쪽 높이는 -1(비어 있음), 오른쪽 높이는 3이다. 균형 인수는 -1 - 3 = -4. 한참 위반이다. AVL 트리라면 이 지경까지 가기 전에 매 삽입마다 고쳤을 것이다.

왜 균형 인수 1이면 높이가 O(log n)인가?

질문: 균형 인수를 1 이하로만 묶으면 정말 높이가 로그로 유지되는가?

이걸 거꾸로 본다. “높이가 h인 AVL 트리를 만들려면 노드가 최소 몇 개 필요한가?”를 따진다. 최소 노드 수를 N(h)라고 하자. 높이 h 트리의 루트는, 한쪽 서브트리 높이가 h-1이고 다른 쪽은 균형 인수 1을 꽉 채워 h-2여야 가장 헐겁다.

N(h) = N(h-1) + N(h-2) + 1
N(0) = 1   (리프 하나)
N(1) = 2   (루트 + 자식 하나)

이 점화식은 피보나치 수열과 같은 꼴이다. 피보나치는 대략 황금비 φ ≈ 1.618의 거듭제곱으로 커진다. 즉 N(h)는 약 φ^h 만큼 커진다.

N(h) ≈ φ^h  이면  h ≈ log_φ N
log_φ N = log N / log φ ≈ 1.44 × log₂ N

결론: 노드가 N개일 때 AVL 트리의 높이는 최악이라도 약 1.44 × log₂ N을 넘지 않는다. 완벽한 균형(log₂ N)보다 44% 정도 더 깊을 수 있지만, 여전히 O(log n)이다. 균형 인수를 1로 묶는 것만으로 최악의 높이가 로그에 갇힌다.

네 가지 회전 — 기울어진 모양을 펴는 동작

균형 인수가 ±2가 되면 회전으로 편다. 위반이 어느 방향에서 왔는지에 따라 네 경우로 갈린다. 이름은 “위반 노드에서 문제가 생긴 자식·손자 방향”을 따른다.

  • LL(Left-Left): 왼쪽 자식의 왼쪽이 무거움 → 오른쪽 회전 한 번
  • RR(Right-Right): 오른쪽 자식의 오른쪽이 무거움 → 왼쪽 회전 한 번
  • LR(Left-Right): 왼쪽 자식의 오른쪽이 무거움 → 자식을 왼쪽 회전 후, 위반 노드를 오른쪽 회전
  • RL(Right-Left): 오른쪽 자식의 왼쪽이 무거움 → 자식을 오른쪽 회전 후, 위반 노드를 왼쪽 회전

가장 기본인 LL을 보자. 노드 30이 왼쪽으로 무거워 균형 인수가 +2가 됐다.

%% LL 위반과 오른쪽 회전
flowchart TD
  b30_r["b30_r"]
  b20_r["b20_r"]
  b30["30<br/>BF +2"]
  b20["20"]
  b10["10"]
  a20["20"]
  a10["10"]
  a30["30"]
  b30 --> b20
  b30 --> b30_r
  b20 --> b10
  b20 --> b20_r
  a20 --> a10
  a20 --> a30
  b30 --> a20

오른쪽 회전(rotate right)은 왼쪽 자식 20을 위로 끌어올리고, 원래 루트 30을 그 오른쪽 자식으로 내린다. 세 노드의 부모-자식 관계만 바꾸면 끝이고, BST 정렬 순서(10 < 20 < 30)는 그대로 보존된다. 높이가 한 단 줄어 균형이 맞는다.

LR은 한 번에 안 펴진다. 꺾인 모양이라 먼저 곧게 편 뒤 회전한다.

%% LR 위반과 두 단계 회전
flowchart TD
  b30_r["b30_r"]
  b10_l["b10_l"]
  m30_r["m30_r"]
  m20_r["m20_r"]
  b30["30<br/>BF +2"]
  b10["10"]
  b20["20"]
  m30["30"]
  m20["20"]
  m10["10"]
  a20["20"]
  a10["10"]
  a30["30"]
  b30 --> b10
  b30 --> b30_r
  b10 --> b10_l
  b10 --> b20
  m30 --> m20
  m30 --> m30_r
  m20 --> m10
  m20 --> m20_r
  a20 --> a10
  a20 --> a30
  b30 --> m30
  m30 --> a20

LR은 “자식을 회전해 LL 모양으로 만든 뒤, 다시 LL 회전”이라는 2단계다. RR과 RL은 LL·LR의 좌우 대칭이다.

다른 균형 트리와의 차이

  • AVL 트리: 균형 인수를 ±1로 빡빡하게 묶는다. 트리가 더 납작해 탐색이 빠르다. 대신 삽입·삭제 때 회전이 자주 일어나 쓰기가 상대적으로 비싸다.
  • 레드 블랙 트리: 색 규칙으로 “최장 경로가 최단 경로의 2배를 넘지 않게”만 묶는다. 균형이 느슨해 트리가 약간 더 깊지만, 삽입·삭제 시 회전·재색칠이 적어 쓰기가 싸다.

읽기가 압도적으로 많으면 AVL, 삽입·삭제가 잦으면 레드-블랙을 고른다. 그래서 C++ std::map이나 리눅스 커널은 레드-블랙을, 읽기 위주 인메모리 인덱스는 AVL을 즐겨 쓴다.

AVL 트리 코드

먼저 노드를 정의한다. 일반 BST 노드와 다른 점은 height 필드를 직접 들고 다니는 것이다. 높이를 매번 새로 세면 O(n)이 들지만, 노드에 저장해 두면 자식 둘의 높이만 보고 O(1)에 갱신할 수 있다.

get_balance가 반환하는 값이 핵심 판단 기준이다. 이 값이 +2 또는 -2면 그 노드에서 회전이 필요하다.

다음은 회전이다. 부모-자식 포인터 세 개만 바꾸고, 바뀐 두 노드의 높이를 다시 계산한다. BST 순서는 회전 전후로 보존된다.

회전 함수가 새 부모를 return하는 이유는, 호출한 쪽이 그 반환값을 자기 자식 포인터에 다시 연결하기 때문이다. 즉 회전은 “이 서브트리의 새 뿌리를 돌려준다”.

이제 삽입이다. 일반 BST처럼 내려가 붙인 뒤, 재귀가 되돌아 올라오는 길에 각 노드의 높이를 갱신하고 균형을 검사한다. 위반이면 네 경우 중 하나로 회전한다.

이 코드에서 기억할 것은 두 가지다. 첫째, 재균형은 삽입한 지점에서가 아니라 재귀가 되돌아 올라오는 경로의 각 노드에서 일어난다. 둘째, balance 부호와 새 키의 위치를 함께 보고 LL·RR·LR·RL을 가른다. 위반 노드 하나만 고치면 그 위 조상들의 균형도 자동으로 회복된다 — 삽입으로 늘어난 높이가 회전으로 원래대로 줄기 때문이다.

정렬된 입력 1, 2, 3을 넣어 보면 차이가 분명하다. 3을 넣는 순간 루트 1의 균형 인수가 -2(RR)가 되고, rotate_left가 2를 루트로 올린다.

%% 정렬 입력 1, 2, 3 삽입 후 RR 재균형
flowchart TD
  i1_l["i1_l"]
  i2_l["i2_l"]
  v1_l["v1_l"]
  v2_l["v2_l"]
  i1["1"]
  i2["2"]
  i3["3"]
  v1["1<br/>BF -2"]
  v2["2"]
  v3["3"]
  b2["2"]
  b1["1"]
  b3["3"]
  i1 --> i1_l
  i1 --> i2
  i2 --> i2_l
  i2 --> i3
  v1 --> v1_l
  v1 --> v2
  v2 --> v2_l
  v2 --> v3
  b2 --> b1
  b2 --> b3
  i1 --> v1
  v1 --> b2

막대가 될 뻔한 트리가 높이 1짜리 균형 트리로 펴졌다. 탐색은 O(n)이 아니라 O(log n)을 유지한다.

정리

AVL 트리는 모든 노드의 좌우 높이 차이(균형 인수)를 ±1 이하로 강제하는 이진 탐색 트리다. 삽입·삭제 후 재귀가 되돌아 올라오며 균형 인수를 검사하고, ±2가 되면 LL·RR·LR·RL 네 경우 중 하나로 회전해 즉시 편다. 최소 노드 수 점화식이 피보나치와 같은 꼴이라, 높이는 최악이라도 약 1.44 × log₂ N으로 갇힌다. 덕분에 정렬된 입력이 들어와도 탐색·삽입·삭제 모두 O(log n)을 보장한다. 균형을 빡빡하게 잡는 만큼 트리가 납작해 읽기가 빠르고, 대신 쓰기마다 회전 비용을 치른다. 읽기가 많으면 AVL, 쓰기가 많으면 레드-블랙이 유리하다는 판단 기준을 가져가면 된다.

함께 보면 좋은 개념.

  • 레드 블랙 트리
    • AVL의 빡빡한 균형 대신 색 규칙으로 균형을 느슨하게 잡아 쓰기 비용을 줄이는 트리다. AVL과 같은 O(log n)을 어떻게 더 싸게 달성하는지 비교하며 읽으면 두 트리의 트레이드오프가 선명해진다.
  • B Tree와 B+Tree
    • 한 노드에 자식을 둘이 아니라 수백 개 두어, 디스크에서 높이를 더 낮추는 균형 트리다. AVL의 “회전으로 높이를 묶는다”는 발상이 디스크 환경에서 어떻게 달라지는지 확인한다.
  • 시간 복잡도
    • AVL이 보장하는 O(log n)과 편향 BST의 O(n)이 입력이 커질 때 실제로 얼마나 벌어지는지, 복잡도 표기의 기준을 잡는다.
