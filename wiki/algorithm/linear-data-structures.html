선형 자료구조

선형 자료구조

한 줄 요약: 배열과 연결 리스트는 데이터를 메모리에 늘어놓는 두 가지 물리적 방법이고, 스택과 큐는 그 위에 “어느 쪽으로 넣고 빼는가”라는 규칙을 씌운 사용 패턴이며, 무엇을 고를지는 접근·삽입·삭제 중 무엇을 빠르게 하고 싶은지로 갈린다.

선형 자료구조 문제

데이터 여러 개를 메모리에 어떻게 둘 것인가? 이 질문은 사소해 보이지만 프로그램 성능의 출발점이다. 같은 100만 개의 숫자를 다뤄도, 어떻게 늘어놓느냐에 따라 “특정 위치 읽기”가 즉시 끝날 수도 있고, “중간에 하나 끼워 넣기”가 100만 번의 이동을 부를 수도 있다.

근본 갈등은 하나다. 메모리를 딱 붙여서 두면 위치 계산으로 즉시 접근할 수 있지만, 중간에 끼우려면 뒤를 전부 밀어야 한다. 반대로 데이터를 흩어 두고 화살표로 연결하면 끼워 넣기는 화살표만 바꾸면 되지만, n번째를 찾으려면 처음부터 화살표를 따라가야 한다. 이 맞교환을 모르면 다음을 판단할 수 없다.

  • 왜 배열 인덱스 접근 arr[i]는 O(1)이고 연결 리스트의 i번째 접근은 O(n)인가
  • 왜 큐는 연결 리스트로, 스택은 배열로 구현해도 무방한가
  • PintOS 커널이 struct list를 이중 연결 리스트로 짠 이유는 무엇인가
  • 함수 호출이 왜 하필 “스택”이라는 이름의 구조를 쓰는가

이 문서를 읽으면 네 자료구조의 차이를 메모리 배치로 설명할 수 있고, 상황에 맞는 것을 고를 수 있다.

선형 자료구조 흐름

비유 — 붙어 앉은 관객석 vs 보물찾기 쪽지

배열은 번호가 매겨진 극장 좌석이다. 모든 좌석이 일정한 간격으로 붙어 있어서, “37번 좌석”은 입구에서 37 × 좌석 폭만큼 떨어진 곳이라고 즉시 계산된다. 누구를 거치지 않고 곧장 간다. 하지만 5번과 6번 사이에 새 좌석을 끼우려면 6번부터 끝까지 전부 한 칸씩 옆으로 옮겨야 한다.

연결 리스트는 보물찾기 쪽지다. 첫 쪽지에 “다음은 화단 아래”라고 적혀 있고, 거기 또 다음 위치가 적혀 있다. 데이터가 어디에 흩어져 있든 쪽지의 화살표만 따라가면 된다. 중간에 새 보물을 끼우려면 쪽지 두 장의 화살표만 고치면 된다. 대신 50번째 보물을 보려면 처음부터 49번 따라가야 한다.

정의 — 두 가지 물리 구조

  • 배열(array): 같은 크기의 원소를 메모리에 연속으로 늘어놓은 구조.
    • 임의 접근(random access): 시작 주소 + 인덱스 × 원소 크기로 i번째에 O(1)에 도달.
    • 삽입·삭제: 중간에 넣거나 빼면 뒤 원소를 모두 이동해야 하므로 O(n).
  • 연결 리스트(linked list): 각 원소(노드)가 데이터와 **다음 노드의 주소(포인터)**를 함께 들고 흩어져 있는 구조.
    • 접근: i번째에 가려면 처음부터 포인터를 따라가므로 O(n).
    • 삽입·삭제: 위치를 알고 있으면 포인터 몇 개만 고쳐 O(1).

배열은 주소가 규칙적이라 곱셈 한 번으로 위치를 안다. 연결 리스트는 주소가 제각각이라 화살표를 직접 밟아야 한다. 이 그림 하나가 “배열 접근 O(1), 리스트 접근 O(n)“의 전부다.

왜 배열 접근이 진짜로 더 빠른가? — 캐시까지 보면

같은 O(1)·O(n) 너머에 실제 속도 차가 하나 더 있다. CPU는 메모리를 읽을 때 한 바이트가 아니라 캐시 라인(보통 64바이트) 단위로 끌어온다. 배열은 원소가 붙어 있어 arr[0]을 읽는 순간 arr[1], arr[2]…가 같은 캐시 라인에 함께 딸려 온다. 반복 순회가 캐시 적중으로 빨라진다. 연결 리스트는 노드가 흩어져 있어 노드마다 새 캐시 라인을 불러야 한다. 그래서 “순회”만 놓고 보면 같은 O(n)이라도 배열이 현실에서 훨씬 빠르다. 이 차이가 CPU 캐시의 지역성(locality) 효과다.

스택과 큐 — 구조가 아니라 규칙이다

배열과 연결 리스트가 “어떻게 놓느냐”라면, 스택과 큐는 “어느 쪽으로 넣고 빼느냐”라는 접근 규칙이다. 둘 다 배열로도, 연결 리스트로도 구현할 수 있다.

  • 스택(stack): LIFO(Last In, First Out). 나중에 넣은 것이 먼저 나온다. 접시를 쌓았다가 위에서부터 꺼내는 것과 같다. push(넣기)와 pop(빼기)이 같은 쪽 끝에서 일어난다.
  • 큐(queue): FIFO(First In, First Out). 먼저 넣은 것이 먼저 나온다. 줄 서기와 같다. enqueue는 뒤에서, dequeue는 앞에서 일어난다.

스택은 함수 호출에 쓰인다. 가장 최근에 부른 함수가 가장 먼저 끝나기 때문이다(재귀의 호출 스택이 바로 이것이다). 큐는 먼저 온 요청을 먼저 처리해야 하는 곳, 즉 운영체제의 ready 큐나 작업 대기열에 쓰인다.

선형 자료구조 코드

배열 접근은 주소 계산 한 번 (C)

arr[i]는 내부적으로 시작 주소 + i × sizeof(int)를 계산해 그 주소를 한 번 읽는다. i가 0이든 100만이든 연산량이 같다. 이것이 배열 접근이 O(1)인 이유다. 자세한 포인터 산술은 C 포인터와 배열에서 다룬다.

연결 리스트는 화살표를 따라간다 (C)

i번째에 가려면 head부터 next를 i번 따라가야 한다. 따라서 접근이 O(n)이다. 대신 위치를 알면 삽입은 포인터 두 개만 고쳐 O(1)이다. 배열과 정확히 반대의 성질이다.

PintOS 커널의 이중 연결 리스트 (실제 코드)

PintOS의 ready 큐, semaphore 대기 리스트, 우선순위 기부 목록은 전부 이 구조로 만든다. prev와 next를 모두 들고 있는 이중 연결 리스트라, 스레드를 큐 중간에서 빼낼 때 앞뒤 노드를 양쪽에서 즉시 이어 O(1)에 제거할 수 있다. 스케줄러는 ready 리스트에서 스레드를 수시로 넣고 빼므로, 임의 접근이 빠른 배열보다 삽입·삭제가 빠른 연결 리스트가 맞다. struct thread가 struct list_elem elem을 직접 품고, 이 큐가 곧 FIFO/우선순위 큐로 동작한다. 자료구조 선택이 커널 설계로 그대로 이어진 예다.

연산별 복잡도 한눈에

연산배열연결 리스트
i번째 접근O(1)O(n)
맨 끝 삽입O(1)*O(1)
중간 삽입 (위치 알 때)O(n)O(1)
중간 삭제 (위치 알 때)O(n)O(1)
메모리 추가 비용없음노드마다 포인터

* 배열 끝 삽입은 빈 공간이 있을 때만 O(1)이고, 가득 차서 더 큰 배열로 재할당하면 그 순간 O(n)이다(동적 배열의 amortized O(1)).

표가 말하는 결론은 단순하다. 읽기가 잦으면 배열, 중간 삽입·삭제가 잦으면 연결 리스트.

정리

배열과 연결 리스트는 데이터를 메모리에 두는 두 가지 물리 방식이고, 그 차이는 하나의 맞교환으로 압축된다. 배열은 연속 배치라 i번째 접근이 O(1)이지만 중간 삽입·삭제가 O(n)이다. 연결 리스트는 흩어진 노드를 포인터로 잇기에 접근이 O(n)이지만 중간 삽입·삭제가 O(1)이다. 스택과 큐는 별도의 구조가 아니라 이 둘 위에 LIFO/FIFO 규칙을 씌운 사용 패턴이며, 함수 호출에는 스택이, ready 큐 같은 순서 처리에는 큐가 맞다.

판단 기준은 “무엇을 자주 하는가”다. 인덱스로 읽기가 잦고 크기가 잘 안 변하면 배열을 고른다. 순서 중간에서 넣고 빼기가 잦으면 연결 리스트를 고른다. 그리고 같은 O(n) 순회라도 캐시 지역성 때문에 배열이 현실에서 더 빠르다는 점을, 성능이 중요한 경로에서는 함께 기억한다.
