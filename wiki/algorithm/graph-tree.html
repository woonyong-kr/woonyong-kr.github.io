그래프와 트리

그래프와 트리

한 줄 요약: 그래프(graph)는 점과 선으로 관계를 나타내는 자료구조이고, 트리(tree)는 사이클이 없는 특별한 그래프다. 그래프를 코드로 담는 방법은 인접 행렬과 인접 리스트 두 가지이며, 트리를 한 번씩 방문하는 순서는 전위·중위·후위·레벨 네 가지다.

그래프와 트리 문제

지하철 노선도를 떠올려 보자. 역이 있고, 역과 역을 잇는 선로가 있다. 역은 점이고 선로는 선이다. 친구 관계도 마찬가지다. 사람이 점이고 “친구다”라는 관계가 선이다. 웹 페이지와 링크, 도시와 도로, 함수와 호출 관계 — 세상의 수많은 문제가 “무엇과 무엇이 연결되어 있는가”로 환원된다.

이런 연결 구조를 코드로 다루려면 먼저 메모리에 담아야 한다. 그런데 점과 선을 어떻게 저장할지부터 막힌다. 배열 하나로는 “1번 역과 3번 역이 이어져 있다”는 사실을 표현할 수 없다. 연결 관계를 저장하는 전용 표현이 필요하다. 그것이 그래프 표현이다.

트리는 그래프의 특수한 형태다. 회사 조직도, 컴퓨터의 폴더 구조, 토너먼트 대진표처럼 “위에서 아래로 갈라지지만 다시 합쳐지지 않는” 구조다. 트리에는 모든 노드를 빠짐없이 한 번씩 방문하는 표준 순서가 정해져 있는데, 이 순서를 모르면 정렬된 데이터를 꺼내거나 수식을 계산하는 코드를 짤 수 없다.

이 개념을 모르면 다음을 이해하지 못한다.

  • DFS와 BFS가 무엇을 입력으로 받아 돌아가는지 (입력이 바로 그래프 표현이다)
  • 데이터베이스 인덱스의 B+Tree, 파일 시스템의 디렉터리 트리가 왜 트리인지
  • 수식 (1 + 2) * 3을 컴퓨터가 어떤 순서로 계산하는지 (후위 순회의 결과다)
  • 왜 어떤 문제는 인접 행렬이 빠르고 어떤 문제는 인접 리스트가 빠른지

이 문서를 읽으면 그래프를 두 가지 방식으로 코드에 담을 수 있고, 트리의 네 가지 순회가 각각 어떤 순서로 노드를 방문하는지 손으로 따라갈 수 있다.

그래프와 트리 차이

그래프 — 점(노드)과 선(간선)의 집합

그래프(graph)는 노드(node, 정점)의 집합과 간선(edge, 노드를 잇는 선)의 집합으로 이루어진다. 도시를 점으로, 도로를 선으로 그린 도로망이 곧 그래프다.

간선에는 두 가지 성질이 붙는다.

  • 방향
    • 무방향 그래프(undirected graph): 선에 화살표가 없다. “A와 B는 친구다”처럼 서로 대칭인 관계.
    • 방향 그래프(directed graph): 선에 화살표가 있다. “A가 B를 팔로우한다”처럼 한쪽 방향만 성립하는 관계.
  • 가중치
    • 가중치 없는 그래프: 연결되었는지 여부만 중요하다.
    • 가중치 그래프(weighted graph): 간선마다 숫자가 붙는다. 도로의 거리, 요금처럼 비용을 표현한다.

그래프를 메모리에 담는 두 가지 방법

노드가 5개라고 하자. 노드 번호는 0부터 4까지다. “누가 누구와 연결되어 있는가”를 저장하는 방법은 두 가지다.

첫째, 인접 행렬(adjacency matrix). 5×5 크기의 2차원 배열을 만든다. matrix[i][j]가 1이면 i에서 j로 가는 간선이 있다는 뜻, 0이면 없다는 뜻이다.

       j=0  j=1  j=2  j=3  j=4
i=0  [  0    1    1    0    0  ]   ← 0번은 1번, 2번과 연결
i=1  [  1    0    0    1    0  ]   ← 1번은 0번, 3번과 연결
i=2  [  1    0    0    1    0  ]
i=3  [  0    1    1    0    1  ]
i=4  [  0    0    0    1    0  ]

둘째, 인접 리스트(adjacency list). 노드마다 “내가 연결된 노드들”의 목록을 따로 둔다.

0 → [1, 2]
1 → [0, 3]
2 → [0, 3]
3 → [1, 2, 4]
4 → [3]

왜 두 가지 표현을 나눠 쓰는가?

노드 수를 V, 간선 수를 E라고 하자.

  • 인접 행렬: 공간은 항상 V × V를 쓴다. 두 노드가 연결됐는지 확인은 matrix[i][j] 한 번 읽기, 즉 O(1)로 빠르다.
  • 인접 리스트: 공간은 V + E만 쓴다. 두 노드의 연결 확인은 목록을 훑어야 하므로 최악 O(V)다.

노드는 많은데 간선이 적은 그래프(희소 그래프)를 생각해 보자. 노드 1만 개에 간선이 2만 개라면, 인접 행렬은 1만 × 1만 = 1억 칸을 잡지만 대부분 0이다. 인접 리스트는 1만 + 2만 = 3만 칸만 쓴다. 현실의 그래프 대부분이 희소하므로 인접 리스트를 기본으로 쓰고, 노드가 적고 연결 확인이 잦은 경우에만 인접 행렬을 쓴다.

트리 — 사이클 없는 연결 그래프

트리(tree)는 그래프의 특수한 경우다. 조건은 두 가지다. 모든 노드가 연결되어 있고, 사이클(출발한 노드로 다시 돌아오는 경로)이 없다. 노드가 N개인 트리의 간선은 정확히 N-1개다.

트리에는 그래프에 없는 용어가 붙는다.

  • 루트(root): 가장 위의 시작 노드. 트리에는 루트가 하나다.
  • 부모(parent)와 자식(child): 루트에서 멀어지는 방향으로 부모 아래에 자식이 달린다.
  • 리프(leaf): 자식이 없는 끝 노드.

가장 많이 쓰는 트리는 이진 트리(binary tree)다. 자식이 최대 둘(왼쪽, 오른쪽)인 트리다. 아래 예시 트리를 기준으로 순회를 설명한다.

            1
          /   \
        2       3
       / \     /
      4   5   6

트리 순회 네 가지 — 노드를 한 번씩 방문하는 순서

순회(traversal)는 트리의 모든 노드를 빠짐없이 한 번씩 방문하는 것이다. “부모와 두 자식을 어떤 순서로 처리하느냐”에 따라 세 가지 깊이 우선 순회가 갈린다. 깊이 우선이란 한 자식 방향으로 끝까지 내려갔다가 돌아오는 방식이다.

  • 전위 순회(preorder): 부모 → 왼쪽 → 오른쪽. 위 트리에서 1 2 4 5 3 6. 트리를 복사하거나 구조를 그대로 출력할 때 쓴다.
  • 중위 순회(inorder): 왼쪽 → 부모 → 오른쪽. 위 트리에서 4 2 5 1 6 3. 이진 탐색 트리에서 중위 순회를 하면 값이 오름차순으로 나온다.
  • 후위 순회(postorder): 왼쪽 → 오른쪽 → 부모. 위 트리에서 4 5 2 6 3 1. 자식을 먼저 처리해야 하는 경우, 예를 들어 폴더 용량 계산이나 수식 계산에 쓴다.

네 번째는 너비 우선인 레벨 순회(level-order)다. 같은 깊이의 노드를 왼쪽부터 한 줄씩 방문한다. 위 트리에서 1 2 3 4 5 6. 큐(queue)를 써서 구현하며, 이는 BFS를 트리에 적용한 것과 같다.

그래프와 트리 코드

먼저 그래프를 인접 리스트로 만든다. 무방향 그래프이므로 간선 하나를 넣을 때 양쪽 노드에 서로를 추가한다.

이 코드는 간선 목록을 받아 노드별 연결 목록으로 바꾼다. 공간은 노드 수 V와 간선 수 E를 더한 만큼만 쓴다.

다음은 이진 트리의 노드 정의와 세 가지 깊이 우선 순회다. 재귀로 짜면 “부모를 언제 처리하느냐”의 위치만 바꿔 세 순회를 모두 표현할 수 있다.

print 위치를 두 재귀 호출 사이로 옮기면 중위 순회, 두 호출 뒤로 옮기면 후위 순회가 된다. 즉 순회의 차이는 “부모를 처리하는 줄의 위치” 하나다.

재귀 호출이 끝까지 내려갔다 돌아오는 이유는 함수 호출이 콜 스택에 쌓이기 때문이다. preorder(node.left)가 호출되면 현재 함수의 상태가 스택에 저장되고, 왼쪽 끝에 닿아 return하면 스택에서 직전 상태를 꺼내 오른쪽 호출로 이어진다.

레벨 순회는 재귀 대신 큐를 쓴다. 방문할 노드를 큐에 넣고, 꺼낼 때마다 그 자식들을 다시 큐에 넣는다.

먼저 들어간 노드가 먼저 나오는 큐의 성질 덕분에, 위쪽 레벨의 노드가 아래쪽 레벨보다 항상 먼저 처리된다. 그래서 같은 깊이를 왼쪽부터 한 줄씩 훑는 순서가 만들어진다.

순회 방식과 사용하는 자료구조의 관계를 정리하면 이렇다.

%% 순회 방식과 다음 방문지 저장 구조
flowchart TD
  dfs["깊이 우선 순회<br/>(재귀 = 스택)"]
  dfs_result["전위·중위·후위<br/>한 방향 끝까지 내려감"]
  bfs["너비 우선 순회<br/>(큐 사용)"]
  bfs_result["레벨 순회<br/>같은 깊이를 한 줄씩"]
  dfs --> dfs_result
  bfs --> bfs_result

정리

그래프는 점과 선으로 관계를 표현하는 자료구조이고, 트리는 사이클이 없고 간선이 노드 수보다 하나 적은 특수한 그래프다. 그래프를 메모리에 담는 방법은 두 가지인데, 연결 확인이 잦고 노드가 적으면 인접 행렬(O(1) 확인, V×V 공간), 노드가 많고 간선이 적은 희소 그래프면 인접 리스트(V+E 공간)를 쓴다. 트리 순회는 부모를 처리하는 위치에 따라 전위·중위·후위로 갈리고, 큐를 쓰면 레벨 순회가 된다. 이진 탐색 트리에서 정렬된 값이 필요하면 중위 순회, 자식을 먼저 계산해야 하면 후위 순회를 고르면 된다.
