연결 리스트 앞·뒤 절반 분할 — 가운데를 기준으로 둘로 나누는 법

한 줄 요약: 연결 리스트 절반 분할은 가운데 지점을 찾은 뒤, 그 앞에서 링크를 한 번 끊어 앞 리스트와 뒤 리스트를 나누는 작업이다.

연결 리스트 앞·뒤 절반 분할 혼동

연결 리스트는 배열처럼 인덱스로 중간을 바로 찍을 수 없다. 그래서 “절반으로 나눈다”는 말이 생각보다 까다롭다.

이 작업은 여러 곳에서 반복해서 나온다.

  • 병합 정렬에서 리스트를 반으로 쪼갤 때
  • 느린 포인터와 빠른 포인터를 배울 때
  • 리스트를 앞부분과 뒷부분으로 따로 처리해야 할 때

알아 두면 좋은 판단 기준은 세 가지다.

  • 가운데를 찾는 기준을 무엇으로 둘 것인가?
  • 홀수 길이일 때 어느 쪽이 하나 더 가질 것인가?
  • 원본 노드를 그대로 나눌 것인가, 새 리스트를 다시 만들 것인가?

연결 리스트 앞·뒤 절반 분할 구조

  • 가장 일반적인 방법
    • 느린 포인터 slow는 한 칸씩 이동
    • 빠른 포인터 fast는 두 칸씩 이동
    • fast가 끝에 도달하면 slow는 가운데 근처에 있다
  • 홀수 길이 규칙
    • 앞 리스트가 하나 더 갖게 하려면 slow가 앞쪽 끝이 되도록 잡으면 된다
  • 실제 분할 순간
    • 중간 바로 앞 노드의 next를 None으로 바꾸면 두 리스트가 갈라진다

동작 순서

연결 리스트 앞·뒤 절반 분할 코드와 값

  • 이 코드에서 중요한 점
    • fast = head.next로 시작하면 홀수 길이일 때 앞 리스트가 하나 더 갖는 쪽으로 맞추기 쉽다
    • back = slow.next로 뒤 리스트 시작점을 잡는다
    • slow.next = None 한 줄이 실제 분할 지점이다

원본 노드를 그대로 쓸지, 새로 만들지

  • 링크를 끊어 나누는 방식
    • 장점: 추가 노드 생성이 거의 없다
    • 단점: 원본 리스트 구조가 바뀐다
  • 새 리스트를 재구성하는 방식
    • 장점: 원본을 보존하기 쉽다
    • 단점: 새 노드 생성과 복사 비용이 들어간다

원자료 실습 글은 size를 바탕으로 앞쪽 길이를 계산하고, 원본을 순회하면서 앞 리스트와 뒤 리스트를 새로 만드는 쪽에 가깝다. 학습 관점에서는 그 구현도 유효하지만, 연결 리스트 자체를 다루는 감각을 익히기에는 포인터를 직접 끊는 방식이 더 일반적이다.

비용

  • 가운데 찾기
    • 리스트를 한 번 훑으므로 O(n)
  • 링크 끊기
    • 포인터 한 번 바꾸므로 O(1)
  • 전체
    • 결국 O(n)

자주 헷갈리는 지점

  • 배열처럼 “중간 인덱스”를 먼저 떠올리는 경우
    • 연결 리스트는 인덱스 접근이 느리므로 포인터 이동으로 생각하는 편이 맞다
  • 홀수 길이 처리
    • 문제마다 앞쪽이 하나 더 갖는지, 뒤쪽이 하나 더 갖는지가 다를 수 있다
    • 조건을 코드로 넣기 전에 규칙을 먼저 문장으로 적는 편이 안전하다
  • 원본 보존 여부
    • 링크를 직접 끊으면 원본이 바뀐다는 점을 놓치기 쉽다
