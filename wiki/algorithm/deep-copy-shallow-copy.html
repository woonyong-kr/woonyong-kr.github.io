깊은 복사와 얕은 복사

확인 범위: 이 문서는 깊은 복사와 얕은 복사의 일반 개념과 선택 기준을 Python·C 예시로 설명하며, 제시된 코드는 동작을 이해하기 위한 예시일 뿐 특정 버전이나 실행 기록을 검증한 결과는 아니다. 실제 적용 여부와 비용은 대상 코드의 객체 구조, 언어·라이브러리 버전, 실행 결과와 성능 측정을 바탕으로 별도로 판단해야 한다.

한 줄 요약: 얕은 복사는 바깥 객체만 새로 만들고 내부 객체는 주소만 공유하는 복사이고, 깊은 복사는 내부 객체까지 모두 새로 만드는 복사이며, 둘의 차이는 복사본을 수정했을 때 원본이 함께 바뀌느냐에서 드러난다.

깊은 복사와 얕은 복사 구분

리스트 하나를 복사해서 복사본을 고쳤더니, 건드리지도 않은 원본까지 같이 바뀌는 일이 있다. 분명히 복사를 했는데 왜 원본이 따라 바뀌는가?

이 현상은 “복사”라는 말이 두 가지 다른 동작을 가리키기 때문에 생긴다. 어떤 복사는 껍데기만 새로 만들고 알맹이는 원본과 공유한다. 다른 복사는 알맹이까지 전부 새로 만든다. 이 차이를 모르면 다음을 설명하지 못한다.

  • 왜 list(원본)이나 원본[:]으로 복사했는데 원본이 바뀌는가
  • 함수에 객체를 넘겼을 때 함수 안 수정이 밖에 반영되는 경우와 아닌 경우
  • 설정값을 복사해 기본값으로 쓰려는데 한 곳을 고치면 전부 바뀌는 버그
  • 객체 안에 객체가 중첩될수록 왜 복사가 위험해지는가

이 문제의 뿌리는 변수가 값이 아니라 **객체의 주소(참조)**를 담는다는 데 있다. 같은 뿌리에서 Python 함수 인자 전달 동작도 나온다. 이 문서를 읽으면 얕은 복사와 깊은 복사를 구분하고, 어떤 상황에서 어느 것을 써야 하는지 판단할 수 있다.

깊은 복사와 얕은 복사 차이

비유 — 공유 문서의 복사

팀 폴더에 표지와 본문으로 된 기획안이 있다.

  • 얕은 복사: 표지만 새로 인쇄하고, 본문은 원본과 같은 클라우드 링크를 붙여 둔다. 새 표지에서 본문 링크를 열어 한 줄 고치면, 원본의 본문도 바뀐다. 본문이 같은 실체를 가리키기 때문이다.
  • 깊은 복사: 표지도 본문도 전부 새 파일로 복제한다. 복사본의 본문을 고쳐도 원본은 그대로다. 서로 다른 실체이기 때문이다.

표지가 바깥 객체(리스트 자체), 본문이 내부 객체(리스트 안의 리스트)에 해당한다.

정의 — 무엇을 새로 만드는가

  • 얕은 복사 (Shallow Copy): 최상위 객체 하나만 새로 만든다. 그 안에 든 원소가 또 다른 객체(리스트, 딕셔너리 등)라면, 그 원소는 복사하지 않고 주소만 그대로 가져온다. 원본과 복사본이 내부 객체를 공유한다.
  • 깊은 복사 (Deep Copy): 최상위 객체부터 그 안의 모든 중첩 객체까지 재귀적으로 새로 만든다. 원본과 복사본이 어떤 객체도 공유하지 않는다.

핵심은 “중첩된 객체를 공유하느냐”다. 원소가 모두 숫자나 문자열 같은 단일 값이면 얕은 복사로 충분하다. 문제는 원소 자체가 또 다른 객체일 때 생긴다.

동작 — 주소 관점에서 보기

리스트 a = [[1, 2], 3]을 얕은 복사한 상황을 주소로 그린다.

%% 얕은 복사에서 바깥 리스트는 분리되고 내부 리스트는 공유되는 구조
flowchart TD
  original["원본 a<br/>[0] → 내부 리스트<br/>[1] = 3"]
  copy["얕은 복사본 b<br/>[0] → 내부 리스트<br/>[1] = 3"]
  inner["공유 내부 객체<br/>[1"]
  original --> inner
  copy --> inner
  original -.-> copy

b[0]과 a[0]이 같은 [1, 2] 객체를 가리킨다. 그래서 b[0].append(99)를 하면 a[0]도 [1, 2, 99]가 된다. 반면 b[1] = 100처럼 바깥 리스트의 원소를 통째로 교체하면, 이것은 바깥 리스트만의 변경이므로 a[1]은 그대로 3이다.

깊은 복사는 내부 [1, 2]까지 새로 만들어 두 화살표가 서로 다른 객체를 가리키게 한다. 그래서 어느 쪽을 고쳐도 다른 쪽은 영향받지 않는다.

언제 무엇을 쓰는가

  • 원소가 전부 불변값(숫자, 문자열, 튜플)이면 → 얕은 복사로 충분하다. 공유해도 수정이 일어나지 않는다.
  • 원소에 가변 객체(리스트, 딕셔너리, 사용자 객체)가 중첩되어 있고, 복사본을 독립적으로 수정할 것이면 → 깊은 복사가 필요하다.
  • 깊은 복사는 모든 중첩 객체를 새로 만들므로 비용이 크다. 중첩 깊이와 원소 수에 비례해 시간·공간 복잡도가 늘어난다. 필요할 때만 쓴다.

깊은 복사와 얕은 복사 코드

Python — 얕은 복사의 함정

b[0].append(99)는 a와 b가 공유하는 내부 리스트를 직접 건드리므로 양쪽에 반영된다. 반면 b[1] = 100은 b의 바깥 리스트만 바꾼다. “복사했는데 원본이 바뀌는” 버그는 거의 항상 공유된 내부 객체를 수정할 때 나온다.

Python — 깊은 복사로 끊어내기

copy.deepcopy()는 중첩된 모든 객체를 재귀적으로 복제한다. a와 b는 어떤 객체도 공유하지 않으므로 완전히 독립적이다. 복사본을 마음대로 고쳐도 원본이 안전해야 한다면 이쪽을 쓴다.

복사 방법별 정리

방법종류내부 객체
b = a복사 아님 (별칭)같은 객체 전체 공유
a[:], list(a), a.copy()얕은 복사주소만 공유
copy.copy(a)얕은 복사주소만 공유
copy.deepcopy(a)깊은 복사전부 새로 생성

b = a는 복사가 아니라 같은 객체에 이름표를 하나 더 붙이는 별칭(alias)이다. 이것까지 합쳐 세 단계(별칭 → 얕은 복사 → 깊은 복사)로 구분하면 동작이 명확해진다.

C — memcpy는 얕은 복사다

C에서 구조체 대입은 바이트를 그대로 복사한다. 포인터 멤버는 가리키는 주소값만 복사되므로, a와 b의 name은 같은 힙 메모리를 가리킨다. 깊은 복사를 하려면 b.name = strdup(a.name)처럼 가리키는 대상까지 새로 할당해야 한다. 언어가 달라도 “포인터(참조)만 복사하느냐, 가리키는 실체까지 복사하느냐”라는 본질은 같다.

정리

얕은 복사는 바깥 객체만 새로 만들고 내부 객체는 주소를 공유한다. 깊은 복사는 중첩된 모든 객체까지 새로 만들어 원본과 완전히 분리한다. “복사했는데 원본이 바뀐다”는 증상은 거의 항상 얕은 복사로 공유된 내부 객체를 직접 수정했을 때 나타난다.

판단 기준은 두 가지다. 첫째, 원소가 전부 불변값이면 얕은 복사로 충분하다. 둘째, 가변 객체가 중첩되어 있고 복사본을 독립적으로 수정할 것이라면 깊은 복사를 쓰되, 비용이 크므로 정말 필요할 때만 쓴다. 이 모든 동작의 뿌리는 변수가 값이 아니라 객체의 참조를 담는다는 사실이다.
