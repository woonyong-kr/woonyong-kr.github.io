병합 정렬

병합 정렬

한 줄 요약: 병합 정렬은 배열을 더 쪼갤 수 없을 때까지 절반씩 나눈 다음, 정렬된 두 조각을 하나로 합치는 과정을 거꾸로 거슬러 올라가며 전체를 정렬하는 분할 정복 정렬이다.

병합 정렬 구분

퀵 정렬은 평균이 빠르지만 입력이 운 나쁘게 들어오면 최악 O(n²)로 떨어진다. 그리고 같은 값의 원래 순서가 뒤바뀔 수 있다. 예를 들어 주문 데이터를 “금액순”으로 정렬한 뒤 다시 “날짜순”으로 정렬했을 때, 금액이 같은 주문끼리 원래 날짜 순서가 유지되길 바란다면 퀵 정렬로는 보장되지 않는다.

여기서 두 가지 요구가 생긴다. 입력이 어떻게 들어와도 성능이 흔들리지 않을 것(최악도 O(n log n)), 그리고 같은 값의 원래 순서를 지킬 것(안정 정렬). 병합 정렬이 정확히 이 두 가지를 만족한다.

발상은 단순하다. “이미 정렬된 두 줄을 하나로 합치는 일”은 쉽다. 두 줄의 맨 앞만 비교해 작은 쪽을 꺼내면 되기 때문이다. 그렇다면 배열을 잘게 쪼개 각 조각이 저절로 정렬된 상태(원소 1개)가 되게 만든 다음, 합치기만 반복하면 전체가 정렬된다.

이 개념을 모르면 다음을 이해하지 못한다.

  • 왜 어떤 정렬은 최악에도 O(n log n)이 보장되는가
  • “안정 정렬(stable sort)“이 무엇이고 왜 실무에서 중요한가
  • 수백 GB짜리 파일처럼 메모리에 다 못 올리는 데이터를 어떻게 정렬하는가(외부 정렬)
  • 분할 정복에서 “합치는 단계(merge)“가 정렬을 만드는 핵심이 되는 경우

이 문서를 읽으면 병합 정렬의 쪼개기와 합치기를 실제 값으로 따라갈 수 있고, 퀵 정렬과 언제 갈라 써야 하는지 판단할 수 있다.

병합 정렬 흐름

비유 — 정렬된 두 줄을 지퍼처럼 합친다

이미 키 순서로 정렬된 두 줄이 있다. 이 둘을 하나의 정렬된 줄로 만들고 싶다. 방법은 간단하다. 두 줄의 맨 앞 사람만 보고 키가 작은 쪽을 새 줄로 보낸다. 그 줄의 다음 사람이 맨 앞이 된다. 다시 두 맨 앞을 비교한다. 이 동작을 두 줄이 빌 때까지 반복하면, 새 줄은 정렬되어 있다. 마치 지퍼의 양쪽 이빨이 번갈아 맞물리듯 합쳐진다.

문제는 “처음부터 정렬된 두 줄”이 어디서 오느냐다. 병합 정렬의 답은 이렇다. 줄을 절반씩 계속 쪼개면 결국 한 명짜리 줄만 남는다. 한 명짜리 줄은 그 자체로 정렬되어 있다. 거기서부터 합치기를 시작하면 된다.

정의 — 분할과 병합

  • 분할(divide): 배열을 가운데서 둘로 나눈다. 각 절반을 다시 둘로 나눈다. 원소가 1개가 될 때까지 계속 나눈다. 1개짜리는 더 나누지 않는다(종료 조건).
  • 병합(merge): 정렬된 두 조각의 맨 앞을 비교해 작은 값을 결과에 차례로 옮긴다. 한쪽이 비면 나머지를 그대로 붙인다. 이 동작이 두 조각을 하나의 정렬된 조각으로 만든다.

퀵 정렬이 “가르고 나서 재귀”라면, 병합 정렬은 “재귀로 끝까지 가른 뒤 돌아오며 합친다”. 정렬을 만드는 진짜 일이 합치는 단계에서 일어난다는 점이 다르다.

어떻게 동작하는가 — 쪼갰다가 합치며 거슬러 올라간다

배열 [3, 7, 1, 5]를 보자.

  1. 가운데서 나눈다: [3, 7]과 [1, 5].
  2. 각각 또 나눈다: [3], [7], [1], [5]. 모두 원소 1개 → 더 나누지 않는다.
  3. 합치기 시작: [3]과 [7]을 합쳐 [3, 7]. [1]과 [5]를 합쳐 [1, 5].
  4. 마지막 합치기: [3, 7]과 [1, 5]의 맨 앞을 비교(3 vs 1)해 1, 다음 3, 5, 7 순으로 옮긴다 → [1, 3, 5, 7].

내려갈 때는 나누기만 하고, 올라올 때 합치며 정렬한다. 정렬은 위로 올라오는 병합 단계에서 만들어진다.

왜 최악도 O(n log n)인가?

병합 정렬은 피벗 선택 같은 운에 기대지 않는다. 항상 정확히 절반으로 나누기 때문이다.

전체 비용 T(n) = 왼쪽 절반 T(n/2) + 오른쪽 절반 T(n/2) + 병합 비용 n 즉 T(n) = 2 × T(n/2) + n

절반으로 나누는 단계가 log₂ n 번 생기고, 각 단계마다 그 층의 모든 원소를 한 번씩 병합하니 n 비용이 든다. 대입하면 T(n) = n × log₂ n

퀵 정렬과 같은 점화식이지만, 병합 정렬은 분할이 입력값에 의존하지 않으므로 이 결과가 최선·평균·최악에서 모두 성립한다. 입력이 정렬돼 있든 거꾸로 돼 있든 항상 O(n log n)이다.

결론: 분할이 데이터와 무관하게 절반이므로 병합 정렬의 O(n log n)은 보장된다.

안정 정렬인 이유와 메모리 비용

병합할 때 두 조각의 맨 앞 값이 같으면 “왼쪽 조각의 값을 먼저” 꺼내도록 정하면, 같은 값의 원래 순서가 보존된다. 이것이 안정 정렬(stable sort)이다. 비교 조건을 < 대신 <=로 쓰는 작은 선택이 안정성을 만든다.

대신 병합은 결과를 담을 보조 배열이 필요하다. 그래서 병합 정렬은 입력과 같은 크기의 추가 메모리 O(n)을 쓴다. 제자리 정렬인 퀵 정렬(추가 메모리 거의 없음)과의 핵심 차이가 여기다.

실제 시스템에서는 — 외부 정렬과 표준 라이브러리

  • 외부 정렬(external sort): 데이터가 너무 커서 메모리(RAM)에 다 못 올릴 때, 디스크의 조각들을 메모리에 들어갈 만큼만 정렬해 임시 파일로 쓰고, 그 정렬된 파일들을 병합한다. “정렬된 조각을 합친다”는 병합 단계가 바로 이 상황에 맞는다. 수백 GB 로그를 정렬하는 빅데이터 처리의 토대다.
  • 안정성이 필요한 내장 정렬: 여러 언어의 표준 라이브러리 안정 정렬은 병합 정렬과 삽입 정렬을 결합한 팀소트(Timsort) 계열을 쓴다. 이미 정렬된 구간(run)을 찾아 병합 횟수를 줄이는 최적화가 더해진 형태다.

병합 정렬 코드

병합 — 정렬된 두 조각을 지퍼처럼 합친다 (C)

두 조각의 맨 앞만 비교해 작은 값을 보조 배열 tmp로 옮긴다. <= 비교가 같은 값일 때 왼쪽을 먼저 꺼내 안정성을 만든다. 한쪽이 비면 나머지를 그대로 붙인다. 보조 배열 tmp 때문에 추가 메모리 O(n)이 든다는 점이 이 함수에서 드러난다.

분할 — 절반씩 끝까지 나눈 뒤 병합 (C)

mid 계산을 (lo+hi)/2가 아니라 lo+(hi-lo)/2로 쓰는 이유는 큰 인덱스에서 lo+hi가 정수 범위를 넘는 오버플로를 막기 위해서다. 재귀로 끝까지 나눈 뒤, 돌아오는 길에 merge()가 정렬을 완성한다. 기억할 것은 “분할은 일을 하지 않고, 병합이 정렬을 만든다”는 점이다.

보조 배열은 한 번만 잡는다 (C)

보조 배열을 재귀 호출마다 새로 잡으면 할당·해제 비용이 폭증한다. 진입점에서 한 번만 잡아 재귀 전체가 공유한다. 재귀 깊이는 log₂ n으로 일정해서 스택 부담도 작다.

정리

병합 정렬은 배열을 원소 1개가 될 때까지 절반씩 나눈 뒤, 정렬된 두 조각을 지퍼처럼 합치며 거슬러 올라가는 분할 정복 정렬이다. 분할이 데이터값과 무관하게 항상 절반이라 최악에도 O(n log n)이 보장된다. 같은 값일 때 왼쪽을 먼저 꺼내면 원래 순서가 지켜지는 안정 정렬이다. 대가로 입력과 같은 크기의 보조 메모리 O(n)을 쓴다. 정렬을 만드는 진짜 일은 나누기가 아니라 합치는 단계에서 일어난다.

판단 기준은 이렇다. 최악 성능이 보장돼야 하거나(실시간·대규모 데이터), 같은 값의 순서를 지켜야 하거나(안정 정렬), 메모리에 다 못 올리는 데이터를 정렬해야 하면(외부 정렬) 병합 정렬을 고른다. 반대로 추가 메모리를 아껴야 하고 평균 속도가 우선이면 퀵 정렬이 낫다. “보장된 성능과 안정성을 추가 메모리로 산다”가 병합 정렬의 자리다.
