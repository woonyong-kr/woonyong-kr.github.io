정렬된 연결 리스트 삽입 — 포인터를 끊지 않고 자리를 찾는 법

한 줄 요약: 정렬된 연결 리스트 삽입은 새 값이 들어갈 위치를 먼저 찾고, prev -> new -> cur 순서로 포인터를 다시 이어 정렬 상태를 유지하는 작업이다.

정렬된 연결 리스트 삽입 오해

  • 문제 상황
    • 정렬된 배열에 삽입하는 방법은 익숙해도, 연결 리스트에서는 값을 밀지 않고 포인터를 다시 이어야 해서 흐름이 끊기기 쉽다.
    • 연결 리스트에서는 “몇 번째 위치인가”보다 “앞 노드와 현재 노드가 누구인가”가 더 중요하다.
    • 맨 앞 삽입, 중간 삽입, 맨 뒤 삽입을 따로따로 외우면 금방 헷갈린다.
  • 이 문서에서 얻을 판단 기준
    • 정렬 조건을 유지하려면 어떤 시점에 탐색을 멈춰야 하는지 설명할 수 있어야 한다.
    • prev와 cur를 같이 움직이는 이유를 말할 수 있어야 한다.
    • 포인터 재배선을 어떤 순서로 해야 기존 리스트를 잃어버리지 않는지 설명할 수 있어야 한다.

정렬된 연결 리스트 삽입 구조

  • 큰 개념
    • 연결 리스트 삽입은 값을 밀어내는 작업이 아니라 링크를 다시 잇는 작업이다.
    • 정렬 리스트 삽입은 두 단계를 가진다.
      • 1단계: 새 값보다 작은 노드들을 지나가며 삽입 위치를 찾는다.
      • 2단계: 새 노드를 prev와 cur 사이에 끼운다.
  • 헷갈리는 지점
    • 배열처럼 인덱스를 먼저 생각하면 연결 리스트의 핵심을 놓치기 쉽다.
      • 실제로 필요한 것은 “삽입 지점의 앞 노드”다.
    • 맨 앞 삽입은 예외처럼 보이지만 원리는 같다.
      • prev가 없고 head를 새 노드로 바꾼다는 점만 다르다.
    • 실제 시스템과 학습용 구현의 차이
      • 실무에서는 더미 헤드(dummy head)를 두어 맨 앞 예외 처리를 줄이는 경우가 많다.
      • 학습용 구현에서는 예외 케이스를 직접 다뤄 보며 포인터 흐름을 익히는 편이 도움이 된다.

정렬된 연결 리스트 삽입 코드와 값

  • 이 예시에서 중요한 점
    • while (cur->data < value)가 멈추는 순간이 바로 삽입 위치다.
    • prev == NULL이면 새 값이 가장 작아서 맨 앞에 들어가야 한다.
    • new_node->next = cur를 통해 중간 삽입과 맨 뒤 삽입을 같은 코드로 처리할 수 있다.
  • 이 예시에서 중요한 점
    • 새 노드가 가리킬 다음 노드를 잃지 않도록 cur를 먼저 기억하고 있어야 한다.
    • 연결 리스트 문제의 핵심은 값 비교보다 “링크를 안전하게 다시 잇는 순서”다.
  • 이 예시에서 중요한 점
    • 연결 리스트는 삽입 자체는 O(1)이지만, 올바른 위치를 찾는 탐색 비용 때문에 전체는 O(n)이다.
