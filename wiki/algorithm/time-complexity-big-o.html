시간 복잡도 (Big-O)

시간 복잡도 (Big-O)

한 줄 요약: 시간 복잡도는 입력 크기 n이 커질 때 알고리즘이 수행하는 연산 횟수가 어떤 비율로 증가하는지를 나타내며, Big-O 표기법은 그중 가장 빠르게 자라는 항만 남겨 알고리즘의 성능을 비교하는 척도다.

시간 복잡도 필요성

같은 문제를 푸는 코드가 두 개 있다. 하나는 데이터 1,000개에서 0.001초, 다른 하나도 0.001초가 걸린다. 둘 중 무엇이 더 좋은 코드인가? 이 정보만으로는 알 수 없다.

데이터가 1,000개가 아니라 1억 개로 늘어나면 이야기가 달라진다. 한쪽은 여전히 0.1초인데 다른 쪽은 3시간이 걸릴 수 있다. 실행 시간을 한 번 재는 것으로는 이 차이를 잡아내지 못한다. CPU 속도, 언어, 컴파일러에 따라 측정값이 흔들리기 때문이다.

필요한 것은 “입력이 커질 때 연산량이 어떤 속도로 늘어나는가”라는 증가 추세다. 이 추세를 모르면 다음을 판단할 수 없다.

  • 데이터가 10배 늘면 이 코드는 10배 느려지는가, 100배 느려지는가
  • 정렬 알고리즘 중 어느 것을 골라야 하는가
  • DB 인덱스가 왜 풀 스캔보다 빠른가 (DB 인덱스의 핵심 근거)
  • 면접에서 “이 풀이의 복잡도는?”이라는 질문에 무엇을 답해야 하는가

이 문서를 읽으면 Big-O 표기를 읽고 쓸 수 있고, 코드를 보고 그 복잡도를 추정할 수 있으며, 두 알고리즘 중 어느 것이 더 잘 확장되는지 판단할 수 있다.

시간 복잡도 변화

비유 — 약속 장소를 찾는 방법

친구 한 명을 1,000명이 모인 강당에서 찾는다고 하자.

  • 맨 앞줄부터 한 명씩 얼굴을 확인한다. 운이 나쁘면 1,000명을 다 봐야 한다. → 인원이 2배면 확인 횟수도 2배.
  • 강당이 학번 순으로 정렬되어 있어서 가운데를 보고 “앞인가 뒤인가”를 반복해 좁힌다. → 1,000명이어도 약 10번이면 찾는다. 인원이 2배여도 한 번만 더 보면 된다.

첫 번째가 O(n), 두 번째가 O(log n)이다. 이 차이가 곧 알고리즘의 확장성 차이다.

정의 — 가장 빠르게 자라는 항만 남긴다

Big-O는 입력 크기 n에 대한 연산 횟수의 상한 증가율을 나타낸다. 핵심 규칙은 두 가지다.

  1. 상수 계수는 버린다. 3n도 100n도 모두 O(n)이다. n이 충분히 커지면 계수는 추세를 바꾸지 못한다.
  2. 가장 빠르게 자라는 항만 남긴다. n² + n + 5는 O(n²)이다. n이 커지면 n²이 나머지를 압도한다.

이 두 규칙 때문에 Big-O는 “정확한 실행 시간”이 아니라 “확장 추세”를 말한다. 세부 측정값이 아니라 큰 그림을 비교하는 도구다.

왜 상수와 작은 항을 버려도 되는가?

n = 1,000,000일 때 각 항의 크기를 대입해 본다.

f(n) = n² + 100n + 10000   에 n = 1,000,000 대입

n²    = 1,000,000,000,000   (1조)
100n  =       100,000,000   (1억)
10000 =            10,000

n² 항이 100n 항보다 1만 배 크다.

n이 커질수록 n² 항이 전체를 지배한다. 그래서 100n과 10000을 버리고 O(n²)이라고 쓴다. 작은 항을 남기는 것은 큰 그림을 흐리게 만들 뿐이다.

자주 나오는 복잡도 등급

아래로 갈수록 빠르게 자란다(느려진다). n = 1,000,000 기준 대략적인 연산 횟수를 함께 적는다.

  • O(1) — 상수 시간. 입력 크기와 무관. 연산 1회. 예: 배열 인덱스 접근 arr[i]
  • O(log n) — 로그 시간. 매번 절반으로 줄임. 약 20회. 예: 정렬된 배열 이진 탐색
  • O(n) — 선형 시간. 입력 1개당 1회. 100만 회. 예: 배열 전체 순회
  • O(n log n) — 선형로그 시간. 약 2천만 회. 예: 병합 정렬, 퀵 정렬 평균
  • O(n²) — 제곱 시간. 1조 회. 예: 이중 for 루프, 버블 정렬
  • O(2ⁿ) — 지수 시간. 사실상 계산 불가. 예: 부분집합 전수 탐색
  • O(n!) — 팩토리얼 시간. 더 빠르게 폭발. 예: 모든 순열 생성

O(n²)와 O(n log n)의 차이가 정렬 알고리즘 선택을 가르고, O(n)과 O(log n)의 차이가 DB 인덱스의 존재 이유다.

Best / Average / Worst

같은 알고리즘도 입력에 따라 연산 횟수가 다르다.

  • 최선(Best): 운이 가장 좋을 때. 예: 선형 탐색에서 찾는 값이 맨 앞 → O(1)
  • 평균(Average): 무작위 입력의 기댓값
  • 최악(Worst): 운이 가장 나쁠 때. 예: 선형 탐색에서 값이 맨 끝이거나 없음 → O(n)

Big-O는 보통 최악의 경우를 말한다. 성능을 보장하려면 “운이 좋을 때”가 아니라 “가장 나쁠 때”를 알아야 하기 때문이다.

시간 복잡도와 공간 복잡도

복잡도는 시간(연산 횟수)뿐 아니라 공간(추가 메모리)에도 적용된다. 병합 정렬은 시간 O(n log n)이지만 정렬 결과를 담을 보조 배열이 필요해 공간 O(n)을 쓴다. 같은 Big-O 도구로 둘 다 표현한다. 이 문서는 시간에 집중하지만, 알고리즘을 고를 때는 메모리 영역을 얼마나 쓰는지도 함께 본다.

시간 복잡도 코드

O(1) — 입력 크기와 무관한 연산

배열 인덱스 접근은 시작 주소에 인덱스 × 원소 크기를 더해 곧장 주소를 계산한다. 원소를 훑지 않으므로 입력 크기와 무관하게 연산 1회다. 이것이 O(1)이다.

O(n) — 입력 하나당 연산 하나

찾는 값이 맨 끝에 있거나 아예 없으면 배열 전체를 훑는다. 입력이 2배면 반복도 2배다. 이 비례 관계가 O(n)이다.

O(n²) — 중첩 반복은 곱해진다

바깥 루프가 n번, 그 안에서 안쪽 루프가 다시 도므로 비교 횟수는 대략 n × n / 2 = n²/2다. 상수 1/2를 버리면 O(n²)다. 중첩 반복이 보이면 곱셈을 의심한다.

O(log n) — 매번 절반으로 줄이기

한 번 비교할 때마다 탐색 범위가 절반으로 줄어든다. n을 1이 될 때까지 반으로 나누는 횟수가 log₂n이다. n = 1,000,000이어도 약 20번이면 끝난다. 단, 입력이 정렬되어 있어야 성립한다.

복잡도 등급별 연산 횟수 비교

n = 100만에서 O(n²)는 1조 번 연산한다. 1초에 1억 번을 처리하는 컴퓨터라면 약 2.7시간이 걸린다. 같은 입력을 O(n log n)으로 풀면 약 0.2초다. Big-O 등급 하나의 차이가 “즉시”와 “사실상 불가능”을 가른다.

정리

시간 복잡도는 입력이 커질 때 연산 횟수가 자라는 추세이고, Big-O는 그중 가장 빠르게 자라는 항만 남긴 표기다. 상수 계수와 작은 항을 버리는 이유는 n이 커지면 그것들이 추세를 바꾸지 못하기 때문이다. 코드를 볼 때는 반복의 중첩 구조를 본다. 단일 루프는 O(n), 중첩 루프는 O(n²), 매번 절반으로 줄이면 O(log n)이다.

판단 기준은 단순하다. 데이터가 작고 한 번만 도는 코드라면 복잡도는 거의 문제되지 않는다. 데이터가 크거나 반복 호출되는 핵심 경로라면, O(n²)를 O(n log n)이나 O(log n)으로 낮출 수 있는지 먼저 살핀다. 이 한 등급의 차이가 서비스가 견디는 규모를 결정한다.
