힙 정렬

힙 정렬

한 줄 요약: 힙 정렬은 배열을 “부모가 자식보다 항상 큰” 최대 힙(max-heap)으로 만든 뒤, 꼭대기의 최댓값을 맨 뒤로 빼내고 힙을 다시 정돈하는 과정을 반복해 정렬하는 알고리즘이다.

힙 정렬 구분

많은 원소를 효율적으로 정렬할 때 함께 비교할 만한 알고리즘으로 퀵 정렬과 병합 정렬이 있다. 퀵 정렬은 평균 시간 복잡도가 O(n log n)이지만, 분할이 계속 한쪽으로 치우치면 최악의 경우 O(n²)이 된다. 병합 정렬은 최악의 경우에도 O(n log n)을 보장하지만, 일반적인 배열 기반 구현에서는 병합 과정에 입력 크기에 비례하는 추가 배열이 필요하다.

그렇다면 최악의 경우에도 O(n log n)을 보장하면서 추가 메모리를 거의 사용하지 않는 정렬은 없을까? 이 두 조건을 함께 만족하는 대표적인 알고리즘이 힙 정렬이다. 핵심은 배열을 “최댓값을 O(log n)에 꺼낼 수 있는 자료구조”로 해석하는 데 있다. 배열을 힙(heap)으로 구성하면 최댓값을 하나씩 꺼내 뒤에서부터 배치할 수 있다.

이 개념을 이해하면 다음 내용을 함께 설명할 수 있다.

  • 우선순위 큐(priority queue)를 힙으로 구현하는 이유
  • C++ std::sort의 인트로 정렬(introsort)이 재귀가 너무 깊어질 때 힙 정렬로 전환하는 이유
  • 완전 이진 트리(complete binary tree)를 포인터 없이 배열로 표현하는 방법
  • 최악 시간 복잡도의 보장이 중요할 때 퀵 정렬 대신 힙 정렬을 고려하는 이유

이 문서에서는 배열이 힙으로 바뀌고, 힙에서 최댓값을 꺼낼 때마다 정렬 구간이 완성되는 과정을 실제 값의 이동을 통해 살펴본다.

힙 정렬 흐름

비유 — 매번 우두머리를 뽑아 뒤에 세운다

여러 사람을 키 순서로 줄 세운다고 생각해 보자. 먼저 토너먼트를 열어 가장 키가 큰 사람을 꼭대기에 올린다. 그 사람을 줄의 맨 뒤, 즉 가장 큰 값이 놓일 자리로 보내 위치를 확정한다. 한 명이 빠지면 남은 사람들로 다시 토너먼트를 열어 새로운 우두머리를 꼭대기에 올리고, 그 사람을 바로 앞자리에 보낸다. 한 명만 남을 때까지 반복하면 뒤쪽부터 큰 값의 자리가 차례로 확정되어 전체가 정렬된다.

여기서 “토너먼트 구조”가 힙이고, “꼭대기의 값을 뒤로 보낸 뒤 구조를 다시 정돈하는 과정”이 힙 정렬의 한 라운드다.

정의 — 힙, 완전 이진 트리, 배열 표현

  • 힙(heap): 부모 노드가 자식 노드보다 항상 크거나 같은 최대 힙, 또는 항상 작거나 같은 최소 힙의 성질을 만족하는 완전 이진 트리다. 힙 정렬에 최대 힙을 사용하면 루트에 전체 최댓값이 놓인다.
  • 완전 이진 트리(complete binary tree): 위에서 아래로, 같은 높이에서는 왼쪽에서 오른쪽으로 빈틈없이 채워지는 트리다. 이 구조는 노드를 배열에 순서대로 담아 표현할 수 있다.
  • 배열 표현: 트리의 노드를 배열 인덱스에 대응시킨다. 인덱스 i인 노드의
    • 부모는 (i - 1) / 2
    • 왼쪽 자식은 2i + 1
    • 오른쪽 자식은 2i + 2
  • 시프트 다운(sift-down, heapify): 어떤 노드가 힙의 순서 조건을 어기면 더 큰 자식과 자리를 바꾸면서 제자리를 찾을 때까지 아래로 내려보내는 동작이다. 최대 힙에서는 이 과정으로 힙 성질을 회복한다.

부모와 자식 사이를 포인터가 아닌 배열 인덱스 계산으로 이동할 수 있으므로, 힙 정렬은 입력 배열 안에서 별도의 배열 없이 동작한다.

어떻게 동작하는가 — 두 단계

  1. 빌드(build max-heap): 배열 전체를 최대 힙으로 만든다. 마지막 비단말 노드부터 0번 노드까지 역순으로 시프트 다운을 적용한다.
  2. 추출(sort down): 루트의 최댓값과 힙의 마지막 원소를 교환한다. 힙 크기를 1 줄여 방금 옮긴 최댓값을 정렬 구간으로 분리한다. 이어서 새로 루트에 온 값을 시프트 다운하여 힙 성질을 회복한다. 이 과정을 힙 크기가 1이 될 때까지 반복한다.

값으로 따라가기 — 빌드와 첫 추출

배열 [4, 10, 3, 5, 1]을 최대 힙으로 만든다. 마지막 비단말 노드는 인덱스 1이므로 인덱스 1과 0의 순서로 시프트 다운한다.

  • 인덱스 1(10): 자식은 5, 1이다. 부모가 이미 가장 크므로 그대로 둔다.
  • 인덱스 0(4): 자식 10, 3 중 10이 더 크므로 교환하면 [10, 4, 3, 5, 1]이 된다. 아래로 이동한 4는 자식 5보다 작으므로 다시 교환하여 [10, 5, 3, 4, 1]을 만든다.

이제 최대 힙 [10, 5, 3, 4, 1]이 완성되었고, 루트의 10이 전체 최댓값이다.

%% 최대 힙 예시와 첫 추출
flowchart TD
  root["10<br/>(i=0)"]
  left["5<br/>(i=1)"]
  right["3<br/>(i=2)"]
  left_left["4<br/>(i=3)"]
  left_right["1<br/>(i=4)"]
  note["배열: [10, 5, 3, 4, 1]<br/>부모 i의 자식: 2i+1, 2i+2<br/>루트에는 항상 최댓값<br/>빈틈없는 완전 이진 트리"]
  extract["추출<br/>10 ↔ 1 교환<br/>[1, 5, 3, 4 &#124; 10]<br/>힙 크기 4, 10 확정"]
  root --> left
  root --> right
  left --> left_left
  left --> left_right
  note -.-> extract

루트의 10을 맨 뒤로 보내 위치를 확정한 뒤, 남은 네 원소를 다시 힙으로 정돈한다. 추출을 한 번 더 수행하면 두 번째로 큰 값이 그 앞자리에 확정된다. 이 과정을 반복하면 뒤쪽부터 큰 값이 차례로 자리 잡아 최종적으로 [1, 3, 4, 5, 10]이 된다.

왜 최악의 경우에도 O(n log n)인가?

시프트 다운 한 번에 드는 비용은 트리 높이에 비례한다. 원소가 n개인 완전 이진 트리의 높이는 O(log n)이다.

추출 단계는 n에 비례하는 횟수만큼 반복되며, 각 추출에서는 최대 O(log n)이 드는 시프트 다운을 수행한다. 따라서 추출 단계의 전체 시간 복잡도는 O(n log n)이다.

빌드 단계는 각 노드에 시프트 다운을 적용하므로 언뜻 O(n log n)처럼 보인다. 그러나 노드 대부분은 트리 아래쪽에 있어 이동할 수 있는 거리가 짧다. 높이별 노드 수와 이동 거리를 합산하면 빌드 단계의 시간 복잡도는 O(n)이 된다.

따라서 전체 시간 복잡도는 빌드 O(n)과 추출 O(n log n)을 합친 O(n log n)이다.

이 상한은 입력 배열의 초기 정렬 상태에 좌우되지 않는다. 완전 이진 트리의 높이가 입력값의 배치와 무관하게 O(log n)으로 제한되기 때문이다. 따라서 힙 정렬은 최악 시간 복잡도의 보장이 필요한 상황에서 고려할 수 있다.

실제 시스템에서는 — 인트로 정렬의 안전망

  • C++ 표준 라이브러리 std::sort: 인트로 정렬(introsort)은 일반적으로 퀵 정렬 방식으로 진행하다가 재귀 깊이가 임계값을 넘으면 힙 정렬 방식으로 전환한다. 힙 정렬의 최악 시간 복잡도가 O(n log n)이므로 전체 정렬의 최악 성능을 제한하는 안전망이 된다.
  • 우선순위 큐: 운영체제 스케줄러나 다익스트라 최단 경로처럼 다음에 처리할 최댓값 또는 최솟값을 반복해서 꺼내야 하는 상황에서는 힙을 사용할 수 있다. 힙 정렬은 이 자료구조의 성질을 정렬에 적용한 알고리즘이다.

힙 정렬 코드

시프트 다운 — 작은 노드를 큰 자식과 바꾸며 내려보낸다 (C)

부모가 자식보다 작으면 두 자식 중 더 큰 값과 교환한다. 교환한 자리에서 비교를 반복하여 해당 값이 힙 성질에 맞는 위치에 이를 때까지 내려보낸다. n은 현재 힙의 크기를 나타내므로, 정렬 구간으로 분리된 뒤쪽 부분인 a[n] 이후는 비교 대상에서 제외된다.

빌드 — 마지막 비단말 노드부터 거꾸로 힙으로 만든다 (C)

자식이 없는 단말 노드는 그 자체로 힙 성질을 만족하므로 별도로 정돈할 필요가 없다. 마지막 비단말 노드의 인덱스는 n/2 - 1이다. 이 노드부터 역순으로 시프트 다운하면 아래쪽 부분 트리가 먼저 힙이 되고, 이를 바탕으로 상위 노드를 차례로 정돈할 수 있다.

본체 — 꼭대기를 뒤로 빼며 정렬한다 (C)

루프가 한 번 실행될 때마다 현재 최댓값이 a[end]에 확정되고 힙 크기는 1씩 줄어든다. 정렬 구간은 배열 뒤쪽에서 앞으로 확장되고, 힙 구간은 배열 앞쪽에서 줄어든다. 두 구간이 하나의 입력 배열을 나누어 사용하므로 별도의 정렬용 배열이 필요하지 않다.

정리

힙 정렬은 배열을 최대 힙으로 만든 뒤, 루트의 최댓값을 맨 뒤로 옮기고 남은 힙을 다시 정돈하는 과정을 반복한다. 완전 이진 트리를 배열 인덱스 계산(2i+1, 2i+2)으로 표현하므로 포인터나 별도의 배열이 필요하지 않다. 힙의 높이는 입력값의 배치와 무관하게 O(log n)이므로 최악의 경우에도 O(n log n)의 시간 복잡도를 보장한다. 다만 멀리 떨어진 부모와 자식 사이의 교환이 반복되어 캐시 지역성 측면에서 불리할 수 있으며, 같은 값의 기존 순서를 보존하지 않는 불안정 정렬이다.

따라서 최악 시간 복잡도의 보장과 적은 추가 메모리가 중요하다면 힙 정렬을 고려할 수 있다. 평균적인 실행 성능을 우선하면 퀵 정렬을, 같은 값의 기존 순서를 보존해야 한다면 안정 정렬인 병합 정렬을 비교 대상으로 삼을 수 있다. 힙 정렬의 핵심적인 선택 기준은 “최악 O(n log n) 보장과 제자리 정렬을 얻는 대신 평균 실행 성능과 안정성을 양보한다”는 점이다.
