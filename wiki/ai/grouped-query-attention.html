그룹화 쿼리 어텐션 (Grouped Query Attention)

그룹화 쿼리 어텐션 (Grouped Query Attention)

확인 범위: 이 문서는 GQA의 일반 원리와 n_heads·n_kv_heads에 따른 메모리와 표현 다양성의 선택 기준을 설명한다. 제시된 구조와 수치는 개념을 설명하기 위한 예시다. 특정 모델이나 구현의 실제 채택 여부와 정확한 메모리 절감·품질 효과는 해당 코드와 설정, 버전, 실행 기록, 성능 측정을 통해 별도로 확인해야 한다.

한 줄 요약: Grouped Query Attention은 여러 Query head를 몇 개의 그룹으로 묶고 그룹마다 Key/Value head를 공유함으로써, MHA와 MQA 사이에서 메모리 사용량과 표현 다양성의 절충점을 만든다.

그룹화 쿼리 어텐션의 위치

멀티헤드 어텐션은 각 head가 K/V를 따로 사용하므로 표현의 다양성이 크지만, decode 단계에서 사용하는 KV Cache 메모리도 크다. 반면 Multi Query Attention은 모든 Query head가 하나의 K/V 세트를 공유하므로 메모리를 크게 줄일 수 있지만, K/V의 다양성도 가장 많이 줄어든다.

GQA는 두 방식의 중간 지점을 택한다. 예를 들어 Query head가 32개이고 K/V head가 8개라면, Query head 4개가 K/V head 1개를 공유한다.

핵심 동작

먼저 Query head를 일정한 수로 묶어 그룹을 만들고, 각 그룹이 K/V head 1개를 공유하게 한다. n_heads=32, n_kv_heads=8이면 각 그룹은 32 / 8 = 4개의 Query head로 구성된다. 구현할 때는 K/V head를 그룹 크기만큼 반복해 Query head 수에 맞춘다.

%% GQA에서 K/V head를 반복해 Q head 수에 맞추는 흐름
flowchart LR
  q_in["Q<br/>(B, 32, T, D_h)"]
  q_out["attention 입력<br/>Q/K/V head 수 일치"]
  k_in["K<br/>(B, 8, T, D_h)"]
  k_repeat["repeat_kv<br/>그룹마다 4번 반복"]
  k_out["K<br/>(B, 32, T, D_h)"]
  v_in["V<br/>(B, 8, T, D_h)"]
  v_repeat["repeat_kv<br/>그룹마다 4번 반복"]
  v_out["V<br/>(B, 32, T, D_h)"]
  q_in --> q_out
  k_in --> k_repeat
  k_repeat --> k_out
  v_in --> v_repeat
  v_repeat --> v_out
  k_out -.-> q_out
  v_out -.-> q_out

n_kv_heads = n_heads이면 MHA이고, n_kv_heads = 1이면 MQA다. GQA는 두 방식 사이의 구조를 n_kv_heads 하나로 조절할 수 있는 일반형이다.

그룹화 쿼리 어텐션 예시

%% GQA에서 4개 Query head가 1개 KV head를 공유하는 예시
flowchart LR
  config["예시 설정<br/>n_heads = 32<br/>n_kv_heads = 8<br/>head_dim = 128"]
  q0["Q head 0~3<br/>4개 Query head"]
  q1["Q head 4~7<br/>4개 Query head"]
  q_mid["...<br/>같은 규칙 반복"]
  q7["Q head 28~31<br/>4개 Query head"]
  kv0["KV head 0<br/>K/V 공유"]
  kv1["KV head 1<br/>K/V 공유"]
  kv_mid["...<br/>KV head 2~6"]
  kv7["KV head 7<br/>K/V 공유"]
  config -.-> q0
  config -.-> q1
  config -.-> q_mid
  config -.-> q7
  q0 --> kv0
  q1 --> kv1
  q_mid --> kv_mid
  q7 --> kv7

KV Cache의 K/V head 축 메모리가 K/V head 수에 비례한다고 보면, 이 예시에서는 일반 MHA 대비 해당 메모리가 32 -> 8로 줄어든다. 이는 이 조건에서 4배 절약된다는 뜻이다. MQA처럼 32배까지 줄어들지는 않지만, 그 대신 더 많은 K/V 표현을 유지한다.

정리

  1. GQA는 Query head를 그룹으로 묶고 각 그룹이 K/V head를 공유한다. KV Cache의 K/V head 축 메모리가 K/V head 수에 비례한다는 조건에서는 MHA 대비 메모리가 n_heads / n_kv_heads배 줄어든다.
  2. GQA는 MHA(n_kv_heads = n_heads)와 MQA(n_kv_heads = 1)를 양 끝으로 두는 일반형이며, K/V 표현의 다양성과 메모리 사용량 사이의 균형을 n_kv_heads 하나로 조절한다.
  3. 실제 LLM이 이 절충형을 채택했는지, 그리고 품질 손실과 KV Cache가 얼마나 줄었는지는 모델별 코드·설정과 측정 결과를 확인해야 한다.

직접 확인하려면 모델 config에서 n_kv_heads가 1 < n_kv_heads < n_heads인지 살펴본다. 이 조건을 만족하면 구조상 GQA에 해당한다. 실제 절감 폭이 n_heads / n_kv_heads와 일치하는지는 KV 캐시 메모리 계산에서 별도로 확인한다.
