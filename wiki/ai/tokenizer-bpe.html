토크나이저와 BPE — 텍스트를 정수 시퀀스로 바꾸는 첫 관문

토크나이저와 BPE — 텍스트를 정수 시퀀스로 바꾸는 첫 관문

확인 범위: 이 문서는 토크나이저와 BPE의 일반 원리와 어휘 크기 선택의 트레이드오프를 설명하고, 제시된 코드는 특정 구현의 동작을 보여 주는 예시로 다룬다. 코드의 실제 동작, 라이브러리·모델별 버전 차이, 출력 결과와 성능에 관한 판단은 해당 환경의 소스와 버전, 실행 기록 및 측정을 별도로 확인해야 한다.

한 줄 요약: LLM은 문자열을 직접 처리하지 못한다. 토크나이저는 텍스트를 정수 ID 시퀀스로 변환하고, BPE는 그 변환 규칙을 학습하는 알고리즘이다.

토크나이저와 BPE가 비용을 줄이는 자리

신경망은 행렬 연산으로 작동한다. 문자열 “Hello”를 곱셈이나 덧셈에 넣을 수 없다. 문자열을 정수로 바꾸는 단계가 반드시 필요하다. 이 변환이 토크나이저의 역할이다.

문자 단위로 쪼개면 “understanding”이 13개 토큰이 된다. Self-Attention은 O(n²) 비용이므로 시퀀스가 길어지면 계산이 폭발한다. 반대로 단어 단위로 쪼개면 어휘가 수십만 이상으로 커지고, 학습 데이터에 없는 단어(OOV)를 처리할 수 없다.

서브워드 방식은 이 둘의 절충이다. 자주 등장하는 문자열은 하나의 토큰으로 묶고(“the”, “ing”), 드문 단어는 여러 서브워드로 분해한다(“un” + “der” + “stand” + “ing”). BPE(Byte Pair Encoding)는 가장 널리 쓰이는 서브워드 알고리즘으로, GPT 계열 대부분이 사용한다.

토크나이저의 품질이 모델 성능의 상한을 결정한다. 아무리 좋은 모델이라도 토크나이저가 망가뜨린 정보는 복구할 수 없다.

토크나이저와 BPE 차이

토크나이저는 두 단계로 나뉜다: **학습(train)**과 사용(encode/decode).

학습 단계에서 BPE는 다음을 반복한다.

  1. 초기 어휘를 개별 바이트(0~255) 256개로 시작한다.
  2. 전체 학습 코퍼스에서 가장 자주 나타나는 인접 토큰 쌍을 찾는다.
  3. 그 쌍을 하나의 새 토큰으로 병합하고 어휘에 추가한다.
  4. 원하는 어휘 크기에 도달할 때까지 2~3을 반복한다.

사용 단계(encode)에서는 새 병합 규칙을 학습하지 않는다. 이미 학습된 merge rule을 순서대로 적용해 입력 텍스트를 정수 ID 시퀀스로 바꾼다. decode는 이 정수 ID를 token byte열로 되돌린 뒤 UTF-8 문자열로 복원하는 역변환이다.

텍스트 "Hello"
  → UTF-8 바이트: [72, 101, 108, 108, 111]
  → byte offset 적용: [76, 105, 112, 112, 115]
  → merge rule 적용: (112, 112) → 260, (105, 260) → 261, ...
  → 최종 token ID 시퀀스

GPT-2 regex pre-tokenizer

GPT-2는 BPE를 적용하기 전에 정규식으로 텍스트를 단어·숫자·기호·공백 경계로 나눈다.

이 규칙은 "don't"를 ["don", "'t"]로, " hello"를 [" hello"]로 분리한다. 단어 앞 공백을 해당 토큰에 붙이면 공백만을 위한 별도 토큰이 늘어 시퀀스가 길어지는 것을 줄일 수 있다. 정규식으로 나눈 각 조각 안에서 BPE merge rule을 적용한다.

특수 토큰

모든 LLM은 텍스트 외의 제어 신호를 위한 특수 토큰을 사용한다.

  • <|endoftext|> — 문서 경계. 학습 시 서로 다른 문서 사이에 삽입한다.
  • <|im_start|>, <|im_end|> — 채팅 모델에서 system, user, assistant 역할 경계를 구분한다.
  • <bos>, <eos> — 문장 시작/끝을 표시한다.
  • <pad> — 배치 학습 시 서로 다른 길이의 시퀀스를 맞추기 위한 패딩이다.

이 토큰들은 BPE 학습에 포함되지 않고 어휘에 수동으로 추가된다.

어휘 크기의 트레이드오프

어휘가 커지면 같은 텍스트를 더 짧은 시퀀스로 표현할 수 있다. 하지만 임베딩 테이블의 파라미터 수도 비례해서 커진다. GPT-2의 어휘 크기는 50,257개, GPT-4의 cl100k_base는 100,277개다.

유니코드와 한글

UTF-8은 하나의 문자가 14바이트다. 한글 “가”는 3바이트(0xEA, 0xB0, 0x80)에서 시작한다. 충분한 학습 데이터가 있으면 이 3바이트가 하나의 토큰으로 병합되지만, 데이터가 부족하면 한글이 비효율적으로 토크나이징되어 같은 의미의 영어보다 35배 더 많은 토큰을 소모한다.

토크나이저와 BPE 코드

BPE 학습 — 핵심 루프

밑바닥 LLM 책의 BPETokenizer.train() 메서드다. 코퍼스를 UTF-8 바이트 시퀀스로 바꾼 뒤, 최빈 인접 쌍을 새 토큰으로 치환하는 과정을 반복한다.

_select_best_pair()는 시퀀스에서 가장 자주 등장하는 인접 쌍을 찾는다. _replace_pair()는 해당 쌍을 새 ID로 치환한다. 이 루프가 끝나면 self.merges에 병합 순서가 기록된다.

BPE 인코딩 — 학습된 규칙 적용

인코딩은 학습 때 기록한 merge rule을 순서대로 적용한다.

학습 때의 merge 순서대로 적용하는 이유가 있다. 예를 들어 (a, b) → ab를 먼저 병합한 뒤에 (ab, c) → abc를 병합해야 train 때와 같은 결과가 나온다. 순서를 바꾸면 토크나이제이션이 달라진다.

쌍 치환 — 핵심 연산

하나의 merge step에서 시퀀스 전체를 왼쪽에서 오른쪽으로 훑으며 해당 쌍을 겹치지 않게 치환한다.

tiktoken으로 실제 GPT-2 토크나이저 사용하기

책의 학습 단계에서는 tiktoken 라이브러리로 이미 학습된 GPT-2 토크나이저를 불러 결과를 확인한다.

이 단계는 “사용”이지 “학습”이 아니다. 새 입력이 왔다고 pair 빈도를 다시 세는 것이 아니라, 이미 학습된 규칙으로 token ID sequence를 만든다. tokenizer.n_vocab은 출력층이 맞혀야 할 class 개수와도 연결된다.

정리

토크나이저는 문자열을 모델이 다룰 정수열로 바꾸는 계약이다. BPE 학습은 자주 붙어 나오는 인접 쌍을 새 토큰으로 병합하는 과정이며, 인코딩은 그 규칙을 순서대로 적용하는 것이다. 어휘가 커지면 시퀀스는 짧아지지만 임베딩 테이블은 커지는 트레이드오프가 있다.

다음 문서 임베딩 룩업에서 이 정수 ID가 신경망이 계산할 수 있는 벡터로 바뀌는 과정을 본다. 어휘 크기 선택은 어휘 크기 트레이드오프에 연결한다.
