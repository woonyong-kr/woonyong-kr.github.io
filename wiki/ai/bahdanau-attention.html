Bahdanau 어텐션 — 인코더 전체를 다시 보는 디코더

Bahdanau 어텐션 — 인코더 전체를 다시 보는 디코더

한 줄 요약: Bahdanau Attention은 Seq2Seq 디코더가 매 시점마다 인코더의 모든 은닉 상태를 유사도 기반으로 가중합해, 고정 크기 context vector 하나에 의존하는 정보 병목을 해결한 최초의 attention 메커니즘이다.

Bahdanau 어텐션이 다루는 문제

Seq2Seq에서는 인코더의 마지막 은닉 상태 하나를 context vector로 삼아 디코더의 초기 상태에 전달한다. 입력이 5개 토큰이든 100개 토큰이든 전체 입력을 hidden_dim 크기의 벡터 하나에 담아야 한다. 디코더는 이 고정된 context에 의존해 모든 출력 토큰을 생성한다.

원문에서 언급한 실험 관찰에 따르면, Seq2Seq 모델의 BLEU 점수는 입력 문장이 2030토큰을 넘어갈 때 급격히 떨어진다. 그 원인은 인코더가 앞쪽 정보를 잃는 데 있다고 설명한다. 다만 이 문서에는 해당 결과의 실험 조건이나 출처가 제시되어 있지 않다. 따라서 2030토큰이라는 범위와 원인 설명을 모든 Seq2Seq 모델에 적용되는 일반적 기준으로 보기는 어렵다. 여기서는 고정 크기 context가 긴 입력의 정보를 보존하기 어렵다는 문제를 보여주는 관찰로 한정해 이해한다.

Bahdanau 등(2015)은 이 병목을 다음 질문으로 풀었다. “디코더가 출력 토큰을 생성할 때마다, 인코더의 모든 시점을 다시 참조하면 어떨까?” 고정된 context vector 하나만 사용하는 대신, 매 디코딩 시점마다 입력 시퀀스의 다른 부분에 집중(attend)하는 동적 context를 만드는 방식이다.

Bahdanau Attention은 Seq2Seq의 정보 병목을 다루기 위해 “유사도 → 가중합” 원리를 사용했다. 이 원리는 이후 Transformer의 Self Attention에서도 이어진다.

Bahdanau 어텐션 흐름

기본 Seq2Seq와 Attention Seq2Seq의 차이

기본 Seq2Seq의 정보 전달은 다음과 같다.

%% 기본 Seq2Seq의 마지막 context 전달
flowchart TD
  x1["x_1"]
  x2["x_2"]
  x3["x_3"]
  h3["h_3 = context"]
  s0["s_0 = context"]
  s1["s_1"]
  y1["y_1"]
  s2["s_2"]
  y2["y_2"]
  x1 --> x2
  x2 --> x3
  x3 --> h3
  h3 --> s0
  s0 --> s1
  s1 --> y1
  s1 --> s2
  s2 --> y2

디코더는 context 하나로 모든 출력을 생성한다. 출력 시점마다 인코더의 중간 상태 h_1, h_2를 다시 참조할 수 없다.

Attention Seq2Seq에서는 인코더의 모든 은닉 상태를 저장한다.

%% Attention Seq2Seq의 동적 context 생성
flowchart TD
  flow["인코더: 모든 은닉 상태 저장<br/>h_1 &#124; h_2 &#124; h_3 &#124; 각 디코더 시점에서 다시 참조<br/>↓ ↓ ↓<br/>s_1 &#124; → &#124; Attention &#124; → &#124; c_1 동적 context<br/>s_2 &#124; → &#124; Attention &#124; → &#124; c_2 다른 context"]

Attention은 디코더의 매 시점에 인코더의 모든 은닉 상태를 가중합해 그 시점에 맞는 context vector를 만든다. 따라서 y_1을 생성할 때와 y_2를 생성할 때 서로 다른 입력 영역을 주로 참조할 수 있다.

Bahdanau Attention의 세 단계

이 과정은 Attention은 부드러운 사전 조회에서 설명한 세 단계로 이루어진다. Bahdanau Attention은 유사도를 dot product가 아니라 작은 신경망(additive/MLP)으로 계산한다.

1단계. 유사도 계산 (alignment score)

  • s_{t-1}: 디코더의 이전 은닉 상태 (query 역할)
  • h_i: 인코더의 i번째 은닉 상태 (key 역할)
  • W_s, W_h: 학습 가능한 projection 행렬
  • v: 학습 가능한 가중치 벡터
  • e_{t,i}: 디코더 시점 t에서 인코더 시점 i의 관련성 점수

Transformer의 scaled dot-product는 Q @ K^T / sqrt(d_k)로 유사도를 구한다. Bahdanau Attention은 v^T · tanh(W_s · query + W_h · key)를 사용한다. 이 방식을 additive attention이라 부른다. query와 key를 각각 projection한 뒤 더하고 비선형 변환을 거쳐 관련성 점수를 만든다. 이 계산에는 dot product 방식보다 많은 파라미터와 연산이 필요하다.

2단계. 정규화 (attention weight)

모든 alignment score를 softmax로 정규화한다. 그 결과 모든 인코더 시점에 대한 가중치의 합은 1이 된다.

3단계. 가중합 (context vector)

가중치가 높은 인코더 시점의 정보일수록 context에 더 많이 반영된다. 이렇게 얻은 c_t가 디코더 시점 t의 동적 context vector다.

디코더 갱신

디코더는 이전 출력과 이전 은닉 상태에 방금 만든 동적 context를 더해 현재 상태와 출력 확률을 계산한다.

[s_t; c_t]는 은닉 상태와 context를 이어붙인(concatenate) 벡터다. 동적 context는 디코더가 현재 출력에 필요한 입력 정보를 다시 참조할 수 있게 한다.

왜 additive인가? dot product와의 비교

Bahdanau Attention과 Luong Attention(dot-product)은 유사도 점수를 계산하는 방식이 다르다.

  • Bahdanau (additive): e = v^T · tanh(W_s · s + W_h · h)
    • query와 key의 원래 차원이 달라도 각각 projection할 수 있다.
    • 비선형 변환(tanh)을 거친다.
    • 파라미터(W_s, W_h, v)가 추가로 필요하다.
  • Luong (dot-product): e = s^T · h
    • query와 key 차원이 같아야 한다.
    • 행렬 곱으로 점수를 계산한다.
    • Transformer의 scaled dot-product도 이 계열이다.

원문은 두 방식의 성능 차이가 크지 않으며 Transformer가 병렬 처리 효율을 위해 dot-product 방식을 채택했다고 설명한다. 다만 이 문서에는 성능 비교의 조건이나 결과가 제시되어 있지 않으므로, 성능 차이에 관한 문장은 제한된 설명으로 읽어야 한다.

Bahdanau 어텐션 코드

다음 numpy 구현은 Bahdanau Attention이 유사도 점수를 계산하고 인코더 은닉 상태를 가중합하는 과정을 보여준다.

설정한 가중치와 은닉 상태로 alignment score, attention weight, 동적 context를 차례로 계산한다.

projected_s + projected_h에서는 디코더 상태(query)와 인코더의 각 시점(key)을 같은 내부 차원으로 projection한 뒤 더한다. 이어서 tanh를 적용하고 v와 곱해 스칼라 점수를 만든다. dot product와 달리 두 벡터의 원래 차원이 달라도 W_s와 W_h가 attention 내부 차원에 맞춰줄 수 있다.

Seq2Seq와 비교

기본 Seq2Seq에서는 인코더의 마지막 은닉 상태 하나만 디코더에 전달한다.

이 예제의 Attention context는 5개 시점의 은닉 상태를 모두 참조한 가중합이다. 관련성 점수가 높은 시점에는 더 큰 가중치가 부여된다. 반면 기본 context는 마지막 시점의 은닉 상태만 사용한다. 코드는 두 context의 계산 방식과 값을 비교하지만, 별도의 성능 평가는 수행하지 않는다.

Bahdanau에서 Transformer로 이어지는 흐름

Bahdanau Attention의 구조를 소프트 사전 조회의 관점에서 보면 다음과 같다.

%% Bahdanau와 Transformer Self-Attention의 lookup 구조 비교
flowchart LR
  bahdanau["Bahdanau<br/>query = 디코더 상태 s_{t-1}<br/>key = 인코더 상태 h_i<br/>value = 인코더 상태 h_i<br/>score = additive (MLP)"]
  shared["공통 구조<br/>query로 key 조회<br/>유사도 계산<br/>value 가중합"]
  transformer["Transformer Self-Attention<br/>query = 같은 시퀀스의 토큰 i<br/>key = 같은 시퀀스의 토큰 j<br/>value = 같은 시퀀스의 토큰 j<br/>score = scaled dot-product"]
  bahdanau --> shared
  shared --> transformer

두 방식 모두 query와 key의 유사도를 구하고, 그 결과에 따라 value를 가중합한다. 그러나 attention이 연결하는 대상과 점수 계산 방식은 다르다.

  • Bahdanau Attention은 인코더와 디코더 사이에서 동작하는 cross-attention이다. Transformer Self-Attention은 한 시퀀스 안의 모든 토큰 쌍을 다룬다.
  • Bahdanau Attention은 additive score를 사용하고 Transformer는 dot-product score를 사용한다.
  • Bahdanau Attention에서는 같은 인코더 은닉 상태 h_i가 key와 value 역할을 한다. Transformer는 별도의 W_K, W_V로 둘을 분리한다.

따라서 두 구조는 동일하지 않지만, 고정 벡터 하나에만 의존하지 않고 query에 맞는 정보를 찾아 가중합한다는 원리를 공유한다.

정리

Bahdanau Attention은 Seq2Seq 디코더가 출력 토큰을 생성할 때마다 인코더의 모든 은닉 상태를 다시 참조하게 한다. 디코더의 이전 상태와 각 인코더 상태로 alignment score를 구하고, 이를 정규화한 가중치로 동적 context vector를 만든다. 이 구조는 마지막 은닉 상태 하나에 전체 입력을 압축해야 하는 의존을 줄인다.

Bahdanau의 additive score는 projection과 비선형 변환을 사용해 유사도를 계산한다. Luong Attention은 dot-product를 사용하며, Transformer는 scaled dot-product와 multi-head 구조를 사용한다. 각 구현에는 차이가 있지만, query로 key를 조회하고 관련도에 따라 value를 가중합한다는 “Attention = 소프트 사전 조회”의 틀로 함께 이해할 수 있다.
