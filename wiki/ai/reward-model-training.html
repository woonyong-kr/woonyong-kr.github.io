보상 모델 학습 — 사람의 선호 순위를 스칼라 점수로 바꾸는 모델

한 줄 요약: Reward Model(RM)은 (prompt, 답변) 쌍을 입력받아 스칼라 점수를 출력하는 모델이며, 사람이 매긴 답변 쌍의 선호 순위를 Bradley-Terry 손실로 학습한다.

보상 모델 학습 문제

RLHF 파이프라인에서 SFT가 끝난 모델은 지시를 따를 수 있다. 그러나 “어떤 답변이 더 좋은지” 판단하는 기준은 없다. 같은 질문에 여러 답변이 가능하고, 사람마다 선호가 다르다.

이 선호를 모델에 주입하려면 비교 판단을 숫자로 바꿔야 한다. Reward Model이 그 변환기다. 사람이 “A가 B보다 낫다”고 판단한 데이터를 보고, RM은 A에 더 높은 점수를 주도록 학습한다.

RM이 없으면 PPO 단계에서 “이 답변이 좋은지 나쁜지”를 판단할 기준이 없다. 보상 신호가 없는 강화학습은 방향을 모르는 최적화와 같다.

보상 모델 학습 계산

비유

시험 채점자를 교육하는 과정이다. 채점자(RM)에게 두 답안을 보여주고 “이쪽이 더 낫다”고 알려준다. 수백~수천 쌍을 보여주면 채점자는 좋은 답안과 나쁜 답안을 구분하는 기준을 스스로 학습한다. 이후 채점자는 처음 보는 답안에도 점수를 매길 수 있다.

아키텍처: GPT backbone + scalar head

RM의 구조는 분류 미세조정과 거의 같다. 차이는 출력 차원이 class 수가 아니라 1이라는 점뿐이다.

입력 토큰 (prompt + answer)
  → GPT backbone (forward_hidden)
  → hidden states: (B, T, d_model)
  → 마지막 토큰 hidden: (B, d_model)
  → reward_head (Linear, d_model → 1)
  → 스칼라 점수: (B,)

SW_AI-W13-gpt/src/finetune.py의 GPTForSequenceClassification과 비교하면 다음과 같다.

  • 분류 모델: Linear(d_model, num_labels) → class logits
  • 보상 모델: Linear(d_model, 1) → 스칼라 점수

마지막 토큰의 hidden state를 대표 벡터로 쓰는 이유는 동일하다. causal mask 때문에 마지막 위치는 앞의 모든 토큰을 참고할 수 있다.

선호 데이터의 형태

사람이 매기는 데이터는 절대 점수가 아니라 상대 순위다.

prompt: "양자역학을 설명해라"
y_win:  "양자역학은 원자 이하 세계의 물리법칙이다..."  (사람이 선택)
y_lose: "양자역학은 아인슈타인이 만든 이론이다..."     (사람이 탈락시킴)

하나의 prompt에 대해 SFT 모델이 여러 답변을 생성하고, 사람이 쌍을 비교해서 순위를 매긴다. 실제 운영에서는 하나의 prompt에 K개 답변을 생성하고, K(K-1)/2개의 비교 쌍을 만든다.

Bradley-Terry 모델

두 답변의 품질 차이를 확률로 모델링하는 방법이다. RM이 답변 A와 B에 각각 점수 r(A), r(B)를 줬을 때, 사람이 A를 선호할 확률을 다음과 같이 정의한다.

P(A > B) = sigmoid(r(A) - r(B))
         = 1 / (1 + exp(-(r(A) - r(B))))

점수의 절대값은 의미가 없다. r(A) = 5, r(B) = 3이든 r(A) = 105, r(B) = 103이든, 차이가 2이면 같은 확률을 준다. 중요한 것은 상대적 차이뿐이다.

왜 점수 차이만 학습하는가?

사람의 선호 판단 자체가 상대적이기 때문이다. “이 답변이 10점짜리다”라고 절대 점수를 매기면 채점자마다 기준이 다르다. “A가 B보다 낫다”는 비교 판단은 절대 기준 없이도 일관적으로 수집할 수 있다.

Bradley-Terry 모델은 이 비교 판단을 최소 가정으로 확률화한다. 점수가 높을수록 선호 확률이 높아지고, 점수 차이가 클수록 확신이 커진다.

손실 함수

사람이 y_win을 선택했으므로, P(y_win > y_lose)를 최대화한다. 이것의 음의 로그를 취하면 손실 함수가 된다.

loss = -log P(y_win > y_lose)
     = -log sigmoid(r(y_win) - r(y_lose))

r(y_win) - r(y_lose)가 양수이고 클수록 sigmoid 값이 1에 가까워지고 loss는 0에 가까워진다. 반대로 RM이 비선호 답변에 더 높은 점수를 주면 loss가 커진다.

왜 cross entropy가 아니라 이 손실인가?

형태를 풀어보면 binary cross entropy와 같다. “y_win이 이길 확률”을 예측하고, 정답은 항상 1(y_win이 이김)이다.

p = sigmoid(r_win - r_lose)
loss = -[1 * log(p) + 0 * log(1-p)]
     = -log sigmoid(r_win - r_lose)

분류 미세조정에서 cross_entropy(logits, label)을 쓰는 것과 같은 원리다. 차이는 입력이 class logits가 아니라 두 점수의 차이라는 점이다.

학습 레시피

실제 학습에서 중요한 결정들이다.

  • 초기화: SFT 모델의 가중치로 초기화한다. LM head를 제거하고 scalar head를 추가한다.
  • 학습률: SFT보다 낮게 설정한다. 1e-5 ~ 5e-6 범위가 일반적이다.
  • 에폭: 선호 데이터가 적으므로 1~3 에폭이면 충분하다. 과적합에 주의한다.
  • 배치 구성: 같은 prompt의 선호 쌍을 같은 배치에 넣으면 학습이 안정적이다.

보상 모델 학습 코드

밑바닥 LLM 레포(SW_AI-W13-gpt)에는 별도 Reward Model(GPT backbone + scalar head + PPO) 구현은 포함되어 있지 않다. 아래 RM 클래스와 학습 루프는 이 레포의 GPTModel과 GPTForSequenceClassification(src/model.py, src/finetune.py에 실재) 구조를 기반으로 작성한 의사 코드다.

단, 이 문서의 핵심인 Bradley-Terry pairwise 손실은 책 DPO 챕터(ch07/04_preference-tuning-with-dpo)에 실제 from-scratch 코드로 존재한다. DPO는 별도 RM을 두지 않고 정책 자신의 log 확률로 “암묵적 보상(implicit reward)“을 정의하지만, 손실 형태는 RM 학습의 -log sigmoid(r_win - r_lose)와 동일하다. 아래 ### 책의 실제 선호 학습 코드에서 실코드를 확인한다.

Reward Model 클래스

forward_hidden()은 SW_AI-W13-gpt/src/model.py의 GPTModel.forward_hidden 메서드다. Embedding → TransformerBlock N개 → LayerNorm까지 실행하고 LM head 직전의 hidden state를 반환한다. 분류 미세조정에서도 이 메서드를 사용한다.

학습 루프

이 코드의 핵심은 r_win - r_lose다. 두 점수의 차이를 sigmoid에 넣어 선호 확률로 바꾸고, 이 확률을 최대화한다.

책의 실제 선호 학습 코드 (DPO 챕터)

위 RM 학습 루프는 의사 코드지만, 같은 Bradley-Terry 손실이 책 DPO 챕터에 실제로 구현되어 있다. DPO는 별도 RM 대신 정책(policy_model)과 참조 모델(reference_model)의 log 확률 차이를 보상으로 쓴다.

먼저 선호/비선호 답변의 토큰별 log 확률을 시퀀스 단위로 모은다.

F.log_softmax + torch.gather로 답변 토큰의 log 확률을 뽑고, selection_mask로 패딩을 제외한 뒤 시퀀스당 하나의 스칼라(B,)로 줄인다. RM이 마지막 토큰 hidden으로 스칼라를 뽑는 것과 목적이 같다. “답변 하나 = 스칼라 하나”로 만드는 단계다.

그 다음 손실은 RM의 Bradley-Terry와 같은 sigmoid(점수 차이) 형태다.

losses = -F.logsigmoid(beta * logits)가 RM의 -log sigmoid(r_win - r_lose)와 같은 형태다. 차이는 두 가지다. RM은 별도 모델이 매긴 스칼라 점수의 차이를 쓰고, DPO는 정책과 참조 모델의 log 확률 차이(암묵적 보상)를 쓴다. chosen_rewards/rejected_rewards가 바로 RM 점수에 대응하는 양으로, DPO에서는 학습 진행을 추적하는 지표로만 쓴다. beta는 책 기본값 0.1이며 0.1~0.5 범위를 쓴다. 수치 안정성을 위해 torch.log(torch.sigmoid(...)) 대신 F.logsigmoid를 쓰는 점도 실무 포인트다.

텐서 shape 변환

선호 답변:
  input_win: (B, T_w)
    → forward_hidden → (B, T_w, d_model)
    → [:, -1, :] → (B, d_model)
    → reward_head → (B, 1) → squeeze → r_win: (B,)

비선호 답변:
  input_lose: (B, T_l)
    → forward_hidden → (B, T_l, d_model)
    → [:, -1, :] → (B, d_model)
    → reward_head → (B, 1) → squeeze → r_lose: (B,)

손실:
  r_win - r_lose: (B,)
  → sigmoid → (B,)
  → -log → (B,)
  → mean → scalar

구체적 숫자 예시

RM과 분류 모델의 비교

분류 미세조정 (GPTForSequenceClassification):
  input_ids → forward_hidden → last_hidden → Linear(d, num_labels) → class logits
  loss = cross_entropy(logits, label)

보상 모델 (RewardModel):
  input_ids → forward_hidden → last_hidden → Linear(d, 1) → scalar reward
  loss = -log sigmoid(r_win - r_lose)

공통: GPT backbone + 마지막 토큰 hidden → Linear head
차이: 출력 차원(class 수 vs 1), 손실 함수(CE vs pairwise ranking)

정리

Reward Model은 GPT backbone에 스칼라 head를 붙인 구조로, 사람의 선호 순위를 Bradley-Terry 손실로 학습한다. 점수의 절대값이 아니라 두 답변의 상대 차이가 학습 신호다. 분류 미세조정과 구조가 같고 출력 차원과 손실만 다르다. RM이 학습되면 PPO 단계에서 보상 신호로 사용된다.

연결 문서:

  • RM 점수를 보상 신호로 쓰는 강화학습 단계
  • SFT → RM → PPO의 3단계 파이프라인
  • RM 없이 선호를 직접 학습하는 대안
