트랜스포머 아키텍처 — 임베딩·블록·LM 헤드를 잇는 전체 조립도

한 줄 요약: 트랜스포머 아키텍처는 입력 임베딩 → 트랜스포머 블록 N개 → 최종 LayerNorm → LM 헤드로 토큰 ID를 받아 다음 토큰의 분포를 출력하는 전체 모델 구조다.

트랜스포머 아키텍처 필요성

트랜스포머 블록은 토큰 표현을 한 단계 변환하는 부품이다. 이 블록만으로는 텍스트를 입력받거나 다음 토큰을 예측할 수 없다. 토큰 ID를 벡터로 바꾸는 입구와 벡터를 어휘 분포로 바꾸는 출구를 함께 조립해야 한다.

이 문서에서 설명하는 트랜스포머 아키텍처는 이러한 부품을 연결한 전체 모델 구조다. 정수 토큰 ID 시퀀스를 입력하면 각 위치에서 다음에 올 토큰의 점수가 나온다. 이 점수에 softmax를 적용하면 확률 분포를 얻는다. 여기서는 개별 블록의 내부 동작보다 입력부터 출력까지 데이터가 흐르는 순서와 부품의 배치를 다룬다.

GPT 구조는 이 아키텍처를 디코더 전용(decoder-only)으로 특수화한 계열이다. 이 문서는 그 공통 골격을 다룬다.

트랜스포머 아키텍처 구조

공장 조립 라인에 비유할 수 있다. 원자재에 해당하는 토큰 ID는 입구에서 벡터로 바뀐다. 이 벡터는 같은 구조의 작업대에 해당하는 블록 N개를 차례로 통과한다. 마지막에는 검수대에 해당하는 최종 LayerNorm을 거친 뒤, 출고 창구에 해당하는 LM 헤드에서 어휘별 점수로 변환된다.

4단계 구성

  • 입력 임베딩 (Input Embedding)
    • 토큰 ID를 emb_dim 차원 벡터로 변환한다.
    • 토큰 임베딩과 위치 임베딩을 더해 순서 정보를 주입한다.
  • 트랜스포머 블록 × N (Transformer Block)
    • 각 블록은 Multi-Head Attention, FFN, LayerNorm, 잔차 연결로 구성된다.
    • 같은 구조의 블록을 N번 쌓아 토큰 표현을 반복해서 변환한다.
  • 최종 정규화 (Final LayerNorm)
    • 마지막 블록의 출력을 한 번 더 정규화한 뒤 LM 헤드에 전달한다.
  • LM 헤드 (Language Modeling Head)
    • emb_dim 벡터를 vocab_size 차원 로짓으로 사영(projection)한다.
    • 각 위치에서 다음 토큰에 대한 점수인 로짓이 나온다.

왜 마지막에 LayerNorm을 한 번 더 두는가?

여기서 다루는 Pre-Norm 구조에서는 블록 내부의 정규화가 서브레이어 앞에 놓인다. 따라서 마지막 블록은 정규화 이후의 서브레이어 출력을 잔차에 더한 상태로 내보낸다.

블록 출력 = x + attn(norm(x)) + ffn(norm(...))   ← 마지막 덧셈은 비정규화 상태

제시된 구조는 이 출력을 LM 헤드에 전달하기 전에 최종 LayerNorm으로 다시 정규화한다. 이 배치는 LM 헤드에 들어가는 값의 분포와 로짓 스케일을 안정화하려는 구성이다. 다만 이 문서에는 그 효과를 측정한 실행 결과가 제시되어 있지 않다.

트랜스포머 아키텍처 코드

PyTorch 구현 — 모델 조립

nn.ModuleList에는 같은 구조의 TransformerBlock이 n_layers개 담긴다. nn.Module을 상속한 모델에서는 등록된 서브모듈의 파라미터가 추적되므로 loss.backward()를 호출할 때 전체 모델의 기울기를 계산할 수 있다. tie_embeddings가 참이면 입력 임베딩과 LM 헤드가 가중치를 공유하므로 별도의 가중치를 둘 때보다 파라미터 수가 줄어든다.

PyTorch 구현 — 순전파 (forward)

forward_hidden은 임베딩, 블록 반복, 최종 정규화를 차례로 수행한다. forward는 그 결과를 LM 헤드에 전달하고, targets가 있으면 F.cross_entropy로 계산한 손실도 반환한다. reshape(-1, vocab)은 배치 차원과 시퀀스 차원을 합쳐 각 토큰 위치를 하나의 분류 대상으로 다루기 위한 변환이다.

PyTorch 구현 — 텍스트 생성 (추론 모드)

이 코드는 torch.no_grad()로 기울기 추적을 끈 상태에서 토큰을 생성한다. 매 단계마다 마지막 위치의 로짓을 보고 argmax로 점수가 가장 높은 다음 토큰을 고른다. 선택한 토큰을 입력 뒤에 붙이고 같은 과정을 반복하는 greedy 방식이다. 다른 선택 전략은 디코딩 전략에서 다룬다.

텐서 shape 흐름

  • 입력 토큰 ID: (B, T) B=배치, T=시퀀스 길이
  • InputEmbedding (토큰 + 위치)
  • 임베딩: (B, T, emb_dim) 예: (B, T, 768)
  • TransformerBlock × N shape 불변
  • 블록 출력: (B, T, emb_dim) (B, T, 768)
  • final_norm shape 불변
  • 정규화 출력: (B, T, emb_dim) (B, T, 768)
  • lm_head (Linear 768→vocab)
  • 로짓: (B, T, vocab_size) (B, T, 50257)
  • softmax (추론 시)
  • 다음 토큰 분포: (B, T, vocab_size)

제시된 구성에서는 블록을 통과하는 동안 shape이 (B, T, emb_dim)으로 유지된다. 따라서 같은 입출력 shape을 갖는 블록을 반복해서 쌓을 수 있다. shape은 입구인 임베딩에서 (B, T)에서 (B, T, emb_dim)으로 바뀌고, 출구인 LM 헤드에서 (B, T, vocab_size)로 다시 바뀐다.

정리

이 문서의 트랜스포머 아키텍처는 입력 임베딩 → 트랜스포머 블록 N개 → 최종 LayerNorm → LM 헤드 순서로 조립된다. 토큰 ID (B, T)를 입력하면 다음 토큰 로짓 (B, T, vocab_size)가 나온다. 블록 구간에서는 shape이 (B, T, emb_dim)으로 유지되므로 같은 구조의 블록을 반복할 수 있다. Pre-Norm 블록 뒤에는 최종 LayerNorm을 두고, 그 출력을 LM 헤드에 전달한다. 제시된 코드는 학습 시 F.cross_entropy로 손실을 계산하고, 추론 시 torch.no_grad 안에서 argmax로 토큰을 하나씩 이어 붙인다.
