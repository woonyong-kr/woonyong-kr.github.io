분산 학습 병렬화 (Distributed Training Parallelism)

분산 학습 병렬화 (Distributed Training Parallelism)

확인 범위: 이 문서는 분산 학습 병렬화의 일반 개념과 병목에 따른 선택 기준을 설명하며, 특정 분산 구현이나 코드·버전·실행 기록을 검증한 결과는 다루지 않는다. 실제 적용 가능성과 성능 판단에는 구체적인 구현 환경에서의 실행 및 측정이 필요하다.

분산 학습 병렬화는 큰 학습을 여러 GPU에 나누는 방법이다. 데이터를 나눌지, 모델 내부 행렬을 나눌지, 층을 나눌지 구분해야 병목이 메모리인지 통신인지 유휴 시간인지 판단할 수 있다.

분산 학습 병렬화 문제

LLM 학습은 한 GPU 안에서 끝나기 어렵다. 모델 파라미터가 크고, batch와 sequence length가 커질수록 활성값도 커지며, Adam 같은 optimizer는 파라미터 외 상태까지 들고 있어야 한다. 그래서 학습이 커지면 문제는 “모델을 어떻게 설계할까”에서 “이 계산과 메모리를 여러 GPU에 어떻게 나눌까”로 이동한다.

분산 학습 병렬화는 계산과 메모리를 나누는 여러 방법을 묶어 부르는 이름이다. 처음에는 “GPU를 여러 개 쓰면 빨라진다”로 보이지만, 실제로는 데이터를 나눌지, 모델 내부 행렬을 나눌지, 모델의 층을 나눌지를 먼저 갈라야 한다. 그래야 병목이 메모리인지, 통신인지, GPU 유휴 시간인지 보인다.

세 가지 나누는 축

분산 학습을 처음 볼 때는 세 가지 축으로 나누면 된다.

  • 데이터 병렬화
    • 같은 모델 복사본을 여러 GPU에 올린다.
    • 각 GPU가 서로 다른 미니배치를 처리한다.
    • backward 후 gradient를 모아 같은 업데이트를 적용한다.
  • 텐서 병렬화
    • 하나의 큰 행렬 곱을 여러 GPU에 쪼갠다.
    • 예를 들어 W_q, W_k, W_v나 FFN의 큰 linear layer를 열 또는 행 기준으로 나눈다.
    • 모델 한 층이 너무 커서 한 GPU에 부담될 때 필요하다.
  • 파이프라인 병렬화
    • Transformer block 여러 개를 GPU별로 나눈다.
    • GPU 0은 앞쪽 block, GPU 1은 중간 block, GPU 2는 뒤쪽 block을 맡는다.
    • microbatch를 흘려보내 GPU가 순서대로 작업하게 만든다.

이 셋은 서로 배타적인 선택지가 아니다. 큰 학습에서는 데이터 병렬화와 텐서 병렬화, 파이프라인 병렬화를 섞어 쓸 수 있다. 다만 처음 설명할 때는 “무엇을 나누는가”를 먼저 분리해야 헷갈리지 않는다.

작은 흐름 예시

작은 GPT 학습 루프를 기준으로 보면, 단일 GPU 학습은 대략 이렇게 흐른다.

데이터 병렬화는 이 흐름을 GPU마다 복제한다.

이 방식은 이해하기 쉽지만, 모델 전체가 각 GPU에 복제된다. 따라서 모델 파라미터 자체가 한 GPU에 너무 크면 데이터 병렬화만으로는 부족하다. 그때 텐서 병렬화나 FSDP/ZeRO 같은 파라미터 분할 방식이 필요해진다.

텐서 병렬화는 한 층 안의 계산을 나눈다.

파이프라인 병렬화는 층 묶음을 나눈다.

파이프라인은 모델을 나눌 수 있지만, 앞 GPU가 출력을 만들기 전까지 뒤 GPU가 기다리는 시간이 생긴다. 그래서 microbatch로 흐름을 잘게 쪼개 유휴 시간을 줄인다.

로컬 코드와의 경계

현재 볼트의 밑바닥 LLM 학습 루프는 단일 학습 루프와 batch 생성, gradient 누적을 먼저 이해하는 데 맞춰져 있다. 이 단계에서는 분산 런타임을 구현하기보다, 다음 질문을 분리하는 것이 중요하다.

  • batch가 너무 커서 메모리가 부족한가?
    • 먼저 그래디언트 누적이나 batch/sequence length 조정을 본다.
  • 모델 파라미터와 optimizer state가 너무 큰가?
    • GPU 메모리 관리에서 파라미터, gradient, optimizer state, activation을 나눠 본다.
  • 여러 GPU를 쓴다면 무엇을 나눌 것인가?
    • 데이터, 텐서, 파이프라인 중 병목에 맞는 축을 고른다.

정리

  1. 데이터 병렬화는 모델을 복제해 batch를 나누고, 텐서 병렬화는 한 층 안의 큰 행렬 계산을 나누며, 파이프라인 병렬화는 층 묶음을 GPU별 stage로 나눈다.
  2. 먼저 볼 질문은 “GPU를 몇 개 쓰는가”가 아니라 “무엇을 나눠야 병목이 풀리는가”다.
  3. 셋은 배타적이지 않아 큰 학습에서는 병목(메모리·통신·유휴 시간)에 맞춰 섞어 쓴다.

학습이 막힐 때는 먼저 OOM(메모리), GPU 간 통신 대기, stage 유휴(bubble) 중 어디에서 시간이 새는지 구분한다. 그다음에 나눌 축을 고르는 편이 덜 헷갈린다.
