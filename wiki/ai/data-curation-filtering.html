데이터 정제 필터링 (Data Curation Filtering)

한 줄 요약: 데이터 정제 필터링은 사전학습 원자료에서 모델이 배워도 되는 텍스트만 남기는 과정이며, 정제는 읽을 수 있게 고치는 일, 필터링은 학습에 넣을지 버릴지 판단하는 일로 갈린다.

데이터 정제 필터링은 사전학습 원자료에서 모델이 배워도 되는 텍스트만 남기는 과정이다. 정제는 텍스트를 읽을 수 있는 형태로 고치는 일에 가깝고, 필터링은 학습에 넣을지 버릴지 판단하는 일에 가깝다.

데이터 정제 필터링 구분

LLM은 데이터에 반복해서 등장하는 패턴을 배운다. 원자료에 깨진 HTML, 중복 문서, 자동 생성 스팸, 개인정보, 평가 데이터와 겹치는 문장이 섞이면 모델은 그 문제까지 같이 배운다.

사전학습 데이터 파이프라인에서 정제 필터링은 토큰화보다 앞에 온다.

이 순서가 중요한 이유는 단순하다. 토큰화한 뒤에는 사람이 원문 문제를 해석하기 어렵다. 깨진 문서인지, 개인정보가 섞였는지, boilerplate가 대부분인지 판단하려면 가능한 한 원문 텍스트 단계에서 걸러야 한다.

정제와 필터링의 차이

정제는 “고쳐서 살릴 수 있는가”를 본다.

  • HTML 태그 제거
  • 깨진 인코딩 수정
  • 줄바꿈과 공백 정리
  • 광고, 메뉴, footer 같은 반복 boilerplate 제거

필터링은 “학습에 넣을 가치가 있는가”를 본다.

  • 너무 짧은 문서 제거
  • 알파벳, 한글, 숫자 비율이 비정상적인 문서 제거
  • 같은 문장이 과도하게 반복되는 문서 제거
  • 개인정보나 민감한 식별 정보가 포함된 문서 제외
  • 평가 데이터와 겹칠 가능성이 높은 문서 제외

정제는 문서를 더 읽기 좋게 만들고, 필터링은 데이터셋의 경계를 정한다. 둘을 섞어서 생각하면 “조금 지저분하지만 귀한 문서”까지 버리거나, 반대로 “형식은 멀쩡하지만 학습에 해로운 문서”를 남기기 쉽다.

처리 방향은 서로 다르다.

  • A
    • HTML 태그만 제거하면 내용이 남는다.
    • 정제 후 학습 후보로 남길 수 있다.
  • B
    • 텍스트는 읽히지만 반복 스팸에 가깝다.
    • 필터링에서 제거 후보가 된다.
  • C
    • 문장은 읽히지만 민감 정보가 있다.
    • 삭제 또는 비식별화 정책 없이는 학습에 넣지 않는다.

즉, “깨끗한 문자열인가”와 “학습해도 되는 문서인가”는 같은 질문이 아니다.

간단한 규칙 예시

작은 실습에서는 완벽한 데이터 품질 모델보다, 재현 가능한 규칙을 먼저 두는 편이 낫다.

이 코드는 실제 대규모 데이터셋에 그대로 쓰기에는 거칠다. 그래도 판단 기준은 분명히 보여준다.

  • 너무 짧으면 문맥 학습에 도움이 적다.
  • 한 단어가 지나치게 반복되면 스팸일 수 있다.
  • 민감 정보 힌트가 있으면 학습 데이터에서 제외한다.

대규모 학습에서는 여기에 언어 판별, 중복 제거, 품질 분류기, 도메인별 샘플링, 평가 데이터 오염 검사까지 붙는다.

데이터 정제 필터링 선택 기준

정제 필터링은 강할수록 좋은 것이 아니다. 너무 약하면 저품질 데이터가 들어가고, 너무 강하면 희귀하지만 가치 있는 문서가 사라진다.

확인할 질문:

  • 제거 규칙을 나중에 재현할 수 있는가?
  • 제거된 샘플 일부를 사람이 직접 봤는가?
  • 훈련 데이터와 평가 데이터가 겹치지 않는가?
  • 짧은 문서, 코드 조각, 표 형식 문서를 무조건 버리고 있지는 않은가?
  • 특정 언어, 도메인, 말투만 과하게 남기고 있지는 않은가?

작은 모델 실습에서는 규칙을 단순하게 두되, “왜 버렸는지”를 기록하는 것이 더 중요하다. 그래야 나중에 모델이 이상하게 말할 때 데이터 문제인지 모델 구조 문제인지 추적할 수 있다.

정리

  1. 데이터 정제 필터링은 원자료에서 모델이 배워도 되는 텍스트만 남기는, 토큰화 이전 단계다.
  2. 정제는 읽을 수 있게 고치는 일(HTML 제거·인코딩 수정), 필터링은 학습에 넣을지 버릴지 판단하는 일(짧은 문서·스팸·민감정보·평가 오염 제외)로 갈린다.
  3. 너무 약하면 저품질이 들어가고 너무 강하면 희귀하지만 귀한 문서가 사라지므로, “왜 버렸는지”를 재현 가능하게 기록해야 한다.

직접 확인하려면: 깨끗한 HTML 문서·반복 스팸·민감정보 문서를 각각 규칙에 넣어, 정제로 살릴지 필터링으로 버릴지 다르게 갈리는지 본다.
