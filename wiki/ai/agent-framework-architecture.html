AI Agent — LLM이 스스로 판단하고 도구를 사용하는 자율 시스템

한 줄 요약: AI Agent는 LLM을 두뇌로 삼아 목표를 분석하고, 도구를 선택·실행하며, 결과를 관찰해서 다음 행동을 결정하는 자율 시스템이다.

AI Agent 문제

LLM은 텍스트를 입력받아 텍스트를 출력한다. 한 번의 호출로 끝나는 구조다. 사용자가 “서울 날씨를 확인하고, 비가 오면 우산을 챙기라고 슬랙에 메시지 보내 줘”라고 요청하면, 일반 LLM은 이 작업을 수행할 수 없다. 세 가지 한계 때문이다.

첫째, 행동 불가. LLM은 텍스트만 생성한다. 날씨 API를 호출하거나 슬랙 메시지를 보내는 것은 텍스트 생성이 아니다.

둘째, 단발성. 한 번의 입력-출력으로 끝난다. “날씨 확인 → 조건 판단 → 메시지 전송”처럼 여러 단계를 순서대로 실행하는 루프가 없다.

셋째, 판단 부재. 중간 결과를 보고 다음 행동을 바꾸는 능력이 없다. 날씨가 맑으면 메시지를 보내지 않아야 하지만, 단순 LLM 호출로는 이 분기를 처리할 수 없다.

AI Agent는 이 세 한계를 해결한다. LLM을 루프 안에 넣고, 매 단계마다 “지금 무엇을 해야 하는가”를 LLM에 물어본다. LLM이 도구 호출을 결정하면 실행하고, 결과를 다시 LLM에 돌려준다. 목표가 달성될 때까지 이 루프를 반복한다.

AI Agent 흐름

비유: 신입 사원과 도구 상자

LLM 단독 사용은 “질문에 답만 하는 사람”이다. AI Agent는 “업무를 맡기면 스스로 계획을 세우고, 필요한 도구를 꺼내 쓰고, 중간에 막히면 다른 방법을 시도하는 신입 사원”이다. 사원의 두뇌가 LLM이고, 도구 상자가 Function Calling이나 MCP다.

Agent 루프: 생각 → 행동 → 관찰 → 반복

Agent의 핵심은 루프다. 가장 대표적인 패턴은 ReAct(Reasoning + Acting)이다.

%% Agent 루프
flowchart TD
  start["Agent 루프<br/>목표와 현재 컨텍스트 입력"]
  thought["1. 생각<br/>Thought<br/>LLM이 현재 상태를 분석<br/>다음 행동을 결정"]
  action["2. 행동<br/>Action<br/>결정된 도구 실행<br/>API 호출"]
  observe["3. 관찰<br/>Observe<br/>실행 결과 확인<br/>컨텍스트에 결과 추가"]
  decision["목표 달성?"]
  final["최종 답변 생성<br/>Final response"]
  start --> thought
  thought --> action
  action --> observe
  observe --> decision
  decision --> final
  decision --> thought

각 단계를 풀어 보자.

  1. 생각(Thought): LLM에 현재까지의 대화 기록, 이전 행동의 결과, 사용 가능한 도구 목록을 넘긴다. LLM은 “다음에 어떤 도구를 어떤 인자로 호출할지” 또는 “이제 최종 답변을 반환할지”를 결정한다.
  2. 행동(Action): LLM이 선택한 도구를 실제로 실행한다. 날씨 API 호출, 파일 읽기, 코드 실행 등이다.
  3. 관찰(Observation): 도구 실행 결과를 LLM의 컨텍스트에 추가한다. LLM은 이 결과를 보고 다음 단계를 결정한다.

이 루프가 반복되면서 Agent는 복잡한 작업을 단계별로 해결한다.

Agent의 구성 요소

Agent를 만들려면 네 가지가 필요하다.

  1. LLM (두뇌): 추론과 판단을 담당한다. GPT-4, Claude, Gemini 등.
  2. 도구 (Tools): Agent가 실행할 수 있는 함수들. MCP Server로 제공하거나, Function Calling으로 직접 정의한다.
  3. 메모리 (Memory): 대화 기록과 중간 결과를 저장한다. 단기 메모리(현재 대화 컨텍스트)와 장기 메모리(벡터 DB에 저장된 과거 경험)로 나뉜다.
  4. 계획 (Planning): 복잡한 목표를 하위 작업으로 분해하는 능력이다. “여행 계획 세워 줘”를 “항공편 검색 → 호텔 검색 → 일정 조합”으로 나누는 과정이다.

주요 Agent 패턴

Agent 설계에는 몇 가지 대표 패턴이 있다.

  • ReAct: 생각과 행동을 번갈아 수행한다. 가장 기본적인 패턴이다. LLM이 자연어로 추론 과정을 출력한 뒤 도구를 호출한다.
  • Plan-and-Execute: 먼저 전체 계획을 세운 뒤 각 단계를 순서대로 실행한다. 복잡한 작업에 적합하다.
  • Tree of Thought: 여러 가능한 행동 경로를 트리 형태로 탐색한다. 각 경로의 결과를 평가하고 최선의 경로를 선택한다.
  • Multi-Agent: 여러 Agent가 역할을 나눠 협력한다. “검색 담당”, “코드 작성 담당”, “검증 담당”처럼 전문화된 Agent를 조합한다.

핵심은 for 루프다. 매 반복마다 LLM이 “도구를 호출할지, 최종 답변을 낼지”를 판단한다. 도구를 호출하면 결과를 messages에 추가하고 다음 반복으로 넘어간다. 최종 답변이면 루프를 끝낸다.

실제 구현에서는 다음을 추가한다.

  • 에러 처리: 도구 실행이 실패하면 에러 메시지를 LLM에 돌려주고 재시도하게 한다.
  • 최대 토큰 관리: 대화가 길어지면 오래된 중간 결과를 요약하거나 제거한다.
  • 가드레일: LLM이 위험한 도구(파일 삭제, 결제 등)를 호출하려 할 때 사용자 확인을 요청한다.

RAG와 Agent의 관계

RAG는 “검색 후 답변”이라는 고정된 파이프라인이다. Agent는 RAG를 도구 중 하나로 품을 수 있다. Agent가 “이 질문에 답하려면 문서 검색이 필요하다”고 판단하면 RAG 도구를 호출하고, “코드를 실행해야 한다”고 판단하면 코드 실행 도구를 호출한다. Agent는 RAG의 상위 개념이다.

정리

AI Agent는 LLM을 루프 안에 넣어 “생각 → 행동 → 관찰”을 반복하는 자율 시스템이다. LLM이 두뇌, 도구가 손과 발, 메모리가 기억, 계획이 전략이다. ReAct, Plan-and-Execute, Multi-Agent 등 다양한 패턴이 있으며, MCP로 도구를 표준화하면 Agent가 접근할 수 있는 외부 시스템의 범위가 넓어진다.
