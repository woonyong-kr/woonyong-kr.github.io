GPT-2 Zero-shot 평가

GPT-2 Zero-shot 평가

한 줄 요약: Zero-shot 평가는 사전학습된 모델에 과업별 학습 데이터를 한 건도 주지 않고, 프롬프트만으로 과업을 수행시키는 것이다. GPT-2는 이 방식이 가능함을 처음 대규모로 보여준 모델이다.

과업별 학습 없이 모델을 평가한다는 것

분류 미세조정이나 명령어 튜닝에는 과업별 라벨 데이터를 모으고 학습한 뒤 검증하는 과정이 필요하다. Zero-shot 평가는 이 과정을 거치지 않고 프롬프트만으로 모델의 과업 수행 능력을 측정한다. 과업별 데이터를 준비하고 별도로 학습하는 비용을 줄일 수 있는 지점은 여기다.

GPT-2 논문(Radford et al., 2019, “Language Models are Unsupervised Multitask Learners”)은 충분히 큰 언어 모델이 추가 학습 없이도 다양한 과업을 수행할 수 있다고 주장했다. 이 주장은 모델을 키우고 더 많은 텍스트로 사전학습하면 Fine-tuning 없이도 요약, 번역, 질의응답 같은 과업의 성능이 올라갈 수 있다는 관점으로 이어졌다. 이후 GPT-3의 few-shot과 GPT-4의 범용 능력을 설명하는 출발점이기도 하다.

밑바닥 LLM 책 Ch5는 사전학습 루프를 구현한 뒤 학습된 모델이 텍스트를 생성하는지 확인한다. 이 생성 과정은 과업별 데이터를 추가로 학습하지 않고 모델의 출력을 관찰한다는 점에서 zero-shot 평가와 맞닿아 있다. 다만 텍스트 생성 여부를 확인하는 것만으로 번역이나 질의응답 같은 개별 과업의 성능까지 검증했다고 볼 수는 없다.

Zero-shot, Few-shot, Fine-tuning의 차이

시험 공부 없이 시험을 보는 상황에 zero-shot을 비유할 수 있다. 수만 권의 책을 읽은 사람에게 “이 문장을 영어로 번역해줘”라고 요청하면 별도의 번역 훈련을 받지 않았더라도 어느 정도 번역할 수 있다고 가정하는 것이다. 이 비유는 사전학습 데이터에 여러 과업의 패턴이 자연스럽게 포함되어 있고, 모델이 그 패턴을 프롬프트에 맞춰 사용할 수 있다는 전제를 보여준다.

  • Zero-shot: 과업 예시 0건. 프롬프트에 지시만 적는다. “Translate to English: 안녕하세요 →”
  • Few-shot: 과업 예시 1~수십 건을 프롬프트에 포함한다. “안녕하세요 → Hello\n감사합니다 → Thank you\n잘자 →”
  • Fine-tuning: 수천~수만 건의 라벨 데이터로 모델 파라미터를 업데이트한다.

Zero-shot과 few-shot은 모델 파라미터를 바꾸지 않고 프롬프트, 즉 입력 텍스트만 바꾼다. Fine-tuning은 학습 데이터를 사용해 파라미터를 바꾼다.

GPT-2가 보여준 결과

GPT-2(1.5B 파라미터)는 과업별 학습 없이 다음 결과를 보였다.

  • 언어 모델링: WebText 테스트셋에서 perplexity 기준 당시 최고 성능
  • 번역: “Translate English to French:” 프롬프트로 BLEU 5점 (당시 supervised learning 모델 대비 낮지만 학습 데이터 0건)
  • 질의응답: CoQA에서 F1 55점 (supervised learning 모델의 89점 대비 낮지만 학습 없이)
  • 요약: TL;DR 프롬프트로 요약 생성 가능

이 결과에서 성능 자체는 fine-tuning 모델보다 낮았다. 의미가 있었던 지점은 과업별 학습 없이도 번역, 질의응답, 요약에 해당하는 출력을 만들 수 있었다는 점이다. 이는 모델 크기를 키우면 추가 학습 없이 수행할 수 있는 과업의 성능도 올라갈 것이라는 스케일링 가설의 근거가 되었다.

Zero-shot 평가는 어떻게 텍스트 생성으로 이어지는가

사전학습된 GPT에 프롬프트를 주면 모델은 이를 토큰으로 변환하고 다음 토큰을 반복해서 예측한다. 출력 시퀀스는 이 예측 결과를 입력 뒤에 하나씩 이어 붙여 만들어진다.

%% Zero-shot 텍스트 생성 흐름
flowchart TD
  prompt["입력 프롬프트<br/>&quot;Transformer는&quot;"]
  tokenizer["토크나이저"]
  token_ids["토큰 ID<br/>[15001, 230, ...]"]
  model["GPT 모델<br/>forward"]
  logits["logits<br/>(1, T, vocab_size)"]
  select["argmax 또는 sampling"]
  next_token["다음 토큰 ID<br/>[1523]"]
  append["입력 시퀀스 뒤에 이어 붙이기<br/>[15001, 230, ..., 1523]"]
  repeat["반복<br/>max_new_tokens번"]
  decode["디코더"]
  output["생성된 텍스트<br/>&quot;Transformer는 self-attention을 사용하여...&quot;"]
  prompt --> tokenizer
  tokenizer --> token_ids
  token_ids --> model
  model --> logits
  logits --> select
  select --> next_token
  next_token --> append
  append --> repeat
  repeat -->|다음 step 입력| model
  repeat -->|반복 종료| decode
  decode --> output

이 과정에서는 모델 파라미터를 업데이트하지 않는다. 모델은 forward pass만 반복한다.

Greedy 생성 — generate_text_simple()

밑바닥 LLM 책의 model.py에 구현된 가장 단순한 생성 함수다.

매 스텝에서 이 함수는 마지막 토큰 위치의 logits를 확인한다. 그중 값이 가장 큰 토큰을 argmax로 고른 뒤 입력 시퀀스 뒤에 붙인다. 입력이 context_size를 넘으면 앞쪽 토큰을 잘라낸다.

greedy는 언제나 확률이 가장 높은 토큰을 고르므로 같은 프롬프트에서 같은 출력을 만든다. 그 결과 반복적이거나 단조로운 텍스트가 나올 수 있다.

temperature와 top-k 샘플링

train.py의 generate() 함수는 temperature와 top-k를 지원한다.

이 함수는 마지막 위치의 logits를 temperature로 나눠 분포의 날카로움을 조절한다. 이어서 torch.masked_fill로 상위 top_k개 밖의 토큰을 차단하고, torch.multinomial로 남은 확률 분포에서 토큰 하나를 뽑는다. 실제 책 코드는 torch.no_grad 대신 torch.inference_mode를 쓴다. temperature <= 0이면 ValueError를 던지고, 생성이 끝나면 원래 학습 모드를 복원한다.

temperature < 1.0이면 확률 분포가 날카로워져 확률이 높은 토큰이 선택되기 쉬워진다. temperature > 1.0이면 분포가 평탄해져 여러 토큰이 선택될 가능성이 커진다. top-k는 상위 k개 후보만 남기고 나머지를 차단한다.

구체적 숫자로 보는 생성 과정

다음 코드는 GPT-small (vocab_size=50257, context_length=256)을 기준으로 한 예시다.

첫 입력에서 모델은 세 토큰 각각에 대한 logits를 만들지만, 생성에는 마지막 위치의 logits만 사용한다. temperature와 top-k를 적용한 뒤 다음 토큰을 뽑고, 그 토큰을 기존 입력 뒤에 붙여 같은 과정을 반복한다.

GPTModel의 forward 흐름

생성 함수가 호출하는 model(idx_cond)의 내부 흐름은 다음과 같다.

%% GPTModel forward 흐름
flowchart TD
  idx["idx_cond<br/>(1, T)<br/>토큰 ID 시퀀스"]
  embedding["embedding<br/>토큰 임베딩 + 위치 임베딩"]
  x["x<br/>(1, T, 768)<br/>벡터 시퀀스"]
  blocks["TransformerBlock × N"]
  hidden["hidden<br/>(1, T, 768)<br/>N개 블록 통과"]
  norm["final_norm<br/>LayerNorm"]
  hidden_norm["hidden_norm<br/>(1, T, 768)<br/>정규화된 은닉 상태"]
  head["lm_head<br/>Linear: 768 → 50257"]
  logits["logits<br/>(1, T, 50257)<br/>다음 토큰 점수"]
  last["생성에서 사용하는 값<br/>logits[:, -1, :]"]
  idx --> embedding
  embedding --> x
  x --> blocks
  blocks --> hidden
  hidden --> norm
  norm --> hidden_norm
  hidden_norm --> head
  head --> logits
  logits --> last

생성 시에는 logits[:, -1, :]만 사용한다. 이 값은 마지막 입력 위치 다음에 올 토큰의 점수다. 이전 위치의 logits는 다음 토큰을 선택하는 데 사용하지 않는다.

Perplexity로 사전학습 품질 보기

perplexity(PPL)는 사전학습 품질을 측정하는 기본 지표다.

PPL = exp(평균 cross-entropy loss)

cross-entropy loss가 2.0이면 PPL = exp(2.0) ≈ 7.4다. 이는 모델이 다음 토큰을 예측할 때 평균적으로 7.4개 후보 중 하나를 고르는 것과 같은 불확실성을 가진다는 해석이다.

PPL이 낮을수록 모델이 검증 데이터의 다음 토큰을 더 잘 예측한다. 따라서 사전학습 상태를 확인할 때 검증 데이터의 PPL을 측정할 수 있다. GPT-2는 WebText 테스트셋에서 이전 모델보다 낮은 PPL을 달성했다.

사전학습이 진행되면서 검증 데이터의 loss와 PPL이 낮아지면 다음 토큰 예측의 불확실성이 줄었다고 볼 수 있다. 이 지표는 자연스러운 텍스트 생성과 zero-shot 과업 수행을 뒷받침하는 사전학습 상태를 보여주지만, 특정 과업의 성능을 직접 대신 측정하지는 않는다.

평가 결과와 생성 코드를 함께 읽는 법

GPT-2의 zero-shot 결과는 과업별 학습 없이 번역, 요약, 질의응답을 시도할 수 있음을 보여준다. generate_text_simple()과 generate()는 이때 모델이 실제로 출력을 만드는 과정을 설명한다. 전자는 argmax로 다음 토큰을 고르고, 후자는 temperature와 top-k를 적용한 확률 분포에서 토큰을 뽑는다.

두 생성 함수는 모델 파라미터를 바꾸지 않는다는 점에서 zero-shot 실행 방식과 연결된다. 그러나 생성 코드가 동작한다는 사실과 개별 과업에서 일정한 성능을 달성했다는 평가는 구분해야 한다. 과업 성능은 BLEU, F1 같은 해당 평가 결과로 판단하고, 사전학습의 다음 토큰 예측 품질은 PPL로 살펴본다.
