학습 파이프라인 — 에폭, 배치, 이터레이션

한 줄 요약: 학습 데이터를 미니배치로 나누고, 배치마다 순전파 → 손실 계산 → 역전파 → 파라미터 갱신을 반복하는 구조가 학습 파이프라인이다. 전체 데이터를 한 번 사용하는 단위는 에폭이다.

전체 데이터를 한꺼번에 처리하지 않는 이유

역전파로 gradient를 구하고 옵티마이저로 파라미터를 갱신할 수 있어도, 실제 학습에서는 데이터를 한 번에 얼마나 처리할지 정해야 한다. MNIST 훈련 데이터 6만 장을 모두 한꺼번에 순전파한다고 생각해 보자.

입력 행렬의 크기는 (60000, 784)이고, 은닉층의 노드가 512개라면 중간 행렬은 (60000, 512)가 된다. 이 방식은 많은 메모리를 요구한다. 파라미터를 한 번 갱신하려면 전체 데이터의 gradient를 계산해야 하므로 갱신 간격도 길어진다. 반대로 샘플을 1개씩 처리하면 gradient의 분산이 커져 학습이 불안정해진다.

미니배치(mini-batch)는 이 두 방식 사이의 타협이다. 데이터를 128개씩 묶으면 한 번에 처리할 데이터의 크기를 줄이면서도 샘플 1개를 사용할 때보다 gradient를 안정적으로 계산할 수 있다. 학습 파이프라인은 이런 미니배치를 만들고 처리하는 반복 구조를 정의한다.

에폭, 이터레이션, 배치 크기

학습이 얼마나 진행되었는지 이해하려면 세 단위를 구분해야 한다.

  • 에폭(epoch): 전체 훈련 데이터를 한 번 모두 사용하는 단위다. 60000장을 128개씩 처리하면 1에폭 동안 약 469번 파라미터를 갱신한다.
  • 이터레이션(iteration): 미니배치 1개를 처리하는 단위다. 순전파 → 손실 계산 → 역전파 → 갱신까지가 1이터레이션이다.
  • 배치 크기(batch size): 미니배치 1개에 들어가는 샘플 수다. 보통 32, 64, 128, 256 중 하나를 쓴다.

에폭 수는 전체 데이터를 몇 번 반복해서 사용할지 결정한다. 배치 크기는 한 번에 처리할 데이터의 양을 결정하고, 이에 따라 에폭 안에서 파라미터를 갱신하는 횟수도 달라진다. 이터레이션 수는 다음과 같이 계산한다.

이터레이션 수 = 훈련 데이터 수 / 배치 크기 = 60000 / 128 = 468.75 → 올림하여 469

따라서 같은 1에폭이라도 배치 크기가 달라지면 이터레이션 수와 파라미터 갱신 횟수가 달라진다.

미니배치 하나를 처리하는 과정

1이터레이션에서는 다음 작업이 차례로 일어난다.

  1. 훈련 데이터에서 배치 크기만큼 무작위로 뽑거나, 셔플된 순서에서 해당 구간을 잘라낸다.
  2. 미니배치를 신경망에 순전파한다 → 예측값 y_pred.
  3. 예측값과 정답으로 손실을 계산한다 → L = CrossEntropy(y_pred, y_true).
  4. 손실에서 역전파하여 모든 파라미터의 gradient를 구한다.
  5. 옵티마이저가 gradient로 파라미터를 갱신한다 → W -= lr * dW.

이 5단계가 1이터레이션이다. 배치 크기가 128이면 1에폭 동안 이 과정을 469번 반복한다. 20에폭을 학습하면 파라미터를 총 9,380번 갱신한다.

에폭마다 데이터를 섞는 이유

에폭이 시작될 때마다 훈련 데이터의 순서를 섞는다(shuffle). 데이터를 섞지 않으면 매번 같은 순서와 구성으로 배치가 만들어져 gradient가 특정 방향으로 치우칠 수 있다. 예를 들어 MNIST의 앞부분에 0~2번 숫자가 몰려 있다면 첫 배치들의 gradient도 해당 클래스의 영향을 크게 받는다. 셔플은 배치마다 특정 순서나 클래스가 반복해서 집중되는 현상을 줄인다.

배치 크기에 따라 달라지는 학습 특성

배치 크기가 크면 여러 샘플에서 계산한 gradient를 함께 사용하므로 분산이 작고 학습이 안정적이다. GPU 병렬 연산의 효율도 높일 수 있다. 다만 1에폭 안에서 파라미터를 갱신하는 횟수가 줄어 수렴이 느릴 수 있다.

배치 크기가 작으면 gradient의 노이즈가 커져 local minimum을 빠져나올 가능성이 있다. 1에폭 안의 갱신 횟수도 많아져 빠르게 수렴할 수 있다. 반면 학습이 불안정해질 수 있고 GPU 활용률은 낮아진다.

이 문서의 MNIST 설정에서는 128을 실용적인 균형점으로 사용한다. 대규모 모델에서는 256~4096까지 쓰기도 한다.

전체 학습 파이프라인

전체 흐름에서는 에폭 루프 안에 이터레이션 루프가 들어간다. 각 에폭이 시작되면 60000개의 데이터 인덱스를 섞는다. 이후 128개씩 나눈 배치를 469번 처리하고, 각 배치에서 순전파·손실 계산·역전파·파라미터 갱신을 수행한다. 에폭이 끝나면 평균 손실을 loss_history에 기록한다.

  • 에폭 루프 (epoch = 1, 2, …, 20)
  • 셔플: indices = permutation(60000)
  • 이터레이션 루프 (iter = 1, 2, …, 469)
  • x_batch (128, 784)
  • 순전파 | → | 손실 계산 | → | 역전파
  • forward() | | CE Loss | | backward()
  • optimizer
  • .update()
  • W -= lr * dW
  • 에폭 평균 손실 기록 → loss_history

코드에서 학습 파이프라인 찾기

학습 루프 (training.py)

바깥쪽 for는 전체 데이터를 반복해서 사용하는 에폭 루프이고, 안쪽 for는 미니배치를 하나씩 처리하는 이터레이션 루프다. model.gradient()가 gradient를 구하면 optimizer.update()가 그 값을 사용해 파라미터를 바꾼다. 이 두 호출이 배치마다 반복되면서 학습이 진행된다.

1이터레이션 내부 흐름 (network.py)

model.gradient()가 호출되면 순전파부터 역전파까지 이어진다.

self.forward()가 예측 확률을 만들고, 그 예측과 정답으로 손실과 역전파의 출발점을 계산한다. 이어서 self.backward()가 각 층의 dW와 db를 저장한다. optimizer.update()는 저장된 self.grads를 읽어 파라미터를 갱신한다.

옵티마이저 갱신 (optimizers.py)

가장 단순한 SGD는 각 gradient에 학습률을 곱한 값을 현재 파라미터에서 뺀다.

params와 grads는 같은 키(W1, b1, W2, b2, …)를 공유하는 딕셔너리다. 역전파가 grads를 채우면 SGD는 각 키에 대응하는 params를 제자리에서 갱신한다.

데이터 로딩 (data.py)

학습 루프에 들어가기 전에 입력 데이터의 모양과 값의 범위를 맞춘다.

MNIST 이미지(28×28)는 784차원 벡터로 펼치고, 0255 범위의 값은 01로 정규화한다. 이 전처리는 미니배치를 만들기 전에 수행된다. 이 문서의 설명에서는 정규화하지 않을 경우 큰 입력값 때문에 gradient가 불안정해질 수 있다고 본다.

숫자로 이터레이션 수 추적하기

다음 코드는 훈련 데이터 60000개, 배치 크기 128, 20에폭이라는 설정에서 이터레이션 수를 계산한다.

이 계산에 따르면 1에폭은 469이터레이션이고, 20에폭은 총 9,380이터레이션이다. 파라미터가 약 53만 개(784×512 + 512 + 512×256 + 256 + 256×10 + 10 = 535,818)라면 각 이터레이션에서 이 파라미터들이 함께 갱신된다.

학습 루프를 다시 읽는 기준

학습 파이프라인은 데이터 로딩 → 미니배치 구성 → 순전파 → 손실 계산 → 역전파 → 파라미터 갱신으로 이어진다. 에폭은 전체 데이터를 한 번 사용하는 범위이고, 이터레이션은 배치 하나를 처리하는 과정이며, 배치 크기는 한 번에 처리하는 샘플 수다. 코드를 읽을 때는 에폭 루프와 이터레이션 루프를 먼저 구분한 뒤, 배치마다 gradient를 계산하고 파라미터를 갱신하는 호출을 찾으면 된다. 이 반복 구조 위에 정규화, 옵티마이저 선택, Early Stopping 같은 기법이 더해진다.
