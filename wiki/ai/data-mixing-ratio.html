데이터 혼합 비율 (Data Mixing Ratio)

데이터 혼합 비율 (Data Mixing Ratio)

확인 범위: 이 문서는 데이터 혼합 비율의 일반 개념과 목표 능력에 따른 선택 기준을 설명하며, 제시된 수치와 코드는 샘플링 방식을 보여 주기 위한 예시다. 특정 구현·버전의 동작이나 실제 학습 효과·성능을 검증한 결과는 아니므로, 그러한 판단에는 실제 코드와 실행 기록, 출처별 성능 측정이 필요하다.

한 줄 요약: 데이터 혼합 비율은 웹, 책, 코드, 대화 등 출처별 텍스트를 학습에 얼마씩 넣을지 정하는 기준이며, 무엇이 많이 있나가 아니라 모델이 어떤 능력을 가져야 하나에서 출발한다.

데이터 혼합 비율은 여러 출처의 텍스트를 학습 데이터에 어떤 비중으로 넣을지 정하는 기준이다. 웹 문서가 90% 있다고 해서 모델도 반드시 웹 문서를 90% 비율로 학습해야 하는 것은 아니다.

데이터 혼합 비율 문제

사전학습 데이터는 보통 한 종류가 아니다. 일반 웹 텍스트, 책, 코드, 문서, 위키, 대화 데이터가 함께 섞인다. 각 데이터는 모델에 다른 능력을 준다.

문제는 원자료의 양과 학습 가치가 항상 같지 않다는 점이다. 웹 텍스트는 많이 모이지만 품질 편차가 크고, 코드는 적어도 특정 능력에는 강한 영향을 준다. 그래서 데이터 혼합 비율은 “무엇이 많이 있나”가 아니라 “모델이 어떤 능력을 가져야 하나”에서 출발한다.

작은 숫자 예시

원자료가 다음처럼 있다고 하자.

원자료 비율 그대로 학습하면 대략 이렇게 된다.

그런데 코드 이해 능력이 중요한 모델을 만들고 싶다면 2%는 너무 작을 수 있다. 이때 학습 샘플링 비율을 다음처럼 바꿀 수 있다.

이 말은 원자료를 실제로 그 비율만큼 새로 모은다는 뜻이 아니다. 학습 batch를 만들 때 코드 데이터를 더 자주 뽑는다는 뜻이다.

실제 학습에서는 batch마다 정확히 이 숫자를 맞추기보다, 긴 시간 동안 평균 비율이 이 값에 가까워지도록 샘플러를 만든다.

많이 넣으면 무조건 좋아질까

특정 데이터 비율을 높이면 그 데이터의 능력은 좋아질 수 있지만, 다른 능력이 밀릴 수 있다.

  • 코드 비율을 높임
    • 장점: 코드 생성, 구조적 추론, API 패턴 학습에 도움
    • 위험: 자연어 답변이 딱딱해지거나 일반 상식 학습량이 줄 수 있음
  • 대화 데이터 비율을 높임
    • 장점: 질문과 답변 형식을 빨리 배움
    • 위험: 사전학습과 지시 튜닝의 경계가 흐려질 수 있음
  • 책/문서 비율을 높임
    • 장점: 긴 문맥과 설명 구조에 도움
    • 위험: 도메인 편향과 라이선스 검토 필요

혼합 비율은 한 번 정하면 끝나는 값이 아니라 실험 대상이다. 작은 모델에서도 web 80 / code 20, web 60 / code 40처럼 두세 가지 조합을 비교하면 모델 행동이 달라지는 것을 볼 수 있다.

정제 필터링과의 차이

데이터 정제 필터링은 “이 문서를 학습에 넣어도 되는가”를 묻는다. 데이터 혼합 비율은 “남긴 문서들을 어떤 비중으로 보여줄 것인가”를 묻는다.

둘은 순서도 다르다. 먼저 정제와 필터링으로 남길 문서를 정하고, 그 다음에 출처별 샘플링 비율을 조절한다.

데이터 혼합 비율에서 판단이 갈리는 지점

데이터 혼합 비율을 정할 때는 다음 질문을 남겨야 한다.

  • 모델의 목표 능력은 무엇인가?
  • 각 데이터 출처가 어떤 능력에 기여하는가?
  • 품질이 낮은 데이터를 비율만 높이고 있지는 않은가?
  • 작은 출처를 너무 자주 반복해 과적합시키지 않는가?
  • 검증 세트를 출처별로 나누어 성능을 확인했는가?
  • 학습 중간에 비율을 바꾸는 curriculum이 필요한가?

처음 배우는 단계에서는 복잡한 샘플러보다 작은 표본을 직접 세어 보는 것이 좋다. “이번 batch에 웹 문서가 몇 개, 코드가 몇 개 들어갔는가”를 확인하면 데이터 혼합이 추상적인 말이 아니라 실제 학습 입력의 비율이라는 점이 선명해진다.

정리

  1. 데이터 혼합 비율은 웹·책·코드·대화 등 출처별 텍스트를 학습에 얼마씩 보여줄지 정하는 샘플링 기준이다.
  2. 원자료의 양이 아니라 모델의 목표 능력에서 출발하며, batch를 만들 때 특정 출처를 더 자주 뽑는다는 뜻이다.
  3. 한 출처 비율을 높이면 그 능력은 오르지만 다른 능력이 밀릴 수 있어, 한 번에 정하는 값이 아니라 실험 대상이다.

직접 확인하려면: 작은 모델에서 web 80/code 20과 web 60/code 40 같은 두세 조합을 학습해, 출처별 검증 성능이 어떻게 갈리는지 본다.
