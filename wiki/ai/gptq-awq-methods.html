GPTQ와 AWQ 양자화 방법

한 줄 요약: GPTQ와 AWQ는 학습이 끝난 LLM 가중치를 낮은 비트로 바꾸는 후처리 양자화로, 가중치 저장 폭을 줄여 같은 GPU에 더 큰 모델·배치를 올린다.

GPTQ와 AWQ는 이미 학습이 끝난 LLM의 가중치를 낮은 비트로 바꾸는 후처리 양자화 방법이다. 두 방법 모두 추론에 필요한 메모리를 줄이지만, 양자화로 인한 품질 손실을 줄이는 기준은 서로 다르다.

GPTQ와 AWQ가 필요한 이유

LLM을 추론할 때는 모델 가중치와 KV cache가 GPU 메모리의 큰 부분을 차지한다. 양자화는 이 가운데 가중치의 저장 폭을 줄인다. 덕분에 같은 GPU에 더 큰 모델을 올리거나 배치 크기를 늘릴 수 있다.

7B 모델의 가중치를 FP16으로 저장한다고 가정하면, 가중치에만 대략 다음과 같은 메모리가 필요하다.

가중치를 4비트로 줄이면 단순 계산상 가중치 본문의 크기는 FP16의 4분의 1 수준이 된다. 실제 저장에는 scale, zero point, group metadata가 추가되고 kernel 제약도 따르므로 전체 메모리가 정확히 4분의 1이 되는 것은 아니다. 그래도 가중치가 만드는 메모리 병목은 줄일 수 있다.

가중치를 낮은 비트로 바꾸면 모델의 출력 품질이 흔들릴 수 있다. GPTQ와 AWQ는 이 손실을 줄이기 위해 어떤 가중치를 어떤 기준으로 보정하거나 보존할지를 다르게 판단한다.

단순 양자화는 W의 값을 일정한 간격에 맞춰 반올림한다.

GPTQ와 AWQ는 여기서 양자화가 출력에 미치는 영향까지 고려한다.

GPTQ는 calibration 데이터로 각 층의 출력을 살펴본다. 이미 낮은 비트로 바꾼 가중치에서 생긴 출력 오차를 줄이도록 나머지 가중치를 순차적으로 보정한다. 따라서 GPTQ가 다루는 질문은 “양자화된 가중치가 만든 오차를 남은 가중치에서 어떻게 보정할 것인가?”에 가깝다.

AWQ는 입력 activation에서 영향이 큰 channel에 주목한다. 모든 가중치를 같은 방식으로 줄이기보다, 실제 입력에서 크게 활성화되는 중요한 channel을 더 조심스럽게 보존한다. AWQ가 다루는 질문은 “실제 입력에 큰 영향을 주는 channel을 살리면서 가중치를 줄일 수 있는가?”에 가깝다.

두 방법 모두 모델을 다시 학습하지 않고 가중치를 작게 만드는 것이 목적이다. GPTQ는 양자화 오차를 순차적으로 보정하는 흐름에 무게를 두고, AWQ는 activation을 기준으로 중요한 channel을 보존하는 데 무게를 둔다.

GPTQ와 AWQ를 선택할 때 확인할 점

이미 배포된 GPTQ 형식 모델이나 kernel을 활용할 수 있거나, calibration 데이터로 층별 양자화 오차를 줄이는 PTQ 흐름이 필요하다면 GPTQ를 먼저 검토할 수 있다.

activation 분포에서 중요한 channel을 보존하는 방식이 적합하거나, 사용할 서빙 엔진이 AWQ weight-only quantization을 잘 지원한다면 AWQ를 먼저 검토할 수 있다.

어느 방법을 선택하든 quantization format 자체만 보고 결정해서는 부족하다. 대상 엔진이 해당 format과 kernel을 지원하는지 확인해야 한다. batch size와 context length, KV cache 메모리까지 포함했을 때 실제 병목이 줄어드는지도 살펴봐야 한다. 품질 평가는 perplexity나 task benchmark에 그치지 않고, 실제 서비스 prompt에서도 답변 품질이 유지되는지 확인해야 한다.
