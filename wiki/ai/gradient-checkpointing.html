그래디언트 체크포인팅 — 메모리를 시간으로 바꿔 큰 모델을 학습하는 기법

그래디언트 체크포인팅 — 메모리를 시간으로 바꿔 큰 모델을 학습하는 기법

범위: 이 문서는 그래디언트 체크포인팅의 일반 원리와 선택 기준을 설명하고 PyTorch 및 특정 GPTModel 루프에 적용하는 예시와 메모리·시간 추정치를 제시하지만, 해당 코드·버전에서의 실행 기록이나 성능 측정으로 검증한 결과는 아니다. 실제 절감량과 학습 시간 변화, 코드 호환성은 구체적인 구현과 실행 환경에서 별도로 확인해야 한다.

그래디언트 체크포인팅은 순전파 중간 활성값(activation)을 전부 저장하지 않고 일부만 남긴 뒤, 역전파 시 필요한 활성값을 다시 계산하여 GPU 메모리 사용량을 줄이는 기법이다.

그래디언트 체크포인팅 문제

신경망 학습에서 역전파는 순전파의 중간 결과를 필요로 한다. 오차역전파법에서 각 층의 gradient를 계산하려면 그 층의 입력값(활성값)이 있어야 한다. 일반적인 학습에서는 순전파를 돌리면서 모든 층의 활성값을 메모리에 저장해 둔다.

문제는 모델이 커지면 이 활성값이 차지하는 메모리가 폭발적으로 늘어난다는 점이다.

GPT-2 small(12층)을 sequence length 1024, batch size 8로 학습한다고 하자. 각 층의 활성값은 (batch, seq_len, emb_dim) = (8, 1024, 768) 크기의 텐서다. 이것이 12개 층, 각 층에 attention + feed-forward의 여러 중간 텐서까지 합치면 수 GB에 달한다. 모델 파라미터와 optimizer 상태에 더해 활성값까지 올려야 하므로 GPU 메모리가 부족해진다.

그래디언트 누적은 배치 크기를 줄여 메모리를 아끼지만, 활성값 자체를 줄이지는 못한다. 그래디언트 체크포인팅은 활성값 저장량을 직접 줄이는 기법이다.

그래디언트 체크포인팅 구조

비유

도서관에서 수학 문제를 푼다고 하자. 일반 방식은 각 단계의 중간 계산 결과를 전부 종이에 적어놓고, 나중에 검산할 때 그대로 쓰는 것이다. 종이가 넉넉하면 빠르지만, 종이가 부족하면 풀 수 없다.

체크포인팅 방식은 핵심 계산 결과만 종이에 남기고 나머지는 버린다. 검산할 때 필요한 중간 결과는 핵심 결과부터 다시 계산한다. 종이(메모리)를 아끼는 대신 계산(시간)을 더 한다.

일반 역전파 vs 체크포인팅 — 메모리 비교

일반 역전파에서 N개 층의 활성값 저장:

순전파: 입력 → [층1 활성값 저장] → [층2 활성값 저장] → ... → [층N 활성값 저장] → loss
역전파: loss → 층N gradient(층N 활성값 사용) → ... → 층1 gradient(층1 활성값 사용)
메모리: O(N) — 모든 층의 활성값을 동시에 보유

체크포인팅에서는 sqrt(N)개 층에만 활성값을 남긴다:

순전파: 입력 → [층1 저장] → 층2 버림 → 층3 버림 → [층4 저장] → 층5 버림 → ... → loss
역전파: loss → 층5~층4 구간 재계산 후 gradient → 층3~층1 구간 재계산 후 gradient
메모리: O(sqrt(N)) — 체크포인트 지점의 활성값만 보유

12개 층 기준으로 비교하면:

일반 역전파: 12개 층의 활성값 전부 저장 → 메모리 12 단위
체크포인팅(3~4개 체크포인트): 3~4개 층의 활성값만 저장 → 메모리 3~4 단위
절감율: 약 60~70%
대가: 순전파 계산을 약 1회 추가 (전체 학습 시간 약 20~30% 증가)

어떤 층을 체크포인트로 남기는가

가장 흔한 전략은 Transformer block 단위로 체크포인트를 걸어, 각 블록의 입력만 저장하는 것이다. 블록 내부의 attention score, feed-forward 중간값은 버린다. 역전파가 해당 블록에 도달하면 저장된 블록 입력부터 순전파를 다시 돌려 중간값을 복원한다.

  • 순전파
  • 입력 → [Block 0] → [Block 1] → [Block 2] → loss
  • ↓ 저장 버림 ↓ 저장
  • 체크포인트 0 체크포인트 1
  • 역전파 (Block 2 gradient 계산 시)
  • 체크포인트 1 → Block 2 순전파 재실행 → 중간값 복원
  • ↓
  • Block 2 gradient 계산
  • ↓
  • 중간값 즉시 해제

그래디언트 체크포인팅 코드

PyTorch는 torch.utils.checkpoint.checkpoint 함수로 체크포인팅을 지원한다. Transformer block의 forward에 적용하는 가장 간단한 형태를 보자.

checkpoint(block, x)가 하는 일:

  1. 순전파 시 block(x)를 실행하되, 블록 내부 중간값은 메모리에서 해제한다.
  2. x(블록 입력)만 저장한다.
  3. 역전파 시 저장된 x로 block(x)를 다시 실행해 중간값을 복원한다.
  4. 복원된 중간값으로 gradient를 계산한 뒤 즉시 해제한다.

밑바닥 LLM 책의 블록 루프에 적용하기

밑바닥 LLM 책의 GPTModel은 블록을 nn.ModuleList로 쌓고 for 루프로 순서대로 통과시킨다. 체크포인팅은 이 루프의 block(x) 호출만 감싸면 된다.

원본 루프는 모든 블록의 중간 활성값을 메모리에 유지한다. 체크포인팅을 끼우면 block(x) 호출만 checkpoint로 감싼다.

원본 모델 구조나 블록 로직은 전혀 바꾸지 않는다. for 루프의 호출 한 줄만 checkpoint로 감싸면 활성값 메모리가 줄어든다는 점이 핵심이다. causal_mask처럼 기본값이 있는 인자는 checkpoint가 그대로 기본값을 쓴다.

메모리 절감 수치 예시

GPT-2 small (12층, emb_dim=768, seq_len=1024, batch=8) 기준 활성값 추정:

한 블록당 주요 활성값:
  attention input:  8 × 1024 × 768 × 4B(fp32) = 24MB
  attention score:  8 × 12 × 1024 × 1024 × 4B = 384MB
  ffn 중간값:       8 × 1024 × 3072 × 4B = 96MB
  블록당 합계: 약 500MB

12개 블록 전체: 약 6GB

체크포인팅 적용 시:
  체크포인트 저장(블록 입력만): 12 × 24MB = 288MB
  역전파 중 한 번에 1블록의 중간값만 보유: 약 500MB
  합계: 약 800MB

절감: 6GB → 약 800MB (약 87% 감소)
대가: 순전파 1회 추가 (학습 시간 약 20~30% 증가)

다른 메모리 기법과의 조합

체크포인팅은 단독으로도 쓰지만, 다른 메모리 절약 기법과 함께 쓰면 효과가 더 크다. 그래디언트 누적은 한 번에 올리는 batch를 줄이고, 혼합 정밀도 학습은 활성값과 gradient의 바이트 수를 줄인다. 여기에 체크포인팅을 더하면 단일 GPU에서 학습 가능한 모델 크기가 크게 늘어난다.

정리

그래디언트 체크포인팅은 순전파 중간 활성값을 버리고 역전파 시 다시 계산하는 시간-메모리 교환 기법이다. 활성값 메모리를 O(N)에서 O(sqrt(N))으로 줄이는 대신 계산량이 약 20~30% 늘어난다. LLM처럼 깊은 모델에서는 GPU 메모리 부족을 줄이기 위해 그래디언트 누적, 혼합 정밀도 학습과 함께 자주 쓴다.
