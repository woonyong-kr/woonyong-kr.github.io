PPO 정책 최적화 — 보상 모델 점수로 언어 모델 정책을 갱신하는 강화학습

PPO 정책 최적화 — 보상 모델 점수로 언어 모델 정책을 갱신하는 강화학습

한 줄 요약: PPO(Proximal Policy Optimization)는 Reward Model이 매긴 점수를 보상 신호로 삼아 언어 모델(정책)을 업데이트하되, 한 번에 너무 크게 바뀌지 않도록 비율을 클리핑하는 강화학습 알고리즘이다.

PPO 정책 최적화 구분

Reward Model이 학습을 마치면 어떤 답변에든 점수를 매길 수 있다. 그러나 RM 자체는 점수만 줄 뿐, 모델의 가중치를 바꾸지 않는다. RM의 판단을 실제로 언어 모델의 행동에 반영하는 메커니즘이 필요하다.

SFT의 cross entropy loss는 “정답 토큰의 확률을 높여라”라는 신호를 준다. 정답이 하나의 토큰 시퀀스로 고정되어 있다. RLHF의 PPO는 “RM 점수가 높은 답변을 더 자주 생성하라”는 신호를 준다. 정답이 고정되어 있지 않고, 어떤 답변이든 점수가 높으면 강화된다.

이것이 SFT와 RLHF의 근본 차이다. SFT는 supervised learning이고, PPO는 강화학습이다.

PPO 정책 최적화 흐름

비유

학생(언어 모델)이 에세이를 쓴다. 채점자(RM)가 점수를 매긴다. 학생은 점수가 높았던 에세이의 작성 패턴을 강화하고, 점수가 낮았던 패턴을 약화한다. 단, 한 번의 피드백으로 작문 스타일을 완전히 바꾸면 기존에 잘 쓰던 것까지 망가질 수 있으므로, 조금씩 바꾼다.

강화학습 관점에서 언어 모델

언어 모델을 강화학습의 틀로 보면 다음과 같다.

정책 (Policy)    = 언어 모델 pi. 토큰을 하나씩 선택하는 주체.
상태 (State)     = 지금까지 생성한 토큰 시퀀스 (prompt + 이전 토큰).
행동 (Action)    = 다음 토큰 선택. vocab_size 크기의 이산 행동 공간.
보상 (Reward)    = 답변이 완성된 후 RM이 매긴 스칼라 점수.
에피소드 (Episode) = prompt 받기 → 토큰 생성 반복 → 답변 완성.

일반 강화학습과 다른 점은 행동 공간이 매우 크다는 것이다. vocab_size가 50,257이면 매 스텝마다 50,257개 선택지가 있다. 100 토큰짜리 답변은 50,257^100 가지 경로 중 하나다.

REINFORCE에서 PPO로

정책 경사 (Policy Gradient)

강화학습에서 정책을 최적화하는 가장 기본적인 방법이다. 보상이 높았던 행동의 확률을 높이고, 보상이 낮았던 행동의 확률을 낮춘다.

gradient = E[R * sum_t grad log pi(a_t | s_t)]

R은 에피소드의 총 보상이다. 보상이 양수이면 해당 행동들의 log 확률이 올라가고, 음수이면 내려간다.

문제는 분산이 크다는 점이다. 한 에피소드의 보상이 높았다고 해서 그 에피소드의 모든 토큰이 좋았다는 뜻은 아니다. 좋은 토큰과 나쁜 토큰이 섞여 있어도 보상이 전체에 동일하게 적용된다.

어드밴티지 함수 (Advantage Function)

분산을 줄이기 위해 보상 대신 어드밴티지를 사용한다. 어드밴티지는 “평균보다 얼마나 좋았는가”를 측정한다.

A(s, a) = Q(s, a) - V(s)

Q(s, a): 상태 s에서 행동 a를 한 뒤의 기대 보상
V(s):    상태 s의 기대 보상 (어떤 행동을 하든 평균적으로 받을 보상)
A(s, a): 행동 a가 평균보다 얼마나 나은가

A > 0이면 평균보다 좋은 행동이다. A < 0이면 평균보다 나쁜 행동이다. V(s)를 빼면 “모든 답변이 높은 보상을 받는 쉬운 prompt”에서 불필요한 강화를 막을 수 있다.

V(s)를 예측하기 위해 별도의 가치 네트워크(Value Network)를 사용한다. 구조는 RM과 비슷하다. GPT backbone에 스칼라 head를 붙이고, 현재 상태의 기대 보상을 예측한다.

PPO 클리핑

정책 경사의 또 다른 문제는 한 번의 업데이트가 너무 클 수 있다는 점이다. 정책이 크게 바뀌면 이전에 수집한 데이터가 현재 정책과 맞지 않아 학습이 불안정해진다.

PPO는 정책 변화의 크기를 비율(ratio)로 측정하고, 일정 범위를 넘으면 잘라낸다(clip).

ratio = pi_new(a|s) / pi_old(a|s)

ratio가 1이면 정책이 바뀌지 않았다. 1.2면 해당 행동의 확률이 20% 높아졌다. 0.8이면 20% 낮아졌다.

PPO의 클리핑된 대리 목적함수(clipped surrogate objective)는 다음과 같다.

L_CLIP = min(ratio * A, clip(ratio, 1-eps, 1+eps) * A)

eps는 보통 0.2다. ratio가 1-eps(0.8)에서 1+eps(1.2) 범위를 벗어나면 잘라낸다.

왜 클리핑이 작동하는가?

어드밴티지가 양수일 때(좋은 행동), ratio를 높이면 목적함수가 커진다. 하지만 ratio가 1.2를 넘으면 clip 때문에 더 이상 커지지 않는다. 좋은 행동이라도 확률을 과도하게 높이지 못한다.

어드밴티지가 음수일 때(나쁜 행동), ratio를 낮추면 목적함수가 커진다. 하지만 ratio가 0.8 아래로 내려가면 clip 때문에 멈춘다. 나쁜 행동이라도 확률을 과도하게 낮추지 못한다.

결과적으로 정책은 매 업데이트마다 조금씩만 바뀐다. 이것이 “Proximal” (근접)의 의미다.

RLHF에서 PPO의 전체 목적함수

RLHF에서는 RM 점수를 보상으로 사용하되, KL 페널티를 추가한다.

maximize  E[RM(x, y)] - beta * KL(pi_rl || pi_sft)

첫째 항은 RM 점수를 높이라는 뜻이다. 둘째 항은 RLHF 모델(pi_rl)이 SFT 모델(pi_sft)에서 너무 멀어지지 않도록 제약하는 것이다. KL 페널티가 없으면 reward hacking이 발생한다. 모델이 RM의 허점을 찾아 점수는 높지만 품질이 낮은 답변을 생성한다.

토큰 단위로 펼치면 다음과 같다.

reward_per_token_t = -beta * (log pi_rl(a_t|s_t) - log pi_sft(a_t|s_t))
reward_last_token += RM(x, y)  (마지막 토큰에 RM 점수를 더한다)

이렇게 만든 토큰별 보상으로 어드밴티지를 계산하고, PPO 클리핑으로 정책을 업데이트한다.

RLHF PPO에 관여하는 모델 4개

%% RLHF PPO에 관여하는 모델 4개
flowchart TD
  policy["현재 정책<br/>pi_rl<br/>(학습 대상)"]
  reference["참조 정책<br/>pi_sft<br/>(frozen)"]
  value["가치 네트워크<br/>V(s)<br/>(학습 대상)"]
  reward["Reward Model<br/>RM(x, y)<br/>(frozen)"]
  policy <-->|KL 계산| reference
  policy -->|rollout 상태| value
  reference --> reward

pi_rl과 V(s)만 학습된다. pi_sft와 RM은 고정이다. 이 때문에 RLHF PPO는 메모리를 많이 사용한다. 최소 4개 모델을 동시에 올려야 한다.

PPO 정책 최적화 코드

밑바닥 LLM 레포(SW_AI-W13-gpt)에는 PPO 구현이 포함되어 있지 않다. 강화학습 단계는 책의 범위를 벗어난다. 다만 PPO 업데이트가 의존하는 두 가지 실코드 기반은 이 레포에 그대로 있다. 하나는 토큰 logits를 뽑는 GPTModel.forward이고, 다른 하나는 손실을 역전파해 가중치를 갱신하는 학습 루프다. PPO 루프의 loss.backward() / optimizer.step()은 아래 사전학습 루프와 같은 PyTorch 기본기를 그대로 쓴다. 차이는 loss를 cross entropy 대신 클리핑된 대리 목적함수로 바꾸는 것뿐이다.

학습 루프의 실코드 기반 (PPO도 그대로 쓴다)

이 세 줄(zero_grad → backward → step)이 PyTorch 학습의 최소 단위다. autograd가 loss에서 역방향으로 그래프를 따라가며 각 파라미터의 gradient를 채우고, optimizer가 그 gradient로 가중치를 한 스텝 갱신한다. PPO도 이 골격을 그대로 쓰되 loss만 policy_loss + value_loss로 바꾼다. 아래 의사 코드는 이 레포의 GPTModel 구조를 기준으로 그 위에 RL 부분만 얹은 것이다.

가치 네트워크 (Value Network)

RM은 마지막 토큰만 사용하지만, Value Network는 각 토큰 위치의 기대 보상을 예측한다. 토큰별 어드밴티지를 계산하기 위해서다.

PPO 학습 루프

이 코드의 핵심 흐름은 세 가지다.

  1. 현재 정책으로 답변을 생성하고 log 확률을 저장한다.
  2. 토큰별 보상을 KL 페널티와 RM 점수로 구성한다.
  3. ratio를 클리핑한 목적함수로 정책을 업데이트한다.

구체적 숫자 예시

전체 데이터 흐름

%% PPO 전체 데이터 흐름
flowchart TD
  prompt["prompt"]
  answer["pi_rl.generate()<br/>answer tokens"]
  old_log_probs["compute_token_log_probs(pi_rl)<br/>old_log_probs: (B, T_ans)"]
  ref_log_probs["compute_token_log_probs(pi_sft)<br/>ref_log_probs: (B, T_ans)"]
  rm_score["reward_model(prompt+answer)<br/>rm_score: (B,)"]
  kl["kl<br/>old_log_probs - ref_log_probs<br/>(B, T_ans)"]
  rewards["rewards<br/>-beta*kl<br/>rewards[:, -1] += rm_score<br/>(B, T_ans)"]
  values["value_net<br/>values: (B, T)"]
  advantages["GAE(rewards, values)<br/>(B, T_ans)"]
  new_log_probs["new_log_probs<br/>(B, T_ans)"]
  ratio["ratio<br/>exp(new - old): (B, T_ans)"]
  clipped["clip(ratio, 1-eps, 1+eps)"]
  policy_loss["policy_loss<br/>min(ratio*A, clipped*A)"]
  prompt --> answer
  answer --> old_log_probs
  answer --> ref_log_probs
  answer --> rm_score
  old_log_probs --> kl
  ref_log_probs --> kl
  kl --> rewards
  rm_score --> rewards
  rewards --> advantages
  values --> advantages
  advantages --> clipped
  answer -->|PPO update| new_log_probs
  old_log_probs --> ratio
  new_log_probs --> ratio
  ratio --> clipped
  clipped --> policy_loss

정리

PPO는 RLHF 파이프라인의 마지막 단계로, RM의 점수를 보상 신호로 삼아 정책을 강화학습으로 갱신한다. ratio 클리핑이 핵심 메커니즘이다. 정책 변화의 크기를 제한하여 학습을 안정적으로 만든다. KL 페널티가 SFT 모델에서 너무 멀어지는 것을 막아 reward hacking을 방지한다. 메모리 측면에서는 정책, 참조 정책, 가치 네트워크, RM의 4개 모델이 필요해 비용이 크다. 이 비용 문제가 DPO가 등장한 동기 중 하나다.

연결 문서:

  • PPO에 보상 신호를 공급하는 RM 학습 과정
  • SFT → RM → PPO의 3단계 파이프라인
  • RM과 PPO 없이 선호를 직접 학습하는 대안
