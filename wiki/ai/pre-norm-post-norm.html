Pre-Norm vs Post-Norm — LayerNorm을 어디에 놓느냐가 바꾸는 것

확인 범위: 이 문서는 Pre-Norm과 Post-Norm의 배치, gradient 흐름, 선택 기준을 개념적으로 설명하고 입력에 제시된 코드가 Pre-Norm 구조임을 해석한다. 다만 특정 모델·코드 버전의 실제 동작과 학습 안정성·수렴 성능에 관한 판단은 원본 코드, 버전, 실행 기록 및 성능 측정을 별도로 확인해야 한다.

한 줄 요약: Pre-Norm은 서브레이어 앞에, Post-Norm은 서브레이어 뒤에 LayerNorm을 배치한다. GPT-2 이후 대부분의 LLM은 Pre-Norm을 쓰며, 깊은 모델에서 학습이 더 안정적이다.

Pre-Norm vs Post-Norm 문제

Layer Normalization이 무엇인지는 이미 알고 있다고 가정한다. 문제는 어디에 넣느냐다.

Transformer 블록은 Multi-Head Attention과 Feed-Forward Network라는 두 개의 서브레이어를 가진다. 각 서브레이어에는 잔차 연결(숏컷 연결 — 깊은 신경망의 기울기를 살리는 우회 경로)과 LayerNorm이 함께 붙는다. 이때 LayerNorm이 서브레이어 앞에 오느냐 뒤에 오느냐에 따라 gradient 흐름이 달라지고, 깊은 모델의 학습 안정성이 크게 바뀐다.

원래 Transformer 논문(Vaswani et al., 2017)은 Post-Norm을 사용했다. 그런데 층을 깊게 쌓으면 학습이 불안정해지는 문제가 있었다. GPT-2(2019)가 Pre-Norm으로 바꾼 이후, 대부분의 LLM이 Pre-Norm을 표준으로 채택했다.

이 문서를 읽고 나면 두 구조의 수식 차이, gradient 흐름의 차이, 그리고 밑바닥 LLM 책의 코드가 왜 Pre-Norm을 쓰는지 판단할 수 있다.

Pre-Norm vs Post-Norm 차이

두 구조의 차이 — 수식으로 보기

서브레이어를 SubLayer()라 하자. 잔차 연결과 LayerNorm의 배치 순서가 다르다.

Post-Norm (원래 Transformer, 2017):

output = LayerNorm(x + SubLayer(x))

서브레이어를 먼저 통과하고, 잔차를 더한 뒤, 마지막에 정규화한다.

Pre-Norm (GPT-2 이후):

output = x + SubLayer(LayerNorm(x))

먼저 정규화하고, 서브레이어를 통과한 뒤, 잔차를 더한다.

구조 다이어그램

flowchart LR
  subgraph post["Post-Norm"]
    post_x["x"] --> post_sub["SubLayer"]
    post_sub --> post_add["+"]
    post_x -->|"잔차 연결"| post_add
    post_add --> post_ln["LayerNorm"]
  end

  subgraph pre["Pre-Norm"]
    pre_x["x"] --> pre_ln["LayerNorm"]
    pre_ln --> pre_sub["SubLayer"]
    pre_sub --> pre_add["+"]
    pre_x -->|"잔차 연결"| pre_add
  end

차이는 한 가지다. LayerNorm이 잔차 합산 뒤에 오느냐(Post), 서브레이어 앞에 오느냐(Pre).

왜 Pre-Norm이 더 안정적인가? — gradient 흐름

핵심은 잔차 경로의 gradient다.

Post-Norm에서 역전파를 추적하면:

output = LayerNorm(x + SubLayer(x))
d_output/d_x = d_LN/d_input * (1 + d_SubLayer/d_x)

LayerNorm의 미분이 잔차 경로 전체를 감싼다. 층이 깊어지면 이 LayerNorm 미분이 연쇄적으로 곱해져 gradient 크기가 불안정해진다.

Pre-Norm에서는:

output = x + SubLayer(LayerNorm(x))
d_output/d_x = 1 + d_SubLayer/d_x * d_LN/d_x

잔차 경로의 gradient가 1이다. LayerNorm 미분은 서브레이어 경로에만 영향을 준다. 층을 96개 쌓아도 잔차 경로를 통해 gradient가 1로 직통한다. 이것이 기울기 소실을 막는 핵심이다.

Pre-Norm의 대가

Pre-Norm이 무조건 좋은 것은 아니다.

  • Pre-Norm은 최종 출력이 LayerNorm을 거치지 않는다. GPT 구조에서는 마지막 블록 뒤에 별도의 final_norm을 추가해 이를 보완한다.
  • 일부 연구(On Layer Normalization in the Transformer Architecture, Xiong et al., 2020)에 따르면, Post-Norm은 warmup을 충분히 주면 수렴 후 성능이 Pre-Norm보다 약간 높을 수 있다. 하지만 warmup 없이 학습하면 발산한다.
  • Pre-Norm은 학습이 안정적인 대신, 층이 깊어질수록 각 서브레이어의 기여가 줄어드는 경향이 있다.

실무에서는 학습 안정성이 성능 차이보다 중요하기 때문에 GPT-2, GPT-3, LLaMA, Mistral 모두 Pre-Norm을 쓴다.

Pre-Norm vs Post-Norm 코드

밑바닥 LLM 책의 TransformerBlock —

docstring이 구조를 말해준다: “LayerNorm -> Causal Self-Attention -> residual”. LayerNorm이 Attention보다 앞에 있다. 이것이 Pre-Norm이다.

GPTModel의 final_norm — Pre-Norm의 보완

Pre-Norm 구조에서는 각 블록이 LayerNorm → SubLayer → 잔차 순서로 진행한다. 마지막 블록의 출력은 LayerNorm을 거치지 않은 상태다. 그래서 final_norm을 별도로 추가한다.

Post-Norm이었다면 각 블록 출력이 이미 정규화된 상태이므로 final_norm이 필요 없다.

두 구조를 numpy로 비교

Post-Norm 출력은 항상 평균 0, 분산 1 근처다. Pre-Norm 출력은 입력 x의 스케일을 유지한다. 이 차이가 final_norm이 필요한 이유다.

정리

Pre-Norm과 Post-Norm은 LayerNorm의 위치만 다르지만, gradient 흐름에 결정적인 차이를 만든다. Post-Norm은 잔차 경로 전체를 LayerNorm이 감싸서 깊은 모델에서 gradient가 불안정해진다. Pre-Norm은 잔차 경로의 gradient가 1로 직통해 학습이 안정적이다. 밑바닥 LLM 책의 TransformerBlock은 Pre-Norm을 쓰며, GPTModel에서 final_norm을 별도로 추가해 Pre-Norm의 출력 스케일 문제를 보완한다.
