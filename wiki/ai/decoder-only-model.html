디코더 전용 모델

디코더 전용 모델

확인 범위: 이 문서는 디코더 전용 모델의 구조와 다른 Transformer 계열과의 차이, 일반적인 선택 기준을 개념적으로 설명한다. 제시된 코드에 대한 판단은 본문의 예시와 가상 코드 수준이며, 특정 구현의 정확한 동작이나 버전별 차이, 실행 결과와 성능 우위는 실제 소스·버전·실행 기록·측정을 별도로 확인해야 한다.

한 줄 요약: 디코더 전용(Decoder-only) 모델은 인과 마스크가 걸린 Transformer 블록만 반복해 쌓은 구조로, 구조의 단순함과 확장 효율 덕분에 GPT, LLaMA, Mistral 등 현대 LLM의 표준이 되었다.

디코더 전용 모델 필요성

Transformer 원논문(Vaswani et al., 2017)은 인코더와 디코더를 나란히 사용했다. BERT는 인코더만 쌓았고, GPT는 디코더만 쌓았다. 세 구조가 모두 가능한데 왜 대규모 언어 모델은 거의 전부 디코더 전용을 선택했는가?

이 질문에 답하지 못하면 “GPT는 왜 Cross-Attention이 없는가?”, “BERT는 왜 텍스트를 생성하지 못하는가?”, “T5와 GPT의 근본 차이는 무엇인가?” 같은 질문 앞에서 멈추게 된다. 디코더 전용 구조가 LLM에 적합한 이유를 이해하면, 모델 계열을 구분하는 판단 기준이 생긴다.

디코더 전용 모델 흐름

세 가지 Transformer 계열

Transformer 블록을 쌓는 방식은 세 가지다.

%% Transformer 계열 비교
flowchart LR
  encoder_only["인코더 전용 (BERT)<br/>양방향 Self-Attention<br/>FFN x N<br/>마스크 없음"]
  decoder_only["디코더 전용 (GPT)<br/>Causal Self-Attention<br/>FFN x N<br/>미래 토큰 차단"]
  encoder_decoder["인코더-디코더 (T5)<br/>Encoder: 양방향 Self-Attention<br/>Decoder: Causal Self-Attention<br/>Cross-Attention 포함"]
  understanding["분류/이해"]
  next_token["다음 토큰 생성"]
  seq2seq["seq-to-seq 변환"]
  encoder_only --> understanding
  decoder_only --> next_token
  encoder_decoder --> seq2seq

세 구조의 핵심 차이는 어텐션이 보는 범위와 Cross-Attention 유무다.

  • 인코더 전용 (Encoder-only)
    • 양방향 Self-Attention. 모든 토큰이 모든 토큰을 본다.
    • 분류, NER, 질의응답처럼 입력을 이해하는 과업에 강하다.
    • 다음 토큰을 순차 생성하는 자기회귀 구조가 아니므로 텍스트 생성에 쓸 수 없다.
    • 대표 모델: BERT, RoBERTa.
  • 디코더 전용 (Decoder-only)
    • 인과(causal) Self-Attention. 각 토큰은 자신과 이전 토큰만 본다.
    • Cross-Attention 없음. 인코더 출력을 참조하지 않는다.
    • 입력(프롬프트)과 출력(생성)이 같은 토큰 시퀀스 안에 이어진다.
    • 대표 모델: GPT-2, GPT-3, GPT-4, LLaMA, Mistral.
  • 인코더-디코더 (Encoder-Decoder)
    • 인코더가 입력을 양방향으로 읽고, 디코더가 Cross-Attention으로 인코더 출력을 참조하며 생성한다.
    • 번역, 요약처럼 입력과 출력의 형식이 다른 과업에 적합하다.
    • 대표 모델: T5, mBART, 원본 Transformer.

디코더 전용이 LLM 표준이 된 이유

1. 구조가 단순하다

디코더 전용 모델의 전체 구조는 다음 네 줄로 요약된다.

%% 디코더 전용 모델의 직선 스택
flowchart LR
  token["토큰 ID"]
  embedding["임베딩<br/>token + position"]
  blocks["Transformer Block x N<br/>Causal MHA + FFN"]
  lm_head["LM Head"]
  logits["logits"]
  token --> embedding
  embedding --> blocks
  blocks --> lm_head
  lm_head --> logits

인코더가 없으므로 Cross-Attention 층이 필요 없다. 같은 구조의 블록을 N번 반복할 뿐이다. 블록 하나의 내부도 동일하다.

%% 디코더 전용 블록의 잔차 흐름
flowchart TD
  input["입력 x"]
  ln1["LayerNorm"]
  mha["Causal MHA<br/>미래 토큰 차단"]
  add1["+ 잔차"]
  ln2["LayerNorm"]
  ffn["FFN"]
  add2["+ 잔차"]
  output["출력"]
  input --> ln1
  ln1 --> mha
  mha --> add1
  add1 --> ln2
  ln2 --> ffn
  ffn --> add2
  add2 --> output
  input --> add1
  add1 --> add2

인코더-디코더 구조의 디코더 블록은 여기에 Cross-Attention 층이 하나 더 들어간다. 디코더 전용은 이것을 생략해 설계, 구현, 디버깅 모두 간단해진다.

2. 모든 위치가 학습에 기여한다

GPT 학습의 목적함수는 다음 토큰 예측(Causal LM)이다. 시퀀스의 모든 위치에서 동시에 다음 토큰을 맞추는 문제를 풀기 때문에, 시퀀스 길이 T인 입력 하나에서 T개의 학습 신호가 나온다.

%% Causal LM의 위치별 학습 신호
flowchart TD
  sequence["입력 &#124; The &#124; cat &#124; sat &#124; on<br/>target &#124; cat &#124; sat &#124; on &#124; the"]
  pos0["위치 0<br/>&quot;The&quot; -&gt; &quot;cat&quot;"]
  pos1["위치 1<br/>&quot;The cat&quot; -&gt; &quot;sat&quot;"]
  pos2["위치 2<br/>&quot;The cat sat&quot; -&gt; &quot;on&quot;"]
  pos3["위치 3<br/>&quot;The cat sat on&quot; -&gt; &quot;the&quot;"]
  signal["T개 위치가 모두 loss에 기여"]
  sequence --> pos0
  sequence --> pos1
  sequence --> pos2
  sequence --> pos3
  pos0 --> signal
  pos1 --> signal
  pos2 --> signal
  pos3 --> signal

BERT의 Masked LM은 전체 토큰 중 15%만 마스킹해서 맞추므로 같은 데이터에서 학습 신호가 적다. 데이터를 대규모로 투입해야 하는 LLM에서는 토큰당 학습 효율이 높은 Causal LM이 유리하다.

3. 프롬프트가 인코더를 대신한다

인코더-디코더 모델에서 인코더는 입력 전체를 양방향으로 읽어 문맥 표현을 만든다. 디코더 전용 모델에서는 프롬프트 자체가 이 역할을 한다.

%% 프롬프트가 인코더 역할을 대신하는 흐름
flowchart TD
  enc_input["인코더 입력<br/>&quot;Translate to Korean: Hello&quot;"]
  dec_output["디코더 생성<br/>&quot;안녕하세요&quot;"]
  prompt["프롬프트<br/>&quot;Translate to Korean: Hello -&gt;&quot;"]
  generation["생성<br/>&quot;안녕하세요&quot;"]
  enc_input --> dec_output
  prompt --> generation

프롬프트 토큰은 인과 마스크 아래에서 서로를 참조할 수 있으므로, 프롬프트 내부에서는 사실상 양방향에 가까운 문맥 이해가 가능하다. 별도의 인코더 없이도 프롬프트 안에서 맥락을 충분히 파악한다.

4. 스케일링에 유리하다

같은 파라미터 예산을 하나의 디코더 스택에 집중할 수 있다. 인코더-디코더 구조에서는 같은 예산을 두 스택에 나눠야 한다.

%% 파라미터 예산을 하나의 디코더 스택에 집중하는 구조
flowchart LR
  budget_a["디코더 전용<br/>120M 파라미터"]
  decoder_stack["디코더 블록 12개<br/>emb_dim 768"]
  budget_b["인코더-디코더<br/>120M 파라미터"]
  split_stack["두 스택에 분산<br/>인코더 6개 + 디코더 6개<br/>또는 인코더 4개 + 디코더 8개"]
  budget_a --> decoder_stack
  budget_b --> split_stack

하나의 스택으로 통일하면 분산 학습 병렬화도 단순해진다. 파이프라인 병렬화에서 인코더-디코더 경계를 관리할 필요가 없다.

5. 하나의 구조로 여러 과업을 처리한다

GPT는 프롬프트 설계만 바꾸면 생성, 분류, 번역, 코딩, 요약을 모두 할 수 있다. 인코더 전용 모델은 생성을 할 수 없고, 인코더-디코더 모델은 입력과 출력을 명시적으로 분리해야 한다.

이 범용성이 사전학습 한 번으로 여러 과업에 적용하는 LLM 패러다임과 맞아떨어졌다.

디코더 전용 모델 코드

밑바닥 LLM 책의 GPTModel은 디코더 전용 구조의 정의 그 자체다. 인코더도 없고 Cross-Attention도 없다.

코드에서 보이지 않는 것이 핵심이다. encoder가 없고, cross_attention이 없다. 모델 전체가 하나의 직선 경로다.

순전파도 직선이다.

causal_mask=True가 디코더 전용 모델을 규정하는 한 줄이다. 이 플래그를 False로 바꾸면 인코더처럼 양방향으로 동작한다. 구조적 차이가 이 불리언 하나에 집약되어 있다.

인코더-디코더였다면 어떻게 달랐을까

인코더-디코더 구조의 TransformerBlock에는 Cross-Attention 층이 추가된다.

Cross-Attention에서 Query는 디코더의 현재 표현이고, Key와 Value는 인코더 출력이다. 디코더 전용 모델은 이 층 전체가 없다. 파라미터가 줄고, 인코더 출력을 메모리에 유지할 필요도 없다.

shape 흐름으로 보는 단순함

%% 디코더 전용과 인코더-디코더의 shape 흐름
flowchart TD
  gpt["디코더 전용 (GPT)<br/>(B, T, D)"]
  t5_encoder["인코더-디코더 (T5) 인코더<br/>(B, T_src, D)"]
  t5_decoder["인코더-디코더 (T5) 디코더<br/>(B, T_tgt, D)"]
  gpt --> t5_encoder
  t5_encoder --> t5_decoder

디코더 전용은 하나의 시퀀스가 시작부터 끝까지 같은 shape로 흐른다. 인코더-디코더는 두 개의 시퀀스(소스, 타깃)를 관리해야 한다.

정리

디코더 전용 모델은 인과 마스크가 걸린 Transformer 블록을 반복 쌓는 가장 단순한 구조다. Cross-Attention이 없고, 프롬프트가 인코더 역할을 대신하며, 모든 토큰 위치에서 학습 신호를 얻는다. 구조가 단순해 스케일링이 쉽고 하나의 모델로 여러 과업을 처리할 수 있어 현대 LLM의 표준이 되었다.
