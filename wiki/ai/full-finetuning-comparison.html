전체 파인튜닝 비교 (Full Fine-tuning)

전체 파인튜닝 비교 (Full Fine-tuning)

확인 범위: 이 문서는 전체 파인튜닝과 Head-only, LoRA/Adapter, QLoRA의 일반적인 차이와 선택 기준을 설명하는 개념 비교이며, 본문의 파라미터 수와 메모리 예시는 비용 차이를 이해하기 위한 것이다. 특정 코드·모델 버전의 실행 결과나 실제 성능 측정에 근거한 검증 문서는 아니므로, 구현 가능 여부와 메모리·성능 판단은 해당 환경에서 별도로 확인해야 한다.

한 줄 요약: 사전학습 모델의 대부분 또는 전체 가중치를 새 데이터에 맞게 다시 조정하는 전체 파인튜닝.

파인튜닝 전략을 고를 때는 먼저 학습 대상으로 삼을 파라미터의 범위를 구분해야 한다. 전체 파인튜닝은 사전학습 모델의 대부분 또는 전부를 열어 두고, 새 데이터에 맞게 모델 본체의 가중치까지 다시 조정한다.

전체 파인튜닝과 다른 전략의 차이

“모델을 학습한다”는 표현은 여러 전략을 가리킬 수 있다. 각 전략은 바꾸는 파라미터의 범위와 필요한 자원이 다르다.

  • 전체 파인튜닝
    • 모델 본체 가중치까지 바꾼다.
    • 성능 여지는 크지만 비용과 위험도 크다.
  • Head-only 파인튜닝
    • backbone은 얼리고 마지막 분류기나 헤드만 바꾼다.
    • 작은 분류 과업에서 단순하고 안전하다.
  • LoRA/Adapter
    • 원본 가중치는 고정하고 작은 보정 파라미터만 학습한다.
    • 큰 모델을 제한된 GPU에서 다룰 때 현실적인 기본값이 된다.
  • QLoRA
    • 원본 모델 저장 비용까지 줄이기 위해 4비트 양자화 위에 LoRA를 얹는다.
    • 7B급 모델을 한두 장의 GPU로 실험할 때 자주 검토한다.

이 차이를 구분하지 않으면 작은 분류 모델에서 사용한 코드를 7B LLM에 그대로 적용하려다가 GPU 메모리와 저장 공간이 부족해지거나 파괴적 망각 문제를 겪을 수 있다.

학습 대상에 따른 비용 차이

작은 GPT 분류 모델의 backbone 파라미터가 4,700,000개이고 분류 헤드가 514개인 상황을 비교해 보자.

전체 파인튜닝은 backbone과 head를 모두 학습하지만, Head-only는 514개의 head 파라미터만 학습한다. LoRA는 원본 backbone을 유지하면서 Q/V projection 옆의 작은 A/B 행렬을 학습 대상으로 삼는다.

Adam 계열 옵티마이저를 사용하면 학습 파라미터마다 보통 gradient와 두 개의 moment 상태가 붙는다. 따라서 학습 대상 파라미터 수가 100배로 늘어나면 파라미터 저장 공간뿐 아니라 학습 중 필요한 메모리도 크게 늘어난다. 이 차이를 확인하려면 gradient와 두 moment 상태를 포함해 학습 대상 파라미터가 100배 증가할 때의 메모리를 계산하면 된다.

전략을 고르는 기준

모델 크기가 작아 전체 학습 비용을 감당할 수 있고, 도메인 데이터가 충분하며 모델의 행동을 크게 바꿔야 한다면 전체 파인튜닝을 검토할 수 있다. 과업 하나에 모델 하나를 장기적으로 운영해도 되는지도 함께 고려해야 한다.

반대로 7B 이상 모델처럼 전체 학습 메모리가 부담되거나 과업별 모델을 여러 개 유지해야 한다면 LoRA/QLoRA를 먼저 검토한다. 원본 모델을 보존하면서 과업별 차이만 추가하려는 경우에도 작은 보정 파라미터를 학습하는 방식이 맞는다.

데이터가 적고 편향되어 있으면 전체 파인튜닝 과정에서 과적합될 수 있다. 기존의 일반 능력을 유지해야 하는데 새 데이터가 좁은 분야에만 몰려 있다면 파괴적 망각도 고려해야 한다. 학습 결과를 되돌릴 수 있는 작은 어댑터 단위가 필요한 운영 환경이라면 전체 가중치를 바꾸는 방식보다 LoRA/Adapter가 적합하다.
