DPO와 RLHF 비교 (DPO vs RLHF)

확인 범위: 이 문서는 DPO와 RLHF의 학습 흐름과 일반적인 선택 기준을 개념적으로 비교하며, 제시된 숫자는 신호의 차이를 설명하기 위한 예시다. 실제 구현의 적합성, GPU 비용, 학습 안정성 및 성능에 관한 판단은 사용한 코드·버전·실행 기록과 측정 결과를 별도로 확인해야 한다.

한 줄 요약: 둘 다 사람의 선호 데이터로 답변 습관을 조정하되, 선호를 학습 신호로 바꾸는 경로가 다른 DPO와 RLHF 비교.

DPO와 RLHF는 둘 다 사람의 선호 데이터를 이용해 언어 모델의 답변 습관을 조정하는 정렬 방법이다. 차이는 선호를 학습 신호로 바꾸는 경로에 있다.

DPO와 RLHF 비교 문제

RLHF와 DPO는 같은 목표를 향하지만 운영 난이도가 다르다. 둘 다 “선호 답변의 확률을 높이고, 비선호 답변의 확률을 낮춘다”는 방향을 가진다. 다만 RLHF는 Reward Model과 PPO를 거치고, DPO는 선호 쌍으로 정책을 직접 업데이트한다.

이 비교가 필요한 이유는 실제 프로젝트에서 “선호 데이터를 모았다” 다음 선택이 갈리기 때문이다. 연구용으로 정교한 보상 모델과 정책 최적화가 필요하면 RLHF를 검토하고, 구현 복잡도와 GPU 부담을 줄이고 싶으면 DPO가 먼저 후보가 된다.

흐름 비교

RLHF는 “채점자를 먼저 만든 뒤, 모델이 채점자의 점수를 올리게 학습”하는 흐름이다. DPO는 “채점자를 따로 만들지 않고, 비교 데이터 자체로 모델을 조정”하는 흐름이다.

작은 숫자 예시

같은 prompt에 두 답변이 있다고 하자.

RLHF에서는 Reward Model이 두 답변에 점수를 준다.

DPO에서는 Reward Model 점수 대신 정책과 참조 모델의 log 확률 차이를 쓴다.

diff가 양수이면 현재 정책이 참조 정책보다 선호 답변을 더 강하게 밀어 주고 있다는 뜻이다. DPO는 이 차이를 키우는 방향으로 학습한다.

DPO와 RLHF 비교 사용 기준

  • DPO가 먼저 어울리는 경우
    • 선호 쌍 데이터는 있지만 Reward Model과 PPO 파이프라인을 따로 운영하기 부담스러울 때
    • 구현을 단순하게 유지하고 싶을 때
    • LoRA/QLoRA 같은 PEFT와 묶어 제한된 GPU에서 선호 정렬을 해 보고 싶을 때
  • RLHF가 어울리는 경우
    • Reward Model 자체를 별도로 분석하거나 재사용해야 할 때
    • 보상 설계, PPO 안정화, KL 제어까지 연구하거나 운영할 여력이 있을 때
    • 생성 정책을 reward signal 기준으로 더 세밀하게 최적화하고 싶을 때
  • 둘 다 과한 경우
    • 단순 출력 형식이나 말투만 맞추면 되는 문제
    • 선호 데이터가 거의 없고, 좋은 예시 답변 데이터만 있는 문제
    • 이 경우 명령어 튜닝이나 프롬프트/RAG부터 검토한다.

정리

  1. RLHF는 보상 모델을 세워 PPO로 정책을 강화학습하는 정교한 경로이고, DPO는 같은 선호 정보를 더 단순한 supervised-style 손실로 정책에 직접 넣는 경로다.
  2. 둘 다 “선호 답변 확률은 올리고 비선호 답변 확률은 낮춘다”는 방향은 같지만, DPO는 보상 모델·PPO 운영 부담을 없애 구현과 GPU 비용을 줄인다.
  3. 처음 실험은 DPO가 가볍고, 보상 모델 자체를 분석·재사용해야 할 때 RLHF의 복잡도를 감수한다.

직접 확인하려면: 같은 선호 쌍에서 RLHF의 RM(win)-RM(lose)와 DPO의 정책-참조 log 확률 차이(win diff - lose diff)를 각각 계산해, 두 경로가 같은 “선호 답변을 더 민다” 방향을 다른 신호로 표현함을 대조한다.
