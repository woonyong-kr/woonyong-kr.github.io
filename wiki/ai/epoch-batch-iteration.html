에폭 · 배치 · 이터레이션

한 줄 요약: 에폭은 전체 데이터를 한 바퀴 도는 단위, 배치는 한 번에 처리하는 샘플 묶음, 이터레이션은 파라미터를 한 번 갱신하는 단위다. 세 값은 이터레이션 = 에폭 × (데이터수 ÷ 배치크기)로 묶인다.

에폭 · 배치 · 이터레이션 구분

학습 코드에는 epochs, batch_size, global_step처럼 서로 다른 범위를 세는 변수가 함께 등장한다. 이 변수를 같은 의미로 받아들이면 모델이 전체 데이터를 몇 번 보았는지와 파라미터를 몇 번 갱신했는지를 혼동하게 된다.

  • “10 에폭 돌렸다”는 전체 데이터를 10회 순회했다는 뜻이고, “10번 갱신했다”는 파라미터 갱신을 10회 수행했다는 뜻이다.
  • 같은 에폭 수로 학습해도 배치 크기가 달라지면 파라미터 갱신 횟수도 달라진다.
  • 학습 로그의 step이 무엇을 세는지 알아야 손실 그래프의 가로축을 해석할 수 있다.

학습 파이프라인이 “배치마다 순전파→손실→역전파→갱신을 반복하는 구조”를 설명한다면, 여기서는 그 반복을 어떤 기준으로 세는지 구분한다.

에폭 · 배치 · 이터레이션 구조

이 문서에서 다루는 미니배치 학습 루프에서는 전체 데이터를 한 번 순회하는 에폭 안에서 여러 배치를 차례로 처리한다. 배치 하나의 처리를 마치고 파라미터를 갱신할 때마다 이터레이션을 한 번 센다.

책 한 권을 읽는 장면에 비유하면 관계를 다음과 같이 볼 수 있다.

  • 에폭(epoch) = 책을 처음부터 끝까지 1회 통독
  • 배치(batch) = 한 번에 펼쳐 읽는 몇 페이지 묶음
  • 이터레이션(iteration) = 묶음 하나를 다 읽고 형광펜으로 밑줄(파라미터 갱신)을 1회 긋는 행위

각 용어의 정의는 다음과 같다.

  • 에폭: 훈련 데이터 전체를 모델이 한 번 본 횟수.
  • 배치: 한 번의 갱신에 함께 넣는 샘플 묶음. 묶음 크기가 배치 크기(batch size).
  • 이터레이션: 배치 하나로 순전파→역전파→갱신을 1회 끝낸 단위. 이 문서의 학습 루프에서는 갱신 횟수와 같다. 아래 PyTorch 코드에서는 global_step이 이 값을 센다.

이 관계를 들여쓰기 트리로 나타내면 다음과 같다.

  • 1 에폭
    • = 데이터 전체를 1회 순회
    • = (데이터수 ÷ 배치크기) 이터레이션
      • 1 이터레이션 = 배치 1개 처리 = 파라미터 1회 갱신

왜 전체를 한 번에 넣지 않는가?

데이터 전체를 한 배치로 넣는 방식은 배치 경사하강법이고, 데이터를 1개씩 넣는 방식은 순수 SGD다. 미니배치는 두 방식의 중간에 해당한다.

배치 크기가 크면 gradient가 전체 평균에 가까워져 안정적이지만 메모리를 더 사용하고 갱신 횟수는 줄어든다. 배치 크기가 작으면 gradient의 분산과 노이즈가 커지지만 메모리를 덜 사용하고 갱신 횟수는 늘어난다.

이러한 특성 때문에 미니배치는 두 방식 사이의 균형점으로 사용된다. 자세한 트레이드오프는 SGD 변형에서 다룬다.

왜 이 값인가? — 이터레이션 수 계산

한 에폭의 이터레이션 수는 전체 데이터를 배치 크기로 나누어 구한다. 데이터가 배치 크기로 정확히 나누어지지 않으면 남은 데이터도 마지막 배치로 처리하므로 나눈 값을 올림한다. 여러 에폭을 반복할 때는 이 에폭당 이터레이션 수에 에폭 수를 곱한다.

이터레이션 수 = 에폭 수 × ceil(데이터수 ÷ 배치크기)

MNIST 훈련 데이터 60,000장을 배치 크기 128로 처리하면 한 에폭에 필요한 배치 수는 다음과 같다.

ceil(60000 ÷ 128) = ceil(468.75) = 469 (마지막 배치는 96장)

배치 하나를 처리할 때마다 파라미터를 한 번 갱신하므로 한 에폭은 469 이터레이션이다. 이를 20 에폭 반복하면 전체 이터레이션 수는 다음과 같다.

469 × 20 = 9,380 이터레이션

따라서 이 조건에서 “20 에폭”은 전체 데이터를 20회 순회하면서 파라미터를 9,380번 갱신한다는 뜻이다. 배치 크기를 256으로 키우면 한 에폭의 배치 수가 235개로 줄어든다. 같은 20 에폭을 반복해도 이터레이션과 파라미터 갱신은 4,700회가 된다.

numpy — 밑바닥 딥러닝1의 미니배치 학습 루프

바깥쪽 루프는 에폭을 세고, 안쪽 range(0, train_size, batch_size)는 이터레이션을 진행한다. np.random.permutation은 에폭마다 데이터 순서를 섞으므로 각 배치의 구성이 달라진다.

배치 인덱싱에 따른 shape의 흐름은 다음과 같다.

%% 미니배치 학습에서 배치 인덱싱과 파라미터 갱신 흐름
flowchart LR
  x_train["x_train<br/>(60000, 784)"]
  indices["indices<br/>permutation(60000)<br/>batch_indices = indices[0:128]"]
  x_batch["x_batch<br/>(128, 784)"]
  forward["순전파<br/>model.gradient(x_batch, y_batch)"]
  loss["손실<br/>loss: scalar"]
  grads["역전파<br/>grads 계산"]
  update["params 갱신 1회<br/>optimizer.update(model.params, model.grads)"]
  repeat["start = 128"]
  x_train --> indices
  indices --> x_batch
  x_batch --> forward
  forward --> loss
  loss --> grads
  grads --> update
  update --> repeat
  repeat --> indices

PyTorch — 밑바닥 LLM의 사전학습 루프

train_loader(DataLoader)는 잘라 놓은 배치를 차례로 공급한다. numpy 예제에서 수동 permutation과 슬라이싱이 맡았던 일을 DataLoader가 담당한다. 이 코드의 global_step은 전체 누적 이터레이션 수이며, 이 값을 학습 로그의 가로축으로 사용할 수 있다.

numpy와 PyTorch 예제의 반복 구조는 같다.

for epoch:                      ← 에폭
    for batch in data:          ← 이터레이션
        forward → loss → backward → update    ← 갱신 1회

두 예제의 차이는 배치를 공급하는 방식이다. numpy는 permutation으로 직접 인덱싱하고, PyTorch는 DataLoader가 셔플·배치·로딩을 담당한다. 자세한 내용은 Dataset과 DataLoader에서 다룬다.

정리

  • 에폭은 전체 데이터의 1회 순회이고, 배치는 한 번에 넣는 샘플 묶음이며, 이터레이션은 배치 하나를 처리하고 파라미터를 1회 갱신하는 단위다.
  • 이터레이션 = 에폭 × ceil(데이터수 ÷ 배치크기). MNIST 60000장·배치 128·20에폭 조건에서는 9,380 이터레이션이다.
  • 배치 크기를 바꾸면 같은 에폭 수로 학습해도 이터레이션 수와 파라미터 갱신 횟수가 달라진다.
  • 제시된 numpy(src/training.py)와 PyTorch(src/train.py) 코드는 같은 반복 구조를 사용하며, 배치 공급 방식은 수동 인덱싱과 DataLoader로 나뉜다.
  • 연결 문서: 학습 파이프라인, SGD 변형, Dataset과 DataLoader
