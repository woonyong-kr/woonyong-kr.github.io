다중 쿼리 어텐션 (Multi Query Attention)

다중 쿼리 어텐션 (Multi Query Attention)

한 줄 요약: Multi-Query Attention은 여러 Query head가 하나의 Key/Value head를 공유해, decode 단계의 KV Cache 메모리를 크게 줄이는 attention 구조다.

다중 쿼리 어텐션 구분

멀티헤드 어텐션은 head마다 Q, K, V를 따로 둔다. 학습이나 짧은 입력에서는 자연스럽지만, LLM 서빙의 decode 단계에서는 이전 토큰들의 K/V를 계속 저장해야 한다. 이 저장소가 KV Cache다.

MQA는 모든 Query head가 하나의 K/V head를 공유한다. Query는 여러 관점을 유지하지만, 캐시에 저장하는 Key와 Value는 1세트만 둔다. 그래서 decode 단계에서 읽어야 하는 KV Cache가 n_heads배 줄어든다.

핵심 동작

Query head는 그대로 여러 개 두고, Key/Value head만 1개로 줄인다. attention을 계산할 때 모든 Query head가 같은 K/V 1세트를 본다. 구현에서는 K/V head 축을 Query head 수만큼 broadcast(반복)해서 shape를 맞춘다.

  • Q: (B, n_heads=32, S, head_dim)
  • K: (B, n_kv=1, S, head_dim) broadcast → (B, 32, S, head_dim)
  • V: (B, n_kv=1, S, head_dim) broadcast → (B, 32, S, head_dim)

연산량은 MHA와 거의 같다. 차이는 캐시에 실제로 저장하는 양이다. broadcast 전의 K/V 1세트만 저장하므로, decode에서 메모리가 줄고 Query의 표현력은 그대로 남는다.

다중 쿼리 어텐션 예시

n_heads=32, head_dim=128인 모델을 생각하자.

KV Cache는 K와 V를 저장하므로, MQA는 MHA 대비 K/V head 수가 32 -> 1로 줄어든다. 이론상 head 축 기준 캐시 메모리는 32배 줄어든다. 정확한 메모리 계산은 KV 캐시 메모리 계산에서 본다.

정리

  1. MQA는 Query head 수는 유지하고 K/V head를 1개로 줄여, KV Cache를 head 축 기준 n_heads배 줄인다.
  2. Query의 표현 다양성은 남기지만 K/V 다양성은 가장 크게 포기하는 극단형이다. decode throughput·메모리가 최우선일 때 강하고, head마다 다른 K/V 표현이 많이 필요하면 지나치게 공격적이다.
  3. K/V 다양성을 일부 되살리려면 Grouped Query Attention이 절충안이다.

직접 확인: 모델 config의 n_kv_heads(또는 num_key_value_heads)가 1이면 MQA다. 이 값과 KV Cache 메모리가 비례하는지는 KV 캐시 메모리 계산에서 수치로 확인한다.
