Mistral과 Mixtral (Mistral/Mixtral)

Mistral과 Mixtral (Mistral/Mixtral)

한 줄 요약: Mistral은 효율을 노린 오픈 가중치 LLM 계열이고, Mixtral은 그 위에 Sparse Mixture-of-Experts를 얹어 토큰마다 일부 전문가만 활성화해 추론 비용을 낮춘 모델이다.

모델을 크게 만들면 추론도 그만큼 느려질까? Mistral 7B와 Mixtral 8x7B는 이 질문을 서로 다른 구조로 풀어낸다. Mistral 7B는 작은 크기 안에서 attention과 cache 비용을 줄인다. Mixtral 8x7B는 여러 expert 가운데 일부만 사용하는 sparse MoE 구조로, 큰 총 파라미터 수와 낮은 활성 파라미터 수 사이에서 균형을 잡는다.

파라미터 수만으로 비교할 때 생기는 오해

LLM의 파라미터 수는 모델의 규모를 보여주지만, 실제 추론 비용을 혼자 결정하지는 않는다. 다음 질문을 구분해야 모델의 구조와 비용을 제대로 비교할 수 있다.

  • 7B 모델은 항상 13B 모델보다 약한가?
  • 47B 파라미터 모델은 추론 때 항상 47B 전체를 계산하는가?
  • 긴 context를 처리하려면 attention 비용을 어떻게 줄이는가?
  • 오픈 가중치 모델은 배포와 실험에서 어떤 장점이 있는가?

Mistral 7B와 Mixtral 8x7B는 이 질문에 서로 다른 답을 제시한다.

  • Mistral 7B
    • Grouped-Query Attention으로 KV cache와 추론 비용을 줄인다.
    • Sliding Window Attention으로 긴 입력의 모든 토큰을 전부 보지 않고 가까운 window를 중심으로 계산한다.
  • Mixtral 8x7B
    • 각 layer의 feed-forward 부분을 여러 expert로 나눈다.
    • token마다 router가 일부 expert를 골라 계산한다.

따라서 “큰 모델”이라는 표현만으로는 실제 동작을 충분히 설명하기 어렵다. 전체 파라미터 수와 실제 활성 파라미터 수뿐 아니라 attention 비용, memory bandwidth, 라이선스까지 나누어 살펴봐야 한다.

Mixtral 8x7B의 처리 흐름

Mixtral 8x7B의 동작을 단순화하면 다음과 같다.

“8개 expert가 있다”는 말이 항상 8개를 모두 계산한다는 뜻은 아니다. Sparse MoE에서는 token마다 일부 expert만 활성화한다. 이 때문에 총 파라미터 수가 크더라도 한 token을 처리할 때 사용하는 계산량은 더 작게 유지될 수 있다.

Mistral 7B는 MoE가 아닌 dense 모델이다. 여러 expert를 선택하는 대신 attention 계산의 병목을 줄이는 데 초점을 둔다. 두 모델의 차이를 나란히 놓으면 다음과 같다.

Mistral과 Mixtral을 비교하는 기준

Mistral/Mixtral 계열을 비교할 때는 모델의 규모를 하나의 숫자로 판단하지 않고 구조, 추론 비용, 배포 조건을 분리해서 본다.

  • 모델 구조
    • dense 모델인가, sparse MoE 모델인가?
    • GQA와 SWA 같은 attention 최적화는 어떤 병목을 줄이는가?
  • 추론 비용
    • 총 파라미터 수와 token당 활성 파라미터 수는 각각 얼마인가?
    • KV cache와 memory bandwidth가 병목인가, expert FFN 계산이 병목인가?
  • 배포 조건
    • 오픈 가중치와 라이선스는 실험과 상용 사용에 어떤 의미가 있는가?
    • llama.cpp 로컬 추론이나 다른 inference runtime에서 실행할 수 있는 형식이 있는가?
  • 비교 방식
    • 특정 벤치마크 숫자 하나에 의존하지 않고 평가 Benchmarks, 실제 prompt, 비용, latency를 함께 봐야 한다.

비교할 때 기억할 차이

  1. Mistral 7B는 dense 모델이다. GQA로 KV cache 비용을 줄이고, SWA로 긴 입력의 attention 비용을 줄이는 효율 설계 사례다.
  2. Mixtral 8x7B는 FFN을 여러 expert로 나눈다. token마다 router가 일부 expert만 활성화하므로 큰 총 파라미터를 매번 모두 사용하지 않는 sparse MoE 사례다.
  3. 두 모델을 비교할 때는 총 파라미터 수뿐 아니라 token당 활성 파라미터 수, attention 비용, 라이선스를 함께 살펴봐야 한다.

두 모델의 차이를 직접 점검하려면 “총 파라미터”와 “token당 활성 파라미터”를 각각 적고, 추론 비용과 관련된 수치가 어느 쪽인지 구분해 본다.
