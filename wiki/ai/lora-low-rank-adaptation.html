LoRA — 저랭크 행렬로 거대 모델을 효율적으로 파인튜닝하는 기법

LoRA — 저랭크 행렬로 거대 모델을 효율적으로 파인튜닝하는 기법

확인 범위: 이 문서는 LoRA의 일반 원리와 적용 위치·하이퍼파라미터 선택 기준을 설명하고, 입력에 제시된 PyTorch 구현과 계산 예시를 해설한다. 실제 코드의 동작, 특정 버전과 환경에서의 학습 파라미터·메모리 절감 및 추론 성능은 실행 기록이나 성능 측정으로 검증한 결과가 아니다.

한 줄 요약: LoRA(Low-Rank Adaptation)는 사전학습된 가중치를 고정(freeze)하고, 각 가중치 행렬에 저랭크 행렬 쌍(A, B)을 추가하여 학습 파라미터 수를 수십~수백 배 줄이면서도 Full Fine-tuning에 가까운 성능을 달성하는 효율적 파인튜닝 기법이다.

LoRA 필요성

GPT-3은 1,750억 개의 파라미터를 가진다. 분류 미세조정이나 명령어 튜닝에서 이 파라미터를 전부 업데이트하면 다음 문제가 생긴다.

  • 메모리: 파라미터, 기울기, 옵티마이저 상태를 모두 저장해야 한다. Adam 기준 파라미터당 12바이트가 필요하다. GPT-3이면 약 2.1TB다.
  • 저장: 과업마다 모델 전체 사본을 저장해야 한다. 10개 과업이면 10개 GPT-3 사본이다.
  • 속도: 모든 파라미터에 대해 기울기를 계산하고 업데이트하는 시간이 오래 걸린다.

LoRA는 “파인튜닝에서 가중치 변화량(delta W)이 실제로는 저랭크(low-rank) 구조를 가진다”는 관찰에서 출발한다. Hu et al.(2021)이 제안했다.

LoRA 구조

비유

큰 사전(사전학습 가중치)을 새 분야에 맞추려고 전체를 다시 쓰는 대신, 얇은 부록(LoRA 행렬)만 붙이는 것이다. 부록에는 새 분야에서 달라지는 항목만 적는다. 사전 본문은 건드리지 않으므로 원본을 보존하면서도 새 분야를 지원한다.

정의

LoRA는 사전학습된 가중치 행렬 W(d_in x d_out)를 고정하고, 두 개의 작은 행렬 A(d_in x r)와 B(r x d_out)를 추가한다. r은 랭크(rank)로, d_in과 d_out보다 훨씬 작은 값이다.

h = (W + delta_W) * x
  = W * x + B * A * x

W는 고정이고 A와 B만 학습한다. 추론 시에는 W + B * A를 미리 합쳐서 원래 모델과 같은 속도로 실행할 수 있다.

왜 저랭크가 작동하는가?

Aghajanyan et al.(2021)은 사전학습된 모델의 파인튜닝 가중치 변화가 매우 낮은 내재 차원(intrinsic dimensionality)을 가진다는 것을 보였다. 175B 파라미터 모델이 실제로 바뀌어야 하는 방향은 수백~수천 차원이면 충분하다.

직관적으로, 사전학습에서 이미 언어의 일반 구조를 배웠기 때문에 파인튜닝에서 바뀌는 부분은 전체 가중치 공간의 작은 부분공간에 집중된다.

파라미터 수 비교

Full Fine-tuning:
  학습 파라미터 = d_in × d_out

LoRA (rank = r):
  학습 파라미터 = d_in × r + r × d_out
               = r × (d_in + d_out)

GPT-small 기준으로 계산한다. d_model = 768이고, Attention의 Q, K, V, O 프로젝션에 LoRA를 적용한다고 하면 각 프로젝션은 768 x 768 행렬이다.

Full Fine-tuning (Q 프로젝션 하나):
  768 × 768 = 589,824개

LoRA (r = 8):
  768 × 8 + 8 × 768 = 6,144 + 6,144 = 12,288개

비율: 12,288 / 589,824 = 2.1%

학습 파라미터가 원래의 2.1%로 줄어든다. r = 4이면 1%로 줄어든다.

초기화

  • A는 정규분포(Kaiming 또는 Gaussian)로 초기화한다.
  • B는 영행렬(zero matrix)로 초기화한다.

학습 시작 시 B * A = 0이므로 delta_W = 0이다. 학습이 시작되기 전에는 원래 사전학습 모델과 동일하게 동작한다. 학습이 진행되면서 B에 값이 채워지며 가중치가 점진적으로 변한다.

스케일링 계수 alpha

실제 LoRA에서는 delta_W = (alpha / r) * B * A로 스케일링한다. alpha는 학습률과 비슷한 역할을 하는 하이퍼파라미터다. alpha / r을 곱해 rank를 바꿔도 출력 크기가 일정하게 유지되도록 정규화한다. 일반적으로 alpha = r 또는 alpha = 2r로 설정한다.

어디에 적용하는가

Transformer에서 LoRA를 적용하는 주요 위치는 다음과 같다.

  • Attention의 Q, K, V, O 프로젝션 행렬
  • FeedForward의 linear1, linear2 행렬

원논문에서는 Q와 V에만 적용해도 충분한 성능을 얻었다. 실무에서는 Q, K, V, O 전부에 적용하는 경우가 많다.

LoRA 코드

밑바닥 LLM 책 부록 E(appendix-E)에 LoRA의 실제 PyTorch 구현이 들어 있다. 핵심은 LoRALayer, LinearWithLoRA, replace_linear_with_lora 세 개다.

책의 실제 구현 — LoRALayer

torch.nn.Parameter로 감싼 A, B만 autograd 추적 대상이 된다. B가 영행렬이라 forward는 학습 시작 시 0을 돌려준다. forward는 보정값(delta)만 계산하고 원본 출력은 다음 LinearWithLoRA가 더한다.

책의 실제 구현 — LinearWithLoRA

기존 nn.Linear 객체를 통째로 품고, 그 옆에 LoRALayer를 단다. forward는 linear(x) + lora(x)로 W*x + (alpha/r)*B*A*x를 구현한다. 원본 nn.Linear의 가중치는 건드리지 않는다.

책의 실제 구현 — 모델 전체에 적용

replace_linear_with_lora는 named_children을 재귀 순회하며 모든 nn.Linear를 LinearWithLoRA로 바꾼다. 먼저 전체 파라미터를 requires_grad = False로 고정했기 때문에, 교체로 새로 생긴 LoRALayer의 A, B만 학습된다.

변형 — Attention 프로젝션에만 적용

책의 replace_linear_with_lora는 모든 nn.Linear를 바꾸지만, 원논문처럼 Q와 V 프로젝션에만 적용하고 싶으면 위처럼 대상 모듈을 지정한다. LinearWithLoRA로 교체한 뒤 requires_grad=True인 파라미터(=A, B)만 옵티마이저에 등록한다.

이 코드들의 핵심은 x @ A @ B다. 입력 x가 먼저 A를 통해 r차원으로 축소되고, B를 통해 원래 차원으로 복원된다. 이 보정값이 원본 출력에 더해진다.

shape 변환 흐름

LoRA가 적용된 Q 프로젝션 (GPT-small, r=8):
  x: (B, T, 768)
    → original W_query: (B, T, 768)    ← 고정, grad 없음
    → x @ A: (B, T, 8)                 ← 768 → 8 차원 축소
    → (x @ A) @ B: (B, T, 768)         ← 8 → 768 차원 복원
    → scaling: * (alpha/r)
    → 합산: original + lora_out = (B, T, 768)

구체적 숫자 예시

GPT-2 small에서 LoRA는 전체 파라미터의 0.24%만 학습한다. 옵티마이저 메모리는 약 400배 줄어든다.

추론 시 합치기 (Merge)

합치고 나면 원래 nn.Linear와 동일한 구조가 된다. 추론 시 추가 연산이 없다. 이것이 LoRA의 중요한 장점이다. 학습 때만 A, B가 별도로 존재하고, 배포 시에는 합쳐서 원래 모델과 같은 속도로 실행한다.

정리

LoRA는 사전학습 가중치를 고정하고 저랭크 행렬 쌍(A, B)만 학습하여 파인튜닝 비용을 크게 줄이는 기법이다. 파인튜닝의 가중치 변화가 저랭크 구조를 가진다는 관찰에 기반한다. 학습 파라미터는 원래의 1% 이하로 줄어들고, 추론 시에는 원본에 합쳐서 추가 비용 없이 배포할 수 있다. 과업마다 A, B 쌍만 저장하면 되므로 하나의 사전학습 모델 위에 여러 과업을 효율적으로 지원할 수 있다.
