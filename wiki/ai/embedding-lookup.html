임베딩 룩업

한 줄 요약: 토크나이저가 출력한 정수 ID는 배열 인덱스일 뿐 의미가 없다. 임베딩 레이어는 각 ID로 가중치 행렬의 해당 행을 꺼내(lookup) 학습 가능한 벡터로 바꾼다.

정수 ID를 그대로 계산할 수 없는 이유

토크나이저는 “Hello”를 [15496] 같은 정수로 바꾼다. 이 숫자는 토큰을 구별하기 위한 카테고리 번호다. 숫자의 크기가 토큰 사이의 의미 관계를 나타내지는 않는다. 따라서 ID를 그대로 연산하면 “ID 5가 ID 3보다 크다”는 관계를 의미로 잘못 받아들일 수 있다. MNIST에서 숫자 이미지의 라벨 7이 라벨 3보다 “더 큰” 것이 아닌 것과 같다.

모델이 곱셈과 덧셈에 사용할 표현을 얻으려면 각 ID를 벡터로 바꿔야 한다. 임베딩 레이어는 학습 가능한 가중치 행렬에서 ID에 해당하는 행을 꺼내 이 벡터를 만든다. 학습 과정에서 벡터는 학습 목표와 데이터에 맞게 조정된다. 그 결과 의미적으로 유사한 토큰의 벡터가 가까워질 수 있지만, 모든 유사성이 언제나 그런 거리 관계로 나타난다고 보장되는 것은 아니다.

토큰 ID에서 입력 벡터까지

임베딩 테이블에서 행 꺼내기

임베딩 테이블은 2D 행렬이다. 행 수는 어휘 크기(vocab_size)이고, 열 수는 임베딩 차원(emb_dim)이다. 각 행은 하나의 토큰 ID에 대응한다.

%% 토큰 ID가 임베딩 테이블의 한 행으로 바뀌는 룩업 흐름
flowchart LR
  input["token ID<br/>42<br/>크기가 아니라 행 번호"]
  table["embedding table<br/>(vocab_size, emb_dim)"]
  output["lookup result<br/>table[42] → (emb_dim,)"]
  input --> table
  table --> output

토큰 ID가 42라면 임베딩 테이블의 42번째 행을 그대로 꺼낸다. 이 연산은 행렬 곱이 아니라 인덱싱이다. 역전파할 때는 조회된 해당 행이 업데이트된다. 테이블에서 필요한 행을 조회하므로 이 과정을 임베딩 룩업이라고 부른다.

토큰 정보에 위치 정보 더하기

Transformer는 RNN처럼 토큰을 한 위치씩 순서대로 읽지 않고 모든 위치를 한 번에 처리한다. 토큰 임베딩만으로는 각 토큰이 몇 번째 자리에 있는지 구분할 수 없다. 이 위치 정보를 입력에 포함하기 위해 위치 임베딩(position embedding)을 토큰 임베딩에 더한다.

%% 토큰 임베딩과 위치 임베딩을 더해 Transformer 입력을 만드는 흐름
flowchart LR
  token["token embedding<br/>&quot;Hello&quot; → (emb_dim,)"]
  position["position embedding<br/>position 0 → (emb_dim,)"]
  add["element-wise add<br/>같은 emb_dim끼리 더하기"]
  output["input embedding<br/>(emb_dim,)"]
  token --> add
  position --> add
  add --> output

두 벡터를 원소별로 더하려면 차원이 같아야 한다. 따라서 토큰 임베딩과 위치 임베딩은 같은 emb_dim을 사용한다.

GPT-2는 위치마다 학습 가능한 임베딩 벡터를 사용한다. 원본 Transformer의 고정 사인·코사인 위치 인코딩과 달리, 위치 표현도 학습 과정에서 조정되는 방식이다.

다음 코드는 GPT-2 small의 차원을 사용해 토큰 임베딩과 위치 임베딩의 마지막 차원을 맞춘다. 마지막 assert는 두 룩업 결과를 더한 뒤 기대하는 shape이 (4, 768)임을 나타낸다.

임베딩 테이블의 파라미터 비용

임베딩 테이블의 파라미터 수는 행 수와 열 수를 곱해 계산한다. 문서에 제시된 GPT-2 small의 124M 파라미터를 기준으로 하면 다음과 같다.

  • 토큰 임베딩: 50,257 × 768 = 38,597,376 (약 38.6M, 전체의 31%)
  • 위치 임베딩: 1,024 × 768 = 786,432 (약 0.8M)

임베딩 차원을 그대로 둔 채 어휘 크기를 늘리면 토큰 임베딩의 파라미터 비용도 선형으로 증가한다.

Weight Tying으로 출력 가중치 재사용하기

GPT-2는 출력층에서 입력 임베딩 테이블의 가중치를 다시 사용한다. 출력 로짓을 계산할 때 별도의 분류 행렬을 두는 대신 임베딩 행렬의 전치를 곱한다. 이 Weight Tying은 별도의 38.6M 파라미터를 추가하지 않으면서 입력 공간과 출력 공간이 같은 가중치를 공유하게 한다.

Word2Vec의 king - man + woman ≈ queen 같은 예시는 정적 임베딩 공간에서 나타나는 기하 관계를 보여준다. LLM에서는 임베딩 룩업으로 얻은 초기 벡터가 Transformer layer를 통과하면서 문맥별 의미 표현으로 바뀐다. 따라서 임베딩 룩업의 결과는 완성된 문맥 표현이 아니라 그 표현을 만드는 시작점이다.

코드로 흐름 따라가기

토큰 ID에서 임베딩 벡터 꺼내기

다음 학습 코드는 토큰 ID가 임베딩 테이블의 행으로 대응되는 과정을 보여준다.

embedding_layer.weight는 (vocab_size, output_dim) 행렬이다. embedding_layer(input_ids)는 이 행렬에서 2번, 3번, 5번, 1번 행을 입력 순서대로 꺼내 쌓는다. 출력 shape이 (4, 3)인 이유는 네 개의 ID마다 3차원 벡터가 하나씩 대응하기 때문이다.

토큰 임베딩과 위치 임베딩 더하기

실제 Transformer 입력을 구성하려면 토큰 벡터와 위치 벡터를 같은 차원으로 만든 뒤 더한다.

inputs의 각 ID를 조회하면 token_embeddings의 shape은 (8, 4, 256)이 된다. 네 위치를 조회한 pos_embeddings의 shape은 (4, 256)이다. 두 텐서를 더할 때 위치 임베딩이 batch 전체에 broadcasting되므로 최종 input_embeddings의 shape은 (8, 4, 256)으로 유지된다.

%% 토큰 ID 텐서와 위치 번호 텐서가 같은 임베딩 차원으로 맞춰진 뒤 더해지는 shape 흐름
flowchart TD
  inputs["inputs<br/>(8, 4)"]
  token_layer["token_embedding_layer<br/>token ID마다 256차원 벡터 조회"]
  token_embeddings["token_embeddings<br/>(8, 4, 256)"]
  positions["torch.arange(4)<br/>(4,)"]
  position_layer["pos_embedding_layer<br/>위치마다 256차원 벡터 조회"]
  pos_embeddings["pos_embeddings<br/>(4, 256)"]
  add["broadcast add<br/>(8, 4, 256) + (4, 256)"]
  output["input_embeddings<br/>(8, 4, 256)"]
  inputs --> token_layer
  token_layer --> token_embeddings
  positions --> position_layer
  position_layer --> pos_embeddings
  token_embeddings --> add
  pos_embeddings --> add
  add --> output

실제 모델의 InputEmbedding 클래스

책의 GPT 모델에서 사용하는 InputEmbedding은 토큰 임베딩, 위치 임베딩, dropout을 하나의 모듈로 묶는다.

forward()는 먼저 입력 x에서 토큰 임베딩을 조회한다. 이어서 입력 길이에 맞는 위치 번호를 만들고 위치 임베딩을 조회한다. 두 결과를 더한 뒤 dropout을 적용해 (batch_size, seq_len, emb_dim) shape의 텐서를 반환한다. 여기서 dropout은 학습 시 임베딩 벡터의 일부 차원을 무작위로 0으로 만드는 방식으로 과적합을 줄이기 위해 사용된다.

토큰 ID에서 Transformer 입력까지의 흐름은 하나로 이어진다. ID는 임베딩 테이블의 행 번호로 사용되고, 조회된 토큰 벡터에는 같은 차원의 위치 벡터가 더해진다. 이렇게 만든 입력 벡터가 Transformer layer를 통과하면서 문맥별 표현으로 바뀐다.
