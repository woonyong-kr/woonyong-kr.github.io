QLoRA와 양자화 LoRA (QLoRA)

QLoRA와 양자화 LoRA (QLoRA)

한 줄 요약: 본체 가중치를 4비트로 압축해 GPU에 올리고 작은 LoRA 행렬만 학습하는 파인튜닝 방법 QLoRA.

QLoRA는 큰 사전학습 모델의 본체 가중치를 4비트로 압축해 GPU 메모리에 올린다. 본체 가중치는 직접 업데이트하지 않고, 실제 학습은 더 높은 정밀도의 작은 LoRA 행렬에서 진행한다.

QLoRA가 줄이려는 메모리 부담

LoRA는 학습할 파라미터 수를 크게 줄이지만, 원본 모델 가중치 자체는 여전히 GPU 메모리에 올려야 한다. 7B 모델을 FP16으로 올리면 가중치만 대략 7B * 2 bytes = 14GB다. 여기에 activation, optimizer state, LoRA 파라미터와 dataloader에 필요한 여유 공간까지 더하면 16GB GPU 한 장으로는 메모리가 빠르게 부족해진다.

QLoRA는 원본 모델과 LoRA 어댑터를 서로 다른 방식으로 다뤄 이 부담을 줄인다.

  • 원본 모델
    • 4비트 양자화로 작게 저장
    • 학습 중 직접 업데이트하지 않음
  • LoRA 어댑터
    • FP16/BF16 같은 더 높은 정밀도로 학습
    • 과업에 맞춰 실제로 바뀌는 부분

큰 원본 모델은 작은 크기로 보관하고, 과업에 필요한 보정은 작은 행렬만 학습하는 방식이다.

일반 LoRA와 QLoRA의 학습 흐름

가중치가 차지하는 메모리는 다음과 같이 단순 계산해 볼 수 있다.

이 계산은 정확한 실행 메모리를 예측하기 위한 것이 아니다. 양자화 메타데이터와 학습에 필요한 여러 상태가 추가되므로 실제 사용량은 단순 가중치 계산보다 크다. 다만 QLoRA가 큰 모델을 작은 GPU에 올리는 선택지가 되는 이유는 이 차이에서 확인할 수 있다.

LoRA와 QLoRA의 차이

  • LoRA
    • 원본 모델: 보통 FP16/BF16 상태로 보관
    • 학습 대상: LoRA A/B
    • 장점: 구조가 단순하고 이해하기 쉽다
    • 한계: 원본 모델을 올리는 메모리는 그대로 필요
  • QLoRA
    • 원본 모델: 4비트 양자화 상태로 보관
    • 학습 대상: LoRA A/B
    • 장점: 더 큰 모델을 제한된 GPU에 올릴 수 있음
    • 한계: 양자화/역양자화와 구현 라이브러리 의존성이 생김

QLoRA를 단순히 LoRA의 더 저렴한 버전으로만 이해하면 두 방법의 차이가 흐려진다. LoRA가 학습할 파라미터 수를 줄이는 방법이라면, QLoRA는 여기에 얼려 둔 원본 가중치를 저장하는 비용까지 줄이는 방법이다.

어떤 방법을 선택할까

7B급 이상 모델을 한두 장의 GPU로 파인튜닝하려는데 full fine-tuning이 불가능하고 일반 LoRA도 원본 모델의 메모리 부담이 크다면 QLoRA를 고려할 수 있다. 모델의 지식 전체를 바꾸기보다 출력 형식, 말투 또는 좁은 과업의 행동을 조정하려는 경우에도 적용할 수 있다.

반대로 모델이 작아서 FP16/BF16 원본을 그대로 올릴 수 있다면 일반 LoRA가 더 단순하다. 양자화 오차와 라이브러리 설정을 줄이고 싶을 때도 같은 판단이 가능하다. 바꾸려는 대상이 모델의 행동이 아니라 최신 문서나 사내 지식이라면 파인튜닝보다 RAG가 더 알맞다.

학습할 때 확인할 내용

QLoRA는 본체 가중치를 4비트로 압축해 GPU에 올리고, 더 높은 정밀도의 작은 LoRA 행렬만 학습한다. 따라서 LoRA가 학습 파라미터 수를 줄이는 데 초점을 둔다면, QLoRA는 얼려 둔 원본 가중치의 저장 비용도 함께 줄인다. 그 대신 양자화·역양자화 과정과 구현 라이브러리에 대한 의존성이 생긴다.

메모리 차이를 확인하려면 7B 가중치를 FP16(7e9 * 2 bytes ≈ 14GB)과 4bit(7e9 * 0.5 bytes ≈ 3.5GB)로 각각 계산할 수 있다. 이후 activation·optimizer state·LoRA가 추가되기 때문에 실제 사용량은 이 단순 계산보다 커진다는 점까지 함께 살펴봐야 한다.
