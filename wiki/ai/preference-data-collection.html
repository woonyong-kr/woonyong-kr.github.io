선호 데이터 Collection (Preference Data Collection)

한 줄 요약: 같은 질문의 여러 답변 중 어느 쪽이 나은지 비교한 기록인 선호 데이터 — RLHF·DPO가 이를 학습에 사용.

선호 데이터는 같은 질문에 대한 여러 답변을 비교해 어느 쪽이 더 나은지 기록한 데이터다. RLHF와 DPO는 이 비교 기록을 이용해 모델의 답변 습관을 조정한다.

선호 데이터가 필요한 이유

요약, 대화, 안전성, 친절함처럼 하나의 답만 정답이라고 보기 어려운 과업이 있다. 이런 과업의 정렬 학습에는 “정답 문장 하나”보다 “이 답변이 저 답변보다 낫다”는 판단이 필요한 경우가 많다. 따라서 사람이 어떤 답변을 더 선호하는지 비교하고, 그 선택에서 반복되는 패턴을 모아야 한다.

좋은 선호 데이터는 모델이 따라야 할 판단 기준을 보여준다.

  • 더 정확한 답변
  • 근거를 지키는 답변
  • 불필요하게 길지 않은 답변
  • 위험한 요청을 안전하게 다루는 답변
  • 질문 형식에 맞는 답변

반대로 선택 기준이 일관되지 않으면 모델도 무엇을 따라야 하는지 배우기 어렵다. 예를 들어 어떤 샘플에서는 긴 답변을 고르고 다른 샘플에서는 짧은 답변을 고르면서 그 이유를 설명하지 못한다면, 두 선택을 가르는 기준이 데이터에 드러나지 않는다.

데이터 형태

가장 단순한 형태는 prompt, 선호 답변, 비선호 답변으로 이루어진 세 묶음이다.

chosen은 사람이 더 낫다고 선택한 답변이고, rejected는 그보다 못하다고 판단한 답변이다. reason은 학습에 반드시 사용하지 않더라도 데이터 검수에 도움이 된다. 나중에 선택 이유를 다시 확인할 수 있기 때문이다.

수집 흐름

하나의 prompt에서 답변 3개를 만들면 비교할 수 있는 쌍은 최대 3개다.

모든 쌍을 만들면 데이터는 늘어나지만 수집 비용도 커진다. 처음에는 대표적인 prompt와 차이가 분명한 답변을 중심으로 작은 데이터셋을 만들 수 있다. 이후 모델이 자주 틀리는 영역의 비교를 추가하는 방식으로 범위를 넓힌다.

판단이 갈리는 지점

  • 좋은 선호 데이터
    • 선택 이유를 짧게라도 설명할 수 있음
    • prompt와 답변이 실제 사용 시나리오에 가까움
    • chosen/rejected의 차이가 학습 목표와 연결됨
    • 안전성 케이스와 정상 케이스가 함께 있음
  • 위험한 선호 데이터
    • 라벨러마다 판단 기준이 다름
    • 긴 답변을 무조건 고르는 편향이 있음
    • 특정 말투나 모델 이름만 보고 고르는 편향이 있음
    • rejected가 지나치게 나빠서 모델이 섬세한 차이를 배우기 어려움
  • 보류할 샘플
    • 두 답변이 모두 틀림
    • 두 답변이 비슷하게 좋음
    • 판단에 필요한 근거가 prompt에 없음
    • 안전 정책의 기준이 아직 정해지지 않음

학습 방법과 연결

수집한 선호 데이터는 다음 학습 및 평가 방법과 연결된다.

  • 보상 모델 학습
  • DPO
  • LLM As 판정 (LLM As Judge)

수집 결과를 점검하는 방법

같은 prompt로 답변 3개를 만들었다면 가능한 비교 쌍이 A-B, A-C, B-C의 3개인지 세어 볼 수 있다. 데이터 전체에서는 라벨러 간 일치율과 특정 모델의 답변만 계속 선택되는 편향이 있는지도 확인한다.

둘 다 틀리거나 비슷하게 좋은 답변처럼 판단이 애매한 쌍은 무리해서 하나를 선택하지 않고 보류한다. 선택할 수 있는 쌍에는 이유를 짧게라도 남겨 판단 기준을 드러낸다. 이렇게 수집한 비교 기록은 보상 모델과 DPO가 답변 간 차이를 학습하는 신호가 된다.
