책임 있는 AI를 요구사항과 검증으로 바꾸기

책임 있는 AI는 선언문을 붙이는 일이 아니라 모델이 틀리거나 오용될 때 누가 어떤 피해를 받고, 이를 어떻게 발견·중단·복구할지를 시스템 요구사항으로 만드는 일이다. 정확도 하나가 높아도 특정 집단에서 오류가 집중되거나 개인정보가 새면 책임 있는 시스템이라고 할 수 없다.

여섯 원칙을 관찰 가능한 질문으로 바꾼다

공정성

전체 평균뿐 아니라 중요한 집단별 precision, recall, false positive와 false negative를 나눠 본다. 집단을 나누는 기준 자체가 합법적이고 필요한지도 확인한다. 데이터의 과거 분포가 차별적 결과를 포함했다면 모델은 이를 패턴으로 재생산할 수 있다.

신뢰성과 안전성

정상 입력의 성능뿐 아니라 누락값, 분포 변화, adversarial input, 외부 도구 실패를 시험한다. 모델 confidence를 진실 확률처럼 사용하지 않고, 확신이 낮거나 피해가 큰 사례는 사람이 검토하도록 전환한다. 중단 장치와 이전 안정 버전으로 돌아가는 경로도 필요하다.

프라이버시와 보안

학습·평가·로그에 필요한 최소 데이터만 수집하고 보존 기간과 접근 권한을 정한다. secret이나 개인 원문을 prompt, vector index, telemetry에 넣기 전에 전송 경계를 확인한다. 모델이 데이터를 암기하거나 tool 권한을 악용할 가능성을 별도 위협으로 다룬다.

포용성

평균 사용자만 가정하지 않는다. 언어, 장애, 기기 성능, 네트워크 조건과 숙련도 차이에서 사용할 수 있는지 확인한다. AI가 사람을 대체한다는 목표보다 사용자가 결과를 이해하고 수정하며 거부할 수 있는 통제권을 설계한다.

투명성

사용자가 AI가 개입했다는 사실, 결과의 근거 범위와 한계를 알 수 있어야 한다. 중요한 결정에서는 입력 자료, 적용한 규칙, model/version, 검토자를 receipt로 재현할 수 있게 한다. 설명 문구가 실제 동작과 다르면 투명성이 아니다.

책임성

모델, 데이터, 배포, 최종 결정의 소유자를 구분한다. 문제가 발생했을 때 “AI가 결정했다”로 끝내지 않고 누가 배포를 멈추고 사용자에게 알리며 데이터를 정정할지 정한다. 채용, 금융, 의료, 법률처럼 결과가 중대한 영역은 사람의 승인과 이의 제기 경로를 기본값으로 둔다.

작은 사례: 채용 공고 추천

개발자 공고 추천 시스템이라면 먼저 위치·경력·고용 형태 같은 명시적 조건을 확인한다. 언어 모델은 공고와 프로젝트 근거의 연결 후보를 제시할 수 있지만 없는 경험을 만들어서는 안 된다. 추천 결과에는 사용한 실제 근거와 부족한 조건을 함께 보여 주고, 지원은 사용자가 결정한다.

이 사례의 검증은 추천 개수보다 다음 질문으로 이루어진다.

  • 실제 이력에 없는 기술을 근거로 사용한 건수가 0인가?
  • 마감되거나 접근할 수 없는 공고를 현재 후보로 남기지 않았는가?
  • 특정 배경의 후보를 간접 변수로 일괄 배제하지 않았는가?
  • 사용자가 추천 근거를 확인하고 제거할 수 있는가?

운영 체크리스트

  1. 사용 목적과 금지 용도를 문장으로 고정한다.
  2. 데이터 출처, 동의, 보존 기간과 대표성 한계를 기록한다.
  3. 전체 및 집단별 평가와 실패 사례를 남긴다.
  4. 외부 도구·권한·개인정보 경계를 테스트한다.
  5. 사람이 개입하는 조건과 책임자를 지정한다.
  6. model·prompt·데이터가 바뀌면 영향받는 평가를 다시 실행한다.
  7. 사고가 발생하면 중단·통지·정정·복구 기록을 남긴다.

스스로 확인할 질문

  • 이 시스템이 틀렸을 때 가장 큰 피해를 받는 사람은 누구인가?
  • 평균 성능이 가리고 있는 집단별 실패가 있는가?
  • 사용자가 AI 결과를 거부하거나 수정할 수 있는가?
  • 어느 변경이 기존 평가를 무효로 만드는지 추적할 수 있는가?

근거와 확인 범위

2026-08-28에 보존한 Microsoft AI-For-Beginners의 한국어 7-Ethics와 영어 정본을 대조했다. 여섯 원칙의 이름은 유지하되 특정 vendor 도구 목록은 복제하지 않고 Woon의 privacy, receipt, 승인 경계에 맞춘 검증 질문과 운영 절차로 흡수했다.
