GPT 구조 — Transformer 디코더를 쌓아 만든 언어 모델

확인 범위: GPT 구성과 설정·shape·파라미터의 일반 관계를 설명한다. 코드 정확성·버전 일치·실행 성능은 별도 검증 대상이다.

한 줄 요약: GPT(Generative Pre-trained Transformer)는 입력 임베딩 → N개의 Transformer Block → LayerNorm → LM Head로 구성된 자기회귀 언어 모델이다.

GPT 구조 혼동

개별 구성 요소 — 토크나이저, 임베딩, Self-Attention, Transformer Block — 를 이해했다면, 이것들을 어떤 순서로 조립해야 “다음 토큰을 예측하는 모델”이 되는지를 알아야 한다. GPT는 이 조립 설계도다.

Transformer 블록 하나는 “한 단계의 사고”에 해당한다. 하지만 블록 하나로는 복잡한 언어 패턴을 포착할 수 없다. GPT는 이 블록을 12개(GPT-2 small)에서 96개(GPT-3)까지 쌓고, 앞뒤에 임베딩 층과 출력 층을 붙여 토큰 ID를 입력받아 다음 토큰의 확률 분포를 출력하는 완전한 모델을 만든다.

GPT 구조 흐름

비유

GPT는 공장의 조립 라인과 같다. 원재료(토큰 ID)가 들어오면 첫 번째 공정(임베딩)에서 벡터로 바꾸고, 중간 공정(Transformer Block N개)에서 문맥 정보를 반복적으로 섞은 뒤, 마지막 공정(LM Head)에서 다음에 올 단어의 확률을 출력한다.

전체 구조

%% GPT 전체 구조
flowchart TD
  token["토큰 ID<br/>(B, T)"]
  embedding["InputEmbedding<br/>(B, T, D)"]
  block1["TransformerBlock 1<br/>LayerNorm -&gt; Causal MHA -&gt; Residual<br/>LayerNorm -&gt; FFN(GELU) -&gt; Residual"]
  block2["TransformerBlock 2<br/>입출력 shape 유지: (B, T, D)"]
  blockn["TransformerBlock N<br/>반복적으로 문맥 정보 혼합"]
  norm["LayerNorm<br/>최종 정규화"]
  head["LM Head<br/>Linear(D -&gt; vocab_size)<br/>(B, T, vocab_size)"]
  logits["logits<br/>(B, T, vocab_size)"]
  token --> embedding
  embedding --> block1
  block1 --> block2
  block2 -->|...| blockn
  blockn --> norm
  norm --> head
  head --> logits

B = batch size, T = sequence length, D = d_model(임베딩 차원), V = vocab_size.

모든 모델이 같은 어휘와 컨텍스트 길이를 쓴다. 차이는 블록 수(n_layers)와 임베딩 차원(emb_dim)뿐이다. 블록을 더 쌓고 벡터를 더 넓히면 파라미터가 늘어나고 표현력이 커진다.

각 구성 요소의 역할

InputEmbedding: 토큰 ID를 d_model 차원 벡터로 변환한다. 토큰 임베딩(무슨 토큰인가)과 위치 임베딩(몇 번째 자리인가)을 더한 뒤 Dropout을 적용한다. 자세한 내용은 임베딩 룩업을 참고한다.

TransformerBlock × N: Causal Attention으로 토큰 간 문맥을 섞되 미래 토큰은 보지 못하게 막고, FeedForward로 토큰별 특징을 추출한다. 블록마다 Residual Connection과 LayerNorm이 붙는다. 자세한 내용은 트랜스포머 블록과 Causal Attention — 미래를 보지 못하게 하는 마스크을 참고한다.

최종 LayerNorm: 마지막 블록의 출력을 정규화한다. Pre-Norm 구조에서는 각 블록 내부에서 LayerNorm을 먼저 적용하므로, 마지막 블록의 최종 출력에는 정규화가 빠져 있다. 이를 보완하는 것이 이 층이다.

LM Head: d_model 차원 벡터를 vocab_size 차원으로 투영하여 각 토큰에 대한 점수(logit)를 만든다. softmax를 적용하면 다음 토큰의 확률 분포가 된다.

GPT 구조 코드

PyTorch 구현 (밑바닥 LLM 과제 템플릿)

forward에서 targets가 주어지면 loss를 함께 반환한다. targets는 입력 시퀀스를 한 칸 밀어낸 것이다. 입력이 [A, B, C, D]이면 targets는 [B, C, D, E]가 되어, 각 위치에서 다음 토큰을 맞추는 문제가 된다.

설정 딕셔너리 예시

이 설정으로 테스트용 소형 GPT를 만들 수 있다. emb_dim이 n_heads로 나누어떨어져야 한다 — 각 head의 차원이 emb_dim // n_heads이기 때문이다.

Greedy 텍스트 생성

생성은 반복이다. 모델에 현재까지의 시퀀스를 넣고, 마지막 위치의 logits에서 가장 점수가 높은 토큰을 뽑아 뒤에 붙인다. 이것을 max_new_tokens번 반복한다.

idx[:, -context_size:]로 컨텍스트 윈도우를 자르는 이유: 위치 임베딩의 크기가 context_length로 고정되어 있어서, 시퀀스가 그보다 길어지면 위치 임베딩을 조회할 수 없다.

파라미터 수 계산

GPT-2 small(emb_dim=768, n_heads=12, n_layers=12, vocab_size=50257)의 파라미터를 세어 보자.

토큰 임베딩: 50,257 × 768 = 38,597,376 위치 임베딩: 1,024 × 768 = 786,432

TransformerBlock 하나:

  • LayerNorm × 2: 768 × 2 × 2 = 3,072 (gamma + beta)
  • MHA (W_q + W_k + W_v + W_o): 768 × 768 × 4 = 2,359,296
  • FFN (W1 + W2): 768 × 3,072 + 3,072 × 768 = 4,718,592
  • 블록 합계: 약 7,080,960

12블록: 7,080,960 × 12 = 84,971,520 최종 LayerNorm: 1,536 LM Head: 768 × 50,257 = 38,597,376 (weight tying 시 0)

총합: 약 124M (weight tying 적용 시)

임베딩 테이블이 전체의 31%를 차지한다. 나머지 69%가 12개의 Transformer Block에 있다.

shape 변환 추적 (전체 흐름)

%% GPT shape 변환 추적
flowchart TD
  idx["idx<br/>(2, 16)"]
  token_emb["token_emb<br/>(2, 16, 768)"]
  pos_emb["pos_emb<br/>(16, 768)"]
  add_dropout["토큰 + 위치<br/>Dropout 적용"]
  x["x<br/>(2, 16, 768)"]
  block1["Block 1<br/>(2, 16, 768)"]
  block2["Block 2<br/>(2, 16, 768)"]
  block12["Block 12<br/>(2, 16, 768)"]
  norm["LayerNorm<br/>(2, 16, 768)"]
  lm_head["lm_head<br/>(2, 16, 50257)"]
  idx --> token_emb
  idx --> pos_emb
  token_emb --> add_dropout
  pos_emb --> add_dropout
  add_dropout --> x
  x --> block1
  block1 --> block2
  block2 -->|...| block12
  block12 --> norm
  norm --> lm_head

모든 Transformer Block의 입출력 shape가 동일하다. 이것이 블록을 자유롭게 쌓을 수 있는 이유다.

정리

GPT는 InputEmbedding → TransformerBlock × N → LayerNorm → LM Head라는 직선 구조다. 설정값 7개(vocab_size, context_length, emb_dim, n_heads, n_layers, drop_rate, qkv_bias)로 모델 전체가 결정된다. 블록 수와 임베딩 차원을 키우면 파라미터가 늘어나고, 더 복잡한 언어 패턴을 학습할 수 있다. 생성은 마지막 위치의 logits에서 토큰을 뽑아 이어 붙이는 반복이다.
