Dataset과 DataLoader — 텍스트를 학습 가능한 배치로 자르는 장치

확인 범위: 이 문서는 GPT 사전학습에서 Dataset과 DataLoader가 토큰 시퀀스를 input/target 쌍과 배치로 구성하는 일반 원리와 context_length·stride의 선택 기준을 설명하고, 제시된 GPTDataset 및 create_dataloader 코드가 그 구조를 어떻게 구현하는지 해설한다. 특정 코드 버전의 실행 결과나 성능을 검증한 기록은 아니므로, 실제 동작·shape·효율에 관한 판단은 해당 구현과 실행 환경에서 별도로 확인해야 한다.

GPT 사전학습에서 Dataset은 긴 token ID 시퀀스를 input/target 쌍으로 자르고, DataLoader는 이 쌍들을 batch로 묶어 모델에 넣는다.

Dataset과 DataLoader 구분

토크나이저가 텍스트를 token ID 시퀀스로 바꾸면, 수만~수백만 개의 정수 배열이 된다. 이 배열을 통째로 모델에 넣을 수는 없다. GPU 메모리에 들어가지 않고, gradient 계산도 불가능하다.

GPT 학습은 “현재까지 본 토큰으로 다음 토큰을 맞히기”다. 그래서 긴 시퀀스를 일정 길이(context_length)로 잘라서, 각 조각마다 input과 target을 만들어야 한다. target은 input을 한 칸 오른쪽으로 밀은 것이다. 사람이 별도로 label을 붙이지 않아도 원문 자체가 정답이 된다.

MNIST와 비교하면 구조가 명확하다. MNIST의 target은 0~9 중 정답 class 번호다. GPT의 target은 vocab 전체 중 다음 token ID 번호다. 형식은 같고 규모만 다르다.

배치가 만들어지는 과정

input과 target의 관계

규칙은 하나다. target은 input을 정확히 한 토큰 뒤로 밀은 것이다.

token_ids: [10, 20, 30, 40, 50, 60, 70]
context_length = 3

sample 1:
  input:  [10, 20, 30]
  target: [20, 30, 40]

sample 2 (stride=3):
  input:  [40, 50, 60]
  target: [50, 60, 70]

[10, 20, 30]을 보고 [40, 50, 60]을 맞히는 것이 아니다. 각 위치에서 바로 다음 토큰을 맞힌다. causal mask 때문에 모델은 각 위치마다 다른 길이의 과거 문맥을 사용한다.

10 보고          → 20 예측
10, 20 보고      → 30 예측
10, 20, 30 보고  → 40 예측

context_length

context_length는 한 샘플의 토큰 수이자, 모델이 한 forward에서 볼 수 있는 최대 문맥 길이다. 학습 내내 고정된 하이퍼파라미터이지 epoch마다 늘어나는 값이 아니다. 이 값이 position embedding 테이블의 크기도 결정한다.

stride — 슬라이딩 윈도우의 이동 폭

stride는 다음 샘플의 시작 위치를 몇 칸 옮길지 결정한다. target을 밀어내는 값이 아니다.

token_ids: [1, 2, 3, 4, 5, 6, 7]
context_length = 3

stride = 1 (촘촘, 겹침 많음):
  [1,2,3]→[2,3,4]   [2,3,4]→[3,4,5]   [3,4,5]→[4,5,6]   [4,5,6]→[5,6,7]

stride = 3 (겹침 없음):
  [1,2,3]→[2,3,4]   [4,5,6]→[5,6,7]

stride=1은 문맥 조합을 촘촘하게 보지만 계산량과 중복이 늘어난다. stride=context_length는 input끼리 겹치지 않아 효율적이지만, chunk 경계 주변의 문맥 조합(예: [2,3,4]→[3,4,5])을 보지 못한다.

샘플 개수

target을 만들려면 input 마지막 토큰 뒤에 다음 토큰 하나가 더 필요하다. 시퀀스 길이가 6이고 context_length=3, stride=3이면 두 번째 샘플 [4,5,6]→[5,6,?]을 완성할 수 없다.

n_samples = max(0, (len(token_ids) - context_length - 1) // stride + 1)

Dataset과 DataLoader 코드

책의 GPTDataset 구현

__getitem__에서 실제 절단이 일어난다. start부터 context_length개를 자르면 input, 한 칸 뒤에서 같은 길이를 자르면 target이다. stride가 None이면 context_length를 기본값으로 사용해 겹침 없이 자른다.

DataLoader로 batch 만들기

DataLoader는 GPTDataset에서 나온 (input_ids, target_ids) 쌍을 batch_size개씩 묶는다. 결과 shape는 다음과 같다.

input_ids:  (batch_size, context_length)   예: (8, 4)
target_ids: (batch_size, context_length)   예: (8, 4)

이후 input_ids는 InputEmbedding을 통과해 (8, 4, emb_dim) 벡터가 되고, GPT가 각 위치마다 vocab 크기의 logits를 출력한 뒤, cross entropy가 target_ids와 비교한다.

학습 스크립트에서 동작 확인

책의 학습 스크립트 주석이 이 구조를 잘 요약한다. “원문이 곧 label이 된다. 문장에 이미 다음 token이 있으므로 사람이 별도 label을 붙이지 않아도 된다.”

전체 데이터 파이프라인 위치

원문 텍스트
  → 토크나이저 (BPE)
  → token ID 시퀀스: [10, 20, 30, 40, ...]
  → GPTDataset (context_length로 자름)
  → (input_ids, target_ids) 쌍
  → DataLoader (batch로 묶음)              ← 여기
  → InputEmbedding (벡터 변환)
  → Transformer blocks
  → logits → cross entropy loss

정리

GPTDataset은 긴 token ID 시퀀스를 context_length 길이로 잘라, input과 그 한 칸 뒤의 target을 만든다. stride는 다음 샘플의 시작점 이동 폭이지 target shift가 아니다. DataLoader는 이 쌍들을 batch로 묶어 GPU에 보낸다. GPT 사전학습에서 별도의 label 작업이 필요 없는 이유는, 원문의 다음 토큰이 곧 정답이기 때문이다.
