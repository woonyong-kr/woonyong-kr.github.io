Query, Key, Value — Attention이 정보를 찾고 읽는 세 가지 역할

확인 범위: 이 문서는 Query, Key, Value의 역할과 projection을 통한 분리, scaled dot-product attention의 계산 흐름을 설명하는 개념 문서다. 포함된 PyTorch 코드는 학습 없이 랜덤 초기값으로 계산 과정을 보여 주는 예시이므로, 특정 구현·버전의 검증 결과나 실행 기록·성능 측정을 근거로 한 판단으로 해석하지 않는다.

한 줄 요약: Query는 “무엇을 찾는가”, Key는 “무엇과 매칭되는가”, Value는 “실제로 전달할 정보”다. 같은 입력 벡터에 서로 다른 가중치 행렬을 곱해 세 역할을 분리한다.

Query, Key, Value 구분

Self-Attention의 기본 아이디어는 “각 토큰이 다른 토큰을 참고해서 자기 표현을 갱신한다”이다. 가장 단순한 방법은 입력 벡터끼리 직접 dot product를 해서 유사도를 구하는 것이다. 실제로 이렇게 하면 동작은 한다.

그런데 문제가 있다. 한 토큰이 “찾고 싶은 것”과 “자신이 제공하는 정보”가 같은 벡터로 표현된다. “고양이가 매트 위에 앉았다”에서 “앉았다”가 주어를 찾을 때와, “앉았다”가 다른 토큰에게 “동작”이라는 정보를 줄 때, 필요한 표현이 다르다.

Query, Key, Value 세 가지 projection을 분리하면 이 문제를 해결한다. 같은 입력 벡터 x에 서로 다른 가중치 행렬 W_Q, W_K, W_V를 곱해서 역할별로 다른 벡터를 만든다.

Query, Key, Value 구조

사전 비유

도서관에서 책을 찾는 상황을 생각하자.

  • Query(질의): 내가 찾고 싶은 주제. “역사 소설”
  • Key(색인): 각 책 표지에 적힌 분류. “역사”, “과학”, “소설”
  • Value(내용): 책의 실제 내용. Query와 Key가 매칭되면 이 Value를 꺼낸다

Attention도 같은 구조다. 각 토큰이 Query를 들고 다른 토큰들의 Key와 대조한다. 잘 매칭되는 토큰의 Value를 많이 가져오고, 안 맞는 토큰의 Value는 적게 가져온다.

수학적 정의

입력 행렬 X의 shape가 (T, d_in)일 때 (T: 토큰 수, d_in: 입력 차원):

Q = X @ W_Q shape: (T, d_in) @ (d_in, d_out) = (T, d_out) K = X @ W_K shape: (T, d_in) @ (d_in, d_out) = (T, d_out) V = X @ W_V shape: (T, d_in) @ (d_in, d_out) = (T, d_out)

W_Q, W_K, W_V는 학습 가능한 가중치 행렬이다. d_out은 보통 d_in과 같거나, multi-head attention에서는 head_dim(= d_model / n_heads)이다.

왜 세 개를 따로 두는가

하나의 projection만 쓰면 “찾는 역할”과 “찾아지는 역할”과 “전달하는 역할”이 모두 같은 변환을 거친다. 세 개를 분리하면:

  • W_Q는 “이 토큰이 어떤 정보를 원하는가”를 학습한다
  • W_K는 “이 토큰이 어떤 질문에 응답할 수 있는가”를 학습한다
  • W_V는 “매칭되었을 때 실제로 넘길 정보”를 학습한다

예를 들어 “The cat sat on the mat”에서 “sat”의 Query가 주어를 찾도록, “cat”의 Key가 주어 역할에 응답하도록, “cat”의 Value가 “고양이라는 의미 정보”를 전달하도록 각각 학습된다.

Shape 변환 흐름

  • 입력 토큰 임베딩
  • X: (T, d_in)
  • @ W_Q (d_in, d_out) → Q: (T, d_out) “각 토큰의 질문”
  • @ W_K (d_in, d_out) → K: (T, d_out) “각 토큰의 색인”
  • @ W_V (d_in, d_out) → V: (T, d_out) “각 토큰의 정보”
  • score = Q @ K^T / sqrt(d_out) shape: (T, T)
  • weights = softmax(score) shape: (T, T)
  • output = weights @ V shape: (T, d_out)

Q와 K의 dot product가 attention score를 만들고, softmax를 거쳐 attention weight가 된다. 이 weight로 V를 가중합하면 각 토큰의 새로운 표현이 나온다.

Query, Key, Value 텐서 코드

각 토큰의 입력 벡터 x는 같지만, W_Q, W_K, W_V가 다르기 때문에 queries, keys, values는 서로 다른 벡터가 된다. 이것이 “역할 분리”의 핵심이다.

“journey” 토큰(인덱스 1)의 attention 계산을 추적하면:

Q @ K^T에서 “journey의 query”와 “각 토큰의 key”를 비교한 점수가 나온다. 점수가 높은 토큰의 value가 더 많이 섞인다. 점수가 낮은 토큰의 value는 거의 무시된다. 이것이 attention의 “선택적 참조” 메커니즘이다.

왜 projection 없이 직접 비교하면 부족한가

projection 없이 입력 벡터를 그대로 비교하면 score가 벡터의 방향뿐 아니라 norm에도 영향받고, Query·Key·Value가 같은 표현 공간을 공유한다. 자기 자신과의 dot product가 다른 모든 벡터보다 항상 크다는 보장은 없다. 다만 이 예제처럼 self-score가 크게 나올 수 있으며, 학습 가능한 W_Q와 W_K는 무엇을 찾고 무엇과 비교할지를 서로 다른 표현으로 조정한다.

정리

Query, Key, Value는 같은 입력에 세 개의 서로 다른 가중치 행렬을 곱해 만든다. Query는 정보를 찾는 역할, Key는 매칭 기준, Value는 전달할 정보다. 이 분리 덕분에 Transformer는 “무엇을 찾을지”와 “무엇을 전달할지”를 독립적으로 학습할 수 있다. 실제 Transformer에서는 이 과정이 여러 head로 나뉘어 병렬로 실행되며, 이것이 멀티헤드 어텐션이다.
