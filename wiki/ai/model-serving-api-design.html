모델 서빙 API 설계

모델 서빙 API 설계

한 줄 요약: 모델 서빙 API는 클라이언트와 서버가 주고받을 필드, 옵션, 에러, 스트리밍을 정하는 계약이며, 실행 backend를 바꿔도 흔들리지 않게 서버 밖에서 보이는 경계를 안정적으로 드러낸다.

모델 서빙 API는 클라이언트가 모델에게 요청을 보내고, 서버가 생성 결과와 실행 상태를 돌려주는 계약이다.

모델 서빙 API 설계 구분

모델 배포와 서빙은 전체 실행 흐름을 다룬다. API 설계는 그중에서도 서버 밖에서 보이는 약속을 정한다.

서빙 API가 흐리면 다음 문제가 생긴다.

  • 클라이언트가 어떤 필드를 보내야 하는지 모른다.
  • max_tokens, temperature, stream 같은 옵션의 의미가 요청마다 달라진다.
  • 에러가 모델 문제인지, 입력 검증 문제인지, GPU 과부하인지 구분하기 어렵다.
  • 나중에 vLLM, TensorRT-LLM, ONNX Runtime 같은 실행 backend를 바꿀 때 애플리케이션 코드까지 흔들린다.

좋은 API는 모델 실행을 숨기는 것이 아니라, 클라이언트가 알아야 할 경계를 안정적으로 드러낸다.

가장 작은 채팅 생성 API를 생각해 보자

가장 작은 채팅 생성 API를 생각해 보자.

서버는 이 요청을 내부 실행 흐름으로 바꾼다.

응답은 최소한 어떤 모델이 답했는지, 어떤 텍스트가 나왔는지, 생성이 왜 끝났는지를 알려줘야 한다.

설계 기준

  • 입력 검증
    • model, messages, max_tokens, temperature, stream 같은 필드를 명확히 둔다.
    • context length를 넘는 요청은 모델 실행 전에 거절한다.
  • 생성 옵션
    • temperature, top k, top p 같은 값은 디코딩 규칙으로 연결된다.
    • 같은 옵션 이름이 endpoint마다 다른 의미를 갖지 않게 한다.
  • 실행 경계
    • API 서버는 요청 검증, 인증, rate limit, 응답 형식을 맡는다.
    • 추론 엔진은 prefill, decode, KV cache, batching을 맡는다.
  • 응답 형식
    • 최종 텍스트뿐 아니라 finish_reason과 token usage를 남긴다.
    • 운영에서는 latency, queue time, model time 같은 관측값도 별도 로그로 남긴다.
  • 스트리밍
    • stream: true일 때는 완성된 JSON 하나가 아니라 생성 조각을 순서대로 보낸다.
    • 채팅 UI에서는 첫 토큰 지연 시간이 체감 품질을 크게 좌우한다.

에러도 계약이다

모델 서빙 API는 성공 응답만 설계하면 부족하다.

에러는 적어도 다음을 구분해야 한다.

  • 입력 문제
    • schema 오류, 빈 메시지, context length 초과
  • 용량 문제
    • rate limit, queue timeout, GPU memory 부족
  • 모델 문제
    • 모델 로드 실패, tokenizer mismatch, backend 실행 실패
  • 클라이언트 재시도 가능 여부
    • 같은 요청을 다시 보내도 되는지, 요청을 줄여야 하는지

모델 서빙 API 설계 적용 기준

  • 내부 프로젝트용 API라면
    • 필드 수를 줄이고, 디버깅에 필요한 token usage와 에러 타입을 먼저 남긴다.
  • 외부 호환 API가 필요하다면
    • 클라이언트 SDK가 기대하는 endpoint, field name, streaming 형식을 맞춘다.
  • 운영 안정성이 중요하다면
    • request id, rate limit, timeout, retryable error를 처음부터 포함한다.
  • 추론 엔진을 바꿀 수 있어야 한다면
    • API 계약을 engine 내부 함수명이나 batch 구조에 묶지 않는다.

모델 서빙 API 설계 관련 문서

  • API 서버가 포함되는 전체 서빙 흐름
  • 생성 옵션이 실제 토큰 선택으로 바뀌는 규칙
  • 요청 하나가 모델 내부에서 처리되는 두 단계
  • API 요청이 추론 엔진의 대기열과 배치로 묶이는 방식
