DPO — 보상 모델 없이 선호를 직접 학습하는 정렬 방법

범위: 이 문서는 DPO의 목적, 손실 함수와 학습 흐름, 일반적인 선택 기준을 개념적으로 설명하고 입력에 제시된 예제 코드와 계산을 해설한다. 특정 구현의 정확성·버전 호환성·실행 결과나 RLHF 대비 메모리 사용량·안정성·성능에 관한 판단은 실제 코드와 환경, 실행 기록 및 측정을 통한 별도 검증이 필요하다.

한 줄 요약: DPO(Direct Preference Optimization)는 RLHF의 Reward Model과 PPO를 제거하고, 선호 쌍 데이터로 언어 모델의 정책을 직접 최적화하는 정렬 알고리즘이다.

DPO 문제

RLHF는 3단계 파이프라인이다. SFT → Reward Model 학습 → PPO 정책 최적화. 각 단계마다 별도 모델과 학습 루프가 필요하다.

이 구조에는 실용적 문제가 있다.

  • Reward Model을 따로 학습해야 한다. GPT 크기의 모델을 하나 더 유지한다.
  • PPO는 강화학습이다. 학습이 불안정하고 하이퍼파라미터에 민감하다.
  • PPO 최적화 중에 SFT 모델(참조 정책), RM, 현재 정책, 가치 함수까지 최소 4개 모델이 메모리에 올라간다.
  • Reward hacking이 발생할 수 있다. 모델이 RM의 허점을 찾아 점수는 높지만 질이 낮은 답변을 생성한다.

DPO는 “Reward Model을 명시적으로 학습하지 않고도 같은 목표를 달성할 수 있다”는 수학적 발견에 기반한다. Rafailov et al.(2023)이 제안했다.

DPO 계산

비유

RLHF는 시험 채점자(Reward Model)를 먼저 교육하고, 학생(정책)이 채점자의 점수를 보고 답안을 고치는 구조다. 채점자 교육과 학생 교육이 별도 과정이다.

DPO는 채점자를 없앤다. 대신 “이 답안이 저 답안보다 낫다”는 비교 데이터를 학생에게 직접 보여주고, 학생이 스스로 좋은 답안의 확률을 높이도록 학습한다.

RLHF의 최적 정책에서 출발

RLHF의 최적화 목표를 다시 보면 다음과 같다.

maximize  E[RM(prompt, answer)] - beta * KL(pi || pi_ref)

pi는 학습 중인 정책, pi_ref는 SFT 모델(참조 정책), beta는 KL 페널티 계수다. 이 목표의 최적해는 닫힌 형태(closed-form)로 구할 수 있다.

pi*(y | x) = (1/Z(x)) * pi_ref(y | x) * exp(r(x, y) / beta)

Z(x)는 정규화 상수다. 최적 정책은 참조 정책에 보상 함수의 지수를 곱한 형태가 된다.

보상 함수를 정책으로 치환

위 최적해를 r(x, y)에 대해 정리하면 다음과 같다.

r(x, y) = beta * log(pi(y | x) / pi_ref(y | x)) + beta * log Z(x)

보상 함수를 정책의 log 비율로 표현할 수 있다. Z(x)는 prompt에만 의존하는 상수이므로, 두 답변의 보상 차이를 구하면 Z(x)가 상쇄된다.

r(x, y_w) - r(x, y_l) = beta * log(pi(y_w | x) / pi_ref(y_w | x))
                        - beta * log(pi(y_l | x) / pi_ref(y_l | x))

이제 RLHF의 Reward Model 학습에서 사용하던 Bradley-Terry 손실을 그대로 적용하되, RM 점수 자리에 위의 정책 log 비율을 넣는다.

DPO 손실 함수

L_DPO = -log sigmoid(beta * (log pi(y_w|x)/pi_ref(y_w|x) - log pi(y_l|x)/pi_ref(y_l|x)))

이 한 줄이 DPO의 전부다. Reward Model도 PPO도 없다. 선호 쌍 (x, y_w, y_l)과 참조 정책 pi_ref만 있으면 된다.

왜 이것이 작동하는가?

sigmoid 안의 값을 풀어 보면 직관이 잡힌다.

  • log pi(y_w|x)/pi_ref(y_w|x) — 현재 정책이 선호 답변에 부여하는 확률이 참조 정책 대비 얼마나 높은가.
  • log pi(y_l|x)/pi_ref(y_l|x) — 현재 정책이 비선호 답변에 부여하는 확률이 참조 정책 대비 얼마나 높은가.

loss를 줄이려면 첫째 항은 커지고 둘째 항은 작아져야 한다. 즉 선호 답변의 상대 확률은 올리고, 비선호 답변의 상대 확률은 내린다.

pi_ref로 나누는 것이 KL 페널티 역할을 한다. 현재 정책이 참조 정책에서 너무 멀어지면 log 비율이 극단적으로 커져 학습이 불안정해지므로, 자연스럽게 참조 정책 근처에 머무른다.

beta의 역할

beta는 RLHF에서와 같은 역할이다. beta가 크면 참조 정책에서 크게 벗어나지 않는다. beta가 작으면 선호 데이터에 더 강하게 적응한다. 일반적으로 0.1~0.5 범위를 사용한다.

DPO 코드

밑바닥 LLM 책 부록 코드(ch07/04_preference-tuning-with-dpo/dpo-from-scratch.ipynb)에 DPO from-scratch 구현이 들어 있다. 핵심은 세 함수다. 토큰별 log 확률을 구하는 compute_logprobs, DPO 손실을 계산하는 compute_dpo_loss, 배치 하나에 둘을 엮는 compute_dpo_loss_batch. 아래는 책 코드 그대로이며 한글 주석만 보강했다.

토큰 log 확률 — compute_logprobs

log_softmax 후 torch.gather로 정답 토큰의 log 확률만 뽑는다. selection_mask로 프롬프트·패딩 토큰을 빼고 응답 토큰만 평균 낸다. 반환 shape는 (B,).

DPO 손실 — compute_dpo_loss

logits = model_logratios - reference_logratios가 핵심이다. 정책의 (선호−비선호) log 비율에서 참조 정책의 (선호−비선호) log 비율을 뺀다. Reward Model이 등장하지 않는다. chosen_rewards/rejected_rewards는 detach()로 그래프에서 떼어내 학습에는 영향을 주지 않고 진행 상황만 추적한다.

배치 결합 — compute_dpo_loss_batch

정책 모델은 chosen·rejected 두 번 forward 하고 grad를 추적한다. 참조 모델은 torch.no_grad() 안에서 같은 두 번을 돌리되 고정한다. 한 배치당 forward는 총 4회(정책 2 + 참조 2)다. 이것이 DPO가 RLHF보다 메모리를 적게 쓰는 이유다. RM과 가치 함수가 없고 참조 모델은 grad를 안 잡는다.

shape 변환 흐름

선호 답변 (chosen):
  batch["chosen"]: (B, T_w)
    → policy_model → logits: (B, T_w, vocab_size)
    → log_softmax → gather → selected_log_probs: (B, T_w-1)
    → mask 적용 + 평균 → pi_win: (B,)

비선호 답변 (rejected):
  batch["rejected"]: (B, T_l)
    → policy_model → logits: (B, T_l, vocab_size)
    → log_softmax → gather → selected_log_probs: (B, T_l-1)
    → mask 적용 + 평균 → pi_lose: (B,)

참조 모델도 동일한 과정 (no_grad):
  ref_win, ref_lose: (B,)

logits = (pi_win - pi_lose) - (ref_win - ref_lose)   # (B,)
loss = -logsigmoid(beta * logits).mean()             # scalar

구체적 숫자 예시

model_logratios - reference_logratios는 (pi_win - ref_win) - (pi_lose - ref_lose)와 항만 재배열한 같은 식이다. 둘 다 1.7이 나온다. diff가 양수이면 현재 정책이 참조 정책 대비 선호 답변을 더 높이 평가하고 있다는 뜻이다. loss가 줄어들며 학습이 수렴한다.

RLHF vs DPO 학습 비교

RLHF 학습:
  1. SFT 모델 학습                    ← 모델 1
  2. RM 학습 (선호 쌍 → 스칼라 점수)   ← 모델 2
  3. PPO (정책 + 가치함수 + RM + 참조) ← 모델 3,4 + 모델 1,2

DPO 학습:
  1. SFT 모델 학습                    ← 모델 1
  2. DPO (정책 + 참조)                ← 모델 2 + 모델 1

RLHF는 최소 4개 모델이 메모리에 올라간다. DPO는 2개(현재 정책 + 참조 정책)만 필요하다.

정리

DPO는 RLHF의 최적 정책 공식을 역으로 풀어, Reward Model과 PPO 없이 선호 데이터로 정책을 직접 최적화하는 방법이다. 손실 함수 하나로 선호 답변의 상대 확률은 올리고 비선호 답변의 상대 확률은 내린다. 참조 정책과의 log 비율이 자연스러운 KL 페널티 역할을 한다. RLHF 대비 학습이 안정적이고 메모리 사용이 적으며 구현이 단순하다.
