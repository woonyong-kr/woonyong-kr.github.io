ONNX Runtime 추론

ONNX Runtime은 ONNX 형식으로 저장된 모델을 여러 실행 환경에서 돌리기 위한 추론 런타임이다.

ONNX Runtime 추론 문제

모델을 학습한 프레임워크와 실제 배포 환경은 다를 수 있다. PyTorch에서 만든 모델을 서버, 모바일, Windows 앱, GPU 서버처럼 서로 다른 곳에서 돌리려면 모델 표현과 실행 런타임을 분리하는 편이 좋다.

ONNX Runtime은 이 분리 지점에 있다.

이 말은 즉, ONNX Runtime은 모델을 새로 학습하는 도구가 아니라 이미 준비된 모델을 어느 장치에서 어떻게 실행할지 정하는 추론 실행 계층이다.

여기서 기억할 이름은 두 개다.

  • InferenceSession
    • ONNX 모델 파일을 읽고 실행 가능한 세션으로 만든다.
    • 입력 이름, 출력 이름, graph 최적화, provider 선택이 이 주변에서 결정된다.
  • Execution Provider
    • 실제 연산을 어느 backend에서 실행할지 정한다.
    • 예: CPU, CUDA, TensorRT, DirectML 같은 실행 경로

LLM 서빙에서는 ONNX Runtime만으로 vLLM 같은 서빙 스케줄러 전체를 대체한다고 보기보다, 모델 실행 backend 후보 중 하나로 보는 편이 안전하다. 배칭, streaming, KV cache 관리, API 서버는 별도 서빙 구조와 함께 판단해야 한다.

ONNX Runtime 추론 사용 기준

  • ONNX Runtime이 어울리는 경우
    • PyTorch 모델을 표준 ONNX 형식으로 export해 여러 환경에서 재사용하고 싶을 때
    • CPU/GPU/Windows/edge 환경처럼 실행 backend 선택이 중요할 때
    • 모델 실행 계층을 애플리케이션 코드와 분리하고 싶을 때
  • 다른 LLM 서빙 엔진을 먼저 볼 경우
    • 대규모 autoregressive LLM에서 continuous batching, paged KV cache, speculative decoding이 핵심 병목일 때
    • OpenAI 호환 API, multi-tenant serving, GPU scheduler가 먼저 필요한 상황일 때
  • 확인할 질문
    • 사용하려는 모델이 안정적으로 ONNX export 되는가?
    • target 환경에서 필요한 Execution Provider가 지원되는가?
    • latency, throughput, 메모리 사용량을 실제 입력 길이와 batch size로 측정했는가?
