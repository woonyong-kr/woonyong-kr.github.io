혼합 정밀도 학습 — FP16과 FP32로 메모리와 속도를 조절하는 기법

확인 범위: 이 문서는 혼합 정밀도 학습에서 FP16·BF16·FP32를 나누어 쓰는 일반 원리와 선택 기준을 설명하며, 제시된 PyTorch 학습 루프와 메모리·속도 수치는 특정 코드·버전·하드웨어에서 실행해 검증한 결과가 아니라 예시다. 실제 적용 여부와 연산별 정밀도, 안정성, 메모리 절감 및 성능 향상은 사용하는 코드와 PyTorch 버전, 모델, GPU에서 실행 기록과 측정으로 확인해야 한다.

혼합 정밀도 학습(Mixed Precision Training)은 순전파와 역전파의 행렬 연산을 FP16 또는 BF16으로 수행하고, 파라미터 업데이트는 FP32 마스터 가중치로 처리하는 방식이다.

혼합 정밀도 학습이 비용을 줄이는 지점

신경망의 모든 연산을 FP32(32비트 부동소수점)로 수행하면 수치적으로 안전하지만, 연산이 느리고 메모리 사용량이 크다. GPT-2 small(124M 파라미터)의 FP32 학습에 필요한 메모리를 나누어 보면 다음과 같다.

파라미터:           124M × 4B(fp32) = 496MB
Gradient:          124M × 4B(fp32) = 496MB
Adam optimizer:    124M × 8B(m + v, 각 fp32) = 992MB
활성값(batch 8):   수 GB (층 수, seq_len에 비례)
합계:              약 2GB + 활성값

모델이 GPT-3(175B)급으로 커지면 파라미터만 700GB를 차지하므로 FP32 상태로는 단일 GPU에 올릴 수 없다.

FP16은 숫자 하나를 표현하는 데 2바이트를 사용한다. FP32의 절반이며 연산도 빠르다. NVIDIA GPU의 Tensor Core는 FP16 행렬 곱을 FP32보다 2~8배 빠르게 처리한다. 그러나 FP16은 표현할 수 있는 값의 범위가 좁다.

FP32: 부호 1비트 + 지수 8비트 + 가수 23비트 → 표현 범위 약 1.2e-38 ~ 3.4e38
FP16: 부호 1비트 + 지수 5비트 + 가수 10비트 → 표현 범위 약 5.96e-8 ~ 65504

gradient 값이 1e-8 이하면 FP16에서 0이 된다 (언더플로우).
gradient 값이 65504를 넘으면 FP16에서 inf가 된다 (오버플로우).

gradient가 0이 되면 파라미터가 업데이트되지 않아 학습이 멈춘다. 혼합 정밀도 학습은 FP16의 속도와 메모리 이점을 활용하면서 이런 정밀도 문제를 보완한다.

정밀도를 나누어 쓰는 방식

비유

혼합 정밀도는 회사에서 업무를 나누는 방식에 비유할 수 있다. 대량의 단순 작업인 행렬 곱은 빠르지만 정밀도가 낮은 인턴(FP16)이 맡는다. 최종 결과를 검토하고 장부인 파라미터를 갱신하는 일은 정확한 회계사(FP32)가 담당한다. FP16 연산에서 생길 수 있는 오차를 FP32 단계에서 보완해 최종 장부의 정확도를 유지하는 구조다.

세 가지 안정화 장치

혼합 정밀도 학습은 다음 세 가지 기법을 함께 사용한다. 이 가운데 하나라도 빠지면 학습이 불안정해질 수 있다.

1. FP32 마스터 가중치 (Master Weights)

파라미터의 원본인 마스터 복사본은 FP32로 유지한다. 순전파와 역전파에는 FP16 복사본을 사용하지만, optimizer가 파라미터를 업데이트할 때는 FP32 마스터 가중치를 갱신한다. 갱신된 FP32 값은 다시 FP16으로 복사해 다음 step에서 사용한다.

  • 학습 루프 한 step
  • FP32 마스터 가중치
  • ↓ FP16으로 복사
  • FP16 가중치 → 순전파(FP16) → loss
  • 역전파(FP16)
  • FP16 gradient
  • ↓ FP32로 변환
  • FP32 마스터 가중치 ← optimizer.step(FP32)

FP32 마스터 가중치가 필요한 이유는 업데이트 값이 매우 작을 수 있기 때문이다. learning rate가 1e-4이고 gradient가 1e-4이면 업데이트 크기는 1e-8이다. FP16은 이 값을 표현하지 못해 파라미터가 바뀌지 않지만, FP32는 표현할 수 있다.

2. Loss Scaling

역전파에서 gradient가 너무 작으면 FP16 언더플로우가 발생한다. Loss scaling은 loss에 큰 상수(예: 1024)를 곱해 gradient도 같은 비율로 키운다. 이후 optimizer가 업데이트하기 전에 gradient를 같은 상수로 나누어 원래 크기로 되돌린다.

원래 gradient 값:  3.2e-8 → FP16에서 0이 됨 (언더플로우)

loss × 1024 → gradient도 1024배 → 3.2e-8 × 1024 = 3.28e-5 → FP16으로 표현 가능
optimizer 업데이트 전에 gradient / 1024 → 원래 크기로 복원

PyTorch의 GradScaler는 이 과정을 자동으로 처리한다. scale factor를 동적으로 조절해 오버플로우와 언더플로우 사이에서 적절한 범위를 유지한다. gradient에 inf나 nan이 나타나면 해당 step을 건너뛰고 scale factor를 줄인다.

3. FP16 연산 + FP32 누적

행렬 곱(matmul)은 FP16으로 수행하되 결과를 더할 때는 FP32로 누적한다. Tensor Core는 이 패턴을 하드웨어 수준에서 지원한다. 곱셈은 빠른 FP16으로 처리하고 합산은 더 정확한 FP32로 처리해 수치 안정성을 확보한다.

FP16 vs BF16

NVIDIA A100 이후 GPU는 BF16(Brain Floating Point 16)을 지원한다.

FP16:  부호 1 + 지수 5 + 가수 10 → 정밀도 높지만 범위 좁음 (max 65504)
BF16:  부호 1 + 지수 8 + 가수 7  → 정밀도 낮지만 범위 넓음 (max 3.39e38, FP32와 동일)

BF16은 FP32와 지수 비트 수가 같아서 오버플로우와 언더플로우가 거의 발생하지 않는다. 따라서 Loss scaling 없이도 안정적으로 학습할 수 있다. LLM 학습에서는 BF16이 표준으로 자리 잡고 있다.

혼합 정밀도 학습 코드

PyTorch는 torch.amp 모듈로 혼합 정밀도를 지원한다.

autocast는 연산의 수치 안정성에 따라 사용할 정밀도를 자동으로 판단한다.

  • FP16으로 수행: torch.matmul, torch.nn.Linear, torch.nn.Conv2d
  • FP32로 유지: torch.nn.LayerNorm, torch.nn.Softmax, cross_entropy
  • 이 분류는 수치 안정성 실험 결과에 기반한다. softmax와 layernorm은 작은 값의 차이가 결과에 큰 영향을 주므로 FP32가 필수다.

밑바닥 LLM 책의 학습 루프와 비교

밑바닥 LLM 책의 학습 루프는 FP32 전용이다. AMP가 바꾸는 부분을 이해하려면 원본 루프와 대조해 볼 수 있다.

이 루프는 순전파, 역전파, 파라미터 갱신을 모두 FP32로 수행한다. AMP를 적용할 때는 세 지점을 바꾼다.

  • loss = ... 계산을 with autocast(...) 블록으로 감싼다 → matmul·linear가 FP16으로 수행된다.
  • loss.backward()를 scaler.scale(loss).backward()로 바꾼다 → loss scaling으로 언더플로우를 막는다.
  • optimizer.step()을 scaler.step(optimizer) + scaler.update()로 바꾼다 → gradient에 inf/nan이 있으면 step을 건너뛰고 scale factor를 조절한다.

책의 코드는 학습 루프의 기본 골격을 보여준다. AMP는 그 골격에 정밀도 제어를 더한다. 일부 연산은 FP16/BF16으로 빠르게 수행하고, 수치적으로 위험한 연산은 FP32로 유지한다.

메모리 절감 수치 예시

GPT-2 small(124M 파라미터)을 기준으로 FP32 전용 학습과 혼합 정밀도 학습의 메모리를 비교하면 다음과 같다.

                FP32 전용         혼합 정밀도 (FP16 + FP32 마스터)
파라미터:       124M × 4B = 496MB   FP16 복사본: 248MB + FP32 마스터: 496MB = 744MB
Gradient:      124M × 4B = 496MB   124M × 2B = 248MB
Adam (m,v):    124M × 8B = 992MB   124M × 8B = 992MB (FP32 유지)
활성값:        ~6GB (FP32)          ~3GB (FP16)

합계:          ~8GB                 ~5GB

활성값 절감이 가장 크다.
GPU Tensor Core 활용으로 연산 속도도 1.5~2배 향상.

FP32 마스터 가중치와 optimizer 상태를 유지하기 때문에 파라미터 관련 메모리는 크게 줄지 않는다. 주된 절감 효과는 활성값과 gradient에서 나온다. 그래디언트 체크포인팅과 함께 사용하면 활성값을 FP16과 체크포인팅으로 이중 절감해 단일 GPU에서 더 큰 모델을 학습할 수 있다.

정리

혼합 정밀도 학습은 행렬 연산에 FP16을 사용해 속도와 메모리 효율을 높이고, FP32 마스터 가중치와 loss scaling으로 정밀도 손실을 보완한다. BF16은 FP16보다 표현 범위가 넓어 loss scaling 의존도를 낮추며, 현대 LLM 학습에서 FP16을 대체하고 있다. GPU 메모리 효율을 설계할 때는 그래디언트 체크포인팅, 그래디언트 누적과 함께 살펴볼 수 있다.
