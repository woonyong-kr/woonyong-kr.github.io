명령어 튜닝

명령어 튜닝

확인 범위: 이 문서는 명령어 튜닝의 일반 개념, 분류 미세조정과의 구조 및 loss 처리 차이, 제시된 과제와 책 원본 코드의 구현 방식을 설명한다. 코드 동작, 구체적인 shape와 수치, 버전별 세부 사항, 성능에 관한 판단은 해당 구현과 실제 실행·측정 결과를 별도로 확인해야 한다.

한 줄 요약: 명령어 튜닝은 사전학습된 언어 모델에 (지시, 입력, 정답 답변) 쌍을 제공하고, 답변 구간의 다음 토큰 예측 loss를 최소화해 자연어 지시를 따르는 행동을 학습시키는 supervised learning 방식이다.

명령어 튜닝 구분

사전학습을 마친 GPT의 기본 학습 목표는 다음 토큰 예측이다. 따라서 “다음 문장을 요약해라”라는 입력을 받더라도 요약하지 않고 원문을 이어 쓰거나 다른 텍스트를 생성할 수 있다. 사전학습만으로는 언어 패턴을 배울 수 있지만, “지시를 읽고 요구된 형식으로 답하라”는 행동까지 직접 학습한다고 보기 어렵기 때문이다.

분류 미세조정은 classification head를 추가해 정해진 label을 고르는 방식으로 문제를 푼다. 그러나 분류는 “긍정/부정”처럼 고정된 label 하나를 선택하는 과업이다. “요약해라”, “번역해라”, “코드를 작성해라”처럼 자연어 문장을 생성해야 하는 과업에는 이러한 분류 head가 적합하지 않다.

명령어 튜닝은 LM Head를 유지한 채 (지시 + 정답 답변) 데이터로 모델을 추가 학습한다. 모델은 지시가 주어졌을 때 그에 맞는 답변 토큰 시퀀스를 생성하도록 훈련된다. 이 문서에서 다루는 일반적인 정렬 흐름에서는 명령어 튜닝을 사전학습 다음, RLHF 이전에 수행하는 첫 단계로 설명한다.

명령어 튜닝 흐름

명령어 튜닝은 데이터 구성, 토큰 연결, loss 범위 설정의 순서로 이해하면 쉽다. 먼저 지시와 답변을 한 학습 사례로 만들고, 이를 하나의 토큰 시퀀스로 연결한 뒤, 학습에 반영할 target 위치를 정한다.

비유

사전학습은 수많은 책을 읽으며 언어 감각을 익히는 과정에 가깝다. 명령어 튜닝은 그 언어 감각을 바탕으로 “질문을 받으면 이런 형식으로 답하라”는 업무 매뉴얼을 따라 연습하는 과정에 가깝다. 책을 많이 읽었더라도 응대 방식을 따로 연습하지 않으면 일관된 형식으로 답하기 어려운 것과 같다.

정의

명령어 튜닝(Instruction Tuning)은 사전학습된 모델을 (instruction, input, output) 형식의 라벨 데이터로 추가 학습하는 supervised learning이다. 이 문서에서는 이러한 학습을 SFT(Supervised Fine-Tuning)의 맥락에서 다룬다. 분류 미세조정과 달리 LM Head를 유지하며, 답변 구간의 토큰 시퀀스를 정답으로 삼는다.

데이터 형태

가장 기본적인 instruction 데이터는 다음 세 필드로 구성된다.

채팅 모델에서는 같은 역할을 message 배열 형식으로 표현할 수 있다.

학습 시 토큰 시퀀스 구성

instruction과 input을 합쳐 prompt 구간을 만들고, output을 answer 구간으로 둔다. 그런 다음 두 구간을 이어 하나의 토큰 시퀀스로 만든다.

%% 명령어 튜닝 토큰과 loss 마스크
flowchart LR
  prompt["prompt 구간<br/>[다음]<br/>[문장을]<br/>[요약해라]<br/>[.]<br/>loss 없음"]
  answer["answer 구간<br/>[Transformer는]<br/>[self-attention으로]<br/>[...]<br/>loss 계산"]
  eos["EOS<br/>답변 종료"]
  prompt -->|이어 붙임| answer
  answer -->|종료 토큰| eos

이 문서에서 설명하는 구성의 핵심은 loss를 answer 구간에만 적용하는 것이다.

prompt 구간에도 loss를 적용할 수는 있다. 다만 사용자 입력 자체를 재현하는 학습보다 답변 생성에 초점을 맞추려면 prompt 위치를 제외하고 answer 위치에만 loss를 적용한다. 구체적인 마스킹 범위는 구현에 따라 달라질 수 있으므로 실제 코드를 함께 확인해야 한다.

Loss 함수

명령어 튜닝에서도 사전학습과 같은 cross-entropy를 사용할 수 있다. 여기서 설명하는 방식은 loss 함수 자체를 바꾸는 대신, 계산에 포함되는 target 위치를 answer 구간으로 제한한다.

loss = - sum_t log P(answer_t | prompt, answer_<t)

answer의 첫 토큰은 prompt 전체를 조건으로 예측한다. 두 번째 토큰은 prompt와 answer의 첫 토큰을 조건으로 예측하며, 같은 과정이 answer의 마지막 토큰까지 이어진다.

세 학습 방식의 차이는 다음과 같이 정리할 수 있다.

  • 사전학습: 모든 위치에서 다음 토큰을 예측한다. P(x_t | x_<t)
  • 명령어 튜닝: answer 위치에서 다음 토큰을 예측한다. P(answer_t | prompt, answer_<t)
  • 분류 미세조정: 마지막 hidden state를 이용해 label을 예측한다. P(label | input)

분류 미세조정과의 구조 차이

flowchart LR
  cls_embed["InputEmbedding"]
  cls_block["TransformerBlock x N"]
  cls_norm["LayerNorm"]
  cls_hidden["마지막 토큰 hidden"]
  cls_logits["긍정/부정 logits"]
  cls_head["cls_head"]
  sft_embed["InputEmbedding"]
  sft_block["TransformerBlock x N"]
  sft_norm["LayerNorm"]
  sft_hidden["모든 answer 위치 hidden"]
  sft_logits["다음 토큰 logits"]
  sft_head["sft_head"]
  cls_embed --> cls_block
  cls_block --> cls_norm
  cls_norm --> cls_hidden
  cls_hidden --> cls_head
  cls_head --> cls_logits
  sft_embed --> sft_block
  sft_block --> sft_norm
  sft_norm --> sft_hidden
  sft_hidden --> sft_head
  sft_head --> sft_logits

제시된 분류 미세조정 구현은 LM Head를 제거하고 Classification Head를 붙인다. 반면 명령어 튜닝 구현은 LM Head를 유지한다. 따라서 사전학습에서 사용한 언어 생성 구조를 이어서 활용하면서, 학습 target과 loss 적용 범위를 지시·답변 데이터에 맞게 구성한다.

명령어 튜닝이 배우는 것

명령어 튜닝의 주된 목적은 지식을 새로 주입하는 데 있다기보다, 사전학습에서 얻은 언어 능력을 지시에 맞는 출력 형식으로 사용하는 행동을 학습시키는 데 있다.

학습 데이터의 구성에 따라 다음과 같은 행동을 훈련할 수 있다.

  • 질문에 맞는 답변 형식 선택하기(요약, 번역, 코드, 비교 등)
  • 요구된 언어와 말투 지키기
  • 단계별 설명 제공하기
  • 불확실할 때 단정하지 않기
  • 위험한 요청에 안전하게 대응하기

이런 의미에서 명령어 튜닝은 “지식 주입”보다 “행동 정렬”에 가깝다고 설명할 수 있다. 이 문서가 인용한 InstructGPT 논문(Ouyang et al., 2022)도 모델 규모 확대와 지시 수행 능력을 같은 것으로 볼 수 없다는 문제의식과 연결된다. 논문의 정확한 주장과 적용 범위는 원문을 기준으로 확인해야 한다.

명령어 튜닝의 종류

  • SFT (Supervised Fine-Tuning)
    • 사람이 작성한 좋은 답변을 정답으로 학습한다.
    • 기본적인 지시 수행 행동을 형성하는 단계로 사용된다.
  • Multi-task Instruction Tuning
    • 요약, 번역, 질의응답, 분류 등 여러 과업을 instruction 형식으로 섞어 학습한다.
    • 다양한 지시에 대응하는 행동을 함께 학습한다.
  • Dialogue Fine-tuning
    • user/assistant 대화 형식으로 학습한다.
    • 대화 흐름과 맥락을 유지하는 행동을 다룬다.
  • Safety Fine-tuning
    • 안전 정책에 맞는 거절, 경고, 대안 답변을 학습한다.
    • 유해한 응답을 줄이는 것을 목표로 한다.

이 문서에서 설명하는 파이프라인에서는 명령어 튜닝(SFT)이 사전학습과 RLHF를 잇는다. 먼저 SFT로 지시와 답변 형식을 학습하면, 이후 단계에서 비교할 답변을 생성하고 평가하는 기반을 마련할 수 있다. 실제 파이프라인의 구성과 단계별 필요성은 적용한 방법과 구현을 별도로 확인해야 한다.

명령어 튜닝 코드

밑바닥 LLM 과제 저장소의 src/finetune.py는 분류 미세조정을 구현한다. 명령어 튜닝(SFT)은 이 과제 코드에 직접 포함되어 있지 않지만, 밑바닥 LLM 책 원본의 local/llm_sources/LLMs-from-scratch/ch07에서 관련 구현을 확인할 수 있다. 아래 비교는 제시된 두 구현을 기준으로 구조와 loss 처리 방식의 차이를 설명한다.

분류 미세조정: Classification Head를 붙이는 방식

이 구현은 LM Head를 제거하고 nn.Linear(emb_dim, num_labels)를 붙인다. 이어서 마지막 비패딩 토큰의 hidden state 하나를 사용해 label을 판단한다.

명령어 튜닝: loss masking을 collate에서 처리

제시된 명령어 튜닝 코드는 모델 구조를 바꾸지 않고 사전학습과 같은 LM Head를 사용한다. 또한 별도의 loss_mask를 forward에서 곱하지 않는다. 대신 데이터를 배치로 묶는 custom_collate_fn에서 loss 계산에서 무시할 위치의 target을 -100으로 바꾼다. PyTorch의 cross_entropy는 기본값이 ignore_index=-100이므로 해당 target 위치를 loss 계산에서 제외한다.

이 코드에서는 targets의 패딩 구간을 -100으로 치환한다. 첫 EOS 하나는 종료 토큰을 학습할 수 있도록 남긴다. torch.Tensor의 boolean mask 인덱싱인 targets[indices[1:]]을 사용해 해당 위치를 한 번에 덮어쓴다. 이 설명은 제시된 코드에 대한 해석이며, 실제 동작과 경계 조건은 실행 결과로 확인해야 한다.

loss 계산에는 사전학습에서 사용한 것과 같은 함수를 재사용한다.

logits.flatten(0, 1)은 (B, T, V)를 (B*T, V)로 펴고, target_batch.flatten()은 (B, T)를 (B*T,)로 편다. target이 -100인 위치는 cross_entropy가 건너뛴다. 이 코드에서는 별도의 마스크 곱셈 없이도 무시하도록 지정한 위치가 loss에 반영되지 않는다.

참고: 위 custom_collate_fn은 패딩 구간만 -100으로 막는다. instruction/input에 해당하는 prompt 구간까지 제외하려면 prompt 길이에 해당하는 target도 추가로 -100으로 채워야 한다. 책 ch07의 연습문제인 exercise-solutions.ipynb가 이 변형을 다룬다.

shape 변환 비교

%% 분류 미세조정과 명령어 튜닝의 shape 변환 비교
flowchart LR
  cls_input["input_ids<br/>(B, T)"]
  cls_hidden["embedding + blocks + norm<br/>(B, T, D)"]
  cls_last["마지막 비패딩 토큰<br/>(B, D)"]
  cls_out["classifier<br/>(B, num_labels)"]
  sft_input["input_ids<br/>(B, T)<br/>prompt + answer"]
  sft_hidden["embedding + blocks + norm<br/>(B, T, D)"]
  sft_lm["lm_head<br/>(B, T, vocab_size)"]
  sft_loss["flatten + cross_entropy<br/>target=-100 제외"]
  cls_input --> cls_hidden
  cls_hidden --> cls_last
  cls_last --> cls_out
  sft_input --> sft_hidden
  sft_hidden --> sft_lm
  sft_lm --> sft_loss

분류 미세조정은 마지막 토큰 하나에서 얻은 벡터 (B, D)를 사용한다. 명령어 튜닝은 answer의 여러 위치에서 나온 logits (B, T_answer, vocab_size)를 사용한다. 실제 shape는 입력 길이, 패딩, 마스킹 방식과 구현에 따라 확인해야 한다.

구체적 숫자 예시

다음은 GPT-small (d_model=768, vocab_size=50257, max_length=256)을 가정해 배치 하나를 계산한 예시다. 이는 일반적인 실행 결과가 아니라 제시된 조건에 따른 설명용 계산이다.

이 예시에서 분류 미세조정은 2개의 logit으로 label을 예측한다. 명령어 튜닝은 76개 위치마다 50,257개 어휘 중 정답 토큰을 예측한다. 따라서 두 방식은 출력과 loss를 구성하는 단위가 다르다. 수치와 shape가 실제 구현에서도 같은지는 입력 데이터와 실행 결과로 검증해야 한다.

정리

명령어 튜닝은 사전학습된 GPT의 LM Head를 유지한 채 (지시 + 정답 답변) 데이터로 추가 학습하는 supervised learning 방식이다. 제시된 분류 미세조정 구현이 Classification Head로 고정된 label을 예측하는 데 비해, 명령어 튜닝 구현은 answer 구간의 토큰 시퀀스를 예측한다. 설명한 코드에서 loss 범위를 제한하는 핵심 방법은 collate 단계에서 무시할 target을 -100으로 바꾸고, cross_entropy의 ignore_index=-100 기본값을 이용해 해당 위치를 건너뛰는 것이다. 다만 제시된 기본 코드는 패딩을 제외하며, prompt까지 제외하려면 추가 마스킹이 필요하다. 이처럼 모델의 생성 구조를 유지하면서 지시에 맞는 응답 행동을 학습한다는 점에서 명령어 튜닝은 “지식 주입”보다 “행동 정렬”에 가깝다. 이 문서에서 다루는 정렬 흐름에서는 사전학습과 RLHF 사이의 첫 단계로 배치된다.
