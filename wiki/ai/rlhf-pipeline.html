RLHF — 사람의 선호로 언어 모델을 정렬하는 파이프라인

한 줄 요약: RLHF(Reinforcement Learning from Human Feedback)는 SFT로 기본 행동을 학습한 모델을 사람의 선호 데이터로 추가 최적화하여, 더 유용하고 안전한 답변을 생성하도록 정렬하는 3단계 파이프라인이다.

RLHF 구분

SFT(Supervised Fine-Tuning)는 “좋은 답변”을 정답으로 두고 그대로 따라 쓰게 학습한다. 문제는 좋은 답변이 하나가 아니라는 점이다.

“양자역학을 설명해라”라는 질문에 수학 중심 답변, 비유 중심 답변, 역사 중심 답변 모두 정답이 될 수 있다. SFT는 정답 하나를 보고 그 token sequence의 확률을 높이지만, “이 답변이 저 답변보다 낫다”는 비교 판단을 학습하지 않는다.

사람이 실제로 선호하는 답변의 특성은 명시적 규칙으로 정의하기 어렵다. 도움이 되면서도 안전하고, 정확하면서도 읽기 쉬운 답변을 만드는 기준은 사람의 판단에 의존한다. RLHF는 이 판단을 모델에 주입하는 방법이다.

RLHF 계산

RLHF는 세 단계로 구성된다. InstructGPT 논문(Ouyang et al., 2022)이 이 파이프라인을 정립했다.

3단계 파이프라인 전체 흐름

  • 정답 답변
  • Base GPT | → | SFT 모델
  • 사전 학습 완료 | supervised loss | 지시 따르기
  • SFT 모델이 여러 답변 생성
  • 선호 데이터
  • A > B 순위
  • 사람의 순위로 학습
  • Reward Model
  • 점수 예측
  • reward 신호로 정책 갱신
  • RLHF 모델
  • 정렬 완료

1단계: SFT (Supervised Fine-Tuning)

사전 학습된 GPT에 사람이 작성한 양질의 답변을 보여주고, 그대로 따라 쓰도록 학습한다.

SFT가 끝나면 모델은 지시를 따르는 기본 능력을 갖춘다. 하지만 “어떤 답변이 더 좋은지” 비교하는 능력은 아직 없다.

2단계: Reward Model 학습

같은 prompt에 대해 SFT 모델이 여러 답변을 생성한다. 사람이 답변 쌍을 보고 “A가 B보다 낫다”고 순위를 매긴다.

이 순위 데이터로 Reward Model(RM)을 학습한다. RM은 (prompt, 답변)을 입력받아 스칼라 점수를 출력한다.

학습 목표는 사람이 선호한 답변의 점수가 비선호 답변보다 높아지도록 만드는 것이다.

y_win은 사람이 선택한 답변, y_lose는 탈락한 답변이다. 두 점수의 차이를 sigmoid에 넣어 확률로 바꾸고, 선호 답변의 확률을 최대화한다.

왜 점수 차이만 학습하는가?

RM이 예측하는 점수의 절대값은 의미가 없다. 중요한 것은 “A가 B보다 몇 점 더 높은가”라는 상대적 순서다. 두 답변의 점수 차이가 클수록 RM은 둘의 품질 차이가 크다고 판단한다.

이 방식을 Bradley-Terry 모델이라 한다. 사람이 A를 B보다 선호할 확률을 다음과 같이 모델링한다.

사람이 A를 골랐다면 이 확률을 최대화한다. 사람이 B를 골랐다면 RM(B) - RM(A)의 sigmoid를 최대화한다.

3단계: PPO로 정책 최적화

Reward Model이 준비되면, 이 RM의 점수를 보상 신호로 삼아 SFT 모델을 강화학습(PPO)으로 추가 최적화한다.

강화학습 관점에서 각 요소를 대응시키면 다음과 같다.

PPO(Proximal Policy Optimization)는 보상을 최대화하면서도 정책이 한 번에 너무 크게 바뀌지 않도록 제한한다.

최적화 목표는 다음과 같다.

첫째 항은 RM 점수를 높이라는 뜻이다. 둘째 항은 RLHF 모델(pi_rl)이 SFT 모델(pi_sft)에서 너무 멀어지지 않도록 KL divergence 페널티를 주는 것이다.

왜 KL 페널티가 필요한가?

KL 페널티 없이 RM 점수만 최대화하면 reward hacking이 일어난다. 모델이 RM의 허점을 찾아 점수는 높지만 실제로는 이상한 답변을 생성하게 된다. 예를 들어 불필요하게 긴 답변, 같은 말 반복, 과도한 아첨 등이다.

KL 페널티는 “SFT 모델이 생성할 법한 답변 분포에서 너무 벗어나지 마라”는 제약이다. beta 값이 클수록 제약이 강해져 SFT에 가까운 답변을 유지하고, 작을수록 RM 점수에 더 자유롭게 최적화한다.

RLHF 코드

밑바닥 LLM 레포(SW_AI-W13-gpt)에는 RLHF 구현이 포함되어 있지 않다. 이 레포의 src/finetune.py는 분류 미세조정(SFT의 한 형태)까지만 다룬다.

아래는 RLHF 파이프라인의 핵심 로직을 의사 코드로 정리한 것이다. 실제 구현은 trl(Transformer Reinforcement Learning) 라이브러리 등을 참고한다.

Reward Model 학습 의사 코드

이 코드의 핵심은 GPT의 마지막 토큰 hidden state를 스칼라로 변환하는 reward_head다. 분류 미세조정에서 classifier가 class logits를 내는 것과 구조가 같다. 차이는 출력 차원이 class 수가 아니라 1이라는 점뿐이다.

PPO 최적화 의사 코드

sft_model은 고정(frozen)이다. KL 페널티 계산의 기준선으로만 사용한다. 학습되는 것은 rl_model뿐이다.

텐서 흐름 정리

Reward Model 학습:
  prompt + y_win  → GPT → hidden (B, T, d) → last token (B, d) → reward_head → r_win  (B,)
  prompt + y_lose → GPT → hidden (B, T, d) → last token (B, d) → reward_head → r_lose (B,)
  loss = -log sigmoid(r_win - r_lose)

PPO 최적화:
  prompt → rl_model.generate → answer tokens
  prompt + answer → reward_model → reward (scalar)
  prompt + answer → rl_model  → log_prob_rl  (per token)
  prompt + answer → sft_model → log_prob_sft (per token, frozen)
  final_reward = reward - beta * sum(log_prob_rl - log_prob_sft)
  PPO update on rl_model

SFT와 RLHF의 차이

구분SFTRLHF
학습 신호정답 답변의 token 확률사람의 선호 순위 → RM 점수
정답 형태하나의 token sequence답변 쌍의 상대적 순서
losscross entropyPPO surrogate + KL penalty
비유모범 답안을 베껴 쓰기여러 답안 중 더 나은 것을 고르는 감각 학습

SFT는 “이 답변을 따라 써라”이고, RLHF는 “이 답변이 저것보다 낫다는 판단을 내면화해라”다.

정리

RLHF는 SFT → Reward Model → PPO의 3단계 파이프라인이다. SFT가 기본 행동을 만들고, RM이 사람의 선호를 점수로 변환하고, PPO가 그 점수를 높이면서 SFT에서 너무 벗어나지 않도록 정책을 갱신한다.

RLHF의 핵심 통찰은 “좋은 답변을 직접 보여주는 것보다, 답변 간 비교 순위를 알려주는 것이 사람의 선호를 더 정확하게 전달한다”는 점이다. 사람은 완벽한 답변을 처음부터 작성하는 것보다, 두 답변 중 어느 쪽이 나은지 고르는 것이 훨씬 쉽고 일관적이다.
