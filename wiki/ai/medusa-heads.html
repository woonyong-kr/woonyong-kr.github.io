Medusa 헤드

Medusa 헤드

한 줄 요약: Medusa 헤드는 LLM 본체 위에 보조 decoding head 여러 개를 붙여 별도 draft 모델 없이 여러 미래 토큰 후보를 한 번에 제안하는 추론 가속 기법이다.

Medusa 헤드는 LLM 본체 위에 여러 개의 보조 decoding head를 붙여, 다음 토큰 하나가 아니라 여러 미래 토큰 후보를 한 번에 제안하는 추론 가속 방법이다.

Medusa 헤드 필요성

추측 디코딩은 보통 작은 draft 모델이 여러 토큰을 먼저 제안하고, 큰 target 모델이 그 제안을 검증한다. 이 방식은 빠르지만 draft 모델을 따로 준비하고 관리해야 한다.

Medusa는 이 질문에서 출발한다.

  • 별도 draft 모델 없이도 여러 토큰 후보를 미리 만들 수 있을까?
  • 기존 LLM 본체는 그대로 두고, 작은 head만 추가해서 decode 병목을 줄일 수 있을까?

핵심은 “다음 토큰 전용 head” 하나만 쓰지 않고, t+1, t+2, t+3처럼 몇 스텝 뒤 후보를 예측하는 head를 여러 개 두는 것이다.

Medusa 헤드 사례

일반 autoregressive decode는 한 번에 한 토큰만 확정한다.

Medusa 계열은 같은 문맥에서 여러 head가 미래 후보를 같이 낸다.

전부 맞으면 한 번의 검증으로 여러 토큰을 확정한다. 앞부분만 맞으면 맞은 prefix만 붙이고, 틀린 지점부터 기존 방식으로 이어간다.

추측 디코딩과의 차이

  • 일반 추측 디코딩
    • 별도 draft 모델이 후보 토큰을 만든다.
    • target 모델은 후보를 검증한다.
  • Medusa
    • 같은 모델 위의 여러 보조 head가 후보 토큰을 만든다.
    • 별도 draft 모델을 운영하지 않는 대신, head 학습과 후보 검증 로직이 필요하다.

이 말은 즉, Medusa는 추측 디코딩의 목표를 공유하지만 “후보를 만드는 장치”가 다르다. draft 모델이 아니라 보조 head가 후보 생성자다.

Medusa 헤드 사용 기준

  • Medusa가 어울리는 경우
    • 별도 draft 모델을 운영하기 부담스러울 때
    • 같은 base model에 작은 head를 붙여 decode 가속을 실험하고 싶을 때
    • 채팅처럼 latency 체감이 중요한 서비스에서 여러 토큰 채택률을 높이고 싶을 때
  • 조심할 점
    • head가 낸 후보가 자주 틀리면 검증 비용만 늘고 이득이 줄어든다.
    • head 학습 데이터와 실제 서비스 prompt 분포가 다르면 채택률이 떨어질 수 있다.
    • 엔진이 Medusa식 후보 tree와 검증을 지원해야 실제 서빙 이득으로 이어진다.
