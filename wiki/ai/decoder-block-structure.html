디코더 블록 구조 — GPT가 하나의 사고 단계를 처리하는 단위

디코더 블록 구조 — GPT가 하나의 사고 단계를 처리하는 단위

확인 범위: 이 문서는 GPT 계열 디코더 블록의 일반적인 구조와 구성 선택 기준을 설명하고, 제시된 코드로 그 흐름과 shape 보존 방식을 예시한다. 특정 구현·버전의 실제 동작, 실행 결과, 성능에 관한 판단은 별도의 코드 대조와 실행·측정으로 검증해야 한다.

한 줄 요약: GPT의 디코더 블록은 Causal Multi-Head Attention과 Feed-Forward Network를 잔차 연결과 LayerNorm으로 감싼 구조이며, 이 블록을 N번 반복해 쌓으면 GPT 모델이 된다.

디코더 블록 구조 필요성

원래 Transformer(Vaswani et al., 2017)는 인코더 블록과 디코더 블록을 모두 사용한다. 인코더가 입력을 압축하고, 디코더가 그 압축 결과를 참조하며 출력을 생성하는 구조다.

GPT는 이 중 디코더 블록만 사용한다. 번역처럼 입력 언어와 출력 언어가 다른 과업이 아니라, “다음 토큰 예측”이라는 단일 시퀀스 과업이기 때문이다. 참조할 인코더 출력이 없으므로 cross-attention이 필요 없다. Causal Self-Attention만으로 이전 토큰들을 보고 다음 토큰을 예측한다.

이 문서를 읽고 나면 인코더 블록과 GPT 디코더 블록의 차이, 하나의 블록 안에서 데이터가 어떤 순서로 변환되는지, 그리고 블록을 N번 쌓아 GPT 전체 모델이 되는 구조를 코드로 설명할 수 있다.

디코더 블록 구조 흐름

인코더 블록 vs GPT 디코더 블록

원래 Transformer 디코더 블록에는 서브레이어가 세 개다.

  • Masked Self-Attention — 자기 자신과 이전 위치만 참조
  • Cross-Attention — 인코더 출력을 참조
  • Feed-Forward Network — 토큰별 독립 비선형 변환

GPT 디코더 블록은 Cross-Attention을 제거하고 두 개의 서브레이어만 남긴다.

  • Causal Self-Attention — 이전 토큰만 참조 (causal mask)
  • Feed-Forward Network — 토큰별 독립 비선형 변환
%% 원래 Transformer 디코더 블록과 GPT 디코더 블록 비교
flowchart LR
  original["원래 Transformer 디코더 블록<br/>Masked Self-Attn<br/>이전 위치만 참조<br/>Cross-Attention<br/>인코더 출력 참조<br/>Feed-Forward Net"]
  gpt["GPT 디코더 블록 (decoder-only)<br/>Causal Self-Attn<br/>이전 위치만 참조<br/>Feed-Forward Net<br/>GELU 활성화"]
  original -.-> gpt

Cross-Attention이 빠졌으므로 인코더 없이 디코더 블록만으로 모델이 완성된다. 이것이 “decoder-only” 아키텍처다.

하나의 디코더 블록 내부 — Pre-Norm 구조

GPT-2 이후의 디코더 블록은 Pre Norm 구조를 사용한다. LayerNorm이 서브레이어 앞에 온다.

%% Pre-Norm 디코더 블록 내부 흐름
flowchart TD
  input["입력 x<br/>(B, T, D)"]
  ln1["LayerNorm<br/>x_norm = LayerNorm(x)"]
  mha["Causal MHA<br/>attn_out = CausalMHA(x_norm)"]
  add1["x + attn_out<br/>잔차 연결"]
  ln2["LayerNorm<br/>x_norm = LayerNorm(x)"]
  ffn["FFN<br/>ffn_out = FFN(x_norm)"]
  add2["x + ffn_out<br/>잔차 연결"]
  output["출력<br/>(B, T, D)"]
  input --> ln1
  ln1 --> mha
  mha --> add1
  input --> add1
  add1 --> ln2
  ln2 --> ffn
  ffn --> add2
  add1 --> add2
  add2 --> output

6단계로 풀어 쓰면 이렇다.

  1. x_norm = LayerNorm(x) — 입력 정규화
  2. attn_out = CausalMHA(x_norm) — 이전 토큰 정보를 attention으로 혼합
  3. x = x + attn_out — 잔차 연결로 원래 입력을 보존
  4. x_norm = LayerNorm(x) — 다시 정규화
  5. ffn_out = FFN(x_norm) — 토큰별 비선형 변환으로 표현력 확장
  6. x = x + ffn_out — 잔차 연결

입력과 출력의 shape이 동일하다 — (B, T, d_model). 이 덕분에 같은 블록을 여러 번 쌓을 수 있다.

N개 블록을 쌓아 GPT로 만들기

GPT-2 small은 디코더 블록 12개, GPT-3은 96개를 쌓는다. 모든 블록의 구조는 동일하지만 파라미터는 각각 독립이다.

%% GPT 디코더 블록 stack 흐름
flowchart TD
  token["토큰 ID<br/>(B, T)"]
  embedding["InputEmbedding<br/>token + position 임베딩<br/>(B, T, D)"]
  block1["DecoderBlock #1<br/>LN -&gt; MHA -&gt; + -&gt; LN -&gt; FFN -&gt; +"]
  block2["DecoderBlock #2<br/>같은 구조"]
  more["..."]
  block12["DecoderBlock #12<br/>(B, T, D)"]
  final_norm["final_norm<br/>Pre-Norm 보완용 마지막 LayerNorm"]
  lm_head["lm_head<br/>Linear(768, 50257)<br/>(B, T, 50257)"]
  token --> embedding
  embedding --> block1
  block1 --> block2
  block2 --> more
  more --> block12
  block12 --> final_norm
  final_norm --> lm_head

Pre-Norm 구조에서는 각 블록이 LayerNorm → SubLayer → 잔차 순서로 진행한다. 마지막 블록의 출력은 LayerNorm을 거치지 않은 상태이므로, final_norm을 별도로 추가한다. lm_head는 hidden state를 어휘 전체에 대한 다음 토큰 점수(logits)로 변환한다.

왜 shape이 보존되어야 하는가?

블록의 입력과 출력이 (B, T, d_model)로 동일해야 하는 이유는 두 가지다.

  • 잔차 연결 x + SubLayer(x)에서 두 텐서의 shape이 같아야 더할 수 있다.
  • 동일한 블록 구조를 N번 반복하려면 출력이 다음 블록의 입력이 되어야 한다.

이 제약 때문에 Multi-Head Attention의 출력 projection W_O는 (d_model, d_model)이고, FFN의 두 번째 Linear도 (4 * d_model, d_model)으로 차원을 원래대로 되돌린다.

디코더 블록 구조 코드

TransformerBlock — 하나의 디코더 블록

_forward_pre_norm이 GPT의 기본 동작이다. self.ln1(x)로 먼저 정규화하고, attention을 통과한 뒤, 원래 x에 더한다. FFN도 같은 패턴이다.

FeedForward — 토큰별 비선형 변환

d_model을 4 * d_model로 확장했다가 다시 d_model로 줄인다. 이 확장-축소 구조가 각 토큰의 표현에 비선형성을 넣는다. GELU가 ReLU 대신 쓰이는 이유는 해당 문서에서 다룬다.

GPTModel — 블록을 쌓아 완성하기

forward_hidden이 디코더 블록의 반복을 보여준다. embedding으로 토큰 ID를 벡터로 바꾸고, blocks를 순서대로 통과시키고, final_norm으로 정규화한다. 이 hidden state에 lm_head를 적용하면 다음 토큰 logits가 된다.

Shape 추적 — GPT-2 small 기준

설정: vocab_size=50257, d_model=768, n_heads=12, n_layers=12, context_length=1024.

%% GPT-2 small 기준 디코더 블록 shape 추적
flowchart TD
  input["입력 토큰 ID<br/>(2, 16)"]
  embed["token_embedding + pos_embedding<br/>(2, 16, 768)"]
  qkv["DecoderBlock #1 / LN -&gt; MHA<br/>Q, K, V: (2, 12, 16, 64)"]
  attn_residual["+ residual<br/>(2, 16, 768)"]
  ffn["LN -&gt; FFN<br/>linear1: (2, 16, 3072)<br/>GELU<br/>linear2: (2, 16, 768)"]
  block_out["+ residual<br/>(2, 16, 768)"]
  blocks["DecoderBlock #2~12<br/>같은 shape 유지"]
  output["final_norm -&gt; lm_head<br/>final_norm: (2, 16, 768)<br/>logits: (2, 16, 50257)"]
  input --> embed
  embed --> qkv
  qkv --> attn_residual
  attn_residual --> ffn
  ffn --> block_out
  block_out --> blocks
  blocks --> output

모든 디코더 블록에서 텐서 shape (B, T, 768)이 보존된다. 변하는 것은 shape이 아니라 각 토큰 벡터의 내용이다. 블록을 지날 때마다 토큰 간 관계(attention)와 개별 표현(FFN)이 정제된다.

정리

GPT의 디코더 블록은 Causal Self-Attention과 Feed-Forward Network를 잔차 연결과 LayerNorm으로 감싼 구조다. 원래 Transformer 디코더에서 Cross-Attention을 제거한 것이 핵심 차이이며, 이 블록을 N번 쌓고 final_norm + lm_head를 붙이면 GPT 모델이 완성된다. 입출력 shape이 (B, T, d_model)로 동일하기 때문에 같은 블록을 반복 적용할 수 있다.
