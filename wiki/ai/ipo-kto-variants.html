IPO와 KTO 선호 최적화 변형

IPO와 KTO 선호 최적화 변형

한 줄 요약: RLHF의 보상 모델·PPO를 줄이려는 흐름에서 DPO 이후 나온, 데이터 형태와 손실 설계가 다른 IPO·KTO 선호 최적화 변형.

IPO와 KTO는 DPO 이후에 나온 선호 최적화 계열 방법이다. 둘 다 RLHF의 보상 모델과 PPO 파이프라인을 줄이려는 흐름에 있지만, 필요한 데이터 형태와 손실 설계가 다르다.

IPO와 KTO 선호 최적화 변형 구분

DPO는 prompt, chosen, rejected처럼 쌍으로 비교된 선호 데이터를 사용한다. 이 구조는 명확하지만, 실제 데이터 수집에서는 항상 두 답변을 나란히 비교할 수 있는 것은 아니다.

그래서 DPO 주변에는 두 갈래 질문이 생긴다.

  • DPO의 수식적 가정이나 학습 안정성을 다르게 해석할 수 있는가?
  • “이 답변은 좋다/나쁘다”처럼 쌍 비교가 아닌 신호만 있어도 정렬 학습을 할 수 있는가?

IPO는 첫 번째 질문에 가깝고, KTO는 두 번째 질문에 가깝다.

같은 선호 데이터가 있다고 하자

같은 선호 데이터가 있다고 하자.

DPO와 IPO는 이런 선호 쌍을 직접 사용할 수 있다. 핵심은 chosen의 상대 확률은 올리고 rejected의 상대 확률은 낮추되, 참조 모델에서 너무 멀어지지 않게 제한하는 것이다.

KTO는 입력 모양이 조금 다르다. 답변 쌍이 없어도 각 답변에 desirable 또는 undesirable 같은 라벨이 붙어 있으면 학습 신호로 쓸 수 있다.

이 차이는 데이터 수집 비용에 직접 영향을 준다. 쌍 비교는 품질 판단이 선명하지만 만들기 비싸고, 단일 라벨은 모으기 쉽지만 라벨 기준이 흔들리면 학습 신호도 흔들린다.

IPO와 KTO 선호 최적화 변형 선택 기준

  • DPO를 기준선으로 두는 경우
    • 같은 prompt에 대해 선호/비선호 답변 쌍이 충분할 때
    • 구현 복잡도를 낮추면서 RLHF보다 가볍게 시작하고 싶을 때
  • IPO를 검토할 만한 경우
    • DPO와 비슷한 쌍 비교 데이터를 쓰되, 선호 최적화 손실의 해석과 안정성을 더 엄밀하게 비교하고 싶을 때
    • 연구 노트나 실험에서 DPO 계열 손실을 서로 비교할 때
  • KTO를 검토할 만한 경우
    • 쌍 비교보다 good/bad, desirable/undesirable 단일 라벨 데이터가 더 많을 때
    • 답변 두 개를 항상 동시에 만들고 비교하는 비용이 부담될 때
  • 피해야 할 신호
    • 라벨 기준이 작업자마다 크게 다를 때
    • 안전성, 사실성, 말투, 과업 성공 여부가 한 라벨에 뒤섞여 있을 때
    • 아직 SFT 데이터 품질이 낮아 선호 최적화 이전 단계가 흔들릴 때

정리

  1. IPO·KTO는 DPO 이후 나온 선호 최적화 변형으로, RLHF의 보상 모델·PPO를 줄이려는 흐름을 공유한다.
  2. IPO는 DPO와 같은 쌍 비교 데이터를 쓰되 손실의 해석·안정성을 다르게 보고, KTO는 쌍 없이 desirable/undesirable 단일 라벨만으로도 학습한다.
  3. 쌍 비교는 판단이 선명하지만 만들기 비싸고, 단일 라벨은 모으기 쉽지만 라벨 기준이 흔들리면 학습 신호도 흔들린다 — 데이터 형태가 방법 선택을 좌우한다.

직접 확인하려면: 같은 선호 사례를 chosen/rejected 쌍과 response+label 단일 라벨 두 형식으로 각각 적어 보고, 어느 쪽이 라벨링 비용·일관성에 맞는지 비교한다.
