어휘 크기 트레이드오프 — vocab_size가 바꾸는 것들

확인 범위: 이 문서는 vocab_size가 어휘 관련 파라미터와 시퀀스 길이에 미치는 일반 원리와 선택 기준을 설명하고, 제시된 GPT 설정·임베딩·BPE 코드와 수치는 그 관계를 보여 주는 예시로 다룬다. 특정 구현에서의 실제 동작, 버전별 토큰화 결과, 메모리·속도·성능에 관한 판단은 해당 코드와 환경의 실행 기록 및 측정으로 별도 검증해야 한다.

한 줄 요약: vocab_size를 키우면 시퀀스가 짧아지고 의미 단위가 보존되지만, 임베딩 테이블과 출력층이 커진다. 줄이면 그 반대다. LLM 설계에서 vocab_size는 메모리·속도·표현력의 균형점이다.

어휘 크기 트레이드오프 필요성

토크나이저는 텍스트를 정수 ID 시퀀스로 바꾸는 첫 관문이다. 이때 어휘(vocabulary)에 몇 개의 토큰을 넣을지가 vocab_size다. 이 숫자 하나가 모델의 파라미터 수, 시퀀스 길이, OOV(미등록 단어) 비율을 동시에 결정한다. vocab_size를 정하지 않으면 토크나이저를 학습할 수도, 모델을 설계할 수도 없다.

어휘 크기 트레이드오프 계산

세 가지 극단을 먼저 보자

  • 문자 단위 (vocab_size ≈ 수백)
    • “understanding” → 13개 토큰
    • 시퀀스가 길어져 self-attention 비용 O(n²)이 폭발한다.
    • OOV는 거의 없지만, 모델이 “und”와 “under”의 관계를 스스로 학습해야 한다.
  • 단어 단위 (vocab_size ≈ 수십만~수백만)
    • “understanding” → 1개 토큰
    • 시퀀스는 짧지만, 학습 데이터에 없는 단어가 전부 <unk>가 된다.
    • 임베딩 테이블이 거대해진다.
  • 서브워드 BPE (vocab_size ≈ 3만~10만)
    • “understanding” → “under” + “standing” (2개 토큰)
    • 자주 쓰는 조각은 하나로 묶고, 드문 단어는 작은 조각으로 분해한다.
    • GPT-2는 50,257개, GPT-4는 약 100,000개를 사용한다.

vocab_size가 바꾸는 것

vocab_size를 V, 임베딩 차원을 D라 하면:

  • 임베딩 테이블 파라미터 = V × D
  • 출력층(언어 모델 헤드) 파라미터 = V × D
  • 합계 = 2 × V × D

왜 V × D가 두 번 나오는가?

임베딩 테이블은 토큰 ID → 벡터 변환이다. 출력층은 벡터 → 토큰별 logit 변환이다. 둘 다 shape이 (V, D)인 행렬이다. 일부 모델은 임베딩 테이블과 출력층의 가중치를 공유(weight tying)해 V × D로 줄이기도 한다.

GPT-2 기준으로 계산하면:

V = 50,257,  D = 768

임베딩: 50,257 × 768 = 38,597,376 (약 3,860만)
출력층: 50,257 × 768 = 38,597,376
합계:   약 7,720만 파라미터

GPT-2 전체 파라미터: 약 1.24억
→ 어휘 관련 파라미터가 전체의 약 62%

V를 2배로 키우면 이 부분만 7,720만이 더 늘어난다. 작은 모델일수록 vocab_size의 비중이 크다.

시퀀스 길이와의 관계

vocab_size가 크면 더 긴 문자열이 하나의 토큰에 담긴다. 같은 문장도 토큰 수가 줄어든다. self-attention 비용이 O(n²)이므로 시퀀스 길이 n이 줄어드는 효과는 크다.

반대로 vocab_size가 작으면 하나의 단어가 여러 토큰으로 쪼개진다. 모델이 처리해야 할 시퀀스가 길어지고, context window 안에 담을 수 있는 텍스트 양이 줄어든다.

어휘 크기 트레이드오프 코드

실제 GPT 설정에서 vocab_size가 쓰이는 위치

vocab_size는 config의 첫 번째 필드다. 이 값이 정해져야 nn.Embedding(vocab_size, emb_dim)과 출력층 nn.Linear(emb_dim, vocab_size)를 만들 수 있다.

임베딩 테이블에서 vocab_size가 행 수를 결정한다

nn.Embedding(vocab_size, emb_dim)은 (vocab_size, emb_dim) shape의 가중치 행렬을 만든다. 토큰 ID가 이 행렬의 행 번호가 된다. vocab_size = 3,000이면 3,000행, 50,257이면 50,257행이다.

BPE 학습에서 vocab_size가 멈춤 조건이다

self.vocab_size가 while 루프의 종료 조건이다. 이 값이 크면 병합 규칙이 많아지고 어휘가 풍부해진다. 작으면 일찍 멈추고 더 잘게 쪼갠다.

구체적 숫자로 보는 차이

vocab_size = 260 (byte만, 병합 없음)
  "Hello" → [72, 105, 112, 112, 115]  # 5개 토큰

vocab_size = 3,000 (BPE 병합 적용)
  "Hello" → [738]                      # 1개 토큰 (빈도 높은 조각)

vocab_size = 50,257 (GPT-2 tiktoken)
  "Hello" → [15496]                    # 1개 토큰

vocab_size가 커질수록 같은 텍스트의 토큰 수가 줄어든다. 대신 임베딩 테이블이 커진다.

정리

vocab_size는 메모리(임베딩·출력층 크기), 속도(시퀀스 길이), 표현력(OOV 비율)의 균형점이다. 작은 모델에서는 vocab_size가 전체 파라미터의 절반 이상을 차지할 수 있으므로 신중하게 정해야 한다. 현재 주류 LLM은 3만~10만 사이의 BPE 어휘를 사용한다.

  • 선행: BPE가 어휘를 만드는 방법
  • 후속: vocab size로 만든 테이블에서 벡터를 꺼내는 방법
  • 관련: vocab size가 모델 전체에서 차지하는 위치
