T5와 Text-to-Text 패러다임

T5는 번역·요약·분류·질의응답을 모두 “텍스트를 입력받아 텍스트를 출력하는 문제”로 통일한 encoder-decoder Transformer다. 과제마다 다른 출력 헤드를 만들지 않고 같은 인터페이스로 다룬다.

이 통일 방식 덕분에 모델을 바꿔 끼우지 않고도 과제 설명만 바꿔 여러 NLP 문제를 같은 학습 루프로 다룰 수 있다.

T5와 Text-to-Text 패러다임 구분

GPT 계열은 프롬프트 뒤에 다음 토큰을 이어 쓰는 방식이 자연스럽다. BERT 계열은 입력 전체를 양방향으로 읽고 빈칸이나 라벨을 예측하는 데 강하다. T5는 이 둘과 다른 질문을 던진다.

“모든 과제를 같은 형식으로 만들면 어떨까?”

T5는 과제 이름과 입력을 텍스트 prompt처럼 붙이고, 정답도 텍스트로 생성한다.

이렇게 하면 분류도, 번역도, 요약도 모두 같은 모델 인터페이스로 다룰 수 있다.

구조 감각

T5는 encoder-decoder 구조다.

이 점에서 디코더 전용 모델인 GPT와 다르다.

  • GPT
    • 입력과 출력이 하나의 토큰 시퀀스에 이어진다.
    • causal attention으로 다음 토큰을 예측한다.
  • T5
    • 입력과 출력 시퀀스가 분리된다.
    • encoder가 입력을 읽고, decoder가 cross-attention으로 입력 표현을 참고한다.

더 오래된 Seq2Seq 인코더 디코더와도 같은 큰 틀을 공유한다. 차이는 RNN 기반 context vector 대신 Transformer attention과 cross-attention을 쓴다는 점이다.

감성 분류를 생각해 보자

감성 분류를 생각해 보자. 일반 분류 모델은 label id를 출력할 수 있다.

T5식 text-to-text에서는 label도 텍스트가 된다.

요약도 같은 형식이다.

모델 입장에서는 두 작업이 모두 “조건 텍스트를 읽고 target 텍스트를 생성하는 문제”가 된다.

정리

  1. T5의 전환점은 과제 이름을 prompt처럼 붙여 모든 NLP 과제를 “조건 텍스트 → target 텍스트” 하나의 형식으로 통일한 데 있다. 분류 라벨도 positive 같은 텍스트로 생성한다.
  2. 구조는 encoder-decoder라, 입력을 양방향으로 읽는 encoder와 그 출력을 cross-attention으로 참고해 생성하는 decoder가 분리된다. 입력과 출력이 한 시퀀스로 이어지는 GPT(decoder-only)와 다르다.
  3. 더 오래된 Seq2Seq와 같은 큰 틀을 공유하되, RNN context vector 대신 Transformer attention을 쓴다.

감성 분류를 class_id=1 출력과 sentiment: ... → positive 출력 두 형식으로 비교하면, 같은 과제가 텍스트 생성 문제로 바뀌는 과정이 선명해진다.
