llama.cpp 로컬 추론

한 줄 요약: llama.cpp는 GGUF 모델 파일을 로컬 PC나 작은 서버에서 실행해, 클라우드 API 없이 LLM 추론을 해볼 수 있게 해주는 C/C++ 기반 런타임이다.

llama.cpp는 모델을 새로 학습하는 도구가 아니라 이미 학습된 모델을 내 장비에서 돌리는 추론 실행 계층이다. 공식 README 기준으로 목표는 다양한 하드웨어에서 최소 설정으로 LLM 추론을 가능하게 하는 것이다.

llama.cpp 로컬 추론 구분

LLM을 배우다 보면 “모델을 호출한다”는 말이 자주 나온다. 클라우드 API를 쓰면 이 과정이 숨겨지지만, 로컬 추론을 직접 해보면 다음 질문이 눈에 보인다.

  • 모델 파일은 어떤 형식으로 저장되는가?
  • CPU와 GPU 중 어디서 계산하는가?
  • 양자화하면 메모리와 속도가 어떻게 달라지는가?
  • 같은 모델이라도 채팅 UI, CLI, HTTP server 중 어떤 형태로 감쌀 것인가?

llama.cpp는 이 질문을 작은 장비에서 실험하기 좋다. 특히 GGUF 모델 파일, 양자화된 weight, llama-cli, llama-server 같은 이름을 직접 만지게 된다.

로컬 추론 흐름은 보통 이렇게 생긴다

로컬 추론 흐름은 보통 이렇게 생긴다.

명령은 환경마다 조금씩 달라지지만, 구조는 다음처럼 읽으면 된다.

여기서 핵심은 model.gguf다. GGUF는 추론에 필요한 weight와 메타데이터를 담는 파일 형식이고, llama.cpp는 이 파일을 읽어 CPU, Metal, CUDA 같은 backend에서 계산을 실행한다.

서버처럼 쓰고 싶으면 같은 모델을 HTTP API 뒤에 둘 수도 있다.

이렇게 하면 모델 서빙 API 설계에서 다루는 요청/응답 계약과도 이어진다. 다만 llama.cpp 자체는 대규모 multi-tenant 서빙 플랫폼이라기보다, 가볍고 이식성 좋은 로컬 추론 런타임으로 먼저 이해하는 편이 안전하다.

llama.cpp 로컬 추론 사용 기준

llama.cpp가 어울리는 경우는 다음과 같다.

  • 로컬에서 작은 모델을 빠르게 실행해보고 싶다.
  • GPU 없이 CPU나 Apple Silicon으로 추론 실험을 하고 싶다.
  • GGUF 양자화 모델의 메모리 사용량과 품질 차이를 체감하고 싶다.
  • 클라우드 API 없이 오프라인 데모나 개인 실험을 만들고 싶다.

다른 엔진을 먼저 볼 상황도 있다.

  • 대규모 GPU 서버에서 여러 사용자의 요청을 계속 묶어 처리해야 한다.
  • 연속 배칭, 페이지드 어텐션, autoscaling이 핵심 병목이다.
  • 운영 환경에서 Kubernetes, 로드밸런서, 관측성까지 포함한 서빙 구조가 먼저 필요하다.

이 경우에는 추론 엔진 프레임워크 비교, vLLM 아키텍처, ONNX Runtime 추론과 함께 비교해야 한다.

정리

  1. llama.cpp는 모델을 학습하는 도구가 아니라 이미 학습된 GGUF 모델을 로컬 장비에서 실행하는 C/C++ 추론 런타임이다.
  2. GGUF 파일·양자화 weight·llama-cli·llama-server를 직접 만지며, CPU·Metal·CUDA backend에서 토큰 단위 decode를 실행한다.
  3. 가볍고 이식성 좋은 로컬·오프라인 실험에 맞고, 대규모 multi-tenant 서빙은 vLLM 같은 엔진과 비교해야 한다.

직접 확인하려면: 같은 모델의 양자화 수준을 바꿔 가며 llama-cli로 실행해, 메모리 사용량과 출력 품질이 어떻게 달라지는지 체감한다.
