채팅 포맷 템플릿

한 줄 요약: 채팅 포맷 템플릿은 system·user·assistant 역할을 특수 토큰이나 구분자 문자열로 나누고, 대화를 하나의 토큰 시퀀스로 직렬화하는 규칙이다. 같은 대화라도 템플릿이 달라지면 토큰 시퀀스와 loss mask 범위가 달라진다.

채팅 포맷 템플릿이 필요한 장면

명령어 튜닝은 (지시, 정답 답변) 쌍으로 모델을 학습한다. 실제 채팅 데이터에는 지시와 답변뿐 아니라 시스템 프롬프트, 여러 턴의 사용자 메시지, 어시스턴트 응답이 함께 들어간다. 이 구조를 토크나이저가 처리할 하나의 문자열로 바꾸려면 각 역할의 경계를 표시하는 규칙이 필요하다. 이 규칙이 채팅 포맷 템플릿이다.

템플릿은 사용자 입력이 끝나고 어시스턴트 답변이 시작되는 위치를 문자열이나 특수 토큰으로 드러낸다. 이 경계는 학습 데이터에서 손실을 계산할 구간을 정하거나, 추론 입력을 학습 때와 같은 형식으로 구성하는 기준이 된다. 생성 종료 지점을 나타내는 토큰도 템플릿에 포함될 수 있다. 따라서 경계 구분, loss mask, 생성 종료가 실제로 어떻게 처리되는지는 사용하는 템플릿과 학습 코드에 따라 확인해야 한다.

역할과 직렬화 방식

편지에서 “보내는 사람”, “받는 사람”, “본문”을 양식으로 구분하듯이, 채팅 포맷 템플릿은 대화의 “시스템”, “사용자”, “어시스턴트” 역할을 구분한다. 같은 내용도 어떤 양식에 넣느냐에 따라 최종 문자열은 달라진다.

세 역할은 다음과 같이 쓰인다.

  • system — 모델의 행동 규칙을 설정한다. “너는 한국어로만 답하는 도우미다” 같은 지시가 들어간다.
  • user — 사용자의 질문이나 요청이다. 매 턴 바뀐다.
  • assistant — 모델이 생성할 답변이나 이미 생성한 답변이다. 이 문서의 명령어 튜닝 설명에서는 이 구간을 손실 계산 대상으로 본다.

Alpaca 포맷 — 단순한 구분자 방식

Stanford Alpaca(2023)가 도입한 포맷은 system 역할 없이 instruction/input/output 세 필드를 구분자 문자열로 이어 붙인다.

Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
다음 문장을 한 문장으로 요약해라.

### Input:
Transformer는 self-attention을 사용해 sequence를 병렬로 처리한다. RNN과 달리 순차 의존성이 없어 학습 속도가 빠르다.

### Response:
Transformer는 self-attention으로 sequence를 병렬 처리하여 RNN보다 빠르게 학습한다.

### Instruction:, ### Input:, ### Response:가 구분자다. 일반 텍스트 구분자를 사용하므로 별도의 특수 토큰은 필요하지 않다. 이 구조는 단순하지만, 여기 제시된 형태만으로는 멀티턴 대화를 표현하지 않는다.

ChatML 포맷 — 특수 토큰 방식

ChatML은 특수 토큰(<|im_start|>, <|im_end|>)으로 역할 경계를 표시한다.

<|im_start|>system
너는 한국어로만 답하는 도우미다.<|im_end|>
<|im_start|>user
BERT와 GPT의 차이를 설명해줘.<|im_end|>
<|im_start|>assistant
BERT는 encoder-only 구조로 양방향 문맥을 본다. GPT는 decoder-only 구조로 왼쪽에서 오른쪽으로만 읽는다.<|im_end|>

이 형식을 처리하려면 어휘 사전(vocabulary)이 해당 특수 토큰을 인식해야 한다. 멀티턴 대화는 user와 assistant 블록을 번갈아 이어 붙여 표현한다.

Llama 2 포맷

Meta의 Llama 2는 [INST]와 [/INST] 태그로 사용자 입력을 감싼다.

<s>[INST] <<SYS>>
너는 한국어로만 답하는 도우미다.
<</SYS>>

BERT와 GPT의 차이를 설명해줘. [/INST] BERT는 encoder-only, GPT는 decoder-only 구조다. </s>

<s>는 BOS(Begin of Sequence), </s>는 EOS(End of Sequence) 토큰이다. 시스템 프롬프트는 <<SYS>> 안에 넣는다.

같은 대화가 다른 토큰 시퀀스가 되는 과정

같은 대화를 서로 다른 템플릿으로 직렬화하면 토크나이저에 전달되는 문자열부터 달라진다.

입력 대화:
  system: "한국어로 답해라"
  user: "안녕"
  assistant: "안녕하세요"

Alpaca 직렬화:
  "Below is an instruction...\n### Instruction:\n안녕\n### Response:\n안녕하세요"

ChatML 직렬화:
  "<|im_start|>system\n한국어로 답해라<|im_end|>\n<|im_start|>user\n안녕<|im_end|>\n<|im_start|>assistant\n안녕하세요<|im_end|>"

서로 다른 문자열을 토크나이저에 넣으면 token ID 시퀀스도 달라진다. 이 때문에 추론 입력은 학습에 사용한 템플릿에 맞춰 구성해야 한다. 템플릿이 다르면 모델이 학습한 역할 경계와 추론 입력의 경계가 일치하지 않을 수 있다.

Loss mask와 역할 경계

명령어 튜닝에서 assistant 답변만 손실 계산 대상으로 삼으려면 먼저 해당 구간을 식별해야 한다. 역할 경계를 명시한 템플릿은 이 구간을 찾는 기준을 제공한다.

ChatML 토큰 시퀀스:
[<|im_start|>] [system] [\n] [한국어] [로] [답] [해라] [<|im_end|>] [\n]
[<|im_start|>] [user] [\n] [안녕] [<|im_end|>] [\n]
[<|im_start|>] [assistant] [\n] [안녕] [하세요] [<|im_end|>]

loss mask:
  0  0  0  0  0  0  0  0  0      ← system 구간
  0  0  0  0  0  0               ← user 구간
  0  0  0  1  1  1               ← assistant 구간 (답변 토큰만 1)

이 개념도에서는 <|im_start|>assistant\n까지를 역할 헤더로 보고 손실 대상에서 제외한다. 실제 답변 토큰부터 손실을 계산하며, <|im_end|>는 생성 종료를 학습시키기 위해 손실 대상에 포함할 수 있다. 다만 구체적인 마스킹 범위와 종료 토큰 처리는 템플릿과 구현에 따라 달라질 수 있다.

코드에서 확인하는 템플릿 적용 과정

밑바닥 LLM 책 ch07의 코드는 Alpaca 포맷을 format_input으로 구현한다. 템플릿 적용, 데이터셋 직렬화, collate 단계의 손실 제외 처리를 차례로 확인할 수 있다.

Alpaca 템플릿 — 책의 실제 구현

format_input은 고정 서문, ### Instruction, 선택적인 ### Input까지만 만든다. ### Response는 이후 데이터셋 코드에서 정답과 함께 붙인다.

템플릿에 따라 달라지는 문자열

같은 책의 연습 코드에는 Phi-3 스타일 템플릿도 있다. 같은 entry를 받아도 구분자가 다르므로 결과 문자열이 달라진다.

format_input은 Alpaca 구분자를 사용하고 format_input_phi는 Phi-3 스타일 역할 토큰을 사용한다. 학습과 추론에서 같은 역할 경계를 전달하려면 두 단계의 템플릿을 맞춰야 한다.

데이터셋 직렬화 — prompt 뒤에 정답 붙이기

full_text = prompt + response가 prompt 구간과 answer 구간을 하나의 문자열로 직렬화한다. 토크나이저는 이 문자열을 token ID 리스트로 바꾼다.

코드의 손실 제외 처리는 -100 치환

앞의 0/1 loss mask는 손실을 계산할 위치를 설명하는 개념도다. 이 책의 collate 코드는 별도의 배열을 곱하지 않고, 무시할 target을 -100(ignore_index)으로 치환한다. PyTorch cross_entropy는 기본값 ignore_index=-100인 위치를 손실 계산에서 제외한다.

이 코드에서는 첫 패딩, 즉 첫 EOS를 종료 학습을 위한 target으로 남기고 이후 패딩을 -100으로 바꾼다. 여기에 제시된 코드가 직접 보여주는 것은 패딩 위치의 손실 제외다. prompt 구간 마스킹의 상세는 명령어 튜닝에서 다룬다.

shape 변환

%% 채팅 포맷 템플릿의 배치 패딩과 loss mask 흐름
flowchart TD
  batch["가변 길이 토큰 리스트들 (batch)<br/>item_a: [t0 t1 t2] (len 3)<br/>item_b: [t0 t1 t2 t3 t4] (len 5)"]
  padded["패딩 후 고정 길이<br/>padded_a: [t0 t1 t2 pad pad pad]<br/>batch_max_length = 6"]
  shifted["한 칸 시프트<br/>inputs = padded[:-1]<br/>targets = padded[1:]<br/>inputs: (B, T)"]
  loss["손실 계산 입력<br/>model.forward<br/>cross_entropy(ignore_index=-100)<br/>logits: (B, T, V)"]
  batch --> padded
  padded --> shifted
  shifted --> loss

분류 데이터와 비교

밑바닥 LLM 과제의 분류 경로는 NSMC 감성 데이터를 사용한다. 실제 데이터 구축은 src/finetune.py의 make_sentiment_dataset이 담당하며, 내부에서 _read_nsmc_tsv를 호출한다.

이 분류 데이터는 text와 label의 쌍으로 구성된다. 반면 여기서 다룬 명령어 튜닝 데이터는 instruction, input, output을 하나의 시퀀스로 직렬화한다. 두 경로의 차이는 다음과 같다.

분류 데이터:       {"text": "재밌는 영화", "label": 1}
                   → 토큰화 → [리뷰 토큰들] + label 1개

명령어 튜닝 데이터: {"instruction": "요약해라", "input": "...", "output": "..."}
                   → format_input + ### Response → [prompt 토큰들 | answer 토큰들]
                   → collate에서 패딩 -100 치환

학습과 추론에서 확인할 점

채팅 포맷 템플릿은 모델 구조를 바꾸지 않는다. system·user·assistant 역할을 특수 토큰이나 구분자 문자열로 표시하고, 입력 시퀀스의 형식을 정한다. Alpaca 포맷은 ### Instruction:/### Response:를 사용하고 ChatML은 <|im_start|>/<|im_end|>를 사용한다.

템플릿을 검토할 때는 역할 경계가 어떤 문자열이나 토큰으로 표시되는지, 어느 구간이 실제 손실 계산에 포함되는지, 종료 토큰을 어떻게 처리하는지 확인해야 한다. 학습과 추론의 템플릿이 다르면 모델이 학습한 경계와 실제 입력의 경계가 어긋날 수 있다. 채팅 포맷은 명령어 튜닝의 데이터 전처리 단계에서 이 경계를 일관되게 구성하는 규칙이다.
