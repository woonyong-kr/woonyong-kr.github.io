INT8·INT4·FP8 포맷

INT8·INT4·FP8 포맷

한 줄 요약: INT8·INT4·FP8은 모델 숫자를 몇 비트로 어떻게 표현할지 정하는 낮은 비트 포맷으로, 메모리 절감과 품질 손상을 함께 따져 고른다.

INT8, INT4, FP8은 모델 숫자를 몇 비트로, 어떤 방식으로 표현할지 정하는 낮은 비트 숫자 포맷이다.

INT8·INT4·FP8 포맷 구분

LLM 추론에서 모델 가중치는 GPU 메모리와 memory bandwidth를 크게 차지한다. FP16 가중치를 그대로 쓰면 숫자 하나가 16비트, 즉 2바이트다. 낮은 비트 포맷을 쓰면 같은 파라미터 수라도 더 적은 메모리에 담을 수 있다.

다만 비트를 줄인다는 것은 표현할 수 있는 값의 범위나 정밀도를 줄인다는 뜻이다. 그래서 포맷을 고를 때는 “얼마나 작아지는가”와 “모델 품질이 얼마나 흔들리는가”를 같이 봐야 한다.

실제로는 scale, zero point, group metadata가 붙어서 정확히 이 숫자만큼 줄지는 않는다. 그래도 비트 폭이 배포 가능한 모델 크기와 batch 크기를 바꾸는 이유는 이 계산만으로도 보인다.

포맷별 감각

  • INT8
    • 정수 8비트 표현이다.
    • 보통 scale과 zero point를 함께 써서 실수 값을 정수 범위에 맞춘다.
    • INT4보다 품질 손실이 작고, FP16보다 메모리를 줄인다.
  • INT4
    • 정수 4비트 표현이다.
    • 가중치 저장량을 크게 줄일 수 있지만, 양자화 오차가 커진다.
    • GPTQ, AWQ 같은 LLM용 후처리 양자화와 함께 자주 본다.
  • FP8
    • 8비트 부동소수점 표현이다.
    • 정수보다 동적 범위를 다루기 쉽지만, 어떤 FP8 변형과 하드웨어를 쓰는지 확인해야 한다.
    • 학습/추론 가속 하드웨어 지원 여부가 특히 중요하다.

INT와 FP의 차이

INT 계열은 정수 격자에 값을 올린다.

FP 계열은 부호, 지수, 가수처럼 부동소수점 구조를 가진다. 큰 값과 작은 값을 넓은 범위로 표현하기 쉽지만, 같은 8비트 안에서 정밀도와 범위 사이의 선택이 생긴다.

이 말은 즉, INT8/INT4/FP8은 단순히 “몇 비트인가”만의 문제가 아니다. 어떤 kernel이 지원하는지, scale을 어떤 단위로 잡는지, activation까지 낮은 비트로 다룰지에 따라 실제 성능과 품질이 달라진다.

정리

  1. 비트 폭을 줄이면 같은 파라미터 수라도 메모리가 비례해 작아진다. 10억 파라미터 기준 FP16 2.0GB → INT8 1.0GB → INT4 0.5GB다.
  2. INT 계열은 real ≈ scale × (int - zero_point)로 정수 격자에 값을 올리고, FP8은 부호·지수·가수 구조라 동적 범위를 다루기 쉽다. 같은 8비트라도 정밀도와 범위 사이의 선택이 다르다.
  3. 포맷은 “몇 비트인가”만이 아니라 kernel 지원·scale 단위·activation 처리까지 함께 봐야 실제 속도와 품질이 정해진다.

직접 확인하려면 쓰려는 모델의 파라미터 수에 비트 폭을 곱해 대략적 메모리를 추정하고, 메모리는 줄었는데 속도가 안 나면 kernel 지원과 dequantization 비용을 측정해 본다.
