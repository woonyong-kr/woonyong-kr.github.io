도구 사용 함수 호출 (Tool Use Function Calling)

한 줄 요약: 도구 사용과 함수 호출은 LLM이 텍스트 답변만 내는 대신, 외부 함수의 이름과 인자를 구조화해서 요청하게 만드는 방식이다.

함수 호출이 필요한 이유

사용자는 “환율을 조회해서 원화로 계산해 줘”, “이슈를 만들고 링크를 알려 줘”처럼 외부 행동이 필요한 작업을 LLM에 맡긴다. 그러나 LLM은 계산기, 데이터베이스, 파일 시스템, 결제 API를 직접 실행할 수 없다.

함수 호출은 이 간격을 애플리케이션과의 역할 분담으로 메운다. LLM은 직접 실행하는 대신 “어떤 도구를 어떤 인자로 호출해야 하는지”를 JSON 같은 구조로 출력한다. 애플리케이션은 이 요청을 실제 함수 실행으로 바꾸고, 실행 결과를 다시 LLM에 전달한다.

함수 호출의 구성 요소: tool schema, tool call, tool executor, observation

도구를 호출하고 결과를 답변에 반영하려면 다음 요소가 이어져야 한다.

  • tool schema
    • 도구 이름, 설명, 입력 파라미터, 타입을 적은 명세다.
    • LLM은 이 명세를 보고 호출할 도구를 고른다.
  • tool call
    • LLM이 생성한 함수 호출 요청이다.
    • 예: get_weather({"city": "Seoul"})
  • tool executor
    • 실제 코드를 실행하는 애플리케이션 부분이다.
    • API 호출, DB 조회, 파일 읽기 같은 부수 효과는 여기서 일어난다.
  • observation
    • 도구 실행 결과다.
    • 결과를 다시 LLM 컨텍스트에 넣어 최종 답변이나 다음 도구 호출을 만든다.

이 과정에서 LLM은 호출할 도구를 결정하고 인자를 작성한다. 실제 실행은 애플리케이션이 맡는다.

함수 호출의 실제 흐름

도구 호출은 Agent 루프의 행동(Action)에 해당한다. AI Agent는 이 과정을 여러 번 반복하며 목표를 달성한다.

함수 호출 JSON은 실행 결과가 아니라 실행 요청이다

이 JSON은 실행 결과가 아니라 실행 요청이다. 애플리케이션은 search_documents(query, top_k)를 실제로 호출하고, 반환된 문서 목록을 LLM에 다시 넣는다.

읽기 도구와 쓰기 도구의 실행 위험

안전한 설계에서는 위험한 도구를 바로 실행하지 않는다. 도구가 외부 상태를 바꾸는지에 따라 실행 전에 필요한 통제가 달라진다.

  • 읽기 도구
    • 파일 조회, 검색, DB SELECT처럼 부수 효과가 작은 도구다.
  • 쓰기 도구
    • 파일 수정, 이슈 생성, 결제, 메일 발송처럼 외부 상태를 바꾸는 도구다.
    • 사용자 확인, 권한 검사, dry-run이 필요하다.

함수 호출과 MCP의 관계

MCP는 도구와 리소스를 LLM 애플리케이션에 연결하는 표준 프로토콜이다. 함수 호출은 “LLM이 어떤 도구를 부르고 싶은지 표현하는 방식”이고, MCP는 “그 도구를 서버로 노출하고 호출 결과를 주고받는 연결 방식”이다.

따라서 함수 호출과 MCP는 경쟁 관계가 아니다. Agent가 함수 호출을 결정하고, 실제 도구 실행은 MCP 서버가 맡는 구조가 가능하다.
