KV Cache와 추론 최적화

KV Cache와 추론 최적화

한 줄 요약: KV Cache는 이전 토큰의 Key와 Value를 저장해서, 다음 토큰을 만들 때 과거 문맥을 다시 projection하지 않게 하는 추론 최적화다.

KV Cache와 추론 최적화가 비용을 줄이는 자리

Autoregressive 생성은 한 번에 한 토큰씩 다음 토큰을 붙인다. 프롬프트가 길고 생성 토큰이 늘어날수록, 이미 계산한 과거 토큰의 attention 정보를 매번 다시 계산하면 시간이 급격히 늘어난다.

KV Cache는 이 중복을 줄이기 위한 장치다. 이전 토큰들의 Key, Value를 저장해두고, 새 토큰에서는 Query와 새 Key/Value만 계산한다. 이 말은 즉, 긴 답변을 생성할 때 “이미 읽은 문장 전체를 매번 다시 읽는 비용”을 줄이는 것이다.

문제: 중복 계산

Autoregressive 생성은 한 번에 한 토큰씩 생성한다. “Hello world”를 생성한다면:

  1. “Hello” → attention 계산 → “world” 생성
  2. “Hello world” → 전체 attention 재계산 → 다음 토큰 생성

2번째 스텝에서 “Hello”에 대한 K, V는 이미 1번째에서 계산했는데 또 계산한다.

Prefill vs Decode 단계

KV Cache가 있는 추론 엔진은 보통 두 단계를 나눈다.

  • Prefill
    • 프롬프트 전체를 한 번에 처리한다.
    • 각 layer의 K/V cache를 채운다.
  • Decode
    • 새 토큰 하나씩 처리한다.
    • 과거 K/V는 cache에서 읽고, 새 토큰의 K/V만 뒤에 붙인다.

메모리 사용량 계산

KV Cache의 메모리 = 2 × n_layers × seq_len × d_model × bytes_per_param

GPT-3 (175B) 기준:

  • n_layers = 96, d_model = 12288, seq_len = 2048
  • FP16: 2 × 96 × 2048 × 12288 × 2 bytes = 9.6 GB per sequence

이것이 배치 크기를 제한하는 병목이다. 배치 32개면 KV Cache만 307 GB.

최적화 기법

Multi-Query Attention (MQA): K, V head를 1개로 공유. KV Cache 메모리를 n_heads배 줄임.

Grouped-Query Attention (GQA): MQA와 MHA의 중간. K, V head를 n_groups개로 묶음. LLaMA 2 70B가 사용.

복잡도 비교

방식새 토큰 1개 생성전체 n 토큰 생성
캐시 없음O(n × d²)O(n² × d²)
KV CacheO(d²) + O(n × d)O(n × d²)

캐시가 있으면 선형 프로젝션 O(d²)은 새 토큰에만 적용하고, attention 계산 O(n × d)만 전체 시퀀스에 대해 수행한다.

학습 체크포인트

  • Prefill은 프롬프트 전체를 병렬로 처리해 KV cache를 채우는 단계다.
  • Decode는 새 토큰 하나의 Q만 계산하고, 과거 K/V는 캐시에서 읽는다.
  • 긴 컨텍스트와 큰 배치에서는 KV cache 메모리가 가장 먼저 병목이 된다.
  • MQA/GQA는 K/V head를 줄여 캐시 메모리를 절약하는 구조적 선택이다.
  • 로컬 GPT 과제의 기본 generate() 구현은 KV Cache 없이도 먼저 완성할 수 있다.
