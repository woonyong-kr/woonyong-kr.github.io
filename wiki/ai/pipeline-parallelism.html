파이프라인 병렬화 (Pipeline Parallelism)

한 줄 요약: 파이프라인 병렬화는 모델의 층을 여러 GPU에 나누고 작은 microbatch를 순서대로 흘려보낸다. 이를 통해 한 GPU에 들어가지 않는 큰 모델을 학습하면서 뒤쪽 GPU의 유휴 시간을 줄인다.

큰 Transformer 모델은 전체가 한 GPU에 들어가지 않을 수 있다. 파이프라인 병렬화는 이런 모델의 층을 여러 GPU에 나누고, 작은 microbatch를 각 GPU에 순서대로 보내는 분산 학습 방식이다. 데이터 병렬화가 batch를 나눈다면, 파이프라인 병렬화는 Transformer block 묶음을 나눈다.

모델을 GPU별 stage로 나누기

24개 block으로 구성된 모델을 4개 GPU에 나누면 각 GPU가 6개 block씩 맡을 수 있다.

이렇게 나누면 각 GPU가 보관해야 하는 파라미터와 activation이 줄어든다. 그 대신 앞 GPU의 출력이 다음 GPU의 입력이 된다. GPU 0의 출력은 GPU 1로, GPU 1의 출력은 GPU 2로 전달되므로 GPU 사이에는 순차 의존성이 생긴다.

microbatch가 흐르는 과정

batch 하나를 나누지 않고 처리하면 GPU 0이 계산을 마친 뒤 GPU 1이 일하고, 이어서 GPU 2가 일한다. 뒤쪽 GPU는 앞쪽 GPU의 결과가 도착할 때까지 기다려야 한다.

이 대기 시간을 줄이기 위해 큰 batch를 여러 microbatch로 쪼갠다.

forward 흐름만 단순화하면 다음과 같다.

파이프라인의 가운데 구간에서는 네 GPU가 모두 일한다. 하지만 파이프라인이 처음 채워질 때는 뒤쪽 GPU가 기다리고, 마지막 작업이 빠져나갈 때는 앞쪽 GPU부터 할 일이 없어진다. 이렇게 일부 GPU가 쉬는 시간을 pipeline bubble이라고 부른다.

pipeline bubble과 microbatch 수

파이프라인은 여러 단계가 차례로 이어진 구조다. 첫 작업이 마지막 단계에 도착하기 전에는 뒤쪽 단계를 모두 가동할 수 없다. 마지막 작업이 앞쪽 단계를 떠난 뒤에는 앞쪽 단계부터 계산할 대상이 사라진다.

microbatch 수를 늘리면 모든 GPU가 함께 일하는 가운데 구간이 길어진다. 그 결과 전체 작업 시간에서 파이프라인을 채우고 비우는 시간이 차지하는 비율이 줄어든다.

그러나 microbatch를 지나치게 잘게 나누면 각 조각의 계산량이 작아진다. 그러면 통신과 스케줄링 비용이 상대적으로 커질 수 있다. 따라서 microbatch 수는 GPU 활용률뿐 아니라 메모리와 통신 비용도 함께 고려해 정한다.

backward가 더해진 학습 흐름

학습 과정에는 forward뿐 아니라 backward도 있다. 마지막 GPU가 loss에 가까운 출력을 만든 뒤에는 gradient가 forward와 반대 방향으로 흐른다.

실제 파이프라인 스케줄은 GPU의 대기 시간을 줄이기 위해 forward와 backward를 섞는다. 흔히 1F1B라고 부르는 방식은 파이프라인이 어느 정도 채워진 뒤, 한 microbatch의 forward와 다른 microbatch의 backward를 번갈아 배치하는 방향이다.

이 흐름을 이해할 때는 다음 관계를 함께 보면 된다.

  • forward activation은 앞 GPU에서 뒤 GPU로 이동
  • backward gradient는 뒤 GPU에서 앞 GPU로 이동
  • stage 사이 통신이 느리면 GPU가 기다림
  • microbatch가 적으면 bubble이 큼

다른 병렬화 방식과 구분하기

데이터 병렬화, 텐서 병렬화, FSDP/ZeRO와 구분하려면 먼저 무엇을 나누는지 살펴본다.

  • 같은 모델을 여러 GPU에 복제
    • 서로 다른 batch 조각을 처리
    • 마지막에 gradient 평균
  • 한 층 안의 큰 행렬 곱을 여러 GPU에 분할
    • attention이나 FFN 계산 자체를 나눔
    • stage보다 층 내부 통신이 핵심
  • FSDP와 ZeRO Optimizer
    • 데이터 병렬 형태를 유지하면서 메모리 복제를 줄임
  • 파이프라인 병렬화
    • 모델의 block 묶음을 GPU별 stage로 분할
    • microbatch가 stage 사이를 흐름
    • bubble과 stage 균형이 핵심

파이프라인 병렬화가 맞는 조건

파이프라인 병렬화는 모델을 층 단위로 자연스럽게 나눌 수 있을 때 잘 맞는다. 24개 block을 4개 GPU에 6개씩 배치하는 것처럼 stage별 계산량이 비슷하면 각 GPU가 비교적 균형 있게 일한다.

반대로 특정 stage의 계산량만 크거나 stage 사이에서 전송하는 activation이 너무 크면 대기 시간이 늘어난다. 이런 경우에는 텐서 병렬화, FSDP/ZeRO, gradient checkpointing과 함께 사용하는 방안을 검토한다.

병렬화 방식을 판단할 때는 다음 질문을 사용할 수 있다.

  • 모델 전체가 한 GPU에 들어가지 않는다: 파이프라인 병렬화 후보
  • block을 GPU별로 비슷하게 나눌 수 있다: 파이프라인 병렬화에 유리
  • 한 층의 행렬 곱 자체가 너무 크다: 텐서 병렬화 후보
  • 모델 복제와 optimizer state가 부담이다: FSDP/ZeRO 후보
  • batch 처리량만 늘리면 된다: 데이터 병렬화 후보

파이프라인 병렬화에서는 모델의 층 묶음을 GPU별 stage로 나누고 microbatch를 차례로 전달한다. stage 사이의 순차 의존성 때문에 파이프라인을 채우고 비우는 동안 bubble이 생긴다. microbatch 수를 늘리면 이 시간이 차지하는 비율을 줄일 수 있지만, 통신과 스케줄링 비용이 상대적으로 커질 가능성도 함께 고려해야 한다.

stage별 계산량이 비슷할수록 GPU가 균형 있게 일한다. 특정 stage가 무겁거나 activation 전송량이 크다면 다른 병렬화 방식이나 gradient checkpointing과의 조합을 검토할 수 있다.

직접 확인할 때는 microbatch 수를 2개부터 늘리면서 GPU 활용률이 어떻게 달라지는지 살펴본다. 동시에 통신과 스케줄링 비용이 커져 이점이 줄어드는 지점도 확인한다.
