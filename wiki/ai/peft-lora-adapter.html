PEFT — 전체를 바꾸지 않고 거대 모델을 조정하는 효율적 파인튜닝 기법들

PEFT — 전체를 바꾸지 않고 거대 모델을 조정하는 효율적 파인튜닝 기법들

확인 범위: 이 문서는 PEFT의 일반 원리와 LoRA·Adapter·Prefix Tuning의 구조 및 선택 기준을 개념적으로 설명하되, 실제 구현이 확인된 범위는 입력에 제시된 밑바닥 LLM 책의 LoRA 경로뿐이다. 코드별 동작, 파라미터 수와 메모리 절감, 성능 비교에 관한 판단은 해당 모델 설정·하이퍼파라미터·버전·실행 기록과 측정 결과를 별도로 검증해야 한다.

한 줄 요약: PEFT(Parameter-Efficient Fine-Tuning)는 사전학습된 모델의 대부분의 파라미터를 고정하고, 소수의 새 파라미터만 학습하여 파인튜닝 비용을 수십~수백 배 줄이는 기법들의 총칭이다.

PEFT 구분

분류 미세조정이나 명령어 튜닝에서 모델의 모든 파라미터를 업데이트하는 것을 Full Fine-tuning이라 부른다. 작은 모델에서는 문제가 없지만, 모델이 커지면 세 가지 벽에 부딪힌다.

첫째, 메모리다. Adam 옵티마이저는 파라미터당 12바이트(가중치 4B + 기울기 4B + 모멘텀 4B)를 필요로 한다. 밑바닥 LLM 레포의 GPTModel을 GPT-2 small 설정(124M 파라미터)으로 만들면 옵티마이저 상태만 약 1.5GB다. GPT-3(175B)이면 약 2.1TB가 된다.

둘째, 저장이다. 과업마다 모델 전체 사본을 저장해야 한다. 감성 분류, 번역, 요약을 각각 파인튜닝하면 모델 3개를 보관해야 한다.

셋째, 과적합이다. 파인튜닝 데이터가 수천 건밖에 없을 때 수억 개 파라미터를 전부 움직이면 훈련 데이터를 외워버린다.

PEFT는 “파인튜닝에서 실제로 변해야 하는 정보는 전체 파라미터 공간의 극히 일부”라는 관찰에서 출발한다. 대부분을 고정하고 소수만 움직여도 Full Fine-tuning에 가까운 성능이 나온다.

PEFT 흐름

비유

거대한 백과사전(사전학습 모델)을 새 분야에 맞추는 상황이다. Full Fine-tuning은 모든 페이지를 다시 쓰는 것이다. PEFT는 세 가지 전략 중 하나를 택한다.

  • LoRA: 각 페이지 옆에 얇은 포스트잇(저랭크 행렬)을 붙인다. 원본은 그대로 두고 포스트잇만 읽으면 수정 내용을 반영할 수 있다.
  • Adapter: 챕터 사이에 짧은 요약 페이지(작은 신경망)를 끼워넣는다. 원본 챕터는 건드리지 않는다.
  • Prefix Tuning: 책 앞에 “이 분야에서는 이런 관점으로 읽어라”라는 서문(학습 가능한 가상 토큰)을 붙인다. 본문은 바꾸지 않고 읽는 맥락을 조절한다.

세 가지 전략 분류

PEFT 기법은 새 파라미터가 들어가는 위치에 따라 크게 세 가지로 나뉜다.

  • 가중치 분해 (Weight Decomposition)
    • 대표: LoRA, QLoRA
    • 위치: 기존 가중치 행렬 옆에 저랭크 행렬 쌍을 추가
    • 핵심: W_new = W_frozen + B × A (A, B만 학습)
    • 추론 시 원본에 합쳐(merge) 추가 비용 없음
  • 모듈 삽입 (Module Insertion)
    • 대표: Adapter Tuning, Parallel Adapter
    • 위치: Transformer 블록 안에 작은 병목 신경망을 삽입
    • 핵심: x → down_proj(r) → nonlinear → up_proj(d) → x + residual
    • 추론 시 삽입된 모듈이 남아 있어 약간의 지연 추가
  • 입력 조작 (Input Manipulation)
    • 대표: Prefix Tuning, Prompt Tuning, P-Tuning v2
    • 위치: 입력 시퀀스 앞에 학습 가능한 가상 토큰을 삽입
    • 핵심: 모델 가중치를 전혀 건드리지 않고 입력만 바꿈
    • 가상 토큰 수가 적으면 학습 용량이 제한됨

Full Fine-tuning과 PEFT의 파라미터 비교

밑바닥 LLM 레포의 GPTModel(model.py)을 GPT-2 small 설정으로 만들면 파라미터가 다음과 같이 분포한다.

%% GPT-2 small 파라미터 분포
flowchart TD
  model["GPTModel<br/>GPT-2 small: vocab=50257"]
  token["token_embedding<br/>50257 × 768 = 38"]
  position["position_embedding<br/>1024 × 768 = 786"]
  block["TransformerBlock × 12<br/>블록 소계: 약 7"]
  attention["MultiHeadAttention<br/>W_query: 768 × 768 + 768 = 590"]
  ffn["FeedForward<br/>linear1: 768 × 3072 + 3072 = 2"]
  layernorm["LayerNorm × 2<br/>768 × 2 × 2 = 3"]
  final_norm["final_norm<br/>1"]
  lm_head["lm_head<br/>768 x 50257 = 38"]
  model --> token
  model --> position
  model --> block
  model --> final_norm
  model --> lm_head
  block --> attention
  block --> ffn
  block --> layernorm

총 파라미터: weight tying 적용 시 약 1.24억.

이 중 LoRA를 Q, V에만 rank=4로 적용하면 학습 파라미터는 다음과 같다.

LoRA 파라미터 (Q, V만, rank=4):
  A: 768 × 4 = 3,072      per projection
  B: 4 × 768 = 3,072      per projection
  합: 6,144                per projection
  × 2 projections (Q, V)  = 12,288   per layer
  × 12 layers             = 147,456  total

비율: 147,456 / 85,054,464(블록 파라미터) = 0.17%

전체 블록 파라미터의 0.17%만 학습한다. Full Fine-tuning 대비 옵티마이저 메모리가 약 580배 줄어든다.

PEFT 코드

먼저 밑바닥 LLM 레포의 model.py와 attention.py 구조를 기준으로 PEFT 세 가지 전략이 Transformer 블록의 어디에 개입하는지 보여준다. 그다음 책에 실제 구현이 있는 LoRA 경로(부록 E·ch07)의 주입 코드를 그대로 인용한다.

Transformer 블록에서 PEFT가 개입하는 위치

각 PEFT 전략은 이 흐름의 다른 지점에 끼어든다.

%% Transformer 블록에서 PEFT가 개입하는 위치
flowchart TD
  input["입력 x<br/>(B, T, d_model)"]
  prefix["Prefix Tuning<br/>가상 토큰 P개를 x 앞에 연결<br/>x': (B, T + P, d_model)"]
  ln1["LayerNorm"]
  lora["LoRA<br/>W_query"]
  mha["MultiHeadAttention"]
  adapter_attn["Adapter<br/>Attention 출력 뒤에 병목 모듈 삽입<br/>att_out -&gt; down(768-&gt;64) -&gt; ReLU -&gt; up(64-&gt;768) + att_out"]
  residual_ln["Residual + LayerNorm"]
  ffn["FeedForward"]
  adapter_ffn["Adapter<br/>FFN 출력 뒤에도 병목 모듈 삽입 가능"]
  output["output"]
  input --> prefix
  prefix --> ln1
  ln1 --> lora
  lora --> mha
  mha --> adapter_attn
  adapter_attn --> residual_ln
  residual_ln --> ffn
  ffn --> adapter_ffn
  adapter_ffn --> output

파라미터 동결 코드

Full Fine-tuning과 PEFT의 가장 근본적인 차이는 requires_grad 설정이다.

이 상태에서 각 PEFT 기법은 자기 방식으로 소수의 학습 가능한 파라미터를 추가한다. 예를 들어 LoRA는 W_query와 W_value에 저랭크 행렬 쌍을 추가하고, Adapter는 Attention/FFN 뒤에 작은 병목 모듈을 삽입한다.

책의 실제 LoRA 주입 코드

위 동결 흐름은 개념 설명이다. 밑바닥 LLM 책에는 LoRA 전략의 실제 PyTorch 구현이 있다. 부록 E의 LoRALayer/LinearWithLoRA/replace_linear_with_lora 세 함수다. 세 함수의 내부 구현은 LoRA 문서에서 한 줄씩 다룬다. 여기서는 “동결 → 주입 → 학습 파라미터 측정”이 실제 학습 스크립트에서 어떻게 호출되는지만 본다.

named_children을 재귀 순회하며 모든 nn.Linear를 LinearWithLoRA로 바꾼다. 원본 nn.Linear는 래퍼 안에 그대로 살아 있고, 새로 붙은 LoRALayer의 A, B만 autograd 추적 대상이 된다.

순서가 핵심이다. 먼저 requires_grad = False로 전체를 고정해 학습 파라미터를 0으로 만든 뒤, replace_linear_with_lora로 LoRA를 주입한다. 교체로 새로 생긴 A, B만 requires_grad=True 상태이므로 옵티마이저는 이 둘만 업데이트한다. rank=16, alpha=16은 책 ch07 실험에서 쓴 값이다.

LoRA는 이렇게 책에 from-scratch 구현이 있지만, Adapter와 Prefix Tuning은 밑바닥 LLM 책에 직접 구현이 없다. 위 비유와 다이어그램의 Adapter/Prefix 부분은 개념 설명이며, 실제 코드는 LoRA 경로만 책에서 검증된다.

수치 비교

Full FT:        85,054,464 (100%)
Adapter (d=64):  2,379,264 (2.80%)
Prefix (L=20):     368,640 (0.43%)
LoRA (r=4):        147,456 (0.17%)

LoRA가 가장 적은 파라미터로 동작한다. 다만 파라미터 수가 적다고 항상 좋은 것은 아니다. 과업과 데이터 규모에 따라 적절한 용량이 다르다.

과업별 모델 관리

PEFT의 실용적 장점은 하나의 사전학습 모델 위에 여러 과업을 올릴 수 있다는 점이다.

%% 과업별 LoRA 가중치 교체 구조
flowchart LR
  base["사전학습 모델<br/>고정"]
  cls["감성 분류<br/>LoRA 가중치 A_cls"]
  sum["요약<br/>LoRA 가중치 A_sum"]
  tr["번역<br/>LoRA 가중치 A_tr"]
  code["코드 생성<br/>LoRA 가중치 A_code"]
  base --> cls
  base --> sum
  base --> tr
  base --> code

과업을 전환할 때 LoRA 가중치만 교체하면 된다. Full Fine-tuning이면 과업마다 모델 전체(약 500MB)를 보관해야 한다.

정리

PEFT는 사전학습 모델의 대부분을 고정하고 소수의 새 파라미터만 학습하여 파인튜닝 비용을 줄이는 기법들의 총칭이다. 가중치 분해(LoRA), 모듈 삽입(Adapter), 입력 조작(Prefix Tuning) 세 갈래로 나뉜다. 공통 원리는 “파인튜닝에서 실제로 변해야 하는 정보가 전체 가중치 공간의 극히 일부”라는 점이다. GPT-2 small 기준 LoRA(rank=4)는 블록 파라미터의 0.17%만 학습하면서도 Full Fine-tuning에 가까운 성능을 낸다.
