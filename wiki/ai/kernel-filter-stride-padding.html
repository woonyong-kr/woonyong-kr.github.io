커널·필터·스트라이드·패딩 — 합성곱 연산의 네 가지 구성 요소

커널·필터·스트라이드·패딩 — 합성곱 연산의 네 가지 구성 요소

확인 범위: 이 문서는 N=1, C=1인 단일 채널의 최소 사례를 기준으로 커널·필터·스트라이드·패딩의 일반 원리와 출력 크기 계산 기준을 설명하며, 제시된 NumPy 코드는 해당 예시 연산을 보여 주기 위한 것이다. 특정 라이브러리·버전의 구현 동작이나 실제 실행 기록·성능을 검증한 결과는 다루지 않는다.

한 줄 요약: 합성곱 연산은 커널(가중치 행렬)을 입력 위에서 스트라이드만큼 이동하며 원소별 곱의 합을 구하고, 패딩으로 출력 크기를 조절한다.

커널·필터·스트라이드·패딩 구분

CNN 문서에서 합성곱의 전체 그림을 잡았다. 하지만 “필터가 입력 위를 이동한다”는 설명만으로는 실제 출력 크기를 계산하거나, 가장자리 픽셀이 왜 손실되는지, 스트라이드를 바꾸면 무엇이 달라지는지 판단할 수 없다.

이 문서는 합성곱의 네 가지 구성 요소 — 커널, 필터, 스트라이드, 패딩 — 를 하나씩 분리해서 각각이 출력에 미치는 영향을 숫자로 확인한다.

커널·필터·스트라이드·패딩 흐름

커널과 필터

커널(Kernel)은 작은 가중치 행렬이다. 보통 3×3, 5×5처럼 정사각형이다. 입력의 한 영역에 올려놓고 원소별 곱의 합(dot product)을 구하면 출력 한 칸이 나온다.

비유: 커널은 “이 패턴이 있는가?”를 묻는 질문지다. 세로선 감지 커널은 왼쪽 열에 +1, 오른쪽 열에 -1을 넣어 세로 방향 밝기 변화를 측정한다.

필터(Filter)는 입력의 모든 채널에 대응하는 커널 묶음이다. 입력이 RGB 3채널이면 필터 하나는 3×3×3 = 27개 가중치를 가진다. 이 문서에서는 1채널 입력을 기준으로 설명하므로 커널 = 필터로 취급한다. 다채널 구조는 특성 맵·채널 문서에서 다룬다.

합성곱 연산 절차

5×5 입력에 3×3 커널을 stride=1, pad=0으로 적용하는 과정이다.

%% 5×5 입력과 3×3 커널
flowchart LR
  input["입력 (5×5)<br/>1 &#124; 2 &#124; 3 &#124; 0 &#124; 1<br/>0 &#124; 1 &#124; 2 &#124; 3 &#124; 0<br/>3 &#124; 0 &#124; 1 &#124; 2 &#124; 1<br/>2 &#124; 3 &#124; 0 &#124; 1 &#124; 2<br/>1 &#124; 0 &#124; 3 &#124; 0 &#124; 1"]
  kernel["커널 (3×3)<br/>1 &#124; 0 &#124; -1"]
  output["출력 (3×3)<br/>-2 &#124; -2 &#124; 4<br/>2 &#124; -2 &#124; 0<br/>2 &#124; 0 &#124; 0"]
  input --> kernel
  kernel --> output

1단계: 커널을 좌상단 (0,0)에 올린다. 겹치는 3×3 영역과 원소별 곱을 구해 합산한다.

위치 (0,0):
1×1 + 2×0 + 3×(-1) + 0×1 + 1×0 + 2×(-1) + 3×1 + 0×0 + 1×(-1) = -2

2단계: 커널을 오른쪽으로 1칸 이동해 (0,1)에서 같은 연산을 반복한다. 3단계: 더 이상 오른쪽으로 이동할 수 없으면 다음 행으로 내려간다. 4단계: 모든 위치를 순회하면 출력 특징 맵이 완성된다.

5×5 입력에 3×3 커널이면 가로 3칸, 세로 3칸 이동할 수 있으므로 출력은 3×3이다.

출력 크기 공식

입력 크기 H×W, 커널 크기 FH×FW, 패딩 P, 스트라이드 S일 때:

OH = (H + 2P - FH) / S + 1
OW = (W + 2P - FW) / S + 1

왜 패딩이 필요한가?

패딩 없이 합성곱을 반복하면 출력이 점점 줄어든다.

28×28 → 3×3 커널, pad=0 → 26×26
26×26 → 3×3 커널, pad=0 → 24×24
24×24 → 3×3 커널, pad=0 → 22×22

세 층만 쌓아도 28에서 22로 줄었다. 깊은 네트워크에서는 특징 맵이 너무 작아져 정보가 사라진다.

패딩은 입력 가장자리에 0을 채워 크기를 키우는 기법이다. pad=1이면 상하좌우에 0을 한 줄씩 추가한다.

%% pad=1 적용 전후
flowchart LR
  before["패딩 전 (5×5)<br/>1 &#124; 2 &#124; 3 &#124; 0 &#124; 1<br/>0 &#124; 1 &#124; 2 &#124; 3 &#124; 0<br/>3 &#124; 0 &#124; 1 &#124; 2 &#124; 1<br/>2 &#124; 3 &#124; 0 &#124; 1 &#124; 2<br/>1 &#124; 0 &#124; 3 &#124; 0 &#124; 1"]
  after["패딩 후 (7×7)"]
  before --> after

pad=1, 3×3 커널이면:

OH = (5 + 2×1 - 3) / 1 + 1 = 5

입력과 출력 크기가 같다. 이를 “same 패딩”이라 부른다.

패딩의 두 번째 효과: 가장자리 픽셀도 커널 중심에 올 수 있다. 패딩 없이는 모서리 픽셀이 한 번만 연산에 참여하지만, 패딩을 넣으면 여러 번 참여해 가장자리 정보 손실이 줄어든다.

왜 스트라이드를 바꾸는가?

스트라이드(Stride)는 커널이 한 번에 이동하는 칸 수다. stride=1이면 한 칸씩, stride=2이면 두 칸씩 건너뛴다.

28×28 입력, 3×3 커널, pad=1:
  stride=1 → OH = (28 + 2 - 3) / 1 + 1 = 28
  stride=2 → OH = (28 + 2 - 3) / 2 + 1 = 14

stride=2는 출력 크기를 절반으로 줄인다. 풀링 대신 stride=2 합성곱으로 다운샘플링하는 설계도 많다. ResNet이 대표적이다.

주의: (H + 2P - FH)가 S로 나누어떨어지지 않으면 합성곱을 적용할 수 없다. 예를 들어 7×7 입력에 3×3 커널, stride=2, pad=0이면 (7 - 3) / 2 + 1 = 3이 되어 정수다. 하지만 6×6 입력에 같은 설정이면 (6 - 3) / 2 + 1 = 2.5로 성립하지 않는다.

커널·필터·스트라이드·패딩 텐서 코드

합성곱 연산 (순수 numpy 구현)

이 코드가 하는 일: 5×5 입력에 3×3 세로선 감지 커널을 stride=1, pad=0으로 적용해 3×3 출력을 만든다. 양수가 큰 위치는 왼쪽이 밝고 오른쪽이 어두운 세로 경계가 있다는 뜻이다.

패딩과 스트라이드에 따른 출력 크기 비교

이 코드가 하는 일: same 패딩 조건(P = (FH-1)/2)과 stride=2 다운샘플링의 출력 크기를 공식으로 확인한다. 3×3 커널은 pad=1, 5×5 커널은 pad=2가 same 패딩이다.

텐서 shape 변환 요약

%% Conv2D 텐서 shape 변환
flowchart TD
  input["입력<br/>(1, 1, H, W)"]
  conv["Conv2D<br/>커널 FH×FW, pad=P, stride=S"]
  output["출력<br/>(1, 1, OH, OW)"]
  formula["OH = (H + 2P - FH) / S + 1<br/>OW = (W + 2P - FW) / S + 1"]
  input --> conv
  conv --> output
  output --> formula

4차원 텐서 (N, C, H, W) 형태에서 N은 배치 크기, C는 채널 수다. 이 문서는 N=1, C=1인 최소 케이스를 다루었다. 다채널 합성곱은 특성 맵·채널 문서에서 이어진다.

정리

커널은 입력의 지역 패턴을 감지하는 가중치 행렬이다. 커널을 입력 위에서 스트라이드만큼 이동하며 원소별 곱의 합을 구하면 특징 맵 한 칸이 나온다. 패딩은 입력 가장자리에 0을 채워 출력 크기를 보존하거나 가장자리 정보 손실을 줄인다. 출력 크기는 (H + 2P - FH) / S + 1로 결정된다. stride=2는 풀링 없이도 특징 맵을 절반으로 줄일 수 있다.
