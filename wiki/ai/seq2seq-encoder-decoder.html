Seq2Seq 인코더-디코더 — 입력 시퀀스를 출력 시퀀스로 바꾸는 구조

확인 범위: 이 문서는 고정 크기 context vector를 사용하는 기본 RNN 기반 Seq2Seq의 구조, 계산 흐름, 학습·생성 방식의 선택 기준과 정보 병목을 개념적으로 설명한다. 포함된 numpy 코드는 순전파 흐름을 보여 주는 최소 예시일 뿐이며, 특정 라이브러리 버전에서의 실행 결과나 모델 학습·성능 측정을 검증한 자료는 아니다.

한 줄 요약: Seq2Seq는 인코더 RNN이 입력 시퀀스를 하나의 고정 벡터로 압축하고, 디코더 RNN이 그 벡터에서 출력 시퀀스를 한 토큰씩 생성하는 구조다.

Seq2Seq 인코더-디코더 혼동

GRU까지 오면 가변 길이 시퀀스를 읽고 마지막 은닉 상태에 요약을 담을 수 있다. 하지만 한 가지 문제가 남는다. 출력도 가변 길이일 때 어떻게 하는가?

문장 감성분류처럼 “문장 하나 -> label 하나”인 문제라면 입력 시퀀스를 읽고 마지막에 하나의 출력만 만들면 된다. 하지만 번역, 요약, 질의응답처럼 출력도 시퀀스인 문제는 다르다.

예를 들어 기계 번역을 생각해 보자. “I love cats”는 3개 토큰이지만 “나는 고양이를 좋아한다”는 4개 토큰이다. 입력 길이와 출력 길이가 다르다. 단순 RNN은 입력 시점마다 출력 하나를 내놓는 구조이므로 길이가 달라지는 변환을 직접 처리하지 못한다.

Seq2Seq(Sequence-to-Sequence)는 이 문제를 두 단계로 나눠 해결한다.

  • 인코더(Encoder): 입력 시퀀스를 읽어 고정 크기 벡터 하나로 압축한다.
  • 디코더(Decoder): 그 벡터를 초기 상태로 받아 출력 시퀀스를 한 토큰씩 생성한다.

입력을 먼저 전부 읽고, 그다음 출력을 생성하므로 두 시퀀스의 길이가 독립적이다. 이 구조가 없으면 기계 번역, 요약, 대화 생성처럼 입출력 길이가 다른 과제를 RNN으로 풀 수 없다.

Seq2Seq 인코더-디코더 계산

전체 구조: 압축 → 생성

비유하면, 인코더는 외국어 문장을 들으며 머릿속에 “의미 덩어리”를 만드는 통역사다. 디코더는 그 의미 덩어리를 보고 한국어 문장을 한 마디씩 말하는 통역사다. 둘은 의미 덩어리(context vector) 하나로만 소통한다.

  • 입력 시퀀스 출력 시퀀스
  • x_1 x_2 x_3 y_1 y_2 y_3 y_4
  • Enc | | Enc | | Enc | 인코더 RNN
  • (LSTM/GRU)
  • h_1 h_2 h_3
  • context | = h_3 (인코더 마지막 은닉 상태)
  • vector
  • Dec | | Dec | | Dec | | Dec | 디코더 RNN
  • (LSTM/GRU)
  • y_1 y_2 y_3

인코더는 입력 토큰을 순서대로 읽으며 은닉 상태를 갱신한다. 마지막 시점의 은닉 상태 h_T가 입력 시퀀스 전체의 요약이 된다. 이것을 context vector라고 부른다.

디코더는 context vector를 초기 은닉 상태로 받고, 특수 토큰 <SOS>(Start of Sequence)부터 시작해 한 시점에 하나의 토큰을 예측한다. 예측한 토큰을 다음 시점의 입력으로 넣고, <EOS>(End of Sequence)가 나올 때까지 반복한다.

인코더의 수식

인코더는 일반적인 RNN(또는 LSTM/GRU) 시간 전개와 같다.

f_enc가 Vanilla RNN이면 tanh(W_xh · x_t + W_hh · h_{t-1} + b)이고, LSTM이면 gate를 거친 (h_t, c_t) 쌍이다. 인코더의 출력은 마지막 시점의 은닉 상태다.

LSTM을 쓸 경우 cell state c_T^enc도 함께 넘긴다.

디코더의 수식

디코더도 RNN이지만, 초기 상태를 인코더의 context vector에서 받는다.

  • s_t: 디코더의 은닉 상태
  • y_{t-1}: 이전 시점에 생성한 (또는 정답으로 넣어준) 토큰의 임베딩
  • W_out: 은닉 상태를 어휘 크기(vocab_size)로 변환하는 projection

디코더의 각 시점에서 softmax 출력이 어휘 전체에 대한 확률 분포가 된다. 가장 높은 확률의 토큰을 고르거나(greedy), 확률에 따라 샘플링한다.

정보 병목 (Information Bottleneck)

이 구조의 가장 큰 약점은 context vector가 고정 크기라는 점이다.

입력이 5개 토큰이든 100개 토큰이든 hidden_dim 크기의 벡터 하나에 전부 담아야 한다. Vanilla RNN의 장기 의존성 문제와 본질적으로 같다. 입력이 길어지면 앞쪽 정보가 희석된다.

이 병목이 Bahdanau Attention이 등장한 직접적인 동기다. “하나의 고정 벡터 대신, 디코더가 매 시점마다 인코더의 모든 시점을 다시 참조하면 어떨까?”라는 질문이 attention의 출발점이다.

Teacher Forcing vs 자기회귀 생성

학습할 때 디코더의 입력을 무엇으로 넣느냐에 두 가지 선택이 있다.

  • 자기회귀(autoregressive) 방식: 디코더가 이전 시점에 예측한 토큰을 다음 입력으로 넣는다. 초기에 모델이 엉뚱한 토큰을 예측하면 이후 시점도 연쇄적으로 틀린다.
  • Teacher Forcing: 이전 시점의 예측 대신 정답 토큰을 디코더 입력으로 넣는다. 학습이 안정적이고 빠르지만, 추론 시에는 정답이 없으므로 학습과 추론 사이에 괴리가 생긴다.

실전에서는 Teacher Forcing으로 학습하되, 일정 확률로 자기 예측을 섞는 Scheduled Sampling을 쓰기도 한다.

Seq2Seq 인코더-디코더 텐서 코드

LSTM 기반 Seq2Seq의 최소 구현을 numpy로 작성한다. 학습 가능한 가중치는 랜덤으로 초기화하고, 순전파 흐름만 추적한다.

인코더와 디코더 순전파를 실행한다.

이 코드에서 중요한 지점은 h_dec = context 한 줄이다. 인코더가 4개 토큰을 읽어 만든 context vector 하나가 디코더의 유일한 입력 시퀀스 정보다. 디코더는 이후 자신의 은닉 상태만 갱신하며 출력을 생성한다.

텐서 흐름 정리

  • 인코더:
  • src_tokens: [2, 5, 7, 3]
  • embedding[tok]: (embed_dim,) × 4시점
  • RNN 시간 전개: h_0 → h_1 → h_2 → h_3 → h_4
  • context = h_4
  • 디코더: ↓
  • h_dec_0 = context → (hidden_dim,)
  • → RNN → logits → softmax → y_1
  • y_1 → RNN → logits → softmax → y_2
  • y_2 → RNN → logits → softmax → y_3
  • … → (종료)

정리

Seq2Seq는 인코더-디코더 구조로 가변 길이 입력을 가변 길이 출력으로 변환한다. 인코더가 입력을 고정 크기 context vector로 압축하고, 디코더가 이 벡터에서 출력을 한 토큰씩 생성한다. 기계 번역, 요약, 대화 생성의 기반 구조다.

가장 큰 한계는 정보 병목이다. 아무리 긴 입력이라도 하나의 벡터에 압축해야 하므로, 입력이 길어지면 앞쪽 정보가 사라진다. 이 병목을 해결하기 위해 디코더가 매 시점마다 인코더의 모든 시점을 다시 참조하는 Bahdanau Attention이 등장한다.
