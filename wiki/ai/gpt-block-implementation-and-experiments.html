GPT 블록 구현과 실험 가능한 구조

확인 범위: 이 문서는 GPT 블록의 구성과 학습되는 가중치, 순전파 흐름, 폭·깊이·초기화 같은 설정의 선택 기준을 개념과 제시된 코드 구조 수준에서 설명한다. 특정 구현의 정확한 동작이나 버전별 차이, 학습 안정성 및 성능은 실제 코드와 실행 환경, 실행 기록, 측정 결과를 별도로 확인해야 한다.

한 줄 요약: GPT는 토크나이저, 임베딩, 여러 개의 Transformer block, 출력 head를 연결한 큰 신경망이다. 각 block은 독립된 가중치를 가지며, config를 통해 모델의 폭과 깊이를 바꾸어 실험할 수 있다.

GPT 블록 구현과 실험 가능한 구조 혼동

GPT 구조 문서에서는 Transformer 디코더를 쌓아 언어 모델을 만드는 전체 구조를 살펴봤다. 그러나 “block을 N개 쌓는다”는 설명만으로는 실제 코드에서 어떤 값이 학습되는 가중치이고, 어떤 설정을 config로 바꿀 수 있는지 판단하기 어렵다.

이 문서에서는 GPT의 순전파 흐름을 코드 수준으로 따라가며 각 부품의 가중치를 확인하고, config를 바꾸어 실험할 수 있는 구조를 정리한다.

GPT 블록 구현과 실험 가능한 구조 차이

전체 흐름

GPT의 순전파는 다음과 같은 큰 흐름으로 진행된다.

%% GPT 순전파 흐름
flowchart TD
  text["텍스트"]
  encode["tokenizer.encode()"]
  ids["token IDs"]
  embed["token embedding + position embedding"]
  x["input embedding X"]
  b1["Transformer Block 1"]
  b2["Transformer Block 2"]
  more["..."]
  bn["Transformer Block N"]
  head["vocab head"]
  logits["logits"]
  softmax["softmax"]
  prob["다음 토큰 확률"]
  text --> encode
  encode --> ids
  ids --> embed
  embed --> x
  x --> b1
  b1 --> b2
  b2 --> more
  more --> bn
  bn --> head
  head --> logits
  logits --> softmax
  softmax --> prob

학습할 때는 마지막에 얻은 확률과 실제 다음 토큰을 비교해 loss를 계산한 뒤 역전파를 시작한다. 따라서 앞에서 살펴본 attention, residual, layernorm, feed forward는 모두 loss를 계산하기 전의 순전파 과정에 해당한다.

Transformer block은 은닉층인가

일반적인 신경망의 은닉층은 보통 입력 -> Linear -> activation -> 출력으로 이해한다. GPT에서는 이 역할을 여러 개의 Transformer block이 맡는다.

따라서 직관적으로는 Transformer block = GPT에서 쓰는 큰 은닉층 단위라고 이해해도 된다. 다만 하나의 block 안에는 여러 부품이 함께 들어 있다.

%% Transformer block과 은닉층 비교
flowchart LR
  simple_in["입력"]
  simple_linear["Linear"]
  simple_activation["activation"]
  simple_out["출력"]
  emb["입력 임베딩 X"]
  block1["Transformer Block 1"]
  block2["Transformer Block 2"]
  more["..."]
  blockn["Transformer Block N"]
  att["1. Multi-Head Causal Self-Attention"]
  add1["2. Residual Add"]
  ln1["3. LayerNorm"]
  ffn["4. Feed Forward Network"]
  add2["5. Residual Add"]
  ln2["6. LayerNorm"]
  simple_in --> simple_linear
  simple_linear --> simple_activation
  simple_activation --> simple_out
  emb --> block1
  block1 --> block2
  block2 --> more
  more --> blockn
  att --> add1
  add1 --> ln1
  ln1 --> ffn
  ffn --> add2
  add2 --> ln2

즉 Transformer block은 일반적인 은닉층 하나보다 훨씬 큰 계산 단위이므로, 보통 layer 또는 block이라고 부른다.

block마다 가중치는 별개다

Block 1과 Block 2는 같은 형태의 계산을 수행하지만, 가중치를 공유하지는 않는다.

이름과 구조는 비슷해도 실제 파라미터는 block마다 다르다. 보통 처음에는 무작위로 초기화되며, 이후 다음 토큰 예측 loss를 줄이는 방향으로 역전파와 optimizer가 각 파라미터를 조금씩 조정한다.

초기화와 시드

개발 단계에서는 다음 두 방식을 모두 지원하면 실험하기 편리하다.

시드가 필요한 이유는 모델 구조가 올바른지 확인할 때마다 값이 달라지면 결과를 비교하기 어렵기 때문이다. 반면 실제 실험에서는 여러 seed를 사용해 모델이 우연한 초기값에 지나치게 의존하는지도 확인할 수 있다.

폭과 깊이

LLM의 크기를 키우는 축은 크게 두 가지로 나눌 수 있다.

폭이 커지면 한 토큰 벡터가 더 많은 정보를 담을 수 있고, 하나의 block 안에서 더 다양한 특징을 계산할 수 있다.

깊이가 커지면 같은 문장을 여러 단계에 걸쳐 반복해서 해석할 수 있다.

두 축의 차이를 정리하면 다음과 같다.

폭과 깊이는 모두 모델의 표현력을 높이지만, 파라미터 수와 메모리 사용량, 연산량, 필요한 데이터도 함께 늘어난다.

토크나이저 학습과 모델 학습은 다르다

BPE 토크나이저를 학습하는 과정은 딥러닝의 역전파 과정과 다르다.

%% 토크나이저 학습과 모델 학습 흐름
flowchart LR
  corpus["대량 텍스트"]
  bytes["byte sequence"]
  pair["자주 등장하는 인접 pair 계산"]
  merge["가장 자주 등장한 pair를 merge rule로 추가"]
  vocab["vocab과 merge rule 완성"]
  text["텍스트"]
  encode["tokenizer.encode()"]
  ids["token IDs"]
  pairs["input/target pair"]
  forward["GPT 순전파"]
  loss["다음 토큰 예측 loss"]
  backward["역전파"]
  update["모델 파라미터 업데이트"]
  corpus --> bytes
  bytes --> pair
  pair --> merge
  merge --> vocab
  text --> encode
  encode --> ids
  ids --> pairs
  pairs --> forward
  forward --> loss
  loss --> backward
  backward --> update

이 과정에서 만들어지는 것은 vocab + merge rules다. 이는 텍스트를 token ID sequence로 변환하기 위한 규칙이다.

모델 학습은 그다음 단계다. 위 그림의 두 번째 흐름처럼 token ID를 input/target pair로 만든 뒤, GPT 순전파와 loss 계산, 역전파, 파라미터 업데이트를 차례로 수행한다.

토크나이저가 만든 ID는 정답 벡터가 아니라 토큰을 구별하기 위한 식별자다. 모델은 이 ID를 이용해 embedding table에서 벡터를 조회하고, 다음 토큰 ID를 맞히도록 학습한다.

Dataset과 DataLoader

다음 토큰 예측에서는 input과 target의 위치를 한 칸 어긋나게 구성한다.

이 구조를 사용하면 모델은 sequence의 각 위치에서 다음 토큰을 맞히는 문제를 동시에 풀 수 있다.

stride는 학습 샘플을 자를 때 문맥을 얼마나 겹치게 할지 결정한다.

이 값이 과적합을 직접 해결하지는 않지만, 같은 문맥을 반복해서 학습하는 정도를 조절하는 데 사용할 수 있다.

Input embedding

토큰 ID 자체는 모델이 의미 있는 계산을 수행하기에 적합한 값이 아니다. 따라서 embedding table에서 해당 ID에 대응하는 벡터를 조회한다.

그다음 두 벡터를 더해 self-attention에 입력할 벡터를 만든다.

같은 token ID는 같은 token embedding을 조회한다. 하지만 위치가 다르면 position embedding도 달라지므로, 최종 input embedding 역시 달라진다.

Attention 가중치

Self-attention에서는 각 입력 벡터 x_i로부터 Q, K, V를 만든다.

W_Q, W_K, W_V는 모두 학습되는 가중치다. 처음에는 무작위 값으로 시작하고, 다음 토큰 예측 과정에서 역전파를 통해 조정된다.

attention score는 query와 key를 비교해 계산한다.

GPT는 미래 토큰을 참조하면 안 되므로 causal mask를 적용한다.

그다음 softmax를 적용해 attention weight를 구한다.

마지막으로 value를 가중합해 context vector를 만든다.

여기서 Z는 단일 값이 아니라 sequence 전체의 context vector를 담은 matrix다.

Multi-head attention

Multi-head attention은 같은 입력 X를 여러 attention head에 병렬로 전달하는 구조다.

%% Multi-head attention 개요
flowchart LR
  input["입력 X"]
  h0["head 0"]
  h1["head 1"]
  h2["head 2"]
  h3["head 3"]
  z0["Z0"]
  z1["Z1"]
  z2["Z2"]
  z3["Z3"]
  concat["concat(Z0, Z1, Z2, Z3)"]
  wo["@ W_O"]
  output["MultiHeadOutput"]
  input --> h0
  h0 --> z0
  z0 --> concat
  input --> h1
  h1 --> z1
  z1 --> concat
  input --> h2
  h2 --> z2
  z2 --> concat
  input --> h3
  h3 --> z3
  z3 --> concat
  concat --> wo
  wo --> output

각 head는 자신만의 W_Q, W_K, W_V를 가진다. 사람이 각 head에 head 0은 문법, head 1은 반복 단어 같은 의미를 직접 지정하는 것은 아니다. 다만 서로 다른 가중치로 학습을 시작하므로, 학습 과정에서 서로 다른 패턴에 민감해질 수 있다.

각 head의 출력은 concat한 뒤 W_O를 거쳐 다시 model dimension에 맞춘다.

W_O 역시 별도로 학습되는 가중치다.

Residual과 LayerNorm

입력이 Attention을 통과하면 원래 정보가 변형된다. 이때 원래 입력을 다시 더해 정보가 이어질 경로를 만든다.

이 구조가 residual connection이다. 그 의미는 다음과 같이 이해할 수 있다.

이후 LayerNorm을 적용한다.

LayerNorm은 서로 다른 토큰을 섞지 않는다. 대신 각 토큰 벡터 내부의 dimension 값들을 평균 0, 분산 1에 가까워지도록 조정해 다음 계산이 안정적으로 진행되도록 돕는다.

gamma, beta도 학습되는 파라미터다. 손으로 계산하며 원리를 확인할 때는 이해를 돕기 위해 gamma=1, beta=0으로 두는 것이 일반적이다.

LayerNorm이 두 번 사용된다면 gamma와 beta도 각각 두 벌이 필요하다.

Feed Forward Network

FFN은 attention처럼 토큰 사이의 관계를 비교하지 않는다. 각 token vector를 서로 독립적으로 동일한 MLP에 통과시킨다.

이는 일반적인 딥러닝에서 말하는 W, b와 같은 개념이다.

그렇다면 왜 3 -> 8 -> 3처럼 차원을 넓혔다가 다시 줄일까?

FFN의 중간 폭이 커지면 각 토큰 위치에서 더 많은 특징을 표현할 수 있다. 대신 파라미터 수와 연산량도 함께 늘어난다.

두 번째 residual과 block 출력

FFN을 통과한 뒤에도 residual과 LayerNorm을 한 번 더 적용한다.

이 값이 Transformer block 하나의 최종 출력이다.

다음 block이 있다면 이 출력은 다음과 같이 전달된다.

현재 block이 마지막이라면 다음 단계로 이어진다.

GPT 블록 구현과 실험 가능한 구조 코드

GPTConfig — 실험 가능한 설정

이 설정을 사용하면 같은 코드로 작은 디버그 모델(emb_dim=32, n_heads=4, n_layers=2)과 큰 실험 모델(emb_dim=256, n_heads=8, n_layers=8)을 만들 수 있다. 핵심은 모델 구조를 하드코딩하지 않고 config를 통해 폭과 깊이를 조절하는 것이다.

GPTModel — 전체 순전파

nn.ModuleList를 사용해 block을 쌓으며, 각 block은 독립된 가중치를 가진다. lm_head는 hidden state를 vocab 크기의 logits로 변환하는 마지막 선형 계층이다.

targets가 주어지면 cross entropy loss도 함께 반환한다. reshape(-1, ...)은 batch 차원과 sequence 차원을 하나로 펼쳐 loss를 계산하기 위한 과정이다.

TransformerBlock — Pre-LN과 Post-LN

norm_first=True이면 Pre-LN 구조가 된다. Pre-LN은 깊은 모델의 학습을 더 안정적으로 만드는 구조다. 자세한 비교는 Pre Norm vs Post Norm 문서에서 확인할 수 있다.

FeedForward — 확장 후 축소

mult=4이면 d_model=256을 기준으로 256 → 1024 → 256 변환이 이루어진다. 좁은 벡터를 더 넓은 특징 공간으로 펼치고 GELU로 비선형성을 더한 다음, 원래 차원으로 되돌린다. residual connection에서 두 값을 더하려면 입출력 차원이 같아야 한다.

MultiHeadAttention — head 분리와 결합

W_query, W_key, W_value는 각각 (d_model, d_model) 크기다. 따라서 head 수가 달라져도 총 파라미터 수는 같다. head별 분리는 view와 transpose를 사용해 텐서의 shape만 바꾸는 과정이다.

텐서 shape이 변하는 흐름은 다음과 같다.

%% MultiHeadAttention 텐서 shape 변환 흐름
flowchart TD
  input["입력 X: (B, T, d_model)"]
  q["W_query(X)<br/>(B, T, d_model)"]
  k["W_key(X)<br/>(B, T, d_model)"]
  v["W_value(X)<br/>(B, T, d_model)"]
  qs["split Q<br/>(B, H, T, head_dim)"]
  ks["split K<br/>(B, H, T, head_dim)"]
  vs["split V<br/>(B, H, T, head_dim)"]
  score["score = Q @ K^T / sqrt(head_dim)<br/>(B, H, T, T)"]
  context["context = weights @ V<br/>(B, H, T, head_dim)"]
  merge["merge<br/>(B, T, d_model)"]
  proj["out_proj<br/>(B, T, d_model)"]
  mask["mask"]
  input --> q
  q --> qs
  qs --> score
  input --> k
  k --> ks
  ks --> score
  input --> v
  v --> vs
  vs --> context
  score --> mask
  mask --> context
  context --> merge
  merge --> proj

가중치 초기화

모든 Linear와 Embedding을 N(0, 0.02) 정규분포로 초기화한다. model.apply(init_gpt_weights)를 사용하면 이 초기화를 모델 전체에 한 번에 적용할 수 있다. init_std를 config에서 바꿀 수 있으므로, 초기화 설정이 학습에 미치는 영향도 실험할 수 있다.

정리

GPT는 InputEmbedding → TransformerBlock × N → LayerNorm → Linear(lm_head) 구조다. 각 block은 Multi-Head Attention, FFN, LayerNorm, Residual을 위한 독립된 가중치를 가진다. GPTConfig에서 emb_dim, n_heads, n_layers, ffn_mult, norm_first 등을 바꾸면 같은 코드로 규모와 구조가 다른 모델을 실험할 수 있다. 폭(emb_dim)은 한 토큰이 표현할 수 있는 정보와 특징의 범위를 넓히고, 깊이(n_layers)는 입력을 반복해서 해석하는 단계의 수를 늘린다.
