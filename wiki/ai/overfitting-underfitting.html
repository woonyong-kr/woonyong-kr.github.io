과적합과 과소적합

과적합과 과소적합

확인 범위: 과적합·과소적합의 진단 원리와 대응 방향을 설명한다. 실제 일반화 성능은 데이터·코드·실행 측정으로 검증해야 한다.

한 줄 요약: 과적합(Overfitting)은 모델이 훈련 데이터의 노이즈까지 외워 새 데이터에서 실패하는 것이고, 과소적합(Underfitting)은 모델이 데이터의 패턴조차 잡지 못하는 것이다.

과적합과 과소적합 문제

신경망 학습의 목표는 훈련 데이터에서 본 패턴을 새로운 데이터에도 적용하는 것이다. 이것을 일반화(Generalization)라고 한다. 일반화에 실패하는 원인은 두 가지다.

  • 과소적합: 모델의 용량(Capacity)이 부족하거나 학습이 덜 되어, 훈련 데이터의 규칙성조차 포착하지 못한다. 훈련 손실도 높고 검증 손실도 높다.
  • 과적합: 모델의 용량이 과하거나 학습 데이터가 부족하여, 훈련 데이터의 노이즈와 우연한 패턴까지 암기한다. 훈련 손실은 낮지만 검증 손실은 올라간다.

과소적합과 과적합의 경계에서 일반화 성능이 최대가 된다. 이 문서는 두 실패 모드를 구분하는 기준과 감지 방법을 다루고, 해결 기법은 정규화 기법에서 이어간다.

과적합과 과소적합 차이

모델 용량과 일반화

모델 용량은 모델이 표현할 수 있는 함수의 복잡도를 뜻한다. 신경망에서는 주로 은닉층의 수와 각 층의 뉴런 수가 용량을 결정한다.

  • 용량이 너무 낮으면: 데이터의 곡선을 직선으로만 그으려는 것과 같다. 어떤 데이터를 줘도 패턴을 놓친다. → 과소적합.
  • 용량이 너무 높으면: 데이터 점 하나하나를 지나는 복잡한 곡선을 그린다. 훈련 데이터에는 완벽하지만 새 데이터에서 크게 빗나간다. → 과적합.

편향-분산 트레이드오프

과소적합과 과적합의 관계를 수학적으로 정리한 것이 편향-분산 분해(Bias-Variance Decomposition)다.

총 오차 = 편향² + 분산 + 줄일 수 없는 노이즈

편향(Bias)  : 모델이 단순해서 정답 함수와 평균적으로 벗어나는 크기
분산(Variance): 학습 데이터가 바뀔 때 모델 예측이 흔들리는 크기
  • 편향이 높으면(High Bias) → 과소적합. 모델이 너무 단순하다.
  • 분산이 높으면(High Variance) → 과적합. 모델이 훈련 데이터에 과하게 맞춰져 있다.

용량을 늘리면 편향은 줄지만 분산은 커진다. 둘의 합이 최소인 지점이 최적의 모델 복잡도다.

손실 곡선으로 구분하기

과적합과 과소적합을 감지하는 가장 직접적인 방법은 훈련 손실(Train Loss)과 검증 손실(Validation Loss)을 에폭마다 추적하는 것이다.

과소적합: 훈련 손실 자체가 충분히 내려가지 않는다.

판단 기준을 정리하면 다음과 같다.

  • 훈련 손실 높음 + 검증 손실 높음 → 과소적합. 모델 용량을 늘리거나 학습을 더 한다.
  • 훈련 손실 낮음 + 검증 손실 높음 → 과적합. 정규화를 강화하거나 데이터를 늘린다.
  • 훈련 손실 낮음 + 검증 손실 낮음 → 적절한 적합. 일반화가 잘 된 상태다.

과적합과 과소적합 코드

밑바닥 딥러닝1의 NeuralNetwork 클래스는 hidden_sizes, use_dropout, use_batchnorm 파라미터로 모델 용량과 정규화를 조절한다. 이 설정을 바꾸면 과소적합 → 적절한 적합 → 과적합을 직접 관찰할 수 있다.

모델 구성으로 용량 조절

훈련과 검증 손실 비교

model.forward(x, train=True)와 model.forward(x, train=False)의 차이가 핵심이다. train=True에서는 Dropout이 뉴런을 끄고 BatchNorm이 배치 통계를 쓴다. train=False에서는 Dropout이 비활성화되고 BatchNorm이 누적된 running 통계를 쓴다. 검증 손실은 반드시 train=False로 계산해야 학습 중의 노이즈 없이 모델의 실제 성능을 본다.

Dropout의 과적합 억제 효과

drop_ratio=0.5이면 학습 때마다 뉴런의 절반이 꺼진다. 매 배치마다 다른 부분 네트워크(sub-network)로 학습하는 셈이다. 특정 뉴런 조합에 의존하지 못하게 하여 모델이 훈련 데이터의 우연한 패턴을 외우기 어렵게 만든다.

파라미터 수와 데이터 수의 관계

과적합이 일어나는 근본 원인은 모델이 표현할 수 있는 자유도가 데이터가 제공하는 정보량보다 큰 것이다. 수치로 대략 감을 잡으면:

MNIST 데이터:
  훈련 샘플 60,000장, 입력 차원 784, 출력 클래스 10

과소적합 모델 (hidden=[16]):
  파라미터 수 ≈ 12,864개
  파라미터당 데이터 비율 = 60,000 / 12,864 ≈ 4.7
  → 데이터가 파라미터보다 충분히 많지만 용량이 부족하다.

과적합 모델 (hidden=[512, 256], 정규화 없음):
  파라미터 수 ≈ 534,538개
  파라미터당 데이터 비율 = 60,000 / 534,538 ≈ 0.11
  → 파라미터가 데이터보다 9배 많다. 제약 없이 외울 수 있다.

이 비율 자체가 과적합 여부를 결정하지는 않는다. Dropout과 BatchNorm 같은 정규화를 쓰면 큰 모델도 일반화할 수 있다. 하지만 정규화 없이 파라미터가 데이터보다 훨씬 많으면 과적합 위험이 높아진다는 직관을 준다.

정리

  • 과소적합은 모델 용량 부족이나 학습 부족으로, 훈련 손실 자체가 높은 상태다.
  • 과적합은 모델이 훈련 데이터를 암기한 상태로, 훈련 손실은 낮지만 검증 손실이 벌어진다.
  • 훈련 손실과 검증 손실의 간격(gap)이 과적합의 직접적인 신호다.
  • 용량을 늘리되 정규화 기법으로 제약을 거는 것이 실전적인 해법이다.
  • 다음 문서: Dropout, Weight Decay와 L2 정규화, Early Stopping과 체크포인팅
