에이전트 평가 (Agent Evaluation)

한 줄 요약: 에이전트 평가는 최종 답변만이 아니라 계획·도구 선택·인자 작성·실패 복구·안전성까지 과정과 결과를 함께 보는 기준으로, 실제 시스템을 바꾸는 도구가 붙은 Agent는 정답률뿐 아니라 비용과 지연 시간도 측정해야 한다.

Agent가 여러 단계를 거쳐 과업을 수행하면 최종 답변만으로는 실행 품질을 판단하기 어렵다. 답변이 맞아 보여도 중간에 위험한 도구를 잘못 호출하거나 불필요한 단계를 반복했을 수 있다. 실패를 적절히 복구하지 못했지만 운 좋게 목표에 도달한 경우도 있다.

에이전트 평가는 이런 실행 과정을 계획, 도구 선택, 인자 작성, 실패 복구, 최종 목표 달성으로 나누어 살핀다. 실제 시스템을 바꾸는 도구가 연결된 Agent라면 정답률에 더해 안전성, 비용, 지연 시간도 함께 측정해야 한다.

과정 평가가 비용을 드러내는 지점

최종 결과만 확인하면 같은 과업을 위해 불필요한 단계를 반복했는지 알기 어렵다. 도구 호출 trace를 함께 보면 과업 완수 여부뿐 아니라 어떤 도구를 골랐고, 어떤 인자를 전달했으며, 실패 뒤에 어떻게 대응했는지 확인할 수 있다. 이 과정에서 반복 실행과 관련된 비용과 지연 시간도 평가 대상이 된다.

Agent 평가 예시: 날씨 확인 후 Slack 메시지 보내기

이 과업에서는 메시지가 전송되었다는 결과만으로 성공을 판단하지 않는다. 비가 올 때만 보냈는지 확인하는 task success와 함께, 날씨 API와 슬랙 API의 선택, city·channel·message 인자의 유효성, API 실패 뒤의 복구, 전송 전 확인이 필요한 상황의 구분까지 살펴야 한다.

LLM·RAG·Agent 평가의 차이

평가 대상에 따라 확인할 범위가 달라진다.

  • 일반 LLM 평가는 한 번의 답변 품질을 본다.
  • RAG 평가는 검색 근거와 답변의 연결을 본다.
  • Agent 평가는 도구 호출 trace와 과업 완수를 본다.
