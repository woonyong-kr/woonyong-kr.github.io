그래디언트 누적 — 작은 배치를 쌓아 큰 배치 효과를 만드는 기법

범위: 이 문서는 그래디언트 누적의 일반 원리와 구현 시 선택 기준을 설명하고, PyTorch 코드는 특정 학습 루프에 적용한 예시로 제시한다. 수학적 동등성은 본문의 가정과 NumPy 예제로 확인하지만, 특정 PyTorch 버전의 실제 실행 기록이나 모델 학습 결과, 메모리·성능 측정을 검증한 문서는 아니다.

그래디언트 누적은 여러 미니배치의 gradient를 더한 뒤 한 번에 파라미터를 업데이트해, GPU 메모리에 올리지 못하는 큰 배치 크기의 효과를 얻는 방법이다.

그래디언트 누적 문제

LLM 학습에서 배치 크기(batch size)는 학습 안정성과 수렴 속도에 큰 영향을 준다. 배치가 클수록 gradient 추정이 안정적이고 loss landscape에서 더 정확한 방향으로 이동한다.

문제는 GPU 메모리다. GPT-2 small(124M 파라미터)도 fp32로 올리면 약 500MB다. 여기에 optimizer 상태(Adam은 파라미터의 2배), activation 캐시, gradient 저장까지 더하면 메모리가 빠르게 찬다. 배치 크기 32로 학습하고 싶은데 GPU 메모리에는 배치 4개밖에 못 올리는 상황이 흔하다.

그래디언트 누적은 이 문제를 소프트웨어적으로 해결한다. 배치 4개씩 8번 forward-backward를 돌리되, 매번 파라미터를 업데이트하지 않고 gradient만 쌓아둔다. 8번째에 한 번에 업데이트하면 배치 32로 학습한 것과 수학적으로 동일한 효과를 얻는다.

작은 배치로 큰 배치를 흉내내기

일반 학습 루프 vs 그래디언트 누적 — 비교

일반 학습 루프에서는 미니배치 하나마다 optimizer.step()을 호출한다.

미니배치 1 → forward → loss → backward → optimizer.step() → zero_grad()
미니배치 2 → forward → loss → backward → optimizer.step() → zero_grad()
미니배치 3 → forward → loss → backward → optimizer.step() → zero_grad()
미니배치 4 → forward → loss → backward → optimizer.step() → zero_grad()

매 배치마다 파라미터가 업데이트된다. 배치 크기가 실질적인 gradient 추정 단위다.

그래디언트 누적(accumulation_steps=4)에서는:

미니배치 1 → forward → loss/4 → backward → gradient 쌓임
미니배치 2 → forward → loss/4 → backward → gradient 쌓임
미니배치 3 → forward → loss/4 → backward → gradient 쌓임
미니배치 4 → forward → loss/4 → backward → optimizer.step() → zero_grad()

4번의 backward에서 gradient가 누적되고, 4번째에 한 번 업데이트한다. loss를 accumulation_steps로 나누는 이유는 gradient의 평균을 구하기 위해서다.

왜 수학적으로 동일한가?

SGD의 파라미터 업데이트 공식:

theta = theta - lr * (1/N) * sum(grad_i)

N은 배치 크기다. 배치 32의 gradient 평균은:

(1/32) * sum(grad_1 ... grad_32)

이것을 배치 4씩 8번으로 나누면:

(1/8) * sum(
    (1/4) * sum(grad_1 ... grad_4),
    (1/4) * sum(grad_5 ... grad_8),
    ...
    (1/4) * sum(grad_29 ... grad_32)
)
= (1/32) * sum(grad_1 ... grad_32)

결과가 같다. gradient를 쌓아서 나중에 평균 내는 것과 한 번에 큰 배치로 평균 내는 것은 동일한 연산이다.

loss를 나누는 이유

backward()는 gradient를 더한다(accumulate). PyTorch에서 zero_grad()를 호출하지 않으면 gradient가 계속 쌓인다. 이 동작을 그대로 이용한다.

단, loss를 accumulation_steps로 나눠야 한다. 나누지 않으면 gradient가 합으로 커져 학습률을 사실상 accumulation_steps배 키운 것과 같아진다.

loss = loss_fn(output, target) / accumulation_steps  # 나눠야 평균
loss.backward()  # gradient가 누적됨

그래디언트 누적 코드

PyTorch 학습 루프에 그래디언트 누적 적용하기

책의 GPT 학습 루프(train.py → train_model)를 기반으로 gradient accumulation을 적용한 코드다.

이 루프에서 확인할 부분은 다섯 줄이다.

  • (3) loss / accumulation_steps — gradient 평균을 보장한다.
  • (4) loss.backward() — zero_grad() 없이 호출하면 gradient가 기존 값에 더해진다.
  • (5) accumulation_steps번째마다 업데이트 조건을 건다.
  • (6) optimizer.step() — 누적된 gradient로 파라미터를 한 번 업데이트한다.
  • (7) zero_grad() — 다음 누적 사이클을 위해 gradient를 0으로 리셋한다.

일반 학습 루프와 비교하면, 바뀌는 코드는 loss 나누기 한 줄과 if문 세 줄뿐이다.

수치로 확인: 일반 학습 vs 누적

numpy로 gradient가 실제로 동일한지 확인한다.

grad_full과 grad_accum이 동일하다. loss를 accumulation_steps로 나눈 뒤 backward하면 gradient 평균이 보존된다는 것을 수치적으로 보여준다.

주의 사항

  • 그래디언트 클리핑은 step 직전에 한다. 누적 중간에 clip하면 방향이 왜곡된다.
  • BatchNorm은 미니배치 단위로 통계를 계산한다. 누적해도 실효 배치 크기가 커지는 효과는 BatchNorm 통계에는 적용되지 않는다. LayerNorm은 샘플 단위이므로 영향 없다.
  • 학습 끝에 남는 배치 처리. 전체 데이터가 accumulation_steps로 나누어떨어지지 않으면 마지막에 남은 배치에서도 step을 호출해야 한다.

정리

그래디언트 누적은 GPU 메모리 제약을 우회하여 큰 배치 효과를 얻는 기법이다. loss를 accumulation_steps로 나누면 gradient 평균이 유지되고, 작은 미니배치 N번의 누적이 큰 배치 1번과 수학적으로 같아진다. 구현에서는 일반 학습 루프에 loss 나누기 한 줄과 update 시점을 고르는 if문만 추가하면 된다.
