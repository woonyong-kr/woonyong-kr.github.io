미니 GPT 노트북

미니 GPT 노트북은 작은 데이터와 모델을 사용해 token id, batch, logits, loss가 이어지는 과정을 직접 확인하는 실습이다.

큰 모델을 훈련하기 전에는 각 단계의 텐서 shape가 서로 맞물리는지 먼저 확인해야 한다. 이 노트북에서는 토큰화부터 생성까지 한 화면에서 차례로 따라가며 shape가 어긋나는 지점을 빠르게 찾는다.

미니 GPT 노트북 문제

LLM 구현 파이프라인은 전체 순서를 보여주지만, 읽는 데 그치면 각 단계가 실제 텐서의 모양과 값으로 어떻게 이어지는지 놓치기 쉽다.

이 실습은 높은 성능을 내는 훈련보다 다음 흐름이 끊김 없이 이어지는지 눈으로 확인하는 데 초점을 둔다.

가장 작은 실습에서 먼저 고정할 값

가장 작은 실습을 시작할 때는 다음 값을 먼저 고정한다.

이 설정은 성능을 측정하기보다 각 단계의 연결을 확인하는 데 맞춘 값이다. 실행할 때도 loss 숫자 하나에 집중하기보다 shape의 흐름이 자연스럽게 이어지는지 먼저 살펴본다.

이 네 항목이 서로 맞으면 Dataset과 DataLoader, 모델 forward, Cross Entropy Loss가 같은 문제를 다루고 있다는 뜻이다.

미니 GPT 노트북 선택 기준

  • 실습이 성공한 상태
    • 입력과 target이 한 칸씩 밀린 next-token prediction 구조다.
    • loss가 scalar로 계산된다.
    • 짧게 학습한 뒤 loss가 대체로 내려가는 흐름을 보인다.
    • 생성 결과가 완벽하지 않더라도 prompt 뒤에 token을 이어 붙인다.
  • 실습이 잘못된 상태
    • logits의 마지막 차원이 vocab_size가 아니다.
    • target shape이 logits의 token 위치와 맞지 않는다.
    • loss의 감소 여부를 살피기 전에 loss 자체가 계산되지 않는다.
    • 생성 루프가 매번 전체 sequence를 다시 입력하는 방식인지, 마지막 token만 입력하는 방식인지 구분하지 못한다.

정리

  1. 미니 GPT 노트북은 토큰화→batch→embedding→Transformer→logits→loss→생성의 흐름이 끊기지 않는지 작은 모델로 직접 확인하는 실습이다.
  2. 성능 평가보다 shape의 흐름을 확인하는 데 초점을 두며, logits의 마지막 차원이 vocab_size인지와 target이 한 칸 밀린 구조인지를 중점적으로 살펴본다.
  3. loss가 scalar로 계산되고 짧은 학습 뒤 대체로 내려간다면 Dataset·forward·Cross-Entropy가 같은 문제를 다루고 있다는 신호다.

직접 확인하려면 input_ids·targets·logits·loss의 shape를 출력하고, 각각 (batch, ctx)·(batch, ctx)·(batch, ctx, vocab)·scalar와 일치하는지 살펴본다.
