에이전트 메모리 시스템 (Agent Memory System)

에이전트 메모리는 대화 전체를 오래 저장하는 기능이 아니다. 다음 작업에서 다시 쓸 가치가 있는 상태·지식·절차를 소유자와 수명주기에 맞춰 보존하고, 필요할 때 근거와 함께 꺼내는 구조다.

기억할 대상과 소유 위치

  1. 현재 대화 — 방금 받은 제약, 도구 결과, 남은 단계다. 세션이 끝나면 그대로 장기 지식이 되지 않는다.
  2. 작업 상태 — 완료 단계, 실패 원인, checkpoint와 receipt다. 재실행과 복구를 위해 runtime이 소유한다.
  3. 재사용 절차 — trigger, 실행 단계, 안전 경계와 검증을 갖춘 Skill이다. woon-skills catalog가 소유한다.
  4. 문서 지식 — source에서 확인한 claim을 사람이 읽는 문서로 합친 것이다. wiki/가 유일한 정본이다.
  5. 코드 관계 — symbol, file, call, impact path는 실제 Git repository가 정본이며 graph와 index는 파생물이다.
  6. 사용자 선호 — 반복해서 적용할 안정된 기준만 장기 기억 후보가 된다. 신원·커리어·민감 정보는 local-only 경계를 유지한다.

수명주기

후보에는 출처, 시점, privacy, content hash와 용도를 붙인다. 기존 정본과 같은 사실이면 새 문서를 만들지 않고 병합한다. 근거가 없거나 다시 쓸 가치가 없으면 폐기한다. 승격된 뒤에도 바뀔 수 있는 사실은 검증 시점과 교체 조건을 남긴다.

정본과 검색 메모리를 구분하는 이유

검색 index와 vector store는 빠르게 찾기 위한 cache다. cache가 사라져도 source·claim·page에서 다시 만들 수 있어야 한다. session log는 왜 그런 판단을 했는지 추적하는 이력이지, 현재 설명을 대신하는 문서가 아니다. 이 경계를 지켜야 오래된 대화와 중복 요약이 현재 Wiki를 덮지 않는다.

원문에서 흡수한 운영 기준

2026-08-28에 TencentDB-Agent-Memory, llm-wiki, claude-obsidian의 사용 문서를 Wiki 내부 source snapshot으로 보존했다. TencentDB-Agent-Memory에서 확인한 Chat Memory·Skill·Wiki·CodeGraph 분리는 기억의 종류별 소유권을 나누는 기준으로 흡수했다. llm-wiki의 명시적 promotion은 후보가 자동으로 정본이 되지 않게 하는 gate로, claude-obsidian의 stale hash와 recovery는 변경된 입력에 과거 판정을 재사용하지 않는 규칙으로 흡수했다.

Woon은 개인 local-only 시스템이므로 원문 구현의 Redis, vector DB, server와 team panel은 추가하지 않는다. 검색 속도를 위한 저장소가 필요해도 source·claim·page에서 지울 수 있는 cache로만 둔다. 외부 도구가 없어져도 이 문서의 소유권 표와 수명주기만으로 같은 판단을 다시 할 수 있어야 한다.

기억을 네 종류로 나눈다

TencentDB-Agent-Memory의 Core·Knowledge·Proxy 분리를 Woon 경계에 맞춰 다시 해석하면 기억은 네 종류다.

  • 대화 기억은 현재 작업에서 필요한 사용자 발화와 결정 맥락이다. 수명이 짧고 자동으로 사실이 되지 않는다.
  • 작업 상태는 cursor, checkpoint, 실패와 재시도처럼 실행을 이어 가는 정보다. 완료 영수증 전에는 진전으로 확정하지 않는다.
  • 절차 기억은 skill과 정책처럼 반복 작업의 방법을 소유한다. 같은 절차를 Wiki 본문에 복제하지 않는다.
  • 지식 기억은 source·claim·page·receipt를 거친 Wiki다. 장기 검색과 설명은 여기서만 제공한다.

CodeGraph와 검색 index는 원본 코드와 Wiki에서 다시 만들 수 있는 파생물이다. 별도 memory server를 정본으로 두지 않는다.

오래 남길 기억을 압축하는 조건

기억을 많이 저장하는 것보다 다시 쓸 질문이 있는지가 중요하다. 같은 판단을 반복하는가, 원문을 다시 찾기 어려운가, 다음 행동이나 설명을 바꾸는가를 확인한다. 세 조건에 답하지 못하면 session log를 정본으로 승격하지 않는다. 승격할 때도 원문 전체가 아니라 근거 범위와 재사용 가능한 판단을 분리한다.

기억을 읽고 쓰는 최소 계약

  1. 쓰기 전에 현재 대화인지, 재실행 상태인지, 장기 지식인지 소유자를 먼저 고른다.
  2. 기존 정본을 검색해 같은 질문이면 새 문서를 만들지 않고 병합한다.
  3. source hash와 target revision이 달라지면 이전 승인을 재사용하지 않는다.
  4. 검색 index가 없어져도 source·claim·page와 receipt에서 다시 만들 수 있어야 한다.
  5. 오래된 사실은 삭제 흔적 없이 덮지 않고 후속 revision과 교체 이유를 남긴다.
  6. 최종 답변은 기억의 존재보다 현재 source가 주장을 실제로 뒷받침하는지 확인한다.
