Transformer Explainer로 보는 GPT 어텐션 흐름

Transformer Explainer로 보는 GPT 어텐션 흐름

한 줄 요약: Transformer Explainer 시각화 앱으로 GPT가 token을 숫자로 바꾸고 attention으로 서로를 읽어 다음 token 확률을 고르는 흐름을, 수식보다 화면을 따라가며 잡는다.

Transformer Explainer는 GPT 계열 언어 모델이 다음 token을 고르는 과정을 화면 위에서 따라가게 해 주는 시각화 앱이다. 이 문서는 수식을 먼저 외우기보다, 앱 화면을 보면서 “문장이 숫자가 되고, attention으로 서로를 읽고, 확률 분포로 다음 token을 고른다”는 흐름을 잡기 위한 안내서다.

원문 앱은 Transformer Explainer이고, 로컬 실행 방법은 Transformer Explainer 로컬 실행 가이드에 따로 정리했다.

Transformer Explainer로 혼동

Self-Attention은 처음 보면 Q, K, V, softmax, mask, head, projection 같은 단어가 한꺼번에 나온다. 각각을 따로 배우면 이해한 것 같지만, 실제 모델 안에서 어느 순서로 이어지는지 놓치기 쉽다.

이 앱을 쓰면 다음 세 가지가 한 화면에서 연결된다.

  • token 흐름
    • 입력 문장이 token으로 잘리고, token마다 세로 벡터가 생긴다.
  • attention 흐름
    • 각 token이 Query, Key, Value로 갈라지고, Query가 Key들을 비교해 어느 Value를 얼마나 읽을지 정한다.
  • 생성 흐름
    • 마지막 표현이 logits와 probability로 바뀌고, temperature와 top-k/top-p 설정에 따라 다음 token 후보가 달라진다.

읽고 나면 다음 판단 기준이 생겨야 한다.

  • “Attention이 단어를 고르는 것”이 아니라 “각 token 표현을 다른 token 표현의 가중합으로 다시 쓰는 것”임을 설명할 수 있다.
  • GPT에서 causal mask가 필요한 이유를 “미래 token을 보면 다음 token 예측 문제가 망가진다”는 기준으로 말할 수 있다.
  • temperature, top-k, top-p가 모델 구조가 아니라 마지막 sampling 정책임을 구분할 수 있다.

앱에서 핵심 링크

처음 열면 예제 문장이 들어가 있다. 예를 들어 Data visualization empowers users to 같은 문장이 들어가면 오른쪽 확률 목록에 visualize, create, see 같은 다음 token 후보가 나타난다.

화면은 왼쪽에서 오른쪽으로 읽는다.

  • 입력 token
    • Data, visualization, em, powers, users, to처럼 token 단위가 세로로 놓인다.
    • empowers가 em과 powers처럼 쪼개질 수 있다는 점이 중요하다. 모델은 사람이 보는 단어가 아니라 tokenizer가 만든 token을 본다.
  • Embedding
    • token ID가 embedding table의 한 행을 고른다.
    • 앱에서는 token마다 옅은 세로 벡터로 나타난다.
  • Transformer Block
    • GPT-2 small 기준으로 12개 block이 반복된다.
    • 앱 화면은 첫 block을 크게 보여 주고, 나머지 block이 뒤에 이어진다는 구조를 보여 준다.
  • Multi-head Self Attention
    • 한 block 안에서 Query, Key, Value, attention matrix, output이 연결된다.
    • Head 1 of 12처럼 head를 바꿔 볼 수 있다.
  • MLP
    • attention으로 섞인 token 표현을 token별 비선형 변환으로 다시 다듬는다.
  • Probabilities
    • 마지막 token 위치의 표현이 vocabulary 전체에 대한 점수로 바뀐다.
    • 점수가 softmax와 sampling 설정을 지나 다음 token 후보 목록이 된다.

한 장 흐름

이 흐름에서 중요한 점은 “다음 token을 고르는 것”이 마지막 단계라는 것이다. Attention은 중간 표현을 만드는 장치이고, sampling은 마지막 확률 분포에서 실제 token을 고르는 정책이다.

Q, K, V를 화면에서 읽기

Attention을 처음 배울 때 가장 좋은 비유는 부드러운 사전 조회다.

  • Query
    • 지금 token이 “나는 어떤 정보를 찾고 싶은가?”를 나타낸다.
  • Key
    • 각 token이 “나는 어떤 정보로 검색될 수 있는가?”를 나타낸다.
  • Value
    • 실제로 읽혀서 섞일 내용이다.

앱에서는 Query가 파란색, Key가 붉은색, Value가 초록색 계열로 표시된다. 이 색은 장식이 아니라 “비교할 것”과 “읽어 올 것”을 구분하기 위한 시각 신호다.

계산은 다음 순서다.

여기서 Q @ K^T는 “현재 token의 질문과 각 token의 검색 키가 얼마나 맞는가”를 점수로 만든다. softmax는 그 점수를 합이 1인 참고 비율로 바꾼다. 마지막 attention weight @ V는 그 비율만큼 Value를 섞어 새 표현을 만든다.

Self-Attention이 보는 것

Self-Attention에서 “self”는 같은 문장 안의 token들이 서로를 본다는 뜻이다.

예를 들어 The cat sat on the를 넣으면 마지막 the는 다음에 올 단어를 예측하기 위해 앞의 cat, sat, on 같은 token들을 참고한다. 앱 검증에서는 이 입력 뒤에 couch, floor, bed 같은 후보가 나타났다.

이때 attention은 사람이 해석하는 “진짜 의미 관계”와 완전히 같은 것은 아니다. 모델 내부의 학습된 통계적 관계다. 그래도 시각화가 유용한 이유는 token 간 정보가 어떤 방향으로 흐르는지 감각을 만들기 때문이다.

Multi-Head가 필요한 이유

하나의 attention head만 있으면 한 종류의 관계를 강하게 볼 수 있다. 하지만 문장 안에는 여러 관계가 동시에 있다.

  • 가까운 위치 관계
    • 바로 앞 token이나 phrase 경계를 본다.
  • 문법 관계
    • 주어와 동사, 수식어와 피수식어를 본다.
  • 의미 관계
    • 같은 주제에 속하는 token들을 본다.
  • 생성 힌트
    • 마지막 token이 다음 token 후보를 고르는 데 필요한 문맥을 본다.

GPT-2 small은 한 block에 12개 attention head를 둔다. 앱의 Head 1 of 12 컨트롤은 같은 입력이라도 head마다 attention pattern이 달라질 수 있음을 보여 준다.

Causal Mask를 놓치면 안 되는 이유

GPT는 다음 token 예측 모델이다. 그래서 학습 중 각 위치는 자기보다 오른쪽의 token을 보면 안 된다.

attention score 행렬로 보면 오른쪽 위 삼각형이 미래다. 그 영역을 -inf로 채우면 softmax 뒤 확률이 0이 된다. 이것이 Causal Attention이다.

앱에서 “Masked Self Attention” 페이지나 attention matrix를 볼 때는 미래 위치가 열리지 않는다는 점을 기준으로 보면 된다.

MLP와 Probabilities

Attention은 token들이 서로를 읽게 한다. 하지만 attention만으로는 충분하지 않다. 각 token 위치의 표현을 더 복잡하게 변환하는 token별 MLP가 뒤에 붙는다.

Transformer block 하나는 대략 다음 두 일을 한다.

  • Attention
    • token 사이 정보를 섞는다.
  • MLP
    • 각 token 위치의 표현을 비선형으로 다듬는다.

12개 block을 지난 뒤 마지막 위치의 hidden state가 LM head로 들어간다. LM head는 vocabulary의 모든 token에 점수를 준다. 이 점수가 logits다.

앱 오른쪽의 probability bar는 이 마지막 단계를 보여 준다. 이때 표시되는 후보는 모델이 “문장 전체를 이해했다”는 증거라기보다, 현재 문맥과 학습된 분포에서 높은 점수를 받은 token들이다.

Temperature, Top-k, Top-p

이 세 가지는 Transformer block 내부가 아니라 출력 sampling 정책이다.

  • temperature
    • logits를 softmax에 넣기 전에 나누는 값이다.
    • 낮으면 높은 점수가 더 압도적이 되어 예측이 보수적이다.
    • 높으면 확률 분포가 평평해져 덜 뻔한 token도 나올 수 있다.
  • top-k
    • 확률이 높은 token k개만 후보로 남긴다.
    • 앱 기본값은 top-k, k=5다.
  • top-p
    • 누적 확률이 p에 도달할 때까지 후보를 남긴다.
    • 후보 개수가 문맥마다 달라질 수 있다.

이 값들을 바꿔도 Q/K/V 계산이나 Transformer block 구조가 바뀌지는 않는다. 마지막 token 선택 방식이 달라진다.

다시 해볼 실습 루틴

앱을 열고 다음 순서로 반복하면 좋다.

  • 1회차: 예제로 전체 흐름 보기
    • Examples에서 예제 문장을 고른다.
    • Embedding, Attention, MLP, Probabilities가 왼쪽에서 오른쪽으로 이어지는지만 본다.
  • 2회차: Attention만 보기
    • Attention 영역을 확대한다.
    • Query, Key, Value가 어디에서 나오고 어디로 들어가는지 본다.
    • Head를 바꿔 attention pattern이 달라지는지 본다.
  • 3회차: 다음 token 예측 보기
    • probability list에서 가장 높은 token과 낮은 token을 비교한다.
    • temperature를 낮추거나 높여 확률 막대가 어떻게 달라지는지 본다.
  • 4회차: 직접 입력하기
    • 모델 로딩이 끝나 Generate 버튼이 활성화될 때까지 기다린다.
    • 12단어 이하의 짧은 문장을 입력한다.
    • Generate를 눌러 마지막 token 후보가 어떻게 바뀌는지 본다.

헷갈리기 쉬운 점

  • token과 단어는 다르다.
    • empowers가 em, powers처럼 나뉠 수 있다.
  • attention weight는 설명 가능성의 전부가 아니다.
    • 어떤 token을 많이 봤다고 해서 항상 사람이 말하는 이유와 일치하지는 않는다.
  • MLP는 부가 장식이 아니다.
    • Attention으로 섞인 표현을 각 위치에서 다시 강하게 변환하는 핵심 구성이다.
  • sampling은 모델 구조가 아니다.
    • temperature, top-k, top-p는 마지막 후보 선택 정책이다.
  • 앱은 학습 도구다.
    • GPT-2 small을 브라우저에서 보여 주기 위한 시각화이므로, 최신 대규모 LLM의 모든 최적화와 같다고 보면 안 된다.

정리

  1. Attention은 단어를 직접 고르는 장치가 아니라, 각 token 표현을 다른 token 표현의 가중합(softmax(Q@K^T/sqrt(d_k)) @ V)으로 다시 쓰는 장치다. 다음 token을 고르는 일은 맨 마지막 단계다.
  2. GPT는 다음 token 예측 모델이라, causal mask로 attention 행렬의 오른쪽 위 삼각형(미래)을 -inf로 막아 softmax 뒤 확률을 0으로 만든다.
  3. temperature·top-k·top-p는 Transformer block 내부 구조가 아니라, 마지막 logits에서 token을 고르는 sampling 정책이다.

직접 확인하려면 앱에서 같은 입력의 temperature만 바꿔, Q/K/V 계산과 attention pattern은 그대로인데 확률 막대만 달라지는지 본다. 아래 체크포인트로 스스로 설명해 본다.

Transformer Explainer로 점검

  • Q, K, V를 “질문, 검색 키, 읽을 값”으로 설명할 수 있는가?
  • Q @ K^T / sqrt(d_k) 뒤에 softmax가 왜 필요한지 말할 수 있는가?
  • GPT에서 causal mask가 없으면 왜 안 되는지 설명할 수 있는가?
  • multi-head가 “같은 attention을 여러 관점으로 병렬 계산하는 구조”임을 말할 수 있는가?
  • temperature와 top-k/top-p가 Transformer block 내부가 아니라 생성 단계 설정임을 구분할 수 있는가?
