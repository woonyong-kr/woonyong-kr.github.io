위치 인코딩 — Transformer가 단어 순서를 알게 만드는 방법

확인 범위: 이 문서는 위치 인코딩의 일반 원리와 방식별 선택 기준을 개념적으로 설명하고, 제시된 Python·PyTorch 및 SW_AI-W13-gpt 코드 조각으로 텐서 형태와 동작을 예시한다. 특정 버전에서의 실행 결과나 모델별 성능·길이 외삽 효과를 검증한 문서는 아니므로, 실제 적용 판단에는 대상 구현의 코드·버전·실행 기록과 성능 측정이 별도로 필요하다.

한 줄 요약: 위치 인코딩(Positional Encoding)은 Transformer의 self-attention이 토큰 순서를 구분하지 못하는 문제를 해결하기 위해, 각 위치에 고유한 벡터를 더해 “몇 번째 자리인가” 정보를 입력에 주입하는 장치다.

위치 인코딩 문제

Self Attention은 모든 토큰 쌍의 관계를 한꺼번에 계산한다. RNN처럼 순서대로 한 토큰씩 읽는 구조가 아니다. 이 병렬성이 Transformer의 장점이지만, 대가가 있다. attention 연산 자체에는 “이 토큰이 몇 번째에 있는가”라는 정보가 없다.

“고양이가 개를 쫓았다”와 “개가 고양이를 쫓았다”를 생각하자. 토큰 집합은 같다. attention score는 토큰 벡터의 내적으로 결정되므로, 위치 정보가 없으면 두 문장의 attention 결과가 동일하다. 의미가 정반대인 두 문장을 구분할 수 없다.

위치 인코딩은 각 토큰에 “나는 0번째다”, “나는 1번째다” 같은 위치 신호를 벡터에 더해 이 문제를 해결한다.

위치 인코딩 계산

두 가지 방식

위치 인코딩은 크게 두 갈래로 나뉜다.

  • 고정 수학 함수 방식: 사인/코사인 함수로 위치마다 고유한 패턴을 만든다. 학습 파라미터가 없다. 원본 “Attention Is All You Need” 논문이 사용한 방식이다.
  • 학습 가능한 임베딩 방식: 위치마다 별도의 학습 가능한 벡터를 둔다. GPT-2, GPT-3이 사용한 방식이며, 밑바닥 LLM 책의 구현도 이 방식을 따른다.

사인·코사인 고정 인코딩

각 차원은 서로 다른 주기의 파형을 담당한다. 낮은 차원은 빠르게 변해 인접 위치를 구분하고, 높은 차원은 느리게 변해 먼 위치를 구분한다. 이진수 자릿수가 서로 다른 2n 주기로 바뀌는 것과 비슷하다.

이 구현은 sin/cos 차원을 쌍으로 사용하므로 d_model이 짝수여야 한다. 학습 파라미터 없이 임의 위치를 계산할 수 있어 학습 길이 밖으로 외삽할 수 있다는 장점이 있지만, 과제와 모델에 따라 학습 가능한 위치 임베딩보다 실제 성능이 낮을 수 있다.

학습 가능한 위치 임베딩 (GPT 방식)

GPT는 토큰 임베딩 테이블과 별개로, 위치 임베딩 테이블을 하나 더 둔다.

토큰 임베딩 테이블: (vocab_size, emb_dim)
  → "이 token ID는 어떤 벡터인가?"

위치 임베딩 테이블: (context_length, emb_dim)
  → "이 위치 번호는 어떤 벡터인가?"

두 테이블 모두 nn.Embedding이다. 토큰 임베딩은 token ID를 주소로, 위치 임베딩은 위치 번호(0, 1, 2, …)를 주소로 사용해 벡터를 꺼낸다.

최종 입력 벡터는 둘을 더한 것이다.

input_embedding = token_embedding(token_id) + position_embedding(position)

왜 더하는가?

비유하면, 토큰 임베딩은 “무슨 단어인가”를 담고, 위치 임베딩은 “몇 번째 자리인가”를 담는다. 둘을 더하면 하나의 벡터 안에 “무슨 단어가 몇 번째에 있다”는 정보가 합쳐진다.

더하기가 아니라 이어붙이기(concatenation)를 쓸 수도 있지만, 차원이 두 배로 커진다. 더하기는 차원을 유지하면서도 학습 과정에서 두 정보를 효과적으로 섞는다.

텐서 shape 변환

token_ids:           (batch_size, seq_len)         예: (8, 4)

token_embedding:     (batch_size, seq_len, emb_dim) 예: (8, 4, 256)
position_embedding:  (seq_len, emb_dim)             예: (4, 256)

broadcasting으로 더하기:
  (8, 4, 256) + (4, 256) = (8, 4, 256)

→ input_embeddings:  (batch_size, seq_len, emb_dim) 예: (8, 4, 256)

위치 임베딩은 batch 차원이 없다. 같은 위치면 어떤 batch든 같은 위치 벡터를 더한다. PyTorch broadcasting이 이를 자동 처리한다.

학습 가능 방식의 한계

위치 임베딩 테이블의 행 수가 context_length로 고정된다. GPT-2는 1024, GPT-3는 2048이 상한이다. 학습 시 본 적 없는 위치에 대한 벡터가 없으므로, context_length를 넘는 입력은 처리할 수 없다.

이 한계를 넘기 위해 이후 모델들은 상대 위치 인코딩(RoPE, ALiBi)을 도입했다. RoPE는 Q/K 벡터에 회전 변환을 적용해 상대 거리 정보를 인코딩하고, ALiBi는 attention score에 거리 기반 페널티를 직접 더한다. 둘 다 학습 시 본 길이를 넘어서는 외삽이 가능하다.

RoPE가 상대 거리를 표현하는 방법

RoPE(Rotary Position Embedding)는 LLaMA와 GPT-NeoX 같은 모델에서 사용한다. 위치 벡터를 입력에 더하지 않고, Q와 K의 인접 차원을 2차원 쌍으로 묶어 위치별 각도만큼 회전시킨다.

위치 m의 Qm​과 위치 n의 Kn​을 내적하면 두 회전각의 차이가 m−n에 비례한다. 따라서 attention score가 절대 위치가 아니라 상대 거리를 직접 반영한다. 사인·코사인 고정 인코딩은 교육용 구현이 단순하고, 학습 가능한 절대 위치 임베딩은 정해진 context 안에서 직관적이다. 더 긴 문맥으로 확장하는 현대 decoder 모델은 RoPE와 NTK-aware scaling 같은 길이 외삽 기법을 주로 선택한다.

ALiBi가 score에 거리를 반영하는 방법

ALiBi(Attention with Linear Biases)는 위치 벡터를 만들지 않고 attention score에 거리 기반 음수 bias를 직접 더한다.

먼 토큰일수록 score가 더 작아진다. head마다 서로 다른 slope을 사용하면 일부 head는 근거리, 다른 head는 원거리 관계를 담당할 수 있다.

위치 인코딩 코드

위치 임베딩이 포함된 InputEmbedding 클래스

torch.arange(seq_len)이 위치 번호 [0, 1, 2, ..., seq_len-1]을 만든다. 이 번호를 위치 임베딩 테이블에 넣으면 각 위치의 벡터가 나온다. 토큰 임베딩과 더한 뒤 dropout을 적용한 결과가 Transformer 블록의 입력이 된다.

학습 스크립트에서 직접 확인

tokenizer.n_vocab은 GPT-2 BPE 토크나이저의 어휘 크기(50257)다. 위치 임베딩 테이블은 max_length 행만 있으므로 파라미터가 훨씬 적다. max_length=4, output_dim=256이면 위치 테이블의 파라미터는 4 x 256 = 1024개에 불과하다.

GPT 설정에서 context_length가 결정하는 것

context_length는 위치 임베딩 테이블의 행 수이자, 모델이 한 번에 볼 수 있는 최대 토큰 수를 동시에 결정한다. InputEmbedding의 forward에서 seq_len <= context_length를 검증하는 이유가 여기에 있다.

정리

위치 인코딩은 self-attention이 잃어버린 순서 정보를 입력 벡터에 되돌려주는 장치다. GPT는 위치마다 학습 가능한 벡터를 두고 토큰 임베딩과 더하는 절대 위치 임베딩 방식을 사용한다. context_length가 위치 테이블 크기를 결정하므로, 이 값을 넘는 입력은 처리할 수 없다는 구조적 한계가 있다. 이후 RoPE, ALiBi 같은 상대 위치 인코딩이 이 한계를 넘기 위해 등장했다.
