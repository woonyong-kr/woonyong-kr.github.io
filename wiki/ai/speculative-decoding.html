추측 디코딩 (Speculative Decoding)

한 줄 요약: 추측 디코딩은 작은 draft 모델이 여러 토큰을 먼저 제안하고, 큰 target 모델이 그 제안을 한 번에 검증해 생성 속도를 높이는 기법이다.

추측 디코딩이 비용을 줄이는 지점

LLM은 보통 토큰을 하나씩 생성한다. 큰 모델은 토큰을 생성할 때마다 전체 layer를 통과한다. 따라서 생성할 토큰이 많아질수록 decode 단계의 latency도 커진다. batch가 작거나 응답을 실시간으로 스트리밍하는 상황에서는 GPU를 충분히 활용하지 못하는 순간도 생길 수 있다.

추측 디코딩은 작은 모델의 빠른 제안과 큰 모델의 정확한 검증을 결합해 이 병목을 줄인다. 작고 빠른 모델이 여러 토큰을 먼저 만들면, 느리지만 최종 품질을 책임지는 큰 모델이 그 토큰들을 자신의 분포에서도 받아들일 수 있는지 확인한다.

추측 디코딩 구조

  • draft 모델
    • 작고 빠른 모델이다.
    • 다음 토큰 여러 개를 연속으로 제안한다.
  • target 모델
    • 실제 서비스 품질을 책임지는 큰 모델이다.
    • draft 토큰들을 병렬에 가깝게 검증한다.
  • accept/reject
    • target 모델이 동의한 토큰은 그대로 채택한다.
    • 동의하지 않는 지점부터 target 모델의 분포로 다시 샘플링한다.

따라서 추측 디코딩은 target 모델을 없애는 최적화가 아니다. target 모델의 출력 분포를 최대한 보존하면서 한 번의 forward로 여러 토큰을 확정하려는 방식이다.

실제 흐름

draft가 A B C D를 제안하고 target이 A B까지만 받아들였다면, 한 번의 검증으로 토큰 2개를 확정한 셈이다. 제안한 토큰이 모두 거절되면 얻는 이득이 작다. 반대로 대부분 채택되면 한 번의 검증으로 더 많은 토큰을 확정할 수 있어 속도 이득이 커진다.

추측 디코딩 값 추적

실제 속도는 draft 모델의 실행 비용과 채택률뿐 아니라 batch 크기와 KV cache 관리 방식에 따라서도 달라진다. draft 모델이 너무 크면 토큰을 제안하는 비용이 커진다. draft 모델과 target 모델의 분포 차이가 너무 크면 채택률이 낮아져 속도 이득도 줄어든다.
