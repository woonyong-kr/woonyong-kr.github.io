어댑터 튜닝 (Adapter Tuning)

한 줄 요약: 어댑터 튜닝은 본체 가중치를 고정하고 Transformer 블록에 작은 병목 모듈을 삽입해 학습하는 PEFT 방법이다.

거대 언어 모델을 과업마다 full fine-tuning하면 GPU 메모리와 학습 시간뿐 아니라, 과업별 모델을 보관하는 데 필요한 저장 공간도 커진다. 어댑터 튜닝은 사전학습 모델의 본체 가중치를 고정하고 Transformer 블록 안에 작은 병목 모듈을 삽입한다. 학습 대상은 이 모듈로 한정되므로 모델 전체를 과업마다 다시 조정하는 비용을 줄일 수 있다.

모델의 어느 부분을 조정하는가

어댑터는 모델 전체를 다시 쓰는 대신 중간 흐름에 작은 보정 장치를 추가한다. LoRA가 기존 Linear 가중치 옆에 저랭크 행렬을 붙이는 방식이라면, Adapter는 Attention이나 FFN의 출력 뒤에 작은 신경망을 삽입한다.

원래 Transformer 블록은 보통 입력을 Attention이나 FFN에 통과시킨 뒤 그 결과를 residual로 더한다. Adapter를 삽입하면 해당 출력이 down projection, nonlinearity, up projection으로 이루어진 병목 모듈을 거친다. 병목 모듈이 만든 보정값은 기존 흐름의 출력에 더해진다.

아래 코드는 이 병목 모듈을 단순화해 보여준다.

d_model=768, bottleneck=64라면 한 Adapter의 주요 파라미터 수는 대략 768*64 + 64*768 = 98,304개다. 각 블록의 Attention 뒤와 FFN 뒤에 하나씩 삽입한다면, 블록 수를 반영해 전체 학습 파라미터 수를 계산할 수 있다. 이 수는 full fine-tuning의 학습 파라미터 수보다 훨씬 작지만, 추론할 때도 Adapter 모듈의 연산은 남는다.

Adapter·LoRA·Prompt/Prefix를 고르는 기준

원본 모델을 고정한 채 여러 과업이나 도메인에 맞춘 작은 보정 모듈을 따로 보관하려면 Adapter를 후보로 둘 수 있다. 다만 모듈이 모델의 실행 흐름에 삽입되므로 추론 시 약간의 추가 지연을 감수해야 한다.

추론 비용을 줄이기 위해 보정값을 기존 Linear 가중치에 병합하고 싶거나, 현재 도구 생태계에서 널리 지원되는 PEFT 경로가 필요하다면 LoRA가 더 적합하다. 모델 구조를 건드리지 않고 입력 쪽의 학습 가능한 토큰만 조정하려면 Prompt/Prefix 계열을 고려할 수 있다.

이 차이를 설명할 때는 먼저 무엇을 학습하는지 구분하면 된다. Adapter는 Transformer 블록 안의 down→nonlinearity→up 병목 모듈을 학습한다. LoRA는 기존 Linear 가중치 옆의 저랭크 행렬을 학습하며, Adapter와 달리 기존 가중치에 병합할 수 있다. Prompt/Prefix 계열은 입력 쪽의 학습 가능한 토큰을 조정한다.

파라미터 규모를 비교하려면 먼저 d_model=768, bottleneck=64인 어댑터 하나에서 768*64 + 64*768 = 98,304개를 계산한다. 이어서 각 블록의 Attention 뒤와 FFN 뒤에 하나씩 삽입한다는 조건을 반영해 블록 수를 곱하고, 그 결과를 full fine-tuning의 학습 파라미터 수와 비교한다. 파라미터 수가 작아지더라도 Adapter 연산 자체는 추론 과정에 계속 포함된다는 점도 함께 살펴야 한다.
