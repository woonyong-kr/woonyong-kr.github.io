Kaplan 스케일링 Law (Kaplan Scaling Law)

Kaplan 스케일링 Law는 언어 모델 loss가 모델 크기, 데이터, 연산량에 따라 비교적 예측 가능하게 줄어든다는 경험 법칙이다. 작은 실험의 loss 곡선으로 다음 크기를 추정하는 출발점이 된다.

Kaplan 스케일링 Law는 언어 모델의 loss가 모델 크기, 데이터 크기, 연산량이 커질수록 비교적 예측 가능한 방식으로 줄어든다는 경험 법칙이다. 이름은 Kaplan 등 연구진의 대규모 언어 모델 스케일링 연구에서 온다.

Kaplan 스케일링 Law 필요성

LLM을 키울 때 가장 먼저 드는 질문은 단순하다.

Kaplan 스케일링 Law의 의미는 “크게 만들면 대체로 좋아진다”가 아니다. 더 정확히는 loss가 줄어드는 양을 모델 크기, 데이터 토큰 수, compute와 연결해 보려는 시도다. 그래서 감으로 실험을 키우기보다, 작은 실험의 loss 곡선을 보고 다음 크기를 추정하는 출발점이 된다.

세 축으로 보기

처음에는 세 축만 구분하면 충분하다.

  • 모델 크기 N
    • 파라미터 수
    • 모델이 표현할 수 있는 패턴의 용량과 연결
  • 데이터 크기 D
    • 학습에 사용한 token 수
    • 모델이 본 예시의 다양성과 연결
  • 연산량 C
    • 학습에 쓴 총 compute
    • 모델 크기와 데이터 크기를 함께 키울 때 필요한 비용과 연결

Kaplan식 관점은 이 세 축 중 하나만 따로 보지 않는다. 예를 들어 모델만 키우고 데이터가 부족하면 큰 모델이 같은 문장을 반복해서 볼 수 있다. 반대로 데이터만 많고 모델이 작으면 다양한 패턴을 충분히 담지 못할 수 있다.

작은 숫자 예시

정확한 논문 지수를 외우는 것보다 관계를 먼저 보는 편이 좋다. 작은 실험을 세 번 했다고 하자.

이 결과를 보면 두 가지를 구분할 수 있다.

  • A -> B
    • 데이터는 같고 모델만 커졌다.
    • 모델 용량 증가가 loss를 줄였다.
  • B -> C
    • 모델은 같고 데이터가 늘었다.
    • 더 많은 token이 loss를 줄였다.

스케일링 법칙은 이런 실험을 여러 크기에서 반복한 뒤, “다음 크기에서도 loss가 대략 어떤 방향으로 움직일까”를 추정하는 도구다.

무엇을 조심해야 하나

Kaplan 스케일링 Law는 강력한 직관을 주지만, 그대로 최종 정답처럼 쓰면 위험하다.

  • 데이터 품질을 자동으로 보장하지 않는다.
    • 같은 token 수라도 정제 상태, 중복, 도메인 구성이 다르면 결과가 달라진다.
    • 데이터 혼합 비율과 사전학습 데이터 파이프라인을 같이 봐야 한다.
  • loss만 좋아진다고 모든 능력이 좋아지는 것은 아니다.
    • 특정 벤치마크, 추론 능력, 안전성, 지시 따르기는 따로 봐야 한다.
  • compute가 같아도 배분이 다르면 결과가 달라진다.
    • 모델을 너무 크게 두고 token을 적게 볼 수도 있다.
    • 모델을 너무 작게 두고 token만 많이 볼 수도 있다.
  • 후속 연구와 실무 경험은 데이터 수와 품질의 중요성을 더 강하게 보게 만들었다.
    • Chinchilla 계열 논의는 이 지점에서 이어진다.

compute-optimal 관점으로 이어지는 지점

스케일링 법칙과 연산 최적 배분은 “정해진 연산 예산 안에서 모델 크기와 데이터 크기를 어떻게 나눌까”를 다룬다. Kaplan식 스케일링 법칙을 먼저 보면, compute-optimal 논의가 왜 단순히 “더 크게”가 아니라 “무엇을 얼마나 키울까”로 넘어가는지 이해하기 쉽다.

구분하면 이렇게 볼 수 있다.

  • Kaplan 스케일링 Law
    • 모델 크기, 데이터 크기, compute가 커질 때 loss가 어떻게 줄어드는지 보는 경험 법칙
    • “규모를 키우면 성능이 예측 가능한 곡선을 따라 좋아질 수 있다”는 직관
  • compute-optimal 관점
    • 정해진 compute 안에서 모델과 데이터 비율을 어떻게 배분할지 보는 판단 기준
    • “무엇을 얼마나 키우는 편이 비용 대비 좋은가”라는 실험 설계 질문

Kaplan 스케일링 Law 적용 기준

Kaplan 스케일링 Law를 읽을 때는 다음 질문을 남기면 된다.

  • 지금 말하는 성능은 validation loss인가, 실제 과업 성능인가?
  • 모델 크기 N, 데이터 토큰 수 D, compute C 중 무엇을 키운 실험인가?
  • 데이터 품질과 중복 제거 기준이 같이 기록되어 있는가?
  • 작은 실험 결과를 큰 실험으로 외삽하고 있지는 않은가?
  • compute budget이 고정되어 있다면 연산 최적 배분 질문으로 넘어갔는가?

짧게 말하면 이렇다.

정리

  1. Kaplan 스케일링 Law는 loss를 모델 크기 N·데이터 D·연산량 C의 함수로 읽으려는 초기 경험 법칙이다.
  2. 세 축 중 하나만 따로 키우지 않고, 작은 실험의 loss 곡선으로 다음 크기를 외삽하는 출발점으로 쓴다.
  3. loss 감소가 모든 능력·안전성을 보장하지는 않고 데이터 품질·배분이 결과를 가르므로, Chinchilla식 compute-optimal 논의로 이어진다.

데이터는 고정하고 모델만 키운 실험과 모델은 고정하고 데이터만 늘린 실험을 나란히 두면, loss가 어느 쪽으로 더 움직이는지 비교하기 쉽다.
