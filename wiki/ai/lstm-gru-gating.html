LSTM/GRU 게이팅

LSTM/GRU 게이팅

확인 범위: 이 문서는 LSTM과 GRU의 게이트가 정보를 보존·삭제·갱신하는 일반 원리와 구조적 차이를 교육용 수식·NumPy 예시로 설명한다. 제시된 코드는 특정 라이브러리·버전의 구현이나 실제 실행 기록·성능 측정을 검증한 결과가 아니므로, 구현 호환성이나 성능에 관한 판단에는 별도의 코드 실행과 측정이 필요하다.

한 줄 요약: LSTM과 GRU는 RNN의 은닉 상태를 그냥 덮어쓰지 않고, gate로 “무엇을 버릴지, 무엇을 보존할지, 무엇을 새로 쓸지”를 조절해 긴 sequence의 기억 손실을 줄이는 구조다.

LSTM/GRU 게이팅 필요성

Vanilla RNN은 매 시점마다 하나의 은닉 상태 h_t를 새로 계산한다.

이 구조는 단순하지만 문제가 있다. h_t가 매번 새 값으로 덮어써지므로 오래전 정보가 쉽게 희석된다. 학습할 때도 BPTT가 시간축을 거슬러 가며 같은 종류의 곱셈을 반복하므로 기울기 소실이 일어난다.

LSTM(Long Short-Term Memory)과 GRU(Gated Recurrent Unit)는 이 문제를 “기억을 무조건 덮어쓰지 말자”는 방향으로 해결한다. 핵심은 gate다. gate는 0과 1 사이의 값으로, 정보를 얼마나 통과시킬지 정하는 조절 밸브다.

LSTM/GRU 게이팅 흐름

Gate는 정보 흐름을 조절하는 벡터다

gate는 보통 sigmoid 출력이다.

sigmoid 출력은 0과 1 사이에 있다.

  • 0에 가까우면
    • 해당 정보를 거의 막는다.
  • 1에 가까우면
    • 해당 정보를 거의 그대로 통과시킨다.
  • 0.5 근처이면
    • 절반 정도 섞는다.

예를 들어 이전 기억 old = [10, 20, 30]과 gate g = [1.0, 0.0, 0.5]가 있으면 통과한 값은 다음과 같다.

첫 번째 정보는 보존하고, 두 번째 정보는 버리고, 세 번째 정보는 약하게 남긴다. 이것이 LSTM/GRU의 기본 감각이다.

LSTM은 기억 통로를 따로 둔다

LSTM은 은닉 상태 h_t와 별도로 cell state c_t를 둔다. c_t는 오래 가져갈 기억 통로다.

%% LSTM에서 gate가 cell state와 hidden state를 조절하는 흐름
flowchart LR
  c_prev["c_{t-1}<br/>이전 cell state"]
  xh["x_t, h_{t-1}<br/>현재 입력과 이전 은닉 상태"]
  forget["forget gate<br/>버릴 양과 보존할 양"]
  input["input gate<br/>새 후보를 쓸 양"]
  candidate["candidate<br/>새 기억 후보"]
  output["output gate<br/>밖으로 보여줄 양"]
  keep["f_t * c_{t-1}<br/>오래된 기억 중 남길 부분"]
  write["i_t * g_t<br/>새로 쓸 기억"]
  cell["c_t = f_t * c_{t-1} + i_t * g_t<br/>덧셈으로 이어지는 장기 기억 통로"]
  hidden["h_t = o_t * tanh(c_t)<br/>다음 step에 넘기는 은닉 상태"]
  xh --> forget
  xh --> input
  xh --> candidate
  xh --> output
  c_prev --> keep
  forget --> keep
  input --> write
  candidate --> write
  keep --> cell
  write --> cell
  cell --> hidden
  output --> hidden

LSTM의 핵심 gate는 세 가지다.

  • forget gate
    • 이전 cell state c_{t-1} 중 무엇을 버릴지 정한다.
  • input gate
    • 새 후보 기억 중 무엇을 c_t에 쓸지 정한다.
  • output gate
    • cell state 중 무엇을 은닉 상태 h_t로 내보낼지 정한다.

이 구조의 중요한 점은 c_t가 덧셈 경로를 가진다는 것이다.

Vanilla RNN은 기억이 매번 tanh(...)로 다시 압축된다. LSTM은 이전 기억을 곱하고 더하는 별도 통로를 두어, 필요한 정보가 더 오래 흐를 수 있게 한다.

GRU는 더 단순한 게이트 구조다

GRU는 LSTM보다 단순하다. 별도의 cell state c_t를 두지 않고 은닉 상태 h_t만 사용한다.

주요 gate는 두 가지다.

  • update gate
    • 이전 은닉 상태를 얼마나 유지하고 새 후보 상태를 얼마나 반영할지 정한다.
  • reset gate
    • 새 후보 상태를 만들 때 과거 은닉 상태를 얼마나 참고할지 정한다.

개념적으로 GRU의 업데이트는 다음처럼 볼 수 있다.

update gate가 0에 가까우면 이전 기억을 유지한다. 1에 가까우면 새 후보 상태로 갈아탄다.

실제 예시로 보는 gate 판단

문장을 왼쪽에서 오른쪽으로 읽는다고 하자.

Vanilla RNN은 뒤쪽 단어 좋다를 처리할 때 앞쪽의 노트북 정보를 은닉 상태 하나에 계속 압축해 들고 가야 한다. 중간에 무겁지만, 성능은 같은 새 정보가 들어오면 앞쪽 정보가 희석될 수 있다.

LSTM/GRU는 다음 판단을 gate로 나눠 한다.

  • 노트북 정보
    • 문장 뒤쪽 평가와 이어지므로 보존한다.
  • 어제 산 정보
    • 현재 감성 판단에는 덜 중요하면 약하게 남긴다.
  • 무겁지만
    • 반대 접속 이후 성능은 좋다와 함께 최종 판단에 영향을 주므로 일부 유지한다.

이 판단이 사람이 직접 규칙으로 넣은 것은 아니다. gate의 가중치가 학습되면서, 어떤 패턴에서 무엇을 보존할지 모델이 데이터로부터 배운다.

LSTM/GRU 게이팅 코드

LSTM과 GRU의 forward 한 step을 numpy로 펼치면 gate가 곱셈·덧셈으로 어떻게 정보를 거르는지 보인다. LSTM과 GRU는 밑바닥 딥러닝1·밑바닥 LLM 책에는 구현이 없으므로, 아래는 표준 수식을 그대로 옮긴 교육용 numpy 코드다.

LSTM cell forward

c_t = f * c_prev + i * g가 핵심이다. 이전 기억 c_prev를 곱셈 한 번과 덧셈 한 번으로 다음 시점에 넘긴다. Vanilla RNN처럼 매번 tanh로 다시 압축하지 않으므로 기억이 더 오래 흐른다.

GRU cell forward

GRU는 cell state가 없다. h_t = (1 - z) * h_prev + z * h_tilde 한 줄로 “유지할지 갱신할지”를 정한다. gate 묶음이 LSTM 4개에서 2개로 줄어 파라미터가 적다.

shape로 따라가기

input_dim = 4, hidden_dim = 3일 때 텐서 흐름은 다음과 같다.

%% LSTM과 GRU의 gate 계산에서 유지되는 텐서 shape 흐름
flowchart TD
  x_t["x_t<br/>(4,)"]
  h_prev["h_prev<br/>(3,)"]
  c_prev["c_prev<br/>(3,) LSTM만"]
  concat["concat([x_t, h_prev])<br/>xh: (4 + 3) = (7,)"]
  weights["W_*<br/>(hidden_dim, input_dim + hidden_dim)<br/>(3, 7)"]
  gates["gate / candidate 출력<br/>(hidden_dim,) = (3,)<br/>LSTM: f, i, o, g<br/>GRU: z, r, h_tilde"]
  lstm_cell["LSTM cell state<br/>c_t: (3,)"]
  lstm_hidden["LSTM hidden state<br/>h_t: (3,)"]
  gru_hidden["GRU hidden state<br/>h_t: (3,)"]
  x_t --> concat
  h_prev --> concat
  concat --> weights
  weights --> gates
  c_prev --> lstm_cell
  gates --> lstm_cell
  lstm_cell --> lstm_hidden
  gates --> gru_hidden
  h_prev --> gru_hidden

gate 출력은 모두 (hidden_dim,) = (3,)이고, 입력·출력 은닉 상태도 (3,)로 유지된다. seed를 고정해 위 코드를 돌리면 h_t, c_t 모두 (3,) 벡터가 나오고 모든 gate 값이 0과 1 사이에 들어온다.

정리

  • LSTM/GRU는 은닉 상태를 무조건 덮어쓰지 않고 gate(0~1 벡터)로 정보 흐름을 조절한다.
  • LSTM은 c_t라는 별도 장기 기억 통로에 c_t = f * c_prev + i * g 형태의 곱셈·덧셈 경로를 둔다.
  • GRU는 cell state 없이 h_t 하나만 두고 update/reset gate로 유지와 갱신을 섞는다. 파라미터가 더 적다.
  • 둘 다 RNN 계열이라 시점 순서대로 입력을 처리하며, Attention처럼 모든 token을 직접 비교하지 않는다.
