부동 소수점과 고정 소수점

부동 소수점과 고정 소수점

컴퓨터는 소수를 정확히 저장할 수 없다. 부동 소수점은 넓은 범위를 근사하고, 고정 소수점은 좁은 범위를 빠르게 계산한다.

부동 소수점과 고정 소수점 구분

정수는 2의 보수로 깔끔하게 표현된다. 그런데 0.1은? 10진수로는 간단한 이 숫자가 2진수로는 0.0001100110011...처럼 무한히 반복된다. 유한한 비트로 무한 소수를 담을 수 없으므로, 어딘가에서 잘라야 한다. 잘리는 순간 오차가 생긴다.

이 문제를 모르면 다음 상황을 이해할 수 없다.

  • Python에서 0.1 + 0.2가 0.30000000000000004를 반환하는 이유
  • 금융 시스템이 float 대신 Decimal 타입을 쓰는 이유
  • OS 커널이 부동 소수점 하드웨어(FPU)를 쓰지 않고 정수만으로 소수를 계산하는 이유

실수 표현법은 “어디서 소수점을 둘 것인가”에 대한 두 가지 전략이다. 소수점을 고정하면 고정 소수점, 떠다니게 하면 부동 소수점(floating point)이다.

소수점을 어디에 둘 것인가

고정 소수점 (Fixed-Point)

소수점의 위치를 미리 정해두고, 정수 연산만으로 소수를 다루는 방식이다.

비유: 원화에는 소수점이 없다. 하지만 “금액을 항상 100으로 나눠서 읽자”고 약속하면, 정수 1550이 15.50원을 의미하게 된다. 실제 덧셈·뺄셈은 정수끼리 하고, 사람에게 보여줄 때만 100으로 나눈다. 이것이 고정 소수점의 원리다.

32비트 정수에서 하위 14비트를 소수 부분으로 쓰는 17.14 형식을 예로 들면 다음과 같다.

%% 17.14 고정 소수점 비트 배치
flowchart TD
  fixed_point["31 &#124; 30 ... 14 &#124; 13 ... 0<br/>부호 &#124; 정수 부분<br/>17비트 &#124; 소수 부분<br/>14비트"]
  scale["변환 계수 F = 2^14 = 16384<br/>정수 3 -&gt; 3 * F = 49152<br/>49152 -&gt; 49152 / F = 3"]
  fixed_point --> scale
  • 변환 계수 F = 2^14 = 16384
  • 정수 3을 고정소수점으로: 3 * 16384 = 49152
  • 고정소수점 49152를 정수로: 49152 / 16384 = 3

장점은 명확하다. 덧셈·뺄셈이 그냥 정수 연산이다. FPU(부동 소수점 연산 장치)가 없는 환경에서도 쓸 수 있다. 단점은 표현 범위가 좁다는 것이다. 17.14 형식은 정수 부분이 17비트(부호 포함)이므로, 대략 -65536 ~ +65535 범위의 수만 표현한다.

부동 소수점 (Floating-Point) — IEEE 754

소수점의 위치가 고정되지 않고, 지수(exponent)에 따라 떠다니는(float) 방식이다. 과학적 표기법과 같은 원리다.

10진수 과학적 표기법: 1.5 × 10^3 = 1500, 1.5 × 10^-2 = 0.015

같은 1.5라는 가수(mantissa)가 지수에 따라 매우 큰 수도, 매우 작은 수도 표현한다. 소수점의 위치가 지수에 의해 이동하므로 “부동(floating)” 소수점이라 부른다.

IEEE 754 표준은 32비트(단정밀도, float)와 64비트(배정밀도, double) 두 형식을 정의한다.

32비트 단정밀도 (float):

%% IEEE 754 32비트 float 비트 배치
flowchart TD
  float32["31 &#124; 30 ... 23 &#124; 22 ... 0<br/>S<br/>부호 &#124; Exponent<br/>지수 8비트 &#124; Mantissa<br/>가수 23비트<br/>bias = 127"]
  • S: 부호 비트. 0이면 양수, 1이면 음수.
  • Exponent: 바이어스 127을 더한 값 저장. 실제 지수는 저장값 - 127.
  • Mantissa: 1.xxxxx에서 소수점 아래 부분만 저장. 앞의 1은 생략.

64비트 배정밀도 (double):

%% IEEE 754 64비트 double 비트 배치
flowchart TD
  double64["63 &#124; 62 ... 52 &#124; 51 ... 0<br/>S<br/>부호 &#124; Exponent<br/>지수 11비트 &#124; Mantissa<br/>가수 52비트<br/>bias = 1023"]
  • S: 부호 비트.
  • Exponent: 지수 11비트. 바이어스는 1023.
  • Mantissa: 가수 52비트.

왜 바이어스를 쓰는가?

지수를 2의 보수가 아니라 바이어스 표현으로 저장하는 이유가 있다. 부동 소수점 수의 크기를 비교할 때, 부호-지수-가수 순서로 비트를 배치하면 정수 비교 회로를 그대로 쓸 수 있다. 2의 보수에서는 음수 지수가 양수 지수보다 비트 패턴이 크므로 비교가 꼬인다. 바이어스를 더하면 지수가 항상 양수가 되어 비트 패턴 순서와 실제 크기 순서가 일치한다.

0.1은 왜 정확하지 않은가?

10진수 0.1을 2진수로 바꾸면 다음과 같다.

0.1 (10진)
= 0.0001100110011001100110011... (2진, 무한 반복)

float (23비트 가수):  저장 가능한 가장 가까운 값
= 0.100000001490116119384765625

double (52비트 가수): 저장 가능한 가장 가까운 값
= 0.1000000000000000055511151231257827021181583404541015625

가수 비트가 유한하므로 어딘가에서 잘린다. 잘린 만큼 오차가 생긴다. 0.1 + 0.2의 결과가 0.3이 아닌 이유는, 세 수 모두 각각 근사값이고, 근사값끼리의 연산 결과가 또 다른 근사값이 되기 때문이다.

특수 값

IEEE 754는 일반 숫자 외에 세 가지 특수 값을 정의한다.

  • ±0: 부호 비트만 다른 두 개의 0이 존재한다. +0 == -0은 true다.
  • ±Infinity (∞): 지수가 전부 1이고 가수가 전부 0이면 무한대다. 1.0 / 0.0의 결과다.
  • NaN (Not a Number): 지수가 전부 1이고 가수가 0이 아니면 NaN이다. 0.0 / 0.0이나 sqrt(-1.0)의 결과다. NaN은 자기 자신과도 같지 않다 — NaN != NaN은 true다.

부동 소수점 vs 고정 소수점 — 선택 기준

  • 넓은 범위 + 범용 연산이 필요하면 → 부동 소수점 (float, double)
    • 과학 계산, 그래픽, 물리 시뮬레이션, 일반 프로그래밍
  • FPU가 없거나 정밀한 정수 연산이 필요하면 → 고정 소수점
    • OS 커널 스케줄러, 임베디드 시스템, 금융 계산(정수 기반 Decimal)
  • 오차가 절대 허용되지 않으면 → 정수 + 스케일링 또는 임의 정밀도 라이브러리
    • 금융 결산, 암호 연산

부동 소수점과 고정 소수점 코드

float의 비트 구조 확인

0.15625(= 1/8 + 1/32 = 2^-3 + 2^-5)는 2진수로 0.00101이다. 정규화하면 1.01 × 2^-3이 된다.

부호 0, 지수 124(= -3 + 127), 가수 01(앞의 1은 생략). 이 세 부분을 조립하면 (-1)^0 × 1.01₂ × 2^-3 = 0.15625가 복원된다.

PintOS 17.14 고정소수점 — 커널에서 소수를 정수로

PintOS의 MLFQS(다단계 피드백 큐 스케줄러)는 load_avg와 recent_cpu를 소수로 계산해야 한다. 그런데 커널은 FPU를 쓰지 않는다. FPU 레지스터를 컨텍스트 스위칭마다 저장·복원하는 비용이 크고, 인터럽트 핸들러에서 부동 소수점 연산을 하면 유저 프로세스의 FPU 상태를 망칠 수 있기 때문이다.

해결책이 17.14 고정소수점이다. 32비트 정수의 하위 14비트를 소수 부분으로 약속한다.

곱셈에서 int64_t로 확장하는 이유는 오버플로우 방지다. 고정소수점 두 수를 곱하면 중간값이 28비트(14 + 14)만큼 스케일이 커지므로, 32비트를 넘을 수 있다. 64비트로 확장해서 곱한 뒤 F로 나눠 14비트를 되돌린다.

이 매크로로 MLFQS의 감쇄 공식을 정수 연산만으로 계산한다.

59/60은 정수 나눗셈이면 0이 된다. 고정소수점에서는 FP_DIV(59 × 16384, 60 × 16384) = 59 × 16384 × 16384 / (60 × 16384) = 59 × 16384 / 60 ≈ 16110이 되어 0.983...에 해당하는 값이 정확히 보존된다.

0.1 + 0.2 문제 확인

float끼리 ==로 비교하면 안 되는 이유가 여기에 있다. 허용 오차(epsilon)를 두고 비교하거나, 정확한 값이 필요하면 Decimal처럼 10진수 기반 타입을 쓴다.

정리

컴퓨터에서 소수를 표현하는 방법은 두 가지다. 부동 소수점(IEEE 754)은 지수를 움직여 매우 넓은 범위를 표현하지만, 2진 근사 때문에 0.1 + 0.2 != 0.3 같은 오차가 생긴다. 고정 소수점은 소수점 위치를 고정하고 정수 연산만으로 소수를 다루므로, FPU가 없는 OS 커널이나 임베디드 환경에서 쓴다.

모든 실수 표현에는 트레이드오프가 있다. 범위를 넓히면 정밀도가 떨어지고, 정밀도를 높이면 비트가 더 필요하다. 어떤 표현을 선택할지는 “이 상황에서 오차를 얼마나 허용할 수 있는가”로 판단한다.
