JPG, PNG, GIF 이미지 포맷

JPG, PNG, GIF 이미지 포맷

확인 범위: 이 문서는 JPG·PNG·GIF의 압축 방식과 기능 차이를 바탕으로 포맷을 선택하는 일반 원리를 설명하며, 제시된 파일 크기·압축률·용량 비교는 특정 이미지나 실행 환경에서 검증한 측정 결과가 아니다. 매직 넘버 판별 코드는 개념을 보여 주는 예시이므로, 실제 적용 여부와 성능·호환성은 사용 코드와 포맷 버전, 실행 기록을 별도로 확인해야 한다.

JPG는 사람 눈이 둔한 색상 변화를 버려 사진을 작게 만들고, PNG는 데이터를 하나도 버리지 않으면서 투명도를 지원하며, GIF는 256색 제한 대신 프레임을 이어 붙여 애니메이션을 만든다.

JPG, PNG, GIF 이미지 포맷 문제

같은 사진을 JPG로 저장하면 500KB인데, PNG로 저장하면 2MB가 된다. 왜 그런가? 두 포맷이 이미지를 압축하는 방식이 근본적으로 다르기 때문이다.

포맷을 잘못 고르면 실질적인 문제가 생긴다. 웹 페이지에 무손실 PNG 사진을 수십 장 올리면 페이지 로딩이 느려진다. 반대로 로고를 JPG로 저장하면 글자 주변에 노이즈가 번진다. 투명 배경이 필요한 아이콘을 JPG로 만들면 흰색 배경이 박힌 채로 나온다. 짧은 반복 영상을 동영상 파일로 만들면 무겁지만, GIF로 만들면 브라우저에서 바로 재생된다.

이미지 포맷의 차이를 이해하면 “언제 어떤 포맷을 쓸지” 판단 기준이 생긴다. 이 판단은 프론트엔드, 백엔드, 데이터 처리 어디서든 필요하다.

압축 방식이 갈라지는 지점

압축의 두 갈래 — 손실과 무손실

이미지 파일이 원본 픽셀 데이터보다 작은 이유는 압축 때문이다. 압축에는 두 가지 방향이 있다.

  • 손실 압축 (Lossy Compression): 사람이 눈으로 구별하기 어려운 정보를 버린다. 원본으로 완벽히 되돌릴 수 없지만, 파일 크기를 극적으로 줄인다.
  • 무손실 압축 (Lossless Compression): 데이터를 하나도 버리지 않는다. 압축을 풀면 원본과 비트 단위로 동일하다. 대신 압축률이 낮다.

이 구분이 세 포맷의 핵심 차이를 만든다.

JPG (JPEG) — 사진을 작게, 대신 조금 뭉개진다

JPEG (Joint Photographic Experts Group)는 손실 압축 포맷이다.

동작 원리를 단순화하면 이렇다:

  1. 이미지를 8×8 픽셀 블록으로 나눈다.
  2. 각 블록에 DCT (이산 코사인 변환, Discrete Cosine Transform)를 적용해서 공간 영역의 픽셀 값을 주파수 영역으로 바꾼다.
  3. 고주파 성분(날카로운 경계, 미세한 색상 변화)을 양자화 (Quantization)로 버린다. 사람 눈은 밝기 변화에는 민감하지만 색상의 미세한 차이에는 둔하다. 이 특성을 이용한다.
  4. 남은 데이터를 허프만 부호화 (Huffman Coding)로 압축한다.

이 과정에서 정보가 사라지므로, JPG를 저장할 때마다 화질이 조금씩 떨어진다. 이를 **세대 손실 (Generation Loss)**이라 한다. 편집 작업 중에는 원본을 따로 보관하고 최종 결과만 JPG로 내보내는 것이 좋다.

특징:

  • 색상 채널: RGB (24비트, 약 1677만 색)
  • 투명도: 지원하지 않는다 (알파 채널 없음)
  • 애니메이션: 지원하지 않는다
  • 압축률: 품질 설정에 따라 원본의 1/10~1/20까지 줄일 수 있다
  • 적합한 용도: 사진, 자연 이미지, 그라데이션이 풍부한 이미지

PNG — 한 픽셀도 버리지 않고, 투명도까지

PNG (Portable Network Graphics)는 무손실 압축 포맷이다. GIF의 특허 문제를 피하기 위해 1996년에 만들어졌다.

동작 원리:

  1. 각 행(scanline)에 필터링을 적용한다. 인접 픽셀 간의 차이값을 저장하면 같은 색이 이어지는 구간에서 0이 많아진다.
  2. 필터링된 데이터를 DEFLATE 알고리즘 (LZ77 + Huffman)으로 압축한다. 반복 패턴이 많을수록 잘 줄어든다.

핵심 차별점은 **알파 채널 (Alpha Channel)**이다. 각 픽셀에 0~255 범위의 투명도 값을 저장할 수 있다. 0이면 완전 투명, 255면 완전 불투명이다. 로고, 아이콘, UI 요소처럼 배경을 투과시켜야 하는 이미지에 필수적이다.

특징:

  • 색상 채널: RGBA (32비트 — RGB 24비트 + Alpha 8비트), 또는 RGB (24비트)
  • 투명도: 지원한다 (픽셀 단위로 0~255 제어 가능)
  • 애니메이션: 기본 PNG는 지원하지 않는다 (APNG 확장이 있지만 범용성이 낮다)
  • 압축률: 무손실이므로 사진에 쓰면 JPG보다 2~5배 크다. 단색·도형이 많으면 매우 작아진다
  • 적합한 용도: 스크린샷, 로고, 아이콘, 도표, 텍스트가 포함된 이미지

GIF — 256색이면 충분한 세계, 그리고 애니메이션

GIF (Graphics Interchange Format)는 1987년 CompuServe가 만든 포맷이다. LZW (Lempel-Ziv-Welch) 무손실 압축을 사용한다.

GIF의 가장 큰 제약은 색상 팔레트가 최대 256색이라는 점이다. 이미지 전체에서 가장 중요한 256개 색상을 골라 팔레트에 등록하고, 각 픽셀은 팔레트 인덱스(0~255)로 저장한다. 사진처럼 색상이 풍부한 이미지에 쓰면 색이 뭉개지고 밴딩 (banding) 현상이 나타난다.

반면, 다른 포맷에 없는 고유 기능이 있다. 여러 프레임을 하나의 파일에 담아 애니메이션을 만들 수 있다. 각 프레임에 표시 시간 (delay)을 지정하고, 반복 횟수를 설정한다. 브라우저가 별도 플레이어 없이 바로 재생한다. 이 때문에 GIF는 인터넷 밈, 이모티콘, 짧은 시연 영상에 널리 쓰인다.

투명도도 지원하지만 PNG와 다르다. GIF의 투명도는 1비트 — 각 픽셀이 완전 투명이거나 완전 불투명이다. 반투명 (Semi-transparent)은 표현할 수 없다.

특징:

  • 색상 채널: 인덱스 컬러 (최대 256색 팔레트)
  • 투명도: 1비트 (투명 or 불투명, 반투명 불가)
  • 애니메이션: 지원한다 (다중 프레임 + 루프 설정)
  • 압축: LZW 무손실 (256색 범위 내에서 무손실)
  • 적합한 용도: 간단한 애니메이션, 아이콘, 단색 그래픽

포맷 선택 흐름

세 포맷의 차이는 결국 하나의 질문으로 정리된다. “무엇을 저장하는가.”

%% JPG, PNG, GIF 포맷 선택 흐름
flowchart TD
  question["어떤 이미지인가?"]
  photo["사진/자연 이미지<br/>색이 풍부함<br/>투명도 불필요"]
  graphic["로고/아이콘/스크린샷<br/>선명한 경계 필요<br/>투명 배경 필요"]
  animation["짧은 반복 애니메이션<br/>여러 프레임<br/>브라우저 즉시 재생"]
  jpg["JPG<br/>손실 압축"]
  png["PNG<br/>무손실 + 알파"]
  gif["GIF<br/>다중 프레임"]
  question --> photo
  question --> graphic
  question --> animation
  photo --> jpg
  graphic --> png
  animation --> gif

투명도가 필요한데 색도 풍부하면 PNG를 쓴다. 무손실의 큰 용량을 감수하는 대신 알파 채널을 얻는 선택이다.

JPG, PNG, GIF 이미지 포맷 코드

파일 포맷은 파일 첫 몇 바이트의 **매직 넘버 (Magic Number)**로 구분할 수 있다. 파일 확장자가 아니라 실제 바이너리 헤더가 포맷을 결정한다.

이 코드에서 기억할 것: 파일 확장자는 사용자가 임의로 바꿀 수 있지만, 매직 넘버는 포맷 명세에 고정되어 있다. 서버에서 업로드된 이미지의 실제 포맷을 검증할 때 확장자가 아니라 매직 넘버를 확인해야 하는 이유다.

각 포맷의 매직 넘버:

  • JPG: FF D8 (2바이트). 파일 끝은 FF D9로 끝난다.
  • PNG: 89 50 4E 47 0D 0A 1A 0A (8바이트). ASCII로 읽으면 두 번째~네 번째 바이트가 PNG다.
  • GIF: 47 49 46 38 37 61 또는 47 49 46 38 39 61 (6바이트). ASCII로 읽으면 GIF87a 또는 GIF89a다. 89a 버전이 애니메이션과 투명도를 지원한다.

정리

세 포맷의 선택 기준은 **“무엇을 저장하느냐”**로 결정된다.

  • 사진, 자연 이미지 → JPG. 손실 압축으로 파일 크기를 극적으로 줄인다. 투명도가 필요 없고 색상이 풍부한 이미지에 최적이다.
  • 로고, 스크린샷, 텍스트 포함 이미지, 투명 배경 → PNG. 무손실이므로 텍스트 경계가 선명하고, 알파 채널로 반투명 표현이 가능하다.
  • 짧은 애니메이션, 이모티콘, 밈 → GIF. 256색 제한이 있지만 브라우저에서 플레이어 없이 재생된다.

현대 웹에서는 WebP (Google, 2010)가 세 포맷의 장점을 통합하려는 시도로 확산 중이다. WebP는 손실/무손실 압축 모두 지원하고, 알파 채널과 애니메이션도 지원한다. 하지만 JPG/PNG/GIF는 여전히 가장 널리 호환되는 기본 포맷이다.
