Python 함수 인자 전달

Python 함수 인자 전달

Python은 객체의 참조(주소)를 값으로 복사해서 함수에 넘긴다. 그래서 재할당과 객체 변이가 서로 다른 결과를 만든다.

Python 함수 인자 전달 혼동

함수에 변수를 넘겼을 때, 함수 안에서 그 변수를 바꾸면 바깥에도 영향이 있는가?

C에서는 Call by Value일 때 복사본이 넘어가고, Call by Reference(*ptr)일 때 원본 주소가 넘어간다고 설명할 수 있다. Python에서는 아래 두 코드가 서로 다른 결과를 보여 혼란이 생긴다.

하나는 바뀌지 않고 다른 하나는 바뀐다. Call by Value만으로 설명하면 리스트의 변화를 설명하기 어렵고, Call by Reference만으로 설명하면 정수가 그대로인 이유를 설명하기 어렵다. 이 차이는 Python의 이름 바인딩, 객체 참조, 재할당, 변이를 함께 살펴보면 이해할 수 있다.

이 문서에서는 다음을 구분한다.

  • Python에서 변수가 “이름표”라는 설명이 뜻하는 것
  • 함수에 인자를 넘길 때 복사되는 것
  • 함수 안에서 = 재할당과 .append() 같은 변이(mutation)가 서로 다른 결과를 만드는 이유

이름표와 객체 참조

Python 변수는 이름표다

이 문서에서는 C 변수와 Python 이름 바인딩의 차이를 상자와 이름표에 비유한다. C의 int a = 5;는 값을 담은 메모리 상자를 변수로 보는 방식으로 설명한다. Python의 a = 5는 정수 객체 5에 a라는 이름을 연결하는 동작으로 설명한다. 이 비유에서 Python 변수는 상자 자체가 아니라 객체에 연결된 이름표(name binding)다.

%% C 변수와 Python 이름 바인딩
flowchart TD
  c_label["C"]
  c_box["변수 a<br/>값 5를 담은 메모리 상자<br/>상자 안의 값을 덮어쓸 수 있음"]
  py_label["Python"]
  py_name["이름 a<br/>객체에 붙은 이름표"]
  py_object["정수 객체 5<br/>id: 0x7ff...<br/>이름표가 가리키는 대상을 바꿀 수 있음"]
  c_label --> c_box
  py_label --> py_name
  py_name -->|참조| py_object

다음 코드는 id()를 이용해 두 이름이 같은 객체를 가리키는 상태와 재할당 뒤의 상태를 비교한다. 주석의 숫자는 실행 결과의 예시다.

b = a는 b를 a가 가리키는 객체에 연결한다. 이어지는 b = 10은 b를 다른 객체에 연결한다. 이 설명에서 바뀌는 것은 b의 바인딩이며, a의 바인딩은 영향을 받지 않는다.

Call by Object Reference (객체 참조에 의한 호출)

Python 함수 인자 전달은 이 문서에서 Call by Object Reference 또는 Call by Sharing이라는 용어로 설명한다. 호출 과정은 다음과 같다.

  1. 호출자(caller)의 이름이 가리키는 객체의 참조(주소)를 복사한다.
  2. 복사된 참조를 함수의 매개변수 이름에 연결한다.
  3. 함수 안에서 매개변수에 =로 재할당하면 매개변수의 이름만 다른 객체로 옮겨진다. 원래 객체와 호출자의 이름에는 영향이 없다.
  4. 함수 안에서 객체 자체를 변이(mutation)하면 — .append(), [0] = ... 등 — 호출자도 같은 객체를 보고 있으므로 변경이 보인다.

이 설명에서 복사되는 값은 객체 자체가 아니라 객체를 가리키는 참조다. C의 Call by Value처럼 값이 복사되지만, 여기서 그 값은 객체의 주소에 해당한다고 본다. 이 때문에 Call by Object Reference 또는 Call by Sharing이라고 부른다.

%% Call by Object Reference 흐름
flowchart TD
  before_name["호출 전<br/>a"]
  before_obj["리스트 객체<br/>[1"]
  call_a["함수 호출 시<br/>a<br/>x"]
  call_obj["같은 리스트 객체<br/>[1"]
  mutate_names["x.append(4)<br/>a<br/>x"]
  mutate_obj["변이된 객체<br/>[1"]
  reassign_a["x = [99]<br/>a"]
  reassign_original["원래 객체<br/>[1"]
  reassign_x["매개변수 x<br/>새 이름 바인딩"]
  reassign_new["새 리스트 객체<br/>[99]<br/>id: 0xDEF"]
  before_name -->|참조| before_obj
  before_obj -->|참조 복사| call_obj
  call_a -->|a와 x가 같은 객체를 봄| call_obj
  call_obj -->|객체 내부 변경| mutate_obj
  mutate_names -->|둘 다 변경된 객체를 봄| mutate_obj
  mutate_obj -->|재할당 전 원래 객체| reassign_original
  reassign_a -->|a는 그대로| reassign_original
  reassign_x -->|x만 새 객체로 이동| reassign_new

변경 가능 객체와 변경 불가능 객체

이 문서의 설명에서는 Python 객체를 변경 가능 여부에 따라 두 부류로 나눈다.

  • 변경 불가능(immutable): int, float, str, tuple, bool, frozenset
    • 객체를 생성한 뒤 내부 값을 바꿀 수 없다.
    • a = 5; a += 1은 5를 6으로 바꾸는 것이 아니라 새 객체 6을 만들고 a를 거기에 연결하는 동작으로 설명한다.
    • 함수 안에서 immutable 인자를 “변경”하는 표현은 재할당으로 이어지므로 호출자의 이름에는 영향이 없다.
  • 변경 가능(mutable): list, dict, set, 사용자 정의 클래스 인스턴스
    • 객체를 생성한 뒤 내부를 바꿀 수 있다.
    • 함수 안에서 .append(), [key] = value 등으로 변이하면 호출자에게도 변경이 보인다.
    • =로 재할당하면 매개변수의 이름만 바뀌므로 호출자에게는 영향이 없다.

따라서 앞의 예에서 정수와 리스트의 결과가 다른 까닭은 서로 다른 인자 전달 방식을 사용해서가 아니다. 이 문서가 제시하는 구분 기준은 객체의 변경 가능 여부와 함수 안에서 수행한 연산이 재할당인지 변이인지다.

Python 함수 인자 전달 코드

immutable 객체: 정수

함수에 진입할 때 x와 a는 같은 객체 42를 가리킨다. x = 100은 x만 새 객체에 연결한다. 따라서 a는 계속 42를 가리킨다. 이 결과는 코드 주석에 제시된 동작을 설명한 것이며, 별도의 실행 검증 결과를 추가한 것은 아니다.

mutable 객체: 리스트

lst와 my_list는 같은 리스트 객체를 가리킨다. lst.append(99)는 이름을 다른 객체에 연결하지 않고 그 객체의 내부를 변경한다. my_list도 같은 객체를 가리키므로 코드 주석과 같은 변경이 보인다.

mutable 객체에서도 재할당은 영향 없음

lst = [99, 100]은 lst를 새 객체에 연결한다. my_list는 계속 원래 리스트를 가리킨다. 따라서 객체가 mutable이어도 = 재할당만 수행하면 호출자의 이름에는 영향이 없다.

C의 Call by Value / Call by Reference와 비교

%% C와 Python 인자 전달 비교
flowchart TD
  c_value["C: Call by Value<br/>void f(int x) { x = 10; }<br/>x는 a의 복사본<br/>a에 영향 없음"]
  c_ref["C: Call by Reference (포인터)<br/>void f(int *x) { *x = 10; }<br/>x는 a의 주소<br/>*x로 a의 상자를 직접 수정"]
  py_obj["Python: Call by Object Reference<br/>def f(x): x.append(10)<br/>x는 객체 참조의 복사본<br/>객체 변이는 호출자에게 보임<br/>x 재할당은 호출자에게 영향 없음"]
  note["Python에 없는 것<br/>C의 *x처럼 호출자의 이름표 자체를<br/>다른 객체로 옮기는 방법은 없음"]
  c_value --> c_ref
  c_ref --> py_obj
  py_obj -->|구분 기준| note

재할당과 변이를 판단하는 기준

Python의 인자 전달을 이 문서의 용어로 표현하면 Call by Object Reference다. 함수에는 객체의 참조(주소)가 값으로 복사되어 전달된다.

함수 호출 뒤 호출자에게 변경이 보이는지 판단하려면 세 가지를 확인한다.

  • 변수는 객체에 연결된 이름표이며, =는 그 이름표를 다른 객체에 연결한다.
  • 함수 안에서 =로 재할당하면 매개변수의 이름만 바뀌므로 호출자에게 영향이 없다.
  • 함수 안에서 객체를 변이하면 호출자도 같은 객체를 가리키므로 .append(), [i] = ... 같은 변경이 보인다.

따라서 “정수는 Call by Value처럼 동작하고 리스트는 Call by Reference처럼 동작한다”고 나누는 설명은 이 문서의 모델과 맞지 않는다. 전달 방식은 같고, 결과는 객체가 mutable인지 immutable인지와 함수가 재할당 또는 변이 중 무엇을 수행했는지에 따라 달라진다.
