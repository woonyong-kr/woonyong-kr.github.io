C 포인터와 배열

C 포인터와 배열

포인터는 메모리 주소를 저장하는 변수이고, 배열은 같은 타입의 값을 연속된 메모리 공간에 저장하는 구조다. C에서는 둘이 밀접하게 연결되어 있지만 서로 같지는 않다. OS 코드를 정확히 읽으려면 이 차이부터 이해해야 한다.

C 포인터와 배열 구분

C로 작성된 시스템 코드에서는 거의 모든 함수에 *와 &가 등장한다. 구조체 포인터, 이중 포인터, 포인터 캐스팅, offsetof 매크로가 각각 어떤 역할을 하는지 모르면 메모리를 다루는 코드의 흐름을 따라가기 어렵다.

PintOS의 list_entry 매크로는 구조체 멤버를 가리키는 포인터를 이용해 구조체 전체의 시작 주소를 역산한다. setup_initial_stack 함수에서는 char **argv라는 이중 포인터로 인자 배열을 다루고, 그 내용을 스택에 쌓는다. 두 코드는 다루는 대상이 다르지만 모두 포인터가 가리키는 위치와 주소의 이동을 이해해야 읽을 수 있다. 이를 위해 포인터가 메모리에서 무엇을 나타내는지부터 배열과의 관계, 포인터 캐스팅이 필요한 이유까지 차례로 살펴본다.

먼저 다음 항목을 구분해 보자.

  • 포인터 변수와 일반 변수의 차이
  • 배열 이름이 포인터처럼 동작하는 상황과 그렇지 않은 상황
  • *, &, ->, []가 메모리에서 수행하는 일
  • 이중 포인터(char **)가 필요한 이유
  • OS 코드에서 void * 캐스팅과 포인터 산술을 사용하는 방식

주소와 연속 메모리: 핵심 용어와 접근 원리

포인터는 주소를 담는 변수다

일반 변수는 메모리의 특정 위치에 값을 저장한다. 포인터는 다른 값이 저장된 메모리의 위치, 즉 주소를 자신의 값으로 저장한다.

창고에 비유하면 일반 변수는 창고에 보관된 물건이고, 포인터는 그 물건이 있는 창고 번호를 적은 메모지다. 메모지에서 번호를 확인한 뒤 해당 창고로 가면 실제 물건을 꺼낼 수 있다.

여기에 사용된 기호의 의미는 다음과 같다.

  • &x: x의 주소를 얻는다(주소 연산자, address-of).
  • *p: p에 저장된 주소로 가서 값을 읽는다(역참조, dereference).
  • int *p: p가 int를 가리키는 포인터라는 선언이다.

이를 메모리 상태로 나타내면 다음과 같다.

주소값변수명
0x7ffc001042x
0x7ffc00180x7ffc0010p에는 x의 주소가 들어 있다

포인터 변수 자체도 하나의 변수이므로 메모리 공간을 차지한다. 64비트 시스템에서는 포인터의 크기가 항상 8바이트다. int를 가리키는 포인터와 struct thread를 가리키는 포인터의 크기가 같은 이유는 두 포인터 모두 같은 크기의 주소를 저장하기 때문이다.

배열은 연속된 메모리 블록이다

배열은 같은 타입의 값을 빈틈없는 연속된 메모리 공간에 나란히 저장한다.

각 원소는 메모리에 다음과 같이 배치된다.

주소값
0x7ffc0020arr[0] = 10
0x7ffc0024arr[1] = 20
0x7ffc0028arr[2] = 30
0x7ffc002carr[3] = 40

int가 4바이트이므로 이 배열에서는 원소 사이의 주소 차이도 정확히 4바이트다. 이처럼 배치가 규칙적이어서 시작 주소에 인덱스와 원소 크기의 곱을 더하면 원하는 원소의 주소를 바로 계산할 수 있다. 배열이 O(1) 시간에 원소에 접근할 수 있는 이유다.

배열 이름은 대부분의 문맥에서 포인터처럼 동작한다

C에서 배열 이름은 대부분의 문맥에서 첫 번째 원소를 가리키는 포인터로 변환된다. 이를 배열의 포인터 변환(decay)이라고 한다.

따라서 p[i]와 *(p + i)는 같은 연산이다. [] 연산자는 포인터 산술과 역참조를 결합한 축약 표현이다.

그러나 배열과 포인터가 항상 같은 것은 아니다. 다음 상황에서는 차이가 분명하게 드러난다.

  • sizeof(arr)는 배열 전체의 크기인 16바이트를 반환하지만, sizeof(p)는 포인터의 크기인 8바이트를 반환한다.
  • &arr은 배열 전체를 가리키는 포인터이며 타입은 int (*)[4]이다. 반면 &p는 포인터 변수 자체의 주소다.
  • 배열 이름에는 새로운 주소를 대입할 수 없다. 따라서 arr = other_array;는 컴파일 오류가 된다. 배열 이름은 대입할 수 있는 변수가 아니기 때문이다.

포인터 산술은 타입 크기만큼 이동한다

포인터에 정수를 더하면 주소의 숫자 값이 그 정수만큼만 증가하는 것이 아니다. 실제 주소는 더한 정수와 포인터가 가리키는 타입의 크기를 곱한 만큼 이동한다.

따라서 char *이면 1바이트씩, int *이면 4바이트씩, struct thread *이면 sizeof(struct thread)만큼 이동한다. 컴파일러는 포인터의 타입 정보를 바탕으로 이동할 바이트 수를 계산한다.

같은 이유로 void *에는 포인터 산술을 직접 적용할 수 없다. void는 가리키는 대상의 크기가 정해져 있지 않아 한 칸을 몇 바이트로 계산해야 하는지 알 수 없기 때문이다. 주소를 바이트 단위로 이동하려면 char *나 uint8_t *로 캐스팅해야 한다.

구조체 포인터와 -> 연산자

구조체 변수에서 멤버에 접근할 때는 . 연산자를 사용한다. 구조체를 가리키는 포인터에서 멤버에 접근할 때는 -> 연산자를 사용한다.

pp->x는 “pp가 가리키는 구조체로 이동한 뒤 그 안의 x 멤버를 읽는다”는 뜻이다. OS 코드에서 자주 보이는 thread_current()->status 같은 표현도 같은 방식으로 구조체 포인터를 역참조한다.

이중 포인터는 포인터의 주소가 필요할 때 쓴다

이중 포인터(Double Pointer)는 다른 포인터를 가리키는 포인터이며, char **argv가 대표적인 예다.

main(int argc, char **argv)에서 argv가 이중 포인터인 이유를 문자열 배열의 구조로 살펴보자. argv는 문자열 배열이다. 문자열 하나는 char *로 나타내고, 이러한 문자열을 여러 개 담는 배열은 char *[]로 나타낸다. 이 배열이 함수에 전달되면 첫 번째 원소를 가리키는 포인터로 변환되므로 char **가 된다.

%% char **argv 이중 포인터 구조
flowchart LR
  argv["argv<br/>type: char **<br/>문자열 포인터 배열의 시작 주소"]
  slot0["argv[0]<br/>type: char *<br/>&quot;ls&quot; 주소"]
  slot1["argv[1]<br/>type: char *<br/>&quot;-l&quot; 주소"]
  slot2["argv[2]<br/>type: char *<br/>&quot;/home&quot; 주소"]
  str0["&quot;ls&quot;"]
  str1["&quot;-l&quot;"]
  str2["&quot;/home&quot;"]
  argv --> slot0
  argv --> slot1
  argv --> slot2
  slot0 --> str0
  slot1 --> str1
  slot2 --> str2

함수 안에서 포인터 자체를 바꿔야 할 때도 이중 포인터가 필요하다. C는 값을 복사해 전달하므로(call by value), 함수에 포인터를 넘기면 원본이 아니라 포인터의 복사본이 전달된다. 함수에서 원본 포인터를 변경하려면 포인터가 저장된 주소, 즉 이중 포인터를 넘겨야 한다.

void *는 대상 타입을 정하지 않은 범용 포인터다

void *는 어떤 객체 타입의 주소든 담을 수 있는 범용 포인터다. C 표준은 모든 객체 포인터를 void *로 변환한 뒤 다시 원래 타입으로 되돌릴 수 있도록 보장한다.

OS 코드에서 void *는 함수가 특정 타입이 아니라 일반적인 메모리 블록을 다룬다는 뜻으로 사용된다. malloc이 void *를 반환하고, memcpy의 매개변수가 void *인 이유도 여기에 있다.

이 포인터가 가리키는 값을 사용하려면 원래 타입으로 캐스팅해야 한다. void *를 그대로 역참조하면 컴파일러가 해당 주소에서 몇 바이트를 읽어야 하는지 판단할 수 없어 오류가 발생한다.

offsetof는 구조체 멤버의 위치를 바이트 단위로 계산한다

offsetof(TYPE, MEMBER)는 구조체의 시작 주소에서 특정 멤버까지 떨어진 바이트 거리를 반환한다. PintOS의 list_entry 매크로는 이 값을 이용해 멤버 포인터에서 구조체 시작 주소를 역산한다.

이 매크로는 주소 0에 TYPE 구조체가 있다고 가정한다. 그러면 MEMBER의 가상 주소가 구조체 시작점에서 해당 멤버까지의 오프셋과 같아진다는 원리를 이용할 수 있다.

C 포인터와 배열 코드

1. list_entry: 멤버 포인터에서 구조체 전체 찾기

PintOS의 연결 리스트는 구조체 내부에 struct list_elem을 포함하는 침투형(Intrusive) 리스트다. 리스트를 순회할 때 얻는 것은 list_elem 포인터이므로, 이를 포함한 바깥 구조체를 찾으려면 포인터 산술로 시작 주소를 역산해야 한다.

이 매크로의 동작을 단계별로 풀어보면 다음과 같다.

  1. &(LIST_ELEM)->next — list_elem의 next 멤버 주소를 구한다.
  2. (uint8_t *) — 바이트 단위로 주소를 계산할 수 있도록 캐스팅한다.
  3. offsetof(STRUCT, MEMBER.next) — 바깥 구조체의 시작점에서 해당 next까지 떨어진 바이트 거리를 구한다.
  4. 뺄셈 — next의 실제 주소에서 오프셋을 빼 구조체의 시작 주소를 얻는다.
  5. (STRUCT *) — 계산 결과를 바깥 구조체를 가리키는 포인터로 캐스팅한다.

메모리 배치를 그림으로 나타내면 다음과 같다.

%% list_entry의 오프셋 역산 구조
flowchart TD
  thread["struct thread 시작 &#124; tid &#124; ... &#124; elem.prev &#124; elem.next"]
  list_elem["LIST_ELEM<br/>&amp;(LIST_ELEM)-&gt;next"]
  offset["offsetof(struct thread, magic)"]
  result["구조체 시작 주소<br/>&amp;(elem.next) - offsetof(...)"]
  thread --> list_elem
  list_elem --> offset
  offset --> result
  result --> thread

이 코드는 void *와 바이트 단위 포인터 산술을 결합하는 전형적인 패턴이다. 멤버의 타입만으로 이동하는 대신 메모리 오프셋을 계산해 바깥 구조체의 주소를 복원한다.

2. parse_command_line: 이중 포인터로 문자열 배열 다루기

PintOS가 유저 프로그램을 실행할 때는 명령줄 문자열을 토큰으로 나누어 char **argv 배열에 저장한다.

이 코드에는 서로 다른 역할을 맡는 포인터가 세 겹으로 등장한다.

  • command는 char *이며 원본 문자열의 시작 주소를 나타낸다.
  • argv는 char **이며 문자열 포인터 배열의 시작 주소를 나타낸다.
  • argc는 int *이며 함수 밖에 있는 카운터를 수정하기 위해 사용한다.

argv[(*argc)++] = token은 다음 순서로 동작한다. 먼저 argc가 가리키는 값을 읽어 배열의 인덱스로 사용한다. 이어서 argv 배열의 해당 위치에 token 주소를 저장하고, 마지막으로 카운터를 1 증가시킨다.

3. setup_initial_stack: 포인터 캐스팅으로 스택 구성하기

유저 프로그램을 실행할 때 커널은 유저 스택에 argv 문자열과 포인터 배열을 직접 기록한다. 이 과정에서는 스택의 정확한 위치에 데이터를 배치하기 위해 포인터 캐스팅과 포인터 산술을 함께 사용한다.

stack_p가 char *인 이유는 스택 포인터를 1바이트 단위로 정밀하게 이동해야 하기 때문이다. 포인터가 int *였다면 한 번 이동할 때마다 주소가 4바이트씩 바뀐다.

문자열을 배치한 뒤 포인터 배열을 스택에 기록할 때는 다시 uintptr_t *로 캐스팅한다.

*(uintptr_t *) stack_p는 stack_p가 가리키는 위치를 uintptr_t, 즉 8바이트 정수를 가리키는 포인터로 해석한 뒤 그 위치에 값을 기록한다는 뜻이다. char * 포인터인 상태에서는 8바이트 값을 한 번에 기록할 수 없으므로 이러한 캐스팅이 필요하다.

정리

포인터는 메모리 주소를 저장하는 변수이고, 배열은 같은 타입의 값을 연속된 메모리 공간에 저장한다. 배열 이름은 대부분의 문맥에서 첫 번째 원소의 주소로 변환되지만, sizeof와 & 연산에서는 포인터로 변환되지 않고 배열 자체로 취급된다. 포인터 산술은 포인터가 가리키는 타입의 크기를 단위로 이동한다. 따라서 바이트 단위로 주소를 조작하려면 char *나 uint8_t *로 캐스팅해야 한다.

OS 코드에서는 이러한 개념이 침투형 리스트의 list_entry, 명령줄 파싱의 char **argv, 포인터 캐스팅을 이용한 스택 구성 같은 핵심 패턴에 반복해서 등장한다. 각 포인터가 무엇을 가리키고 어떤 단위로 이동하는지 확인하면 복잡해 보이는 코드도 메모리 배치의 변화에 따라 읽을 수 있다.
