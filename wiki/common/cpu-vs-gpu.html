CPU와 GPU

CPU와 GPU

범위: 이 문서는 CPU와 GPU의 설계 차이, 데이터 병렬성, 하드웨어 선택 기준을 개념적으로 설명한다. 제시된 코드의 동작과 성능 관련 판단은 특정 라이브러리·하드웨어·버전·실행 환경에서 검증한 결과가 아니므로, 실제 적용 전 해당 환경의 실행 기록과 성능 측정으로 확인해야 한다.

CPU는 복잡한 작업 하나를 빠르게 끝내는 데 최적화되어 있고, GPU는 단순한 작업 수천 개를 동시에 처리하는 데 최적화되어 있다.

CPU와 GPU 필요성

프로그램을 실행하는 하드웨어가 CPU 하나뿐이던 시절이 있었다. 그런데 화면에 수백만 개의 픽셀을 매 프레임 갱신해야 하는 그래픽 처리가 등장하면서, CPU만으로는 감당이 안 되는 상황이 생겼다. 각 픽셀의 색상 계산은 단순하지만 그 수가 너무 많기 때문이다.

이 문제를 해결하기 위해 “단순 연산을 대량으로 병렬 처리”하는 전용 칩이 만들어졌다. 그것이 GPU(Graphics Processing Unit)다. 오늘날 GPU는 그래픽뿐 아니라 딥러닝, 과학 시뮬레이션 등 대규모 병렬 연산이 필요한 모든 분야에 쓰인다.

CPU와 GPU의 차이를 모르면 다음을 판단할 수 없다.

  • 내 프로그램이 왜 느린지 — CPU 병목인지, 병렬화 부족인지
  • 딥러닝 학습이 왜 GPU를 쓰는지 — 행렬 곱셈이 왜 GPU에 적합한지
  • 어떤 작업에 어떤 하드웨어를 선택해야 하는지

복잡한 하나와 단순한 다수

비유: 교수 한 명 vs 조교 천 명

시험 채점을 해야 한다고 하자.

  • CPU 방식: 수학 교수 한 명이 채점한다. 서술형 문제를 읽고, 부분 점수를 판단하고, 예외 케이스를 처리한다. 복잡한 판단을 빠르게 해내지만, 답안지가 1,000장이면 혼자서 오래 걸린다.
  • GPU 방식: 조교 1,000명이 채점한다. 각 조교는 “정답이면 O, 아니면 X” 수준의 단순 작업만 할 수 있다. 하지만 1,000장을 동시에 처리하니 전체 시간은 짧다.

CPU는 **소수의 강력한 코어(Core)**로 복잡한 흐름 제어(분기 예측, 비순차 실행 등)를 처리한다. GPU는 수천 개의 단순 코어로 같은 연산을 데이터만 바꿔 동시에 실행한다.

CPU의 설계 철학: 지연 시간(Latency) 최소화

CPU는 하나의 작업을 최대한 빨리 끝내는 것이 목표다.

  • 코어 수: 보통 416개 (서버용은 64128개)
  • 클럭 속도: 높다 (3~5 GHz)
  • 캐시(Cache): 크다 (L1/L2/L3 합계 수십 MB). 데이터를 미리 가져와 메모리 접근 지연을 줄인다.
  • 분기 예측(Branch Prediction): if/else 분기를 미리 예측해서 파이프라인이 비는 시간을 줄인다.
  • 비순차 실행(Out-of-Order Execution): 명령어 순서를 바꿔 실행해 대기 시간을 숨긴다.

이 모든 하드웨어는 “한 스레드가 다음 명령어를 최대한 빨리 실행하게” 만들기 위한 것이다. 대신 이런 제어 로직이 칩 면적의 상당 부분을 차지하기 때문에, 코어 수를 수천 개로 늘릴 수 없다.

GPU의 설계 철학: 처리량(Throughput) 최대화

GPU는 전체 작업을 최대한 많이 동시에 끝내는 것이 목표다.

  • 코어 수: 수천~수만 개 (NVIDIA RTX 4090: 16,384 CUDA 코어)
  • 클럭 속도: CPU보다 낮다 (1~2 GHz)
  • 캐시: 작다. 대신 높은 대역폭(Bandwidth)의 메모리(GDDR, HBM)를 사용한다.
  • 제어 로직: 단순하다. 분기 예측 없고, 비순차 실행 없다.
  • 실행 모델: SIMT (Single Instruction, Multiple Threads) — 하나의 명령어를 수천 스레드가 동시에, 각자 다른 데이터에 대해 실행한다.

GPU 코어 하나는 CPU 코어보다 훨씬 단순하고 느리다. 하지만 수천 개가 동시에 돌아가면 전체 처리량은 CPU를 압도한다.

  cpu -.-> gpu

CPU는 칩 면적 대부분을 캐시와 제어 로직에 쓴다. GPU는 같은 면적을 연산 유닛(ALU)으로 채운다.

어떤 작업에 어떤 하드웨어가 적합한가

  • CPU가 유리한 작업
    • 분기가 많은 로직: 웹 서버 요청 처리, 컴파일러, OS 커널
    • 순차 의존성이 강한 작업: 이전 결과가 있어야 다음 단계 진행 가능한 알고리즘
    • 단일 스레드 성능이 중요한 작업: 게임 로직, 스크립트 인터프리터
  • GPU가 유리한 작업
    • 데이터 병렬성이 높은 작업: 같은 연산을 수만 개 데이터에 독립적으로 적용
    • 행렬 연산: 딥러닝의 forward/backward pass, 3D 그래픽의 정점 변환
    • 이미지/영상 처리: 각 픽셀에 같은 필터 적용

판단 기준은 **데이터 병렬성(Data Parallelism)**이다. 같은 연산을 서로 독립적인 데이터에 반복 적용할 수 있으면 GPU가 유리하다. 데이터 간 의존성이 있거나 분기가 복잡하면 CPU가 유리하다.

딥러닝에서 GPU를 쓰는 이유

신경망의 핵심 연산은 행렬 곱셈이다. 예를 들어 입력 벡터 x (크기 784)에 가중치 행렬 W (784 × 256)를 곱하면, 결과 벡터의 각 원소는 독립적으로 계산할 수 있다.

결과[0], 결과[1], …, 결과[255]는 서로 의존성이 없다. 256개를 동시에 계산할 수 있다. 실제 딥러닝에서는 배치(batch) 단위로 여러 입력을 한꺼번에 처리하므로, 병렬 처리할 연산이 수만수백만 개가 된다. GPU의 수천 코어가 이 연산을 동시에 나눠 처리하면, CPU 대비 10100배 빠르다.

CPU와 GPU 코드

CPU와 GPU의 차이를 행렬 곱셈으로 비교한다. Python의 NumPy는 CPU에서 실행되고, PyTorch의 .cuda()는 GPU에서 실행된다.

NumPy의 @ 연산자는 내부적으로 BLAS 라이브러리를 호출한다. CPU의 멀티코어와 SIMD 명령어를 활용하지만, 코어 수의 한계 때문에 4096×4096 행렬 곱셈에 수 초가 걸린다.

같은 4096×4096 행렬 곱셈이 GPU에서는 수십 밀리초에 끝난다. 데이터를 GPU 메모리로 옮기는 비용(device='cuda')이 있지만, 연산량이 충분히 크면 전송 비용을 압도하는 속도 이점을 얻는다.

CPU가 더 빠른 경우

이 코드는 a + b의 결과가 다음 반복에 필요하다. 병렬화할 수 없다. GPU로 옮기면 오히려 데이터 전송 오버헤드만 추가된다. 이런 순차 의존성이 강한 코드는 CPU의 높은 클럭과 분기 예측이 유리하다.

정리

CPU는 복잡한 제어 흐름을 적은 코어로 빠르게 처리하는 지연 시간 최적화 장치다. GPU는 단순한 연산을 수천 코어로 동시에 처리하는 처리량 최적화 장치다. 둘은 경쟁이 아니라 상호 보완 관계이며, 작업의 데이터 병렬성에 따라 적합한 하드웨어가 달라진다.

판단 기준: “같은 연산을 독립적인 데이터에 대량으로 반복하는가?” 그렇다면 GPU, 아니라면 CPU가 적합하다.
