AWS 실습 비용 안전장치와 리소스 정리

EC2뿐 아니라 RDS·NAT Gateway·ALB 같은 관리형 리소스가 실습 후에도 비용을 만들 수 있으므로, 실습을 시작하기 전에 비용 안전장치를 마련하고 끝난 뒤에는 의존 관계에 맞춰 리소스를 정리해야 한다.

AWS 실습에서는 리소스를 만드는 일만큼 지우는 일도 중요하다. 콘솔을 닫아도 생성한 리소스는 남아 있으며, EC2 한 대보다 RDS, NAT Gateway, ALB, OpenSearch Serverless 같은 관리형 리소스가 더 오래 비용을 만들 수 있다.

따라서 다시 실습할 때는 이 체크리스트를 먼저 열어 둔다. 완벽한 비용 최적화보다는 실습이 끝난 뒤에도 남아서 비용을 만드는 리소스를 줄이는 데 목적이 있다.

비용이 남는 이유

AWS는 사용량에 따라 과금하므로 콘솔을 닫는 것만으로는 비용 발생을 막을 수 없다. 실행 중이거나 생성된 상태로 남은 리소스를 직접 확인하고 정리해야 한다.

실습 리소스는 서로 의존하기도 한다. 예를 들어 VPC를 삭제하려면 그 안의 subnet, NAT Gateway, endpoint, security group, ENI 등을 먼저 삭제해야 한다. 이런 의존 리소스가 남아 있으면 상위 리소스 삭제가 막힐 수 있다.

Bedrock 계열 실습도 연결된 저장소와 벡터 인덱스를 함께 살펴야 한다. Knowledge Base만 확인하지 말고 S3, OpenSearch Serverless, IAM role, guardrail, agent가 남아 있는지도 확인한다.

시작 전 안전장치

  • Budget 만들기
    • AWS Billing and Cost Management에서 Budget을 만든다.
    • 개인 계정이라면 낮은 금액으로 알림을 먼저 설정한다.
    • 이메일 알림을 받을 주소가 맞는지 확인한다.
  • 리전 고정
    • 실습에 사용할 리전을 하나로 정한다.
    • 리소스를 정리할 때도 같은 리전에서 확인한다.
  • 이름과 태그 사용
    • VPC-Lab, Web-ASG, Web-ALB, rdscluster, mysecret처럼 실습에서 사용한 이름을 유지한다.
    • 이름과 태그를 남겨 두면 나중에 리소스를 검색해 삭제하기 쉽다.
  • 중간 중단 기준 정하기
    • 시간이 부족하다면 새 리소스를 더 만들지 않는다.
    • 현재 단계까지 만든 리소스 가운데 비용이 발생할 수 있는 항목부터 확인한다.

비용 위험 우선순위

먼저 확인할 리소스는 비용 위험에 따라 다음과 같이 나눌 수 있다.

  • 높음
    • RDS/Aurora cluster와 DB instance
    • NAT Gateway와 Elastic IP
    • ALB
    • EC2 instance와 Auto Scaling Group
    • OpenSearch Serverless vector store
  • 중간
    • S3 bucket과 object
    • CloudWatch log와 metric
    • Secrets Manager secret
  • 낮지만 정리 필요
    • AMI와 snapshot
    • Launch template
    • IAM role과 policy
    • Bedrock Agent, Flow, Guardrail

Compute & Network 정리 순서

리소스 사이의 의존 관계를 고려하면 다음 순서로 삭제할 때 막히는 경우를 줄일 수 있다.

  • Auto Scaling과 웹 계층
    • Auto Scaling Group Web-ASG 삭제
    • ALB Web-ALB 삭제
    • Target Group Web-TG 삭제
    • Launch Template Web 삭제
    • AMI Web Server v1 deregister
    • AMI가 만든 snapshot 삭제
    • 남은 EC2 instance를 확인한 뒤 종료
  • RDS와 Secret
    • DB deletion protection 끄기
    • reader instance 삭제
    • writer instance 삭제
    • cluster 삭제
    • final snapshot을 만들지 않을지는 실습 정책에 맞게 선택
    • 실습 snapshot이 남아 있다면 삭제
    • Secrets Manager secret mysecret 삭제 예약
  • S3
    • bucket 안의 object 비우기
    • versioning을 켰다면 object versions와 delete markers까지 비우기
    • bucket 삭제
  • VPC 주변 리소스
    • VPC endpoint 삭제
    • NAT Gateway 삭제
    • Elastic IP release
    • 다음 security group 삭제
      • Immersion Day - Web Server
      • DB-SG
      • ASG-Web-Inst-SG
      • web-ALB-SG
    • route table, subnet, internet gateway가 남아 있는지 확인
    • VPC VPC-Lab 삭제

Bedrock 정리 순서

  • Agent
    • Agent alias가 있다면 먼저 삭제한다.
    • Agent를 삭제한다.
    • 연결된 Lambda와 action group의 실습 리소스가 남아 있는지 확인한다.
  • Flow
    • Prompt Flow에 연결된 prompt, Lambda, role을 확인한다.
  • Guardrail
    • Agent와 guardrail의 연결을 제거한 뒤 guardrail을 삭제한다.
  • Knowledge Base
    • data source sync 상태를 확인한다.
    • Knowledge Base를 삭제한다.
    • OpenSearch Serverless collection/vector store를 삭제한다.
    • S3 data source bucket과 object가 남아 있는지 확인한다.
    • service role과 policy를 정리한다.

삭제 후 확인

삭제 작업이 끝나면 실습에 사용한 리전에서 다음 항목을 다시 확인한다.

  • EC2 instances
  • Auto Scaling Groups
  • Load Balancers
  • Target Groups
  • NAT Gateways
  • Elastic IPs
  • RDS Databases
  • S3 Buckets
  • Secrets Manager
  • Bedrock Agents, Knowledge Bases, Flows, Guardrails

리소스가 보이지 않더라도 Billing 확인은 별도로 필요하다. Cost Explorer 또는 Bills에서 서비스별 비용을 살펴본다. 다음 날 비용이 늦게 반영될 수 있으므로 하루 뒤에도 다시 확인한다.
